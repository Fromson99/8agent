벡터 단계 Python 호환 수정 R2 — 2026-11-04

사진의 오류 원인
R1 vector_stage.py 111행에서 zip(items, vectors, strict=True)를 사용했습니다.
strict는 Python 3.10부터 지원됩니다. Python 3.9.25에서 사진과 같은
TypeError: zip() takes no keyword arguments를 실제 재현했습니다.
사진만으로 현장의 정확한 Python 버전 번호는 확인되지 않았습니다.
R2는 구간 수와 벡터 수가 같은지 먼저 확인한 뒤 일반 zip으로 결합합니다.
길이가 다를 때 일부 행만 적재하는 방식으로 검사를 완화하지 않았습니다.

실행 방법
1. DATAIKU_GOLD_VECTOR_FAST_20261104_R2.zip을 Dataiku LEGAL_RAG의 관리 폴더
   ehA8dpVm에 이름 그대로 업로드합니다. ZIP을 직접 풀지 않습니다.
2. DATAIKU_GOLD_VECTOR_FAST_RUN_R2.txt 전체를 기존 Python 노트북의 새 셀에
   붙여 실행합니다. ACTION="vector"를 사용합니다.
3. OLD_JOB_DIR은 이전에 직접 입력했다면 같은 값을 넣고, 빈 문자열로 사용했다면
   그대로 둡니다. 임베딩 모델/차원도 기존 실행과 같게 유지합니다.
   기본 모델 openai:genos-embedding:embedding-kure-v1 / 차원 1024입니다.
   원문 적재 셀이나 다른 벡터 셀과 동시에 실행하지 않습니다.
4. 실행문 첫 줄에서 실제 Python 버전과 실행파일 위치를 확인할 수 있습니다.
   R1 작업을 이어 쓰면 VECTOR_PYTHON_COMPAT_RESUMED와 백업 위치가 표시됩니다.
5. 완료 표시는 VECTORS_STORED_INSERT_ACK_NOT_ACTIVATED입니다.
   로그는 기존 노트북 폴더/gold-progress-logs에 남습니다.

기존 작업을 이어 쓰는 방법
사진의 호출 경로는 임베딩 응답을 캐시에 저장한 뒤 DB행을 조립하는 위치입니다.
정상 보존된 캐시는 R2가 재사용합니다. 현장 캐시 내용 자체는 여기서 읽지 못했습니다.
state.json, embed-*.json, vectors-fast-r1 폴더를 지우거나 초기화하지 않습니다.
R2도 같은 vectors-fast-r1/<게시ID> 폴더와 동일 게시ID를 사용합니다.

정확한 R1 코드 binding과 일치하고, 나머지 원문/DB/모델/차원/표/파일 정보가
모두 동일할 때만 기존 잠금 안에서 코드 binding을 R2로 이행합니다.
변경 전 state는 state-before-python-compat-<R1코드해시>.json으로 보존합니다.
최초 deadline, 호출수, 한도, 완료행, 커서, DB 미확정 상태, 임베딩 미확정 상태,
과거 오류는 유지합니다. 모델 결과 불명 상태를 재전송으로 우회하지 않습니다.
다른 코드/원문/설정 또는 기존 백업 충돌은 구체 오류를 남기고 중단합니다.
R2로 진행한 뒤 과거 state를 덮어쓰거나 구 R1 실행문으로 되돌리지 않습니다.
R1 파일과 이행 전 백업은 조사·복구 판단용으로 보존됩니다.

변경 범위
제품 코드 변경은 vector_stage.py 하나이며 재개 부모 명세 파일 하나를 추가했습니다.
임베딩 SDK 어댑터, SQL, 16구간 임베딩/128행 적재, 원문·검색 적재와 모델 설정은
기존과 동일합니다. 완료 표시는 INSERT 응답 기준이며 전수 되읽기 완료가 아닙니다.
이 작업으로 VCTR_HEAD나 GENOS 서비스 선택을 전환하지 않습니다.
