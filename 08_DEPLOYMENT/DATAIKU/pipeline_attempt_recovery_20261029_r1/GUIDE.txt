R10 Dataiku 계산 시도 한도 복구 — 2026-10-29 R1

이번 사진의 오류: COMPUTE_ATTEMPT_BUDGET_EXHAUSTED
Dataiku checkpoint_upgrade.py의 기존 작업 시도 한도 검사에서 종료됐다.
기본 최대 3회에는 코드 수정본으로 전환한 시도도 포함된다.
이 경로는 GENOS OPEN/RUN 이전이다. 같은 오류에서 바로 다시 RUN해도 해결되지 않는다.
사진에는 실제 attempt_count가 없어 아래 조회로 확인한다. 손상된 횟수도 같은 오류를 낼 수 있으므로 3회로 단정해 값을 덮어쓰지 않는다.

변경 범위
- GENOS는 이미 배포한 R10 그대로 사용한다. 이번 ZIP은 Dataiku 클라이언트만 포함한다.
- 1코어/16GB, fulltext worker 1 그대로다. 추가 성능 최적화나 1시간 완료 보장이 아니다.
- 기존 작업명/입력/DB/서비스 연결/원래 기한/SQL·HTTP 누적 사용량을 유지한다.
- 확인된 R7/R8/R9 FAILED/CANCELLED, 정확히 3회, 유효한 원래 기한, 반환 결과가 없는 상태에만 추가 1회를 허용한다.
- 허용 기록은 원래 checkpoint 해시에 연결한다. 02를 시작하면 누적 횟수는 4가 된다.
- 허용 파일 작성만으로 계산은 시작되지 않는다. 같은 허용 명령을 반복해도 추가 허용 횟수는 늘지 않는다.
- 일반 retry의 3회 차단은 유지한다. 네 번째 계산 후 자동 다섯 번째 재시도는 허용하지 않는다.
- 원문과 01 결과는 재사용한다. 02는 처음부터 재계산하며 과거 added/색인 중간부터 이어지지 않는다.

실행 순서
1. 02가 종료된 상태에서 실행한다. 같은 작업의 시나리오/레시피를 동시에 돌리지 않는다.
2. 바깥 DATAIKU_R10_ATTEMPT_RECOVERY_20261029_R1.zip을 PC에서 압축 해제한다.
   안쪽 DATAIKU_R10_RECOVERY_CLIENT_20261029_R1.zip은 압축 해제하지 않고
   LEGAL_RAG의 ehA8dpVm 관리 폴더 루트에 업로드한다.
3. LEGAL_RAG의 새 Python 노트북 셀에 DATAIKU_RECOVERY_INSTALL.txt 전체를 붙여 실행한다.
   기본 ACTION='apply'. 기존 00/02/03 레시피를 확인·백업·교체한다.
   R10_RECOVERY_CLIENT_READY 출력이 필요하다.
4. 새 셀에 DATAIKU_ONE_ATTEMPT.txt 전체를 붙여 기본 ACTION='inspect'로 실행한다.
   ONE_ATTEMPT_SUMMARY_BEGIN/END 사이 요약을 확인한다.
   attempt_count=3, saved_phase=FAILED 또는 CANCELLED,
   deadline_seconds_remaining>0, result_saved=false가 대상이다.
   값이 다르거나 오류가 나오면 출력 요약을 공유한다. 작업명·횟수·기한은 임의로 바꾸지 않는다.
5. 위 조건을 확인하고 추가 계산 1회를 실행하려면 같은 셀 맨 위 두 줄을 다음처럼 바꾼다.
   ACTION = 'authorize_one_attempt'
   CONFIRMATION = 'AUTHORIZE_ONE_ADDITIONAL_COMPUTE_ATTEMPT'
   전체 셀을 다시 실행한다. 이것이 추가 1회에 대한 운영자 명시적 허용이다.
   현재 GENOS R10 HEALTH와 입력/대상/상태를 확인한 뒤 허용 파일만 Dataiku에 저장한다.
   additional_attempt_authorized=true, compute_started=false가 출력돼야 한다.
6. Flow에서 LEGAL_00_CHECK_GENOS_R1 → LEGAL_02_STRUCTURE_GENOS_R1 순서로 실행한다.
   02 성공 후 LEGAL_03_LOAD_SILVER_R1을 실행한다. 기존 01을 다시 돌릴 필요는 없다.
   재실행해도 추가 허용은 정확히 한 번만 소비한다.

한도와 상태 오류
- ORIGINAL_DEADLINE_EXHAUSTED: 원래 기한 만료. 이 도구는 기한을 늘리지 않는다.
- RECOVERY_REQUIRES_EXACTLY_THREE_PRIOR_ATTEMPTS: 현재 횟수가 3이 아니다.
- RECOVERY_REQUIRES_CONFIRMED_TERMINAL: 종료 상태/핸들이 확인되지 않았다.
- RECOVERY_RETURN_EXISTS_PRESERVE_RESULT: 기존 결과가 있어 덮어쓰기 경로를 차단했다.
- RECOVERY_INPUT_TARGET_OR_CODE_CHANGED: 원문/DB/연결/코드 조건이 다르다.
- RECOVERY_GRANT_CHANGED: 허용 파일의 결속 값이 다르다.
어떤 경우에도 기존 checkpoint를 삭제하거나 job 이름을 바꿔 한도를 초기화하지 않는다.

롤백
02를 중지하고 DATAIKU_RECOVERY_INSTALL.txt의 ACTION을 'rollback'으로 실행한다.
설치 전 레시피 원문을 복원한다. 이미 시작한 계산을 취소하거나 사용 횟수를 되돌리지는 않는다.
허용 파일·실패 로그·checkpoint는 감사 기록으로 남는다.
