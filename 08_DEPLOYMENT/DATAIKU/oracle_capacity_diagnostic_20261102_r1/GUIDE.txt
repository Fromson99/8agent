Oracle 용량 확인 R1 — 2026-11-02

목적
현재 중단된 SIDDS.LGL_SRCH_ROW_S 적재와 관련해 계정 Quota,
테이블스페이스 여유/확장 설정, 해당 테이블·인덱스·LOB 할당량을 확인합니다.
이 첨부는 읽기 전용 용량 진단입니다. Gold R19 적재기 변경본은 아닙니다.

첨부 3개
1. ORACLE_CAPACITY_CHECK_20261102_R1.zip
   실제 SQL 원본 01_CHECK_ORACLE_CAPACITY.sql 한 개가 들어 있습니다.
2. 01_CHECK_ORACLE_CAPACITY.txt
   ZIP 안 SQL과 바이트가 같은 전체 실행문입니다. 복사할 때 이 파일을 사용합니다.
3. GUIDE.txt
   이 실행 안내입니다.

실행 환경과 위치
- 프로젝트: 기존 적재를 실행한 Dataiku LEGAL_RAG.
- 노트북 종류: SQL 노트북. 기존 Python/Jupyter 셀에 SQL을 그대로 넣지 않습니다.
- 연결: 기존 적재와 같은 AIDP.
- 대상: Oracle SIDDS.LGL_SRCH_ROW_S.
- 실행문은 노트북에 붙여 넣으므로 서버 작업 디렉터리나 경로 설정이 없습니다.
- 관리 폴더 ehA8dpVm에 ZIP을 업로드할 필요가 없습니다.
- ZIP은 SQL 원본 전달용입니다. PC에서 열거나 압축을 풀어 SQL을 확인할 수 있습니다.
- 별도 비밀번호·토큰을 코드에 넣지 않습니다. Dataiku의 기존 연결을 사용합니다.

실행 순서
1. AIDP 연결의 SQL 노트북을 엽니다.
2. 01_CHECK_ORACLE_CAPACITY.txt를 열고 Q1의 SELECT부터 세미콜론까지
   첫 SQL 셀에 복사해 실행합니다.
3. Q2, Q3, Q4도 각각 하나씩 별도 SQL 셀에서 실행합니다.
   파일 전체를 한 셀에 한꺼번에 붙이지 않습니다.
4. Q1~Q4의 결과 또는 오류 코드를 캡처합니다.
   정상 결과는 Q1 1행, Q2/Q3 보통 0~1행, Q4 최대5행입니다.
5. Q2 조회 권한이 없고 Q1의 CONNECTED_AS가 정확히 SIDDS일 때만
   보조 Q5/Q6를 별도 셀에서 실행합니다.

각 결과의 뜻
Q1
- CONNECTED_AS: 실제 접속 계정. AIDP라는 연결 이름과 다를 수 있습니다.
- SCHEMA_AS: 현재 기본 스키마. SIDDS로 표시돼도 접속 계정은 다를 수 있습니다.
- TABLESPACE_NAME: 대상 테이블 본체가 있는 테이블스페이스.
- TABLE_NAME이 NULL이면 현재 연결에서 대상을 확인하지 못한 것입니다.

Q2 / Q5
- CHARGED_GIB: 해당 계정이 해당 테이블스페이스에서 사용하도록 할당된 용량.
  테이블 한 개만의 크기가 아닙니다.
- QUOTA_GIB: 등록된 계정 한도. -1이면 등록 Quota 무제한입니다.
  실제 tablespace/디스크 공간도 무제한이라는 뜻은 아닙니다.
- 0행은 용량0 또는 무제한을 증명하지 않습니다.
  UNLIMITED TABLESPACE 권한의 존재도 별도로 확인해야 합니다.
- 다른 계정의 USER_TS_QUOTAS 결과를 SIDDS 사용량으로 해석하지 않습니다.

Q3
- FILE_GIB: 현재 테이블스페이스 데이터파일 크기의 합계.
- FREE_GIB: 현재 파일 안의 미할당 extent 여유 공간 합계.
- AUTO_GROW_LIMIT_GIB: 자동 확장 설정상 더 늘릴 수 있는 양.
  실제 스토리지 여유·확장 성공을 보장하지 않습니다.
- MAX_FREE_EXTENT_MIB: 현재 가장 큰 미할당 extent 크기(MiB).
- AUTO_FILES: 자동 확장이 켜진 파일 개수.
- NOT_ONLINE_FILES: 온라인 상태가 아닌 파일 개수. 0보다 크면 DBA 확인이 필요합니다.
- 공간은 이 테이블스페이스의 다른 객체도 함께 사용합니다.

Q4
- 이 테이블에 직접 연결된 본체·인덱스·LOB의 물리 할당량입니다.
- TABLESPACE_NAME/SEGMENT_TYPE별 큰 순서 상위5개 그룹만 출력합니다.
- 저장 원문의 순수 크기, SIDDS 전체 사용량, 반환 가능한 공간과는 다릅니다.
- 이 대상의 현재 일반 테이블 구조를 기준으로 한 진단입니다.
  Q1에서 파티션 등 다른 구조가 보이면 추가 확인이 필요합니다.

권한 오류 / 중단
- ORA-00942 또는 ORA-01031이면 해당 DBA 관리 뷰 조회 권한을 확인해야 합니다.
  용량0이라는 뜻이 아닙니다. 오류 코드만 캡처해도 됩니다.
- Q3/Q4가 막히면 DBA에게 동일 SQL을 전달해 조회를 요청합니다.
- 쿼리가 오래 대기하면 해당 SQL 실행을 취소하고 어느 Q였는지 기록합니다.
- 모두 SELECT이므로 진단에는 재개 지점이 없습니다. 필요하면 개별 Q만 다시 조회합니다.
- 기존 R11/R12 적재·후속 임베딩 셀, Run All, 커널 재시작은 이 진단에 필요 없습니다.
- 임의의 DELETE/TRUNCATE/ALTER/재적재를 실행하지 않습니다.

판정 범위
이 SQL은 수천만 행의 COUNT, 원문 JSON/CLOB 읽기, 적재/모델 호출 없이
Oracle 관리 정보만 조회합니다. 저장공간 전체를 자동 진단·수정하지는 않습니다.
Q1~Q4 결과와 실패 당시 ORA-01653의 전체 테이블/테이블스페이스 이름을 함께
대조해야 원인을 좁힐 수 있습니다. 실제 물리 디스크 여유는 DBA 확인 대상입니다.
로컬에서는 Oracle 문법 기준 정적 파싱과 읽기 전용 SELECT6개 구성을 점검했습니다.
현장 Oracle 실행·권한·실제 용량 결과는 아직 확인하지 않았습니다.
