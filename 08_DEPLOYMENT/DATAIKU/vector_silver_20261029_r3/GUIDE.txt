                lease(적재 잠금), active_revision(현재 활성 게시본의 변경 순번)

4. 이전 R1/R2와 이관
- 이번 파일의 SET/ITEM 두 테이블만 새로 생성한다.
  이전 PBLS/SEG/ACT 테이블 및 그 데이터는 자동 변경·삭제·이관하지 않는다.
  기존 원문 실버 테이블도 변경하지 않는다.
- 사용자는 원문 테이블 이관 후 벡터를 적재할 예정이므로 이번 R3 SQL을 사용하면 된다.
  이미 R2에 벡터를 적재했다면 기존 행은 R3에서 자동 재사용되지 않는다.
  기존 Dataiku 작업 기록·호출 예산은 이어받지만 새 테이블에는 다시 적재한다.
  기존 벡터를 그대로 옮기는 별도 데이터 이관은 이번 구현에 포함하지 않는다.
- 이전 벡터 Flow와 새 Flow를 동시에 실행하지 않는다.
  새 R4 결과 폴더는 기존 R3/R2/R1 중 연결된 이전 폴더의 해당 작업 기록을 읽는다.
  작업 식별값·원문·프로필이 같아야 하며 기존 호출 예산과 최초 기한을 초기화하지 않는다.
- 복귀는 이전 GENOS 코드 리비전과 보존된 R2 테이블을 함께 사용한다.
  새 R3만 사용했다면 벡터 검색을 off로 설정해 기존 원문 검색 경로로 복귀할 수 있다.

5. 실패·재개와 동시 실행
- 정상 종료와 일반 실패에는 현재 lease만 해제한다. 기존 성공 행은 남겨 재개 때 검증·재사용한다.
- 프로세스가 강제 종료되어 lease가 남으면 다른 작업이 임의로 가져가지 않는다.
  Dataiku에서 이전 작업이 종료되었음을 확인한 뒤 정확한 PUB_ID/기존 lease를 기록하고
  아래 조건부 SQL로 해제한 다음 같은 Flow를 재개한다. 임의 자동 만료/잠금 탈취는 없다.
  UPDATE SIDDS.LGL_VCTR_SET_S
   SET PAYLOAD_JSON=JSON_MERGEPATCH(PAYLOAD_JSON,'{"lease":null}' RETURNING CLOB ERROR ON ERROR)
   WHERE PUB_ID=:pub_id
     AND JSON_VALUE(PAYLOAD_JSON,'$.status')='BUILDING'
     AND JSON_VALUE(PAYLOAD_JSON,'$.lease')=:confirmed_stopped_lease;
  COMMIT;
- 전량 건수·기존 행의 원문 메타·차원/형식이 일치한 뒤 READY로 바꾼다.
  BUILDING은 활성 검색 대상이 아니며 검색 시에도 거절한다.
- 활성 교체 시 이전 PUB_ID와 revision을 확인하고, 짧은 DB 트랜잭션 안에서
  SET 테이블을 NOWAIT 잠금해 이전 활성 해제/새 활성 선택을 원자적으로 처리한다.
  모델 계산 동안 이 잠금을 보유하지 않는다. 경합하면 즉시 실패·상태 보존한다.
  Dataiku에서 현 상태를 확인한 뒤 재개하면 READY 데이터는 재임베딩하지 않는다.
- 같은 원문 조회 릴리스에 활성 게시본이 두 개 생기지 않도록 유일 함수 색인이 제한한다.
  A→B→A 전환도 revision이 증가하여 오래된 교체 요청이 덮어쓰지 못한다.
- 스키마·모델/원문 해시·권한 불일치는 자동 보정하지 않는다.
  부분 성공/실패/사용한 호출 수와 SQL 영수증은 Dataiku 관리 폴더에 보존한다.
  임베딩 최대 20,000회·SQL 1,000,000회·최초 7일 기한은 재개해도 유지한다.

6. 성능·검증·신청 범위
- 배치 16개, 렌더링된 SQL 블록 60,000 UTF-8바이트 이내 묶음 INSERT 유지.
  원격 반복 행 SELECT 대신 묶음 기존 행 검사. 문서·원문 JSON 속성에 함수 색인 적용.
- 컬럼 수 감소는 물리 속성을 JSON으로 통합한 결과이며 검색 지연이나 저장 크기의
  동일 비율 감소를 뜻하지 않는다. JSON 추출 비용과 게시 전환 잠금 비용이 있다.
  실제 GENOS 임베딩/JDBC/ORDS/네트워크/Oracle 검색 지연은 현장에서 측정해야 한다.
- 로컬 Oracle native VECTOR, 적재/검색/권한/재개/잠금/동시 교체,
  Dataiku 레시피 진입점·공개 SDK·GENOS QuerySQL 소비자와 설치기를 검사한다.
  테스트 임베딩은 고정 합성 배열이고 실제 내부 모델 호출은 없다.
  최종 숫자는 VALIDATION.json과 TEST_RESULTS_final.xml을 따른다.
- SQL·XLSX의 명칭/설명은 운영 Gold 등록 후보다. 표준단어·용어·도메인·인포타입,
  JSON/VECTOR 타입 허용·관리부서·보유기간·메타 등록·DBA 승인은 미완료다.
  JSON 내 필수 속성은 없어지지 않는다. 운영에서 개별 표준 컬럼을 요구하면 추가 분리할 수 있다.
- 실제 현장 Dataiku/GENOS 설치·DB 적재·Gold 등록·MAIN 승격은 이번 로컬 검증과 별도다.
