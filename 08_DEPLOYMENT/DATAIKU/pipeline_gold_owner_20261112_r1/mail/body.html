수신 파이프라인 R7 · 증분 실험 표/권한 · Gold 메타 등록 R20 (2026-11-12)

현장 설치·실행 전 자료입니다. 로컬 Oracle에서만 검증했습니다. 자세한 순서는 첨부 8 GUIDE.txt.

1. 증분 실험 표 — 개발계 SIDDS (첨부 1~6)

  • 만들 표: SIDDS.TST_B003_LGL_* 13개 (운영 Gold와 같은 정의, 이름 앞부분만 TST_) + PK 13 · 추가 인덱스 11 = SQL 24문장 (첨부 2). 데이터 복사 없음, 지금 서빙 중인 Gold(IDD_B003)는 그대로.
  • 필요한 권한 (첨부 1에 정리, GRANT SQL 첨부 3):
    • 표 만들기: SIDDS 소유자(또는 DBA)가 첨부 2 실행 권장. Dataiku 계정이 직접 만들려면 CREATE ANY TABLE · CREATE ANY INDEX. 공간 약 1GB 이내(추정).
    • Dataiku 계정 PIDD2APP: 시험 복사본 13표 SELECT, INSERT, UPDATE, DELETE
    • SIDDA.LGL_PIPE_RESULT_A: PIDD2APP DELETE 추가 (SELECT는 있음)
    • GENOS ORDS 계정(BAIP04APP): 변경 없음
  • Agent 표는 새로 만들 필요 없음 — 이미 있는 SIDDA.LGL_PIPE_RESULT_A를 그대로 씁니다. GENOS는 이 표에만 결과를 쓰고(코드 고정), 증분은 자기 작업 번호 행만 지웁니다. 필요한 건 위 DELETE 권한 하나.
  • 순서: 첨부 2(만들기) → 3(권한) → 4(확인: Q02 18행, Q03~Q05 0행) → GUIDE 3장 실험 → 5(main 채널) → 증분 셀 → 끝나면 6(지우기).

2. 운영 Gold 메타 등록 엑셀 R20 (첨부 7)

  • 10-30 R19 최종 신청 형식 그대로 + 이전 규칙의 활용테이블목록 · Bizmeta · 메타등록대상 · 표준용어/도메인 시트 추가.
  • R19 대비: 표·인덱스 IDD_B03_→IDD_B003_, 컬럼명 5곳(RGSN_ASTM, RFRN_DTA_HASH_VALU, RFRN_DTA_CTNT, CHAN_NO×3), 규정문서ID 50→100, 본문단위ID 50→100, 부가정보미지정여부 CHAR(1)→VARCHAR2(1). 데이터 값이 바뀌는 변경 없음.
  • 확인: 13표 60컬럼·PK·인덱스 11개가 운영 적재기 정의와 차이 0, 한글 속성명 60개가 11-04 신청 작업함 화면과 모두 같음.
  • 신청 전에 정할 것 2개(19 시트): 등록일시 타입(작업함 TIMESTAMP·기본값 없음 / R20 TIMESTAMP(6) WITH TIME ZONE·SYSTIMESTAMP, 둘 다 동작), 작업함 인덱스의 LOCAL 표시(비파티션 표에는 불가).

3. 수신 파이프라인 R7 — Gold 소유자를 변수로 (첨부 9~12)

  • S3 원문 ZIP → GENOS 구조화·색인 → SIDDA.LGL_PIPE_RESULT_A → Dataiku 03_LOAD → Gold. 임베딩은 Dataiku 그대로.
  • Dataiku 프로젝트 변수 LGL_GOLD_OWNER = 개발계 SIDDS / 운영 SIDDG (필수, 03_LOAD 실행 때마다 읽음). 시험 복사본 실험 때만 LGL_GOLD_TABLE_PREFIX=TST_B003_LGL_.
  • 코드서빙은 기존 환경변수 GENOS_ORACLE_GOLD_OWNER(SIDDS/SIDDG) 그대로. GENOS 파이프라인 코드는 R6 그대로라 재배포 없음.
  • 설치: 코드 폴더에 첨부 9 업로드 → Python 노트북에 첨부 10 한 셀. 증분은 첨부 11 업로드 → 첨부 12 셀.

4. 표 확인·그 밖 SQL (첨부 13~19)

  • 13 CHECK_TABLES_SIDDS / 14 CHECK_TABLES_SIDDG: 파이프라인 표 18개 확인(읽기 전용)
  • 15 MAIN_CHANNEL_SIDDS: 실제 개발계 Gold에 증분을 붙일 때 main 채널 · 16 GRANT_GOLD_INCREMENT_SIDDS: 그때 필요한 권한(지금은 불필요)
