한 문서 PDF 변환 + GENOS 파싱 테스트 (R4 코드 사용)

1. GENOS에서 실제 TRANSFER 위치로 이동해 이번 ZIP을 전용 폴더에 풉니다.
   python3 -m zipfile -e GENOS_ONE_DOCUMENT_TEST_20261028_R1.zip one-test
   cd one-test

2. 테스트할 문서 한 개를 이 Pod에서 읽을 수 있는 위치에 올립니다.
   DOC/DOCX/HWP/HWPX/PPT/PPTX 입력이면 PDF 변환 후 파싱합니다.
   PDF 입력이면 변환은 건너뛰고 파싱만 확인하므로, 둘 다 보려면 DOCX 같은 원문을 넣으세요.

3. 아래 두 경로만 실제 경로로 바꿔 실행합니다(공백/한글 이름은 따옴표 유지).
   bash GENOS_ONE_DOCUMENT_TEST.txt "/실제/경로/문서.docx" --config "/실제/경로/agent8_pod_parser.yaml"

   GENOS_STRUCTURE_CONFIG가 이미 설정되어 있으면:
   bash GENOS_ONE_DOCUMENT_TEST.txt "/실제/경로/문서.docx"

이번 ZIP에 정확한 R4 계산 코드가 들어 있습니다. 별도 임시 경로에 풀어 실행하며 ~/DEV 반영, Git commit/push, 전체 Flow 배포가 필요하지 않습니다.
이미 설치된 R4 ~/DEV를 직접 확인하려면 선택적으로 --code-root "$HOME/DEV"를 추가합니다. R4 전체 파일 해시가 맞아야 실행합니다.

환경 준비
- 실행할 Python은 3.11 이상, GENOS parser fork/호환 의존성과 PDF 변환기(PDF SDK/rhwp/LibreOffice)가 준비된 Pod여야 합니다.
- parser YAML은 현장의 GENOS layout/OCR/table 연결이 설정되어 있어야 합니다. enrichment: [], output.format: docling이 필요합니다.
- 기존 설정에서 새 전용 YAML을 만드는 명령은 이전 R4의 prepare_pod_config.py를 사용합니다. 원본 YAML을 덮어쓰지 않습니다.
- 이 테스트는 설치 도구가 아닙니다. 필요한 패키지/모델을 인터넷에서 자동 다운로드하지 않습니다.
- 실제 parsing 과정에서 YAML에 설정된 GENOS layout/OCR/table 모델이 호출될 수 있습니다. 이후의 RAG 구조 검수·색인·DB 적재·전체 Dataiku Flow는 실행하지 않습니다.
- 코드스페이스에서 실행했다면 그 코드스페이스의 결과입니다. 운영 코드서빙 리비전 성공으로 간주하지 마세요. 확인할 Pod와 같은 이미지/Python/YAML에서 실행하세요.

결과 확인
현재 폴더 아래 pod-one-날짜-시각-고유값/ 폴더가 생깁니다. 시작 시 RESULT_DIR로 표시합니다.
  result.pdf           실제 변환 PDF(입력이 PDF면 검증 후 복사)
  parsed.txt           파싱된 전체 텍스트
  parsed.docling.json  구조/표/페이지를 포함한 파싱 JSON
  summary.json         PDF 변환과 파싱의 단계별 성공/실패, 원문·PDF·코드 해시
  test.log             자세한 실행/오류 로그
  report.zip           위 결과와 변환/파싱 receipt 모음

성공 표시: STATUS=PASS / PDF_CONVERSION=PASS / PARSING=PASS
기존 PDF 입력: PDF_CONVERSION=SKIPPED_ALREADY_PDF (변환 검증은 수행하지 않음)
변환 PASS + 파싱 FAILED이면 result.pdf를 열어 변환 결과를 볼 수 있습니다. summary.json과 test.log로 파싱 오류를 확인하세요.
진행 중에는 다른 터미널에서 tail -f "RESULT_DIR에 표시된 경로/test.log"로 볼 수 있습니다.
원본 파일은 수정하지 않고, 새 결과 폴더와 임시 계산 사본만 사용합니다. report.zip에는 입력 DOC/HWP 원문이나 전체 R4 코드를 중복 포함하지 않습니다.

기본 총 제한 30분, 자동 재시도 없음. Ctrl+C는 이번 테스트 프로세스와 그 자식만 종료합니다.
필요하면 --timeout-seconds 3600 추가(최대7200초). 중단/실패 시 이미 생성된 PDF와 진단을 보존합니다.
일반 테스트 스크립트이며 실제 현장 문서 성공/파싱 품질/전체1657건 성공은 아직 확인하지 않았습니다.
