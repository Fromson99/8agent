결과의 범위
- 테이블: 본체+일반 인덱스+LOB 데이터/인덱스 물리 할당 GiB. 현재 확보한 공간이지 순수 본문/회수 가능량이 아니다.
- 한도: SIDDS/SIDDA 소유자가 해당 tablespace에서 쓰는 전체 할당량과 등록 quota.
  기존 표도 포함되며, 접속 계정 PIDD2APP의 USER_SEGMENTS/USER_TS_QUOTAS로 대신하지 않는다.
- 여유: 공유 tablespace의 현재 파일/미할당 extent/자동확장 설정. 사용자의 독점 공간이나 실제 디스크 여유가 아니다.
- 자료: 이미 저장한 R3의 검색 계획과 앞쪽 SQLite JSON 표본을 읽는다. 새 원문 스캔/INSERT를 하지 않는다.
  원본 SQLite JSON은 최종 Oracle 행의 전체 크기가 아니다. 32행 prefix와 FTS 편향이 있고
  일부 종류는 미측정이므로 전체/최소/최대 예상 GB로 제시하지 않는다.
  전체 보고서의 partial_source_json_bytes도 측정된 종류의 단순 외삽 참고값이며 Oracle 총량이 아니다.
  BLOB 내용이 숫자 길이로 대체된 표본, 중복 표본, 변경 감지 표본은 외삽에서 제외한다.
- STATS_ROWS/AVG_ROW_LEN은 과거 통계다. 오래되거나 LOB/인덱스를 빠뜨릴 수 있어 최종 용량으로 환산하지 않는다.
- 파티션/IOT/클러스터는 이 확인기의 완전한 용량 계산 대상이 아니다. 별도 진단 필요로 표시한다.

권한이 막히면
앞서 DBA_SEGMENTS/DBA_TS_QUOTAS 조회 권한이 없었다는 기록이 있다.
이번에도 ORA-00942/ORA-01031이면 해당 항목은 미확인으로 표시하고 가능한 다른 항목만 진행한다.
권한 우회로 정확한 물리 용량을 알아내는 기능은 없다. 02_DBA_CAPACITY_SELECT.sql을 DBA에 전달해
Q3(테이블), Q4(계정 quota), Q5(공유 공간)를 조회받아야 한다.
USER_FREE_SPACE 보조 결과는 현재 접속자에게 보이는 공간뿐이며 SIDDS quota를 대체하지 않는다.
DBA가 추가로 소유자에게 직접/역할로 부여된 UNLIMITED TABLESPACE 권한을 확인해야 한다.

전체 최종 용량 산정에 남은 것
이번 셀은 현재 할당/한도/여유를 확인한다. 최종 GB를 임의 배수로 만들지 않는다.
전체 필요한 용량은 원문+종류별 검색행+PK/보조인덱스+LOB+벡터/메타데이터를 합산한다.
대표성 있는 종류별 표본과 실제 저장 형태/세그먼트 비용으로 추정하고, 벡터 예정 개수/저장 타입을 포함한다.
기존 표를 보존할 경우 기존 할당량, 적재 중 임시 공간, 유지할 과거 판본/증가 여유는 구분해 추가한다.
부분 적재의 현재 할당량을 현재 통계 행 수로 나눠 전체 6천만 행에 일괄 곱하지 않는다.

결과 파일
노트북 작업 폴더/gold-capacity-reports/<시각-고유값>/CAPACITY_REPORT.json
동일 폴더 TABLE_CAPACITY.csv (Excel용 UTF-8 BOM).
원문/전체 SQL/인증 정보는 보고서에 저장하지 않는다. 새 진단 파일만 생성한다.
R3가 같은 커널에 있으면 _g19_observer.REPORT를 복사해 사용한다. 원본 보고서는 변경하지 않는다.
커널이 바뀌었다면 TXT 상단 CAPACITY_REPORT_PATH에 기존 REPORT.json의 정확한 경로를 지정할 수 있다.
사진에는 gold-bottleneck-reports/20261103-085804-d7470704/REPORT.json이 표시됐다.
자동으로 최신 파일을 선택하지 않는다. R3 보고서가 없어도 Oracle 메타 조회는 진행할 수 있다.

중단
모두 순차 SELECT이며 대형 COUNT/본문 스캔/INSERT/DDL/임베딩은 없다.
한 조회가 오래 대기하면 노트북에서 중단한다. 완료한 결과를 저장하며 자동 재시도하지 않는다.
클라이언트 중단만으로 원격 SELECT 취소를 보장하지 않는다. 종료 확인 후 필요한 경우만 재실행한다.
