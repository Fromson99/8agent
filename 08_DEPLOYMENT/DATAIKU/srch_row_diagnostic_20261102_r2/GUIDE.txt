SRCH_ROW 행 수 진단 R2 — 한 화면 캡처용 / 2026-11-02

사용할 첨부
1. SRCH_ROW_DIAGNOSTIC_RUN_R2.txt: 전체 실행 코드. 이전 FIELD_PLANNED_ROWS_READONLY.txt 대신 사용.
2. SRCH_ROW_DIAGNOSTIC_20261102_R2.zip: 동일 코드 diagnostic.py와 코드 해시 MANIFEST.json.
3. GUIDE.txt: 이 안내문.
ZIP 안에 다른 ZIP은 없다. 배치 확대/재적재 실행 파일은 포함하지 않는다.

대상과 실행
Dataiku 프로젝트 LEGAL_RAG에서 기존 _1 적재를 실행했던 Python/Jupyter 노트북을 연다.
사진 기준 aidptest's Python notebook_13이며 기존 준비 파일을 읽을 수 있는 같은 환경을 사용한다.
새 Python 셀 하나에 SRCH_ROW_DIAGNOSTIC_RUN_R2.txt 내용을 처음부터 끝까지 복사한다.
OLD_JOB_DIR = ''는 기존 적재의 기본 임시 경로를 사용한다.
기존 적재에서 OLD_JOB_DIR을 직접 지정했다면 진단 셀에도 정확히 같은 값을 입력한다.
작업 디렉터리 변경, pip 설치, DB 접속 정보, 관리 폴더 업로드는 필요 없다.
Shift+Enter로 이 진단 셀만 한 번 실행한다. 적재 셀은 재실행하지 않는다.
TXT를 열 수 없는 경우 ZIP의 diagnostic.py가 동일 코드다. 해당 내용을 새 셀에 복사할 수 있다.

기본 입력 경로
Python tempfile.gettempdir() 아래
legal-existing-nfs-20261029-r1/financial-risk-success-20261005-schema-r2/oracle-import-r2/
projection-descriptor-r7.json
현장의 실제 tempfile 경로를 임의로 /tmp 등으로 고정하지 않는다.

캡처
SRCH_ROW 행 수 진단 R2 제목부터 아래 짧은 해시/안내까지 보이는 요약 카드 한 장만 캡처한다.
전체 예정/제외 검토/가정 잔여, 후보 3개, 큰 항목 5개만 표시하며 진행 로그를 계속 출력하지 않는다.
오류도 짧은 카드 하나로 표시한다. 미발견과 0행은 구분한다.
브라우저 확대율이나 노트북 폭에 따라 화면 높이가 달라질 수 있다.
전체 목록은 SRCH_ROW_DIAG_R2_REPORT 변수에 남기며 기본 화면에 펼치지 않는다.
해당 변수를 별도 셀 마지막 줄에 입력하면 긴 목록이 출력되므로 캡처용으로는 입력하지 않는다.

결과 해석
완료 표시는 저장된 준비 명세의 checksum·형식 검사와 집계가 끝났다는 뜻이다.
현장의 현재 입력 파일 전체 재검증이나 Oracle 실제 저장 행 수·용량 검증을 뜻하지 않는다.
제외 후보 합계는 실제 삭제량이 아니다. 검색 소비자 확인 및 별도 축소 구현이 필요하다.
큰 항목 5개는 후보 3개와 중복될 수 있어 두 표의 숫자를 합산하면 안 된다.

중단·재실행
입력 JSON 한 개(최대 32MiB)만 읽고 원본/상태/DB에 쓰지 않는다.
중단했거나 입력 경로를 바로잡은 경우 이 진단 셀만 다시 실행할 수 있다.
이전 출력은 같은 셀에서 교체된다. 적재 재개·수리·state 삭제는 하지 않는다.
이번 파일은 배치 조정 R2와 다른 진단 전용 R2다.
