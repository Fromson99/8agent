Agent 기록 테이블 이름 통일 — _A / 2026-11-05 R1

1. Dataiku에서 한 번에 생성

SIDDA에 테이블을 생성할 수 있는 Oracle 연결의 SQL 노트북에서 새 Query를 엽니다.
AGENT_A_CREATE_ALL_R1.txt의 전체 내용을 그대로 한 번 붙여넣고 Run을 누릅니다.
동일 내용의 .sql 파일도 제공합니다. 두 파일을 모두 실행할 필요는 없습니다.
DECLARE부터 END;까지 하나의 Oracle PL/SQL 블록입니다. 끝에 /를 추가하지 않습니다.
내부 세미콜론으로 문장을 나누거나 SELECT로 감싸지 않습니다.

생성·검증 대상
  SIDDA.LGL_AGT_BODY_A : 4컬럼
  SIDDA.LGL_AGT_REC_A  : 8컬럼
  SIDDA.LGL_AGT_RUN_A  : 9컬럼
  SIDDA.LGL_EXEC_ST_A  : 5컬럼
  위 테이블의 기본키 4개와 조회 인덱스 7개

기존 테이블이 있으면 먼저 컬럼·타입·NULL·기본키를 비교합니다.
구조가 맞는 기존 객체는 재사용하며, 없는 테이블·인덱스만 생성합니다.
기존 구조가 다르면 AGENT_A_SCHEMA와 대상 이름/차이를 표시하며 중단합니다.
기존 인덱스도 대상 테이블·컬럼 순서·UTC 시간 표현·상태를 검증합니다.
마지막까지 성공하면 4테이블/26컬럼/7인덱스 검증을 통과한 것입니다.
DBMS_OUTPUT을 표시하는 도구에서는 AGENT_A_READY 문구가 나옵니다.
Dataiku에서 이 문구를 표시하지 않더라도 SQL 블록 자체의 성공/실패 상태를 확인합니다.

Oracle CREATE는 성공한 문장마다 커밋됩니다. 중간 오류 때 앞서 생성한 객체는 남습니다.
원인을 해결한 뒤 같은 블록을 다시 실행할 수 있습니다.
DROP/ALTER/TRUNCATE/GRANT나 기존 행 변경은 실행하지 않습니다.
권한이나 quota 오류는 해당 Oracle 연결에서 해결해야 하며 스크립트가 우회하지 않습니다.

2. 코드 매핑도 함께 반영

현재 로컬 MAIN157(agent-a-unified-20261105-r1)에 같은 이름을 반영했습니다.
GENOS 현장에는 MAIN157_FULL_20261105_R1.zip과 MAIN157_ONECLICK_R1.txt를 적용해야 합니다.
코드 반입·새 리비전 배포 방법은 해당 패키지의 GUIDE.txt를 따릅니다.
DP=oracle, GENOS_ORACLE_TABLE_MAPPING=gold, 실제 GENOS_ORACLE_GOLD_OWNER 설정을 유지합니다.
gold/development_g19_1/mapped/legacy 모두 Agent 기록은 위 _A 4개로 통일됩니다.
Gold 데이터 13테이블의 이름·컬럼은 유지하고, 개발계 원문·색인·온톨로지 이름도 유지합니다.
Gold JSON은 계속 13개만 포함하며, Agent 4개는 development_g19_1.json에서 합칩니다.
이 JSON과 로더는 코드서빙 패키지에 들어 있습니다. NFS 데이터 파일이 아닙니다.

기존 _A_1 테이블과 기록은 삭제하거나 자동 이관하지 않습니다.
새 매핑에서는 _A 테이블의 기록을 사용하므로, _A_1에만 있던 과거 대화는 자동으로 이어지지 않습니다.
기존 _A 기록이 있으면 그대로 보존합니다. 새 질문/새 요청 ID로 현장 동작을 확인합니다.
Dataiku에서 생성 성공과 GENOS ORDS 계정의 조회·저장 권한은 별도로 확인해야 합니다.

3. 검증 범위

전달 SQL과 동일한 블록을 로컬 Oracle 23.26.3의 임시 owner로만 치환해 실행했습니다.
신규 생성·재실행·기존 행/객체 보존·인덱스 재개·구조 이상 거절·원래 AgentRecords.preflight를 확인했습니다.
Dataiku 공식 문서는 SQL 노트북의 DDL/프로시저 실행과 Query 단위를 지원한다고 설명합니다.
https://doc.dataiku.com/dss/latest/notebooks/sql-notebook.html

제품 무결성 검사를 제거하지 않았고 새 모델 호출·현장 DB 변경·메일 발송은 없습니다.
