보내주신 Dataiku 화면의 첫 요청 TIMEOUT 원인을 구분하는 추가 셀을 보냅니다.

첫 법령 본문 요청이 시간 초과로 끝났고, 뒤의 BLOCKED 행은 기존 코드가 후속 호출을 생략한 표시입니다. 방화벽 차단이 확인됐다는 의미는 아니며, OC 오류나 법제처 데이터 부재도 아직 판단할 수 없습니다.

제가 보낸 R1은 연결 시간 초과와 응답 대기 시간 초과를 모두 TIMEOUT으로 기록했습니다. 이번 추가 셀은 같은 요청을 수동으로 1회 진단하고 예외 종류·실패 단계·프록시·실제 주소·소요 시간을 구분합니다. 기존 결과와 차단 상태를 보존하며 같은 셀을 다시 눌러도 재호출하지 않습니다.

지금 화면에서 실행
1. 커널을 재시작하지 마세요.
2. 첨부 CELL.txt를 열어 전체 복사.
3. 기존 Notebook의 In [7] 코드 상자 클릭 → 상단 Insert → Insert Cell Below.
4. 새 셀 유형을 Code로 선택 → 전체 붙여 넣기 → Shift+Enter.
5. 출력의 status / stage / exception_classes 확인.
6. 기존 8번 결과 저장 셀을 다시 실행하면 timeout_diag_r1.json도 Managed Folder에 저장됩니다.

이번 ZIP은 기존 R1 Notebook에 추가하는 진단 셀입니다. 기존 Notebook 전체를 교체하지 않습니다. TXT는 Python 코드이며 bash 실행 파일이 아닙니다. 세부 결과 해석과 담당자에게 전달할 문구는 GUIDE_UTF8.txt에 있습니다.

14개 검사와 동일 TXT의 로컬 HTTPS 요청 검증을 통과했습니다. 사내 중계 연결 복구나 실제 원인 확정은 아직 확인하지 못했습니다.
