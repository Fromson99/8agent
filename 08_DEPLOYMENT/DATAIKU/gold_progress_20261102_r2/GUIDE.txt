Gold 진행 표시·개발계 Mesh 벡터 통합 R2

실행
1. 현재 실행 중인 적재 셀이 종료된 뒤 같은 Dataiku Python 노트북을 사용합니다.
2. Dataiku에서 아래 환경변수를 직접 등록합니다. 같은 이름의 프로젝트 변수도 지원합니다.
   LEGAL_EMBED_LLM_ID=openai:genos-embedding:embedding-kure-v1
   LEGAL_EMBED_DIMENSIONS=1024
   승호님과 같은 get_llm → new_embeddings → add_text → execute → get_embeddings 경로입니다.
   Dataiku 등록 인증을 사용하므로 별도 URL/API 키 입력은 없습니다.
   실제 환경변수가 있으면 우선 사용합니다. 코드가 모델 값을 덮어쓰지 않습니다.
   환경변수를 바꾼 경우 해당 Python 커널/실행 환경에 반영한 뒤 실행합니다.
3. LEGAL_RAG 관리 폴더 ehA8dpVm에 다음 두 ZIP을 압축 해제하지 않고 업로드합니다.
   DATAIKU_GOLD_SHAPE_20261102_R1.zip: 기존 R1과 동일. 이미 있으면 재업로드 불필요.
   DATAIKU_GOLD_PROGRESS_VECTOR_20261102_R2.zip: 이번 진행 표시·Mesh 벡터 추가 코드.
   각 파일명은 한 개씩만 있어야 합니다. ZIP 안에 ZIP을 넣지 않습니다.
4. DATAIKU_GOLD_ALL_WITH_VECTOR_R2.txt 전체를 새 Python 셀에 붙여 실행합니다.
   OLD_JOB_DIR을 이전 실행에서 지정했다면 같은 값을 입력합니다.
   기존 관리 폴더 ehA8dpVm의 DATAIKU_GOLD_SHAPE_20261102_R1.zip을 그대로 사용합니다.
   기존 state.json은 삭제하지 않습니다. 별도의 환경변수 설정 셀은 필요하지 않습니다.
   이번 R2 통합 TXT를 사용하며 앞서 전달한 추가 적재/검증 TXT와 동시에 실행하지 않습니다.

메일 첨부: 위 ZIP 2개, DATAIKU_GOLD_ALL_WITH_VECTOR_R2.txt, ENVIRONMENT.txt, GUIDE.txt.

순서: 남은 원문·검색 적재 → 전체 검증·시험 게시 → 임베딩·벡터 저장 검증.
앞 단계가 실패하거나 사용자가 중단하면 다음 단계는 실행하지 않습니다.
원래 R1 적재 코드·ZIP·재개 binding은 변경하지 않습니다.
이미 적재/검증이 끝난 단계는 기존 R1의 재개 규칙을 따릅니다.

표시와 로그
- 기존 적재기는 15초 간격으로 상태를 보내며, 화면에서 완료 기록의 누적 행 수를 읽어 갱신합니다.
- 원문/검색/벡터 각각 처리 행 수·전체 행 수·진행률·경과 시간·예상 잔여 시간을 표시합니다.
- 시간은 시간·분·초 형식입니다. 이번 실행 경과이며 과거 실행 시간을 합한 값은 아닙니다.
- 예상 잔여는 해당 단계의 관측 평균으로 계산합니다. 시작 전 단계는 계산 중으로 표시합니다.
  전체 적재+검증+임베딩의 합산 완료 시간 예측은 아닙니다. 데이터 크기·DB·모델 응답에 따라 바뀝니다.
- 적재는 완료된 묶음만 누적합니다. 반복 heartbeat나 과거 완료 행을 신규 처리량으로 더하지 않습니다.
- 전체 표준 출력은 현재 노트북 작업 폴더/gold-progress-logs에 실행별로 보존합니다.
  Dataiku 노트북 파일 영역이며 NFS 내구 저장을 인증한 것은 아닙니다.
- 적재/검증만 필요하면 별도 LOAD_PROGRESS/VERIFY_PROGRESS TXT를 사용합니다.

벡터 범위
- 검증된 동일 고정 원본의 비어 있지 않은 본문을 800자, 100자 겹침으로 나눕니다.
  마지막 구간도 포함하며 원문 자체를 변경하지 않습니다. 검색자료 약6천만 행 전부를 임베딩하지 않습니다.
- 개발계 SIDDS.LGL_G19_VCTR_ITEM_S에 실제 벡터와 원문 좌표·입력 해시를 저장합니다.
  문서/원문구간 ID의 Gold 컬럼 길이를 전체 사전 확인하고, 모델 출력 개수·차원·유한값·정규화를 검사합니다.
- 묶음 INSERT 후 같은 좌표·메타데이터·차원·벡터 거리를 대조하고 최종 전체 행 수를 확인합니다.
  완료 정보를 LGL_G19_VCTR_POST_S에 기록합니다.
- 완료 표시는 VECTORS_STORED_VERIFIED_NOT_ACTIVATED입니다.
  VCTR_HEAD 변경, 서비스 매핑/GENOS 전환, 벡터 전용 검색 인덱스 DDL은 하지 않습니다.
  실제 검색 consumer의 모델/전처리/원문 ID 연결과 법률 검색 품질은 별도 확인 범위입니다.
- 모델 ID는 Dataiku 등록 별칭이며 실제 가중치 불변성 증명은 아닙니다.
  동일 별칭의 실제 모델을 교체한 경우 이전 벡터를 그대로 이어 쓰지 않습니다.

중단·재개
- 기존 작업 잠금과 최초 7일 기한을 유지합니다. 재실행으로 기한을 늘리지 않습니다.
- 벡터 상태·응답은 기존 gold-shape 작업 폴더/vectors/<게시ID>에 보존합니다.
- 모델 응답을 확보했으나 DB 저장에 실패한 경우 같은 셀 재실행 시 보존 응답으로 확인·저장합니다.
- 모델 호출 의도는 남았는데 응답이 없으면 결과불명으로 멈추며 자동 재호출하지 않습니다.
- 코드/원문/DB 객체/모델 설정이 바뀌면 기존 작업을 무조건 재사용하지 않습니다.
- 원문/검색 적재 완료분, 과거 실패 기록, 기존 운영 벡터는 삭제하지 않습니다.

환경변수/SDK 요청·잘못된 차원·성공 재조회·DB 실패 뒤 응답 재사용·결과불명 무재전송·기한 유지.
