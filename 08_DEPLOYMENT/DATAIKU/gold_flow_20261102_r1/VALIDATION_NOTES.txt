2026-11-02 · Dataiku Flow R1 구현/검증 기록

구현 경로: package/flow_spec.py → install_flow.py / flow_runtime.py → flow_entry.py
입력: flow_inputs.py가 기존 NFS INFO/READ 계약과 기존 R11 준비 함수를 호출한다.
DB: engine/의 FRESH_1 60파일은 이전 메일 전달본과 바이트 동일. 계약/PK/DDL/SQL/배치/벡터 엔진 변경 없음.
기존 노트북 state.json과 같은 code/contract/database/object/generation/files/source/query binding을 사용한다.
기존 준비 명세가 없을 때만 flow-inputs.json으로 로컬 입력 계획을 저장하며 DB 성공 기록을 만들지 않는다.

실패 처리: HTTP 읽기 요청은 한 번 실행, 수신 완료 조각은 S3에 보관 후 재실행에서 재사용.
해시/세대/DB/미확인 쓰기 충돌은 원문 오류와 함께 중단. 다음 Scenario 단계 미실행.
기존 Job.batch와 vector_stage의 pending/reconciliation/unknown 계약은 그대로 유지.
로컬 job.lock으로 현재 노트북과 Flow의 동시 쓰기를 차단한다.
Flow별 로그는 Dataiku Job과 단계별 S3 폴더에 보관한다. 대형 로그 전체 반복 업로드 대신 조각 기록.
화면 갱신 실패는 로그에 별도 표시하고, DB 적재 결과와 대시보드 게시 상태를 구분한다.
