Dataiku Flow 연결 구조 확인용 — 실제 적재 실행 안 함
2026-11-02 / Gold Flow R1

이번 목적
현재 다른 곳에서 실행 중인 적재는 그대로 두고, Dataiku의 Flow 연결 구조만 생성해 확인합니다.
INSTALL 셀은 Flow 구성 정보를 등록하는 설치입니다. 데이터 처리 레시피를 실행하지 않습니다.

첨부
  DATAIKU_GOLD_FLOW_20261102_R1.zip  : 앞서 검증한 동일 코드 ZIP
  DATAIKU_GOLD_FLOW_INSTALL_R1.txt  : 앞서 검증한 동일 전체 설치 셀
  GUIDE.txt                       : 이번 연결 구조 확인용 안내
  PREVIEW.png                     : 현황판 모양 참고. 실제 Dataiku Flow 캡처는 아님

이것만 하세요
1. Dataiku의 LEGAL_RAG 프로젝트를 엽니다.
2. 관리 폴더 ehA8dpVm에 ZIP을 이름 그대로, 압축을 풀지 않고 업로드합니다.
   이미 같은 ZIP을 올렸다면 중복 업로드하지 않습니다.
3. 새 Python 노트북 한 셀에 DATAIKU_GOLD_FLOW_INSTALL_R1.txt 전체를 붙여 실행합니다.
4. FLOW_INSTALLED가 출력되면 Dataiku Flow 화면을 새로고침합니다.
5. Gold _1 구역을 펼쳐 레시피·폴더·DB 연결선이 이어지는지만 확인합니다. 여기까지입니다.

생성되는 Flow
  NFS 데이터 준비 → 적재 자료 준비 → _1 테이블 준비 → 원문 적재
  → 검색 자료 적재 → 원문·검색 검증 → 벡터 저장 → DB 결과 확인

  색상 구역 7개 / 레시피 8개 / Oracle 외부 연결 데이터셋 17개 / 결과 폴더 8개
  실제 DB 테이블은 각 단계의 출력으로 연결되어 표시됩니다.
  이번에는 연결 정의만 등록하며 DB에 표를 생성하거나 데이터를 넣지 않습니다.

이번에는 하지 않는 것
  레시피 Run / Build, 전체 Scenario Run, MONITOR 실행, 데이터셋 Explore/Count 실행
  NFS 수신, 원문·검색 INSERT, DB 검증 SELECT, 벡터 생성 및 임베딩 호출

설치에 포함된 Scenario는 신규 생성 시 자동 실행이 꺼져 있으며, 설치 셀이 이를 실행하지 않습니다.
설치 출력에 보이는 일반적인 Scenario Run 안내는 나중의 적재용 설명입니다. 이번에는 누르지 마세요.
앞선 메일의 MONITOR TXT와 실행용 설정 안내도 이번 확인에는 필요 없습니다.

설치의 실제 변경 범위
  Dataiku 프로젝트 안에 Flow/레시피/외부 데이터셋 연결/결과 관리 폴더/Scenario/대기 현황판을 등록합니다.
  설치 기록과 대기 화면은 관리 폴더·Insight에 저장합니다.
  DB의 DDL·INSERT·DELETE·COUNT와 NFS 데이터 수신을 호출하지 않습니다.
  다른 곳에서 돌아가는 기존 적재 작업을 중단하거나 코드를 변경하지 않습니다.

이미 같은 R1을 설치했다면 동일한 구성인지 확인하고 재사용합니다.
현재 다른 작업의 실행 상태나 완료 여부를 이 Flow 연결 그림만으로 판단하지 마세요.
Flow의 연결이 보인다는 것은 배선이 등록됐다는 뜻이며, 현장 실행 검증 완료를 뜻하지 않습니다.

검증된 ZIP과 설치 TXT는 원본 그대로입니다. 다시 압축하거나 다른 버전을 섞지 않았습니다.
이번 전달에서는 실행을 유도할 MONITOR TXT·임베딩 설정표를 첨부하지 않습니다.
