R7 정정 패치 — 전처리기를 사용하지 않고 PDF 파싱·변환 건너뜀

R6의 오류
사용자 요청은 전처리기를 쓰지 않고 패스하는 것이었는데, 실패한 문서만 제외하는 것으로
잘못 해석해 기존 HTTP 전처리기 설정·호출을 유지했습니다. R6 코드와 가이드 모두 수정 대상입니다.
R6 가이드 3번을 따르지 말고 이번 R7로 교체합니다.

수정한 동작
1. 전체 Flow의 HEALTH/OPEN/RUN/worker에서 파서 주소·공유 경로·YAML·검수 모델 설정을 요구하지 않습니다.
2. 전체 Flow를 skip으로 고정합니다. 이전 HTTP/Pod 환경변수가 남아 있어도 전처리기를 사용하지 않습니다.
3. PDF는 구조화 진입 전에 건너뜁니다. 간접 호출 시에도 로컬 PDF 파서로 대체하지 않도록 차단합니다.
4. PDF 변환은 off입니다. 구형 DOC는 변환 호출 없이 보류하고, 사유를 BYPASSED_BY_USER로 남깁니다.
5. DOCX/HWPX/XML/HTML 등의 직접 구조화와 성공 문서 선택·색인·기존 실버 적재는 유지합니다.
   HWP의 기존 로컬 파서 실패는 기타 실패로 기록합니다. 직접 읽기 뒤 열람용 합성 PDF는 유지됩니다.
6. 제외 CSV의 문서명과 사유를 보완하고, 요청에 따른 건너뜀/실제 처리 실패 건수를 구분합니다.
7. 기존 R5 변환·파싱 진단 목적은 R7에서 차단합니다.
8. 원문/해시/권한/선택 검증, 전체 실패 중단, 최초 기한·사용량·시도 한도, 과거 이력은 유지합니다.

입력·소비자와 실패 처리
Dataiku RAW snapshot → GENOS 계산 → 문서별 직접 처리/건너뜀 원장 → 성공 receipt 선택 →
prepare/index → Dataiku 결과 ZIP/CSV/JSON → 기존 03의 SIDDS.*_S 적재.
PDF 건너뜀은 사용자 정책이며 재시도하지 않습니다. 성공이 없으면 적재하지 않습니다.
문서별 실패는 보류하며, 취소·무결성·입력 전체 오류·후속 검증 실패는 기존 중단 정책을 유지합니다.
새 파서 서비스·재시도 실행기·모델 호출을 추가하지 않습니다.

설치
GUIDE.txt와 동봉 GENOS_R7_INSTALL.txt / DATAIKU_R7_INSTALL.txt를 사용합니다.
전처리기 관련 환경변수는 추가하지 않습니다. Dataiku 계산 서비스 URL/TOKEN은 유지합니다.
서버/client를 R7 한 쌍으로 적용합니다. 기존 R6 및 이전 ZIP은 과거 이력으로 보존합니다.

검증·한계
최종 검사 수는 VALIDATION.json에 기록합니다.
합성 DOCX 성공 + PDF/DOC 건너뜀으로 실제 색인/결과 반환과 호출0을 검사합니다.
PDF만 있는 입력과 직접 파서까지 실패한 입력은 성공 결과를 만들지 않는지 확인합니다.
SQL 소비자·Dataiku SDK는 모의이며 실제 현장 Oracle·전체 문서·배포는 미실행입니다.
초기 검사에서 DOC 보류가 일반 오류로 분류되던 누락을 발견해 실제 team_raw 경로를 수정했습니다.
R6 인계본과 최초 R7 검사 실패 기록은 덮어쓰지 않고 보존합니다.
