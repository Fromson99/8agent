기존 GENOS pipeline 코드서빙 · 덮어쓰기 실행 TXT R3

현장 실행
사진의 pwd 출력은 /workspace/TRANSFER입니다. 파이프라인 코드서빙 코드스페이스의 이 폴더에 GENOS_DEPLOY_R3.txt를 올립니다. 같은 폴더에 있는 GENOS_AGENT_ASYNC_R2.zip은 그대로 사용합니다. 이전 메일의 GENOS_DEPLOY_R2.txt를 R3 실행 TXT로 교체합니다.

bash ./GENOS_DEPLOY_R3.txt

이 명령은 ~/DEV의 실제 Git checkout에서 실행합니다. 터미널 위치는 TRANSFER에 둡니다. R2 ZIP에 들어있는 파이프라인 서빙 코드 1,284개 전체를 기준으로 기존 버전과 다른 파일을 백업·교체하고 빠진 파일을 추가합니다. Oracle 원문·NFS 데이터·Dataiku 파일은 이 코드 ZIP의 적용 대상 밖에 있습니다.
메모리·용어집·모델 설정과 법령 ZIP은 앞선 R2 안내를 사용합니다. 기존 R2 Dataiku Flow ZIP, Python 설치 셀, LAW_SAMPLE_R2.zip, SAMPLE_SUPPORT_R2.zip을 그대로 사용하면 됩니다.

Git 대상과 완료 기준
이전 인계에서 확인된 legal_pipeline_serving(761) 주소를 우선 선택합니다. 기존 pipeline 별칭 또는 식별 가능한 전용 checkout의 단일 원격도 사용할 수 있습니다. RAG의 risk_team·financial_team 및 기존 623·701 저장소는 제외합니다. 코드스페이스 화면 URL의 숫자 452를 코드서빙 저장소 번호로 쓰지 않습니다.
PIPELINE_BACKUP은 기존 파일 원본과 해시 목록이 저장된 Git 내부 경로입니다. PIPELINE_CHECKOUT_VERIFIED는 실제 ~/DEV의 패키지 파일 검사가 끝난 상태입니다.
마지막 GENOS_CODE_PUSHED 옆에 표시한 기존 원격 이름·브랜치·커밋을 확인합니다. 스크립트는 해당 원격 브랜치 최신판에서 시작해 이번 ZIP 파일만 커밋하고, 커밋 안의 파일 해시와 push 후 원격 SHA를 대조합니다. 로컬의 다른 작업이나 staged 파일을 함께 보내지 않도록 임시 Git index를 사용합니다. 배포 화면에는 GENOS_CODE_PUSHED의 SHA를 지정합니다. 같은 터미널에서 따로 git add나 git push를 실행할 필요는 없습니다.
기존 GENOS pipeline 코드서빙에서 해당 커밋으로 새 리비전을 배포합니다. Dataiku의 AGENT_PIPELINE_URL과 AGENT_PIPELINE_TOKEN도 이 pipeline 서비스용 값을 사용합니다.

오류와 재실행
R2의 OCCUPIED_NEW_CHECKOUT은 기존 파일과 전달 파일의 해시가 다를 때 사전 검사에서 멈췄다는 뜻입니다. 사진의 oracle_full_package.py를 직접 삭제하거나 옮길 필요가 없습니다.
원격이 여러 개라 PIPELINE_REMOTE_NOT_UNIQUE가 나오면 git -C ~/DEV remote로 이미 등록된 이름을 확인합니다. 명시 실행 예시는 다음과 같습니다. 마지막 단어에는 실제 기존 pipeline 원격 이름을 넣습니다.
bash ./GENOS_DEPLOY_R3.txt --remote legal_pipeline_serving
네트워크 중단 후에는 같은 명령으로 재실행합니다. 원래 버전·이번 버전과 다른 추가 수정이나 별도의 원격 커밋을 발견하면 내용을 보존하고 중단합니다.
로컬 작업 파일을 실행 전으로 복구할 때는 같은 TRANSFER 폴더에서 아래처럼 실행합니다.
bash ./GENOS_DEPLOY_R3.txt --restore-local
이 복구는 로컬 코드 파일에 적용됩니다. 현장 트래픽을 이전 배포로 되돌릴 때는 기존 pipeline 코드서빙 화면의 이전 리비전을 선택합니다.
