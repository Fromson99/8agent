벡터 생성·Oracle 적재 R1 — R6/R7 원문·검색 load 완료 뒤 실행
2026-11-03 / Dataiku LEGAL_RAG / AIDP / 기존 SIDDS의 _1 표

첨부
1. DATAIKU_GOLD_VECTOR_FAST_20261103_R1.zip — 실제 실행 코드. 그대로 업로드.
2. DATAIKU_GOLD_VECTOR_FAST_RUN_R1.txt — Dataiku 노트북에 붙일 전체 실행문.
3. GUIDE.txt — 이 안내서.
4. VECTOR_INSERT_SQL_R1.txt — 실제 적재 SQL과 입력 형태 설명.
이 ZIP은 기존 R6 원문·검색 적재 ZIP을 대체하는 용도가 아니라, 완료 뒤 실행할 벡터 단계입니다.

바로 실행
1. 기존 R6 또는 R7 load가 LOADED_INSERT_ACK로 끝난 뒤 실행합니다.
   이미 ACTION="publish"를 실행해 SOURCE_QUERY_PUBLISHED인 경우도 지원합니다.
   원문 적재 셀과 이 벡터 셀을 동시에 실행하지 않습니다.
2. LEGAL_RAG 관리 폴더 ehA8dpVm에 이번 ZIP을 이름 그대로 업로드합니다. 압축을 풀지 않습니다.
3. 이전 R6를 실행한 LEGAL_RAG Python 노트북에서 실행 TXT 전체를 새 셀에 붙여 실행합니다.
   노트북 현재 작업 디렉터리는 기존 것을 사용합니다. 새 패키지 설치가 없습니다.
   기본 ACTION="vector"입니다. 별도 check를 먼저 돌릴 필요는 없습니다.
   OLD_JOB_DIR은 R6에서 직접 지정했으면 같은 값을 넣고, 기본 경로였다면 빈 문자열을 유지합니다.
   EMBED_LLM_ID="openai:genos-embedding:embedding-kure-v1", EMBED_DIMENSIONS=1024는 이전 전달본 설정입니다.
   현장 Mesh 연결 이름/차원이 바뀌었다면 실제 값으로 수정합니다. 다른 모델로 자동 전환하지 않습니다.
4. VECTORS_STORED_INSERT_ACK_NOT_ACTIVATED가 나오면 벡터 적재 응답 기준 완료입니다.
   로그는 현재 노트북 폴더/gold-progress-logs에 남습니다.
   진행 표시는 완료 벡터행/SDK 호출수/묶음 DB시간입니다. 전체 벡터수를 미리 세지 않아 %와 총 ETA는 표시하지 않습니다.

실행 내용
- 현재 완료된 full/reduced 원문·검색판본을 그대로 사용합니다. 원문/검색 state를 초기화하거나 이행하지 않습니다.
- navigation.source의 실제 조문 ID와 연결된 원문 블록을 사용합니다.
  종전 보조 코드의 document_id+":"+unit_id 임의 조합을 쓰지 않습니다.
- 원문을 800문자·100문자 겹침으로 나누고 내부 Dataiku Mesh에 최대16구간씩 전달합니다.
- 응답은 차원·유한수·0이 아닌 벡터를 확인하고 L2 정규화합니다.
- DB에는 최대128행/JSON 약2MiB로 모아 INSERT SELECT JSON_TABLE + TO_VECTOR(FLOAT32) + COMMIT합니다.
- Dataiku SQLExecutor2 1요청 안에 적재 PL/SQL과 SELECT 1 응답 확인을 사용합니다. COMMIT을 두 번 보내지 않습니다.
- 적재 대상: SIDDS.LGL_G19_VCTR_ITEM_S_1, SIDDS.LGL_G19_VCTR_POST_S_1.
- 임베딩 원문·벡터는 실패/미확정 캐시에 보존합니다. DB ACK와 재개 위치 저장 뒤 확정된 임시 응답 캐시만 정리합니다.

제거한 반복 비용
- 전체 원문·벡터 구간 수 선계산, 대용량 파일 전체 SHA 재계산.
- 매 묶음 NOT EXISTS/기존행 COUNT/메타데이터 CLOB 비교/벡터 거리 비교.
- 적재 후 전체 벡터 COUNT 및 전수 되읽기.
- 정상 완료 묶음의 DB 조회 및 임베딩 재생성.
- 재개할 때 이미 끝난 문서/조문/블록을 처음부터 순회하는 작업.
DB 시작 대상 확인 2조회(DB 식별/벡터2표 object ID)는 1회 유지합니다.
PK·길이·VECTOR 타입은 Oracle이 검사하고, 원문 범위·차원·체크포인트·단일 writer 잠금은 유지합니다.
저장된 명세/소량 파일 stat은 확인하되 큰 SQLite 내용 해시는 다시 계산하지 않습니다.
이 완료는 INSERT 응답 기준이며 full_values_verified=false입니다.

중단·재개
- 같은 ZIP/TXT, OLD_JOB_DIR, 모델/차원으로 다시 실행합니다. state·캐시를 지우지 않습니다.
- 마지막 DB ACK의 조문/블록/문자 위치부터 재개하며 이미 만든 미확정 응답 캐시는 재사용합니다.
- DB 결과 불명 묶음만 PK 조회: 전부 있으면 완료, 없으면 같은 캐시로 삽입, 일부면 중단합니다.
- EMBEDDING_OUTCOME_UNKNOWN_NO_AUTOMATIC_RETRY는 모델 응답을 확보하지 못한 상태입니다.
  성공/실패를 임의로 가정해 모델을 재호출하지 않습니다. 오류 로그와 해당 state를 보존합니다.
- VECTOR_PENDING_PARTIAL_KEYS_REVIEW_REQUIRED/PK 충돌/원문 변경도 중단·보존합니다.
- 새 벡터 단계의 최초 시작부터 7일·최대1,000,000 SDK 시도를 저장하며 재시작으로 초기화하지 않습니다.
- 벡터 작업 폴더는 선택된 기존 체크포인트 아래 vectors-fast-r1/<게시ID>입니다.
  과거 vectors 폴더의 R1 미완료 작업을 자동 이행하지 않습니다.

적재 뒤
벡터 본문과 완료 명세까지 저장합니다. VCTR_HEAD·운영/GENOS 서비스 선택은 바꾸지 않습니다.
기존 원문·검색 publish도 대신 실행하지 않습니다. 서비스가 이 판본을 쓰도록 연결하는 것은 별도 단계입니다.
새 테이블·컬럼·인덱스·통계 DDL을 실행하지 않습니다.

검증과 한계
최종 ZIP에서 추출한 동일 코드의 정상/실패/재개/메타데이터 reader/전체 실행 TXT 검사를 수행합니다.
실제 로컬 Oracle 23.26에서 1024차원 FLOAT32와 긴 한글·보조문자 CLOB, 중복 전체 롤백,
잘못된 차원 롤백, 미확정 PK 확인, 완료 명세 적재 SQL을 확인했습니다. 격리 시험 스키마는 제거했습니다.
Dataiku SQLExecutor2 인터페이스는 모의이며 생성 SQL은 실제 Oracle에서 실행했습니다.
내부 현장 Mesh 호출/전체 Oracle 적재/실제 처리량은 여기서 실행하지 않았습니다.
JDBC payload별 SQL 문자열 파싱 비용은 남습니다. 시간 개선율·완료시간을 약속하지 않습니다.
