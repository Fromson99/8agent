기존 개발 테이블 목록·실제 행 수 확인 R4

현재까지 전달한 생성 SQL/매핑에서 SIDDS/SIDDA 테이블 이름 44개를 확인했습니다.
과거 경로 27개 + 현재 Gold형태/Agent 대상 17개입니다. 실제 생성 완료·개인 소유 판정은 아닙니다.
TABLE_LIST.txt에서 전체 목록을 볼 수 있으며 CATALOG.json에 근거 파일을 기록했습니다.

실행 위치: Dataiku LEGAL_RAG, 기존 AIDP 연결을 쓰는 Python/Jupyter 노트북의 새 셀.
기존 적재 작업이 종료된 상태에서 DATAIKU_TABLE_INVENTORY_R4.txt 전체를 붙여 실행하세요.
SQL 노트북용이 아닙니다. 원본 파일 경로 설정이나 관리 폴더 ZIP 업로드는 필요 없습니다.
첨부 ZIP은 같은 코드/목록 원본 보관용입니다. 실행 TXT가 전체 코드를 포함합니다.

기본 동작
1. SIDDS/SIDDA에서 보이는 LGL_/LEGAL_ 테이블 메타데이터 목록을 조회합니다.
2. 알려진 44개 이름과 합치며 보이지 않는 이름도 NOT_VISIBLE_OR_ABSENT로 남깁니다.
   조회 권한이 없어 안 보이는 것과 실제 부재를 구분할 수 없으므로 0행으로 표시하지 않습니다.
3. 권한이 허용되면 DBA_SEGMENTS로 테이블 본체/인덱스/LOB의 할당 bytes를 확인합니다.
   ORA-00942/01031 등으로 실패해도 실제 행 수 조회는 계속합니다.
   접속자 PIDD2APP의 USER_SEGMENTS로 대체하지 않습니다.
4. 알려진 이름 중 보이는 표에 COUNT(*)를 한 개씩 순차 실행합니다. 병렬 힌트는 끕니다.
   정확한 행 수 조회이므로 큰 표는 오래 걸릴 수 있습니다. 15초마다 현재 표·경과 시간을 표시합니다.
5. 표별 완료 즉시 결과를 출력하고 노트북 작업 폴더/gold-table-inventory/*.csv에 저장합니다.
   최종 화면에도 전체 표/행 수/할당 MiB/구분을 출력합니다. CSV는 Excel에서 열 수 있습니다.

설정
- COUNT_EXACT=True: 실제 COUNT 실행. False이면 목록/통계/할당량만 확인합니다.
- COUNT_DISCOVERED=False: 과거 전달본에서 근거를 찾지 못한 추가 발견 표는 목록만 표시합니다.
  이 값을 True로 명시 변경하면 추가 발견 표도 COUNT합니다. 생성자가 사용자라는 뜻은 아닙니다.
- INCLUDE_ALLOCATED_BYTES=True: 물리 할당량 조회 시도. False이면 행 수 확인에만 집중합니다.
- 기본 CONNECTION='AIDP'. 모델 설정/임베딩은 필요하지 않습니다.

결과 해석
- EXACT_ROWS + COUNTED: 해당 SELECT 시점의 실제 행 수. 표마다 조회 시점이 다릅니다.
- STATS_ROWS/STATS_AT: 이전 통계 행 수/수집 시점. NULL 또는 오래된 통계를 현재 행 수로 쓰지 않습니다.
- ALLOCATED_BYTES: 본체+인덱스+LOB 할당량. 현재 내용의 순수 바이트나 삭제 후 회수 보장량이 아닙니다.
- PARTITIONED_NOT_FULLY_MAPPED: 별도 파티션 구조이므로 이번 조회로 전체 용량을 확정하지 않습니다.
- CURRENT_TARGET=YES: 현재 R1 코드가 사용하는 대상입니다. 삭제 대상으로 해석하지 않습니다.
- 과거 표도 현재 서비스·이관·복구에 쓰일 수 있습니다. 행 수/이름만으로 삭제 가능성을 결정하지 않습니다.
- 공용 계정에서 누가 실제로 만든 표인지 이 조회로 증명하지 않습니다.

이번 사진: 실패 대상 SIDDS.LGL_G19_DOC_VER_S, LOB 컬럼 DOC_ADDN_IFMN_CTNT,
테이블스페이스 TS_IDDS_DN01이 표시됐습니다. 이 표는 현재 적재 대상입니다.
크기가 큰 과거 표가 보여도 삭제 전에 참조·현재 사용 여부·보존 범위를 확인해야 합니다.

중단: Python 실행을 중단하면 완료한 표의 CSV를 유지하고 현재 COUNT를 INTERRUPTED_UNKNOWN으로 표시합니다.
서버 쪽 실행이 종료됐는지 확인한 뒤 재실행하세요. 재실행은 새로운 시점의 행 수를 다시 조회합니다.
DB INSERT/UPDATE/DELETE/DROP/TRUNCATE/DDL/통계수집/임베딩은 실행하지 않습니다.
로컬 모의 8개 검사 통과. 실제 현장 행 수·할당량은 사용자가 이 셀을 실행해야 확인됩니다.
