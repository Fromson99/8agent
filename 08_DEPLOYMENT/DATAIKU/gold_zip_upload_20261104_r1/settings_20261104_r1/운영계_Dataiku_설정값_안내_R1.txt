운영계 Dataiku 설정값 안내 — 2026-11-04 R1

이 문서는 설정 안내입니다. 문서 전체를 Python 셀에 붙여넣지 않습니다.
앞서 받은 아래 파일은 그대로 사용합니다.
  코드 ZIP: DATAIKU_GOLD_ZIP_FLOW_20261104_R1.zip
  실행 TXT: DATAIKU_GOLD_ZIP_UPLOAD_RUN_R1.txt
이번 안내는 위 실행 TXT의 맨 위 설정값을 운영계에 맞추는 방법입니다.

1. 새로 만들 때 사용할 이름 — 아래대로 정합니다

  Dataiku 프로젝트 이름       LEGAL_RAG
  Dataiku 프로젝트 Key        LEGAL_RAG
  Managed Folder 이름         LEGAL_RAG_UPLOAD
  Python 노트북 이름          01_GOLD_ZIP_IMPORT

LEGAL_RAG는 Dataiku 프로젝트입니다.
그 프로젝트의 Flow 안에 LEGAL_RAG_UPLOAD라는 Managed Folder 하나를 만들고
저장소 유형 S3와 운영계에서 제공된 S3 연결을 선택합니다.
Managed Folder의 표시 이름과 자동 생성되는 ID는 서로 다릅니다.
스크립트의 CODE_FOLDER_ID/INPUT_FOLDER_ID에는 표시 이름 대신 ID를 넣습니다.

프로젝트 Key를 LEGAL_RAG로 만들 수 없거나 이미 다른 Key로 만들었다면,
이름만 바꾸는 것으로 끝내지 말고 실행문의 EXPECTED_PROJECT를 실제 Key로 바꿉니다.

2. S3 설정 — 이름을 정할 수 있는 부분과 실제 자원을 구분합니다

  저장소 유형                S3
  S3 연결                    운영계에서 사용 권한이 있는 기존 연결을 선택
  버킷                       그 연결에 등록된 운영계 버킷을 선택
  업로드 폴더 경로(제안값)    /LEGAL_RAG/gold_zip_flow_20261104_r1/upload

위 경로는 새 입력 폴더에 사용할 제안값이며 현재 서버에 존재한다고 확인한 경로가 아닙니다.
S3 연결 이름과 버킷명은 이미 등록된 실제 자원이므로 임의 문자열로 만들지 않습니다.
연결 설정에서 버킷이 고정되어 있으면 그대로 사용합니다.
S3 설정은 Dataiku Managed Folder에서 합니다. Python 설정에는 S3 주소나 접근키를 넣지 않습니다.

현재 설치 코드는 결과 폴더8개를 같은 S3 연결/버킷에 자동으로 만듭니다.
프로젝트 Key가 LEGAL_RAG이면 결과 경로는 다음과 같습니다.
  /LEGAL_RAG/gold_zip_flow_20261104_r1/inspect
  /LEGAL_RAG/gold_zip_flow_20261104_r1/restore
  /LEGAL_RAG/gold_zip_flow_20261104_r1/prepare
  /LEGAL_RAG/gold_zip_flow_20261104_r1/source
  /LEGAL_RAG/gold_zip_flow_20261104_r1/search
  /LEGAL_RAG/gold_zip_flow_20261104_r1/publish
  /LEGAL_RAG/gold_zip_flow_20261104_r1/vector
  /LEGAL_RAG/gold_zip_flow_20261104_r1/report
따라서 S3 연결의 허용 경로는 upload 한 곳뿐 아니라 위 결과 경로도 포함해야 합니다.
운영계 S3 정책이 다른 루트 경로만 허용하면 현재 설치 코드의 경로도 맞춰야 합니다.

3. 폴더에 올릴 파일 — 같은 폴더의 맨 위에 업로드

  DATAIKU_GOLD_ZIP_FLOW_20261104_R1.zip                           1개
  genos-rag-data-20261007T002029Z-7c0b050f.zip.part000000~000033   34개
  PARTS.sha256                                                 1개
  ORIGINAL.sha256                                              1개

총37파일입니다. 코드 ZIP은 풀지 않고 올립니다.
이번 실행문은 위 34조각용이며 통합 데이터 ZIP 한 개를 넣는 방식은 아닙니다.
데이터 조각이 다른 Managed Folder에 이미 있으면 옮기지 않아도 됩니다.
그때만 INPUT_FOLDER_ID에 기존 데이터 폴더 ID를 넣습니다.

4. 실행 TXT에서 바꿀 곳

  EXPECTED_PROJECT
    정한 값: 'LEGAL_RAG'
    실제 프로젝트 Key가 다를 때만 바꿉니다.

  CODE_FOLDER_ID
    직접 입력: LEGAL_RAG_UPLOAD의 실제 Managed Folder ID
    보낸 파일의 ehA8dpVm는 이전 환경 값입니다. 운영계 새 ID로 바꿉니다.

  INPUT_FOLDER_ID
    직접 입력: 위 CODE_FOLDER_ID와 같은 ID
    코드와 데이터를 같은 폴더에 두므로 두 값은 같습니다.
    데이터가 별도 폴더에 있을 때만 그 데이터 폴더 ID를 넣습니다.

  ORACLE_CONNECTION
    기존 전달 기본값: 'AIDP'
    운영계에서 Gold 테이블에 접근하는 Dataiku Oracle 연결 이름을 확인합니다.
    운영계도 이름이 AIDP이면 그대로 쓰고, 다르면 실제 연결 이름으로 바꿉니다.
    S3 연결 이름이나 DB 주소를 넣는 칸이 아닙니다.

  EXPECTED_DB_USER
    기존 전달 기본값: 'PIDD2APP'
    위 Oracle 연결이 실제로 로그인하는 계정명입니다.
    운영계도 PIDD2APP이면 그대로 쓰고, 다르면 실제 계정명으로 바꿉니다.

  GOLD_OWNER
    직접 입력: IDD_B003_LGL_* 테이블이 등록된 실제 소유 스키마명
    필수 입력이며 현재 빈 값입니다. 운영계 DBA/테이블 등록 정보로 확인합니다.
    접속 계정과 테이블 소유자는 다를 수 있으므로 PIDD2APP라고 임의로 넣지 않습니다.
    로컬 시험 스키마 A8_GR12_CM1208도 운영계 값으로 사용하지 않습니다.

  WORK_DIR
    기본값: ''  (작은따옴표 두 개, 빈 문자열)
    이 값이면 /tmp/legal-gold-zip-flow/LEGAL_RAG를 작업 폴더로 사용합니다.
    실제 프로젝트 Key가 다르면 마지막 경로도 해당 Key로 바뀝니다.
    이 기본값은 모든 레시피가 동일 DSS 호스트의 같은 /tmp를 사용할 때만 적용합니다.
    재개 상태/복원 파일은 이 서버 작업 경로에 남습니다. S3 결과 폴더만으로 재개되지 않습니다.
    서로 다른 컨테이너/호스트에서 실행한다면 운영계에서 제공된 영속 공유 Linux 절대경로를
    직접 입력해야 합니다. 공유 경로는 현재 확인되지 않아 임의로 정하지 않았습니다.
    여기에 S3 URI, 버킷명, Managed Folder ID를 넣으면 안 됩니다.

5. 그대로 유지할 값

  TARGET_MODE                  'GOLD'
  TABLE_PREFIX                 'IDD_B003_LGL_'
  TABLE_NAMES                  {}
  EMBED_MODEL                  'openai:genos-embedding:embedding-kure-v1'
  EMBED_DIMENSIONS             1024
  ACTIVATE_NEW_VECTOR_HEAD     True
  EXPECTED_ARCHIVE             'genos-rag-data-20261007T002029Z-7c0b050f.zip'
  EXPECTED_PARTS               34
  ORIGINAL_SHA_FILE            ''
  PARTS_SHA_FILE               ''
  RUN_AFTER_INSTALL           True

임베딩 값은 기존 전달에서 사용한 모델 ID/차원입니다.
운영계에도 같은 모델 ID가 등록되고 접근 가능해야 그대로 사용할 수 있습니다.
다르면 운영계의 실제 모델 ID와 차원을 함께 확인해 바꿉니다.
ORIGINAL_SHA_FILE/PARTS_SHA_FILE의 빈 값은 폴더의 해당 SHA파일을 찾는 설정입니다.
RUN_AFTER_INSTALL=True는 Flow 설치 후 시나리오를 한 번 시작하는 설정입니다.
ACTIVATE_NEW_VECTOR_HEAD=True는 이번 검색 게시본에만 벡터를 연결합니다.
기존 서비스의 사용 채널을 바꾸는 설정은 아닙니다.

6. 실행 순서

  ① LEGAL_RAG 프로젝트와 S3 Managed Folder LEGAL_RAG_UPLOAD를 만듭니다.
  ② 코드 ZIP·데이터34조각·SHA파일2개를 업로드합니다.
  ③ 같은 프로젝트에 새 Python 노트북 01_GOLD_ZIP_IMPORT를 만듭니다.
  ④ 앞서 보낸 실행 TXT 전체를 셀 하나에 붙여넣습니다.
  ⑤ 위4번의 폴더 ID, Oracle 연결/계정, GOLD_OWNER, WORK_DIR 조건을 맞춥니다.
  ⑥ 셀을 한 번 실행합니다.
  ⑦ Scenarios → G19ZIP_RUN_ALL · ZIP부터 Gold 벡터까지의 실행 상태를 확인합니다.
  ⑧ 성공 후 Flow의 G19ZIP_07_REPORT_RESULT 폴더에서 report.json을 확인합니다.

운영계 Gold 테이블은 미리 등록되어 있어야 합니다. 이 코드는 테이블 DDL을 실행하지 않습니다.
설치 셀이 끝난 것은 적재 완료와 다릅니다. 시나리오 성공과 report.json을 확인합니다.
실행 중 셀을 반복 실행하지 않습니다. 중단 후에는 기존 실행이 종료된 것을 확인하고,
같은 설정과 같은 WORK_DIR로 동일 시나리오를 재실행합니다.
임베딩 응답이 불명확해 중단된 경우에는 체크포인트를 지워 다시 호출하지 않습니다.

이번 안내에서 정한 이름과 경로는 운영계 구성 제안입니다.
폴더 ID·S3 연결/버킷·Oracle 연결/계정/소유자·공유 작업 경로는 실제 운영계 정보로 확인합니다.
현장 Dataiku에 접속해 생성하거나 실행을 완료한 상태는 아닙니다.
