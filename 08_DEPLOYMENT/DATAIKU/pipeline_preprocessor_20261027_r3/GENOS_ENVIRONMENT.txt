R3 — legal_pipeline_serving 실제 코드서빙 환경변수

기존 187번 전처리기를 사용합니다. 187 서버 코드/모델/설정은 변경하지 않습니다.

GENOS_PDF_PARSER=preprocessor
GENOS_PREPROCESSOR_ID=187
GENOS_PREPROCESSOR_RESPONSE_MODE=auto
GENOS_PREPROCESSOR_SHARED_ROOT=<기존 전처리기 공유 폴더가 코드서빙에서 보이는 절대경로>

R2에서 RESPONSE_MODE=docling을 넣었다면 auto로 바꾸거나 삭제하세요.
GENOS_PREPROCESSOR_URL이 남아 있으면 ID보다 우선하므로 다른 주소라면 제거하세요.
ID=187이면 기존 코드가 http://preprocessor-187:8080/run 으로 호출합니다.
같은 공유 폴더가 187에서 다른 경로로 보일 때만 아래를 설정합니다.
GENOS_PREPROCESSOR_REMOTE_ROOT=<187 컨테이너에서 보이는 같은 폴더 절대경로>
양쪽 경로가 같으면 REMOTE_ROOT는 생략합니다. /tmp를 공유 경로로 추정하지 않습니다.
187 호출 인증이 필요한 경우 기존 GENOS_PREPROCESSOR_API_KEY를 사용합니다.

기존 PDF 구조 검수 연결도 복원합니다.
LLM_BACKEND=genos
STRUCTURE_RECIPE_VLM=on
GENOS_LLM_URL=<기존 RAG 구축에서 사용한 이미지 입력 지원 GENOS 모델서빙 주소>
GENOS_LLM_KEY=<그 모델서빙의 기존 인증키, 필요한 경우>
GENOS_LLM_MODEL=<기존 모델명, 생략하면 기존 모델 목록 조회 경로 사용>

직접 GENOS_LLM_URL 대신 기존 GENOS_BASE_URL + GENOS_LLM_SERVING_ID 조합도 지원합니다.
187은 전처리기 ID이며 위 검수용 모델서빙 ID와 다릅니다. 값을 임의로 187로 맞추지 마세요.
기존 RAG 구축 설정을 legal_pipeline_serving 실행 환경에도 입력합니다.
새 모델·외부 모델·전처리기 재설치를 요구하는 변경은 아닙니다.
기존 문서별 STRUCTURE_RECIPE_MAX_CALLS(기본64, 최대256)·검수 정책을 유지합니다.
같은 R3 실행을 취소/실패한 뒤 모델 예산을 초기화해 새 계산하는 retry는 차단합니다.

공유경로/전처리기/검수 설정을 저장하고 R3 코드 리비전을 배포한 뒤 Dataiku 00 실행.
ready=true는 로컬 설정·코드 일치 확인이며 실제 187/모델 HTTP 성공이 아닙니다.
실제 연결과 응답 처리는 02 실행에서 확인합니다.
Dataiku LEGAL_PIPELINE_URL/TOKEN, AIDP 연결, 작업 이름은 그대로 유지합니다.
이 파일은 설명입니다. 꺾쇠 값은 실제 값으로 입력하고 셸에 통째로 실행하지 마세요.
