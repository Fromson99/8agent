[개발계] 첫 질문 VECTOR_NOT_PUBLISHED 대응 + 벡터 게시 확인 SQL (읽기 전용)

현장 로그: oracle_query_vector.py:120 VECTOR_NOT_PUBLISHED: selected Oracle query has no vector head

원인
첫 질문의 초기 벡터 검색이 SIDDS.LGL_G19_VCTR_HEAD_S_1에서 현재 채널 판본 행을 찾지 못했습니다. 개발계 벡터 적재기(R1~R4)는 VCTR_POST/VCTR_ITEM까지만 쓰고 VCTR_HEAD는 쓰지 않습니다. 코드서빙에 GENOS_RAG_INITIAL_SEARCH=vector가 있으면 이때 키워드 검색으로 넘어가지 않고 요청이 실패합니다.

1. 바로 할 일 (코드 변경 없음)
코드서빙 환경 설정에서 GENOS_RAG_INITIAL_SEARCH를 auto로 바꾸거나 지운 뒤 재기동합니다.
DP, GENOS_ORACLE_TABLE_MAPPING, DP_QUERY_CHANNEL, 임베딩 설정은 그대로 둡니다.

2. 벡터 사용 가능 여부 확인 (선택, 읽기 전용)
Dataiku 노트북 SQL에서 첨부 TXT마다 별도 Query로 전체를 붙여 실행합니다. 세미콜론·PL/SQL 없음.

  • VECTOR_V1_COUNTS.txt — 채널/HEAD/POST/ITEM 행 수
  • VECTOR_V2_CHANNEL_HEAD.txt — 채널 판본(QUERY_ID)과 HEAD 연결
  • VECTOR_V3_POSTS.txt — 적재된 벡터 판본의 QUERY_ID·모델·차원·완료상태·행 수·HEAD 참조
  • VECTOR_V4_ITEM_GROUPS.txt — ITEM 묶음별 행 수와 완료 명세 유무

결과 읽는 법

  • V1의 POST_ROWS=0, ITEM_ROWS=0 → 개발계에 벡터 없음. auto로 운영.
  • V3에 V2의 QUERY_ID와 같은 행이 있고 STATUS=READY, COMPLETION_COUNT=ITEM_ROWS, HEAD_REFS=0 → 벡터는 적재됨, HEAD 1행만 없음(활성화는 별도 결정).
  • V3의 QUERY_ID가 현재 채널과 다름 → 예전 판본용 벡터, 현재 판본에는 사용 불가.
  • V4의 POST_ROWS=0 → 완료 명세 없는 미완료 적재.

주의: 판본·문서 목록이 맞지 않는 HEAD 행을 넣으면 auto여도 요청이 실패합니다. 확인 전에 HEAD를 직접 넣지 마세요.

로컬 검증: Oracle 23.26.3 임시 스키마(개발계와 같은 컬럼/타입)에서 HEAD 없음/있음 두 경우 4개 SQL 통과, 임시 스키마 삭제. 현장 실행 결과는 미확인입니다.
