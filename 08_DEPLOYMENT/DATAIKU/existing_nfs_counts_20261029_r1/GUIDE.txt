2. 안의 DATAIKU_NFS_TOTAL_COUNTS_R1.txt를 텍스트 편집기로 엽니다.
   같은 실행 TXT를 메일에 별도로도 첨부했습니다.
3. 최근 500줄 로그를 조회한 Dataiku Python 노트북의 새 셀에
   TXT 전체를 붙여넣고 실행합니다. Python 코드이므로 bash로 실행하지 않습니다.
4. 문서(document), 원문 구조 단위(source_unit), 본문 블록(block_payload)의
   총건수와 원문 3테이블 합계가 출력됩니다.

현재 적재 노트북의 실행을 중지하거나 커널을 재시작할 필요가 없습니다.
이 파일은 기존 적재용 DATAIKU_EXISTING_NFS_RUN_R2.txt의 대체본이 아닙니다.
별도의 조회용 파일이며 기존 적재 코드와 설정은 그대로 사용합니다.
사용자가 새로 입력할 값은 없습니다. 프로젝트의 LEGAL_PIPELINE_SCRATCH 또는
기본 임시 디렉터리에서 수신 완료 manifest를 읽습니다.

해석
- 사진의 337,340은 source_unit의 당시 검증 완료 건수입니다.
  출력된 source_unit 전체 건수가 해당 단계 진행률의 분모입니다.
- 문서 수와 구조 단위 수, 본문 블록 수는 다릅니다.
- 합계는 원문 적재 행 수입니다. 후속 자산/조회 색인 게시 및 재검증을 포함한
  전체 이관 작업량이나 현재 완료율로 해석하지 않습니다.
- 수신한 manifest만 읽으므로 Oracle COUNT 쿼리나 GENOS 호출이 없습니다.
- 파일이 안 보이면 기존 로그 조회 노트북과 같은 실행 환경인지 확인합니다.
  이를 적재 중단이나 데이터 0건으로 해석하지 않습니다.

이 자료는 현장 실행 전 전달본입니다. 현재 총건수 숫자는 현장에서 이 조회를
실행해 확인해야 하며, 로컬 보관 사진만으로 확정한 값은 없습니다.
