DP Oracle 메인 사용·기록 이관

선택
  DP 미설정 또는 DP=nfs: 기존 NFS/SQLite 경로를 유지합니다.
  DP=oracle: 원문·탐색 데이터는 게시된 Oracle 조회 버전에서 읽고,
             대화·조사·실행·재개 상태·원문 확보 기록·답변·게시 결과·진행 기록은
             SIDDA의 Agent 기록 저장소에서 읽고 씁니다.

  코드와 설정 파일은 코드서빙 패키지에 있습니다. 기존 기록 SQL/트리거는 요청 메모리의
  SQLite에서 검증하며, 디스크 SQLite 파일이나 NFS 기록 복제본은 생성하지 않습니다.
  Oracle가 영구 정본이고 변경 행·본문·CAS 상태·소유권 영수증을 저장합니다.
  Oracle 오류 때 NFS/로컬 파일로 전환하지 않습니다.

필수 준비
  1. DATAIKU_실행안내.txt에 따라 신규3표21컬럼과 인덱스7을 생성/확인합니다.
     기존 LGL_EXEC_ST_A 5컬럼을 재사용하여 총4표26컬럼입니다. Gold 추가/변경은 없습니다.
  2. 기존 Oracle 원문 및 조회 릴리스를 게시하고 main 채널을 연결해야 합니다.
     Agent 표만 생성하면 원문 조회 게시까지 완료되는 것은 아닙니다.
  3. 기존 ORDS 인증·연결값을 유지하고 다음 설정을 사용합니다.

     DP=oracle
     DP_QUERY_CHANNEL=main

     DP_QUERY_RELEASE_ID를 고정한다면 DP_QUERY_CHANNEL과 동시에 지정하지 않습니다.
     GENOS_ORACLE_TABLE_MAPPING은 기본 mapped입니다. 기존 구물리명 DB만 legacy를 지정합니다.
     ORDS 계정은 새3표 및 기존 STATE의 SELECT/INSERT/UPDATE/DELETE와 기존 원문 조회 권한이
     필요합니다. 이 SQL 묶음은 계정/권한/테이블스페이스 quota를 자동 변경하지 않습니다.
  4. 연결/DP/기록 경로를 바꾼 후 코드서빙 프로세스를 재시작합니다.
     HEALTH binding의 state_storage=oracle, persistent_sqlite=false를 확인합니다.

기록 식별자
  GENOS_RUNTIME_DIR, GENOS_STATE_DIR, GENOS_SHARED_LOG_DIR은 Oracle 모드에서 논리 경로입니다.
  기존 값이 /nfs-root/...여도 마운트를 요구하거나 해당 경로에 기록을 만들지 않습니다.
  새 설치에서 GENOS_RUNTIME_DIR을 생략하면 /__oracle_agent__/runtime을 사용합니다.
  기존 이력을 이어 쓸 경우에는 과거 기록에 결속된 정확한 절대 경로를 유지합니다.
  경로 또는 GENOS_ORACLE_AGENT_NAMESPACE를 바꾸면 다른 이력 공간으로 보입니다.
  namespace 기본값은 genos-rag입니다. 임의로 요청마다 바꾸지 않습니다.

기존 NFS 이력 이관
  신규 요청의 Oracle 저장과 과거 기록 이관은 별개입니다. 서빙 시작 때 자동 이관하지 않습니다.
  모든 기존/신규 기록 writer를 정지한 뒤, 기존 트리를 읽기 전용으로 이관합니다.
  예시는 배포 코드 루트에서 실행하며 기존 Oracle 환경변수/동일 namespace를 사용합니다.

  PYTHONPATH=02_BACKEND python3 -m semantic_runtime.oracle_records_migration \
    --source /실제/기존/runtime \
    --logical-root /기존/기록에/결속된/runtime \
    --writers-stopped \
    --receipt /감사결과/새파일.json

  --logical-root는 GENOS_RUNTIME_DIR 등 현재 설정한 논리 루트와 같아야 합니다.
  GENOS_STATE_DIR/GENOS_SHARED_LOG_DIR이 별도 트리라면 정지 상태에서 각 루트도 이관합니다.
  원본 파일과 해시를 보존하고 typed 행/rowid/PK/NULL/빈문자/BLOB/압축 참조를 이관합니다.
  lock/WAL/SHM 같은 제어 부속물은 데이터 행으로 복사하지 않으며 원본에 보존합니다.
  원문·색인 SQLite는 Agent 이관에서 제외합니다. 이미 Oracle 지식 게시 경로를 사용합니다.
  중단 시 같은 원본과 설정으로 재개합니다. 불완전 이관은 Oracle 서비스가 거절합니다.
  원본 변경이나 기존 다른 Oracle 이력과 충돌하면 덮어쓰지 않고 중단합니다.
  기존 코드·원문·권한 결속이 달라진 요청의 자동 재개는 허용하지 않습니다.
  실제 현장 NFS 이력의 전량 이관은 이 코드 검증에 포함되지 않았습니다.

검증 범위와 한계
  CODE_STATUS.json과 연결된 감사 결과를 확인합니다. 로컬 실제 Oracle SQL 및 모의 모델로
  기록·원문·중복 요청·출처 재조회·이관을 검증했습니다. 실제 GENOS/현장 ORDS·Oracle19·
  실제 LLM·다중 인스턴스 부하·대용량 기록 지연은 아직 별도 검증이 필요합니다.
  기록 네임스페이스를 메모리로 복원하므로 대형 대화/조사 공간에서 비용이 증가할 수 있습니다.
  GENOS_ORACLE_AGENT_MEMORY_MIB 기본256MiB이며, 초과 데이터는 잘라 성공 처리하지 않습니다.
  1초 응답이나 NFS보다 빠른 성능을 보장하지 않습니다.
  Dataiku/S3의 지식화 배치 진행·전송 기록 책임은 기존과 같습니다.

되돌림
  이전 MAIN과 기존 NFS 원본을 보존합니다. Oracle 쓰기 이후 DP=nfs로 되돌리면 NFS에 남은
  과거 이력을 보게 됩니다. Oracle에서 새로 생긴 이력이 NFS에 자동 역복사되지는 않습니다.
  별도 기록 대조/이관 없이 서로 다른 저장소의 상태를 섞어서 재개하지 않습니다.
