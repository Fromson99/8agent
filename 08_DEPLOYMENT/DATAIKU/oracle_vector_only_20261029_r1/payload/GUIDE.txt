설치·실행 (현장 LEGAL_RAG에서 수행)
1. 기존 00~03 및 구/신 벡터 작업이 실행 중이면 종료 상태를 먼저 확인한다.
   이전 이관을 실행하는 예약 시나리오도 중지한다. Zone 이동만으로 예약 실행이 꺼지지 않는다.
2. 01_ORACLE_STATUS.sql로 COMPLETE 조회 판본과 연결된 완료 원문 판본을 확인한다.
   사용할 SRCH_PBLS_ID를 선택한다. 여러 판본 중 최신 날짜만으로 자동 선택하지 않는다.
3. 다음 기존 Oracle 테이블을 가리키는 외부 데이터셋 3개가 있어야 한다.
   LGL_SRCH_PBLS_S / LGL_VCTR_SET_S / LGL_VCTR_ITEM_S
   연결 AIDP(프로젝트 LEGAL_ORACLE_CONNECTION이 있으면 그 값), schema SIDDS,
   mode table, managed=false. 사진 1의 이 이름을 그대로 사용한다.
   다른 레시피의 출력인 LEGAL_OUT_... 별칭 대신 생산 레시피가 없는 입력 등록을 사용한다.
   누락됐다면 기존 테이블을 연결한다. 새 테이블 생성이나 덮어쓰기가 아니다.
4. ORACLE_VECTOR_ONLY_CODE_20261029_R1.zip을 기존 ehA8dpVm 루트에 업로드한다.
   새 Python 노트북 커널에서 DATAIKU_INSTALL.txt의 QUERY_RELEASE_ID를 채워 실행한다.
   기존 LEGAL_VECTOR_PROFILE이 있으면 모델 항목은 공란으로 둔다.
   없으면 내부 모델명·불변 버전·차원과 기존 GENOS 임베딩 프로젝트 변수가 필요하다.
   이 설치는 DB SQL/임베딩을 실행하지 않는다. 기존 R3에서 만든 R4 코드만 교체한다.
   현장 코드가 다르면 변경하지 않고 FLOW_EXISTING_RECIPE_CONFLICT로 끝난다.
   기존 레시피 코드·입출력은 결과 폴더 flow-backup/<hash>.json에 먼저 보존한다.
5. 같은 노트북에서 DATAIKU_RUN.txt의 ACTION="check"를 실행한다.
   DB/원문/모델 연결을 확인하며 임베딩 호출과 벡터 쓰기는 하지 않는다.
   성공하면 기존 R4 레시피만 Run 하거나 ACTION="build"로 실행한다.
   00~03 전체 Build는 필요 없다. 두 경로를 동시에 실행하지 않는다.
6. READY와 PUB_ID/문서·구간 수를 확인한다. GENOS가 이미 6컬럼 R3 조회 패치를
   사용해야 새 SET/ITEM을 검색할 수 있다. 이번 Dataiku 정리는 GENOS 코드를 변경하지 않는다.

사진의 Flow 정리
- '벡터 적재' Zone: LGL_SRCH_PBLS_S, 기존 R4 레시피, SET/ITEM 데이터셋, R4 결과 폴더.
  평소 이 Zone을 펼쳐 사용한다. ehA8dpVm은 코드 보관용으로 유지한다.
- '이전 이관 보관' Zone: 00 연결확인, 01 ZIP 해제, 02 구조화, 03 실버 적재,
  RAW/STRUCTURED/LOAD/연결 결과 폴더와 LEGAL_OUT_... 출력 별칭.
  작업 원본·실패·완료·재개 기록을 가진 폴더는 보존한다.
- 나머지 원문 테이블 등록은 '오라클 원문' Zone에 둔다.
- DATAIKU_INVENTORY.txt는 현재 프로젝트의 실제 테이블 연결과 입출력을 출력한다.
  같은 AIDP/SIDDS/테이블을 가리키는 LGL_...와 LEGAL_OUT_LGL_...가 있으면
  등록 노드가 두 개인 것이며 물리 테이블이 두 개라는 뜻은 아니다.
  중복 데이터셋 삭제는 레시피·시나리오·다른 프로젝트 참조를 확인한 뒤 등록만 제거한다.
  물리 데이터 삭제 옵션은 선택하지 않는다.

  LGL_FILE_PART_S: 기존 자산 복원/이관/롤백 경로가 참조한다.

  SIDDA의 예전 LEGAL_*: 과거 이름만으로 미사용 판정 불가. 실제 owner 매핑·접속자 확인 필요.
  SIDDA.LGL_EXEC_ST_A: Agent 실행 상태 영역. 벡터 적재와 별개라 이번 정리 대상에서 제외.

증명하지 않으므로 결과가 비었다고 미사용으로 판단하지 않는다. DROP SQL은 포함하지 않았다.

- 설정/판본/해시 불일치: 모델 호출 전에 수정할 항목을 확인한다. 가짜 완료기록을 만들지 않는다.

- 복귀: R4 결과 폴더의 flow-backup JSON에 저장된 레시피 코드와 입출력을 복원한다.
  원문·벡터 데이터와 이전 적재 레시피는 설치 과정에서 삭제하지 않는다.
