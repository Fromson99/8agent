전체 원문·용어집·색인 데이터 Oracle 이관 / 2026-10-20 R1

이번 전체 이관에는 LEGAL_ORACLE_FULL_PARTS_20261020_R1.zip을 사용합니다.
앞서 보낸 LEGAL_ORACLE_QUERY_PARTS_20261020_R1.zip은 추가 조회 데이터만 반출하는 별도 방식입니다.
두 묶음의 코드·조각·manifest·작업 폴더를 섞지 마세요.
메일의 ZIP은 코드입니다. 운영 데이터는 코드스페이스에서 아래 명령으로 생성합니다.

1. 범위와 바뀐 점
사용자가 확인한 '기존 추가본과 같은 위치'의 generation을 그대로 입력으로 받습니다.
기존 방식: 코드스페이스에서 추가 query-data.db만 생성 → Oracle의 기존 원문 완료 릴리스에 붙임.
이번 방식: 같은 generation의 전체 원문 DB + 등록된 모든 navigation/fulltext/glossary 자산 + 검색 선택표를 원본 바이트 그대로 압축 → Dataiku에서 복원 → 기존 원문·자산·조회 적재 엔진을 순서대로 실행.
샘플·문서 수 제한·팀 필터로 반출 범위를 줄이지 않습니다. 검색 선택표가 구버전 노출을 제한하더라도 원본 DB 전체를 보존합니다.
질의용 행은 Dataiku에서 기존 publisher로 생성하므로 반출 쪽에 대형 query-data.db를 추가로 만들지 않습니다.
다른 generation, RAW 원본 PDF/Office, 감사·실패 원장, runtime 대화/대사 DB와 작업 코드 전체를 섞어 압축하는 방식은 아닙니다.
manifest에 선언된 vectors는 현행 이관 계약에서 지원하지 않아 조용히 누락하지 않고 중단합니다.
현재 선택 generation 자체가 실험용 일부 문서만 가진 경우 이 도구가 없는 문서를 추가하지 않습니다. check 결과의 실제 문서 수/파일 목록이 의도한 전체 범위인지 확인합니다.

2. 코드스페이스 실행
첨부 ZIP을 실제 업로드한 TRANSFER 폴더에서 실행합니다. TRANSFER의 절대 위치를 추정하거나 먼저 DEV로 이동하지 않습니다.

python3 -m zipfile -e ./LEGAL_ORACLE_FULL_PARTS_20261020_R1.zip ./full-transfer-tools
bash ./full-transfer-tools/LEGAL_ORACLE_FULL_PARTS_20261020_R1/CODESPACE_FULL_50MB_RUN.txt check --output /workspace/FULL_TRANSFER_20261020_R1
bash ./full-transfer-tools/LEGAL_ORACLE_FULL_PARTS_20261020_R1/CODESPACE_FULL_50MB_RUN.txt export --output /workspace/FULL_TRANSFER_20261020_R1

기본 입력 경로(기존 추가본과 동일):
/nfs-root/diamo/8-agent/term-releases/financial-risk-success-20261005-schema-r2/generation
실제로 추가본에 --generation 다른경로를 사용했다면 위 check/export에도 같은 --generation 실제경로를 붙입니다.
최신 폴더/여러 실험 폴더를 자동 탐색해 합치지 않습니다.
이 데이터 도구는 ~/DEV에 코드를 설치하지 않습니다. Git push나 코드서빙 리비전 변경 없이 반출만 합니다.

check: 실제 문서/단위/본문 건수, 파일 수·크기·해시, 디스크 확인.
export: 전체 데이터 ZIP → 최대 49,000,000바이트 조각. 성공 상태 FULL_EXPORT_COMPLETE.
완성 파일은 /workspace/FULL_TRANSFER_20261020_R1/download 아래에 있습니다.
- full-data.zip.part000001, part000002 ... 마지막 조각까지 전부
- parts-manifest.json
왼쪽 workspace 파일 목록에서 위 파일 각각을 우클릭 → Download로 받습니다.
각 조각은 단독 ZIP이 아닙니다. 개별 압축해제하지 마세요. 폴더 전체 다운로드로 다시 큰 ZIP을 만들지 마세요.
원본/자산/선택표와 각 조각 및 전체 ZIP에 SHA-256을 기록합니다.
로그는 실행한 TRANSFER의 ./full-transfer-command-logs와 출력 폴더 events.jsonl/export-state.json입니다.

3. Dataiku 업로드와 실행
Managed Folder 최상위에 아래를 모두 업로드합니다.
- LEGAL_ORACLE_FULL_PARTS_20261020_R1.zip (작은 실행 코드)
- download의 모든 full-data.zip.partNNNNNN
- parts-manifest.json
추가본용 조각/query-data.db는 필요하지 않습니다.
새 Python 노트북/새 커널을 사용합니다. SQL 노트북에 Python을 붙이지 않습니다.
별도 첨부 DATAIKU_FULL_IMPORT_RUN.txt 전체를 한 셀에 붙이거나 ZIP 안의 DATAIKU_FULL_IMPORT.ipynb를 가져옵니다.
설정:
FOLDER_ID: 실제 Managed Folder ID
ORACLE_CONNECTION: 기존 SIDDA 테이블을 조회하는 Dataiku Oracle 연결 이름
WORK_DIR: 충분한 공간이 있는 쓰기 가능한 영속 작업 폴더. 기본 ./legal-full-transfer-work.
재실행/커널 재시작에도 WORK_DIR를 유지합니다. 새 전체 데이터/다른 버전은 별도 WORK_DIR를 사용합니다.
비밀번호를 코드에 입력하지 않습니다. Dataiku의 기존 연결을 재사용합니다.

ACTION = "restore"  : 조각·ZIP·모든 원본 파일 해시 검증과 복원
ACTION = "check"    : 원본 건수/해시 및 기존 9개 테이블·조회 인덱스 검사. Oracle 쓰기 없음
ACTION = "publish"  : 전체 적재와 최종 전체 읽기 대조
ACTION = "status"   : Oracle을 다시 읽어 원문·자산·조회 데이터 전체 대조. 데이터 쓰기 없음
ACTION 값을 바꿀 때마다 같은 셀 전체를 실행합니다.

publish 내부 순서:
(1) 원문 문서/document → 구조단위/source_unit → 본문/block_payload
(2) 원문 전체 행 재조회 및 건수·내용 대조
(3) 용어집·navigation·fulltext 등 등록 자산을 기존 ASSET_PART에 저장, RELEASE 게시
(4) 같은 데이터에서 구조·용어·참조·전문검색 토큰 위치 등 QUERY_ROW 생성, QUERY_RELEASE 게시
(5) 원문 전체 행, 자산의 모든 조각/전체 파일 해시, 조회 전체 행/총건수, 양쪽 릴리스 결속을 다시 검사
최종 상태 FULL_DATA_VERIFIED만 전체 적재/대조 완료입니다.
SOURCE_COMPLETE나 자산 게시 완료 메시지는 중간 단계입니다.
결과의 source_release_id, query_release_id, source_counts, asset_files, query_rows를 보관합니다.

4. 테이블별 기록
SIDDA.LEGAL_SRC_DOCUMENT_A: 전체 문서 정보
SIDDA.LEGAL_SRC_SOURCE_UNIT_A: 전체 구조 단위/부모 연결
SIDDA.LEGAL_SRC_BLOCK_PAYLOAD_A: 전체 본문 블록
SIDDA.LEGAL_RAG_ASSET_PART_A: 등록 자산의 압축 조각
SIDDA.LEGAL_RAG_RELEASE_A: 원문+자산 완료 릴리스
SIDDA.LEGAL_RAG_QUERY_ROW_A: Oracle에서 직접 읽는 전체 조회 행
SIDDA.LEGAL_RAG_QUERY_RELEASE_A: 조회 완료 릴리스
SIDDA.LEGAL_RAG_QUERY_ACTIVE_A: 이관에서는 변경하지 않음. 검증된 버전을 서빙에 선택하는 별도 단계
SIDDA.LEGAL_RAG_QUERY_STATE_A: 이관에서는 변경하지 않음. 대화/대사 운영 이력 자동 변환 없음
테이블 생성/삭제/TRUNCATE 없음. 기존 버전은 유지하고 동일 내용은 대조 후 재사용합니다.
기존 키에 다른 값이 있으면 덮어쓰지 않고 중단합니다.

5. 중단·재개·공간
큰 데이터 작업을 동시에 실행하지 않습니다. 스트리밍 1MiB, 기존 원문/조회 작은 배치, Dataiku에서 한 실행만 사용합니다.
코드스페이스: 원본 외에 ZIP+동일 크기 조각이 필요합니다. 복사한 generation이나 추가 대형 query DB는 만들지 않습니다.
Dataiku: 다운로드 조각+합친 ZIP+복원 generation+로그가 필요합니다. 합성 테스트 용량을 운영 용량 예상으로 사용하지 않습니다.
가용 디스크/RAM이 512MiB 미만이면 감지 지점에서 멈춥니다. 이는 전체 실행에 충분한 용량 보장이 아닙니다.
코드스페이스 데이터 프로세스 주소 공간 한도 6GiB, 현장 최대 메모리/시간은 미측정입니다. Dataiku는 기존 커널 자원 한도를 따릅니다.
한 실행 기본 반출 6시간/적재 1시간. 첫 작업 이후 7일 deadline을 유지하며 재실행해 초기화하지 않습니다.
SQL 저널별 누적 100만 호출 제한. 전체 coordinator 7일 제한과 단계별 제한 모두 적용됩니다. 해시/투영 중 시간 제한은 경계에서 확인될 수 있습니다.
자동 재시도는 없습니다. 중단 원인을 확인한 뒤 같은 명령 또는 ACTION으로 다시 실행합니다.
완성 ZIP 전 압축 중단은 압축부터 다시 시작합니다. 부분 파일은 실패 이력으로 남습니다. 완성 ZIP/조각은 해시 확인 후 재사용합니다.
Dataiku 원문/자산은 저장된 위치부터 재개합니다. 조회 적재는 이미 저장된 앞 행도 재대조합니다. 최종 전체 대조는 처음부터 재실행합니다.
쓰기 성공 응답이 유실되면 실패로 남기며 다음 실행에서 기존 행을 확인합니다. 쓰기 안 됐다고 추정해 덮어쓰지 않습니다.
코드/입력/대상 변경, 해시 불일치, 키 충돌은 기록을 보존한 채 중단합니다. 로그/상태를 지워 성공으로 만들지 않습니다.
SOURCE_SCHEMA/NAVIGATION_BINDING 등은 다른 세대나 잘못된 manifest일 수 있으므로 원본을 수정하지 않습니다.
원본·실험 데이터·원격 기존 버전·실패 기록을 자동 삭제하지 않습니다.

6. 이관 완료와 서빙 전환 구분
FULL_DATA_VERIFIED는 Oracle 데이터 적재/대조 완료입니다.
QUERY_ACTIVE 선택, GENOS Oracle 조회 환경 설정/코드서빙 리비전, 워크플로우 시험은 별도입니다.
이관용 Dataiku 복원 DB는 반입 작업 파일입니다. GENOS 서빙이 전체 DB를 다운로드/상주 캐시하도록 바꾸는 작업이 아닙니다.
검증된 결과와 현장 실제 실행 여부는 동봉 VALIDATION.json을 참고합니다.
