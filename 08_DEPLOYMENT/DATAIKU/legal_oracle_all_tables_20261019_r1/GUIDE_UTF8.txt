Oracle 전체 9테이블 생성 SQL — 2026-10-19 R1

사용할 파일
LEGAL_ORACLE_ALL_9_TABLES_20261019_R1.sql
LEGAL_ORACLE_ALL_9_TABLES_20261019_R1.txt
두 파일의 내용은 동일합니다. 기존 5개와 추가 조회 4개의 전체 생성문입니다.
추가 조회 인덱스 4개, 생성 전후 메타데이터 확인 SQL, 주석 처리된 권한 예시가 포함됩니다.
이전 추가 2개/4개만의 생성문을 조합하는 대신 이번 전체본을 사용합니다.
이미 만들어진 객체는 구조를 대조하고 해당 CREATE만 건너뜁니다.

압축 해제
받은 ZIP을 압축 해제해 SQL 또는 TXT를 엽니다.
GENOS Linux 코드스페이스에서 풀 경우, 실제 업로드한 TRANSFER 폴더를 현재 위치로 두고:
python3 -m zipfile -e ./LEGAL_ORACLE_ALL_9_TABLES_20261019_R1.zip ./legal-oracle-all-9-20261019-r1
압축 해제는 파일을 꺼내는 작업이며 Oracle 테이블을 만들지는 않습니다.
TRANSFER의 절대 위치를 새로 가정하거나 먼저 DEV로 이동할 필요가 없습니다.

실제 SQL 실행
1. Dataiku의 SQL 노트북에서 AIDP 연결을 사용합니다.
2. SIDDA 소유자 또는 해당 스키마의 생성 권한을 가진 계정으로 진행합니다.
3. SQL/TXT의 00번 SELECT를 먼저 실행해 기존 객체를 확인합니다.
4. 없다고 확인한 객체의 CREATE TABLE/CREATE INDEX를 번호 순서대로 실행합니다.
   각 SQL 문장을 별도 Query로 실행합니다. 전체 파일을 단일 Query에 넣지 않습니다.
5. 14~17번 확인 SQL로 9테이블, 46컬럼, 제약조건, 조회 인덱스 4개를 확인합니다.
6. 18번 GRANT는 주석입니다. 권한 담당자가 실제 작업 계정을 확인한 뒤 필요한 문장만 실행합니다.

이 TXT/SQL은 SQL 노트북용입니다. bash로 실행하거나 Python 셀에 붙여넣지 않습니다.
동일 이름이 이미 있거나 응답이 유실되면 구조를 다시 확인합니다.
기존 객체가 다르면 자동 삭제/수정하지 않습니다. 접근 권한 부족을 객체 부재로 보지 않습니다.
테이블 owner는 SIDDA이며 ORDS 접속 별칭 b04와 구분합니다.

범위와 확인 결과
현재 코드의 유지 DDL과 9개 테이블/4개 인덱스를 대조했습니다.
SQL/TXT 바이트가 동일하며 ZIP 내부에 JavaScript 파일은 없습니다.

데이터 이관, 조회 데이터 게시, main 채널 활성화와 GENOS 코드 배포는 별도입니다.
