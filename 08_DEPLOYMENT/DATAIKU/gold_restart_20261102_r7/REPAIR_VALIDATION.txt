R7 수정·검증 기록 / 2026-11-02
증상: 현장 R6 reset_source.py에서 RESET_REFUSED_MORE_THAN_10000_SOURCE_ROWS.
코드 근거: R6는 type(n) is not int와 합계 >10000을 동일 오류로 처리. 오류만으로 현장 실제 분기 확정 불가.
이전 화면 완료 3854행은 checkpoint로 현재 DB COUNT 아님.
수정: exact integral count 정규화, 임의 합계 10000 제한 제거, 원본 manifest 표별 범위 확인,
실제 COUNT/DB 반환형/원본 기준 표시, 임의 전체 백업 512MiB 제한 제거 및 4MiB 목표 묶음 분리.
보존: 이번 원문 세대·3표 범위, 원본·코드·DB binding, 이전 상태 및 백업,
동일 내용/PK 확인 후 DELETE, 공개·검색·벡터 이력 차단, reset_id 중복 초기화 방지.
R6 인계: 정확한 알려진 helper hash 및 BACKING_UP/삭제 전/manifest 없음만 허용,
기존 state/hash/backup 확인 뒤 기존 controller 바이트 별도 백업, 같은 초기화 ID 유지.
최초 검사: 테스트 fixture가 production의 20행 페이지 대신 전체10002행을 반환하여 BATCH_SIZE 실패,
COUNT 함수를 fixture가 덮어써 직접 정규화 테스트 실패, 생성 전 R6 파일명을 참조해 파일 없음 실패.
제품 코드를 완화해 숨기지 않고 fixture 페이지와 실제 함수 참조 및 R7 파일명을 수정하고 build 실행.
최종 같은 실행기: pytest 69 passed in 2.62s.

합성 fixture 두 표 생성/제거만 수행, 기존 사용자 데이터/현장 DB/MAIN/모델 호출 변경0.
