Dataiku 적재 빠른 진단 R1 — 캡처용 읽기 전용

대상: Dataiku LEGAL_RAG 프로젝트에서 실행 중인 기존 NFS→Oracle R8/R9/R10 적재.
이번 첨부는 진단 코드입니다. 고속 적재 수정본이나 적재 재개 코드는 아닙니다.

첨부 3개
1. DATAIKU_NFS_QUICK_DIAG_20261031_R1.zip — 실제 진단 코드
2. DATAIKU_NFS_QUICK_DIAG_RUN_R1.txt — 노트북에 붙여넣을 전체 실행 코드
3. GUIDE.txt — 이 안내

실행 순서
1. ZIP을 압축 그대로 기존 반입 관리 폴더 ehA8dpVm에 업로드합니다.
   기존 적재 ZIP과 자료를 삭제하거나 교체하지 않습니다.
2. LEGAL_RAG에서 별도의 조회용 Python 노트북을 엽니다.
   적재 중인 노트북의 셀에 붙이면 현재 작업 뒤에서 기다리므로 별도 커널을 사용합니다.
   기존 로그 조회가 되던 같은 실행 환경과 LEGAL_PIPELINE_SCRATCH 설정을 사용하세요.
   적재 중인 커널을 Interrupt/Restart하지 않습니다.
3. DATAIKU_NFS_QUICK_DIAG_RUN_R1.txt 전체를 새 Python 셀에 붙여 한 번 실행합니다.
   Bash나 터미널 명령이 아닙니다. ZIP 압축 해제나 작업 디렉터리 변경은 필요 없습니다.
4. 기본 출력은 요약 15줄 + 상세 9줄(제목 포함)입니다. 1~2장으로 캡처하세요.
   상세를 생략하려면 TXT 상단 SHOW_DETAIL = False로 바꿉니다(요약 15줄만).
5. 기록이 안 보이면 그 출력만 보내주세요. 파일이 없다는 이유로 작업을 재시작하지 않습니다.

출력 해석
05: 저장된 준비 명세의 전체 검색행수. 원문 3테이블 건수와 구분합니다.
06: 누적 재개 묶음 번호. 각 묶음은 1~20행이며 실제 500행 요청수와 다릅니다.
07: 완료된 묶음당 행수가 별도로 남지 않아 1~20행 범위로 계산한 남은 행수.
    기존에 끝낸 작업을 버리거나 20×묶음수를 정확한 완료 행수로 간주하지 않습니다.
08: 최근 최대10분의 실제 적재 속도. 재시작 전후를 섞지 않습니다.
09: 그 속도가 유지될 때의 남은 검색행 적재 예상 범위. 전수검증은 제외합니다.
    마지막 기록이90초 넘게 오래됐거나 표본이60초 미만이면 ETA를 내지 않습니다.
10/D: 최근 Oracle 요청의 경과 시간. Dataiku/JDBC/전송/DB 및 기록 경계가 포함됩니다.
    DB CPU 시간만을 뜻하지 않으며 검사·네트워크·INSERT 각각의 비중은 알 수 없습니다.
11/C: 성공 응답 없는 요청이 보이면 실행 중/응답 유실/중단 여부는 이 기록만으로 구별 불가.
FTS_POSTINGS_SORT 표시는 Oracle 적재 중에도 남아 있을 수 있습니다.

범위
저장된 JSON 3개와 로그 끝부분만 제한해서 읽습니다.
DB SQL/Oracle COUNT/GENOS 요청, 원문 SQLite 열기·재정렬, 적재/재개, 파일 쓰기/삭제를 하지 않습니다.
원시 로그·본문·접속 정보는 출력하지 않습니다. 자동 반복·대기·화면 로그 폭증도 없습니다.
관리 폴더 ZIP을 한 번 읽고, 기존 로컬 기록을 읽습니다. 데이터 재수신은 아닙니다.
로컬 합성 검증과 현장 실행은 별개입니다. 현장 결과는 캡처로 확인해야 합니다.

중단·재개
이 조회를 다시 실행해도 적재를 재시작하지 않습니다.
조회 셀에 오류가 나더라도 기존 적재 커널을 중단하거나 재개 기록을 지우지 마세요.
큰 ZIP/데이터 사본이나 추가 DB 표를 만들지 않습니다.
