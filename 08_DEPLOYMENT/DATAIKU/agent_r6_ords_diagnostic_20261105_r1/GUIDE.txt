R6 WAIT_AGENT COMPUTE_FAILED_DPERROR 진단 R1

사진에서 확인한 상태
01_SUBMIT는 성공했고 02_WAIT_AGENT가 GENOS의 FAILED/COMPUTE_FAILED_DPERROR를 받았습니다.
R6 코드에서 이 예외 형식은 원문 worker를 시작하기 전 ORDS 사전 점검의 DPError에
해당합니다. 접속 클라이언트 생성·인증·SQL 응답·Agent 접근 중 상세 실패는 현재
사진의 단일 오류명에 남아 있지 않습니다. Agent 결과 저장 실패였다면 별도
STAGE_PENDING/AGENT_WRITE_*로 표시하므로 현재 단계와 구분합니다.

다음 파일은 원인 확인용입니다. 권한이나 테이블을 바꾸는 수정본이 아닙니다.
Dataiku의 AIDP 연결 정보는 GENOS로 자동 전달되지 않습니다.
GENOS는 자신의 ORACLE_ORDS_* 환경 설정과 ORDS 실행 계정으로 SIDDA에 접근합니다.

실행 환경
실패한 GENOS pipeline 코드서빙과 같은 Python·ORDS 환경변수·접속 경로에서 실행합니다.
코드스페이스에서 실행할 경우 코드서빙 리비전의 환경과 같은지 먼저 대조합니다.
코드스페이스에 환경변수가 없어서 실패한 결과를 실제 서빙 환경 오류로 해석하지 않습니다.
Dataiku 노트북에 붙이는 파일이 아닙니다.

실행
GENOS_R6_ORDS_CHECK_R1.txt를 pipeline 코드스페이스의 TRANSFER에 놓습니다.
그 폴더에서 다음 명령을 한 번 실행합니다.

  bash ./GENOS_R6_ORDS_CHECK_R1.txt

현재 디렉터리·~/DEV·상위 디렉터리에서 원래 R6 CODE_PINS.json의 정확한 해시를
찾고, 선택한 코드의 모든 pin 파일 바이트를 검증합니다.
자동으로 찾을 수 없으면 실제 R6 경로를 지정합니다.

  bash ./GENOS_R6_ORDS_CHECK_R1.txt --code-root /실제/R6/경로

ORDS 접속 설정은 기존 환경값을 사용합니다. 비밀번호나 토큰을 코드에 붙이지 않습니다.
확인하는 변수 이름은 ORACLE_ORDS_SCHEMA, ORACLE_ORDS_CLIENT_ID,
ORACLE_ORDS_CLIENT_SECRET이며, BASE_URL은 기존 ORACLE_ORDS_BASE_URL 또는
LLMOPS_ORDS_BASE_URL 설정을 확인합니다. 출력에는 값 대신 설정 유무만 표시됩니다.

검사와 출력
DB_IDENTITY          실제 접속 계정·현재 스키마·DB 이름 SELECT
AGENT_SELECT         SIDDA.LGL_PIPE_RESULT_A에 WHERE 1=0으로 조회 권한 확인
R6_EXACT_PREFLIGHT   원래 R6의 SELECT/INSERT 컴파일 점검을 동일하게 실행
최대3 SQL이며 첫 실패에서 종료합니다. 마지막 검사의 INSERT는 원래 R6와 같은
IF FALSE 분기 안에 있어 행을 넣지 않습니다. 모델·RUN·PUBLISH·DDL을 호출하지 않습니다.

터미널에 ORDS_DIAGNOSTIC으로 시작하는 JSON 한 줄이 나옵니다.
실행 디렉터리의 r6-ords-diagnostic-날짜-식별자/diagnostic.json에도 같은 결과가 남습니다.
이 JSON을 확인하면 실패 검사명과 HTTP 상태/Oracle 오류 번호를 볼 수 있습니다.
원문·SQL 값·비밀번호·토큰·원래 서버 오류 본문은 출력하지 않습니다.

결과 해석
configuration_present의 false   이 실행 환경에 해당 설정이 없음
DP_CONFIG / DP_CONNECT          기본 URL·별칭 형식 또는 SDK 구성 점검
HTTP 401 / 403                  ORDS 인증·접근 설정 점검
ORA-00942                       대상 테이블·소유자·실제 접속 DB 또는 조회 권한 점검
ORA-01031                       실제 ORDS 실행 계정의 권한 점검
ORA-06550                       PL/SQL 컴파일 오류. response_metadata의 함께 나온 ORA 번호 확인
RESPONSE_SHAPE                  실제 SDK/ORDS 응답 형식 점검
EXACT_R6_CODE_ROOT_NOT_FOUND     실행 위치가 원래 R6 checkout인지 확인

세 검사 PASS는 이 실행 환경에서의 사전 점검 성공입니다. 원래 실패한 리비전과 환경이
같은지 대조해야 하며 전체 파이프라인/실모델/운영 Gold 성공으로 해석하지 않습니다.
현재 실패한 trial과 로그를 보존합니다. 이 진단은 기존 실패 job을 재계산하거나
새 trial로 바꾸지 않습니다. 실제 오류가 확인된 뒤 해당 원인에 맞춰 복구합니다.
