Dataiku 임시 디스크 점유 확인과 중복 압축 사본 정리 R1

첨부 파일
- DATAIKU_TEMP_CLEANUP_20261030_R1.zip: 정리 코드 사본
- CLEAN_DATAIKU_TEMP.txt: 노트북에 붙여 실행할 전체 Python 코드
- GUIDE.txt: 이 실행 안내

실행 위치
LEGAL_RAG 프로젝트의 기존 오류 난 Python 노트북에서 실행합니다.
기존 적재/검증 셀과 같은 데이터를 쓰는 다른 노트북/레시피가 종료된 상태에서
새 셀에 CLEAN_DATAIKU_TEMP.txt 전체를 붙여 넣고 실행하세요.
ZIP 업로드/설치, 커널 재시작, 경로 변경은 필요하지 않습니다.
ZIP은 동일 실행 코드의 전달용 사본입니다. 기존 R6B ZIP을 대체하지 않습니다.

하는 일
1. /tmp, /var/tmp, /usr/tmp 및 기존 LEGAL_PIPELINE_SCRATCH를 조사합니다.
   파일 내용 대신 파일 크기/실제 할당량을 읽어 큰 폴더와 파일 30개를 표시합니다.
   심볼릭 링크, 다른 파일시스템, 다른 소유자의 하위 폴더는 따라가지 않습니다.
   경로별 최대 20만 파일/60초 범위여서 한도/권한에 걸리면 부분 목록이라고 표시합니다.
2. 아래 두 종류만 검사한 뒤 조건을 모두 만족하면 그 압축 파일만 삭제합니다.
   - legal-recipes-*/package.zip: 확인된 R5/R6/R6B 배포 ZIP 해시이며,
     압축 안의 모든 파일이 옆 code/에 같은 바이트로 남아 있는 경우.
   - 현재 financial-risk-success-20261005-schema-r2 작업 루트의
     oracle-receipts.zip 또는 saved-oracle_*_blob-<hash>.zip:
     모든 JSON/JSONL이 oracle-import-r2/ 또는 oracle-import/에 동일하게 남은 경우.
   원본과 다르거나 누락된 사본, 최근 10분 이내 파일, 열린 파일,
   동일 사용자 프로세스 조회 권한이 부족한 경우는 삭제하지 않습니다.
3. 삭제한 경로와 크기, 정리 전후 여유 공간을 표시합니다.
   이미 지워졌지만 프로세스가 열고 있는 파일도 별도로 표시합니다.

보호하는 것
generation 전체, store.sqlite, fulltext/units.sqlite 등 검색 색인,
추출한 code/, full-state.json/체크포인트/SQL 기록/실패 기록,
종류를 확정하지 못한 ZIP과 임시 파일, Oracle/S3/NFS 원본.
폴더 통째 삭제, 프로세스 종료, DB 접속, 모델 호출은 없습니다.
S3나 다른 디스크로 데이터를 이동하지 않으며 TMPDIR 설정도 바꾸지 않습니다.

결과 읽기
마지막 CLEANUP_RESULT의 다음 항목을 확인하세요.
- inventories[].largest_directories / largest_files: 실제 큰 점유자
- deleted_archive_count: 실제 삭제한 중복 압축 파일 수
- actions: DELETED_DUPLICATE 또는 PRESERVED와 사유
- free_GiB_before / free_GiB_after: 관측된 여유 공간
- open_deleted_files: 프로세스 핸들이 남아 있어 아직 회수되지 않은 파일

그 결과의 큰 폴더/파일 목록과 여유 공간을 전달해 주세요.
현재 사진만으로는 어떤 대용량 파일을 삭제해야 하는지 아직 확정할 수 없습니다.
이 스크립트는 이름만 보고 오래된 원본/색인/실패 작업을 지우지 않습니다.
큰 점유자가 현재 generation이면 이번 압축 사본 정리만으로는 해결되지 않습니다.
정리 결과가 0건이거나 공간이 적게 늘어도 적재 전체를 바로 다시 실행하지 마세요.
다음 삭제 대상은 이 실제 목록과 재개 의존성을 확인하여 지정해야 합니다.

중단/재실행
크기 조사 중 중단하면 삭제 전입니다. DUPLICATE_CHECK 이후 중단했다면
이미 출력된 DELETED_DUPLICATE 항목만 삭제됐을 수 있습니다.
현재 원본/체크포인트는 유지되며 같은 정리 셀을 다시 실행할 수 있습니다.

검증 범위
로컬 Python3.11 계약14개 통과. 삭제 성공 검사는 격리 임시 파일과
프로세스가 모두 보인다는 모의 조건에서 실행했습니다. 실제 열린 파일 거절과
실제 로컬 /proc 권한 부족 시 삭제 보류도 확인했습니다.
내부 Dataiku에서의 파일별 점유량/삭제량/적재 재개 성공은 아직 미확인입니다.
