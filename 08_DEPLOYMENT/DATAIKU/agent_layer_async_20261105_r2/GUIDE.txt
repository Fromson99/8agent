GENOS Agent Layer 실험 R2 | 로컬에서 압축한 중소기업기본법 1건

무엇을 실행하는가
Dataiku에 올린 LAW_SAMPLE_R2.zip의 원래 바이트 → GENOS 비동기 구조화·검색 색인
→ Oracle SIDDA.LGL_PIPE_RESULT_A → Dataiku가 다시 읽어서 개발 Silver에 적재합니다.
ZIP 안의 법령은 저장소에 수집한 「중소기업기본법」(법률 제21290호, 2026-07-01 시행본) 전체 본문 XML입니다.
파일별 해시·경로 목록도 함께 들어 있습니다. SAMPLE_SUPPORT_R2.zip은 이 한 건에 결속한 소형 시험 용어집과 카탈로그입니다.
두 ZIP은 메일로 받은 이름과 내용 그대로 사용합니다. 예시 경로에서는 Dataiku가 법령 원문을 풀어 새 ZIP을 만드는 과정이 없습니다.

1. 새 GENOS 코드서빙의 Git 저장소에 올리기
새 파이프라인 코드서빙용 Git 저장소와 연결된 코드스페이스를 엽니다. 기존 RAG 채팅이나 운영 서비스의 checkout과 구분합니다.
GENOS_AGENT_ASYNC_R2.zip과 GENOS_DEPLOY_R2.txt 두 개를 TRANSFER에 놓고 그 폴더의 터미널에서 실행합니다.

bash ./GENOS_DEPLOY_R2.txt

기본 대상은 해당 코드스페이스의 ~/DEV와 origin입니다. 다른 새 checkout·remote를 쓴다면 다음과 같이 지정합니다.
bash ./GENOS_DEPLOY_R2.txt /실제/새/checkout 새remote이름

스크립트가 ZIP SHA 확인 → 새 checkout 파일 설치·재검사 → 패키지 파일만 commit → commit blob 해시 대조 → 현재 브랜치 push → 원격 SHA 대조 순서로 실행합니다. Git 계정과 새 저장소의 push 권한이 필요합니다. 같은 명령을 다시 실행해도 동일 코드 commit은 중복 생성되지 않습니다. 이미 다른 service.py 등 동명 파일이 있으면 해당 경로를 출력하고 멈춥니다. 새 checkout인지 확인하고 필요한 기존 템플릿은 별도로 보관합니다.
GENOS_CODE_PUSHED 옆 브랜치와 커밋을 확인합니다. GENOS 화면에서 그 커밋으로 새 코드서빙 리비전을 배포합니다. 진입점은 저장소 루트 service.py의 async service(config, data)입니다. 기존 R10 호환 계산 이미지·requirements.txt, CPU 1/메모리 16GB 기준, worker 1개·replica 1개를 사용합니다.
새 서비스에 ORACLE_ORDS_SCHEMA, ORACLE_ORDS_CLIENT_ID, ORACLE_ORDS_CLIENT_SECRET을 설정합니다. SDK 기본 주소를 쓰지 않는 환경에서는 ORACLE_ORDS_BASE_URL도 지정합니다. 전용 샘플은 지원 ZIP을 Dataiku가 전송하므로 AGENT_PIPELINE_SUPPORT_ZIP과 AGENT_PIPELINE_SUPPORT_SHA256은 비워둘 수 있습니다.

2. Dataiku에 ZIP 세 개를 그대로 올리기
실험 프로젝트 안에서 기존에 업로드 가능한 Managed Folder(S3 또는 Filesystem) 하나를 선택합니다. 그 폴더 최상단에 아래 세 첨부를 올립니다.
  DATAIKU_AGENT_FLOW_R2.zip   Flow 실행 코드·Agent 테이블 설치 Python
  LAW_SAMPLE_R2.zip           로컬에서 압축한 법령 XML 1건과 무결성 목록
  SAMPLE_SUPPORT_R2.zip       이 법령 시험용 용어집·카탈로그
별도의 압축·압축 해제·문서 재저장은 필요 없습니다. 폴더의 실제 ID를 복사합니다.

3. Python 셀 한 번으로 Agent Layer와 Flow 생성
같은 프로젝트의 Python 노트북 새 커널에서 DATAIKU_SETUP_R2.txt 전체를 한 셀에 붙여넣습니다. 맨 위 PARAMS만 현장 값으로 수정합니다.
  CODE_FOLDER_ID        위 세 ZIP을 올린 Managed Folder ID
  WORK_DIR              모든 레시피가 같은 파일 잠금과 디렉터리를 공유하는 영속 POSIX 절대경로
  SETUP_CONNECTION      SIDDA 대상 CREATE TABLE 및 GRANT가 가능한 기존 Dataiku Oracle 연결명
  EXPECTED_SETUP_USER   위 연결이 실제로 로그인하는 Oracle 사용자 이름(대문자)
  GENOS_DB_USER         새 GENOS ORDS가 SQL을 실행하는 실제 Oracle 사용자 이름(대문자)
  AGENT_CONNECTION      Dataiku가 SIDDA에서 다시 읽을 때 쓰는 Oracle 연결명
  TARGET_CONNECTION     개발 Silver 적재용 Dataiku Oracle 연결명
  EXPECTED_DB_USER      TARGET_CONNECTION의 실제 로그인 사용자 이름
  EMBED_MODEL / EMBED_DIMENSIONS  개발 Dataiku 프로젝트의 임베딩 모델과 차원
GENOS_DB_USER는 ORDS 클라이언트 ID나 스키마 별칭과 구분합니다. 운영자 권한과 과제용 계정 이름은 실제 값을 사용합니다. 토큰이나 비밀번호는 셀에 넣지 않습니다. 기본 SAMPLE_ZIP·DEV로 시작합니다.

셀은 첨부 해시와 DB·계정을 확인하고, SIDDA.LGL_PIPE_RESULT_A 한 표를 생성합니다. 기존 표는 컬럼·길이·PK·체크 제약을 검사해 재사용합니다. 지정한 GENOS DB 사용자에게 해당 표의 SELECT·INSERT, Dataiku 읽기 계정에게 SELECT를 부여하고 결과를 확인합니다. 이미 부여된 권한은 재사용합니다. AGENT_LAYER_READY 출력 뒤 새 Flow 구역, 레시피 세 개, 결과 폴더 세 개, 수동 시나리오를 만듭니다. 두 번째 완료 표시는 FLOW_INSTALLED LGL_AGENT_R2_DEV_RUN_ALL입니다.
생성 권한이 없다면 이 단계만 권한이 있는 Dataiku 연결로 실행합니다. 역할 분리 때문에 생성·권한 부여를 담당자가 미리 수행했다면 설치 연결에서 테이블과 직접 부여한 권한을 조회할 수 있어야 합니다.
Silver/Gold 최종 대상은 기존 등록 테이블을 사용합니다. 개발 G19 매핑 13표의 SELECT와 원문·검색·벡터 적재 대상의 INSERT를 미리 확인합니다.

4. Flow 실행 및 결과
Dataiku 레시피에서 get_custom_variables()로 읽을 수 있게 새 코드서빙의 AGENT_PIPELINE_URL(HTTPS), AGENT_PIPELINE_TOKEN을 설정합니다. AGENT_FLOW_TRIAL에는 예를 들어 law-sample-001을 지정합니다. 토큰은 현장 보안 변수 관리 방식을 사용합니다.
Scenarios → LGL_AGENT_R2_DEV_RUN_ALL → Run을 실행합니다.
  01_SUBMIT     ZIP 해시 확인 후 비동기 작업 번호 발급
  02_WAIT_AGENT 같은 작업 번호의 Agent Layer 완료 행과 반환 ZIP 해시·크기를 확인
  03_LOAD       Dataiku가 Agent Layer의 조각을 읽고 개별·전체 해시 대조, 개발 SIDDS Silver 적재 및 재조회
03_LOAD_OUT에 해당하는 결과 폴더에서 <trial>/report.json을 확인합니다. DEV_LOADED, target_layer=Silver, input_documents=1, 원문·구조·검색·벡터 건수와 게시 ID가 기록됩니다. 완료되지 않은 조각이나 잘못된 해시는 적재에서 차단합니다.

재실행과 운영 입력
중단 후에는 같은 trial과 WORK_DIR로 해당 레시피를 실행합니다. READY가 있고 작업 번호를 보존했다면 GENOS가 중단된 뒤에도 03_LOAD를 이어갈 수 있습니다. Pod가 사라졌고 READY도 없으면 기존 제출 및 오류를 확인한 뒤에 새 trial을 사용합니다. 완전히 끝난 판본의 WORK_DIR를 지우고 새로 실행하면 기존 판본·체크포인트 충돌로 멈출 수 있습니다.
실제 낱개 원문 Flow는 별도 프로젝트·Flow 설정에서 INPUT_MODE='LOOSE', INPUT_FOLDER_ID 및 DOCUMENT_PREFIX(실제 원천·팀 경로), 실제 R10 지원 ZIP/영수증 폴더 또는 GENOS 지원 마운트를 사용합니다. 운영 Gold는 ENVIRONMENT='PROD', 실제 GOLD_OWNER, 운영 Oracle 연결·계정 및 임베딩 설정을 사용합니다. LOOSE는 기존 Dataiku 압축 경로이므로 이번 DRM 대응을 확인할 때는 기본 SAMPLE_ZIP을 사용합니다. 소형 예시 용어집은 개발 Silver 샘플 전용입니다. 서비스 조회 채널 전환은 별도입니다.
망분리 현장의 리비전 반영·DB 권한·DRM·실제 모델은 현장 실행 결과로 확인합니다.
