사진으로 확정: 보존 업로드 단계에서 중단, ACK 미도달, 관리 폴더 진단 저장도 실패.
미확정: 실제 권한/하위 디렉터리 생성/원격 저장공간·쿼터/파일 크기/일시 장애 중 원인.
복구 R1·원래 실행기·원문·기존 체크포인트·예산·deadline은 변경하지 않는다.

행동: 기존 R2 노트북 설정과 봉인 클라이언트/서비스/endpoint/폴더 결속을 확인하고,
원래 복구 저널·최근 로컬 진단을 읽는다. 새 이름의 2KiB 파일 네 개를 루트,
기존 복구 부모, 실패한 files 하위, 실패한 진단 하위에 순서대로 쓰고 읽는다.
실제 파일 읽기/쓰기 오류와 경로·UTC 시각·소요시간을 즉시 출력·로컬 저장한다.
GENOS API 호출 0, ACK/START/EXECUTE 0, 큰 ZIP 전송/해시 읽기 0, 삭제/덮어쓰기 0.

담당: 이 점검 함수 하나만 저장소 검사를 수행한다. 실패한 쓰기는 자동 재시도하지
않는다. 같은 check_name의 최초 5분·최대 쓰기4회·총8192bytes 한도를 저널로 보존한다.
응답 유실/프로세스 중단 뒤에는 같은 검사 파일의 읽기 확인만 수행하며 쓰기를 반복하지 않는다.
최초 복구의30분/API100회와 새 작업의 deadline/SQL 사용량은 읽어서 표시만 한다.
Dataiku SDK 호출 자체의 중단/timeout은 해당 환경 설정을 따르며 단일 호출을 강제 중단하지 않는다.

종료: CHECK_COMPLETE 또는 CHECK_INCOMPLETE. 작은 파일 성공은 큰 ZIP 저장이나
복구 성공의 증명이 아니다. 원인 구분 불가 시 관리자에게 확인할 정확한 경로/시각을 출력한다.
기존 복구 예산이 만료되면 기존 release/run 반복을 안내하지 않는다. 해제는 별도 미완료.
로그에는 토큰/비밀번호/쿠키를 제거하고 본문 원문/ZIP 내용은 읽지 않는다.
