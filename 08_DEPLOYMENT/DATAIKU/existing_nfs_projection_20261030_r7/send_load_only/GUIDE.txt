이번 메일 전용 실행본: 기본값 load_only. 적재 후 전수 재조회 검증은 자동 실행하지 않습니다.
로컬 검색자료 준비/정렬과 원본 해시/쓰기 충돌 확인은 계속 수행합니다.

NFS 기존 자료 Oracle 이관 R7 — 검색자료 정렬 입력 축소·완료 준비 계산 재사용

첨부/전달 파일
DATAIKU_EXISTING_NFS_CLIENT_20261030_R7.zip: Dataiku 실행 패키지
DATAIKU_EXISTING_NFS_LOAD_ONLY_R7.txt: 노트북 전체 실행 코드
GUIDE.txt: 이 안내

현재 상태 설명
이전에 나온 document/source_unit/block_payload verified는 원문 행 대조입니다.
그 뒤에도 검색자료를 Oracle 조회 행으로 바꾸는 준비·적재·검증이 있습니다.
R6/R6B는 이 과정에서 전체 FTS 검색어 위치를 다시 정렬했습니다.
R7은 정렬하는 행에서 반복 문서ID/원본ID/논리ID를 제외하고,
정렬된 각 문서에 정보를 한 번씩 붙입니다. 검색행과 순서·ID·위치는 유지합니다.
한 번 성공한 준비 계산은 파일/코드/원문 게시 명세가 모두 같을 때 재사용합니다.
실패한 준비 계산은 캐시하지 않고, Oracle 내용 검증은 별도로 계속 수행합니다.

실행 환경과 업로드
LEGAL_RAG 프로젝트, 기존 AIDP/SIDDS 연결과 기존 관리 폴더 설정을 사용합니다.
기존 반입 관리 폴더 ehA8dpVm에 R7 ZIP을 압축 그대로 올리세요.
S3의 기존 원문/지원 ZIP, NFS generation, 기존 수신 폴더와 재개 기록은 유지합니다.
이번 ZIP은 R3 정리 ZIP과 역할이 다르며 기존 R6/R6B 적재 실행본을 대체합니다.

실행 순서
1. 기존 적재/검증 셀이 종료되고 커널이 Idle인지 확인합니다.
2. Kernel > Restart로 이전 이관 모듈을 비웁니다. 원본/재개 기록은 디스크/S3에 남습니다.
3. 새 셀에 DATAIKU_EXISTING_NFS_LOAD_ONLY_R7.txt 전체를 붙여 실행합니다.
   기본 ACTION = 'load_only'로 설정돼 있어 바로 적재 경로를 실행합니다.
   기존 반입/연결/스키마/입력 무결성 확인은 자동으로 수행합니다.
4. 이번 실행은 적재만 수행하고 전수 Oracle 재조회 검증은 나중으로 미룹니다.
   기존 완료 원문 쓰기 커서는 재사용하며 남은 파일 조각/검색행을 적재합니다.
   LOADED_UNVERIFIED가 나오면 적재 완료, 전수 검증은 아직이라는 의미입니다.
5. 필요 시 ACTION = 'status'로 관리 폴더의 단계 요약을 확인합니다.
6. 나중에 전수 검증이 필요할 때만 ACTION = 'verify'로 바꿔 별도 실행합니다.
   원문/파일 조각/검색행 재조회가 모두 통과해야 FULL_DATA_VERIFIED입니다.
기존 00/01/02/03 레시피를 다시 실행하는 절차는 아닙니다.
load는 적재와 검증을 한 번에 실행하므로 이번에는 load_only → verify로 구분합니다.

진행 표시
PREPARING_LOCAL_PROJECTION: 검색자료 준비 단계입니다.
PROJECTION_PREPARATION_REUSED: 같은 불변 입력의 성공한 준비 계산을 재사용했습니다.
QUERY_LOADED: 검색행 적재 진행입니다.
QUERY_VERIFIED: 검색행 검증 진행입니다.
source_unit verified 등 원문 verified와 검색자료 준비/적재/검증을 구분하세요.

재개와 호환 한계
R6B의 원문 이관/전체 이관 identity 모듈은 동일 바이트입니다.
기존 동일 원문·판본·DB·경로·기한·SQL 누적 예산을 유지합니다.
이번 검색 publisher의 코드가 바뀌어 새 query release ID가 생성됩니다.
R6B가 첫 describe 단계에서 실패해 deferred plan이 아직 없는 현장 경로가 대상입니다.
이미 다른 query release의 deferred plan/검색행 적재가 있는 경우
무거운 검색자료 준비 전에 DEFERRED_BINDING으로 중단합니다.
기존 기록/검색행을 삭제하거나 ID를 바꿔 우회하지 마세요.
그 결과를 확인한 뒤 별도 호환 처리가 필요합니다.
쓰기 응답 유실 시 자동 재시도하지 않습니다. 종료 결과를 확인한 뒤 같은 입력/경로로 재개합니다.
검증 도중 중단하면 검증 진행 커서는 재사용하지 않고 전수 검증을 다시 수행합니다.
전체 FTS 정렬은 여전히 남아 있어 2.942GiB로 충분한지 보장하지 않습니다.
다른 디스크로 자료를 옮기거나 대형 검색행 사본을 새로 저장하지 않습니다.
추가 파일은 작은 projection-descriptor-r7.json 준비 명세이며 기존 receipt ZIP에도 보관됩니다.

되돌림
R6B ZIP/TXT와 기존 작업/S3 기록은 보존했습니다.
R7의 새 query plan이 생성된 후 R6B로 되돌리면 publisher ID 차이로 거절될 수 있습니다.
원문을 다시 넣거나 receipt를 지우지 말고 plan 상태를 확인해야 합니다.
MAIN/GENOS 코드서빙/실제 Oracle 테이블 및 데이터는 이 로컬 준비 작업에서 변경하지 않았습니다.

검증 범위
검색행·ID·offset·행순서·종류별 chain 대조 및 캐시 무효화/손상/이전plan 거절 등13검사 통과.
실제 전달 TXT 전체를 실행한 모의 Dataiku/Oracle/NFS 검사1개 통과:
R5 완료 원문 재개, 이전 모듈 거절, 응답 유실 후 명시 재개, load_only/verify,
누락/변조/추가 행 거절, 원래 기한/예산 유지, 준비 계산1회 확인.
R6B full/migration 모듈은 불변이나 이미 적재된 옛 query plan의 자동 이행은 구현하지 않았습니다.
현장 Oracle/Dataiku 대규모 자료의 성공/속도/임시 공간 효과는 아직 미측정입니다.
