실행 방법
LEGAL_RAG 프로젝트의 현재 Python 노트북에서 실행합니다.
구조화/적재/검증 및 같은 자료를 쓰는 다른 작업이 종료된 상태에서,
새 셀에 CLEAN_DATAIKU_LARGE_ZIPS_R3.txt 전체를 붙여 실행하세요.
R1/R2 셀은 다시 실행하지 않습니다. ZIP 업로드/설치나 커널 재시작은 불필요합니다.
이 ZIP은 코드 전달용 사본이며 R6B 적재 코드를 교체하지 않습니다.

이번 수정
R2의 SUPPORT_BACKUP_MISSING_OR_AMBIGUOUS와
AUDIT_CURRENT_CHECKPOINT_REFERENCE_NOT_FOUND로 삭제가 0건이었던 조건을 수정했습니다.
- 지원 ZIP: 반입 폴더 ehA8dpVm에서 PIPELINE_SUPPORT로 시작하는 ZIP을 찾습니다.
  원래 이름을 우선하고, 중복 번호/하위 폴더의 후보도 최대20개까지 내용으로 비교합니다.
  여러 이름이 있다는 이유만으로 중단하지 않습니다.
- 진단 ZIP: 현재 레시피의 structured 관리 폴더에 있는 동일 해시 이름의 보관 객체를
  직접 읽습니다. 최신 체크포인트의 참조 유무는 삭제 조건에서 제외했습니다.
  체크포인트와 실패 이력은 변경하지 않습니다.
- 두 종류 모두 실제 보관본 전체 바이트 수/SHA-256이 로컬과 같아야 삭제합니다.
  이름이나 해시로 된 파일명이 같다는 것만으로 삭제하지 않습니다.

대상은 사진에서 확인된 파일명/크기의 로컬 ZIP 두 개뿐입니다.
PIPELINE_SUPPORT.zip: 2,267,000,459 bytes (약2.11GiB)
compute-audit.zip: 440,366,952 bytes (약0.41GiB)
현재 generation/SQLite 원본/검색색인/재개기록/실패기록은 보존합니다.
S3 보관본도 유지합니다. 다른 디스크로 이동하거나 새로운 대형 사본을 만들지 않습니다.
SQL/모델 호출, 데이터 적재/검증 재실행은 없습니다.

확인 방법
보관본은 스트림으로 읽으며 시간이 걸리면 30초마다 진행을 표시합니다.
후보가 여러 개이면 내용이 맞는 첫 보관본에서 비교를 끝냅니다.
마지막 두 파일 결과와 '여유 공간: 전 → 후 GiB' 부분만 확인해 주세요.
DELETED_VERIFIED_BACKUP: 보관본까지 일치하여 해당 로컬 ZIP 삭제 완료.
PRESERVED: 읽기/내용/권한/현재 사용 등의 조건 불충족으로 보존.
NO_VERIFIED_BACKUP: 실제 읽어본 후보 중 같은 내용의 보관본을 확인하지 못함.
NOT_FOUND_AT_OBSERVED_SIZE: 이미 없거나 사진 당시와 크기가 다름.
세부 결과는 LARGE_CLEANUP_RESULT 변수에 저장되며 긴 JSON은 자동 출력하지 않습니다.

중단/재실행
검사 도중 중단하면 검사 중인 파일은 보존됩니다. 앞서 삭제 완료된 파일은 삭제 상태입니다.
같은 셀을 다시 실행하면 이미 없는 파일은 건너뜁니다.
보관본이 없는 파일을 강제 삭제하거나 프로세스를 종료하지 않습니다.

검증 및 한계
로컬 Python3.11 검사17개 통과. 정상 삭제는 합성 파일/모의 관리 폴더에서 확인했습니다.
실제 열린 파일 거절도 확인했으며 현장 두 파일의 삭제/회수량은 아직 미확인입니다.
