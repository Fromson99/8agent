증분 처리 "바뀐 문서만" 1단계 — R8 재적재 Flow와 개발계 사전 점검 SQL입니다. 개발계(LEGAL_RAG)부터 돌립니다.

1. 무엇을 하나

  • Gold 검색 행 번호를 "몇 번째 행"에서 "행 내용" 기준으로 바꿔, 이미 S3에 있는 구조화 세대 ZIP 조각(원문 불필요)을 Gold에 새 세대로 넣습니다. 다음 증분부터 안 바뀐 문서의 행을 재사용하기 위한 첫 단계입니다.
  • 지금 서빙 채널·기존 R7/R5 Flow는 그대로입니다. 새 세대는 적재기가 만드는 고유 채널(g19_…)에만 연결됩니다.
  • S3는 읽기만 합니다. 실행 기록은 OBS 폴더에, 작업 파일은 Dataiku 서버 디스크에 둡니다. GENOS 재배포 없음.
  • 시나리오 LGL_R8_RELOAD_RUN_ALL 버튼 한 번: 01 조각 합치기·세대 풀기 → 02 DB·표·권한 점검 → 03 Gold 적재·다시 읽어 대조 → 04 통계 갱신.

2. 순서

  1. 사전 점검: DEV_INCREMENT_PREP_CHECK_R1.txt 의 [P01]~[P11]을 Dataiku SQL 노트북에서 하나씩 RUN (읽기만). 결과 사진 보내 주세요 — 특히 P01(지금 채널), P02(세대 형식·GENERATION_ID), P10·P11(권한).
  2. 프로젝트 변수 LGL_GOLD_OWNER = SIDDS (R7 때 넣었으면 그대로)
  3. Flow에서 OBS에 폴더 하나 만들고(Store into: OBS) DATAIKU_ZIP_R8_RELOAD.zip 업로드
  4. Python 노트북 셀에 DATAIKU_SETUP_R8_RELOAD.txt 전체를 붙여 넣고 아래 칸을 채운 뒤 실행 → FLOW_INSTALLED LGL_R8_RELOAD_RUN_ALL 나오면 설치 끝(실행은 안 됨)
  5. Scenarios > LGL_R8_RELOAD_RUN_ALL > RUN
  6. 04_STATS가 PRIVILEGE_REQUIRED로 멈추면 로그의 dba_statements를 DBA에 요청(또는 PIDD2APP에 ANALYZE ANY) 후 04만 다시 RUN
설치 셀 칸넣을 값
CODE_FOLDER_ID3번에서 만든 OBS 폴더 ID
INPUT_FOLDER_ID구조화 세대 ZIP 조각이 있는 S3 폴더 ID (11-04 안내의 LEGAL_RAG 폴더 등)
WRITE_FOLDER_ID비우면 CODE_FOLDER_ID와 같은 OBS 연결에 결과 폴더 4개 생성
EXPECTED_ARCHIVE / EXPECTED_PARTS실제 조각 이름·개수 (기본: genos-rag-data-20261007T002029Z-7c0b050f.zip, 34)
SELECTION_CHANNEL아래 판본 선택 참고
TARGET_CONNECTION / EXPECTED_DB_USERAIDP / PIDD2APP (현장 값이 다르면 수정)

판본 선택 정보(11-09 운영 503 원인 — 10-07 ZIP에는 없음): 둘 중 하나
· OBS 코드 폴더에 SEARCH_SELECTION_GENERATION.json 업로드 (NFS 세대 옆 SEARCH_SELECTION/generation.json, 운영 R7f 때 올린 파일과 같은 것)
· 또는 SELECTION_CHANNEL에 같은 세대를 서빙 중인 채널 이름(P01)
세대가 다르면 멈춥니다(잘못 넣을 위험 없음).

5. 로컬 확인

  • 전용 Oracle + Dataiku 대역(S3 읽기 전용, OBS 쓰기)으로 이 설치 셀 그대로 실행, 13항목 통과: S3 쓰기 0, 기존 채널 그대로, 적재 후 행 수·게시 내용 다시 읽어 대조, 통계 권한 없으면 DBA 문장 출력 후 멈춤, 다른 세대 판본 선택 거부 등.
  • 재사용 측정: 같은 용어집으로 각각 만든 두 세대에서 공통 문서 행이 같은 번호·내용인 비율 16% → 89%.
  • 확인 못 한 것: 현장 Dataiku·OBS·S3·임베딩·34조각 실제 시간, 새 세대를 현재 서빙 코드로 읽어 같은 답인지(다음 단계), 바뀐 문서만 적재(다음 단계).
