근거: 다른 세션이 받은 개발계 사진 — LGL_R8_PARTS > Settings > Storage 화면은
  Type "Amazon S3" / S3 connection "OBS" / Path in bucket "/${projectKey}/${odbId}" 세 줄뿐, Bucket 입력 칸 없음.
  dataikuapi create_managed_folder는 params에 connection·path만 넣고 bucket은 넣지 않음(사진 경로와 같음)
  → 코드로 만든 폴더는 연결 기본 버킷 'AIDP-YNY-DEV-BUC-SRI'로 열림 = 11-13 404 원인. R4가 코드 폴더 버킷·경로를 복사하는 방향은 맞음.
그래서 메일 본문의 "Settings의 Bucket 값을 …", "Settings에서 Bucket을 … 직접 저장"은 현장에서 할 수 없다. 기본 순서(R4 ZIP 업로드 → R4 셀 실행)는 그대로다.

     노트북 셀:  import dataiku; print(dataiku.Folder('LGL_R8_CODE').get_info()['accessInfo'])
     출력의 bucket 값을 설치 셀 PARAMS의 BUCKET 칸에 넣고 다시 실행. bucket이 출력에 없으면 그 출력 사진을 보내 주세요.

  FOLDER_STORAGE_SAVE_UNCONFIRMED <폴더>  또는  FOLDER_STILL_UNREACHABLE <폴더>
     이 연결이 폴더별 버킷 값을 저장·사용하지 않는다는 뜻(현장에서만 확인 가능). 화면으로 만든 폴더는 열리므로 화면으로 다시 만든다:
       1) Flow에서 R3가 만든 레시피 4개(LGL_R8_RELOAD_01_RESTORE ~ 04_STATS)와 시나리오 LGL_R8_RELOAD_RUN_ALL 삭제
       2) 열리지 않는 폴더 삭제: LGL_R8_PARTS, LGL_R8_RELOAD_01_RESTORE_OUT, _02_CHECK_OUT, _03_LOAD_OUT, _04_STATS_OUT
       3) Flow > + ADD ITEM > Folder, Store into OBS 로 위 5개를 같은 이름으로 다시 만듦 (LGL_R8_CODE 만들 때와 같은 방법)
       4) R4 설치 셀 다시 실행 — 이름으로 폴더를 찾고, 열리면 설정을 건드리지 않으며, 레시피 4개·시나리오를 새로 만든다
       5) LGL_R8_PARTS에 조각 34개 + ORIGINAL.sha256 + PARTS.sha256 업로드 → RUN_ALL
     (설치기 코드 reload_install.py는 이름으로 찾은 폴더가 열리면 그대로 쓴다 — find()·pin(created=False))

  CODE_FOLDER_UNREACHABLE: LGL_R8_CODE 자체가 안 열림 — CODE_FOLDER_ID 철자 확인.
