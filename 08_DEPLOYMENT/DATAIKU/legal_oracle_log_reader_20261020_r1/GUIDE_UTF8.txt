Oracle 이관 로그 읽기 — 2026-10-20 R1

1. 실행 중인 R4 이관 노트북은 그대로 둡니다. Run/Restart/Interrupt를 누르지 않습니다.
2. 같은 Dataiku LEGAL_RAG 프로젝트에서 별도의 Python 노트북을 엽니다. 기존의 바쁜 커널을 공유하지 않는 노트북이어야 합니다.
3. 별첨 LOG_READER_RUN.txt 전체를 새 셀에 붙여 실행합니다.
   ZIP으로 받는 경우 LEGAL_ORACLE_LOG_READER_20261020_R1.zip을 풀고 그 안의 같은 TXT를 사용하세요.
   이 TXT는 Python 코드입니다. SQL 창이나 bash에서 실행하지 마세요.
4. 원문 이관 상태, 테이블별 대조 완료 행, 마지막 갱신 시각, 최근 진행/SQL 로그를 확인합니다.
5. 최신 상태를 보려면 이 조회 셀만 다시 실행합니다. 이관 실행 셀을 다시 실행하는 것이 아닙니다.

이 코드는 Oracle에 접속하지 않고 기존 로그 파일만 읽습니다. 파일/진행 기록/데이터를 변경하거나 이관을 시작·중단하지 않습니다.
각 로그는 마지막 최대 16KiB만 읽고 최대 5줄을 표시하므로 커진 SQL 로그 전체를 메모리에 올리지 않습니다.
R4도 R2 작업 폴더와 oracle-import-r3 진행 기록을 사용하므로 경로의 r2/r3를 r4로 바꾸지 마세요.

BASE_DIR는 이전 현장 로그에 나타난 프로젝트 작업 경로입니다.
다른 노트북의 실행 환경/컨테이너에서 기존 작업 폴더가 보이지 않거나 접근 권한이 없을 수 있습니다.
찾은 폴더가 0개/여러 개이거나 권한 오류가 나오면 출력만 공유하세요. 최신 파일을 임의 선택하거나 이관을 다시 실행하지 않습니다.
시각은 해당 서버의 로컬 시간입니다. 상태 파일과 로그는 서로 다른 순간에 갱신될 수 있으며, 쓰는 중인 로그의 마지막 줄은 부분적으로 보일 수 있습니다.

rows_added/rows_checked 같은 공통 카운터의 0만으로 정지를 판단하지 마세요. 원문 이관은 state.json의 테이블별 rows와 calls.jsonl의 BATCH_VERIFIED 증가를 확인합니다.
PROGRESS의 시간 증가만으로 데이터 처리 진척이 증명되지는 않습니다. 이 조회 결과는 전체 이관 완료를 판정하지 않습니다.
