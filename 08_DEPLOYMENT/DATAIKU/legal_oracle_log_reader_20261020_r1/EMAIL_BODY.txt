실행 중인 Oracle 이관의 저장 로그를 확인하는 코드를 보냅니다.

기존 R4 이관 노트북은 그대로 두세요. 같은 Dataiku LEGAL_RAG 프로젝트에서 별도의 Python 노트북을 만들고, 첨부 LOG_READER_RUN.txt 전체를 새 셀에 붙여 실행하면 됩니다. 기존 바쁜 노트북에 새 셀로 넣으면 실행 대기만 하므로 별도의 커널에서 실행해야 합니다.

ZIP 안에도 같은 실행 TXT와 안내가 들어 있습니다. 이 TXT는 Python 코드이며 SQL 창이나 bash에서 실행하지 않습니다.

원문 이관 상태, document/source_unit/block_payload별 대조 완료 건수, 마지막 갱신 시각과 최근 진행·SQL 로그를 확인합니다. 최신 내용을 보려면 이 조회 셀만 다시 실행하세요.

Oracle 접속이나 데이터 쓰기 없이 기존 로그만 읽습니다. 이관을 다시 실행하거나 중단하지 않으며, 진행 기록도 변경하지 않습니다. 각 로그는 마지막 최대 16KiB만 읽습니다.

R4도 기존 legal-existing-zip-r2-work/oracle-import-r3를 사용합니다. 경로의 r2/r3를 r4로 바꾸지 마세요. 별도 실행 환경에서 기존 폴더가 보이지 않아 폴더 0개/여러 개 또는 권한 오류가 나오면 그 출력만 보내 주세요. 기존 이관의 Run/Restart/Interrupt를 누르지 마세요.

시간 로그만 증가하는 것으로 데이터 처리 진척을 확정할 수는 없습니다. 테이블별 대조 완료 행과 BATCH_VERIFIED의 증가를 확인하면 됩니다.

실행 TXT 구문과 작은 합성 로그로 조회 결과·원본 해시 불변·폴더 누락/중복 시 중단을 확인했습니다. 현장 노트북 사이의 파일 접근 가능 여부는 아직 미확인입니다.
