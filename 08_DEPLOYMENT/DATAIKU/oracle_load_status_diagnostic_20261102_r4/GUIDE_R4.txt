테이블별 기존 적재 기록 확인 R4 — 2026-11-02

목적
현재 남은 작업을 구분합니다: 기존 데이터 적재, 전수검증/게시, Gold R19 구조 전환.
이 코드는 기존 적재 영수증만 읽습니다. 현재 DB에 새 INSERT가 가능한지 시험하지 않습니다.
읽기 전용 SELECT/메타데이터/과거 성공 기록만으로 새 INSERT 성공을 보장할 수 없습니다.

첨부파일
- ORACLE_LOAD_STATUS_20261102_R4.zip: check_load_status.py 원본 1개.
- 04_CHECK_LOAD_STATUS.txt: 완전한 Python 실행문.
- GUIDE_R4.txt: 이 안내.

실행 위치와 순서
1. Dataiku LEGAL_RAG에서 R11 적재를 실행했던 Python/Jupyter 노트북을 엽니다.
   AIDP SQL 노트북에 넣는 코드가 아닙니다.
2. 아래의 새 Python 셀 하나에 04_CHECK_LOAD_STATUS.txt 전체를 붙여 넣고 실행합니다.
   ZIP/관리 폴더 업로드나 Bash 명령은 필요 없습니다.
3. 최대18줄 출력 화면만 캡처합니다. 재개/임베딩 셀은 실행하지 않습니다.

DIAG_JOB_DIR는 보통 비워둡니다. 사진에서 확인한 경로를 사용합니다:
<현재 임시 폴더>/legal-existing-nfs-20261029-r1/
financial-risk-success-20261005-schema-r2/oracle-import-r2
이 위치에 full-state.json이 있어야 합니다. 파일을 찾지 못하면 자동으로 디스크를 뒤지거나
DB/S3에 접속하지 않고 미확인으로 종료합니다. 기존 기록을 복원/수정하지 않습니다.
실제 경로가 다르면 DIAG_JOB_DIR에 full-state.json이 들어 있는 폴더의 절대 경로를 넣습니다.
경로가 없거나 기록이 없어졌다면 실패 출력만 캡처하세요. 적재를 새로 시작하지 않습니다.

출력 해석
- SOURCE_STAGED: 원문3표 적재 응답과 그 당시 판본별 행수 확인을 마친 기록.
  원문 내용 전체를 다시 읽는 전수검증 완료는 아닙니다.
- 원문3표 성공응답 누적: 해당 원본 판본의 저장 커서입니다. 현재 DB 행수/이번 실행 신규행수 아님.
- 파일조각 커서 합: 저장된 파일별 성공응답 합계입니다. 예상 총수와 대조하지 않아 완료로 판단하지 않습니다.
- 검색 ACK 커서: 최대20행의 옛 묶음 단위입니다. 커서에20을 곱해 정확 행수로 사용하지 않습니다.
- 검증 후 게시 단계 COMPLETE: 저장된 해당 단계 완료 기록이며 현재 DB 재검증 결과가 아닙니다.
- NO_RECORD/빈값/경로 오류: 완료 증거가 없거나 읽지 못한 상태. INSERT 실패/0행과 다릅니다.
- 원문/검색 게시 정보는 전수검증 성공 뒤에 쓰도록 되어 있습니다.
  검색 적재 도중 중단됐다면 후속 게시표가 미완료일 수 있고, 그것을 별도 용량 실패로 세지 않습니다.
- 채널 선택과 벡터 임베딩/승인 온톨로지는 R11 완료만으로 실행되지 않습니다.

Gold 요구사항
개발계부터 확정 Gold R19의13표60컬럼, 타입/길이/PK/게시 계약에 맞게 적재해야 합니다.
현재 R11 개발용9표와 R12 벡터2표는 이 요구를 반영한 완료본이 아닙니다.
운영 Gold의 이름을 개발계 owner에 그대로 가정하지 않습니다. 환경별 배치와 구조 계약을 구분합니다.
이번 R4는 적재 상태 진단이며 Gold 적재기/DDL/재적재/임베딩 실행 코드가 아닙니다.

다른 테이블에 새 INSERT도 실패하는지
기존 성공 기록만으로 현재 쓰기 가능 여부는 확정할 수 없습니다.
같은 테이블스페이스에서 새 공간 할당이 필요하면 다른 표도 영향을 받을 수 있습니다.
반대로 작은 테스트1행 성공만으로 대량 적재용 공간이 확보됐다고 판단할 수 없습니다.
현재 DBA_SEGMENTS/DBA_TS_QUOTAS 조회가 막혀 있으므로 DBA에 공간/Quota/자동확장 상태를 확인합니다.
임의 더미 데이터를 공용표에 넣는 시험이나 전체 COUNT는 이 진단에 포함하지 않았습니다.

검증/중단/재실행
구문 검사와 작은 합성 영수증의 실패/미확인 분류를 검증한 준비본입니다. 현장 DB 실행 검증은 아닙니다.
full-state 최대16MiB, 원문 상세 기록 최대2MiB만 읽으며 원문/검색 DB와 긴 로그는 읽지 않습니다.
파일 읽는 중 변경을 감지하면 그 파일은 미확인으로 표시합니다. 여러 파일의 원자 스냅샷은 아닙니다.
출력 후 셀이 종료되면 진단 완료입니다. 별도 재개 지점이 없고 동일 셀을 다시 실행해도 기록을 바꾸지 않습니다.
