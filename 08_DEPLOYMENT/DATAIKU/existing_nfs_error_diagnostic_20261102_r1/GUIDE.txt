R11 적재 중 ORA-12801 오류 진단 — 2026-11-02 R1

목적
사진의 R11 검색행 INSERT 실패에서 숨겨진 상세 Oracle 오류 코드와 마지막 저장 위치를 확인합니다.
ORA-12801은 병렬 작업 중 다른 오류가 발생했다는 상위 오류입니다. 실제 원인은 뒤따르는 오류로 확인해야 합니다.
R11 연결기는 첫 ORA 코드만 화면에 표시했으며, 이 진단은 같은 커널에 남아 있는 원래 예외 연결을 읽습니다.
로그인 만료와 DB 실패 사이의 인과관계는 사진만으로 확인되지 않았습니다.
이 코드는 진단 전용입니다. 적재 재개·DB 조회/변경·임베딩·파일 변경을 하지 않습니다.

실행 위치와 순서
1. 현재 LEGAL_RAG / aidptest2's Python notebook_7에서 실행합니다.
2. 로그인 만료 상태이면 상단 Log back in으로 다시 로그인한 후 같은 노트북으로 돌아옵니다.
   Kernel > Restart / Shutdown / Run All은 누르지 않습니다. 원래 예외를 보존해야 합니다.
3. 실패한 R11 셀과 R12 후속 셀은 다시 실행하지 않습니다.
4. 첨부 01_DIAGNOSE_R11_ERROR.txt를 메모장으로 열고 전체를 복사합니다.
5. 같은 노트북의 새 셀 하나에 붙인 뒤 그 셀만 Shift+Enter로 한 번 실행합니다.
   원문 적재 셀이나 R12 후속 셀이 아닌, 새 진단 셀을 선택했는지 확인합니다.
6. 출력 최대24줄을 캡처합니다. 본문·비밀번호·전체 SQL·전체 traceback은 출력하지 않습니다.

첨부 파일

  실제 error_diagnostic.py, 별도 실행 TXT와 바이트가 같은 코드입니다.
  다른 ZIP이나 JavaScript를 포함하지 않습니다. 기존 R11/R12 ZIP을 교체하는 파일이 아닙니다.
- 01_DIAGNOSE_R11_ERROR.txt
  생략 없는 전체 셀 코드. 위 방식으로 복사해 실행합니다.

  이 안내입니다.

이번에는 TXT 전체 복사 실행 방식이므로 ZIP을 ehA8dpVm에 업로드할 필요가 없습니다.
ZIP 파일 실행 방식을 택한다면 Dataiku 노트북 Files 화면에서 ZIP을 업로드·압축 해제한 후,
같은 커널에서 실제 파일 위치로 %run ./error_diagnostic.py를 실행합니다.
어느 방식이든 같은 커널을 사용해야 합니다. 별도 Python 프로세스/새 커널에서는 원래 예외가 없습니다.

결과 해석
E1/E2/E3 등: 같은 예외의 연결 단계. ORA/PLS 코드만 추려 표시합니다.
원인 확인 후보: ORA-12801/ORA-06512를 제외한 코드. 이 코드를 확인한 뒤 원인별 조치가 가능합니다.
저장 상태/적재 완료 기록: 파일에 남은 상태이며 실제 DB의 모든 행을 다시 검증한 결과는 아닙니다.
마지막 확정 커서: 기존1~20행 단위의 묶음 위치입니다. 그 숫자를 전체 적재 행수로 읽지 않습니다.
이번 실행 성공응답: 마지막 진행 기록의 이번 실행 행수·요청수입니다. 전체 누적 행수와 다를 수 있습니다.
마지막 요청: WRITE_UNCONFIRMED면 마지막 실패 묶음의 DB 반영 여부는 아직 확인되지 않았습니다.
기존 기한 잔여: 최초 작업의 남은 기한입니다. 이 진단은 기한·호출 예산을 초기화하지 않습니다.
중단 상태에는 과거 처리속도로 새 완료시간을 계산하지 않습니다.

원래 예외 없음 / 상세 코드 미확보
이미 커널을 재시작했거나 다른 오류로 마지막 예외가 바뀌었다면 원인 코드가 복원되지 않을 수 있습니다.
그 경우 원인을 추측하지 않고 미확인으로 표시합니다. 상세 JDBC/DBA 오류 기록 확인이 필요할 수 있습니다.
경로 미확인은 기록 삭제·0행을 뜻하지 않습니다. 알고 있는 정확한 기존 oracle-import-r2 경로가 있는 경우만
TXT 맨 위 DIAG_JOB_DIR에 넣어 읽을 수 있습니다. 경로를 추측하거나 새 작업 폴더를 만들지 않습니다.

다음 단계
진단 결과를 확인하고 원인에 맞게 수정한 뒤 기존 완료 커서와 마지막 실패 묶음을 대조하여 재개합니다.
이미 성공한 데이터를 무조건 처음부터 다시 적재하지 않습니다. 재개 가능 여부는 실제 기록으로 확인합니다.
R11이 LOADED_UNVERIFIED까지 성공하기 전에는 R12 검증·임베딩을 진행하지 않습니다.

로컬 확인
실제 전달했던 R11 어댑터/SQL 래퍼에 합성 ORA-12801 + ORA-01652를 주입하여
from None로 감춰진 하위 오류 복원, 정확한 커서 출력, 비밀·본문 비출력, 진단 중 파일 무변경,
예외 없음·순환 참조·출력/읽기 한도·불완전 로그·TXT 동일성 등6개 검사를 통과했습니다.
합성 ORA-01652는 시험용이며 현장의 원인이 공간 부족이라는 증거가 아닙니다.
실제 현장 DB/모델 호출은 하지 않았습니다. 원인 해결·현장 재개 완료로 표시하지 않습니다.
