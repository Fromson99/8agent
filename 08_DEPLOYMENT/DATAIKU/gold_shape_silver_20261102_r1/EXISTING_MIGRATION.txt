기존 이관 코드 확인 및 이번 전달본의 재사용 범위 — 2026-11-02

확인 결론
기존 Gold 이관 코드와 Agent 기록 이관 코드가 모두 있습니다.
기존 이관이 없어서 전체를 새로 구현해야 한다는 설명은 맞지 않습니다.
이번 전달본은 기존 변환/검증 로직을 사용하고, 삼성 Dataiku 연결과 개발계 Gold 형태 대상에 맞추는 작업입니다.

1. 실제 Gold 이관 코드
고정 코드:
02_BACKEND/lawrag/research/candidates/adr_1208/gold-b03/revisions/rev-021/snapshot/08_DEPLOYMENT/LOCAL/gold_connection_r12/gold_lab.py
주요 함수: source_rows, mapped_source, mapped_query, insert_batch, oracle_import, verify_rows.
실행 진입: 06_TOOLS/EXPERIMENTS/adr_1208/run.py
검증 기록: 04_EXPERIMENTS/ADR/ADR-1208-gold-r12-full-migration-vector/README.md
실제 적재: 선택21문서 / 구조단위56,475 / 원문구간64,629 / 검색3,344,267행 / 벡터16,085개.
이는 현장 전체 데이터 이관 결과가 아닙니다.

2. Gold 엔진용 검색 자료 보완 이관
고정 코드:
02_BACKEND/lawrag/research/candidates/adr_1214/connected/revisions/rev-036/snapshot/08_DEPLOYMENT/LOCAL/gold_connection_r12/engine_build.py
동일 폴더 engine_publish.py / engine_check.py / engine_activate.py.
논리1,492,223행을 물리1,050,337행으로 묶어 적재·검증한 별도 확장 경로입니다.
고정21문서·준비 SQLite stage·기존 base 게시판본·packed reader 계약에 묶여 있습니다.
그 패키지를 현장 전체 원본에 그대로 실행하거나, 기존 행수를 현장 완료분으로 계산하면 안 됩니다.

3. 기존 SQLite/NFS Agent 실행 기록 → Oracle 이관
유지 코드: 02_BACKEND/semantic_runtime/oracle_records_migration.py
주요 진입: migrate_tree(source_root, logical_root, store=..., quiesced=True).
ADR1242에서 실제 Oracle로 원본 bytes/NULL/빈값/PK/재개/중복 재실행을 검증했습니다.
현재 코드는 이후 MAIN128의 구조화 Oracle·상세 NFS 정책을 반영하므로 과거판을 그대로 가져오지 않습니다.
원문 store.sqlite 등의 지식 DB는 이 Agent 기록 이관기에 넣지 않습니다.
현장 이관에는 실제 기존 runtime 경로, 동일 logical namespace, writer 중지 및 상세 NFS 설정이 필요합니다.
이번 start는 Agent 표 생성·INSERT 검사까지이며 과거 실행 이력을 임의로 이관하지 않습니다.

4. 이번 R1에서 실제로 재사용하는 부분
- ADR1208의 READ_COLUMNS / mapped_source / mapped_query 정의를 원문 그대로 추출해 legacy_gold_mapping.py로 사용.
  로컬 전용 Docker 접속·관리자 계정 생성·quota 조정·21문서 필터 시작 코드는 가져오지 않음.
- 이미 현장에 반입한 R11의 원문 읽기/체인·검색 투영·준비 명세·Dataiku CLOB 전달 함수를 그대로 사용.
  vendor 파일들은 기존 ZIP 바이트와 일치하며 원문/검색 내용을 새 규칙으로 바꾸지 않음.
- 확정 R19의 컬럼·타입·길이·키를 적용하고 환경별 대상명만 LGL_G19_*에 연결.
- 추가 부분: 17표 생성/구조 확인, INSERT→ROLLBACK 확인, Gold 길이 검사, 성공분/결과불명분 재개 기록,
  Dataiku 묶음 INSERT, 별도 전수검증, 화면18줄 제한.

5. 그대로 남는 제한
이번 전체 load는 현장 기존 준비 명세의 약6천만 검색행을 유지합니다.
과거21문서 축소 실험이나 packed extension을 전체 현장 데이터에 이미 적용했다고 주장하지 않습니다.
기존 데이터 삭제/공간 회수·실제 임베딩·승인 온톨로지 입력·현장 서비스 매핑 전환은 자동 실행하지 않습니다.
공간 부족 상태에서는 새 대상도 실패할 수 있습니다. 우선 start의 INSERT 결과를 확인합니다.
