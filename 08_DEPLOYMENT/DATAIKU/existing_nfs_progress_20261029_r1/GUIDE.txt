NFS 이관 R2 진행상황 조회 — 읽기 전용

이번 파일은 앞서 보낸 적재 수정본을 교체하는 패치가 아니라 추가 상태 조회 도구입니다.
GENOS 수정/배포, Dataiku 클라이언트 재설치, NFS 데이터 재다운로드가 필요하지 않습니다.

실행
1. 현재 load 실행 중인 노트북/커널은 그대로 둡니다. 중단하거나 Restart하지 않습니다.
2. 방금 status를 조회한 별도 커널의 Dataiku Python 노트북에서 새 셀을 만듭니다.
3. DATAIKU_NFS_PROGRESS_READONLY_R1.txt 전체를 붙여넣어 실행합니다.
   별도로 입력할 값은 없습니다. 기존 LEGAL_PIPELINE_SCRATCH 설정을 읽습니다.
   실행 중인 load와 같은 커널에서는 셀이 대기하므로 별도 커널을 사용합니다.
4. 필요하면 30초~1분 뒤 같은 조회 셀만 다시 실행하여 출력의 시간/크기를 비교합니다.
   이 TXT는 Dataiku Python 셀용이며 bash 스크립트가 아닙니다.

ZIP 사용
첨부 ZIP에는 같은 전체 실행 TXT와 이 안내가 들어 있습니다.
ZIP이 있는 Linux 폴더에서 풀 때는 아래 명령을 사용할 수 있습니다.
python3 -m zipfile -e ./DATAIKU_NFS_PROGRESS_READONLY_20261029_R1.zip ./nfs_progress_readonly_r1
압축을 푼 TXT의 내용을 Dataiku Python 셀에 붙여넣습니다.
이 ZIP을 ehA8dpVm에 업로드하거나 기존 R2 ZIP을 바꾸는 단계는 없습니다.

출력 의미
source       : 원문 적재 단계
verify       : 원문 대조 단계
assets       : 색인 파일 적재 단계
query        : 검색 행 적재 단계
final_source : 최종 원문 대조 단계. 뒤에 자산/검색 행의 최종 대조가 이어집니다.

마지막 저장 단계는 마지막으로 기록된 단계입니다. 완료된 단계 목록과 구분합니다.
저장 상태는 기록상의 값으로, 재개 중에는 이전 FAILED 값이 남아 있을 수도 있습니다.
최근 로그의 수정 시각/크기가 변하면 처리 기록이 갱신되고 있다는 뜻입니다.
갱신이 없다는 이유만으로 멈췄다고 단정하지 않습니다. 긴 조회/검증 중일 수 있습니다.
이 도구는 실행 프로세스의 생존, 실제 DB 쓰기 성공, 전체 진행률 %를 인증하지 않습니다.

별도 커널의 임시 디스크가 실행 커널과 다르면 기록 경로가 보이지 않을 수 있습니다.
이때의 '경로가 보이지 않습니다'는 실패/미실행 판정이 아닙니다.
load를 추가로 실행하거나 기존 기록을 지우지 말고 조회 출력과 원래 실행 셀의
마지막 출력을 함께 확인합니다.

사진에서 확인된 상태
RECEIVED_VERIFIED는 문서 2,121건·약 5.84GB의 수신/파일 검증 완료 기록입니다.
load_result=null이므로 최종 Oracle 적재 완료는 아직 확인되지 않았습니다.
last_error의 deferred_indexes는 이전 R1 오류일 수 있으며 재발 증거가 아닙니다.
최종 완료는 기존 R2 load의 FULL_DATA_VERIFIED와 저장된 COMPLETE로 확인합니다.

검증/범위
Python 3.9 문법 검사 및 ZIP 구성 검사를 수행합니다.
현장 실행은 아직 확인하지 않았습니다. 이 조회 코드는 원문/DB 본문을 읽거나
Oracle/GENOS에 요청하지 않고 로컬 진행 기록과 로그 파일 정보만 읽습니다.
