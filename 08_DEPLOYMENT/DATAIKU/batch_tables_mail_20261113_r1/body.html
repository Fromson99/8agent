3. 실행 순서 (개발계, Dataiku SQL 노트북)

  1. CREATE_INCREMENT_GOLD_SIDDS_R3.txt [C01]~[C04] — 증분 3표
  2. (증분 실험할 때만) CREATE_TEST_COPY_SIDDS_R1.txt [T01]~[T24] — 시험 복사본 13표
  3. 위 권한 표의 '신청' 항목 GRANT (SIDDS·SIDDA 소유자 또는 DBA)
  4. 확인은 11-12 메일의 CHECK_INCREMENT_GOLD_SIDDS_R3.txt, CHECK_TEST_COPY_SIDDS_R1.txt

[번호] 하나씩 별도 Query로, 문장 끝 ; 없음, 버튼은 RUN(RUN SELECTION 아님).
운영은 메타 승인 뒤 CREATE_INCREMENT_GOLD_SIDDG_R3.txt(DBA). 운영에 SIDDA.LGL_PIPE_RESULT_A가 없으면 CREATE_AGENT_STAGE_R1.txt.

4. 참고

· Dataiku 프로젝트 변수: LGL_GOLD_OWNER = SIDDS(개발계) / SIDDG(운영). 시험 복사본 실험 때만 LGL_GOLD_TABLE_PREFIX = TST_B003_LGL_ (끝나면 지우기).
· 지금 증분 코드(R2)는 증분 3표에 아직 기록하지 않습니다(기록은 관리 폴더 JSON). 표가 생기면 기록 쓰기와 처음 한 번 채우기를 붙입니다.
· 현장 실행·권한 상태는 이 메일로 바뀌지 않았습니다. 위 '지금 상태'는 기록 기준입니다.
