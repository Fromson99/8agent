이미 만든 Dataiku Managed Folder 최상위에 모두 업로드합니다. 큰 데이터 ZIP을 PC에 다시 다운로드해 합칠 필요는 없습니다.
사진의 ORIGINAL (4).sha256, PARTS (1).sha256 같은 파일명도 지원합니다. 여러 복사본의 검증 내용이 같으면 자동으로 처리하고, 내용이 다르면 정확한 검증 파일명을 지정하도록 알려줍니다. 번호가 큰 파일을 무조건 선택하지 않습니다.

실행
1. Dataiku 새 Python 노트북/새 커널에서 첨부 DATAIKU_EXISTING_ZIP_IMPORT_RUN.txt 전체를 한 셀에 붙입니다.
2. FOLDER_ID를 실제 생성한 폴더 ID로 설정합니다. INPUT_MODE="legacy_parts"는 그대로 둡니다.
3. ACTION="inspect" 실행: 큰 조각을 읽기 전에 번호/검증 목록/업로드 누락을 확인합니다. LEGACY_PARTS_READY가 나와야 합니다.
4. ACTION="merge" 실행: 모든 조각 SHA와 전체 원본 SHA가 일치해야 VERIFIED_ZIP_READY가 됩니다.
5. ACTION="restore" 실행 후 ORACLE_CONNECTION을 실제 연결 이름으로 설정하고 "check" → "publish"로 이어갑니다.
각 단계는 ACTION만 바꾸고 같은 셀 전체를 다시 실행합니다. 같은 WORK_DIR를 유지합니다.

병합 결과는 WORK_DIR/legacy-joined/legacy-verified.zip입니다. restore가 이 파일을 그대로 사용하므로 PC로 다시 내려받거나 재업로드하지 않습니다.
Managed Folder에서 1MiB씩 읽어 하나의 ZIP에 바로 기록합니다. 전체 조각의 로컬 복사본을 추가로 만들지 않습니다.
과거 part000030 끝1바이트 문제도 해당 조각의 원본 SHA와 병합 전체 원본 SHA가 모두 맞을 때만 새 출력에서 복구합니다. 업로드한 조각/검증 파일은 그대로 보존합니다. 중간 바이트 변조나 다른 해시 오류는 중단합니다.
병합 실패의 부분 ZIP은 보존되며 다시 실행하면 병합은 첫 조각부터 시작합니다. 완료 ZIP은 원본 해시 대조 후 재사용합니다.

기존 Oracle 이관 동작은 유지했습니다. 같은 원문/자산/조회 버전·키·내용은 재사용하고 없는 내용만 넣으며, 충돌은 덮어쓰지 않습니다. DELETE/TRUNCATE/ACTIVE/STATE 변경은 하지 않습니다. 최종 이관 완료 기준은 FULL_DATA_VERIFIED입니다.
