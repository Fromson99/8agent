Dataiku KURE 원문 3건 -> Oracle VECTOR 실제 임시 삽입·재조회 시험 (R2)
작성일: 2026-10-30 / ADR1236 / 현장 실행 결과 대기

1. 지금 실행하는 방법

같은 Dataiku 프로젝트(준비 확인에서 AIDP / SIDDS / KURE가 보였던 프로젝트)에서
새 Python notebook을 하나 만든다. 전체 적재 중인 notebook_7은 그대로 둔다.
Kernel Restart/Interrupt 또는 적재 셀 재실행은 필요하지 않다.

02_RUN_EMBEDDING_ORACLE_TEST.txt를 메모장으로 열고 전체를 복사한다.
새 notebook의 첫 셀에 전체를 붙인 뒤 Shift+Enter로 한 번 실행한다.
R1 준비확인 셀이나 sample 변수가 없어도 된다. 필요한 3행을 자체 조회한다.
ZIP을 올리는 방법을 쓴 경우 압축을 풀고 embedding_smoke.py를 실행하면 된다.
TXT 복사 방식과 ZIP 실행 방식 중 하나만 사용한다.
추가 패키지 설치, 비밀번호 입력, 테이블 생성, 전체 Flow 실행은 없다.

3. 무엇을 실행하나

입력: AIDP 연결의 SIDDS.LGL_DOC_BLK_S에서 본문이 있는 최대 3행.
DATA_VER_ID/DOC_ID/UNIT_ID/BLK_ID/SRC_DATA_HASH_VAL 및 본문 앞 800자를 읽는다.
3행 미만이거나 좌표/본문이 비정상이면 모델 호출 전에 멈춘다.

모델: openai:genos-embedding:embedding-kure-v1
승호님 코드와 같은 Dataiku LLM Mesh 경로:
get_llm -> new_embeddings -> add_text(3건) -> execute(1회) -> get_embeddings.
실제 원문 앞 800자씩 최대 2,400자가 이 등록 모델로 전달된다.
다른 외부 모델/API로 바꾸거나 API 키를 새로 입력하지 않는다.
등록 ID만으로 내부 모델 가중치 리비전/질의 서빙과의 동일성이 증명되는 것은 아니다.

응답: 3개, 각각 1,024차원, 유한 숫자, 0이 아닌 벡터인지 검사한다.
L2 정규화하고 FLOAT32로 변환한 뒤 아래 실제 테이블에 넣는다.

- SIDDS.LGL_VCTR_SET_S: 시험 정보 1행
- SIDDS.LGL_VCTR_ITEM_S: 시험 벡터 3행

새 무작위 시험 ID만 사용한다. 원문 테이블에 쓰지 않는다.
독립 Oracle 트랜잭션(PRAGMA AUTONOMOUS_TRANSACTION) 안에서 INSERT한다.
벡터 3행을 다시 읽어 차원·원래 벡터와의 Euclidean 거리·JSON 메타를 검사한다.
3x3 총 9쌍의 COSINE 거리를 Python의 같은 FLOAT32 벡터 계산과 대조한다.
정상/오류 모두 ROLLBACK하고, 별도 조회에서 시험 ID가 0행인지 확인한다.
COMMIT/DELETE/UPDATE/DDL/활성화/READY 게시 전환은 없다.

이 시험은 실제 INSERT와 같은 트랜잭션의 재조회 능력을 검증하지만,
COMMIT 후 영구 저장·다른 세션의 조회·전체 RAG 검색/답변을 검증하지 않는다.
시험이 성공해도 2개 벡터 테이블의 최종 행수가 그대로인 것이 정상이다.

4. 성공 화면

SOURCE_SAMPLES_OK 3; MODEL openai:genos-embedding:embedding-kure-v1
EMBEDDING_OK 3 x 1024
ORACLE_ROUNDTRIP_OK 3; COSINE_PAIRS_OK 9; ROLLBACK_OK remaining=0
EMBEDDING_ORACLE_SMOKE_PASS ...

마지막 JSON의 status=PASS와 위 마지막 성공 표시까지 있어야 통과다.
EMBEDDING_OK만 있으면 생성만 통과한 것이며 Oracle 확인은 아직 아니다.
모델 호출은 SDK execute 기준 1회다. 내부 서비스 물리 호출/재시도 수는 미측정이다.

5. 결과와 재실행

출력의 SUMMARY_FILE 경로에 summary.json이 남는다.
notebook 현재 작업 폴더/legal_embedding_smoke_ADR1236/run-001/
아래에 시작 기록, 실제 입력 좌표·문자열 gzip, SDK 임베딩 숫자 gzip, 요약을 저장한다.
입력/벡터 파일은 현장 안에 보관한다. 화면에는 본문이나 전체 벡터를 출력하지 않는다.
summary.json 또는 마지막 출력 화면을 공유하면 단계별 결과를 확인할 수 있다.

같은 위치에서 셀을 다시 실행하면 ALREADY_STARTED를 출력하고 기존 요약만 보여준다.
실수로 중복 임베딩 호출하지 않도록 한 장치다. 실행 중에는 새 노트북에서도 반복하지 않는다.
UNKNOWN/FAILED면 실패 단계·오류 코드가 요약에 남는다. 기록을 지워 재실행하지 말고
먼저 해당 출력으로 원인을 확인한다. 중간에 커널이 끊겼다면 마지막 IN_FLIGHT는 성공이 아니다.

6. 이번 확인 범위와 다음 단계

원문 전체 이관 검증이 진행 중이어도 이 제한된 연결 시험을 할 수 있다.
완료 게시본·전체 자료 무결성·법률 정답률을 통과로 취급하지 않는다.
정식 RAG 벡터 적재는 FULL_DATA_VERIFIED와 COMPLETE 조회 게시본을 확인한 다음,
같은 모델/차원/분할/정규화 설정을 고정하고 기존 정식 벡터 적재 절차로 수행한다.
Gold에 저장된 다른 모델의 기존 벡터와 KURE 벡터를 섞지 않는다.

로컬 사전 확인: 합성 임베딩 응답 + 임시 로컬 Oracle로 실제 SQL/롤백 및 실패 경로 검사.
현장 Dataiku 모델 호출·JDBC 드라이버·쓰기 권한은 이 셀을 실행해야 확인된다.
MAIN·GENOS 서빙·전체 적재 코드 변경 없음. 메일 발송 없음.
