요청하신 대로 중계서버 통신 확인 → 중계를 통한 법제처 호출을 노트북 하나로 정리했습니다.

사용할 파일: DATAIKU_RELAY_LAW_20261019_R1.ipynb
앞서 보낸 LAW_API·PHOTO_INPUTS 두 노트북 대신 이번 통합본 하나를 Dataiku에 가져와 위에서 아래로 실행하면 됩니다. 별도 모듈 업로드는 필요 없습니다.

  1. 준비: 중계 주소·CA 설정을 확인하고 공통 코드 셀을 실행합니다.
  2. 1단계 — 중계서버 통신: HEAD https://45.101.64.86:8443/law/DRF 요청 1회. 법제처 OC·Cookie·target_url은 보내지 않습니다.
  3. 2단계 — 법제처 호출: HTTP 응답을 받았으면 등록 OC와 필요한 경우 현재 중계 Cookie를 입력합니다. 같은 중계 주소로 GET 요청을 보내고 target_url: http://www.law.go.kr/DRF/lawService.do?target=law를 전달합니다.
  4. 결과: 중계 응답 여부와 실제 법령 본문 확인 결과를 따로 표시합니다.

첫 단계의 401·403·404·405도 HTTP 응답 수신입니다. 프록시 경로의 응답일 수도 있으며, 법제처 API 성공은 두 번째 단계에서 확인합니다. BODY_OK는 HTTP200과 XML 법령명·ID·조문 확인을 모두 통과한 결과입니다. 기본 조회 대상은 자본시장과 금융투자업에 관한 법률 본문 1건입니다.

같은 run_id는 성공·실패 기록을 다시 보여주며 중복 요청을 보내지 않습니다. 연결 설정을 고쳐 다시 확인하려면 설정 셀의 run_id를 relay-law-02처럼 바꾸세요. 기존 기록은 보존됩니다.

실행은 ipynb 하나만 사용하면 됩니다. ZIP과 전체 실행 Python TXT는 기존 첨부 선호에 따른 보조본입니다. ZIP 사용 시 압축을 풀고 안의 동일 ipynb를 가져오세요. TXT는 노트북 가져오기가 어려울 때 빈 Python 코드 셀에 전체 붙여 넣는 용도입니다.

실제 전달 셀로 로컬 15검사와 로컬 HTTPS 서버의 HEAD→GET→저장 흐름을 확인했습니다. 사내 Dataiku·중계서버 연결은 현장에서 이 파일을 실행해 확인해야 합니다. 이전 사진의 개발계 주소를 기본값으로 두었고 인증값은 저장하지 않았습니다.
