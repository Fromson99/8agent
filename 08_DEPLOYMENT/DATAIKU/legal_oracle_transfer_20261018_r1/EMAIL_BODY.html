요청하신 추가 테이블 SQL과 데이터 이관 코드를 한 묶음으로 보냅니다.

이번 첨부의 01 → 02 → 03 → 04 → 05 순서로 사용하세요. 이전 메일에서 셀을 따로 찾아 조합할 필요 없습니다. 기존 데이터와 샘플 행은 보존하며, 동일한 행은 재사용합니다.

  1. 01 TABLES — Dataiku AIDP SQL 노트북: SIDDA.LEGAL_RAG_ASSET_PART_A와 SIDDA.LEGAL_RAG_RELEASE_A를 추가합니다. CREATE 2문장을 각각 실행하고, GRANT 2문장은 권한 담당자가 실행합니다. BAIP04APP의 SELECT/INSERT가 필요합니다.
  2. 02 SOURCE_RUN — GENOS R6 노트북 새 Code 셀: 원문 3테이블 전체 이관. SOURCE_COMPLETE까지 실행합니다.
  3. 03 SOURCE_VERIFY — 같은 커널 새 Code 셀: 쓰기 없이 모든 원문 행/열과 건수를 다시 대조합니다. VERIFIED까지 확인합니다.
  4. 04 ASSETS — 같은 커널 새 Code 셀: 기존 탐색·전문검색 색인과 용어집/캐시를 업로드합니다. COMPLETE와 DP_RELEASE_ID를 보관합니다.
  5. 05 CHECK_SQL — Dataiku: 원문 버전별 건수와 완료 버전을 확인합니다.

GENOS의 성공한 R6 연결 desk를 그대로 사용합니다. client ID/secret은 첨부에 없습니다. 원본은 /nfs-root/diamo/8-agent/term-releases/financial-risk-success-20261005-schema-r2/generation/store.sqlite 입니다.

02/04는 PAUSED 후 같은 셀로 이어갈 수 있습니다. 03 전체 대조는 기본 6시간이며 중단 후 재실행하면 처음부터 검사합니다. 세부 한도와 복구 방법은 GUIDE_UTF8.txt에 적었습니다.

ZIP을 업로드한 실제 TRANSFER 폴더에서 다음 명령으로 풉니다.

python3 -m zipfile -e ./LEGAL_ORACLE_TRANSFER_20261018_R1.zip ./LEGAL_ORACLE_TRANSFER_20261018_R1

02~04 TXT는 Python 노트북 셀에 붙여넣는 코드입니다. bash로 실행하지 않습니다. 모든 실행 TXT는 ZIP 안과 별도 첨부에 같은 내용으로 들어 있습니다.

이 묶음의 전체 이관 범위는 선택한 RAG generation의 원문과 선언된 검색 자산입니다. NFS 전체 파일·과거 세대·대화/피드백 DB 이관은 포함하지 않습니다. 이번 메일은 데이터 이관용이며 MAIN 코드 패치나 서빙 전환을 실행하지 않습니다.

실제 임시 SQLite와 모의 Oracle/ORDS로 21검사 통과, Python 3.11.15 문법 컴파일 확인. 현장 Oracle SQL 엔진·전체 건수·속도와 실제 서빙 동작은 현장 실행으로 확인해야 합니다.
