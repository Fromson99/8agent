기존 NFS 구조화·색인 SQLite 재사용 확인 — 2026-10-29

사용자 확인: nfs-root를 여러 GENOS 코드서빙에서 볼 수 있다.
요청 방향: 원문 재구조화·재색인을 반복하지 않고 기존 결과를 Dataiku/Oracle로 이관한다.
사용자 예상: 기존 결과가 전체 남아 있을 가능성이 높다. 실제 잔존·완료 상태는 아직 미확인이다.

메일 첨부 실행 방법
GENOS_EXISTING_SQLITE_CHECK_20261029_R1.zip에는 실행 TXT와 이 안내가 함께 들어 있다.
PC에서 ZIP을 풀고 GENOS_EXISTING_SQLITE_CHECK.txt 전체를 GENOS Jupyter 새 셀에 붙여 실행한다.
별도로 첨부한 동일 TXT를 열어 사용해도 된다. Dataiku 노트북이 아니라 NFS가 보이는 GENOS에서 실행한다.
코드서빙 재배포·GENOS 패키지 설치는 필요 없다.

GENOS 터미널에서는 실제 업로드한 TRANSFER 폴더를 현재 위치로 두고 다음 순서로 실행한다.
python3 -m zipfile -e ./GENOS_EXISTING_SQLITE_CHECK_20261029_R1.zip ./GENOS_EXISTING_SQLITE_CHECK_20261029_R1
python3 ./GENOS_EXISTING_SQLITE_CHECK_20261029_R1/GENOS_EXISTING_SQLITE_CHECK.txt
EXISTING_SQLITE_CHECK_BEGIN부터 END까지의 출력만 전달한다.
이 ZIP은 확인 도구이며 기존 R10 구조화 계산 서비스의 설치 ZIP을 교체하는 자료가 아니다.

확인한 기존 구현
- oracle_full_package.inventory/export: 명시 세대의 원문·연결·사전·검색 자산 목록과 해시를 검증하고 내보낸다.
- oracle_query_package.export: 기존 SQLite 행과 FTS 위치를 Oracle 조회 행으로 변환한다. 구조화/형태소 색인을 새로 만드는 함수가 아니다.
- oracle_full_package.import_generation: 기존 원문·자산·조회행 적재 및 재조회 검증을 수행한다.
- 현재 02 worker는 STRUCTURE/PREPARE/INDEX/RETURN을 실행하므로 기존 결과 사용 경로로 연결하는 변경은 별도 필요하다.
- 실제 개발계 대상은 SIDDS.*_S / 기존 Dataiku 연결 AIDP다. 옛 SIDDA 무접미사 적재 가이드를 그대로 실행하지 않는다.

현장 확인 1단계
GENOS_EXISTING_SQLITE_CHECK.txt 전체를 NFS가 보이는 GENOS Jupyter의 새 Python 셀에서 실행한다.
터미널이라면 이 파일이 있는 폴더에서 다음 명령을 실행한다.
python3 ./GENOS_EXISTING_SQLITE_CHECK.txt

기본값은 환경변수 GENOS_GENERATION, ~/DEV/00_SYSTEM/GENOS_SERVING_PATHS.json,
2026-10-21에 기록된 financial-risk-success-20261005-schema-r2 경로를 후보로 표시한다.
이들은 과거/설정 경로이며 현장에 현재 존재하거나 이번 사용 대상이라고 확정하지 않는다.
실제 위치를 알면 TXT 맨 위 GENERATION_PATH에 해당 절대경로를 넣는다.
후보를 날짜순으로 자동 선택하거나 NFS 전체를 탐색하지 않는다.
BEGIN~END 출력으로 기존 자료 위치·명세·관련 파일 존재를 확인한다.

이 도구는 작은 명세와 파일 크기만 읽는다. SQLite를 열거나 원문을 출력하지 않는다.
파일 복사·원본 수정·모델/HTTP 호출·구조화·색인·Oracle 적재·서비스 변경은 없다.
파일이 있다는 결과만으로 무결성·완료·현행 최신 판본·Oracle 호환을 보증하지 않는다.
실제 이관에는 명시 세대의 전체 해시·연결 일치와 현재 SIDDS 매핑 검증이 필요하다.

다음 연결
완성된 구조화/색인 묶음이면 기존 결과를 읽기 전용으로 제공하고 Dataiku가 수신·보관·적재한다.
GENOS가 S3에 직접 쓰는 구조는 사용하지 않는다. 행 변환·전송·Oracle 대조 비용은 남는다.
source.sqlite만 남은 중간 결과이면 원문 재구조화는 생략할 수 있어도 검색 자산 존재는 별도 확인한다.
기존 세대 이후 추가/변경된 문서는 이번 재사용 범위에 자동 포함되지 않는다.

로컬 확인
실제 TXT의 문법과 합성 명세를 실행해 파일 존재 검사, 원본 바이트 보존,
없는 경로/상대경로/세대 밖 참조/손상 JSON 처리를 확인했다.
GENOS 현장 접근·NFS 존재 확인·이관 경로 변경·배포·Oracle 적재는 아직 수행하지 않았다.
