Gold R3 — 오류 상세 즉시 표시 수정본 / 2026-11-02

사진의 상태
ORA-12801 / ORA-06512 / ORA-01691, WRITE_UNCONFIRMED가 보입니다.
ORA-01691은 LOB 세그먼트 확장에 필요한 공간 할당 실패입니다.
사진만으로 실패 LOB 세그먼트명·테이블스페이스명·확장 제한 원인은 알 수 없습니다.
이전 R2는 오류 코드만 저장하고 상세 문장을 버렸으므로 과거 원문 복원은 불가능합니다.
Oracle 설명: https://docs.oracle.com/en/error-help/db/ora-01691/

먼저 이번 실패를 확인
1. 기존 셀이 종료된 상태에서 같은 LEGAL_RAG Dataiku Python 노트북 새 셀을 사용합니다.
2. DATAIKU_GOLD_FAILURE_DIAG_R3.txt 전체를 붙여 실행합니다.
   이전 OLD_JOB_DIR을 직접 지정했다면 동일한 값을 넣습니다.
   이 셀은 기존 상태와 미확인 묶음을 읽고 ALL_TABLES/ALL_LOBS만 조회합니다.
   DB 적재·삭제·DDL·임베딩·재시도는 없습니다. ZIP을 새로 올릴 필요도 없습니다.
3. 표시된 실패 대상 표와 LOB 세그먼트/테이블스페이스를 DBA에 전달해 공간 할당 실패를 확인합니다.
   현재 상태 파일은 삭제하지 말고 RETRY_MISSING_BATCH=False를 유지합니다.

- GUIDE.txt — 이 안내

공간 문제 확인·조치 뒤 재개할 때는:
1. LEGAL_RAG 관리 폴더 ehA8dpVm에 R3 ZIP을 이름 그대로 업로드합니다.
   R1 ZIP도 같은 폴더에 필요하며 이미 있으면 재업로드하지 않습니다.
   R2 ZIP은 과거 기록으로 보존할 수 있습니다. 각 정확한 파일명은 한 개씩만 둡니다.
2. Dataiku 환경변수 또는 프로젝트 변수:
   LEGAL_EMBED_LLM_ID=openai:genos-embedding:embedding-kure-v1
   LEGAL_EMBED_DIMENSIONS=1024
   실제 환경변수 우선이며 별도 URL/API 키는 넣지 않습니다.
3. R3 통합 TXT 전체를 새 Python 셀에 붙여 실행합니다. R2 실행 TXT와 동시에 실행하지 않습니다.
   남은 적재 → 검증 → 벡터 순서이며 앞 단계 실패 시 다음 단계는 멈춥니다.

R3 변경점
- 실제 DB 호출 경계에서 예외 체인·ORA 상세 문장·단계·테이블·묶음 행 수를 먼저 출력합니다.
- 오류를 최근 18줄 화면 갱신으로 지우지 않으며 마지막 RuntimeError에도 상세 내용을 붙입니다.
- 오류 전용 .errors.jsonl과 전체 .log를 노트북 작업 폴더/gold-progress-logs에 보존합니다.
- WRITE_UNCONFIRMED/VERIFY_FAILED/FAILED 상태에서 잔여시간 대신 중단됨을 표시합니다.
- SQL 바인딩·원문 본문·인증값은 출력하지 않습니다. DB가 반환한 오류 설명과 코드 위치만 남깁니다.
- R1 실행 파일은 그대로 해시 검증하고, 별도 진단 어댑터가 예외 출력만 추가합니다.
  SQL/인자/반환값/예외 객체·기존 재개 binding·원래 기한·확인 검사·DB 쓰기 의미는 유지합니다.
- 이 수정은 공간을 늘리거나 과거 결과불명 묶음을 자동 재전송하는 수정이 아닙니다.
  이전 실패 묶음이 실제 DB에 없으면 기존 재개 검사가 다시 멈출 수 있습니다.
  그 경우 오류를 확인하고 별도 복구해야 하며 상태 삭제/강제 재시도하지 않습니다.

벡터 완료 표시는 VECTORS_STORED_VERIFIED_NOT_ACTIVATED입니다.
서비스 검색 전환과 벡터 검색 전용 인덱스 생성은 별도입니다.
R2에서 이미 벡터를 생성한 별도 작업은 helper binding 변경으로 자동 재사용되지 않을 수 있습니다.
이번 사진은 원문 적재 실패로, 통합 실행의 벡터 단계까지 도달한 화면이 아닙니다.
