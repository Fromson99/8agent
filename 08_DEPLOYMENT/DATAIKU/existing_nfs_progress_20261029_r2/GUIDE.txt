NFS→Oracle 진행상황 및 최근 로그 500줄 조회 — R2 / 2026-10-29

이번 파일은 기존 DATAIKU_NFS_PROGRESS_READONLY_R1.txt 대신 사용하는 조회용 R2입니다.
적재용 DATAIKU_EXISTING_NFS_RUN_R2.txt와는 다른 파일입니다.

사용 방법
1. 첨부 ZIP을 압축 해제합니다. 같은 실행 TXT를 별도로도 첨부했습니다.
2. DATAIKU_NFS_PROGRESS_TAIL500_R2.txt를 텍스트 편집기로 엽니다.
3. Dataiku의 Python 조회 노트북에서 새 셀에 전체 내용을 붙여넣고 실행합니다.
   사진에서 Oracle 문서 2,121건을 조회했던 노트북을 사용해도 됩니다.
   이 파일은 Python 셀용입니다. bash로 실행하지 않습니다.
4. 위쪽의 마지막 저장 단계, 검증된 건수, 오류 기록을 확인합니다.
5. 아래쪽에 가장 최근 수정된 calls.jsonl의 마지막 최대 500줄이 나옵니다.
   SQL 로그가 없으면 가장 최근 수정된 JSONL 로그를 선택합니다.
   500줄 미만인 파일은 있는 줄만 표시합니다. 파일 전체를 처음부터 읽지 않습니다.
6. 20초 정도 뒤 같은 셀을 다시 실행하면 새 시점의 결과를 확인할 수 있습니다.
   자동 반복 실행은 하지 않습니다. 출력이 길면 셀 출력 영역을 스크롤합니다.

특정 로그를 선택할 때
출력되는 '최근 로그 목록'에서 상대경로를 복사해 실행 TXT 위쪽의
LOG_RELATIVE_PATH = "" 안에 넣습니다. 기본값은 그대로 두면 됩니다.
TAIL_LINES = 500을 변경하면 표시할 줄 수를 조절할 수 있습니다.

판독 기준
- BATCH_VERIFIED: 해당 배치를 DB에서 다시 읽어 데이터 대조까지 완료한 기록입니다.
- 검증된 누적 건수는 해당 source 상태 파일에 저장된 마지막 값입니다.
- RUNNING / WRITE_STARTED: 저장 당시 상태입니다. 현재 프로세스 생존 증거는 아닙니다.
- STARTED / ACKNOWLEDGED의 write=false는 조회이며 데이터 삽입 성공을 뜻하지 않습니다.
- WRITE_UNCONFIRMED: 쓰기 결과를 확정하지 못한 상태입니다. 중복 적재를 임의 실행하지 마세요.
- READ_FAILED / failure: 오류를 확인할 단서입니다. 과거 오류일 수도 있으므로 시각과 후속 기록을 함께 봅니다.
- 로그가 잠시 늘지 않는 것만으로 중단됐다고 단정하지 않습니다.
- SOURCE_COMPLETE는 원문 단계 완료입니다. 전체 이관 완료와 구분합니다.
- 기존 주피터 탭을 닫아도 커널이 계속 실행됐을 수 있습니다.
  셀의 화면 출력 전체가 아니라 서버에 저장된 진행 기록을 읽는 도구입니다.

기록이 보이지 않을 때
LEGAL_PIPELINE_SCRATCH 설정 또는 /tmp를 기준으로 이전 R2 이관 경로를 찾습니다.
별도 컨테이너/실행 환경에서는 원래 기록 경로가 보이지 않을 수 있습니다.
파일이 보이지 않는다는 이유만으로 원래 적재를 중단/재시작하지 마세요.

실행 범위
이 TXT는 상태 JSON과 JSONL 로그를 읽기만 합니다. Oracle/GENOS 호출, 적재 실행/재개,
파일 쓰기, 커널 종료/재시작을 하지 않습니다. 현장 실행 결과는 아직 검증하지 않았습니다.
로컬에서 Python 문법 및 끝부분 읽기를 확인한 조회 도구입니다.
