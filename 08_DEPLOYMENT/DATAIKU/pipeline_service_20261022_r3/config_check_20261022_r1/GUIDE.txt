Dataiku 파이프라인 변수 설정 및 Oracle 테이블 목록 조회 — 2026-10-22 R1

1. LEGAL_PIPELINE_URL이란
Dataiku가 원문을 보내 구조화·색인을 요청할 새 GENOS 파이프라인 전용 코드서빙의
실제 HTTPS 호출 주소입니다. GENOS_PIPELINE_SERVICE_20261022_R2.zip으로 전용
서비스를 배포한 뒤, 그 서비스의 API 호출 예제에서 POST에 사용하는 전체 주소를 넣습니다.
아직 전용 서비스를 배포하지 않았다면 그 주소를 먼저 확보해야 합니다.
이 문서에는 확인되지 않은 서비스 URL이나 서비스 ID를 예시값으로 넣지 않았습니다.

Dataiku 프로젝트 변수
  LEGAL_PIPELINE_URL: 위 전용 서비스의 실제 HTTPS 호출 주소
  LEGAL_PIPELINE_TOKEN: 그 서비스를 호출하는 실제 토큰. Bearer 접두어 제외
  LEGAL_ORACLE_CONNECTION: 기존 Oracle 연결 이름 AIDP
토큰은 메일로 회신하지 말고 현장 관리 설정에 입력하세요.

2. 현재 READY의 의미
사용자 제공 화면의 READY는 원문·용어집 파일 복원과 검증 완료입니다.
oracle_written=false는 prepare 단계의 정상 결과입니다.
GENOS 서비스 연결 또는 Oracle 테이블 존재·적재 완료를 뜻하지 않습니다.

3. Oracle 테이블 확인
메일에 별도로 첨부한 DATAIKU_ORACLE_TABLE_CHECK_20261022_R1.txt 전체를
LEGAL_RAG 프로젝트의 Python 노트북 새 셀에 붙여넣고 실행하세요.
현재 기본 연결 이름은 AIDP이며, 현장 연결 이름이 다를 때만 수정합니다.
이 코드는 SELECT 조회만 합니다. GENOS를 호출하거나 DB 데이터를 변경하지 않습니다.

적재 대상 7개
  SIDDA.LEGAL_SRC_DOCUMENT_A
  SIDDA.LEGAL_SRC_SOURCE_UNIT_A
  SIDDA.LEGAL_SRC_BLOCK_PAYLOAD_A
  SIDDA.LEGAL_RAG_ASSET_PART_A
  SIDDA.LEGAL_RAG_RELEASE_A
  SIDDA.LEGAL_RAG_QUERY_ROW_A
  SIDDA.LEGAL_RAG_QUERY_RELEASE_A

현재 공통 스키마 검증에서 추가로 확인하는 2개
  SIDDA.LEGAL_RAG_QUERY_ACTIVE_A
  SIDDA.LEGAL_RAG_QUERY_STATE_A
파이프라인 적재에서는 이 두 제어 테이블의 값을 변경하지 않습니다.
따라서 이전 안내의 적재 대상 7개와 이번 존재 확인 대상 9개는 범위가 다릅니다.

결과 해석
  9개 조회: 현재 연결에서 해당 테이블 목록을 확인한 것입니다.
  빠진 항목: 미생성 또는 현재 연결의 접근 권한을 확인해야 합니다.
  연결 오류: AIDP 연결 이름·이용 권한·접속 상태를 확인해야 합니다.
  목록 조회 성공만으로 컬럼·인덱스·제약조건·쓰기 권한까지 확인된 것은 아닙니다.
현재 파이프라인은 적재 전에 유지보수 중인 스키마 검사도 수행하며,
테이블 생성·전체 초기화를 자동 수행하지 않습니다.
그 검사가 GENOS 처리 후에 있으므로 이 목록 조회를 먼저 실행합니다.

4. 실행 순서
  (1) 지금 첨부한 조회 코드로 Oracle 테이블 목록을 확인합니다.
  (2) 파이프라인 전용 GENOS 서비스 R2 배포와 실제 호출 주소·토큰을 확보합니다.
  (3) Dataiku 프로젝트 변수 3개를 설정합니다.
  (4) 기존 DATAIKU_PIPELINE_RUN_20261022_R3.txt의 ACTION을 "run"으로 실행합니다.
prepare에서만 진행한 지금 작업의 WORK_DIR와 JOB_NAME은 그대로 유지합니다.
이미 다른 서비스 버전으로 GENOS 작업을 시작한 기록은 기존 재개 지침을 따릅니다.

이 첨부는 앞서 보낸 Dataiku R3 실행본 / GENOS 서비스 R2를 대체하지 않습니다.
변수 설정과 DB 목록 확인을 위한 추가 안내입니다. 기존 데이터는 다시 올리지 않습니다.
NFS 설정·마운트·데이터 generation은 변경하지 않습니다.

5. ZIP 사용
PC에서 ZIP을 풀고 내부 TXT를 열어도 됩니다. Linux 터미널에서 풀 때:
  python3 -m zipfile -e ./DATAIKU_PIPELINE_CONFIG_CHECK_20261022_R1.zip ./
TXT는 Python 노트북에 붙여넣을 코드이며 bash 실행 파일이 아닙니다.

검증 범위
로컬에서 Python 3.11 문법과 최종 ZIP 파일 목록·무결성을 확인했습니다.
실제 내부 Dataiku/Oracle 접속 및 현장 테이블 존재는 이 세션에서 확인하지 않았습니다.
