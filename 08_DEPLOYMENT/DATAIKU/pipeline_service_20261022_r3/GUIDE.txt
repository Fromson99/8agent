2. GENOS 실행 전에 필요한 코드
GENOS에서도 같은 압축 해제 모듈을 쓰므로 서비스 쪽도 고쳐야 합니다.
새 파이프라인 전용 코드서빙은 GENOS_PIPELINE_SERVICE_20261022_R2.zip을 사용합니다.
R3 실행본의 ACTION="run"은 이 서비스 R2의 코드 해시를 요구합니다.
서비스가 구 R1이면 DEPLOYED_CODE_MISMATCH로 멈춥니다. 임의로 해시를 바꾸지 마세요.
기존 RAG DEV/service.py에 덮어쓰거나 NFS generation을 바꾸는 작업이 아닙니다.

GENOS 현장 반입
실제 ZIP을 올린 TRANSFER를 현재 작업 폴더로 두고:
  python3 -m zipfile -e ./GENOS_PIPELINE_SERVICE_20261022_R2.zip ./
압축을 푼 위치와 실제 배포하는 파이프라인 전용 Git checkout은 구분합니다.
새 전용 코드서빙을 아직 만들지 않았다면 R2의 전체 내용을 그 전용 저장소 코드로 사용합니다.
R1 전용 checkout이 이미 있다면 기존 코드를 보존/백업한 뒤 다음 변경만 반영합니다.
  교체: transport.py, 02_BACKEND/lawrag/core/rawstore.py, GUIDE.txt, CODE_PINS.json
  추가: VERIFY_PIPELINE_RELEASE.py, GENOS_PIPELINE_CHECK.txt
그 외 R1 파일은 동일합니다. 변경 파일과 git diff --check를 확인하고 전용 저장소에 commit합니다.
아래 실제 경로는 파이프라인 전용 checkout 절대경로로 바꿉니다. 기존 RAG checkout을 넣지 마세요.
  bash ./GENOS_PIPELINE_SERVICE_20261022_R2/GENOS_PIPELINE_CHECK.txt /실제/파이프라인전용/Git체크아웃
체크 결과 CODE_VERIFIED와 commit을 확인한 뒤 해당 커밋을 push하고 새 코드서빙 리비전을 배포합니다.
후보 폴더 검사만 통과한 것을 실제 배포 성공으로 취급하지 않습니다.
체크 로그는 명령을 실행한 TRANSFER 아래 PIPELINE_RELEASE_CHECK_LOGS에 남습니다.
이 서비스는 요청별 임시 입력을 처리하므로 고정 NFS generation/RAG 릴리스 게이트를 실행하지 않습니다.
실제 서비스 요청은 Dataiku의 기존 파이프라인 호출 경로로 확인하며, 직접 테스트 UI를 요구하지 않습니다.
기존 작업이 실행 중인 서비스의 리비전을 중간에 교체하지 마세요. 이번 사진의 실패는 GENOS 호출 전입니다.
