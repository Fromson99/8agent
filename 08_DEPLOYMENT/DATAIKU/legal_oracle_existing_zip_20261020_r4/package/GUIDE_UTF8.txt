실행 순서
1. 기존 Managed Folder에 LEGAL_ORACLE_EXISTING_ZIP_20261020_R4.zip만 추가 업로드합니다.
2. 이관이 중단된 같은 노트북에서 Kernel → Restart 후, R4 DATAIKU_EXISTING_ZIP_IMPORT_RUN.txt 전체로 실행 셀을 교체합니다. 코드 파일명/해시만 수작업으로 바꾸지 마세요.
3. FOLDER_ID, ORACLE_CONNECTION은 기존 성공한 값으로 설정합니다. WORK_DIR는 ./legal-existing-zip-r2-work 그대로, ALLOW_MISSING_LOOKUP_INDEXES=True를 유지합니다.
4. ACTION="check"로 실행해 READY_FOR_FULL_IMPORT를 확인합니다.
5. ACTION="diagnose"로 같은 셀을 실행합니다. 기존 R3 source_unit checkpoint 다음 배치의 키만 Oracle에서 두 번 조회해 기본 추정과 수정 경로를 비교합니다. 키 원문/본문은 출력하지 않고 상태나 Oracle 데이터도 변경하지 않습니다.
   TYPE_INFERENCE_DIFFERENCE_CONFIRMED: 기본 경로에서 변형된 키가 수정 경로에서는 원본과 일치함을 확인했습니다.
   KEYS_MATCH_ON_BOTH_PATHS: 이번 배치의 키는 양쪽 모두 일치합니다. 이전 오류의 정확한 원인은 이 검사로 확정되지 않습니다.
   NO_EXISTING_TARGET_ROWS: 대상 행이 없어 실제 반환 자료형 비교를 확정하지 못했습니다.
   TYPED_KEYS_STILL_DIFFER: 수정 경로도 원본 키와 다릅니다. publish하지 말고 결과를 공유하세요.
6. TYPE_INFERENCE_DIFFERENCE_CONFIRMED이면 ACTION="publish"로 재개합니다. 다른 결과는 먼저 출력 결과를 공유해 원인을 좁힙니다. 최종 FULL_DATA_VERIFIED가 전체 대조 완료 상태입니다.
