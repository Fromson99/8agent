CM R14 — 이전 CM R11/R12 대신 실행

정식 문서명·개별 파일명·보존된 원래 이름/별칭으로 연결합니다.
부모 폴더명만 같은 시행령·시행규칙·시행세칙은 다른 법령에 연결하지 않습니다.
정상 규정명에 포함된 서식·별첨은 보존하고 추가 개정·제정안·신구대비·요약·참고와
별표/서식 폴더는 구분합니다. 분해된 한글(NFD)도 NFC로 대조합니다.
본문/전문/조문을 유지하며 사본 번호·날짜·판본을 임의로 삭제하지 않습니다.
금지 문자 치환이나 해시 접두어는 보존된 정식명/원래 이름으로 해결합니다.
실제 원문 누락·중복 판본/조문·권한·세대 해시 불일치는 계속 중단합니다.

ZIP을 기존 ~/DEV/TRANSFER에 올리고 아래 세 줄을 실행합니다.
python3 -m zipfile -e ~/DEV/TRANSFER/GENOS_CM_ONECLICK_20261008_R14.zip ~/DEV/TRANSFER
(cd ~/DEV/TRANSFER && sha256sum -c GENOS_CM_ONECLICK_20261008_R14_SHA256SUMS.txt)
bash ~/DEV/TRANSFER/GENOS_CM_ONECLICK_20261008_R14_RUN.txt

별도 RUN TXT를 TRANSFER에 올렸으면 마지막 bash 한 줄로도 실행할 수 있습니다.
R11 package-check 실패 상태와 이미 R12를 적용한 상태에 이어 적용합니다.
검증된 R8/R10/선행 코드도 지원합니다. 기존 조사 한도 설정과 service.py 바이트,
R11/R12의 원래 부모 inventory·백업·실패 기록을 모두 대조해 보존합니다.
알 수 없는 코드 변경이나 선택 generation 변경은 덮어쓰지 않습니다.
원문 재구축·RAW 이름 변경·조사 한도 재적용·새 환경변수/사용자 JSON 입력은 없습니다.

원문51건/근거98개 연결 확인 → commit → 같은 checkout/generation gate →
공통 등록/검증 → 기존 origin push를 수행합니다. 기존 CM 등록도 원래 이름으로
같은 문서·근거에 결속되는지 재대조한 뒤 재사용하며 중복 등록하지 않습니다.
이전 등록이 다른 원문에 연결돼 있으면 기존 자료를 보존하고 중단합니다.
EXIT=0과 READY_FOR_REVISION_DEPLOYMENT이면 출력된 COMMIT으로 새 코드서빙
리비전을 배포하고 워크플로우 테스트 화면에서 질문을 확인합니다.
코드 적용·등록·push·새 리비전·질문 성공은 각각 별도 상태입니다.
