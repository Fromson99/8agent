GENOS 함수별 시간 진단 R1 — 기존 보고서 분석 + 선택적 새 요청 계측

A. 기존 로깅으로 확인 가능한 것
기존 요청 보고서를 extract로 먼저 다시 읽습니다. 서버 변경·모델 호출은 없습니다.
R2의 전체/모델/HTTP/토큰/공백 분석에 fulltext.sql.timings 등의 숫자 세부값을 더 보여줍니다.
해당 로그가 남아 있으면 SQL 실행·fetch·범위 필터 시간을 확인할 수 있습니다.
원문 블록별 호출 횟수, 후보 읽기량 계산, 함수별 시간은 기록이 없으면 복원할 수 없습니다.
기존 query_latency는 rollback 구현으로 꺼져 있어 GENOS_QUERY_LATENCY=1만으로 켜지지 않습니다.

실제 파일을 올린 TRANSFER 폴더에서:
mkdir -p ./function-timing-extract-logs
python3 -m zipfile -e ./GENOS_FUNCTION_TIMING_20261022_R1.zip ./GENOS_FUNCTION_TIMING_20261022_R1 > ./function-timing-extract-logs/unzip.log 2>&1
TASK_UNZIP_RC=$?
printf '%s\n' "$TASK_UNZIP_RC" > ./function-timing-extract-logs/unzip.exit
cat ./function-timing-extract-logs/unzip.log

압축 해제 종료가 0일 때:
bash ./GENOS_FUNCTION_TIMING_20261022_R1/GENOS_FUNCTION_TIMING_20261022_R1.txt extract "/정확한/요청보고서.json"
.json.gz도 지원합니다. 과거 요청에 함수 계측 미기록이라고 나오는 것은 정상입니다.
결과는 현재 위치의 GENOS_TIMING_RESULTS/DETAIL-R1-시각-임의문자/에 보존됩니다.
SUMMARY.txt / TIMELINE.txt / DIAGNOSTICS.json / EXECUTION.log / EXIT_CODE.txt를 확인합니다.
완료 표시와 종료0이 없는 결과를 완료 자료로 취급하지 않습니다.
별도 TXT에도 전체 코드가 들어 있어 정상 텍스트 환경에서는 단독 실행 가능합니다.

B. 다음 요청의 함수별 시간 기록 — 코드서빙 반영 필요
기존 ~/DEV Git checkout이 적용 대상입니다. TRANSFER에서 계속 명령을 실행합니다.
기본 대상이 다르면 아래 모든 설치 명령에 --root /실제/DEV/경로를 동일하게 추가합니다.
기존 MAIN99/MAIN101 인계본과 동일한 service.py 바이트만 허용합니다.
다른 service.py이면 check가 실제 해시를 알려주고 중단합니다. 파일을 임의 덮어쓰거나 rehash하지 않습니다.
수정은 service.py의 기존 요청 dispatch에 진단 연결 1곳과 genos_timing_probe.py 추가뿐입니다.
원문·색인·모델·프롬프트·질문·읽기 예산·MAIN 포인터·워크플로우 편집기는 변경하지 않습니다.

bash ./GENOS_FUNCTION_TIMING_20261022_R1/GENOS_FUNCTION_TIMING_20261022_R1.txt check
bash ./GENOS_FUNCTION_TIMING_20261022_R1/GENOS_FUNCTION_TIMING_20261022_R1.txt apply
bash ./GENOS_FUNCTION_TIMING_20261022_R1/GENOS_FUNCTION_TIMING_20261022_R1.txt gate

check/apply/gate는 현재 엔진과 워크플로우의 코드 해시도 검증합니다. 전체 rehash는 하지 않습니다.
원본 백업·재실행 상태는 현재 TRANSFER의 GENOS_FUNCTION_TIMING_STATE_R1에 보존됩니다.
같은 TRANSFER 위치에서 재실행합니다. 중단 후 apply를 반복하면 같은 원본과 대상 해시를 확인해 이어 적용합니다.
기존 사용자 변경이 생기면 적용/복원을 중단하고 보존합니다.

~/DEV에서 실제 변경 diff를 검토하고 service.py, genos_timing_probe.py를 기존 방식으로 커밋합니다.
다른 진행 중인 변경이나 staged 파일을 섞지 않습니다. 이 도구는 commit/push/배포를 실행하지 않습니다.
커밋 뒤 TRANSFER에서:
bash ./GENOS_FUNCTION_TIMING_20261022_R1/GENOS_FUNCTION_TIMING_20261022_R1.txt gate --committed

SQLite/NFS generation을 사용하는 현장은 검증된 기존 세대 경로로 추가 게이트를 실행합니다.
bash ./GENOS_FUNCTION_TIMING_20261022_R1/GENOS_FUNCTION_TIMING_20261022_R1.txt gate --committed --generation "/실제/선택된/generation"
이때 기존 genos_release_gate의 실제 checkout/세대 검사와 verify_assets가 실행됩니다.
원문 전체 해시를 확인하므로 무거운 다른 작업과 동시에 실행하지 않습니다.
Oracle 조회 환경에는 SQLite 경로를 만들거나 다운로드하지 않고, --generation을 생략합니다.
Oracle 데이터 버전·조회 권한과 실제 서빙 리비전은 현장 확인으로 별도 남깁니다.

같은 커밋을 push하고 코드서빙 리비전을 갱신합니다.
코드서빙 프로세스 환경변수 GENOS_FUNCTION_TIMING=1을 설정하고 반영/재시작합니다.
이 값을 TRANSFER 터미널에서 export하는 것만으로 이미 떠 있는 코드서빙 환경이 바뀌지는 않습니다.
GENOS_SHARED_LOG_DIR은 기존 정상 요청 보고서 저장 설정을 유지합니다.
질의는 기존 워크플로우 테스트 화면에서 한 번 실행합니다. 코드서빙 직접 테스트 UI/API는 사용하지 않습니다.
새 요청의 정확한 JSON 경로로 extract 명령을 다시 실행합니다.
새 JSON에 timing.probe.started와 timing.probe.summary가 모두 있어야 계측 결과가 있습니다.
요청 ID·서빙 리비전/커밋·선택 데이터 버전·함수 코드 지문을 함께 보존합니다.

C. 측정 항목과 해석
- fulltext: rank / projection / law_groups_page / article_groups_page / hit_page
- 비활성 query_latency 호출 지점: SQL execute+fetch(rows), projection/decode/모델 준비 등 기존 span
- 후보 준비: filter_navigation / article_plan / article_sequence / sequence_cost / read_cost
- 원문: Store.source / sources, check_unchanged / binding_signature
- 상태: evidence / heads / navigation_save / save_view / reserve_attempt / finish_attempt
- 모델: send_once / send_stream_once (기존 모델·HTTP 시간과 중첩; 합산 금지)
- 후보 수, 함수 호출/오류 횟수, 포함/자체 벽시계, 스레드 CPU, 느린 개별 호출, 호출 관계
- source 호출 수, 같은 Store 객체·문서·블록 키의 고유 수와 재호출 수

포함 시간에는 하위 호출이 들어 있습니다. 자체 시간은 계측된 같은 스레드 자식의 시간을 뺀 값입니다.
미계측 하위 작업은 자체 시간에 남습니다. 자체 시간도 순수 계산/SQL 실행만을 뜻하지 않습니다.
부모/자식 포함 시간은 더하지 않습니다. 병렬 스레드 합계는 요청 벽시계보다 클 수 있습니다.
원문 호출 횟수는 Python API 호출 횟수이며 물리 SQL·디스크 I/O 횟수가 아닙니다.
같은 키의 재호출은 다른 이유로 필요할 수도 있어 전부 삭제 가능한 중복으로 단정하지 않습니다.
벽시계-CPU 차이에는 I/O/잠금/스케줄링/네트워크 등이 들어갑니다. Oracle/디스크 시간이라고 단정하지 않습니다.
모델 서버 큐·입력 처리·추론·생성의 구분은 서버 자체 계측이 필요합니다.
진단 연결 준비 시간은 setup_ms로 따로 기록합니다. 계측 자체의 부하도 요청에 포함됩니다.
수집은 요청당 최대20만 진입/15분/고유 블록키2만/관계512/느린 호출30개로 제한합니다.
한도 초과는 warnings와 skipped_calls로 표시하며 원래 요청을 계속 처리합니다.
대상 함수 미연결, 요청 컨텍스트가 전파되지 않은 별도 스레드, import 시 이미 복사된 함수 별칭은 미계측일 수 있습니다.
started의 coverage와 summary의 warnings를 확인합니다. 누락 함수는 0초로 판정하지 않습니다.
질문·원문·모델 답변·SQL·바인드·인증정보·문서/블록 ID는 새 진단 집계에 기록하지 않습니다.
기존 원장/응답/오류/권한·무결성 검사는 그대로 실행합니다. 모델을 추가 호출하지 않습니다.

D. 종료/원복
진단 요청을 마치면 코드서빙 환경변수 GENOS_FUNCTION_TIMING=0으로 반영합니다.
설정이 없거나 0이면 새 함수 계측은 동작하지 않습니다. 필요할 때만 1로 켭니다.
코드까지 복원하려면 같은 TRANSFER에서:
bash ./GENOS_FUNCTION_TIMING_20261022_R1/GENOS_FUNCTION_TIMING_20261022_R1.txt rollback
복원 후 이전 코드 커밋·코드서빙 리비전 복귀는 별도입니다. 사용자 추가 수정이 있으면 보존하고 중단합니다.
프로세스 강제 종료 시 summary가 없을 수 있습니다. 기존 원장/불완전 로그는 보존합니다.

현장 상태: 이번 패키지의 반입·commit/push·리비전·환경변수·새 질의는 미수행입니다.
로컬 검사 결과는 VALIDATION.json에 별도로 기록하며 현장 성공을 대신하지 않습니다.
