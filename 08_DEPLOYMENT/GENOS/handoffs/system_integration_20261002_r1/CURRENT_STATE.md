# 전체 시스템 통합과 GENOS 이관 상태

2026-10-02. 사용자 요청: 현재 MAIN에 누적 개발을 통합하고 GENOS 반입 자료까지 준비.

최신 MAIN 작업 코드에 누적 멀티턴 구현을 **반영했다**. 수정 전 파일은 별도 백업했고, 같은 코드로 GENOS 반입본을 만든다. Git 작업 브랜치는 `feature/legal_RAG`이며 Git main 병합·commit/push는 하지 않았다. 선택된 로컬 MAIN은 `legal-agent-source-prefix-20260930-r3`, generation37이다. 활성 릴리스 변경·GENOS 코드서빙 배포는 실행하지 않았다. 과거 ADR0613은 Rejected이며 그 판정을 바꾸지 않았다.

## 구성과 소비자

기존 RAW 반입 → 구조화 → 원문 통합 → 용어 후보/정의/관계 검토 → 문서–용어·명시 참조 연결 → navigation/fulltext → RAG → 피드백을 보존한다. 기준은 현재 작업 코드이며 활성 r3 이후 작업판 수정도 포함한다. 수신 로그·질문 의무·오류 수리·구조 우선 검색·PeCab·팀/내규/외규·SSE·워크플로우 진행 UI, 10월1일 구축/의미 검토 자료를 함께 인계한다.

멀티턴 입구는 기존 `service.py → /v1/rag/ask`다. memory 요청에서만 세션·사용자·요청 ID를 보존한다. 워크플로우가 플랫폼 사용자/대화와 고정 TEAM_ID를 서명하고 서버가 확인한다. 요청 본문의 user_id만으로 권한을 만들지 않는다. 플랫폼 필드가 실제 신뢰된 사용자 값인지, 워크플로우에서 키를 읽을 수 있는지는 현장 확인 항목이다. 팀 메타데이터 필터는 조직 인증·ACL을 대신하지 않는다.

`memory_binding.RuntimeModel`은 한 턴의 모든 모델 호출·수정·제한을 하나의 기존 native model session에 묶는다. 새로운 외부 모델 fallback은 없다. 법률 탐색은 기존 Pipeline·SourceRecall·READ·select_sources를 사용한다. 정정 상태와 7단계 체크포인트는 `corrected-memory/memory-v2.sqlite`에 저장한다. 새 v2 DB이며 연구 prototype DB를 자동 변환하지 않는다.

## 이번 통합에서 고친 연결

- 추가 근거 요청을 소비해 RECALL→READ→SELECT로 돌아가며, 거절된 선택과 재진입 사유를 보존한다. 한 턴 추가 검색은 1회로 제한하고 미해소 상태는 PENDING으로 남긴다.
- 기존 MAIN의 중복 ID 거절/모델 수정 계약을 유지한다. 멀티턴 adapter에서만 허용 후보·원래 개수 한도를 검증한 뒤 중복을 합치고 원응답과 실제 실행 선택을 따로 기록한다.
- 최종 경험에는 READ_SOURCE, ADOPTED_SOURCE, CITED_SOURCE를 분리하고 claim→원문에만 SUPPORTED_BY를 연결한다. 단순히 읽은 자료를 결론의 뒷받침 근거로 표시하지 않는다.
- 실제 조건을 바꾼 정정은 과거 경험을 RETIRED로 만들고, 표 변환/이력 조회는 확인 경험을 보존한다. 최초 이벤트 복원, 실패 후 재개, 다른 대화의 판단 노드 재결속을 유지한다.
- API 응답을 기존 채팅의 출처 표시 계약에 연결했다. 서명값은 모델·메모리 이벤트에 저장하지 않는다. 멀티턴은 최종 결과 전달이며 문단별 생성 스트리밍은 아직 연결하지 않았다. 일반 RAG SSE는 보존한다.
- 코드 전용 기본 허용목록에서 빠져 있던 SSE 실행 파일·현행 도구 세대 등은 저장소의 genosIgnore 전체 코드 선택 규칙으로 포함한다.

## 저장 경계

질문/정정/event/실행 node는 작업 원장이다. 매 질문을 온톨로지 정답으로 승인하지 않는다. 사용자 최종 확인의 현재 완성 경로만 USER_CONFIRMED_EXPERIENCE로 저장한다. 수정 전 경로는 재사용에서 제외하지만 감사 이력을 지우지 않는다. 개인 경험 확인은 공통 법률 지식 승인이 아니다. wiki 연결 정정은 원래 다른 질문 묶음의 내용을 변경하지 않는다.

## 검증과 한계

현재 작업 코드에서 계약·회귀 검사 **292개 중 290개 통과, 2개 실패**다. 두 실패는 수정 전 코드에서도 재현된다. `test_document_release`의 용어 시작점/후속 목록 검사에서 PeCab가 단독 질문의 ‘영업일’을 ‘영업/NNG + 일/VCP’로 읽어 `fixture:day`를 발견하지 못한다. ‘영업일에 관한 원문’에서는 ‘일/NNG’로 읽힌다. 색인 적재 누락이나 멀티턴 회귀로 분류하지 않으며, 기존 검색 문제로 남긴다. 통과를 위해 질문이나 단언을 바꾸지 않았다.

정확한 검사 결과와 실패 이력은 이관 폴더의 XML/로그 및 VALIDATION.json을 따른다. 모의 모델 응답을 사용한 계약 검사이며 새로운 외부 모델/CM 비교 실험은 하지 않았다. 기존 CM114턴·최종 법률 일치6/12 결과를 이번 통합 성능으로 바꾸어 쓰지 않는다. ADR0590~0613의24개 기록과 동결 코드180개 검사에서 변경이 없음을 확인했다. 전역 ADR graph의 기존6개 오류는 별도 미해결 상태로 보존한다.

아직 구현하지 않은 요구는 온톨로지 도메인 catalogue compile/승인, 모든 native 판단의 domain proof, journal v6/publication recovery, 아주 긴 대화의 계층 조회, 답변 문단 anchor, 멀티턴 문단 스트리밍이다. 원문 선별의 의미 오류와 법률 답변의 일관성도 실제 모델 검증이 남아 있다. 12개 메모리 작업 방법을 법률 도메인 온톨로지 전체 통제로 부르지 않는다.

## 활성화 조건과 롤백

AGENTS.md의 실험→MAIN 규칙은 Accepted·out-of-sample·decision_eligible=true·complete를 요구한다. 현재 연구 부모는 이를 충족하지 않는다. 현재 요청을 품질 gate 면제 승인으로 기록하지 않았다. 작업 코드 통합과 활성 릴리스 승격을 구분하며 활성 MAIN 포인터와 원문 세대는 유지한다. 활성화하려면 분리 평가 통과 또는 해당 미검증 상태를 수용하는 별도 명시 지시가 필요하다.

GENOS에서는 기존 ~/DEV에 백업 후 코드만 반영한다. 데이터·.env·.git·기존 runtime은 유지한다. Git push, 코드서빙 새 리비전, 워크플로우 편집기 교체는 별도 단계다. GENOS_MEMORY_ENABLED 기본값은0이며, 사용하는 경우 양쪽 GENOS_MEMORY_SIGNING_KEY와 고정 TEAM_ID 및 신뢰된 사용자/세션 필드를 확인한다. 이전 코드·이전 리비전과 이전 데이터 선택을 보존하고 복구한다. 새 memory-v2 DB를 지우지 않는다. 실제 현장 성공은 워크플로우 테스트 화면의 요청으로 확인한다.

전체 항목의 소비자·근거·완료/미완료는 함께 제공하는 CHECKLIST.md와 checklist.json을 따른다.
