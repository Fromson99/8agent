적용 위치와 명령
ZIP을 실제 업로드한 TRANSFER 폴더에서 다음을 실행한다.
TRANSFER의 절대 위치를 추측하거나 먼저 DEV로 이동해 압축을 풀지 않는다.
코드 적용 대상은 기존 Git checkout ~/DEV다. GENOS_DEV_ROOT가 있으면 그 명시 경로를 사용한다.
독립 RUN.txt와 ZIP 안의 RUN.txt는 완전히 같은 실행 파일이다.

python3 -m zipfile -e ./GENOS_TOOL_AVAILABILITY_20261014_R1.zip ./tool-availability-r1-package
bash ./tool-availability-r1-package/GENOS_TOOL_AVAILABILITY_20261014_R1_RUN.txt check
bash ./tool-availability-r1-package/GENOS_TOOL_AVAILABILITY_20261014_R1_RUN.txt apply
bash ./tool-availability-r1-package/GENOS_TOOL_AVAILABILITY_20261014_R1_RUN.txt verify

한 명령이 실패하면 다음 단계로 진행하지 않는다. check 실패 시 현재 코드/해시와 로그로 기준을 확인한다.
이미 이전 스키마 R1이 적용됐으면 다시 설치할 필요가 없다. 알 수 없는 변경을 강제로 덮어쓰지 않는다.

실행 시작부터 현재 TRANSFER/tool-availability-r1-logs에 지속 로그를 남긴다.
실제 Python 실행 경로/버전, checkout 경로와 commit, generation 정보를 로그에 기록한다.
apply가 출력한 BACKUP 절대경로를 저장한다. BACKUP은 설치 대상 DEV 아래의 전용 기록 폴더다.
재실행 apply는 설치본을 검증하며 새 백업을 만들거나 예산/원장을 초기화하지 않는다.
백업 receipt.json은 변경 파일과 전후 해시를, APPLIED_CODE.zip은 적용된 전체 코드 inventory를 담는다.

commit·generation gate·push·리비전 배포
1. 기존 DEV에서 git diff --check, git status --short와 변경 내용을 검토한다.
   BACKUP/receipt.json의 files 범위만 stage/commit한다. 다른 작업 변경은 섞지 않는다.
2. 검증한 commit의 DEV에서 사용할 generation의 절대경로를 확인한다. 임의 최신 폴더를 고르지 않는다.
3. 다시 실제 TRANSFER에서 아래를 실행한다. 따옴표 안 두 값은 현장 실제 값으로 교체한다.

bash ./tool-availability-r1-package/GENOS_TOOL_AVAILABILITY_20261014_R1_RUN.txt gate "apply가 출력한 실제 BACKUP 절대경로" --generation "현재 선택된 실제 generation 절대경로"

gate는 DEV의 committed code, APPLIED_CODE.zip, generation manifest 및 자산을 검증한다.
부분 패치 ZIP 자체를 전체 코드 ZIP이라고 넣지 않는다. RUN의 gate가 정확한 APPLIED_CODE.zip을 선택한다.
코드나 pin을 다시 수정하면 새 commit으로 gate를 다시 실행한다.
4. gate를 통과한 commit을 push하고 그 commit의 새 코드서빙 리비전을 배포한다.
   별도로 실행 중인 SSE 프로세스도 같은 코드로 재시작한다.
5. 실제 리비전이 같은 commit·generation 경로/manifest 해시를 선택하는지 기록한다.
   코드 적용, commit, generation gate, push, 리비전 배포, 실제 요청 성공은 별도 상태다.
