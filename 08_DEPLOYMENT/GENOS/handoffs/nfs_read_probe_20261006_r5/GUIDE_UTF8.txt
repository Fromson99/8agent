R5: 과거 GENOS 대화·현장 기록의 확정 경로로 검사

최종 사용본은 이번 R5 ZIP+RUN.txt다. 앞서 발송한 R1/R2는 보존하고 R5로 이어간다.
R3/R4는 미발송 중간본이며 최종 사용본이 아니다.

다시 확인한 과거 기록:
0. 이전 findmnt 현장 사진: /workspace, /nfs-root/diamo, /ext_vol/aiweb_upload는 모두 nfs.
   findmnt -T "$HOME/DEV"도 /workspace의 nfs를 반환했다. DEV는 로컬 ZIP 출력이 아니다.
   출처: 07_DOCS/REFERENCE/OPERATIONS/GENOS_ZIP_TO_PDF_NFS.md의 마운트 기록.
1. 2026-10-02 공유 폴더 설정 및 실제 runtime 검사 사진:
   코드 ~/DEV → /workspace, runtime /nfs-root/diamo/8-agent/runtime.
   당시 runtime의 SQLite 무결성·쓰기·롤백·별도 프로세스 잠금 검사가 통과했다.
2. 2026-10-03 완료 자료 재사용 구축의 데이터 root:
   /nfs-root/diamo/8-agent/01_DATA (STRUCTURE, TERM_RELEASES 등 구축 자료).
3. 2026-10-06 OFFLINE_READY/SHARE READY 사진과 이후 배포 설정 안내:
   /nfs-root/diamo/8-agent/term-releases/financial-risk-success-20261005-schema-r2/generation.
4. 2026-10-06 사용자 확인: GENOS_RUNTIME_DIR은 위 runtime, GENOS_STATE_DIR 미설정.
   NFS 외 영속 상태 저장소가 없다는 기록과 현재 코드스페이스 ZIP 출력은 구분한다.

기존 NFS 발행기는 generation 내부 링크를 거부하고 파일 전체를 복사/해시 검증한다.
NFS 진입점 자체가 링크라는 증거는 위 사진에 없다. 최신 오류도 거부된 경로가 없어
사진만으로 그 위치를 확정하지 않는다. R5는 이 추정을 성공 근거로 쓰지 않는다.

기존 R2는 코드스페이스 환경변수/.env를 먼저 사용하므로 과거
/home/genos/DEV/GENOS_DATA 설정이나 CURRENT를 따라갈 수 있다.
R5 RUN의 all/prepare/pack-data는 위 확정 generation/runtime을 명령행으로 넘기고
--state-unset을 명시하여 그 오래된 코드스페이스 선택을 기본으로 사용하지 않는다.
별도 state가 현재 실제로 있다면 --state <정확한-경로>로 명시한다.
경로가 실제로 변경되었다면 --generation / --runtime으로 정확한 변경 경로를 명시한다.
날짜순 최신 폴더를 선택하지 않으며 데이터/.env/CURRENT/기존 리비전 설정을 고치지 않는다.

기록에 따른 구조:
/nfs-root/diamo/8-agent/
  01_DATA/STRUCTURE/<fingerprint>/source.sqlite  문서별 구축 자료
  01_DATA/TERM_RELEASES/<run>/...               구축·재개 자료
  term-releases/financial-risk-success-20261005-schema-r2/
    generation/manifest.json, store.sqlite
    generation/navigation/...                  manifest 지정 연결 색인
    generation/fulltext/...                    manifest 지정 전문 색인
    generation/glossary/...                    bundle/dictionary/cache/receipt
    share-receipt, links, audit 등              존재하는 발행/감사 자료
  runtime/case-memory/cases-v4.sqlite          shortcut/legal_wiki 공용 SQL DB
  runtime/case-memory/SHORTCUT_CURRENT.json    존재하면 지정된 세대 DB 선택
  runtime/case-memory/artifacts/...            기본 DB의 연결 artifacts
  runtime/legal-agent/runs/.../journal.sqlite  요청·판단 이력
  runtime/runs/, feedback/...                  존재하는 운영 산출물
  rag-request-reports/                         공유 요청 LOG/JSON/TXT/XLSX/CSV
위 하위 asset 이름/경로는 실제 generation manifest가 정본이다.
SHORTCUT_CURRENT.json이 있으면 지정된 case-memory generation DB를 사용한다.
artifacts는 선택 DB와 같은 폴더의 artifacts/를 사용하므로 runtime 전체를 이관한다.
위 경로는 확인된 설정과 저장 코드의 결합이다. 현재 DB/포인터 생성 여부는 현장 검사로 확인한다.

사진의 R2는 코드 적용 INSTALLED 후 prepare에서 실패했고 커밋/push는 진행되지 않았다.
R5는 알려진 R1/R2 helper만 정확한 해시로 교체하고 진단 훅은 재사용한다.
DEV alias를 실제 checkout으로 확인하며 NFS 진입점 alias가 있더라도 논리 경로는 보존한다.
선택 NFS root 아래 개별 파일/하위 폴더 링크는 계속 거부하고 전체 경로를 출력한다.
NFS_MOUNT_ENTRY.json: 논리/실제 진입점, alias, 실제 mount/fs_type.
PATH_ENTRIES.json: 명시 선택 generation/runtime/state, 실제 경로와 링크 목록.
실패 STATUS.json: phase, 오류 유형, 거부된 전체 경로와 요청 경로.
DB 본문/질문/인증키는 위 로그에 넣지 않는다.

GENOS 코드스페이스 → NFS → commit/push → 코드서빙 → 워크플로우 읽기 검사 R5

실제 GENOS DEV에서 기존 운영 데이터를 사용한다. 외부 로컬 공개 generation 42와
GENOS 세대를 섞지 않는다. RUN.txt는 확인된 generation/runtime 및 state 미설정을 명령행으로 고정한다.
코드스페이스의 기존 환경변수/.env/CURRENT가 이 기본 선택을 덮어쓰지 않는다.
다른 현장 경로는 실행 명령의 --generation/--runtime/--state로 명시한다.
현장 실행 명령은 python3다. 코드서빙 직접 테스트 화면/API 실행은 요구하지 않는다.

첨부
  GENOS_NFS_READ_20261006_R5.zip : stdlib 진단/설치/워크플로우/데이터 ZIP 도구
  GENOS_NFS_READ_20261006_R5_RUN.txt : bash로 실행하는 완전한 단계별 스크립트
  GENOS_NFS_READ_20261006_R5_GUIDE_UTF8.txt : 이 안내
ZIP에는 JavaScript, .env, 인증키, 운영 DB/원문이 없다. 기존 운영 데이터는 GENOS에 둔다.

1. 코드스페이스 DEV에 두 첨부 배치

  ~/DEV/TRANSFER/GENOS_NFS_READ_20261006_R5.zip
  ~/DEV/TRANSFER/GENOS_NFS_READ_20261006_R5_RUN.txt

다른 기존 Git checkout이면 GENOS_DEV에 그 절대경로를 지정한다. 별도 후보 checkout을
자동 선택하지 않는다. 실행 TXT는 시작부터 자체 로그와 EXIT_STATUS.json을 남긴다.
실패 시 기존 원본 데이터/manifest/CURRENT/기존 ZIP은 유지한다.

2. 진단 코드 적용, NFS 복사/읽기, 커밋, push — 한 명령

GENOS DEV의 Git 이름/메일/기존 origin 인증과 기존 브랜치가 설정되어 있어야 한다.
관련 없는 staged 파일/추적 파일 수정이 있으면 보존하고 중단한다. 이 스크립트가
다른 작업까지 임의로 커밋하거나 .env/데이터를 Git에 추가하지 않는다.
상태 DB 검사는 쓰기가 멈춘 일관된 DB를 대상으로 한다. WAL/SHM/journal이 남으면
자동 삭제/checkpoint 없이 FAIL로 표시하므로 정상 종료한 뒤 재실행한다.

  bash ~/DEV/TRANSFER/GENOS_NFS_READ_20261006_R5_RUN.txt all

실행 단계:
  a. 첨부 ZIP/각 파일 해시 검증 → 기존 DEV 원본 백업 → 작은 진단 훅 추가.
  b. /nfs-root/diamo/8-agent/code-probes/<고유ID>/code/ 에 진단 코드를 복사.
  c. 그 NFS 코드로 실제 generation SQLite와 위키/shortcut SQL을 읽기 전용 검사.
  d. 데이터 읽기 성공 후 진단 변경과 경로 설정만 커밋.
  e. 실제 커밋 바이트를 NFS에 기록하고 코드 ZIP·코드스페이스 읽기 결과를 다시 대조.
  f. 현재 브랜치를 기존 origin으로 push하고 원격의 정확한 커밋을 확인.

기본 데이터:
  /nfs-root/diamo/8-agent/term-releases/financial-risk-success-20261005-schema-r2/generation
  /nfs-root/diamo/8-agent/runtime
별도 GENOS_STATE_DIR이면 해당 case-memory도 검사한다. 전역 문자열 치환은 하지 않는다.
경로를 고정해서 실행하려면:
  bash ~/DEV/TRANSFER/GENOS_NFS_READ_20261006_R5_RUN.txt all \
    --generation /nfs-root/diamo/8-agent/term-releases/financial-risk-success-20261005-schema-r2/generation \
    --runtime /nfs-root/diamo/8-agent/runtime

단계를 따로 실행해도 된다:
  bash ~/DEV/TRANSFER/GENOS_NFS_READ_20261006_R5_RUN.txt install
  bash ~/DEV/TRANSFER/GENOS_NFS_READ_20261006_R5_RUN.txt prepare
  bash ~/DEV/TRANSFER/GENOS_NFS_READ_20261006_R5_RUN.txt push
origin 이외의 기존 remote이면 GENOS_NFS_REMOTE에 remote 이름을 지정한다. 새 remote나
새 브랜치를 만들거나 저장소 URL/인증키를 수정하지 않는다.

prepare의 STATUS.json=PREPARED_AND_COMMITTED와 push의 STATUS.json=PUSHED를 각각 확인한다.
각 단계가 출력한 RUN_DIR의 상태/기록을 사용한다. 파일명 날짜로 최신 성공을 추정하지 않는다.
prepare 실패가 커밋 뒤에 발생할 수도 있다. STATUS와 git HEAD를 확인하고 그대로 보존한다.
재실행하면 새 검사 ID/커밋을 만들므로 새로 출력된 워크플로우 TXT와 커밋을 함께 사용한다.

3. 코드서빙에 정확한 커밋 적용

코드서빙 화면에서 push 결과의 commit을 선택하고 새 리비전을 배포한다.
진단 훅은 기존 service(config,data) 및 /json 흐름의 API_TYPE=NFS_DATA_PROBE로 호출된다.
다른 기존 RAG 요청 흐름은 보존한다. 최신 service/service.py 진입점도 루트 service로 연결된다.
진단 모듈은 실제 checkout의 정확한 파일에서 로드하며 다른 sys.path 후보를 선택하지 않는다.

prepare가 출력한 SERVING_ENV_PATHS.txt의 경로 값을 해당 코드서빙 리비전에 반영한다.
코드스페이스 env가 코드서빙에 자동 공유된다고 간주하지 않는다.
이 진단 리비전에서 불필요한 RAG 초기화/상태 쓰기를 피하도록 다음도 설정한다:
  GENOS_AUTO_WARMUP=0
  AD_WORKER_ENABLED=0
LLM/임베딩 인증 설정을 지우거나 .env를 첨부하지 않는다. 이 검사는 모델을 호출하지 않는다.
진단 후 실제 RAG 운영을 재개할 때는 기존 warmup/AD 설정을 복원한다.
생성된 00_SYSTEM/GENOS_NFS_PROBE.json은 커밋에 포함된 작은 경로/검사 ID 설정이다.
NFS DEPLOYMENT.json에는 커밋/코드 파일 해시/불변 데이터 샘플 해시를 기록한다.
코드서빙 리비전은 수동 배포 상태이므로 로컬/코드스페이스 성공만으로 배포 PASS라 하지 않는다.

4. 워크플로우 테스트 화면에서만 실행

prepare가 출력한 WORKFLOW_PASTE_ALL.txt 전체를 별도 테스트 워크플로우의 Python 단계에
붙여 넣고 진입점을 run으로 둔다. ZIP 안의 placeholder 템플릿을 그대로 붙이지 않는다.
이 파일은 그 prepare의 고유 검사 ID와 정확한 커밋을 포함한다.
워크플로우에는 기존 코드서빙 호출 설정을 사용한다:
  GENOS_BASE_URL : 기존 GENOS 내부 base URL
  GENOS_CODESERVING_ID : 위 커밋을 배포한 코드서빙의 실제 ID (모델 ID가 아님)
  GENOS_CODESERVING_TOKEN 또는 GENOS_CODE_KEY : 해당 코드서빙 인증키
실제 값을 supplied 설정에서 가져온다. 코드/메일/로그에 키 값을 붙이지 않는다.
기존 운영 워크플로우를 직접 덮어쓰려면 먼저 기존 Python을 별도로 보존한다.
테스트 화면에서 임의 문장을 입력해 실행한다. 입력 문장은 서버로 보내지 않는다.
워크플로우가 /json gateway로 진단 요청 한 번만 전달한다. 직접 코드서빙 UI/API 테스트는 없다.

PASS 기준
  nfs_probe_pass=true, 표시 첫 줄=NFS 데이터 읽기 검사 PASS.
  검사 ID와 커밋이 prepare 생성 TXT의 값과 같음.
  배포 코드 파일 SHA256 = 커밋 파일 SHA256 = NFS 복사 코드 SHA256.
  실제 serving generation/runtime/state env가 준비한 절대경로와 일치.
  generation/navigation/fulltext/glossary manifest 및 cache receipt 해시 일치.
  원문, navigation, fulltext, dictionary/bundle/cache SQL 실제 조회 성공.
  선택 shortcut/legal_wiki DB 및 존재하는 v3 정본 읽기 성공.
  runtime 디렉터리 실제 접근 성공.
운영 전 DB가 아예 없으면 NOT_CREATED로 표시한다. 이를 위키 데이터 보유 PASS라 하지 않는다.
.git 없는 컨테이너는 Git HEAD 자체를 확인할 수 없으므로 준비 커밋의 파일 바이트로 대조한다.

FAIL 예
  serving_path_environment: 코드서빙 리비전의 경로 env 미설정/다른 경로.
  committed_code / nfs_code: 다른 커밋, 파일 변조, NFS 코드 경로 미노출/권한 실패.
  FileNotFoundError / PermissionError: 실제 mount 또는 경로/운영 사용자 권한 확인.
  source_store/fulltext_sql/glossary_cache_sql: DB 접근/스키마/실제 SQL 조회 실패.
  SQLite sidecar: 쓰기가 진행 중이거나 정상 종료되지 않은 상태. 파일을 임의 삭제하지 않는다.
  HTTP 401/403/404: 워크플로우 대상 ID/인증/라우팅/배포 커밋 확인.
HTTP 200이나 health만으로 PASS하지 않는다. 실패한 항목/경로/오류 유형을 표시한다.

5. 실제 데이터 ZIP/이관을 아직 하지 않은 경우의 보조 명령

기존 GENOS NFS 데이터를 NFS 밖에 ZIP으로 보관:
기본 출력은 /tmp/genos-rag-data-export/genos-rag-data-<UTC>-<ID>.zip이다.
/tmp도 추정만으로 로컬이라고 처리하지 않는다. 실제 mount/fs_type 확인 후 NFS이면 중단한다.
GENOS_RAG_DATA_OUTPUT_DIR 또는 --output-dir로 다른 비NFS 폴더를 지정할 수 있다.
DEV=/workspace와 /ext_vol/aiweb_upload는 과거 기록상 NFS이므로 기본 출력으로 쓰지 않는다.
/tmp는 임시 저장소이므로 생성된 ZIP을 컨테이너 종료 전에 다운로드/이관한다.
출력 위치는 고정 요구가 아니다. --output-dir로 여유 공간이 있는 임의 로컬 폴더를 지정한다.
NFS/nfs4 mount 또는 /nfs-root 아래를 ZIP 출력으로 선택하면 중단한다.
선택 출력의 mount/fs_type과 완성 ZIP 절대경로를 로그에 출력한다.
ZIP.sha256은 ZIP 옆, PLAN/STATUS/RUN.log는 같은 이름의 별도 run 폴더에 남는다.
RAG/AD 쓰기를 정상 종료한 후에만 --writers-stopped를 사용한다.
  bash ~/DEV/TRANSFER/GENOS_NFS_READ_20261006_R5_RUN.txt pack-data --writers-stopped
다른 로컬 출력 폴더를 사용하려면:
  bash ~/DEV/TRANSFER/GENOS_NFS_READ_20261006_R5_RUN.txt pack-data --writers-stopped \
    --output-dir <NFS가-아닌-실제-로컬-폴더-절대경로>
생성 ZIP을 로컬 폴더에서 해제한 뒤 새 볼륨을 기존 /nfs-root/diamo 위치에 연결하고,
동봉된 RESTORE.sh --writers-stopped를 실행한다. 경로/DB 바이트/폴더 구조를 그대로 보존한다.
또는 해제 폴더를 지정해 실행:
  bash ~/DEV/TRANSFER/GENOS_NFS_READ_20261006_R5_RUN.txt restore-data \
    --bundle <DATA_MANIFEST.json이-있는-해제폴더> --writers-stopped
이 명령은 mount/unmount를 자동 수행하지 않는다. 다른 기존 파일은 덮어쓰지 않는다.
기존 /nfs-root/diamo 데이터가 이미 새 볼륨에 준비되어 있으면 바로 all을 실행하면 된다.
code-probes/<검사ID>가 만들어진 뒤 이 볼륨을 또 이관한다면 해당 검사 폴더도
pack-data --extra-path /nfs-root/diamo/8-agent/code-probes/<검사ID> 로 포함한다.

6. 검증 범위와 복귀

이 검사는 간이 NFS 읽기/작은 메타데이터/SQL 조회/코드 해시/앞뒤 샘플 검사다.
다중 GB SQLite 전체 해시·전체 release 품질·LLM 답변·runtime 쓰기/잠금 성공은 별도다.
실제 RAG를 재개할 때에는 같은 checkout/세대의 genos_generation_e2e.py와
lawrag.pipeline.term_serving_bundle.verify_assets 게이트를 실행하고 워크플로우에서
warmup/기존 대화/새 질문을 확인한다. 간이 진단을 전체 GENOS 배포 인증으로 확대하지 않는다.
문제가 있으면 이전 코드서빙 리비전과 보존한 워크플로우 Python으로 복귀한다.
설치 전 파일은 install RUN_DIR/before에 백업된다. 원본 데이터·영수증·CURRENT는 보존된다.
NFS 코드 검사 폴더/커밋 기록도 감사용으로 남긴다. 자동 삭제/데이터 재구축/해시 우회는 없다.

검증 기록: 모의 NFS/Git/로컬 remote/워크플로우 및 기존 데이터 ZIP의 40개 검사 PASS.
기존 service 회귀 검사 22개 PASS, 기존 max_input_bytes 기대 검사 1개는 이전 사용자
입력 바이트 상한 제거 정책과 불일치하며 NFS 훅을 제거한 원본에서도 같은 실패를 재현했다.
전체 기존 검사 PASS로 보고하지 않는다. 실제 GENOS 접속·현장 실행·push·배포·워크플로우
성공은 아직 확인하지 않았다. 자세한 원본/첨부 해시와 결과는 VALIDATION.json에 기록한다.
