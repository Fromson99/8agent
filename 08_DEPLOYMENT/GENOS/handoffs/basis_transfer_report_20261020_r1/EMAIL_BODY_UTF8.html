요청하신 흐름으로 준비했습니다: 후보 JSON 저장 → HTML 확인 → 적용 대상 선택 → SQLite 증분 적용.

기존 R3 배치는 SQLite에 직접 저장하는 방식입니다. 이 패키지는 실행 중인 배치를 중단하거나 기존 연결을 삭제하지 않습니다. 지금은 report로 현재 결과를 확인하고, 새 JSON 방식은 현재 배치 종료 후 stage-plan / stage-run으로 시작하세요.

1. 지금 HTML 확인 — 실제 TRANSFER에서 다른 터미널을 열어 실행:

python3 -m zipfile -e ./GENOS_BASIS_ARTIFACTS_20261020_R1.zip ./GENOS_BASIS_ARTIFACTS_20261020_R1
bash ./GENOS_BASIS_ARTIFACTS_20261020_R1/GENOS_BASIS_ARTIFACTS_20261020_R1_RUN.txt report --output ./연결검토표.html

내규 문서·조항·실제 원문 ↔ 외규 문서·조항·실제 원문, 연결 이유, 검토 상태, 원문 일치 확인을 한 행에 표시합니다. 실행 중에는 저장된 중간 결과이며 같은 명령으로 갱신합니다.

2. 다음 새 배치는 JSON에만 저장

bash ./GENOS_BASIS_ARTIFACTS_20261020_R1/GENOS_BASIS_ARTIFACTS_20261020_R1_RUN.txt stage-plan --count 3
bash ./GENOS_BASIS_ARTIFACTS_20261020_R1/GENOS_BASIS_ARTIFACTS_20261020_R1_RUN.txt stage-run
bash ./GENOS_BASIS_ARTIFACTS_20261020_R1/GENOS_BASIS_ARTIFACTS_20261020_R1_RUN.txt export

후보는 별도 CANDIDATES.json에 저장됩니다. 이 단계에서는 공유 관계 SQLite에 쓰지 않습니다. export가 출력한 폴더의 LINKS.html을 확인합니다.

3. 맞는 연결 선택 후 운영으로 이동

bash ./BASIS_RELATIONS_실제해시/APPLY_RELATIONS.txt review --all

일부만 옮기려면 --all 대신 --ids 연결ID1 연결ID2 를 사용합니다. 검토하지 않은 apply는 거부됩니다. 이관 선택은 기존 PROPOSED/APPROVED 검토 상태를 바꾸지 않습니다.

이 명령으로 *_REVIEWED.zip이 생성됩니다. 후보 데이터, 검토 기록, 선택된 SQL, 적용 코드가 모두 들어 있으므로 ZIP 하나를 운영으로 옮깁니다. 운영에서 풀고 APPLY_RELATIONS.txt check → apply → status 순서로 실행합니다. 구체적 해제·원복·재개 명령은 첨부 GUIDE에 있습니다.

같은 원문 DB·최신 선택 필터 및 R3 소비자 코드를 확인하며, 관계 행과 해당 조회 색인만 추가합니다. 기존 전체 DB를 덮어쓰거나 전체 재색인을 하지 않습니다. 동일 연결은 건너뛰고 다른 운영 검토 상태와 충돌하면 중단합니다. rollback은 이번에 새로 넣은 연결만 철회하고 이력을 보존합니다.
