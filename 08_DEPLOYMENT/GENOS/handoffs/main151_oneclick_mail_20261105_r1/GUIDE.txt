MAIN151 — 확인한 내용 설명 후 추가 질문으로 이어가는 답변

대상 환경
GENOS 코드스페이스의 기존 ~/DEV Git checkout과 GENOS 워크플로우 Python 편집기.
릴리스: guided-answer-20261105-r1 / 로컬 MAIN151 / 서빙 531파일.
현재 사용 중인 원문 데이터, Oracle/NFS 연결, 모델 주소·키, 온톨로지 연결 설정을 유지합니다.
이번 첨부는 MAIN151 전체 서빙 코드입니다. 예전 MAIN 전체 코드 ZIP을 그 위에 덮어쓰지 마세요.

변경 내용
일반 대화의 최종 조건·예외 판단 및 재검토·보완 과정을 한 번의 답변 작성으로 바꿨습니다.
확인한 기준을 먼저 설명하고, 마지막에 무엇을 모르는지와 구체적인 추가 질문을 표시합니다.
문서명과 원문 안내는 출처 카드로 제공합니다. 본문에 원문 미리보기나 검토 실패 목록을 반복하지 않습니다.
대화·조사 단계 검토와 별도 업무/시나리오 경로는 유지합니다.
추가 정보는 같은 대화의 다음 메시지에서 반영합니다. 미해결 답변은 확정 지식으로 저장하지 않습니다.
해결 후 사용자가 '기억해줘' 등 기존 확인 명령으로 확정하면 조건·답변·근거가 경험 온톨로지에 저장됩니다.
공유 도메인 온톨로지의 승인·게시를 자동으로 생략하는 기능은 아닙니다.

1. 파일 업로드
다음 두 첨부를 같은 TRANSFER 폴더에 이름을 유지한 채 업로드합니다. ZIP은 미리 풀지 않습니다.
  MAIN151_FULL_20261105_R1.zip
  MAIN151_ONECLICK_R1.txt
해당 TRANSFER 폴더의 터미널에서 한 줄 실행합니다:
  bash MAIN151_ONECLICK_R1.txt

~/DEV가 링크이면 실제 checkout을 자동으로 찾습니다.
패키지 확인 → 기존 코드 백업 → 코드 교체 → 엔진 해시 검사 순으로 실행합니다.
Python 3.11 이상이 필요하며 기존 환경을 사용합니다.
완료 표시: MAIN151_ONECLICK_DONE 및 MAIN151_EXIT=0.
자바스크립트는 메일 첨부에서 제외했습니다. 기존 app.js의 필요한 해시가 맞는지 교체 전에 검사합니다.
의존성 검사 실패 시 기존 파일을 임의 수정하지 말고 해당 오류를 확인하세요.

설치 상태를 다시 확인하려면:
  bash MAIN151_ONECLICK_R1.txt status

2. 실제 Git checkout과 코드서빙 반영
변경 파일을 검토하고 스테이징합니다:
  bash MAIN151_ONECLICK_R1.txt stage
  git -C ~/DEV diff --cached --stat
  git -C ~/DEV diff --cached --check
기존 절차로 commit한 뒤 코드 패키지와 commit 일치를 확인합니다:
  bash MAIN151_ONECLICK_R1.txt gate-code

NFS/SQLite 원문 세대를 사용하는 환경에서는 현재 GENOS_GENERATION 실제 절대경로로 전체 검사를 실행합니다:
  python3 ~/DEV/06_TOOLS/COMMANDS/genos_release_gate.py --code-zip "$PWD/MAIN151_FULL_20261105_R1.zip" --deploy-root "$(realpath ~/DEV)" --generation "$GENOS_GENERATION"
이 명령은 GENOS_GENERATION이 기존 실제 세대로 설정된 터미널에서 실행합니다.
Oracle 환경에는 NFS 세대 경로를 새로 만들어 넣지 않습니다. 기존 Oracle 설정으로 코드서빙 기동·원문 조회를 확인합니다.
기존 절차로 push하고 해당 commit의 새 코드서빙 리비전을 배포합니다.
시작 명령은 기존대로 유지합니다:
  python3 08_DEPLOYMENT/GENOS/start_sse.py
실행 TXT는 Git push나 현장 리비전 배포를 자동으로 수행하지 않습니다.

3. 워크플로우 편집기 반영
별도 첨부 MAIN151_WORKFLOW.py는 메인 코드의 워크플로우 전체 원본과 같습니다.
GENOS 워크플로우 Python 편집기에 전체 내용을 교체하거나 파일 가져오기를 사용하고 저장·배포합니다.
기존 코드서빙 연결 주소와 인증 설정을 유지합니다.
코드 ZIP만 설치하면 별도 워크플로우 편집기의 코드까지 자동 교체되지는 않습니다.

4. 현장 확인
새 코드서빙 리비전의 health 및 원문 조회를 확인합니다.
워크플로우 SSE_CHECK에서 answer_display_revision은 다음 값입니다:

실제 질문에서 확인된 설명이 먼저, 미확인 부분과 추가 질문이 마지막에 표시되는지 확인합니다.
본문에는 문서명·원문 미리보기·내부 검토 실패 목록이 반복되지 않아야 합니다.
출처 카드는 접힌 상태로 제공되며 클릭하면 원문을 확인할 수 있어야 합니다.
다음 답변은 같은 chatId/session_id의 새 메시지로 보냅니다. 새 메시지는 새 request_id를 사용합니다.
기존 GENOS_MEMORY_ENABLED=1 설정 및 사용자/대화 식별자 전달을 유지합니다.
해결 확인 후 기존 '기억해줘' 명령의 저장 결과를 확인합니다.
