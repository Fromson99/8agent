MAIN204 교체본 (설치 TXT R2)

앞서 보낸 설치 TXT R1이 git add에서 멈춘 문제를 고친 R2입니다. R1을 이미 실행했어도 R2를 그대로 실행하면 commit·push까지 이어집니다. ZIP은 같습니다.

조문 연결 목록 SQL(44.6초)과 반복 조회를 고친 전체 코드와, 첫 본문 검색 원인을 재는 현장 검사 R3입니다. 현장 적용 전이며 로컬 검증까지 완료했습니다.

  1. TRANSFER 폴더에 첨부를 올리고 bash MAIN204_ONECLICK_R2.txt (ZIP은 풀지 않음, 비밀번호 입력 없음). 코드 적용·git commit·push까지 합니다.
  2. 새 코드서빙 리비전 뒤 같은 질문을 보내고 GENOS_CPU_REPORT_R2·GENOS_ORACLE_REPORT_R4 사진
  3. bash ./GENOS_FTS_CHECK_R3.txt 화면 사진 (서빙과 같은 ORACLE_ORDS_* 환경변수 필요, 안내는 GENOS_FTS_CHECK_R3_GUIDE.txt)

예상(추정): 같은 질문 SQL 58.9초 → 약 7초, 전체 143.6초 → 약 90초. 첫 본문 검색 4.9초는 이번에 바꾸지 않았습니다.

워크플로우 파일은 MAIN203과 같아 교체하지 않아도 됩니다. 설치 TXT에 Git 비밀번호가 들어 있으니 다른 곳에 전달하지 말아 주세요.

MAIN204 — 조문 연결 목록 SQL과 반복 조회 수정 (MAIN203 대체)
MAIN203 내용을 그대로 포함한 전체 코드입니다. 이 MAIN204만 적용하면 됩니다. 워크플로우 파일은 MAIN203과 같습니다(교체 불필요).
본문 검색 현장 검사 R3(GENOS_FTS_CHECK_R3.txt, 안내 GENOS_FTS_CHECK_R3_GUIDE.txt)도 같이 보냅니다.

설치 TXT R2: 앞서 보낸 R1은 현장 저장소가 TRANSFER를 무시하고 있어 git add에서 멈췄습니다(코드 교체는 완료 상태). R2만 다시 실행하면 이어서 commit·push까지 끝납니다. ZIP은 R1과 같습니다.

0. 원인과 수정 (현장 사진 11-11 12:40, 143.6초 = 모델 74.0 + SQL 58.9 + 그 외 10.7)
  1) 조문 연결 목록 44.6초(27회, 회당 1.65초): 조문 하나의 연결을 찾으려고 참조 표 전체를 읽고 있었습니다.
     → 그 조문의 연결 ID를 인덱스로 먼저 받고, 그 ID로 참조 행을 읽습니다(인덱스 2번). 같은 라운드의 조문은 묶어서 읽습니다.
  2) 반복문 안의 SQL: 원문 블록 목록 218회 → 문서당 1번, 하위 조문 146회 → 100개씩 묶어서, 용어 92회 → 묶어서.
     블록 길이 59회·원문 후보 준비 35회는 그대로입니다.
  3) 저장 용량 확인(1.3초): 측정값을 1시간 재사용, 한도 초과로 거절하기 직전에만 다시 잽니다.
     GENOS_ORACLE_STORAGE_CHECK_SECONDS 로 바꿀 수 있습니다(0이면 매번).
  4) 첫 본문 검색 2건(4.9초): 이번에 바꾸지 않았습니다. GENOS_FTS_CHECK_R3 결과를 보고 판단합니다.
  예상(추정): SQL 58.9초 → 약 7초, 같은 질문 143.6초 → 약 90초.

1. 적용 (TRANSFER 폴더에서, ZIP은 미리 풀지 않음)
  bash MAIN204_ONECLICK_R2.txt  → 완료 표시 MAIN204_ONECLICK_DONE, MAIN204_EXIT=0 (코드 교체·검증 후 git add/commit/게이트/push까지, 비밀번호 입력 없음)
  확인: bash MAIN204_ONECLICK_R2.txt status
  환경변수 그대로. 시작 명령: python3 08_DEPLOYMENT/GENOS/start_sse.py
  이 TXT에 Git 비밀번호가 들어 있습니다. 다른 곳에 전달하지 말아 주세요.

2. 확인
  - 새 코드서빙 리비전 뒤 같은 질문을 보내고 GENOS_CPU_REPORT_R2·GENOS_ORACLE_REPORT_R4 사진을 보내 주세요.
  - bash ./GENOS_FTS_CHECK_R3.txt 화면 사진(첫 본문 검색 원인, 연결 목록 예전·지금 비교).

3. 원복: bash MAIN204_ONECLICK_R2.txt undo --backup '출력된 백업 폴더 절대경로'

4. 검증 범위 (로컬, 현장 미실행)
  - 실제 참조 데이터 15,000행(연결 끝 26,233행)을 넣은 로컬 Oracle: 예전·새 조회 180건 결과 모두 같음(문서 권한 밖 행 제외 포함), 82.8초 → 9.8초.
  - 회귀 182파일 새 실패 0, Oracle 규모 점검 통과(질문 실패 0, 한도 초과 0, 한 질문 최대 SQL 294 → 130), SQL 계획 389 그대로.
  - 설치기: MAIN203 격리 checkout에서 설치·재실행·commit·push·코드/원문 세대 게이트·원복 22개 명령 통과.
  - 안 한 것: 현장 Oracle 시간, 현장 참조 행의 키 확인(R3가 출력, 없으면 예전 방식으로 동작), 실제 모델 실행.
