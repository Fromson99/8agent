1. 구현한 동작
fulltext → A 검토 → B 확인 → 예외 C 확인 뒤 최종 근거로 B·C를 채택하면,
shortcut에는 B·C를 다시 읽을 원문 위치와 필요한 조건만 남습니다.
A의 실패한 탐색과 과거 법률 결론을 답으로 복제하지 않습니다.
현재 조건/권한/데이터 세대가 맞으면 B·C를 직접 확보해 현재 SELECT·ASSESS로
선택 및 충분성을 판단합니다. 더 필요한 자료가 있으면 기존 fulltext로 돌아갑니다.

멀티턴으로 최종 근거가 D로 바뀌면 성공한 답변 발행 뒤 현재 head를 D로 바꿉니다.
정정이 시작되면 이전 head는 현재 재사용에서 제외하며, 정정 실패·중단 중에도
되살리지 않습니다. 이전 이력은 보존하고 goal/branch별 조건을 섞지 않습니다.
SQL v4의 기존 sw_unit/sw_knowledge/sw_member/sw_dependency가 정본입니다.
legal_wiki 파일은 기존 compiler projection이며, 현재 상태·권한은 SQL에서 확인합니다.
같은 normalized task/facts/category로 찾습니다. 표현이 다른 질문의 일반화 및
GENOS 내부 모델의 법률 정확도/속도는 현장 검증 전까지 미확인입니다.

3. 반입/확인/적용
첨부 RUN.txt는 코드와 패치가 모두 포함된 독립 실행 파일입니다.
ZIP 해제는 필수가 아닙니다. ZIP을 ~/DEV에 그대로 덮어 풀지 마십시오.
모든 명령은 첫 단계부터 TRANSFER/core-evidence-shortcut-r1/logs에 기록합니다.
DEV 선택은 GENOS_DEV_ROOT → GENOS_DEV → ~/DEV 순서이며 루트 링크를 해결합니다.
현장 명령은 python3를 사용하고 실제 executable/version을 로그에 남깁니다.

예: 첨부 파일을 ~/DEV/TRANSFER/core-shortcut-r1에 저장한 경우
cd ~/DEV/TRANSFER/core-shortcut-r1
sha256sum -c SHA256SUMS.txt
bash GENOS_DB_LOG_ROLLBACK_20261007_R3_RUN.txt check
bash GENOS_DB_LOG_ROLLBACK_20261007_R3_RUN.txt apply
bash GENOS_DB_LOG_ROLLBACK_20261007_R3_RUN.txt verify
bash GENOS_CORE_EVIDENCE_SHORTCUT_20261007_R1_RUN.txt check
bash GENOS_CORE_EVIDENCE_SHORTCUT_20261007_R1_RUN.txt apply
bash GENOS_CORE_EVIDENCE_SHORTCUT_20261007_R1_RUN.txt verify

check는 설치 inventory 전체와 변경 결과, PIPELINE→engine→code/schema 연결을
쓰기 전에 검사합니다. apply는 변경 전 파일을 먼저 백업하고 receipt를 남깁니다.
성공 시 BACKUP 및 APPLIED_CODE_ZIP 경로를 출력합니다.
같은 apply를 다시 실행하면 파일 해시를 확인하고 ALREADY_APPLIED로 끝납니다.
apply가 중단되면 임의 rehash/삭제로 계속하지 말고 출력된 BACKUP으로 undo하십시오.

4. 같은 checkout의 배포 게이트
apply/verify 성공 후 변경 목록을 검토하고 실제 push할 ~/DEV에서 commit하십시오.
새 core_evidence_route.py 및 CODE_MANIFEST.json도 Git에 포함되어야 합니다.
git diff --check와 git status로 다른 변경을 확인하고 섞어서 commit하지 마십시오.

사용자가 직접 채울 값:
TASK_BACKUP = apply가 출력한 BACKUP 절대경로
GENOS_GENERATION = 기존 코드서빙이 실제 선택한 generation 디렉터리의 절대경로
아래 두 값은 예시가 아니라 반드시 현장 출력/설정에서 채워야 합니다.

export TASK_BACKUP='/현장에서_apply가_출력한_BACKUP_절대경로'
export GENOS_GENERATION='/현장_코드서빙의_실제_선택_generation_절대경로'
bash GENOS_CORE_EVIDENCE_SHORTCUT_20261007_R1_RUN.txt gate "$TASK_BACKUP" --generation "$GENOS_GENERATION"

이 명령은 APPLIED_CODE.zip과 commit된 동일 checkout의 모든 코드를 대조하고
그 checkout의 Python으로 generation E2E와 verify_assets를 실행합니다.
PASS 뒤 코드/pin을 바꾸면 commit/gate를 다시 수행해야 합니다.
통과 commit을 push하고 새 코드서빙 리비전이 같은 commit/generation을 쓰는지
확인하십시오. 코드 적용, push, 리비전 배포, 환경변수 반영은 각각 별도 상태입니다.
health의 generation ID만으로 선택 경로와 코드 일치를 판정하지 않습니다.
