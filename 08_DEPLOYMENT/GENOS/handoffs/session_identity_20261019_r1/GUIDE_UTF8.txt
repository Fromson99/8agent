GENOS_SESSION_IDENTITY_20261019_R1 — 팀·세션 기반 대사/멀티턴 수정

1. 변경 내용
사진의 403 WORKFLOW_IDENTITY_REQUIRED를 발생시키던 WORKFLOW_USER_ID 필수 조건을 제거했습니다.
대화는 team_id + session_id로, 요청 중복은 request_id로 구분합니다. 로그인 user_id는 입력하지 않아도 됩니다.
기존 DB의 owner/user_id 열에는 팀·세션으로 계산한 내부 저장 키를 사용합니다. 사용자 계정을 요구하거나 공유 anonymous 계정으로 합치지 않습니다.
다른 팀·세션 분리, 원문/문서 범위, 코드·데이터 해시, 재개 revision, 예산·기한 검사는 유지합니다.
세션 ID 원문을 보존하므로 특수문자 제거/64자 절단에 의한 충돌을 방지합니다.
대사 run/status/resume, 일반 멀티턴, 기존 직접 채팅 어댑터와 워크플로우 편집기를 함께 수정했습니다.

이번 ZIP은 기존 MAIN87 누적 코드에 이 수정을 결합한 전체 코드 인계본입니다.
이전 GENOS_MAIN87_PATCH_20261019_R1 코드 적용본 대신 이번 GENOS_SESSION_IDENTITY_20261019_R1을 사용합니다.
원문·NFS generation·Oracle DP 설정·검색 선택표·.env·Git 이력은 보존합니다. 로컬 MAIN87 포인터는 변경하지 않았습니다.

2. 실제 첨부를 업로드한 TRANSFER 폴더에서 실행
TRANSFER의 절대 위치는 추정하지 않습니다. 압축 해제를 위해 먼저 DEV로 이동하지 마세요.

python3 -m zipfile -e ./GENOS_SESSION_IDENTITY_20261019_R1.zip ./GENOS_SESSION_IDENTITY_20261019_R1
bash ./GENOS_SESSION_IDENTITY_20261019_R1/GENOS_SESSION_IDENTITY_20261019_R1_RUN.txt check
bash ./GENOS_SESSION_IDENTITY_20261019_R1/GENOS_SESSION_IDENTITY_20261019_R1_RUN.txt apply
bash ./GENOS_SESSION_IDENTITY_20261019_R1/GENOS_SESSION_IDENTITY_20261019_R1_RUN.txt status

적용 대상은 기존 Git checkout ~/DEV입니다. 다를 때만 각 명령 끝에 --root /실제/DEV를 붙입니다.
기존 GENOS_SERVING_PATHS.json의 generation/runtime 선택을 유지합니다.
현장 Python은 python3입니다. /venv/bin/python3가 있으면 사용하며, 필요 시 GENOS_PYTHON_DIR=/실제/파이썬/bin을 지정합니다.
첫 단계부터 TRANSFER/session-identity-r1-logs에 stdout/stderr와 종료 상태를 저장합니다.
상태·백업 위치는 TRANSFER/session-identity-r1-state/STATUS.json에 기록합니다.
중단된 적용은 같은 apply로 재개합니다. 백업/코드가 달라졌으면 강제로 덮어쓰지 않고 실패 기록을 남깁니다.

3. 기존 DEV에서 변경 검토·commit 후 코드 gate
다음은 기본 적용 대상 ~/DEV 기준입니다. 사용자 설정으로 --root를 썼다면 그 checkout을 사용합니다.

cd ~/DEV
git diff --check
git diff --stat
python3 - <<'PY'
import json, subprocess
from pathlib import Path
root=Path.cwd()
manifest=json.loads((root/'CODE_MANIFEST.json').read_text())
paths=[r['path'] for r in manifest['files']]+['CODE_MANIFEST.json']
subprocess.run(['git','add','--',*paths],check=True)
PY
git diff --cached --stat
git commit -m "Fix GENOS conversation identity to team and session"

실제 업로드한 TRANSFER 폴더로 돌아와 아래를 실행합니다.
bash ./GENOS_SESSION_IDENTITY_20261019_R1/GENOS_SESSION_IDENTITY_20261019_R1_RUN.txt gate-code

gate-code는 같은 committed checkout의 ZIP·코드·pin 일치를 검사합니다.
전체 generation 검사는 아래 별도 명령입니다. NFS I/O가 큰 검사이므로 여유가 있을 때 한 개씩 실행합니다.
bash ./GENOS_SESSION_IDENTITY_20261019_R1/GENOS_SESSION_IDENTITY_20261019_R1_RUN.txt gate

코드 gate만으로 전체 데이터 검증 완료를 뜻하지 않습니다. 기존 최신 문서 선택표가 준비되지 않으면 전체 gate는 중단하며 임의로 재생성하지 않습니다.
DP=oracle 선택 시 NFS generation gate는 Oracle 실제 접속/선택 릴리스의 현장 검증을 대신하지 않습니다.
gate 후 코드를 바꿨다면 새 commit으로 다시 검사합니다. 기존 DEV에서 검증한 commit을 git push하고 같은 commit으로 코드서빙 새 리비전을 배포합니다.
기존 generation/runtime·Oracle·내부 모델 설정을 유지하고 SSE 프로세스를 재시작합니다.

4. 워크플로우 편집기와 테스트
GENOS_SESSION_IDENTITY_20261019_R1_WORKFLOW_PASTE_ALL.txt 전체를 기존 워크플로우 Python 단계에 붙여 넣고 저장합니다.
기존 URL·인증 설정과 TEAM_ID=risk_team 또는 요청의 team_id를 유지합니다.
WORKFLOW_USER_ID는 설정하지 않아도 됩니다. 이미 남아 있어도 이번 코드의 대사 식별에는 사용하지 않습니다.
같은 대화에서는 GENOS가 제공한 chatId/chat_id/sessionId/session_id 중 기존 세션 값을 계속 전달합니다.
세션이 없거나 anonymous면 새 임의 세션을 자동 생성하지 않고 오류로 안내합니다.
오래된 코드로 시작한 요청이 진행 중이면 먼저 종료 상태를 확인하고 이번 버전에서는 새 채팅으로 테스트합니다.

질의·warmup은 워크플로우 테스트 화면에서만 실행합니다.
첫 질문:
대사: 위험관리위원회운영준칙의 위원회 역할과 심의·의결사항을 관련 외규와 비교하고, 공통사항·차이·확인하지 못한 자료를 알려줘.
일반 RAG 같은 세션 후속 질문: 앞에서 확인한 승인 대상에 A라는 조건을 추가해서 설명해 줘.
대사의 실행 재개는 WORKFLOW_STATUS / WORKFLOW_RESUME과 원래 run_id·session_id·team_id·현재 revision을 사용합니다.
이번 수정은 기존 대사 요청 사이의 자연어 후속 참조 기능을 새로 만드는 변경이 아닙니다.
확인 항목: 403 WORKFLOW_IDENTITY_REQUIRED 제거, 같은 팀·세션의 대화 유지, 중복 요청 재사용, 다른 세션 분리, 원문·인용·미확보 표시.

5. 이전 기록과 원복
이전 사용자 기준 대화 DB와 immutable 저널은 수정·삭제하지 않습니다.
이전 멀티턴 대화를 같은 세션으로 새로 시작하려 하면 SESSION_LEGACY_BINDING으로 명시하고 이력/예산을 자동 초기화하지 않습니다.
정확한 과거 run_id의 대사 조회·재개는 팀/세션과 저장 해시를 확인하며 코드·데이터 결속이 달라졌으면 기존 WORKFLOW_BINDING_CHANGED 검사를 유지합니다.
다른 코드 리비전의 실행을 이어 붙이지 마세요. 이전 실행은 원래 리비전으로 복귀하여 재개하거나 별도 이행 검증이 필요합니다.
