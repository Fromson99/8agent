GENOS 분리 워크플로우 진행 표시 복구 — 편집기 Python 단계 전용

원인: R3의 별도 Python 워크플로우는 코드서빙 /stream SSE를 읽지만 화면
진행 송신을 끄고 최종 JSON만 반환합니다. GENOS_MAIN_MODE=workflow는
코드서빙의 앱만 바꾸므로 화면 진행을 복구하지 않습니다.

적용 위치: GENOS의 기존 채팅 워크플로우 편집기 Python 단계.
WORKFLOW_PASTE_ALL.txt 전체를 붙이고 진입점 run(data)를 유지하세요.
코드 ZIP, service/service.py, main_router.py, 선택 NFS generation은 바꾸지
않습니다. 이미 적용한 R3 ZIP을 되돌리거나 R2 ZIP을 다시 적용하지 마세요.

코드서빙 701이 분리 백엔드라면 다음 상태를 유지합니다.
  Run: python3 main_router.py
  GENOS_MAIN_MODE=workflow
  코드서빙의 socket.io 실시간 스트리밍 사용: 체크 해제
  워크플로우 Python 단계의 GENOS_CODESERVING_ID: 701
  워크플로우 Python 단계의 GENOS_BASE_URL/GENOS_CODESERVING_TOKEN: 기존 값 유지
  채팅 대상: 코드서빙 /chat 직접 연결이 아니라 이 Python 워크플로우

워크플로우 Python 단계의 GENOS_RAG_PROGRESS_UI 선택:
  socketio-inline  처리 중 채팅 문구와 Visible Reasoner 진행 카드를 보냅니다.
                   기존과 같은 실시간 표시입니다. 플랫폼 main_socketio와
                   입력 socketIOClientId가 필요합니다.
  final-cards      Socket.IO 없이 최종 결과의 agentFlowExecutedData에 진행
                   카드를 포함합니다. 완료 전 실시간 표시는 불가능합니다.
                   변수를 설정하지 않았을 때 이 모드가 기본입니다.
  off              진행 카드를 만들지 않고 최종 답변만 반환합니다.

중요: socketio-inline은 "Socket.IO 없음"이라는 이전 선택을 워크플로우
Python 단계에 한해서 변경합니다. 코드서빙 701의 Socket.IO 체크박스를
켜는 뜻이 아닙니다. GENOS Python 워크플로우의 main_socketio 송신과
코드서빙이 자체 Socket.IO 서버를 띄우는 기능은 서로 다릅니다.

현장 검증은 워크플로우 테스트 화면에서 수행합니다.
  1. {"API_TYPE":"WORKFLOW_SETTINGS"} → progress_mode, socketio_enabled 확인.
  2. {"API_TYPE":"SSE_CHECK"} → sse_ready=true, route=/stream 확인.
  3. 짧은 공개 테스트 질문 → 처리 중 첫 진행 문구/카드가 최종 답변보다
     먼저 보이는지 확인. 결과의 code_serving_transport.progress_events가
     1 이상인지 확인합니다.
  4. socketio-inline에서 진행이 안 보이면 입력 socketIOClientId 존재 여부,
     워크플로우 로그의 workflow.progress.socket_failed, 채팅 대상이 이
     워크플로우인지 확인합니다. 코드서빙 컨테이너 로그만으로 화면 전송을
     판단하지 않습니다.

이 파일은 로컬에서 모의 Socket.IO/분리 백엔드 계약 테스트를 통과한
워크플로우 편집기 코드입니다. GENOS 현장 화면 성공은 아직 확인되지
않았습니다. 이전 Python 단계 내용을 먼저 별도로 저장하면 즉시 되돌릴 수
있습니다. 결과 확인 전에는 기존 채팅 연결의 대상을 바꾸지 마세요.
