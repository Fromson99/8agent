GENOS 워크플로우 연결만 롤백 — 20261002 R1

범위: main.py /chat로 이관한 플랫폼 연결을 기존 Python run(data) 방식으로 복귀.
RAG v6 코드·NFS runtime·원문/용어집/색인·CURRENT·기억 DB는 유지합니다.
기존 R2 전체 rollback 명령은 실행하지 마세요. v6까지 되돌리는 요청이 아닙니다.
이번 코드는 R2에 보존된 LEGACY_WORKFLOW_FOR_ROLLBACK.txt와 바이트가 같습니다.

1. 현재 /chat 워크플로우 연결 리비전·채팅 앱 연결을 기록하고 보존합니다.
2. 이전 Python 단계 워크플로우를 새 리비전으로 열거나 복제합니다.
   첨부 GENOS_WORKFLOW_ONLY_ROLLBACK_20261002_R1_PASTE_ALL.txt 전체를
   Python 편집기에 붙여 넣습니다. 진입 함수 run, 입력 data는 채팅 앱 입력 전체입니다.
   이 TXT는 실행용 Python 전체 소스입니다. bash로 실행하는 파일이 아닙니다.
3. 워크플로우 환경에 기존 값으로 아래 연결 설정을 복원합니다.
   GENOS_BASE_URL=<기존 GENOS 게이트웨이 주소>
   GENOS_CODESERVING_ID=<v6가 배포된 현재 코드서빙 ID, LLM ID가 아님>
   GENOS_CODESERVING_TOKEN=<현장 코드서빙 인증키, 메일/코드/로그에 쓰지 않음>
   GENOS_CODESERVING_TIMEOUT_SECONDS=2100
   GENOS_RAG_PROGRESS_UI=socketio
   TEAM_ID=<대상 실제 팀: risk_team 또는 financial_team>
   코드서빙으로 /chat을 호출하는 노드 대신 이 Python run 단계를 선택합니다.
4. 저장·배포하고 채팅 앱이 이 Python 워크플로우 리비전을 선택하게 연결합니다.
   DEV 파일 변경이나 Git push만으로 편집기/앱 연결은 바뀌지 않습니다.

코드서빙 유지:
 현재 R2의 main.py 서버는 /json·/stream도 제공하므로 정상 배포돼 있으면
 시작 명령과 코드서빙 리비전을 바꿀 필요가 없습니다. /chat은 남아 있어도 됩니다.
 GENOS_RAG_IMPLEMENTATION=legal-agent-unified-v6
 GENOS_RUNTIME_DIR=/nfs-root/diamo/8-agent/runtime
 GENOS_MEMORY_JOURNAL_MODE=DELETE
 SEMANTIC_LLM_BACKEND=genos
 기존 정확한 GENOS_GENERATION 또는 GENOS_DATA_ROOT, 내부 모델 설정을 유지합니다.
 /stream이 없다는 404/405만 /json으로 한 번 대체하고, 중간 실패는 재질의하지 않습니다.
 SSE_CHECK가 실패하면 실제 오류와 코드서빙 리비전을 확인합니다.

현장 검증 — 워크플로우 테스트 화면만 사용:
 A. {"API_TYPE":"WORKFLOW_SETTINGS"}
    workflow_revision=rag-v6-progress-20261002-r1
    progress_display_revision=reasoner-display-v6-20261002-r1
    json/stream timeout=2100, transport_mode=sse 확인.
 B. {"API_TYPE":"SSE_CHECK"} → sse_ready=true 확인.
 C. {"API_TYPE":"WARMUP"}, 이어서 {"API_TYPE":"WARMUP_STATUS"}
    실제 준비 상태를 확인합니다. warmup 성공만으로 답변 검증 완료가 아닙니다.
 D. 실제 질문 → answer_status=answered, text, run_id 확인.
    같은 run_id의 GENOS 내부 요청 로그에서 실제 구현이 legal-agent-unified-v6인지 확인.
    이 경로는 기존 text dict 반환이며 /chat의 code/data 출력 검증 TXT와 형식이 다릅니다.
    이전 R2 VERIFY의 answer/confirmed 모드를 이 출력에 그대로 실행하지 마세요.

v6 멀티턴·확정 경험까지 확인할 때:
 워크플로우의 GENOS_MEMORY_ENABLED=1과 GENOS_MEMORY_SIGNING_KEY를 설정합니다.
 코드서빙에도 같은 GENOS_MEMORY_SIGNING_KEY와 GENOS_MEMORY_ENABLED=1을 설정합니다.
 서명 키는 현장 32자 이상 값을 사용하고 TEAM_ID를 고정합니다.
 플랫폼에서 전달한 실제 userId/userInfo·chatId가 있어야 합니다.
 워크플로우 테스트가 신원을 전달하지 않으면 실제 채팅에서 확인해야 합니다.
 같은 대화 질문→정정→복원→최종 확인→새 대화 재사용을 확인합니다.
 일반 질문만 먼저 확인하면 워크플로우 memory를 0으로 두어 개인 기억 없이 실행할 수 있습니다.
 기존 /chat과 Python 브릿지의 신원 정규화 방식이 다를 수 있어 이전 기억이 즉시 보인다고
 보장하지 않습니다. DB를 삭제·변환하지 말고 같은 플랫폼 신원/내부 run 기록으로 확인합니다.
