MAIN156 — 운영 Gold R5 조회 연결 수정 / 전체 코드 교체

릴리스: operating-gold-20261105-r1
기준: 실제 활성 MAIN155. MAIN155의 멀티턴·문서명 표시·탐색 안내를 유지합니다.
이번 MAIN156 ZIP/TXT 한 쌍을 사용하세요. 이전 MAIN142/151/152 코드 첨부를 나중에 다시 덮어쓰지 않습니다.
서빙 532파일 중 제품/매핑 3파일과 엔진 pin 31파일만 변경했습니다. 실행 SQL 계획 642개는 같습니다.

수정한 운영 차이
1. DOC_BLK.ADDN_IFMN_UN_APPN_YN: CHAR(1 BYTE) → VARCHAR2(1 BYTE)
2. SRCH_ROW.RFRN_DATA_HASH_VALU → RFRN_DTA_HASH_VALU
3. SRCH_ROW.RFRN_DATA_CTNT → RFRN_DTA_CTNT
4. VCTR_ITEM.BODY_UNIT_ID: VARCHAR2(50 BYTE) → VARCHAR2(100 BYTE)
5. SRC_POST.RGSN_ASTM: 기존 TIMESTAMP(6) WITH TIME ZONE NOT NULL과 운영 R4/R5 적재기가 지원하는 일반 TIMESTAMP(0~9), nullable Y/N을 조회 계약에서 수용합니다. 다른 컬럼과 Agent 시각 검사는 유지합니다. 적재 기본값 생성은 Dataiku 책임이며 이 코드는 DB를 변경하지 않습니다.

필수 설정 — 코드스페이스 터미널과 실제 코드서빙 환경은 별도입니다.
  DP=oracle
  GENOS_ORACLE_TABLE_MAPPING=gold
  GENOS_ORACLE_GOLD_OWNER=운영의 IDD_B003_LGL_* 13테이블이 존재하는 실제 Oracle owner
마지막 값에는 실제 대문자 owner를 넣습니다. Dataiku 연결명이나 ORDS 별칭을 대신 넣지 않습니다.
기존 ORDS 주소/인증, DP_QUERY_CHANNEL 또는 명시된 게시 ID, 임베딩·모델 설정은 유지합니다.
GENOS_ORACLE_TABLE_MAPPING을 생략하면 기존 mapped 경로이며 Gold를 자동 탐색하지 않습니다.

Gold 모드의 Agent 기록 4표는 기존 SIDDA.LGL_AGT_BODY_A_1 / LGL_AGT_REC_A_1 / LGL_AGT_RUN_A_1 / LGL_EXEC_ST_A_1입니다.
이번 변경은 suffix 없는 *_A 테이블로 전환하지 않습니다. *_A만 만든 상태는 Gold Agent 준비와 다릅니다.
기존 전달된 agent_gold_layer_20261105_r1 SQL 및 GENOS 접속 계정의 읽기/쓰기 권한이 필요합니다.
테이블 미존재·미노출·필수 컬럼 차이는 계속 사전검사에서 중단합니다. 다른 테이블로 fallback하지 않습니다.
사진의 suffix 없는 SIDDA.LGL_AGT_BODY_A 오류만으로 타입 오류라고 판단할 수 없습니다.

1. 전체 코드 설치
아래 ZIP/TXT를 같은 TRANSFER 폴더에 올립니다. ZIP은 미리 풀지 않습니다.
  MAIN156_FULL_20261105_R1.zip
  MAIN156_ONECLICK_R1.txt
그 폴더에서 실행:
  bash MAIN156_ONECLICK_R1.txt
기존 ~/DEV 링크의 실제 Git checkout을 찾아 검사·백업·코드 교체·엔진 검증합니다.
Python3.11 이상을 사용합니다. 원문/실제 .env/키/가상환경/Git 이력은 보존합니다.
JavaScript 첨부는 제외하고 기존 app.js 해시를 교체 전에 확인합니다.
완료 표시: MAIN156_ONECLICK_DONE / MAIN156_EXIT=0.

2. 코드 확인과 현장 배포
  bash MAIN156_ONECLICK_R1.txt status
  bash MAIN156_ONECLICK_R1.txt stage
  git -C ~/DEV diff --cached --stat
  git -C ~/DEV diff --cached --check
기존 절차로 commit한 뒤:
  bash MAIN156_ONECLICK_R1.txt gate-code
검증한 commit을 기존 절차로 push하고 그 commit의 새 코드서빙 리비전을 배포합니다.
시작 명령은 기존 python3 08_DEPLOYMENT/GENOS/start_sse.py를 유지합니다.
TXT는 push·플랫폼 배포·환경변수 저장을 자동 수행하지 않습니다.
실제 코드서빙 리비전에도 위 Gold 설정이 적용되어야 합니다.

별도 워크플로우 편집기가 구버전이면 MAIN156_WORKFLOW.py 전체를 교체·저장·배포합니다.
이미 최신 MAIN155 워크플로우이면 바이트가 같습니다. 기존 코드서빙 주소·인증은 유지합니다.
기존 워크플로우에서 질문·원문 출처 열기를 실행해 선택 commit, 요청 ID, 응답과 서버 로그를 확인합니다.
health·설치 성공만으로 실제 Gold 조회 성공이라고 판단하지 않습니다.

NFS 원문 세대도 사용하는 환경에서만 기존 실제 GENOS_GENERATION으로 다음을 실행합니다.
  python3 ~/DEV/06_TOOLS/COMMANDS/genos_release_gate.py --code-zip "$PWD/MAIN156_FULL_20261105_R1.zip" --deploy-root "$(realpath ~/DEV)" --generation "$GENOS_GENERATION"
Oracle 전용 환경에 임의 NFS 경로를 넣지 않습니다.
