GENOS MAIN82 코드 반입 R1 — 최신 워크플로우 유지·최소 모델 출력
2026-10-18 / basis-link-lifecycle-20261016-r1 / 대사 workflow 1.9.0 + 내규 근거 발굴 workflow 1.0.0

MAIN82에 이미 통합·선택된 최신 워크플로우와 최소 모델 출력 계약을 함께 전달합니다.
선택 MAIN82의 서빙 파일 370개는 수정 없이 그대로 포함합니다. 이전 MAIN81 R2 및 Oracle DP 코드 적용 후에도 사용할 수 있습니다.
모델은 필요한 판단·이유·선택을 반환하고, 시스템은 계약으로 확정 가능한 고정값·빈 구조를 조립하여 기존 JSON 소비자에 전달합니다.
최종 답변의 근거·인용·미확인 사항, 권한·원문·상태 검사는 유지합니다. 사진의 timeout이 해소됐다는 현장 확인은 아직 없습니다.
최근 대사 원문 전달/비교표, 근거 후보 검토·승인·철회와 다음 요청 반영, GENOS 워크플로우 편집기 수정도 포함합니다.
Oracle DP 연결 코드와 기존 설정은 유지합니다. DP를 새로 켜거나 Oracle 테이블/원문을 이관하는 패키지는 아닙니다.
기존 ~/DEV에 전체 코드 목록을 백업 후 적용합니다.
참조는 현장 데이터의 기존 연결을 먼저 사용합니다. 현장 내규/참조가 없다고 가정하지 않습니다.
이전 GENOS 출력 상한 제거·추가 사실 안내 수정은 유지했습니다.
이미 실행 중인 대사 요청은 끝내고 새 버전에서 새 요청 ID로 시작합니다.

1. 파일을 업로드한 실제 TRANSFER 폴더에서 실행
TRANSFER의 절대 경로는 가정하지 않습니다. 먼저 DEV로 이동하지 마세요.

python3 -m zipfile -e ./GENOS_MAIN82_MINIMAL_20261018_R1.zip ./GENOS_MAIN82_MINIMAL_20261018_R1
bash ./GENOS_MAIN82_MINIMAL_20261018_R1/GENOS_MAIN82_MINIMAL_20261018_R1_RUN.txt check
bash ./GENOS_MAIN82_MINIMAL_20261018_R1/GENOS_MAIN82_MINIMAL_20261018_R1_RUN.txt apply
bash ./GENOS_MAIN82_MINIMAL_20261018_R1/GENOS_MAIN82_MINIMAL_20261018_R1_RUN.txt status

기본 적용 대상은 기존 ~/DEV입니다. 다를 때만 위 명령 뒤에 --root /실제/DEV를 지정합니다.
python3 3.11 이상과 기존 GENOS 의존성을 사용하며 실제 실행 파일·버전을 로그에 남깁니다.
/venv/bin/python3가 있으면 사용합니다. 필요 시 GENOS_PYTHON_DIR=/사용할/파이썬/bin을 설정합니다.
ZIP 안 RUN.txt와 별도 첨부 RUN.txt는 같은 완전한 실행 파일입니다.

check/apply/status는 코드 및 작은 GENOS_SERVING_PATHS/manifest를 확인합니다.
NFS 원문 DB·색인·기존 검색 선택표를 읽거나 수정하지 않고 데이터 재구축도 하지 않습니다.
.env, .venv, Git 이력, 기존 GENOS_SERVING_PATHS, 코드 목록 밖 파일을 보존합니다.
코드 목록 안 파일은 검증한 MAIN82 인계본으로 교체하며 원본은 ~/DEV/09_ARTIFACTS/BACKUPS/code-replacement에 백업합니다.
MAIN82_CODE_APPLIED와 종료코드0은 코드 적용 완료이며 현장 대사 성공을 의미하지는 않습니다.
로그: 현재 TRANSFER/main82-minimal-r1-logs/*.log 및 *.log.exit
상태: 현재 TRANSFER/main82-minimal-r1-state/STATUS.json
실패: 같은 state/LAST_FAILURE.json 및 백업 receipt.json
적용 도중 중단됐으면 같은 TRANSFER에서 같은 RUN의 apply로 복구·재개합니다.
중복 적용은 설치한 코드와 receipt가 같으면 재사용합니다.

2. 기존 DEV에서 적용 파일 검토·commit
아래 코드 목록만 add하며 .env, 실행 로그, 백업, unrelated 작업은 포함하지 않습니다.
이 단계의 작업 위치만 기존 DEV입니다. TRANSFER 원래 위치는 따로 기억해 두세요.

cd ~/DEV
git diff --check
git diff --stat
python3 - <<'PY'
import json,subprocess
from pathlib import Path
m=json.loads(Path('CODE_MANIFEST.json').read_text())
names=[r['path'] for r in m['files']]+['CODE_MANIFEST.json']
for i in range(0,len(names),100):
    subprocess.run(['git','add','-f','--',*names[i:i+100]],check=True)
PY
git diff --cached --stat
git commit -m "Apply GENOS MAIN82 workflows and minimal model output"

관련 없는 staged 변경이 있으면 함께 commit하지 말고 먼저 분리합니다.

3. 원래 TRANSFER로 돌아가 검증한 checkout과 코드 ZIP 결속 확인

bash ./GENOS_MAIN82_MINIMAL_20261018_R1/GENOS_MAIN82_MINIMAL_20261018_R1_RUN.txt gate-code

gate-code는 코드만 검사합니다. 데이터·서비스 검증 완료로 표시하지 않습니다.
아래 gate는 같은 committed DEV에서 선택 generation의 DB/색인/해시까지 읽는 전체 검사입니다.
현장에서 대규모 NFS I/O를 제한하고 있다면 실행을 미루고 CODE_GATE_PASSED_GENERATION_UNVERIFIED 상태를 남깁니다.
데이터 읽기를 허용한 시점에 실행하고, 통과한 commit과 generation을 새 리비전에 사용합니다.
기존 최신 문서 선택표 또는 원본의 최신 표시가 있어야 MAIN82가 서빙됩니다. 이번 코드 적용은 이 데이터를 새로 만들지 않습니다.
gate에서 'latest document selection required'가 나오면 기존 데이터의 표시가 준비되지 않은 상태입니다.
데이터 읽기가 허용된 시점에 기존 search-selection 경로로 보강한 뒤 gate를 다시 실행합니다.
이를 참조 문서 부재나 대사 의미 판단 실패로 해석하지 않습니다.

bash ./GENOS_MAIN82_MINIMAL_20261018_R1/GENOS_MAIN82_MINIMAL_20261018_R1_RUN.txt gate

gate 통과 후에는 코드/pin을 다시 바꾸지 않습니다. 바뀌면 새 commit으로 다시 검사합니다.
기존 DEV에서 해당 commit을 git push하고 같은 commit으로 코드서빙 새 리비전을 배포합니다.
GENOS_SERVING_PATHS의 generation/runtime, DP/Oracle 연결 설정, 내부 LLM·임베딩 설정을 유지하고 SSE를 새 코드로 재시작합니다.
DP=oracle 사용 시 전체 generation gate는 기존 NFS generation 검사이며 Oracle 연결/선택 릴리스 성공을 증명하지 않습니다.
실제 Oracle provider/release/cache 선택은 워크플로우 테스트에서 확인하고, Oracle 모드 오류를 NFS로 바꾸어 우회하지 않습니다.
STATUS.json의 commit/generation/manifest 해시와 실제 코드서빙 리비전/선택 경로를 함께 기록합니다.
새 리비전·실제 generation·내부 모델 결과는 로컬 검사만으로 확인되지 않습니다.

4. 별도 워크플로우 편집기 반영·현장 확인
GENOS_MAIN82_MINIMAL_20261018_R1_WORKFLOW_PASTE_ALL.txt 전체를 기존 워크플로우 Python 단계에 붙여 넣고 저장합니다.
코드 ZIP 적용/Git push와 별도 단계입니다. 기존 호출 URL/인증 설정은 현장 설정을 사용합니다.
질의와 warmup은 워크플로우 테스트 화면에서만 수행합니다. 코드서빙 직접 테스트 UI/API는 요구하지 않습니다.

예시 질의:
대사: 위험관리위원회운영준칙의 위원회 역할과 심의·의결사항을 관련 외규와 비교하고, 공통사항·차이·확인하지 못한 자료를 알려줘.

질문한 내규 원문이 들어왔는지, 기존 참조를 활용하는지, 근거·비교 의견·미확보가 함께 표시되는지 확인합니다.
참조 문서명은 현장 등록 제목에 맞게 지정할 수 있습니다. 원문 미확보가 있어도 의견과 한계를 반환하는 것이 정상입니다.
request/run ID, 선택 commit/리비전, generation 경로·manifest 해시와 결과를 보존합니다.

5. 원복
같은 TRANSFER에서:
bash ./GENOS_MAIN82_MINIMAL_20261018_R1/GENOS_MAIN82_MINIMAL_20261018_R1_RUN.txt undo

정확한 백업으로 코드만 복원합니다. 데이터와 검색 선택표는 바꾸지 않습니다.
적용 후 사용자가 수정한 코드가 있으면 덮어쓰지 않고 보존하며 그 파일을 알립니다.
이전 코드 commit/코드서빙 리비전·워크플로우 편집기본으로 복귀하고 기존 generation을 유지합니다.
새 버전 진행 중 저널을 구버전으로 강제 재개하지 않고, 버전별 조회 기록을 보존합니다.

검증 범위와 근거
MAIN82는 ADR-0853에서 ADR-0852의 최신 워크플로우/편집기 수정과 ADR-0850의 압축을 통합한 선택본입니다.
이번 전달 파일을 기존 코드에 설치한 뒤 압축·워크플로우·원문 경계·AD·Oracle 연결 계약, 서비스 진입점, 재개·원복을 별도로 검사합니다.
정확한 실행 결과는 ZIP의 VALIDATION.json 및 별도 FINAL_VERIFICATION.json에 기록합니다.
SOURCE_BINDING.json은 파일별 정본과 MAIN 연결을 기록하며, 설치 후 DEV/CODE_MANIFEST.json은 실제 현장 설정과 결속됩니다.
로컬 서비스는 MAIN82를 계속 선택하며 새 승격이나 데이터 포인터 변경을 하지 않았습니다.
GENOS 현장 반입·push·리비전·워크플로우 저장·내부 모델 질의는 수행 전까지 미확인입니다.
