GENOS 팀별 legal_agent / ad_mode 로그 및 공통 모델 계약 R1 — 2026-10-13

적용 대상
앞서 발송한 GENOS_MODEL_STREAM_FIX_20261013_R1이 적용된 기존 ~/DEV입니다.
이번 GENOS_AD_REQUEST_LOGS_20261013_R1.zip과 동일한 이름의 RUN.txt를 그 위에 적용합니다.
종료 처리 수정 R1을 대체하거나 취소하지 않습니다. 알려진 현장 코드 inventory330종의
해시가 일치할 때만 백업 후 수정하고, 다른 수정이 있으면 변경 전에 중단합니다.
현장 httpx 전송·모델 선택·원문 generation·DB 스키마·캐시를 유지합니다.

변경 내용
1) GENOS_SHARED_LOG_DIR 아래 기존 날짜/팀 구분에 실행 구분을 추가합니다.
   <로그 root>/<한국 날짜>/<팀>/legal_agent/
   <로그 root>/<한국 날짜>/<팀>/ad_mode/
   예: /nfs-root/diamo/8-agent/rag-request-reports/2026-10-13/financial_team/ad_mode/
   각 폴더에 요청별 .json / .log / .txt와 질문답변.csv / 질문답변.xlsx가 생성됩니다.
   과거 팀 폴더의 로그는 이동하거나 덮어쓰지 않습니다. 요약 재구축은 신구 형식을 읽습니다.
2) AD에서 처리한 요청만 AD 보고서로 만듭니다. 일반 질문에 대한 AD 사전 확인은 별도
   보고서를 만들지 않아 legal_agent와 중복 기록하지 않습니다. AD 팀은 배포 TEAM_ID 또는
   AD_WORKSPACE를 사용하며 사용자가 보낸 임의 team_id로 바꾸지 않습니다.
3) AD의 정확한 모델 전송 요청을 호출 전에 기존 ad_language_call.input에 저장합니다.
   실제 schema/messages/model/max_tokens/stream/thinking 옵션과 반환 원문·해석·receipt,
   SQL 작업/변경/실패 기록을 같은 요청의 보고서로 내보냅니다. 인증 정보는 제거합니다.
   request_id가 같아도 workspace/channel/chat이 다르면 다른 대화 기록을 가져오지 않습니다.
4) upstream HTTP error의 status_code와 body_json/body_text는 JSON 보고서의
   journal.calls[].model_output에서 확인합니다. 화면에도 HTTP 상태·구조화된 오류 코드와
   param/hint를 표시합니다. 외부 HTTP200이어도 answer_status=error이면 요약표에 실패로 남깁니다.
   저장소 장애가 AD 결과를 바꾸지 않습니다. 공유 파일은 요청 완료 후 기존 비동기
   finalizer로 생성됩니다. 실행 중 중단된 AD 원장은 기존 SQL에 남으며, 프로세스 강제 종료나
   NFS 장애 시 공유 보고서가 늦거나 누락될 수 있습니다.
5) legal_agent와 AD가 같은 structured_request / structured_content 처리를 사용합니다.
   기존 legal_agent는 GENOS 문법 컴파일러 호환을 위해 uniqueItems를 전송 스키마에서
   제거했으나 AD에는 그 처리가 없었습니다. 이 차이를 없앴습니다.
   원래 AD SCHEMA와 legal 검증 계약을 유지하여 중복 항목 등은 응답 수신 후 계속 거부합니다.
   AD도 정상 모델 ID·단일 choice·완결 응답·유효 JSON을 확인합니다.
   모델은 같아도 업무별 프롬프트/입력/스키마는 다릅니다. 관리 명령은 stream=false,
   기존 법률 최종 작성은 stream=true를 유지합니다. AD에 법률 검색/판단이나 자동 재시도를
   추가하지 않았습니다. 정확한 서버 오류 본문이 없어 사진의 HTTP 실패 원인은 아직 미확정입니다.

실행
아래 ZIP 경로만 실제 업로드 경로로 바꿉니다. ZIP과 별도 RUN.txt의 내용은 같습니다.
RUN.txt는 전체 코드를 내장하므로 별도 TXT만 사용할 때도 bash로 실행할 수 있습니다.

python3 -m zipfile -e /실제/업로드/GENOS_AD_REQUEST_LOGS_20261013_R1.zip ~/DEV/TRANSFER/ad-request-logs-r1-package
bash ~/DEV/TRANSFER/ad-request-logs-r1-package/GENOS_AD_REQUEST_LOGS_20261013_R1_RUN.txt check
bash ~/DEV/TRANSFER/ad-request-logs-r1-package/GENOS_AD_REQUEST_LOGS_20261013_R1_RUN.txt apply

기본 적용 대상은 ~/DEV이고 GENOS_DEV_ROOT로 기존 checkout을 지정할 수 있습니다.
시작부터 지속 로그·실패 코드·Python 경로/버전·적용 대상을 남깁니다.
BACKUP 및 APPLIED_CODE_ZIP의 실제 경로를 보관합니다. 이미 적용됐으면 검증 후
ALREADY_APPLIED로 끝납니다. 호환되지 않는 코드를 해시만 다시 계산해 통과시키지 않습니다.

변경 검토/배포
cd ~/DEV
git diff --check
git status --short

BACKUP/receipt.json의 변경 소스·엔진 pin·PIPELINE·CODE_MANIFEST를 검토해 같은 checkout에
commit합니다. 다른 작업 파일을 통째로 포함하지 않습니다. 아래 두 값을 실제 값으로 바꿉니다.

TASK_BACKUP='/실제/apply/출력의/backup-경로'
TASK_GENERATION='/현재/선택된/generation/절대경로'
bash ~/DEV/TRANSFER/ad-request-logs-r1-package/GENOS_AD_REQUEST_LOGS_20261013_R1_RUN.txt gate "$TASK_BACKUP" --generation "$TASK_GENERATION"

같은 checkout의 APPLIED_CODE.zip, Git commit, 선택 generation E2E/verify_assets를 확인합니다.
통과한 commit을 기존 배포 branch로 push하고 같은 commit의 새 코드서빙 리비전을 배포합니다.
별도 SSE 서버도 같은 코드로 재시작합니다. 코드 적용·push·새 리비전·SSE 재시작은 별도 단계입니다.
원문 재구축, DB 스키마 이행, 워크플로우 Python 편집기 재붙여넣기는 필요하지 않습니다.

현장 검증은 기존 워크플로우 테스트 화면에서만 합니다.
- 법률 질문: 기존 최종 답변 및 legal_agent 폴더의 요청 로그를 확인합니다.
- 같은 대화에서 [AD모드 시작] 후 숏컷 보여줘: ad_mode 폴더의 결과를 확인합니다.
- AD 호출 실패 시 같은 요청의 HTTP 번호와 서버 원문 오류를 확인합니다.
- [AD모드 종료] 후 인사 또는 법률 질문이 다시 legal_agent로 기록되는지 확인합니다.
직접 코드서빙 테스트 UI/API나 내부 모델 직접 호출을 요구하지 않습니다.

원복
bash ~/DEV/TRANSFER/ad-request-logs-r1-package/GENOS_AD_REQUEST_LOGS_20261013_R1_RUN.txt undo "$TASK_BACKUP"

종료 처리 수정 R1까지 적용된 직전 코드로 돌아갑니다. 이후 파일이 달라졌으면 원복을 거부합니다.
이미 배포했다면 이전 리비전 복귀와 별도 SSE 재시작도 필요합니다. 로그·DB·원문·백업은 보존합니다.

검증/한계
VALIDATION.json 및 VALIDATION_SUMMARY.txt를 함께 확인합니다. 모의 HTTP/SQL/문서로 검증했고
실제 GENOS/외부 모델 추론은 0회입니다. 사진 오류 해결, 실제 반입·리비전·화면은 미확인입니다.
수정 중 별도 작업으로 로컬 선택 포인터는 source-provider-20261013-r2(MAIN58)로 바뀌었습니다.
이 작업은 그 포인터를 변경하지 않았고, 확인 시 이번 9개 수정 파일은 선택 릴리스와 달랐습니다.
따라서 작업 코드/현장 인계본의 반영이며 로컬 선택 릴리스 반영이나 GENOS 배포 완료가 아닙니다.

재현됐습니다. 이번 AD/로그 변경과 별도로 보존하며 검증 통과 수에 포함하지 않습니다.
