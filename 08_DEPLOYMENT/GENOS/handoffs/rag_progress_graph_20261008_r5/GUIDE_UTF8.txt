3. 같은 DEV commit/generation gate → push → 리비전
적용은 실행 중인 서버 교체와 별도입니다. 실제 DEV의 변경을 검토합니다.
아래 TASK_BACKUP에는 이번 apply가 출력한 BACKUP 절대경로를 넣고,
GENOS_GENERATION은 현재 서비스가 선택한 실제 generation 절대경로를 사용합니다.
00_SYSTEM/GENOS_SERVING_PATHS.json이 있으면 경로·manifest SHA도 대조합니다.

export TASK_BACKUP='/이번_apply가_출력한_BACKUP_절대경로'
export GENOS_GENERATION='/기존_선택_generation_절대경로'
cd ~/DEV
python3 - "$TASK_BACKUP/receipt.json" <<'COMMIT_PY'
import json,subprocess,sys
receipt=json.load(open(sys.argv[1],encoding='utf-8'))
paths=[row['path'] for row in receipt['files']]
subprocess.run(['git','diff','--check','--',*paths],check=True)
subprocess.run(['git','add','-f','--',*paths],check=True)
subprocess.run(['git','commit','--only','-m','Apply standalone SSE judgment and evidence SVG R5','--',*paths],check=True)
COMMIT_PY
bash ~/DEV/TRANSFER/rag-progress-graph-r5-delivery/GENOS_RAG_PROGRESS_GRAPH_20261008_R5_RUN.txt gate "$TASK_BACKUP" --generation "$GENOS_GENERATION"
git rev-parse HEAD
git push

독립 RUN만 올렸다면 gate 명령에도 그 실제 RUN 경로를 사용합니다.
gate는 설치 DEV의 APPLIED_CODE.zip과 동일 committed checkout에서 generation E2E와
verify_assets를 실행합니다. 통과 후 코드를 바꾸면 다시 commit/gate해야 합니다.
새 리비전은 이 commit과 같은 generation을 선택하게 합니다.

4. SSE 서버는 따로 실행
기존 SSE 서버의 시작 명령을 교체하고 재시작합니다. 기존 수신 포트와 인증을

PORT/UVICORN_PORT 등 기존 포트 환경변수가 없거나 서로 다르면 기존 실제 포트를

전체 stdout/stderr 지속 로그를 남기는 제공 실행 TXT:

또는 bash ~/DEV/TRANSFER/rag-progress-graph-r5-delivery/START_SSE.txt --port <기존_수신_포트>

START_SSE는 서버를 foreground로 계속 실행합니다. 기존 플랫폼 프로세스 관리 방식에서
동일 명령을 사용합니다. bootstrap 로그는 TRANSFER/rag-progress-graph-r5/server-start-logs,
전체 시스템 로그는 기존 GENOS_SYSTEM_LOG_DIR 또는 /nfs-root/diamo/8-agent/logs/system입니다.
NFS 기록 실패 시 로컬 SPOOL을 보존하고 기존 재전송 절차로 회수합니다.
