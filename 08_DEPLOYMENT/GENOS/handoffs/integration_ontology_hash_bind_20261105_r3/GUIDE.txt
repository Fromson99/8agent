문서명 검색 → 사용자 확인 해시로 온톨로지 연결 R3

요청한 순서
1. 현재 NFS SQLite의 document.name으로 위험관리위원회 운영준칙 후보를 검색한다.
2. 문서명, document_id, document_hash(64자리), 단위/블록 수를 화면에 출력한다.
3. 사용자가 문서와 해시를 확인한다. 검색만으로는 원문/온톨로지/코드에 쓰지 않는다.
4. 확인한 해시를 연결 명령에 직접 넣는다. 자동 첫 후보 선택은 하지 않는다.

파일과 위치
GENOS 코드스페이스의 기존 ~/DEV/TRANSFER/에 다음 파일을 둔다.
  INTEGRATION_ONTOLOGY_HASH_BIND_R3.zip (이번 보조 코드)
  GENOS_ONTOLOGY_FIND_R3.txt            (문서명/해시 조회)
  GENOS_ONTOLOGY_BIND_R3.txt            (확인한 해시로 연결)
  INTEGRATION_ONTOLOGY_B03_B05_R2.zip   (이전에 보낸 검토 완료 지식, 같은 바이트 재사용)
ZIP 두 개를 서로 다시 묶지 않는다. FIND는 기존 R2 ZIP이 없어도 실행할 수 있다.
실제 코드 checkout 기본값은 ~/DEV이며 링크를 실제 경로로 해석한다.

1단계: 우선 이것만 실행
  cd ~/DEV/TRANSFER
  bash GENOS_ONTOLOGY_FIND_R3.txt

문서명 띄어쓰기를 제거해 검색하므로 '위험관리위원회 운영 준칙'도 찾는다.
같은 이름의 후보가 여러 개면 모두 출력한다. 정확한 이름이 없으면 위원회 관련 이름도 참고 출력한다.
본문 전체를 출력하지 않고 문서 메타데이터만 읽는다. NFS DB에 쓰기/전체 DB 해시/색인 재구축을 하지 않는다.
확인할 해시는 document_hash이다. 문서 ID를 문서 해시 대신 넣지 않는다.

2단계: 출력된 문서와 해시를 확인한 뒤
  bash GENOS_ONTOLOGY_BIND_R3.txt '<확인한 64자리 document_hash>'

같은 해시의 문서가 여러 개면 출력된 document_id도 넣는다.
  bash GENOS_ONTOLOGY_BIND_R3.txt '<확인한 64자리 document_hash>' '<문서ID>'

위 꺾쇠 표기는 실제 출력값으로 바꾼다. 검색에서 나오지 않은 해시는 거절한다.
문서 이름·확인한 해시·선택 문서ID를 대조한 뒤, 내규17단위의 같은 조항과 같은 본문을 찾는다.
문서ID/문서해시/단위ID/블록번호가 다르면 실제 현장 값으로 재결속한다.
본문과 인용, 조건, 정답 지식은 원래 검토본 그대로 유지한다. 공백을 삭제하거나 본문을 추측해서 맞추지 않는다.
같은 본문이 다른 조항에 있거나 후보가 중복되거나 내용이 다르면 연결하지 않고 중단 사유를 표시한다.
외규44단위도 기존 검토본과 일치해야 한다. 내규만 지정해 다른 문서의 검사를 생략하지 않는다.

연결 결과
검증된 실제 checkout의 기존 저장/승인/게시 Workflow로 코드스페이스 임시 위치에서 새 SQLite를 만든다.
모델 호출0, 원문 SQLite/manifest/탐색색인 변경0이다. 24묶음/46경로를 다시 읽어 확인한다.
NFS에는 기존 generation 아래 ontology/integration-b03-b05-r3-<binding>/의 봉인 DB와 설정만 추가한다.
이전 R2 온톨로지 디렉터리는 보존한다. 동일 요청 반복은 같은 게시본을 재사용한다.
완료 표시는 CONFIRMED_HASH_ONTOLOGY_PREPARED다. 이는 코드서빙 배포 완료 표시는 아니다.

TRANSFER/ONTOLOGY_R3_<binding>/ 아래에 다음 결과가 생긴다.
  BIND_RECEIPT.json                         선택한 문서와 결과
  bound-package/SOURCE_REBINDING.json        원래 좌표 → 현장 좌표, 사용자 지정 해시
  install-receipt/SERVING_ENV.txt            코드서빙에 복사할 정확한 설정
  install-receipt/DEPLOY_CODE.zip            실제 checkout과 대조할 코드
  install-receipt/code-before/              부분 패치 전 코드 백업
payload의 원래 정답검토표는 R1 검토 이력으로 보존한다. 현장 출처 좌표는 SOURCE_REBINDING.json을 기준으로 한다.

코드서빙 적용
기존 GENOS_GENERATION/GENOS_RUNTIME_DIR은 유지한다.
DP=nfs, GENOS_RAG_ONTOLOGY_ENABLED=on, GENOS_RAG_ONTOLOGY_CONFIG=출력된 절대경로를 사용한다.
코드 변경을 검토/commit하고 실제 checkout의 genos_release_gate.py에 DEPLOY_CODE.zip과 같은 generation을 전달한다.
게이트 통과 commit을 push한 뒤 새 코드서빙 리비전에 설정을 적용한다.
새 리비전에서 원문 출처와 과제3/5 질문을 확인한다. shell export만으로 서비스 설정은 바뀌지 않는다.

선택 generation
IT35_GENERATION → GENOS_GENERATION 환경변수 순서로 사용한다.
둘 다 없으면 사용자가 사진에서 지정한 다음 경로를 쓴다.
  /nfs-root/diamo/8-agent/term-releases/financial-risk-success-20261005-schema-r2/generation
다른 세대를 실제로 쓰고 있으면 그 값을 명시한다.
  IT35_GENERATION='/실제/generation' bash GENOS_ONTOLOGY_FIND_R3.txt
  IT35_GENERATION='/실제/generation' bash GENOS_ONTOLOGY_BIND_R3.txt '<확인한 해시>'
확인 없이 최신 날짜의 디렉터리를 자동 선택하지 않는다.

중단/원복
동일 해시로 명시 재실행하면 준비된 묶음을 검증해 재사용한다. 다른 해시·세대·작성 코드의 결과는 섞지 않는다.
코드 부분 반영 실패는 install-receipt의 백업과 bound-package/genos_install.py --rollback-code로 복구한다.
  python3 <bound-package>/genos_install.py --code-root <실제 checkout> --output <install-receipt> --rollback-code
후속 코드 수정은 덮어쓰지 않는다. 원문 generation/과거 온톨로지는 삭제하지 않는다.
시험 중단은 코드서빙 GENOS_RAG_ONTOLOGY_ENABLED=off 또는 이전 연결 설정/리비전으로 복귀한다.

범위
이번 추가 실행본은 GENOS NFS SQLite의 내규 문서 해시 선택을 다룬다.
Oracle/Dataiku 기존 R2 반입본은 보존한다. 현장 확인한 hash와 원문을 검증하기 전에는 실제 일치로 보고하지 않는다.
새 법률 판단이나 실제 모델 답변 품질 시험은 수행하지 않는다.
