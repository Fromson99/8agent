2. 실제 업로드한 TRANSFER에서 실행
ZIP/TXT를 올린 TRANSFER 폴더를 현재 터미널 작업 위치로 유지합니다.
아래 /workspace는 앞선 현장 사진에서 확인한 실제 기존 Git checkout 경로입니다.
현재 git rev-parse --show-toplevel 결과가 다르면 확인한 기존 checkout 경로로 바꿉니다.
~/DEV가 그 checkout을 가리키는 경우에도 실제 경로를 확인해 적용합니다.
TRANSFER를 임의로 ~/TRANSFER나 ~/DEV/TRANSFER라고 추정하지 않습니다.

python3 -m zipfile -e ./GENOS_WORKFLOW_PROGRESS_20261019_R1.zip ./GENOS_WORKFLOW_PROGRESS_20261019_R1
bash ./GENOS_WORKFLOW_PROGRESS_20261019_R1/GENOS_WORKFLOW_PROGRESS_20261019_R1_RUN.txt check --root /workspace
bash ./GENOS_WORKFLOW_PROGRESS_20261019_R1/GENOS_WORKFLOW_PROGRESS_20261019_R1_RUN.txt apply --root /workspace
bash ./GENOS_WORKFLOW_PROGRESS_20261019_R1/GENOS_WORKFLOW_PROGRESS_20261019_R1_RUN.txt status --root /workspace

Python 3.11 이상이며 실제 실행 파일/버전을 로그로 남깁니다. 기존 패키지의 sqlglot 30.23.0을
이미 설치했다면 deps를 반복할 필요가 없습니다. 설치하지 않은 경우에만 check 전에 실행합니다.

별도 첨부 RUN.txt도 ZIP 옆에서 실행하면 같은 설치기로 연결합니다.
첫 실행부터 TRANSFER/workflow-progress-r1-logs에 지속 로그와 .log.exit 종료 코드를 남깁니다.
패키지 폴더 STATUS.json/LAST_FAILURE.json에 상태와 실패를 보존합니다.
기존 checkout의 09_ARTIFACTS/BACKUPS/code-replacement에 바뀐 파일 원본을 백업합니다.
중단된 apply는 원본 복원 후 다시 적용할 수 있으며 재적용은 동일 바이트를 확인합니다.
