GENOS 출력 토큰 상한 제거 R1

변경: GENOS RAG의 계획·조사·판단·최종 답변/스트리밍과 AD 요청에서 앱의 max_tokens를 보내지 않는다.
기존 GENOS_RAG_MAX_OUTPUT_TOKENS 값은 무시한다. 수정 후 effective profile의 max_output_tokens는 null이다.
6,400/12,800 토큰의 단계별 상한은 이 GENOS 실행에 적용되지 않는다.
모델 서버 자체의 기본 생성 길이·컨텍스트·출력 제한은 서버 설정에 따라 남는다.
서버가 length로 종료하면 미완료 상태를 보존한다. 앱 상한 확대를 위한 같은 호출은 반복하지 않는다.
JSON/스키마 수정, 근거·권한·해시 검증, 전체 요청 시간·모델/도구 횟수, 부분 스트림 실패 처리는 유지한다.

적용 대상: LENGTH_RECOVERY R1 또는 R2를 적용한 기존 ~/DEV. FACT_REASON R1 적용 여부 모두 지원한다.
이 패치는 이전 복구 패치 전체를 대신하지 않는다. 필요한 복구/문구 패치를 적용한 뒤 이 패치를 마지막에 적용한다.
코드 inventory가 알려진 구성과 다르면 코드 쓰기 전에 중단하며 기존 파일을 보존한다.

1. 실제 업로드한 TRANSFER 폴더를 현재 작업 위치로 두고 실행한다.
TRANSFER의 절대 위치를 추정하거나 압축을 풀기 위해 DEV로 이동하지 않는다.

python3 -m zipfile -e ./GENOS_OUTPUT_UNLIMITED_20261015_R1.zip ./GENOS_OUTPUT_UNLIMITED_20261015_R1
bash ./GENOS_OUTPUT_UNLIMITED_20261015_R1/GENOS_OUTPUT_UNLIMITED_20261015_R1_RUN.txt install

install은 사전 검사 → 백업 → 적용 → 검증을 연결한다. 실패 시 중단하며 처음부터 지속 로그와 exit 상태를 기록한다.
실제 checkout이 ~/DEV와 다를 때만 확인한 경로를 GENOS_DEV_ROOT로 지정한다.
독립 TXT와 ZIP 안의 TXT는 같다. 검사만 하려면 install 대신 check를 사용한다.
현재 TRANSFER/output-unlimited-r1-logs에 실행 로그가 남는다.
출력된 BACKUP 및 APPLIED_CODE_ZIP 절대경로를 보관한다. 재실행은 이미 적용한 해시를 확인한다.

2. 기존 DEV에서 변경 범위와 git diff --check를 확인하고 receipt에 나온 파일 및 CODE_MANIFEST.json만 commit한다.
다른 미완료 변경은 함께 stage하지 않는다. 실제 변경 목록은 설치 receipt가 기준이다.

3. 실제 TRANSFER에서 다음 두 따옴표 안을 현장 출력과 설정의 실제 절대경로로 바꾼다.

bash ./GENOS_OUTPUT_UNLIMITED_20261015_R1/GENOS_OUTPUT_UNLIMITED_20261015_R1_RUN.txt gate "실제 BACKUP 절대경로" --generation "현재 선택된 generation 절대경로"

위 한글 예시 값을 그대로 실행하지 않는다.
gate는 commit한 동일 DEV 코드·생성된 전체 APPLIED_CODE.zip·현재 generation을 검사한다.
통과 후 코드나 pin을 바꾸면 다시 commit하고 gate를 재실행한다.
통과한 commit을 push하고 해당 commit의 새 코드서빙 리비전을 배포한다. 같은 코드로 분리 SSE 프로세스를 재시작한다.
원문/NFS generation 재구축과 이번 패치를 위한 워크플로우 Python 편집기 교체는 필요 없다.

4. 워크플로우 테스트 화면에서 새 요청으로 기존 정상 질문과 길이 종료 질문을 확인한다.
같은 요청의 모델 request 기록에 max_tokens와 max_completion_tokens가 없는지 확인한다.
실제 usage와 finish_reason, 최종 답변/실패 상태, request ID, code commit/리비전/generation을 남긴다.
실제 내부 모델 응답 길이와 성공은 외부 합성 검사로 확인하지 않았다.

5. 원복할 때는 진행 중 요청을 정리한 뒤 설치 시 출력한 BACKUP을 사용한다.

bash ./GENOS_OUTPUT_UNLIMITED_20261015_R1/GENOS_OUTPUT_UNLIMITED_20261015_R1_RUN.txt undo "실제 BACKUP 절대경로"

원래 파일·권한·CODE_MANIFEST를 복원한다. 설치 후 별도 수정은 덮어쓰지 않고 중단한다.
필요한 commit/push/이전 검증 리비전 배포·SSE 재시작은 별도다. 데이터와 기존 실패 기록은 삭제하지 않는다.

상태 구분: 로컬 작업 코드 및 모의 설치본 검증. 로컬 외부 Qwen 모델 정책과 MAIN66은 유지한다.
GENOS 반입·Git push·코드서빙 리비전 배포·내부 모델·워크플로우 성공은 현장에서 확인해야 한다.
