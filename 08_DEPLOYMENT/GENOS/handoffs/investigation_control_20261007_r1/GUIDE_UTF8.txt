현장 실행 — 기존 Git checkout ~/DEV에 적용
ZIP과 APPLY TXT를 같은 디렉터리(예: ~/DEV/TRANSFER)에 저장합니다.
현장 실행 명령은 python3이며 실행기 자체가 실제 sys.executable/버전을 기록합니다.
모든 모드는 시작부터 investigation-control-r1-logs/*.log와 events.jsonl에 기록합니다.
긴 검사는 20초마다 진행 중 표시를 남깁니다. 실패 종료 코드와 로그 경로를 보존합니다.

기본 선택 경로는 2026-10-06 사용자 현장 기록의
/nfs-root/diamo/8-agent/term-releases/financial-risk-success-20261005-schema-r2/generation
입니다. 실제 코드서빙 선택이 달라졌다면 GENOS_GENERATION에 그 절대경로를 지정합니다.
폴더명·날짜로 최신 세대를 자동 선택하지 않습니다. ~/DEV 별칭은 실제 Git root로 해석합니다.

cd "$HOME/DEV/TRANSFER"
export GENOS_DEV="$HOME/DEV"
export GENOS_GENERATION="/nfs-root/diamo/8-agent/term-releases/financial-risk-success-20261005-schema-r2/generation"
bash GENOS_INVESTIGATION_CONTROL_20261007_R1_APPLY.txt all "$GENOS_GENERATION"

all: ZIP/기존 cache 확인 → 알려진 코드 대조 → 파일별 백업/적용 → 실제 checkout의
loader·generation E2E·verify_assets → 해당 파일만 Git commit → 같은 checkout의
release gate → 현재 브랜치를 origin으로 push 순서입니다.
기존 remote/branch 설정을 사용하며 필요 시 GENOS_PUSH_REMOTE, GENOS_PUSH_BRANCH로
대상을 지정할 수 있습니다. detached HEAD는 브랜치 명시가 필요합니다.
다른 추적/스테이징 변경이 있으면 보존하고 commit 전에 중단합니다.
알 수 없는 현장 코드 수정·cache compiler 불일치는 파일 교체 전에 중단합니다.
코드 자체를 검토할 필요가 있으면 아래 단계별 모드를 사용합니다.

bash GENOS_INVESTIGATION_CONTROL_20261007_R1_APPLY.txt check "$GENOS_GENERATION"
bash GENOS_INVESTIGATION_CONTROL_20261007_R1_APPLY.txt apply "$GENOS_GENERATION"
bash GENOS_INVESTIGATION_CONTROL_20261007_R1_APPLY.txt verify "$GENOS_GENERATION"
# 여기서 git diff를 검토합니다.
bash GENOS_INVESTIGATION_CONTROL_20261007_R1_APPLY.txt push "$GENOS_GENERATION"

성공 종료 마커: INVESTIGATION_CONTROL_EXIT=0
CODE_APPLIED의 backup 경로와 GIT_PUSHED의 commit·generation·manifest hash를 보관합니다.
재실행은 같은 설치의 바이트를 확인하고 기존 backup을 재사용합니다.
CODE_APPLIED만 나온 경우 Git push·리비전 배포가 끝난 것이 아닙니다.

코드서빙 리비전 배포 — 플랫폼에서 별도 수행
GIT_PUSHED와 RELEASE_GATE_PASS가 기록한 정확한 commit으로 새 리비전을 배포합니다.
새 리비전이 같은 GENOS_GENERATION과 아래 실제 설정을 사용하는지 대조합니다.
SEMANTIC_LLM_BACKEND=genos
GENOS_RAG_IMPLEMENTATION=legal-agent-unified-v6
GENOS_RUNTIME_DIR=/nfs-root/diamo/8-agent/runtime
GENOS_GENERATION=위에서 검증한 정확한 generation 절대경로
기존 GENOS_BASE_URL/GENOS_LLM_SERVING_ID/GENOS_LLM_KEY 또는 GENOS_LLM_URL,
내부 모델·임베딩 설정과 신뢰된 AD/기억 인증 설정을 보존합니다.
키의 실제 값을 메일/사진/로그로 공유하지 않습니다.
GENOS 내부 provider와 실행 환경의 프로필은 로컬 Qwen 프로필과 다르며,
현장 native 실행 지문과 선택 모델을 별도로 기록합니다.

원복
