GENOS 파이프라인 최적화 R1 / 2026-10-02

기존 복구 R3는 실패한 전문 색인을 복구하는 용도다. 이 ZIP은 이후 반복 처리 비용을 줄이는 코드 패치다. 진행 중인 기존 검토·구축은 종료하고, 기존 복구 R3와 완료된 검토 결과를 먼저 보존한다. 새 패치를 적용한 뒤에는 구현 hash가 달라지므로 기존 review plan의 pin을 고쳐 재개하지 않는다.

바뀐 경로: 별첨 제목 regex 재사용, 용어 hit 포함관계 정렬, matcher 본문 복사 제거, review JSON 집계의 transactional counter와 작업 index, 충돌 scope/edge 탐색, 본문당 hash 1회, catalogue 범위 1회 해석, 감사 원본 rename+runtime table projection, 전문 색인 pool 묶음 전송, longest literal trie와 immutable serving cache, navigation 내부 시간 로그.

로컬 합성 결과: 별첨 처리 62.2배(별도 ADR-0615); 포함관계 399.3배; 상태집계 1780.6배(최초 migration 제외); 충돌검사 8.3배; 감사분리 4.8배; 용어검색 21.0배(constructor 포함). 각 작업의 합성 조건 수치이고 전체 navigation/GENOS 속도 예상치가 아니다. 사진의 navigation은 33,384.2초=9시간16분24.2초이며 56분이라는 과거 판독은 잘못됐다.

검증: 원문/범위/ID/미해결 사유/충돌 witness/감사 행/전문색인 토큰과 순위 보존. 추가 계약 136개, 용어 holdout 205사례, 최종 working 통합 151개 통과. baseline에서도 실패하는 기존 검사 2개를 기록했다. 실제 GENOS/NFS/내부 모델 성능은 미확인이다.

실행 (GENOS Python 명령은 python3):
  bash GENOS_PIPELINE_OPTIMIZATION_R1.txt /절대경로/GENOS_PIPELINE_OPTIMIZATION_20261002_R1.zip

기본 ~/DEV의 11개 코드 파일을 기존/중간/최종 허용 hash와 대조한다. 다른 코드가 있으면 FILE_DRIFT로 적용 전에 중단한다. 강제로 덮어쓰지 말고 해당 파일 diff/현장 hash를 확인한다. 맞으면 코드 및 engine/PIPELINE pin을 먼저 백업하고 적용한다. 새 dependency 설치 없음. 실제 Python 경로/버전, package ZIP SHA, checkout, file hashes, backup/receipt와 지속 로그를 남긴다. 오류 시 적용한 파일과 pin을 원래 바이트로 되돌린다.

완료된 구조화 source.sqlite와 완료된 glossary 디렉터리가 선택됐으면 새 출력에만 구축할 수 있다:
  bash GENOS_PIPELINE_OPTIMIZATION_R1.txt /절대경로/GENOS_PIPELINE_OPTIMIZATION_20261002_R1.zip /기존/완료/source.sqlite /기존/완료/glossary /새로운/미활성/출력경로

기존 검토 자료를 읽어 새 generation을 만든다. 원래 source/glossary/세대/원장/CURRENT를 수정하지 않는다. BUILD.py라는 실제 파일로 실행하므로 stdin spawn 오류를 피한다. 새 출력의 generation과 감사 파일을 검증한다. 실패 상태와 stdout/stderr는 로그에 남는다. 동일 출력 재실행은 identity/hash가 같을 때만 검증 또는 재개가 허용된다. 내부 LLΜ 검토를 새로 호출하지 않는다.

코드 적용, generation 생성, Git commit/push, 코드서빙 revision 배포, workflow Python 편집기 반영, 현장 질문 검증은 별도 상태다. 이 TXT는 코드 적용/새 generation 구축까지만 한다. 실제 질의와 warmup은 workflow 테스트 화면에서 확인한다. 새 serving revision/선택 generation은 그 단계에서 별도 기록한다.
