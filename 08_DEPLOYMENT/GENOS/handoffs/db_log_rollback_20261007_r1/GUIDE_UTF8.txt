GENOS DB 지연 진단 로그 롤백 R1

사용 파일: GENOS_DB_LOG_ROLLBACK_20261007_R1_RUN.txt
TXT 한 개만으로 실행 가능하며 ZIP을 먼저 풀 필요가 없습니다.
GENOS_QUERY_LATENCY_20261007_R3 등 기존 계측 적용 TXT를 다시 실행하지 말고,
이번 로그 롤백에는 아래 RUN.txt를 사용하세요.

변경: DB/검색/모델 준비의 query_latency 세부 step 로그와 DB 연결 PRAGMA
진단을 제거합니다. GENOS_QUERY_LATENCY=1이 남아 있어도 세부 계측은 꺼집니다.
기존 검색 캐시·순위·권한·원문·세션 저장·RAG 진행/오류/감사 로그는 유지합니다.
원문 DB·NFS generation·CURRENT·.env·완료 로그를 수정하거나 삭제하지 않습니다.
query_latency.py, unit_fulltext.py와 그 두 코드의 기존 엔진 해시 30개,
설치 inventory만 변경합니다. 과거 전체 코드로 되돌리지 않습니다.

1. RUN.txt를 ~/DEV/TRANSFER에 저장합니다. 현장 요청이 실행 중이면 끝날 때까지
기다리고 기존 코드서빙 프로세스를 중지한 뒤 적용하세요.
모든 Python 실행은 현장 python3를 사용합니다.

cd ~/DEV/TRANSFER
bash GENOS_DB_LOG_ROLLBACK_20261007_R1_RUN.txt check
bash GENOS_DB_LOG_ROLLBACK_20261007_R1_RUN.txt apply
bash GENOS_DB_LOG_ROLLBACK_20261007_R1_RUN.txt verify

DEV 위치가 다르면 GENOS_DEV_ROOT=/실제/checkout을 같은 명령 앞에 지정합니다.
알 수 없는 현장 코드 변경은 CHECKOUT_DRIFT로 중단하며 덮어쓰지 않습니다.
CODE_MANIFEST.json이 없는 checkout도 중단합니다. 기존 파일과 출력 로그를
보존해서 변경 경로를 확인해야 합니다. apply를 다시 실행하면 이미 적용된
상태를 검사하고 ALREADY_APPLIED를 출력합니다.

2. apply가 출력하는 BACKUP=/절대경로를 보관합니다.
이 폴더의 receipt.json은 실제 Python·코드 루트·변경 전후 해시를 기록합니다.
APPLIED_CODE.zip은 현재 checkout의 설치 코드를 그대로 묶은 배포 검증 ZIP입니다.
기본 지속 로그: ~/DEV/TRANSFER/db-log-rollback-r1/logs/*.log
끝에 DB_LOG_ROLLBACK_EXIT=0을 확인합니다. 실패/중단 시에도 BACKUP 기록은 남습니다.

3. 기존 배포 절차로 이번 수정만 Git commit합니다. 아래 task_backup과
task_generation은 apply 출력 및 실제 선택 generation의 절대경로로 직접 채웁니다.
서버에 적용되어 있던 GENOS_GENERATION과 같은 경로를 사용하세요.

task_backup='/apply가 출력한/BACKUP/절대경로'
task_generation='/실제/선택된/NFS/generation'
bash ~/DEV/TRANSFER/GENOS_DB_LOG_ROLLBACK_20261007_R1_RUN.txt gate "$task_backup" --generation "$task_generation"

gate는 동일 Git checkout의 ZIP 해시 비교 → generation E2E → verify_assets를
실행합니다. commit하지 않은 변경 또는 서로 다른 코드/generation은 거부합니다.
PASS 뒤 그 commit을 기존 원격에 push하고 그 commit과 같은 generation을
선택한 새 코드서빙 리비전을 배포합니다. 코드 apply만으로 실행 중인 리비전은
바뀌지 않습니다. 빌드·시작 명령·모드·플랫폼 연결은 기존 값을 유지하세요.
분리 Python 워크플로우 편집기는 이번 패치의 변경 대상이 아닙니다.

4. 현장 질의 검증은 워크플로우 테스트 화면에서만 실행합니다.
기존 질의로 RAG 진행·최종 답변·오류 기록을 확인하고, 신규 요청 로그에
query-latency-20261007-r1의 step.started/finished/failed와 unit_fts.connection이
추가되지 않는지 확인합니다. 다른 모듈의 일반 진행/오류 step 로그는 계속 남습니다.
현장 코드서빙 리비전·요청 ID·generation/manifest 해시·결과를 기록하세요.

5. 이번 로그 롤백 패치 자체를 되돌릴 때:

bash ~/DEV/TRANSFER/GENOS_DB_LOG_ROLLBACK_20261007_R1_RUN.txt undo "$task_backup"

undo는 정확한 백업과 현재 해시를 비교한 뒤 이번에 변경한 파일만 복구합니다.
이후 다른 변경이 있으면 보존/중단합니다. 실행 중인 서빙 복귀는 기존 검증된
리비전과 같은 generation으로 별도 배포해야 합니다.

이번 인계의 상태: 로컬 계약/첨부 실행 검증 및 반입 자료 준비.
GENOS 현장 적용·push·리비전 배포·내부 질의 결과는 현장 확인 전까지 미확인입니다.
