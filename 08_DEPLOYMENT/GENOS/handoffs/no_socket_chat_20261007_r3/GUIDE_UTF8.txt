GENOS 통합 직접 JSON / 분리 Python 워크플로우 SSE R3

사용자 보고: R2는 현장 ~/DEV에 apply까지만 완료했습니다. Git push와 새 코드서빙
리비전 배포는 하지 않았습니다. R3는 R2 적용본 위에 직접 적용하는 누적 교체본입니다.
R2 rollback부터 실행하지 마세요. 그 백업은 R1 또는 그 전 상태일 수 있습니다.
기존 R2 백업과 로그는 보존하세요.

R3 ZIP과 R3 APPLY TXT를 같은 ~/DEV/TRANSFER 폴더에 놓습니다.
ZIP SHA-256: 5ec5384b020cb76e8ca2f28b252850168888bed29e855c6116ee113b2002cb06
현장에서 실제 선택 중인 NFS generation 절대경로를 확인해 지정합니다.

 export GENOS_GENERATION='/실제로/선택한/절대/generation/경로'
 cd ~/DEV/TRANSFER
 sha256sum GENOS_NO_SOCKET_CHAT_20261007_R3.zip
 bash GENOS_NO_SOCKET_CHAT_20261007_R3_APPLY.txt check "$GENOS_GENERATION"

check의 NO_SOCKET_CHAT_EXIT=0, CHECKOUT_PREFLIGHT 불일치 없음,
GENERATION_SELECTED 경로와 manifest SHA를 확인할 때만 아래를 실행합니다.
CHECKOUT_DRIFT, 다른 staged/dirty 파일, generation/cache 불일치가 나오면
즉시 멈추고 CHECKOUT_PREFLIGHT-*.json과 events.jsonl의 파일명/해시를 확인합니다.
과거 ZIP을 순서대로 적용하거나 해시·manifest를 수동 수정하지 마세요.

 bash GENOS_NO_SOCKET_CHAT_20261007_R3_APPLY.txt apply "$GENOS_GENERATION"
 cd ~/DEV
 python3 -m pip install -r 08_DEPLOYMENT/GENOS/requirements-sse.txt
 GENOS_MAIN_MODE=integrated bash ~/DEV/TRANSFER/GENOS_NO_SOCKET_CHAT_20261007_R3_APPLY.txt verify "$GENOS_GENERATION"
 GENOS_MAIN_MODE=workflow bash ~/DEV/TRANSFER/GENOS_NO_SOCKET_CHAT_20261007_R3_APPLY.txt verify "$GENOS_GENERATION"

apply는 R3 백업 경로를 출력하고 코드만 교체합니다. 선택 generation, 원문, DB,
CURRENT, .env, Git remote와 이전 백업은 보존합니다. 재실행은 같은 해시에서만
안전하며 알 수 없는 현장 변경은 거절합니다. 두 verify의 NO_SOCKET_CHAT_EXIT=0,
NO_SOCKET_CHAT_CONTRACT PASS mode, GENERATION_E2E PASS, VERIFY_ASSETS PASS를
각각 확인합니다. 현장 Python은 python3이며 출력된 sys.executable/버전을 기록합니다.

새 코드서빙의 Build:
 python3 -m pip install -r 08_DEPLOYMENT/GENOS/requirements-sse.txt
새 코드서빙의 Run:
 python3 main_router.py
PORT 환경변수가 없으면 기존 코드서빙과 같은 수신 포트를 --port로 지정합니다.

통합 직접 실행의 코드서빙 환경변수:
 GENOS_MAIN_MODE=integrated
 GENOS_CHAT_TRANSPORT=json
 GENOS_RAG_IMPLEMENTATION=legal-agent-unified-v6
GENOS 채팅앱은 해당 코드서빙의 /chat을 선택합니다. 별도 Python 워크플로우
단계를 사용하지 않고 socket.io 실시간 스트리밍 옵션을 끕니다.
질문에는 기존 {code,data.text} 완성 JSON을 반환합니다.

분리 워크플로우의 코드서빙 환경변수:
 GENOS_MAIN_MODE=workflow
 GENOS_RAG_IMPLEMENTATION=legal-agent-unified-v6
코드서빙 /stream을 기존 GENOS Python 단계가 HTTP SSE로 읽습니다. 편집기에
첨부 GENOS_NO_SOCKET_CHAT_20261007_R3_WORKFLOW_PASTE_ALL.txt 전체를 붙여 넣고
run(data)를 사용합니다. 코드 ZIP 적용·Git push가 편집기 내용을 바꾸지 않습니다.
기존 GENOS_BASE_URL, GENOS_CODESERVING_ID/TOKEN, timeout, 내부 모델·team·NFS
runtime·AD/기억 설정은 실제 검증된 값으로 유지합니다. 이 Python 단계는
main_socketio를 import하거나 토큰을 소켓으로 보내지 않고 최종 JSON을 반환합니다.
GENOS 채팅앱은 이 별도 Python 워크플로우를 선택하고 코드서빙의 socket.io 옵션을
끕니다. GENOS_RAG_PROGRESS_UI의 기존 값이 socketio여도 R3 단계는 off입니다.

주의: 서버 환경변수만으로 채팅앱 대상·워크플로우 정의·소켓 옵션은 자동으로
바뀌지 않습니다. 플랫폼 설정을 선택한 실행 방식에 맞춰 별도로 연결합니다.
현장 질의·warmup 검증은 워크플로우 테스트 화면에서만 합니다.
통합: __verify__ 후 짧은 질문의 완성 JSON과 근거/AD/기억을 확인합니다.
분리: WORKFLOW_SETTINGS의 socketio_enabled=false와 SSE_CHECK, 일반 질문의
code_serving_transport.route=/stream, opened=true, 최종 text를 확인합니다.

선택적으로 이후 push하려면 R3 APPLY TXT의 push 모드 또는 첨부
GENOS_NO_SOCKET_CHAT_20261007_R3_PUSH_NEW_REMOTE.txt를 사용합니다.
같은 ~/DEV checkout과 선택 generation에서 release gate를 통과한 commit만
push하고, 새 코드서빙 리비전은 그 commit과 같은 generation을 선택합니다.
push·리비전 배포·채팅앱 연결·현장 질문 성공은 각각 별도 상태입니다.

R3 자체 적용을 원복할 때만 R3 apply가 출력한 정확한 backup으로 실행합니다:
 bash ~/DEV/TRANSFER/GENOS_NO_SOCKET_CHAT_20261007_R3_APPLY.txt rollback /정확한/R3/backup
이 명령은 R3 직전의 코드 바이트로 돌아갑니다. 플랫폼 리비전/채팅앱 설정은
별도로 이전 검증 상태를 선택합니다.

이번 로컬 검사 성공은 실제 GENOS 적용·서비스 성공이 아닙니다. R2가 apply
까지만 되었다는 상태는 사용자 보고이며 로그로 확인된 현장 commit/revision은 없습니다.
