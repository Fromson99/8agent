GENOS 길이 복구·기존 계약 실패 수정 누적 R1 — 2026-10-14

적용 대상과 파일
- 기존 Git checkout ~/DEV. 다른 위치를 실제로 쓸 때만 GENOS_DEV_ROOT를 지정한다.
- ZIP과 실행 TXT는 사용자가 실제 업로드한 TRANSFER 폴더에서 실행한다. TRANSFER의 절대 위치를 추정하지 않는다.
- 파일: GENOS_LENGTH_RECOVERY_20261014_R1.zip / GENOS_LENGTH_RECOVERY_20261014_R1_RUN.txt
- 이전 schema recovery R1 이상 알려진 누적 코드 inventory에 적용한다. tool recovery R1까지의 수정도 포함한다.
- 검증되지 않은 코드/수동 수정이 있으면 해시 검사에서 중단한다. 강제 적용하지 않고 로그와 기존 파일을 보존한다.

1. 업로드한 TRANSFER 폴더를 현재 위치로 두고 실행
python3 -m zipfile -e ./GENOS_LENGTH_RECOVERY_20261014_R1.zip ./GENOS_LENGTH_RECOVERY_20261014_R1
bash ./GENOS_LENGTH_RECOVERY_20261014_R1/GENOS_LENGTH_RECOVERY_20261014_R1_RUN.txt check
bash ./GENOS_LENGTH_RECOVERY_20261014_R1/GENOS_LENGTH_RECOVERY_20261014_R1_RUN.txt apply
bash ./GENOS_LENGTH_RECOVERY_20261014_R1/GENOS_LENGTH_RECOVERY_20261014_R1_RUN.txt verify

첨부 TXT 하나만 쓸 때도 전체 설치기와 해시 고정 payload가 내장되어 있다.
bash ./GENOS_LENGTH_RECOVERY_20261014_R1_RUN.txt check
bash ./GENOS_LENGTH_RECOVERY_20261014_R1_RUN.txt apply
bash ./GENOS_LENGTH_RECOVERY_20261014_R1_RUN.txt verify

처음부터 현재 TRANSFER 아래 length-recovery-r1-logs에 지속 로그를 남긴다.
출력된 BACKUP 경로와 APPLIED_CODE.zip 경로를 보관한다. apply 재실행은 이미 적용된 동일 바이트를 확인한다.
실행 Python은 python3다. 현장 sys.executable/Python 버전은 로그에서 확인한다.

2. 적용된 ~/DEV checkout에서 기존 Git 절차로 변경 검토 및 commit
설치 receipt에 나온 수정 파일과 CODE_MANIFEST.json을 함께 commit한다. 다른 미완료 변경을 무심코 포함하지 않는다.
코드 적용/commit/push/코드서빙 리비전은 각각 별도 단계다. NFS 원문·색인 재구축은 필요 없다.

3. 같은 commit과 현재 실제 NFS generation의 gate
TRANSFER 폴더에서 다음 형식에 apply가 출력한 BACKUP 경로와 실제 선택 generation 경로를 넣는다.
bash ./GENOS_LENGTH_RECOVERY_20261014_R1/GENOS_LENGTH_RECOVERY_20261014_R1_RUN.txt gate BACKUP_PATH --generation ACTUAL_GENERATION_PATH
BACKUP_PATH와 ACTUAL_GENERATION_PATH는 실제 출력/설정을 사용하며 위 예시 문자열을 그대로 실행하지 않는다.
gate 성공 후 기존 원격으로 push하고, 해당 commit으로 새 코드서빙 리비전을 배포한다. 기존 SSE 프로세스도 재시작한다.
워크플로우 편집기 코드 변경은 이번 패치에 필요 없다. 질의 확인은 워크플로우 테스트 화면에서만 한다.

4. 현장 확인
최근 length 오류 질문을 워크플로우 테스트 화면에서 다시 실행한다.
정상 max_tokens=6400은 유지된다. source-law-navigation-N 응답이 finish_reason=length이면
기존 담당의 수정1회 source-law-navigation-N-repair에 max_tokens=12800을 사용한다.
LENGTH_RECOVERY_POLICY와 model.attempt.*의 실제 cap/usage/finish_reason을 확인한다.
잘린 출력은 실행하지 않으며 완전한 결정의 스키마·근거·권한·상태 검증 후에만 후속 단계를 진행한다.
다시 length이면 중단하고 원인/원본 시도/사용 예산을 보존한다. 다른 질문·검색·원문·모델을 임의 변경하지 않는다.
내부 모델/서빙이12800을 허용하는지와 실제context한도는 현장 기록으로 확인해야 한다. HTTP200만으로 답변 완료로 보지 않는다.
기존에 성공하던 원문 읽기·후속 질문·숏컷·답변 스트리밍도 함께 확인한다.

5. 원복
진행 중인 요청을 마친 뒤 apply가 출력한 BACKUP 경로로 undo한다.
bash ./GENOS_LENGTH_RECOVERY_20261014_R1/GENOS_LENGTH_RECOVERY_20261014_R1_RUN.txt undo BACKUP_PATH
현재 파일이 패치 후 예상 해시와 다르면 undo도 중단하여 수동 변경을 보호한다.
원복된 checkout으로 필요한 commit/push 및 이전 검증 리비전 배포·SSE 재시작을 진행한다.
데이터와 실패 원장은 삭제하지 않는다. local MAIN rollback과 GENOS 리비전 원복은 별개다.
