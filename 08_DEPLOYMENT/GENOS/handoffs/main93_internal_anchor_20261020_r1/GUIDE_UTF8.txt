실행 위치와 적용 대상
ZIP과 TXT를 실제 업로드한 TRANSFER 폴더를 현재 위치로 두세요.
TRANSFER의 절대 위치를 가정하지 않습니다. 압축을 풀기 위해 DEV로 이동하지 않습니다.
설치 대상은 기존 ~/DEV Git checkout이며 링크이면 검증한 실제 경로로 적용합니다.
다른 checkout을 사용하는 경우 확인한 경로를 각 명령 뒤 --root /실제/checkout 에 지정합니다.
코드 ZIP은 원문·색인·관계 DB·실행 상태를 포함하지 않습니다.
기존 GENOS_SERVING_PATHS.json, 환경 설정, 데이터와 런타임은 유지합니다.

TRANSFER에서
python3 -m zipfile -e ./GENOS_MAIN93_INTERNAL_ANCHOR_20261020_R1.zip ./GENOS_MAIN93_INTERNAL_ANCHOR_20261020_R1
bash ./GENOS_MAIN93_INTERNAL_ANCHOR_20261020_R1/GENOS_MAIN93_INTERNAL_ANCHOR_20261020_R1_RUN.txt check

python3 3.11 이상과 기존 requirements 의존성을 사용합니다.
실제 실행 Python 경로·버전은 로그로 남습니다.
sqlglot 30.23.0이 없을 때만 check 전에 아래 동봉 wheel 설치를 실행합니다.
bash ./GENOS_MAIN93_INTERNAL_ANCHOR_20261020_R1/GENOS_MAIN93_INTERNAL_ANCHOR_20261020_R1_RUN.txt deps
인터넷 설치나 내부 모델 호출을 이 명령이 수행하지 않습니다.

apply는 기존 checkout의 검증 가능한 백업을 만든 뒤 코드를 적용합니다.
같은 명령 재실행은 적용 상태를 확인하며, 설치 중단은 기록된 백업으로 복구합니다.
이후 수정된 파일·손상된 백업은 덮어쓰지 않고 중단합니다.
TRANSFER/main93-internal-anchor-r1-logs 에 첫 단계부터 로그와 .log.exit를 남깁니다.
패키지 폴더의 STATUS.json과 기존 checkout의 BACKUPS를 보존하세요.

현장 배포 — 코드 적용과 별도
1. 기존 checkout에서 변경 파일을 검토하고 필요한 코드만 commit합니다.
   다른 작업을 섞는 git add -A나 ignored 원문을 넣는 git add -f는 사용하지 않습니다.
   과거 코드 목록의 agent6/corpus 빌드 자료 6개는 이번 코드 목록에서 제외했습니다.
2. TRANSFER로 돌아와 commit한 실제 checkout을 검사합니다.
bash ./GENOS_MAIN93_INTERNAL_ANCHOR_20261020_R1/GENOS_MAIN93_INTERNAL_ANCHOR_20261020_R1_RUN.txt gate-code
3. 현재 현장이 명시된 SQLite/NFS generation을 사용하는 경우 같은 세대도 검사합니다.
   GENOS_SERVING_PATHS의 선택 세대가 있으면:
bash ./GENOS_MAIN93_INTERNAL_ANCHOR_20261020_R1/GENOS_MAIN93_INTERNAL_ANCHOR_20261020_R1_RUN.txt gate-sqlite
   설정이 없다면 확인한 실제 generation 경로를 --generation 인자로 지정합니다.
   Oracle 직접 조회 현장은 gate-code 뒤 현장의 기존 Oracle 연결·조회 릴리스 설정을
   유지하고 워크플로우 테스트에서 조회를 확인합니다. 전체 로컬 복원을 요구하지 않습니다.
4. 게이트를 통과한 같은 commit을 push하고 같은 commit의 코드서빙 리비전을 배포합니다.
   데이터 generation 생성·Oracle 채널 변경·push·리비전 배포는 설치기가 실행하지 않습니다.
5. 동봉 GENOS_MAIN93_INTERNAL_ANCHOR_20261020_R1_WORKFLOW_PASTE_ALL.txt 전체를
   워크플로우 Python 단계 편집기에 반영하고 저장합니다. Git push와 별도 단계입니다.
   팀·세션 설정과 기존 인증 정보를 유지합니다.
6. 현장 검증은 워크플로우 테스트 화면의 새 채팅에서만 합니다.
   예: 대사: 유동성비율 관련 외규가 위험관리기준시행세칙에 어떻게 반영되어 있나요?
   내규 원문 → 개념·범위 → 연결 외규 → 대사표의 실제 양쪽 원문을 확인합니다.
   연결이 없는 항목은 조사 또는 미확인으로 남고 외규 부재로 단정하지 않아야 합니다.
   서빙 revision, commit, Python, 데이터/조회 릴리스, 요청 ID와 결과를 보관하세요.
