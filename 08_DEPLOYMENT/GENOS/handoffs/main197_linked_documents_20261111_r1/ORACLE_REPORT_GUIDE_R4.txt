GENOS Oracle 병목 보고 R4 (2026-11-10) — 실제 질문에서 SQL 시간을 쪼개 보기 (사진 5장)

왜 R4인가
  커밋 한 번이 평균 142ms(읽기는 13~17ms)인데, Oracle 쪽 실행 통계(V$SQLSTATS)는 이 계정으로 조회 권한이 없었습니다.
  그래서 DB를 보지 않고 GENOS 쪽에서 SQL 시간을 나눕니다. MAIN186을 적용하면 코드서빙이 실제 질문을 처리하면서
  SQL마다 아래를 함께 남기고, 질문 끝의 요약 줄(oracle.sql.summary)에 합계가 들어갑니다.
    - 보낸 크기(바이트)와 받은 행 수
    - SQL 하나를 보내고 받는 동안 쓴 CPU(요청 스레드 / 프로세스 전체)
    - 보낸 크기 구간별(<4KB, 4~64KB, 64~512KB, 512KB 이상) 횟수·시간 (읽기·쓰기 따로)
    - ORDS 빈 왕복: SQL 300번마다 한 번 SELECT 1 FROM DUAL 을 보내 네트워크+ORDS 기본 비용을 같은 부하에서 잼
      (측정만 함. 실패해도 질문은 그대로 진행. 끄려면 코드서빙 환경변수 GENOS_ORACLE_SQL_PROBE_EVERY=0)
  질문 처리 방식·답변·DB 데이터는 바뀌지 않습니다. SQL 6,000회 질문이면 빈 왕복 약 20회(0.3초 안팎)가 더해집니다.

순서
  1) MAIN186 적용(GUIDE.txt) → 새 코드서빙 리비전 → 평소처럼 느린 질문을 하나 합니다(실제 질문 그대로).
  2) TRANSFER 폴더에서
       bash ./GENOS_ORACLE_REPORT_R4.txt list       번호 확인(사진 불필요)
       bash ./GENOS_ORACLE_REPORT_R4.txt 번호        사진 1/5 ~ 5/5
     한 장이 다 안 보이면: bash ./GENOS_ORACLE_REPORT_R4.txt 번호 --page 5
     요청 보고서 위치가 기본과 다르면 끝에 --root /실제/GENOS_SHARED_LOG_DIR값
  3) 사진 5장을 보내 주세요. (V$SQL Dataiku 사진은 이제 필요 없습니다.)

사진 1~4는 R3와 같고, 사진 1 [A]에 "요청 CPU(프로세스)" 줄이 추가됩니다.
  요청 CPU가 "그 외"에 가까우면 그 외 시간은 대부분 GENOS 쪽 계산, 훨씬 작으면 기다림(계산 아님)입니다.

사진 5 — SQL 시간 쪼개기
  [1] ORDS 빈 왕복: 횟수·평균·최소·최대. SQL 한 번은 최소 이만큼 걸립니다(네트워크+ORDS+연결 처리).
  [2] SQL 도중 CPU: 요청 스레드 CPU(JSON 만들고 읽기) / SQL 시간. 나머지는 기다림(네트워크·ORDS·DB).
      프로세스 전체 CPU가 스레드보다 훨씬 크면 그동안 다른 스레드가 CPU를 쓴 것입니다.
  [3] 보낸 크기별: 읽기·쓰기 × 크기 구간마다 횟수·합계·평균, "빈 왕복 초과" = 평균 - 빈 왕복
      (그 SQL이 빈 왕복보다 더 걸린 시간 = DB 처리 + 큰 본문 전송).
  [4] 위치별 상위 8: 평균, 빈 왕복 초과, 보낸 크기/회, CPU/회, 받은 행/회.
  [5] 판정: 왕복 자체가 SQL 시간의 몇 %인지, 작은 쓰기도 느린지(DB 쓰기·커밋 처리), 큰 쓰기가 얼마나 더 느린지,
      GENOS 쪽 계산 비중.
  이걸로 가르는 것
    - 빈 왕복이 크면(예: 평균 SQL 33ms 중 25ms) → 횟수 줄이기가 답(같은 문장 묶기·잠금 왕복 줄이기)
    - 작은 쓰기도 빈 왕복보다 훨씬 느리면 → DB 쪽 쓰기·커밋 처리(커밋 기록 대기 등)
    - 큰 쓰기만 느리면 → 커밋에 넣는 본문 크기. 다만 큰 쓰기는 대부분 원장 커밋이라 크기 탓인지 커밋 처리 탓인지는
      [4]의 커밋 위치(평균 보낸 크기)와 같이 봅니다.
  못 가르는 것: DB 안에서 읽은 블록 수·실행 계획(DB 권한 필요), "그 외" 시간 중 어느 함수인지(다음 단계).

MAIN186 이전 코드의 보고서도 읽습니다(사진 1~4는 R3와 같고, 사진 5에 "측정 없음"이 나옵니다).
읽기 전용: 이 명령은 코드·DB·설정을 바꾸지 않고 Oracle에 접속하지 않습니다. 질문·답변·원문·SQL 본문·바인드 값은 출력하지 않습니다.

검증(로컬): 실제 로컬 Oracle 원장 + 모의 모델 한 질문(SQL 896회)에서 빈 왕복 2회·크기 구간 3개·위치별 크기/CPU가 남는 것 확인,
  보고서 시험 7개 × Python 3.9 / 3.11 / 3.14 통과(현장 모양 합성 보고서로 사진 5 숫자·한 장 40줄·폭 100칸·질문 미출력 확인).
  현장 ORDS·현장 질문에서의 숫자는 이번 사진이 처음입니다.
