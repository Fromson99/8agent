GENOS 완료 자료 재사용 · 참조 연결/저장 최적화 — 2026-10-03 R1

대상은 기존 ~/DEV이다. ZIP과 같은 이름 TXT를 같은 TRANSFER 폴더에 둔다.
이 반입은 작업 코드에 적용할 구현이다. 현장 구축 시간과 배포 성공은 아직 확인하지 않았다.
이전 compact lifecycle R2 자료는 보존하며 이번 새 run에서 compact-v2를 명시 사용한다.

1. 범위와 준비

재사용: 선택한 완료 구조화 store.sqlite, glossary-draft와 그 knowledge 묶음.
완료 의미 검토 용어집이 별도로 있으면 GENOS_COMPLETED_GLOSSARY에 그 정확한 경로를 지정한다.
선택 자료가 prepared의 파생본인지 확인하며 최근 폴더를 자동 선택하지 않는다.
구조화·용어 정의 생성·의미 검토·참조 모델 검토를 새로 호출하지 않는다.
미해결 참조는 유지한다. 새 문서 추가와 원자료부터의 LLM 처리 시간은 이번 작업 범위 밖이다.

신규 의존성 없음. Python 3.11+, 기존 PeCab/서비스 의존성 사용.
명령은 python3를 사용한다. /venv/bin/python3가 있으면 우선하며 실행기/버전을 로그에 남긴다.
다른 Python 환경이면 GENOS_PYTHON_DIR에 python3가 있는 디렉터리를 명시한다.
72개 반입 파일과 739개 미변경 의존성을 확인한다. 알 수 없는 현장 파일 차이는 중단한다.
허용 기반: 누적 v6 20261002 R4, 이전 SQLite reuse R1, compact lifecycle 20261003 R2의 알려진 바이트.

2. 코드 적용 — 같은 DEV에 백업 후 적용

cd ~/DEV
export GENOS_DEV="$HOME/DEV"
export GENOS_DATA_ROOT=/nfs-root/diamo/8-agent/01_DATA
export GENOS_PREPARED_RUN=financial_risk-success-20261002-index-r8
export GENOS_REUSE_RUN=financial_risk-success-20261003-reference-r1
# 데이터 루트와 prepared run은 실제 완료 자료 위치에 맞게 위 값을 확인/수정한다.
# 별도 완료 검토본을 선택할 때만 설정:
# export GENOS_COMPLETED_GLOSSARY=/정확한/완료/용어집/경로
bash TRANSFER/GENOS_REFERENCE_BUILD_20261003_R1.txt check
bash TRANSFER/GENOS_REFERENCE_BUILD_20261003_R1.txt apply
bash TRANSFER/GENOS_REFERENCE_BUILD_20261003_R1.txt verify

첫 줄부터 지속 로그와 HANDOFF_EXIT를 남긴다. apply가 출력한 backup 경로를 보존한다.
같은 ZIP을 다시 apply하면 이미 설치된 바이트를 확인한다. 실행 중인 같은 구축은 거부한다.
다른 작업을 자동 종료하거나 현장 변경을 일괄 덮어쓰지 않는다.

3. 완료 입력에서 새 구축/재개

bash TRANSFER/GENOS_REFERENCE_BUILD_20261003_R1.txt build

기존 genos_reindex_runner.py build --serving --storage-profile compact-v2
--fulltext-granularity unit 경로를 사용한다. reference scope 설정은 현재 환경을 유지한다.
GENOS_REFERENCE_SCOPE_V2=0/1 두 모드는 로컬 검사했으나 이번 최적화를 이유로 모드를 바꾸지 않는다.
code/input/scope/profile이 같으면 같은 명령으로 재개한다. 변경했으면 새 GENOS_REUSE_RUN을 쓴다.

출력: $GENOS_DATA_ROOT/TERM_RELEASES/$GENOS_REUSE_RUN/serving/
  baseline/generation/                 서빙 원문/용어/참조/단위 FTS
  baseline/audit/source/                변경하지 않은 native 원문 전체
  baseline/audit/navigation/            구축 근거 4개 표 전수
  baseline/checkpoints/                 완료 단계 hash 영수증
  baseline/links/                       문서–용어 연결
  offline-e2e.json, release.json         결속/검색 자산 검사 영수증
실행 중 출력은 baseline 대신 .baseline.building이다.
navigation DB의 navigation_checkpoint에 문서·참조 source·witness·evidence·statistics 완료 경계가 있다.
64개 문서/참조 source 단위로 내구성 commit한다. 블록 내부의 이어진 인용 문맥은 나누지 않는다.
전역 위임/근거 결합은 별도 완료 경계다. 중단된 마지막 chunk는 rollback 후 다시 처리한다.
runtime와 audit DB는 같은 파일시스템의 DELETE journal/FULL sync 연결 트랜잭션을 사용한다.
실제 GENOS NFS 잠금·저널 동작과 현장 강제 종료 복구는 미검증이다.

완료 기준: OFFLINE_READY, offline_e2e=PASS, FINISHED status=0.
live_workflow_e2e=NOT_RUN, quality_certified=false는 현장 모델 검사 전 유지한다.

4. 저장 계약과 기대효과의 범위

term-navigation-index-v7 / storage-v3:
- 별표의 제목 fallback과 선언/등록 약칭은 한 번 만든 역방향 문자 색인으로 검색한다.
  인용마다 문서명 수만큼 순회하지 않는다. 왼쪽 경계·공백·긴 이름·동률 순서를 보존한다.
- 원문 JSON 전체를 리스트/사전으로 쌓지 않는다. 본문 cache는 UTF-8 직렬화 크기 8MiB/64항목,
  초과 단일 본문은 cache에서 제외한다. 실제 Python 메모리에는 객체 오버헤드가 추가된다.
- 참조별 source_text는 reference_body에 hash별 한 번 저장하고 reference view로 복원한다.
  승인 참조의 기존 INSERT/UPDATE/DELETE 경로도 지원한다. ID/span/판정/대상/근거는 유지한다.
- occurrence는 처음부터 정수 키로 저장한다. 감사 표 4개도 처음부터 별도 DB에 기록한다.
  거대한 완성 navigation 전체를 보관하고 다시 서빙 DB로 복사하는 단계가 없다.
- 감사 v3는 논리적 구축 근거 전수 보존 계약이다. 기존 v1/v2의 분리 전 전체 DB snapshot과 다르다.
  새 audit DB와 runtime DB를 함께 보존하며, 기존 세대/스냅샷은 변경하지 않는다.

속도 측정/배수/완료 시간 보장은 없다. 과거 사진의 navigation 9시간16분이 몇 분으로
줄어드는지는 현장 실행 전 알 수 없다. 예전 합성 6초 기록을 전체 구축 시간으로 사용하지 않는다.

5. 공유 발행 · 실제 배포 경로 확인

export GENOS_SHARED_ROOT=/nfs-root/diamo/8-agent/term-releases
bash TRANSFER/GENOS_REFERENCE_BUILD_20261003_R1.txt publish

새 경로에 복사·hash 확인 후 발행한다. 기존 CURRENT/서빙 리비전을 자동 전환하지 않는다.
배포할 ~/DEV의 변경 파일과 diff를 검토하고 Git commit한 뒤 다음을 실행한다.

bash TRANSFER/GENOS_REFERENCE_BUILD_20261003_R1.txt gate

정확한 다른 generation을 검사할 때는 gate 뒤에 그 절대경로를 명시한다.
게이트는 ZIP bytes/미변경 의존성/Git 추적 코드와 선택 generation의 오프라인 E2E를 결속한다.
통과한 commit을 push하고, 그 commit과 검사한 generation을 선택한 새 코드서빙 리비전을 배포한다.
코드 적용, generation 생성, push, 리비전 배포, 워크플로우 반영은 각각 별도 상태다.
워크플로우 Python 단계 변경은 편집기에 별도로 반영해야 한다.
warmup과 실제 질문은 워크플로우 테스트 화면에서 실행한다. 요청 ID와 근거/실패 상태를 남긴다.
코드서빙 직접 테스트 UI/API 검증은 요구하지 않는다.

6. 원복

bash TRANSFER/GENOS_REFERENCE_BUILD_20261003_R1.txt rollback /apply가/출력한/정확한/backup

패키지 적용 후 별도로 바뀐 파일은 무조건 덮어쓰지 않는다.
배포까지 했다면 이전 코드 리비전과 이전 검증된 generation 쌍으로 복귀한다.
새 generation/audit/로그는 원인 확인을 위해 보존한다. 기존 원문·용어집을 삭제하지 않는다.
