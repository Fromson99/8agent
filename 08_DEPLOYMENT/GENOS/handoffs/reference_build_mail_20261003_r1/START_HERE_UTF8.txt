기존 compact lifecycle R2 대신 새 compact-v2 구축 코드가 들어 있습니다.
원본 코드 ZIP의 검증 바이트는 변경하지 않았습니다.

1) 준비
ZIP을 ~/DEV/TRANSFER/reference-e2e-r1 같은 폴더에 해제합니다.
그 폴더에는 코드 ZIP, 실행 TXT 2개, 상세 안내와 검증 기록이 함께 있습니다.
내부의 코드 ZIP을 ~/DEV에 수동 덮어쓰지 마세요. 실행 TXT가 백업 후 적용합니다.
실제 GENOS 실행은 python3를 사용합니다. 필요하면 GENOS_PYTHON_DIR로 설치 환경을 지정합니다.
실행은 이 안내의 경로를 따릅니다. 상세 원본 안내에서 TRANSFER/로 시작하는 예시를
사용할 때는 압축을 푼 실제 폴더 TRANSFER/reference-e2e-r1/로 바꿉니다.

2) 반드시 확인할 값
GENOS_DATA_ROOT: 완료 자료가 있는 데이터 루트의 실제 절대경로
GENOS_PREPARED_RUN: 재사용할 완료 prepared run ID
GENOS_REUSE_RUN: 이번 새 출력 run ID. 코드/입력/설정을 바꾸면 다른 ID를 사용합니다.
GENOS_COMPLETED_GLOSSARY: 별도 완료 의미 검토 용어집을 선택할 때만 정확한 경로 지정

3) 실행 예시 — 앞의 데이터 위치와 완료 run ID를 현장 값으로 맞춘 뒤 실행

cd ~/DEV/TRANSFER/reference-e2e-r1
export GENOS_DEV="$HOME/DEV"
export GENOS_DATA_ROOT=/nfs-root/diamo/8-agent/01_DATA
export GENOS_PREPARED_RUN=financial_risk-success-20261002-index-r8
export GENOS_REUSE_RUN=financial_risk-success-20261003-reference-r1
bash GENOS_REFERENCE_E2E_RUN_20261003_R1.txt

이 명령은 파일/코드 검사 → DEV 백업·적용 → 완료 자료 재사용 구축 → 단위 FTS →
서빙 자산/원문/참조 결속의 오프라인 E2E 순서로 진행합니다. 실패 즉시 중단하고 로그를 보존합니다.
같은 코드/자료/설정으로 다시 실행하면 완료 단계를 검증하고 재개합니다.
완료 표시는 OFFLINE_E2E=PASS와 E2E_LAUNCH_EXIT=0이며 정확한 generation 경로와 해시를 출력합니다.
RAW 구조화·용어집 생성·모델 검토를 처음부터 다시 실행하지 않습니다.

4) 공유 경로 발행과 실제 배포 게이트

실제 배포할 ~/DEV에서 변경을 검토·Git commit한 뒤:
bash GENOS_REFERENCE_E2E_RUN_20261003_R1.txt gate

게이트 통과 commit을 push하고 같은 generation을 선택한 새 코드서빙 리비전을 배포합니다.
이 스크립트가 CURRENT, Git push, 코드서빙 리비전, 워크플로우 편집기를 자동 변경하지는 않습니다.

5) 모델을 포함하는 마지막 E2E — 워크플로우 테스트 화면
- 새 코드 리비전과 위에서 출력한 generation이 연결되어 있는지 확인합니다.
- 기존 warmup 요청을 워크플로우 테스트 화면에서 실행합니다.
- 선택한 내부 문서의 알려진 조문 질문 1개를 실행하고 원문/인용/참조 대상 표시를 확인합니다.
- 별표 참조가 있는 질문 1개와 후속 질문을 실행하고 문서 범위 및 근거가 유지되는지 확인합니다.
- 요청 ID, 코드 리비전, generation 경로/manifest 해시, 성공 또는 실패 상태를 보존합니다.
코드서빙 직접 테스트 UI/API 실행은 필요하지 않습니다.
워크플로우의 Python 단계 변경이 필요하면 편집기에 별도로 반영합니다.
