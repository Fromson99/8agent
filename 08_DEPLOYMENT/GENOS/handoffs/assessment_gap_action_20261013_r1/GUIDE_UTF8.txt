GENOS 판단 단계 원문 부족과 사실 요청 충돌 수정 R1

수정 내용
사진에 확인된 오류는 "A legal source gap requires source research, not REQUEST_FACT."입니다.
원문 부족이라는 판단과 사용자 사실 질문이라는 행동의 충돌입니다.
v5~v8의 판단 준비에서 schema-valid 원문 gap에 잘못 붙은 REQUEST_FACT만 RESEARCH로
바꿉니다. 부족 종류/대상/사유, 원래 제안, 원문/사실/권한 검증은 보존합니다.
기존 조사 한도 안에서 SELECT로 복귀하며, 한도가 없으면 검증된 주장만 제한 답변에 씁니다.
검증된 주장이 없거나 다른 근거/스키마/무결성 오류가 있으면 계속 중단합니다.
두 번째 거절 원문의 세부 사항은 사진에서 확인되지 않았으므로 모든 422의 해결을 보장하지 않습니다.

대상
MODEL_STREAM_FIX R1이 적용된 기존 ~/DEV, 또는 그 위에 AD_REQUEST_LOGS R2가 적용된 ~/DEV.
검증된 조사 예산 설정 패치의 유무와 기존 캐시 변형을 보존합니다.
원문 재구축, DB 이행, 워크플로우 Python 편집기 교체는 없습니다.
알려진 전체 코드 inventory와 맞지 않으면 기존 파일을 보존하고 설치를 거부합니다.
코드 핀만 다시 계산해 미확인 현장 수정을 강제로 통과시키지 마세요.

1. 설치
독립 RUN.txt 한 개를 ~/DEV/TRANSFER에 반입해도 됩니다. ZIP과 RUN은 같은 수정입니다.

bash ~/DEV/TRANSFER/GENOS_ASSESSMENT_GAP_ACTION_20261013_R1_RUN.txt check
bash ~/DEV/TRANSFER/GENOS_ASSESSMENT_GAP_ACTION_20261013_R1_RUN.txt apply

또는 ZIP을 ~/TRANSFER에 놓았다면:
python3 -m zipfile -e ~/TRANSFER/GENOS_ASSESSMENT_GAP_ACTION_20261013_R1.zip ~/DEV/TRANSFER/assessment-gap-action-r1-package
bash ~/DEV/TRANSFER/assessment-gap-action-r1-package/GENOS_ASSESSMENT_GAP_ACTION_20261013_R1_RUN.txt check
bash ~/DEV/TRANSFER/assessment-gap-action-r1-package/GENOS_ASSESSMENT_GAP_ACTION_20261013_R1_RUN.txt apply

첫 단계부터 로그를 남기며 실제 Python/checkout 경로와 EXIT를 출력합니다.
CHECK PASS, CODE_APPLIED, EXIT=0 및 출력된 BACKUP/APPLIED_CODE_ZIP 경로를 확인하세요.
재실행은 해시 검사 후 ALREADY_APPLIED로 종료합니다.

2. 같은 checkout의 검토, commit, generation 게이트
cd ~/DEV
git diff --check
git status --short

BACKUP/receipt.json에 기록된 수정 파일을 검토하고 같은 checkout에 commit합니다.
다른 작업까지 git add .로 포함하지 마세요.
아래 두 값은 실제 apply 출력과 현재 선택 generation 절대경로로 바꿉니다.

TASK_GAP_BACKUP='/실제/apply/출력의/backup-경로'
TASK_GAP_GENERATION='/현재/선택된/generation/절대경로'
bash ~/DEV/TRANSFER/GENOS_ASSESSMENT_GAP_ACTION_20261013_R1_RUN.txt gate "$TASK_GAP_BACKUP" --generation "$TASK_GAP_GENERATION"

ZIP을 풀어 실행했다면 RUN 경로를 해당 package 폴더로 바꿉니다.
게이트는 실제 적용 코드 ZIP, 같은 committed checkout, 선택 generation을 결속합니다.
통과한 commit을 기존 팀별 remote로 push하고 그 commit의 코드서빙 새 리비전을 배포합니다.
별도 SSE 서버도 같은 코드로 재시작해야 합니다.

3. 현장 검증
기존 워크플로우 테스트 화면에서 실패했던 요청을 새 요청으로 실행합니다.
판단 결과의 model_proposal.gap_action_corrections에 REQUEST_FACT -> RESEARCH가
기록되는지, ASSESSMENT_GAP_REENTRY_PLANNED 또는 제한 답변/근거 부족 종료를 확인합니다.
답변의 근거/미확인 범위, 실제 선택 commit/generation/리비전과 request_id를 함께 보관합니다.
동일 문구가 사라진 것만으로 질문 전체의 정확성이나 성공을 확정하지 않습니다.
GENOS 직접 코드서빙 테스트 UI/API는 요구하지 않습니다.

4. 원복
bash ~/DEV/TRANSFER/GENOS_ASSESSMENT_GAP_ACTION_20261013_R1_RUN.txt undo "$TASK_GAP_BACKUP"

적용 뒤 다른 코드 변경이 있으면 원복을 거부하고 보존합니다.
원복한 commit/이전 리비전과 SSE 서버도 별도로 복귀하세요. 원문/로그/저널은 삭제하지 않습니다.
