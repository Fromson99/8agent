MAIN201 — LOG=on 이면 .log 와 CPU·Oracle 보고서 자료를 함께 저장 (MAIN200 대체)
MAIN199(ORA-40478 수정)·MAIN200(LOG=on .log) 내용을 그대로 포함한 전체 코드입니다. 이 MAIN201만 적용하면 됩니다.
워크플로우 파일은 그대로입니다.

0. 무엇이 바뀌었나
  코드서빙 환경변수에 LOG=on 을 넣으면 질문마다 아래 3개 파일이 생깁니다(같은 이름):
    /nfs-root/diamo/8-agent/rag-request-reports/<날짜>/<팀>/legal_agent/<요청ID>-<번호>.log    ← 읽는 로그
    /nfs-root/diamo/8-agent/rag-request-reports/<날짜>/<팀>/legal_agent/<요청ID>-<번호>.json   ← 보고서 자료
    /nfs-root/diamo/8-agent/rag-request-reports/<날짜>/<팀>/legal_agent/_qa/<요청ID>-<번호>.row ← 보고서 목록
  그래서 LOG=on 상태에서 GENOS_CPU_REPORT_R2 / GENOS_ORACLE_REPORT_R4 를 그대로 돌릴 수 있습니다.
  (.txt·.trace.txt·.llm_raw.jsonl 은 계속 안 만듭니다. LOG 를 빼면 MAIN200과 같습니다.)
  경로를 바꾸려면 GENOS_SHARED_LOG_DIR 에 절대경로(그 경로엔 Oracle 원본 보관 agent-raw-v1 도 기존처럼 생김).

1. 적용 (TRANSFER 폴더에서, ZIP은 미리 풀지 않음)
  bash MAIN201_ONECLICK_R1.txt  → 완료 표시 MAIN201_ONECLICK_DONE, MAIN201_EXIT=0
  확인·스테이징: bash MAIN201_ONECLICK_R1.txt status / stage, git -C ~/DEV diff --cached --stat / --check
  기존 절차대로 commit 후: bash MAIN201_ONECLICK_R1.txt gate-code → push → 새 코드서빙 리비전
  코드서빙 환경변수 LOG=on (나머지 그대로). 시작 명령: python3 08_DEPLOYMENT/GENOS/start_sse.py

2. 보고서 보기 (질문 몇 개 보낸 뒤, 보고서 TXT를 둔 폴더에서)
  bash ./GENOS_CPU_REPORT_R2.txt list     → bash ./GENOS_CPU_REPORT_R2.txt <번호>     (사진 3장)
  bash ./GENOS_ORACLE_REPORT_R4.txt list  → bash ./GENOS_ORACLE_REPORT_R4.txt <번호>  (사진 5장), 합산은 sum
  로그: 위 날짜 폴더의 같은 이름 .log
  .log 가 안 생기면 코드서빙 로그의 shared_live.failed error_type 을 알려 주세요(답변은 정상으로 나갑니다).

3. 원복: bash MAIN201_ONECLICK_R1.txt undo --backup '출력된 백업 폴더 절대경로'
