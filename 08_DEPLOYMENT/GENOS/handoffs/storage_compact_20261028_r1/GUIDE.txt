GENOS RAG 기록 중복 방지 — 2026-10-28

현재 상태
- 마지막 전달 MAIN112(vector-initial-20261028-r1)에 저장 변경만 적용한 반입 후보입니다.
- 작업 코드 수정·로컬 모의 API 검증·반입 파일 해시 검증 완료. 현장 배포는 하지 않았습니다.
- 선택 MAIN112, 원문/색인 데이터, 모델, 출력 토큰 상한 없음, 호출·도구·시간 예산은 유지합니다.
- ZIP에는 코드만 있습니다. DB·원문 데이터 복사본과 자격증명은 없습니다.

바뀌는 동작
1. 요청 저널/사건 DB 안의 긴 본문을 SHA256 참조와 무손실 압축으로 저장합니다.
   원문, 모델 화면·요청·응답, 판단 버전, 관측, 발행 결과, 사건 결과의 반복 문자열을 공유합니다.
   모델 messages.content 안에 JSON으로 다시 들어간 원문도 분해해 공유합니다(최대 4단계).
   서로 다른 요청 DB 사이까지 합치는 전역 캐시나 Oracle 전체 다운로드는 만들지 않았습니다.
2. 판정·오류·실패·중단·미완료·원문 좌표·권한 결속과 기존 내용 해시는 보존합니다.
   읽을 때 압축을 풀고 SHA256을 검사합니다. 누락·변조는 오류이며 새 본문으로 대체하지 않습니다.
   실패 로그의 error_diagnostics는 온전히 남기되 같은 내용을 또 담던 error_record 문자열은 제거합니다.
3. 기존 평문 기록을 자동 재작성하거나 삭제하지 않습니다. 평문과 압축 기록을 함께 읽습니다.
   원문 조회, 재사용, 재시작 복구, 진행 화면, 오류 보고서, 운영자 trace를 같은 읽기에 연결했습니다.
4. GENOS_RUNTIME_DIR와 별도 GENOS_STATE_DIR를 합산해 저장 한도를 확인합니다.
   한도에 가까우면 모델을 부르기 전에 HTTP503/STORAGE_CAPACITY로 새 실행을 거절합니다.
   실행 중에도 추가 모델/도구 호출 전 최대 5초 간격으로 용량을 재확인합니다.
   조회·복구·이미 받은 응답·실패 기록 저장을 막거나 오래된 실패를 지우지는 않습니다.

기본 설정(바이트 단위 환산 기준 MiB/GiB)
GENOS_JOURNAL_STORAGE=compact
GENOS_RUNTIME_LIMIT_MIB=20480       # runtime + 별도 state 합계 20GiB
GENOS_RUNTIME_RESERVE_MIB=1024      # 새 요청마다 진행 중 예약 여유 1GiB
GENOS_RUNTIME_MIN_FREE_MIB=2048     # 파일시스템 최소 여유 2GiB

GENOS_RUNTIME_DIR가 설정된 GENOS에서는 compact가 기본입니다.
설정 변경 후 모든 해당 서빙 프로세스를 재시작합니다.
20GiB는 새 작업 진입/추가 실행을 제한하는 운영 한도입니다. 이미 수신한 응답·실패를 보존하므로
파일시스템 강제 quota처럼 정확히 20GiB에서 쓰기를 끊지는 않습니다. 실행 중 기록, 동시 다른
프로그램의 쓰기, SQL 임시 파일 때문에 일시 초과할 수 있습니다. GENOS/Dataiku 플랫폼 자체의
stdout 보관과 별도 공유 로그 폴더의 보관 정책은 이 한도의 대상이 아닙니다.
한도를 풀고 계속 누적하기보다 Dataiku가 소유하는 외부 보관/용량을 확인해야 합니다.
자동 S3 이관·보관 확인 뒤 삭제·무기한 보관 보장은 이번에 추가하지 않았습니다.

반입 절차
1. ZIP을 코드 저장소 밖의 임시 폴더에 압축 해제합니다.
2. 같은 runtime/state를 사용하는 서빙·관리 프로세스의 진행 작업을 마무리하고 정지합니다.
   기존 버전과 새 버전이 같은 압축 기록을 동시에 읽는 혼합 배포를 하지 않습니다.
3. 아래 실제 checkout 경로를 지정해 먼저 검사합니다(검사만으로 파일을 바꾸지 않습니다).

python3 apply_storage_patch.py --root /실제/GENOS/코드저장소

4. VERIFIED 뒤 적용합니다.

python3 apply_storage_patch.py --root /실제/GENOS/코드저장소 --apply

- 마지막 MAIN112 전달본 또는 이 패치와 일치해야 합니다. 다른 변경이 있으면 덮어쓰지 않고 거절합니다.
- 기존 UI app.js는 원래 해시를 확인하고 보존합니다. 데이터/환경파일을 복사하지 않습니다.
- 460개 서빙 파일을 검증하며, 바뀐 코드·pin 60개만 반영합니다.
- 기존 코드 백업/영수증은 checkout/.genos-storage-code-backups/에 둡니다. DB 백업이 아닙니다.
- CODE_APPLIED는 로컬 checkout 반영이며 GENOS 리비전 배포 완료가 아닙니다.
5. 기존 조직 배포 절차로 이 코드가 실제 서빙 리비전에 포함되도록 반영한 뒤 재시작합니다.
   현장에서는 정상 요청/인용/재시작 조회와 NFS/CIFS의 파일 잠금·fsync를 별도로 확인합니다.
   기본 한도보다 기존 runtime/state가 크면 새 요청이 제한됩니다. 배포 전 실제 사용량을 확인하세요.

운영/롤백
- 기록을 조사할 때 새 API/보고서 또는 다음 공통 리더를 사용합니다.
  PYTHONPATH=02_BACKEND python3 06_TOOLS/COMMANDS/legal_agent_trace.py --runtime-root /기존/runtime --run-id 실제실행ID
- Python에서 SQLite를 직접 읽어야 하면 semantic_runtime.legal_agent.journal_storage.connect를 사용합니다.
  압축된 필드를 기존 sqlite3.connect로 읽으면 실제 본문 대신 BLOB 참조가 나옵니다.
- 새 압축 쓰기만 중단하려면 GENOS_JOURNAL_STORAGE=plain으로 설정하고 재시작합니다.
  새 코드는 기존 압축 기록을 계속 읽습니다. 보관 한도는 GENOS에서는 계속 적용됩니다.
- 압축 기록 생성 후 예전 reader 없는 코드만 되돌리지 않습니다. 이 경우 새 리더를 유지하거나,
  별도 검증된 평문 이행이 필요합니다. 본문을 버려 이전 코드에 맞추지 않습니다.
- 이번 패치는 기존 외부 NFS 상태 저장 경로를 유지합니다. Dataiku 관리 책임을 GENOS의 새
  영속 작업 관리 시스템으로 옮긴 것이 아니며, 현장 S3/Oracle 저장 배선 완료 주장도 아닙니다.
