GENOS RAG 패치 R3 — SELECT unit_keys 인자 불일치 정정 / 2026-10-13

1. 이번 R3는 R1·R2가 적용된 기존 ~/DEV에 이어 적용합니다
GENOS_RAG_FOCUSED_RULES_20261013_R3.zip
GENOS_RAG_FOCUSED_RULES_20261013_R3_RUN.txt (ZIP 없이도 독립 실행 가능)
사진의 오류: UnitFulltextIndex.article_groups_page() got an unexpected keyword argument 'unit_keys'
law_navigation.article_menu에서 조문 후보를 조회하다 SELECT 단계가 중단되고 HTTP 500이 발생했습니다.
R1에서 범위 제한 검색 호출을 옮기면서 unit_fulltext.py의 대응 구현을 누락한 인계 결함입니다.
R2는 초기화 검증 파일만 정정했으므로 이번 누락이 남았습니다.
R3는 알려진 R2 결과 330종과 전체 코드/해시를 대조한 뒤 해당 캐시 계열의 수정본을 적용합니다.
R2 미적용 상태라면 기존 R2를 먼저 적용합니다. R3를 R1 단독 상태에 억지로 적용하지 않습니다.

2. 변경 범위
unit_fulltext.py의 페이지 조회 3종과 공통 범위/커서 결속만 MAIN53 구현에 맞춥니다.
unit_keys를 SQL 필터로 적용하고 다른 범위의 커서를 거부합니다. 빈 범위는 빈 결과입니다.
선택 범위가 있으면 전체 범위용 검색 결과 캐시를 재사용하지 않고 범위에 맞춰 조회합니다.
기존 캐시 연결/프로세스 캐시/본문 캐시 함수와 설정은 해당 설치 계열 그대로 보존합니다.
그 파일의 엔진 연결 해시, PIPELINE, CODE_MANIFEST를 함께 갱신합니다.
R1·R2, CM, 서비스 예산, 모델/인증/전송, 원문 generation, CURRENT, DB, 워크플로우는 유지합니다.
원문 재구축이나 워크플로우 Python 편집기 교체는 필요하지 않습니다.

3. 적용 — 기존 ~/DEV에서 실행
첨부 RUN.txt를 ~/DEV/TRANSFER에 올린 후 아래 명령 전체를 실행합니다.

bash ~/DEV/TRANSFER/GENOS_RAG_FOCUSED_RULES_20261013_R3_RUN.txt

기본 동작은 백업 → 코드 적용 → 설정 및 실제 조문 조회의 모의 계약 검증입니다. python3 경로/버전을 로그에 남깁니다.
별도 checkout은 GENOS_DEV_ROOT=/실제/DEV로 지정합니다. 새 후보 폴더에만 적용하지 않습니다.
별도 Python 위치는 GENOS_PYTHON_DIR에 현장 python3가 있는 폴더를 지정합니다.
ZIP으로 실행할 경우:

python3 -m zipfile -e ~/DEV/TRANSFER/GENOS_RAG_FOCUSED_RULES_20261013_R3.zip ~/DEV/TRANSFER/rag-focused-rules-r3-delivery
cd ~/DEV/TRANSFER/rag-focused-rules-r3-delivery
sha256sum -c PACKAGE_SHA256SUMS.txt
bash GENOS_RAG_FOCUSED_RULES_20261013_R3_RUN.txt

이하 예시는 독립 RUN.txt가 ~/DEV/TRANSFER에 있는 경우입니다.
ZIP으로만 반입했다면 위에서 추출한 RUN.txt의 절대경로로 바꿔 실행합니다.
읽기 전용 사전 검사 / 적용 후 검사:
bash ~/DEV/TRANSFER/GENOS_RAG_FOCUSED_RULES_20261013_R3_RUN.txt check
bash ~/DEV/TRANSFER/GENOS_RAG_FOCUSED_RULES_20261013_R3_RUN.txt verify

확인할 출력: R3_REAL_ARTICLE_MENU PASS / R3_SCOPED_FULLTEXT_CONTRACT PASS / FOCUSED_RAG_ALL_PROFILES PASS
BACKUP=... / APPLIED_CODE_ZIP=... / CODE_ZIP_SHA256=... / CODE_APPLIED
재실행은 ALREADY_APPLIED로 검증합니다. 최초 실행부터 FOCUSED_RAG_LOG 경로에 로그와 .exit를 남깁니다.
BACKUP 절대경로와 출력 로그를 보존합니다. apply PASS는 현장 서비스 부팅 성공과 별도입니다.

4. 같은 checkout에서 commit → gate → push → 새 리비전
다음 두 값은 현장에서 실제 값으로 바꿉니다.
TASK_BACKUP: R3 apply가 출력한 BACKUP 절대경로 (R1·R2 백업과 구분).
GENOS_GENERATION: 현재 서비스가 선택한 기존 generation 절대경로.
GENOS_SERVING_PATHS.json의 선택 경로/manifest SHA가 있으면 함께 대조합니다.

export TASK_BACKUP='/이번_R3_apply가_출력한_BACKUP_절대경로'
export GENOS_GENERATION='/현재_서비스가_선택한_generation_절대경로'
cd ~/DEV
python3 - "$TASK_BACKUP/receipt.json" <<'COMMIT_PY'
import json,subprocess,sys
receipt=json.load(open(sys.argv[1],encoding='utf-8'))
paths=[row['path'] for row in receipt['files']]
subprocess.run(['git','diff','--check','--',*paths],check=True)
subprocess.run(['git','diff','--stat','--',*paths],check=True)
subprocess.run(['git','add','-f','--',*paths],check=True)
subprocess.run(['git','commit','--only','-m','Fix GENOS scoped unit fulltext integration with R3','--',*paths],check=True)
COMMIT_PY
bash ~/DEV/TRANSFER/GENOS_RAG_FOCUSED_RULES_20261013_R3_RUN.txt gate "$TASK_BACKUP" --generation "$GENOS_GENERATION" && git rev-parse HEAD && git push

순서대로 실행하고 실패하면 다음 단계로 진행하지 않습니다.
R1·R2 변경도 committed 상태여야 전체 installed-code gate가 통과합니다.
gate는 이번 DEV에서 생성한 APPLIED_CODE.zip과 같은 committed checkout을 대조하고
선택 generation의 E2E/verify_assets를 확인합니다. 원문/manifest hash를 임의로 갱신하지 않습니다.
gate 후 코드가 바뀌면 다시 commit/gate합니다. PASS 후 push한 동일 commit과 기존 generation으로
플랫폼에서 새 코드서빙 리비전을 배포합니다. 별도 SSE 서버도 기존 시작 설정으로 재시작합니다.
Git push만으로 실행 중인 코드서빙 리비전이 갱신되었다고 보지 않습니다.

6. 실패·재개·원복
apply 실패 시 로그와 BACKUP을 보존합니다. 알려진 원본/패치 바이트의 부분 적용만 원복합니다.
bash ~/DEV/TRANSFER/GENOS_RAG_FOCUSED_RULES_20261013_R3_RUN.txt undo "$TASK_BACKUP"
R3 undo는 R2 코드로 돌아가므로 이번 SELECT 결함도 다시 생깁니다.
정상 동작하던 R1 이전으로 복구해야 한다면 각 패치의 원래 백업으로 R3 → R2 → R1 순서로
원복하고 이전 검증 리비전과 generation으로 복귀합니다. 기존 실패/적용 기록은 보존합니다.
Git에 반영한 뒤 원복했다면 원복 commit/gate/push와 서버 리비전 복귀도 별도 수행합니다.
코드/백업이 알 수 없는 바이트로 바뀌었으면 덮어쓰지 않고 멈춥니다.
데이터·DB·캐시·기존 로그·백업은 삭제하지 않습니다.
