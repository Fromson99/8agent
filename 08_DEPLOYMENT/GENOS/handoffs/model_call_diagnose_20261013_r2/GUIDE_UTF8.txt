GENOS 모델 스트림 종료 진단 R2 / 2026-10-13

목적
COMPOSE / model stream ended before completion 오류의 기존 요청 JSON을 읽습니다.
RAW 로그 화면에서 빠진 stream_events의 개수·종료 사유·내용 길이를 요약합니다.
질문·원문·프롬프트·답변·수신 이벤트 본문은 출력하지 않습니다.
모델 호출, 코드 설치, 서비스 재시작, 배포, 원문 재구축은 없습니다.
단독 RUN.txt만 반입하면 됩니다. 기존 R1을 먼저 실행할 필요가 없습니다.

실행
RUN.txt를 ~/DEV/TRANSFER에 놓고, 아래 JSON 경로를 실패 요청의 실제 파일로 바꿉니다.

bash ~/DEV/TRANSFER/GENOS_MODEL_STREAM_DIAG_20261013_R2_RUN.txt "/실제/요청보고서.json"

기존 현장 설정의 요청보고서 폴더:
/nfs-root/diamo/8-agent/rag-request-reports/2026-10-13/financial_team/
GENOS_SHARED_LOG_DIR 설정이 다르면 실제 설정 경로를 사용합니다.
사진의 실패 요청과 request_id/run_id가 같은 파일을 선택합니다.
.log/.txt/.llm_raw.jsonl이 아니라 전체 요청 .json이 입력입니다.
같은 위치에 .stream_diag.txt를 새로 만들고 마지막 24줄을 화면에 보여 줍니다.
원본 JSON은 읽기만 하고 출력 파일이 이미 있으면 덮어쓰지 않습니다.

다른 출력 위치나 재실행:
bash ~/DEV/TRANSFER/GENOS_MODEL_STREAM_DIAG_20261013_R2_RUN.txt "/실제/요청보고서.json" "$PWD/stream_diag_02.txt"

확인할 값
sse_events: 저장된 파싱 완료 이벤트 수. unknown과 0은 다릅니다.
finish_reason_counts: 저장 이벤트에 있는 stop/length/tool_calls/content_filter 등의 수.
content_chars/content_json: 수신 content 문자열의 길이와 JSON 파싱 가능 여부.
tool_argument_chars/tool_arguments_json: 도구 인자 채널의 길이와 JSON 파싱 가능 여부.
stream_completion_tokens: 스트림이 제공한 출력 토큰 수. 미기록이면 unknown.
message_chars: delta 대신 message 채널을 보낸 경우의 길이.
model_mismatches: 요청 모델과 다른 model 값을 담은 이벤트 수.

판정 한계
기존 전송 코드는 [DONE] 수신 여부와 미완성 마지막 프레임을 따로 저장하지 않습니다.
따라서 done_marker=unknown이 정상 출력이며 [DONE] 미수신으로 단정하지 않습니다.
stream_complete=False는 실패 표시이며 어떤 종료 표식이 누락됐는지 알려 주지 않습니다.
content_json=parsed는 JSON 구문 확인일 뿐 최종 답변·스키마·근거 검증 성공이 아닙니다.
finish_reason=stop이어도 최종 종료 표식/마지막 구분 줄의 실제 수신은 별도 확인 대상입니다.
response_bytes는 줄 단위 수신 계측값이며 답변 분량이나 정확한 네트워크 바이트 수가 아닙니다.
body/model/http_status=null은 이 실패 경로에서 비워 저장하는 값일 수 있습니다.
UNASSESSED_AT_STOP은 실패 후 정리 기록이며 그것만으로 실패 원인으로 보지 않습니다.

요약 TXT의 실패한 memory-compose 호출 블록만 확인하면 됩니다.
원본 요청 JSON과 모델 원문을 외부로 보낼 필요는 없습니다.
실제 GENOS 원인은 현장 요약 결과 확인 전까지 미확인입니다.
