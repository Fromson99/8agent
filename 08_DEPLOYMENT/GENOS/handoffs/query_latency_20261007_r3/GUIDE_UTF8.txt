GENOS 검색 준비 최적화·세부 계측 — 2026-10-07 R3

사용할 파일: GENOS_QUERY_LATENCY_20261007_R3.zip / _APPLY.txt
직전 발송 GENOS_NO_SOCKET_CHAT_20261007_R3를 포함한 300파일 누적본입니다.
이전 코드 ZIP을 순서대로 적용할 필요 없습니다. 이번 계측 R1/R2는 미발송 준비본입니다.
최신 session-runtime MAIN45를 결속한 R3만 사용하세요. 기존 code/data/hash 차이를 rehash로 덮지 않습니다.

1. 이번 변경
- 권한 범위 조회: 전체 원문 JSON을 로딩하던 방식을 source ID 단일 SQL 조회로 변경.
- 같은 요청·SQLite 연결·색인 해시·검색식·ACL의 FTS 적중 메타데이터를 한 번 계산해 재사용.
  본문은 실제 표시할 key로 조회. 다른 사용자/질문과 캐시를 공유하지 않습니다.
  메타데이터 50,000개 초과 시 기존 전체 SQL 검색으로 복귀. 검색 결과를 자르지 않습니다.
- INFO 상세 계측: RECALL 토큰화/범위/구조 해석, SQL execute/fetch, JSON 해석,
  SELECT 초기화/후보 메뉴/화면 구성, 원문 검증/읽기, checkpoint, 모델 입력 기록,
  요청 구성/인코딩/예약/transport, 출력 검증/기록.
- 기존 프로필 내용과 어긋나 있던 기본 v6 프로필 pin을 실제 해시로 결속했습니다.
  프로필 내용·검색 정책은 바꾸지 않았습니다.

2. 적용 위치와 선택 generation
ZIP과 첨부 TXT를 GENOS의 ~/DEV/TRANSFER에 같은 디렉터리로 놓습니다.
기존 Git checkout ~/DEV에 백업 후 적용하며 별도 후보 폴더에만 설치하지 않습니다.
Python 단계의 추가 패키지는 없고 현장 python3(3.11 이상)를 사용합니다.

cd ~/DEV/TRANSFER
export GENOS_DEV="$HOME/DEV"

# 아래 값은 10월 6일 인계 기록에 있던 generation입니다.
# 실제 코드서빙이 다른 generation을 선택했다면 그 절대경로로 바꾸세요.
# 이미 설정된 GENOS_GENERATION을 덮지 않습니다.
export GENOS_GENERATION="${GENOS_GENERATION:-/nfs-root/diamo/8-agent/term-releases/financial-risk-success-20261005-schema-r2/generation}"

bash GENOS_QUERY_LATENCY_20261007_R3_APPLY.txt check "$GENOS_GENERATION"
bash GENOS_QUERY_LATENCY_20261007_R3_APPLY.txt apply "$GENOS_GENERATION"
bash GENOS_QUERY_LATENCY_20261007_R3_APPLY.txt verify "$GENOS_GENERATION"

각 명령은 실패 즉시 중단합니다. check가 실패하면 apply하지 마세요.
CHECKOUT_PREFLIGHT의 파일명/해시를 확인하며 현장 변경과 기존 데이터는 보존됩니다.
verify의 SERVICE_LOADER / QUERY_LATENCY_CONTRACT / GENERATION_E2E / ASSETS
검사가 같은 checkout과 선택 generation을 검증합니다. 대형 NFS 파일 검증은 시간이 걸립니다.
실행 로그와 events.jsonl은 첨부 위치의 query-latency-r2-logs에 지속 기록됩니다.

3. Git push와 코드서빙
기존 origin에 push할 때:
bash GENOS_QUERY_LATENCY_20261007_R3_APPLY.txt push "$GENOS_GENERATION"

새 원격을 사용하던 경우 _PUSH_NEW_REMOTE.txt의 GENOS_NEW_REMOTE_URL에
실제 저장소 URL을 지정하고 실행합니다. 기존 원격을 다른 URL로 덮지 않습니다.
push 모드는 이번 ZIP 범위만 commit하고 같은 checkout/generation release gate를
통과한 뒤 push합니다. 실제 commit과 generation manifest SHA가 로그에 남습니다.

GENOS에서 그 commit으로 새 코드서빙 리비전을 배포하세요.
main_router:app / python3 main_router.py와 기존 GENOS_MAIN_MODE를 유지합니다.
workflow = 별도 Python 단계 + /stream SSE, integrated = 같은 프로세스 /chat JSON.
R3의 Socket.IO 제거 상태를 포함합니다. 플랫폼 Socket.IO 옵션은 두 모드 모두 꺼야 합니다.
코드 ZIP 적용과 push만으로 실행 중인 리비전이 바뀌지는 않습니다.
실제 배포 리비전/commit/GENOS_GENERATION 설정을 함께 확인하세요.

분리 workflow 사용 시 Python 편집기 반영은 ZIP/push와 별개입니다.
이번에는 MAIN45의 세션 런타임 변경도 포함합니다. 분리 workflow를 사용하면
기존 no-socket R3 단계에서도 첨부 _WORKFLOW_PASTE_ALL.txt의 전체 내용으로
편집기를 갱신하세요. user_wiki와 별도 HMAC signing이 제거되었으며,
GENOS_MEMORY_SIGNING_KEY를 등록할 필요는 없습니다. 기존 플랫폼/API 인증과
실제 사용자·대화 식별자, 문서 권한 범위 및 세션 상태는 유지합니다.

4. 현장 질의와 계측
질의·warmup은 기존 workflow 테스트 화면에서만 실행합니다.
코드서빙 직접 테스트 UI/API를 요구하지 않습니다.

GENOS_QUERY_LATENCY=1, GENOS_LOG_LEVEL=INFO는 기본입니다.
기존 환경에서 LOG_LEVEL=ERROR/WARNING으로 바꿨다면 INFO로 맞춰 배포합니다.
진단 버전 query-latency-20261007-r1은 R3 반입본에 담긴 계측 코드 버전입니다.

문제가 생겼던 질의를 실행하면 기존 요청 .log에 다음 세부 step이 보입니다.
law.native.RECALL / law.recall.tokenize / law.allowed_scope / unit_fts.bind
unit_fts.projection / unit_fts.sql.* / unit_fts.decode
law.native.SELECT / law.evidence.verify / law.select.initialize
law.select.article_menu / law.select.build_view / law.select.view
law.read.original / law.select.checkpoint / law.select.model_prepare
model.input_journal / model.request_build / model.request_encode
model.attempt_reserve / model.transport / model.output_validate / model.output_journal

heartbeat의 active_step이 현재 작업을 가리킵니다. SQL execute/fetch 시간,
캐시 hit/overflow, SQLite 설정과 mount_type, wall/CPU/non-CPU 시간,
cgroup throttle 증분, 모델 request_bytes로 공백을 구분합니다.
non-CPU 시간이 길다는 사실만으로 NFS/모델 대기라고 확정하지 마세요.
중첩 step의 시간을 모두 더하면 중복 계산됩니다.
새 계측은 질문/본문/SQL 문자열/키를 추가 로그로 쓰지 않습니다.
기존 감사 journal은 그대로 보존합니다.

요청 하나의 실제 로그 절대경로와 새 출력 경로를 넣어 요약합니다:
python3 GENOS_QUERY_LATENCY_20261007_R3_SUMMARIZE.txt /절대경로/요청.log --output /절대경로/새_요약.json

요약은 timing/count 필드만 담고 질문/본문을 옮기지 않습니다.
로그 기록 비용(start_log_ms)이 크면 GENOS_QUERY_LATENCY=0으로 신규 span을
끄고 재배포할 수 있습니다. 검색 재사용과 기존 감사 기록은 계속 유지됩니다.

5. 원복
apply가 출력한 정확한 BACKUP/RECOVERY 경로를 사용합니다:
bash GENOS_QUERY_LATENCY_20261007_R3_APPLY.txt rollback /apply가_출력한_절대_백업경로

이는 작업 checkout의 파일 원복입니다. 이미 push/배포했다면 기존 코드서빙
리비전과 검증된 동일 generation으로 플랫폼에서도 복귀합니다.
데이터 generation/CURRENT/runtime 상태는 이번 반입이 변경하지 않습니다.

기존 선택 계약 테스트 7개는 이전 발송본에서도 같은 실패로 재현되어 별도 보존했습니다.
이번 검색 결과·순위·건수·페이지·ACL·overflow·변조·중단·요청 격리와 완료 계약,
실제 첨부 TXT의 적용/재실행/원복/같은 checkout gate·모의 로컬 push를 검증합니다.
정확한 통과 수와 원시 기록 해시는 VALIDATION.json / HANDOFF.json에 남깁니다.
