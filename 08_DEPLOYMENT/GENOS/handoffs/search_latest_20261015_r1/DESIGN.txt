입력/소비자: 기존 선택 generation의 document 메타데이터 → 명시적 제외 plan →
generation 옆 SEARCH_SELECTION/<generation-directory>.json → Store/TermIndex → 검색/목록/원문/참조.
원본 SQLite/색인/manifest를 수정하거나 복사하지 않는다. 종료된 generation 내부도 쓰지 않는다.
런타임 연결마다 TEMP view로 구버전 원문·정의·참조를 숨기고 공통 문서 범위에서도 제거한다.
검색 통계/FTS 원본 통계는 재계산하지 않는다. 기존 순위 통계는 남지만 제외된 문서는 반환하지 않는다.
참조가 구버전을 가리키면 해당 참조를 숨긴다. 최신본으로 임의 치환하지 않는다.
메모리 캐시의 selection 지문을 분리하고 실행 중 설정 변경은 재시작 필요 오류로 종료한다.
원문 조회와 요청 범위가 구버전을 직접 지정하면 오류로 종료한다.
구 shortcut 시스템 결과 재사용도 selection 지문과 현재 문서 범위를 확인한다.

오류/복구: 잘못된 날짜·경로·중복은 warnings/보존. 출처 해시·generation·plan 불일치는 차단.
메타데이터 plan 담당 한 곳, 적용 담당 한 곳. 모델/재시도 호출 0. 동일 실패 무한 재시도 없음.
코드 apply는 정확한 사전/사후 바이트만 허용하고 실패 시 백업 복구. 알 수 없는 현장 코드는 중단.
제외 apply는 원자적 설정 교체, PREPARED receipt와 before/after 보존, 검사 실패 시 이전 설정 복구.
중단 후 같은 plan 재실행은 멱등. 다른 변경 이후 과거 receipt 원복은 거부.
새 코드 적용·제외 설정 적용·commit·게이트·push·리비전·워크플로우 질의는 별도 상태.

현장 속도: document 메타데이터 1회 스캔과 선택 검증을 수행한다.
전체 source_block 본문 스캔, 구조화, LLM, 임베딩, FTS 재생성, VACUUM, DB 전체 백업 없음.
apply 전 stale plan 검사는 메타데이터를 한 번 더 확인한다. 실제 처리시간은 현장 문서 수/NFS에 의존한다.
정상 런타임 및 배포 게이트의 원래 해시 무결성 검사는 유지한다.

검증: 일반/compact-v2의 기존 구·신 버전 DB를 사용해 원문/색인 바이트 불변,
구버전 차단/최신본 유지/단어 검색/FTS/실제 API/원복/모호성/변조/재실행을 검사한다.
모든 데이터는 모의이며 내부 모델/현장 성능 실험이 아니다. 로컬 선택 MAIN 포인터는 바꾸지 않는다.
