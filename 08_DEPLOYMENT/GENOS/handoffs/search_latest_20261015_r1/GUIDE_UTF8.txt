GENOS 기존 SQLite 구버전 검색 제외 R1

이번에는 전체 재구축을 하지 않습니다. 기존 generation의 문서 메타데이터를 읽어
같은 폴더·제목의 (YYYYMMDD) 중 오래된 문서 ID만 검색에서 제외합니다.
원본 SQLite, navigation/FTS 색인, RAW는 그대로 둡니다. 모델 호출은 0회입니다.
이전 LATEST_INTERNAL R1의 재구축 안내 대신 이번 SEARCH_LATEST R1을 사용하세요.

1. ZIP과 실행 TXT를 실제 업로드한 TRANSFER 폴더에서 실행합니다.
TRANSFER의 절대 위치를 가정하지 않습니다. 먼저 DEV로 이동하지 마세요.

python3 -m zipfile -e ./GENOS_SEARCH_LATEST_20261015_R1.zip ./GENOS_SEARCH_LATEST_20261015_R1
bash ./GENOS_SEARCH_LATEST_20261015_R1/GENOS_SEARCH_LATEST_20261015_R1_RUN.txt check
bash ./GENOS_SEARCH_LATEST_20261015_R1/GENOS_SEARCH_LATEST_20261015_R1_RUN.txt apply

check: 기존 ~/DEV 코드와 의존성 확인, 현재 선택 generation 확인, 제외 계획 생성.
apply: ~/DEV 파일 백업·패치·검증, 위 계획을 검색 제외 설정으로 적용.
GENOS_GENERATION/GENOS_DATA_ROOT 및 ~/DEV/.env의 기존 데이터 설정을 먼저 사용합니다.
선택 세대를 찾을 수 없으면 추정하지 않고 중단합니다. 이때 코드서빙에 설정된
정확한 generation 절대경로를 아래처럼 전달합니다. 경로는 사용자가 현장값으로 바꿉니다.
bash ./GENOS_SEARCH_LATEST_20261015_R1/GENOS_SEARCH_LATEST_20261015_R1_RUN.txt check --generation '/실제/선택/generation'
bash ./GENOS_SEARCH_LATEST_20261015_R1/GENOS_SEARCH_LATEST_20261015_R1_RUN.txt apply --generation '/실제/선택/generation'

SELECTION_PLAN.json에서 counts.excluded_documents가 실제 제외 건수입니다.
groups에는 최신본과 구버전 ID가, warnings에는 자동 판단하지 않은 항목이 남습니다.
경로 메타데이터 누락, 날짜 없음/6자리/잘못된 날짜, 같은 날짜·같은 형식의 다른 내용,
다른 폴더에서 여전히 최신인 동일 문서는 임의 제외하지 않습니다.
날짜는 파일 버전 표기이며 법적 시행일을 인증하지 않습니다.
DB에 이미 들어 있는 문서 중 최신본을 선택합니다. RAW에만 있고 아직 구조화되지 않은
새 파일은 이번 작업으로 추가되지 않습니다.

2. Git 검토·commit·배포 전 게이트 (코드 적용 위치는 기존 ~/DEV)

git -C "$HOME/DEV" diff --check
git -C "$HOME/DEV" status --short
git -C "$HOME/DEV" diff --stat

출력된 CODE_APPLIED.json의 files 목록이 이번 코드·pin 변경 목록입니다.
이 목록과 실제 diff를 검토하여 해당 파일만 git add/commit합니다.
다른 작업의 미완료 변경을 함께 커밋하지 마세요.
이후 다시 TRANSFER에서 실행합니다.

bash ./GENOS_SEARCH_LATEST_20261015_R1/GENOS_SEARCH_LATEST_20261015_R1_RUN.txt gate

gate는 실제 커밋된 ~/DEV 바이트와 CODE_APPLIED.zip, 선택 generation을 함께 검사합니다.
기존 무결성 게이트의 대용량 파일 해시는 시간이 걸릴 수 있습니다. 데이터 재구축은 아닙니다.
VERIFIED_CHECKOUT.json의 commit을 push하고 같은 commit으로 새 코드서빙 리비전을 배포합니다.
기존 GENOS_GENERATION/GENOS_DATA_ROOT를 유지하고 별도 SSE 서버도 재시작합니다.
워크플로우 Python 편집기 교체는 없습니다. 현장 질의·warmup은 워크플로우 테스트 화면에서만 합니다.

코드 패치와 검색 제외 설정만 적용하면 이미 실행 중인 구 리비전은 바뀌지 않습니다.
새 리비전/SSE 재시작 후 같은 규정의 구버전 파일명과 본문 고유문구를 질의하여 제외를 확인하고,
최신본 조회가 유지되는지도 확인합니다. 요청 ID·commit·generation·리비전을 함께 기록합니다.
과거 대화/감사 기록을 삭제하지 않습니다. 새 검색에는 제외가 적용되며,
이전 문서 범위를 가진 조사는 최신 범위로 새 질문을 시작해야 할 수 있습니다.

3. 상태와 원복

bash ./GENOS_SEARCH_LATEST_20261015_R1/GENOS_SEARCH_LATEST_20261015_R1_RUN.txt status

원복은 apply 출력 또는 SELECTION_APPLIED.json의 정확한 receipt 경로를 사용합니다.
bash ./GENOS_SEARCH_LATEST_20261015_R1/GENOS_SEARCH_LATEST_20261015_R1_RUN.txt rollback --receipt '/출력된/receipts/이름/receipt.json'

원복 후 코드서빙/SSE를 재시작합니다. 기존 SQLite 전체를 복사하거나 복구할 필요가 없습니다.
코드 자체도 원복할 경우 먼저 검색 제외를 원복한 다음 출력된 CODE_BACKUP 경로로 실행합니다.
bash ./GENOS_SEARCH_LATEST_20261015_R1/GENOS_SEARCH_LATEST_20261015_R1_RUN.txt undo-code --backup '/출력된/CODE_BACKUP'
코드 원복 후에는 해당 Git 변경을 검토·commit하고 이전 검증 리비전으로 배포합니다.

변경된 코드·계획·원복 대상이 있으면 실패를 숨기거나 덮어쓰지 않고 중단합니다.
로그는 실행 시작부터 TRANSFER의 search-latest-*.log에 남고 종료 코드도 기록됩니다.
apply 재실행은 동일 계획/동일 코드라면 안전하게 확인만 합니다.
다른 세대나 달라진 문서에는 새 --plan './새계획.json'을 사용해 check부터 실행합니다.

4. 이후 데이터 추가

이번 기존 데이터 처리에는 build 명령을 실행하지 않습니다.
향후 정상적인 신규 구조화 작업에서는 build-data-stages/build-all에
--latest-internal-versions 옵션을 추가하면 구버전을 구조화하기 전에 제외합니다.
동일 작업 run-id의 선택 옵션/입력은 재개 도중 바꾸지 않습니다.
새 generation으로 바꾸면 그 generation에 check/apply를 다시 실행해야 합니다.

의존성: 기존 GENOS의 python3 및 설치된 기존 프로젝트 의존성을 사용합니다.
새 외부 패키지·모델·임베딩 다운로드가 없습니다.
외부 합성 데이터 검사 성공과 GENOS 현장 배포/실제 내부 데이터 성공은 별도입니다.
