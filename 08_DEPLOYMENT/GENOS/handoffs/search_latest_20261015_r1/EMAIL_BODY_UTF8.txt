기존 SQLite의 구버전만 검색에서 제외하는 GENOS 적용 패키지입니다.

전체 재구축은 하지 않습니다. 같은 폴더·문서명 뒤 (YYYYMMDD)를 비교하여 구버전 문서 ID만 검색·목록·원문·참조 탐색에서 제외합니다. 기존 SQLite/색인/RAW는 보존하며, 모델 호출·임베딩·색인 재생성 없이 문서 메타데이터로 제외 목록을 만듭니다. 날짜·경로가 불명확한 항목은 보고서에 남기고 보존합니다.

이전 LATEST_INTERNAL R1의 재구축 안내 대신 이번 SEARCH_LATEST R1을 사용하세요.
실제 업로드한 TRANSFER 폴더에서 아래 명령을 실행합니다. 먼저 DEV로 이동하지 않습니다.

python3 -m zipfile -e ./GENOS_SEARCH_LATEST_20261015_R1.zip ./GENOS_SEARCH_LATEST_20261015_R1
bash ./GENOS_SEARCH_LATEST_20261015_R1/GENOS_SEARCH_LATEST_20261015_R1_RUN.txt check
bash ./GENOS_SEARCH_LATEST_20261015_R1/GENOS_SEARCH_LATEST_20261015_R1_RUN.txt apply

코드 적용 대상은 기존 ~/DEV이며 백업 후 적용합니다. 현재 generation은 기존 GENOS_GENERATION/GENOS_DATA_ROOT 설정으로 확인합니다. 찾을 수 없으면 추정하지 않고 중단하며, GUIDE의 --generation 방법으로 실제 현장값을 지정할 수 있습니다.

apply 후 SELECTION_PLAN.json의 제외 문서 수와 warnings를 확인하세요. 이후 변경 파일 검토·commit → RUN의 gate → push → 새 코드서빙 리비전 배포 및 별도 SSE 서버 재시작이 필요합니다. 워크플로우 Python 편집기 교체는 없습니다. 현장 질의 확인은 워크플로우 테스트 화면에서 합니다.

적용한 제외 목록은 receipt를 이용해 바로 원복할 수 있습니다. 전체 DB 백업/복원은 필요하지 않습니다. 원복 명령·실패/재실행 안내와 지속 로그 설명은 GUIDE에 포함했습니다.

검증: 신규 계약 12개, 관련 회귀 66개 통과. 기존 실패 2건은 수정 전 코드에서도 동일 재현했습니다. 실제 첨부 ZIP 설치본 28계약·실행 27명령·동일 committed checkout의 두 저장 형식 generation gate를 확인했습니다. v5/v6 검색 API와 구버전 차단·최신본 유지·원복을 합성 데이터로 검사했습니다.
GENOS 현장 반입·배포·실제 내부 검색은 아직 미확인입니다. 로컬 MAIN66 포인터도 바꾸지 않았습니다.

첨부: 코드 ZIP, 독립 실행 TXT, 적용/원복 안내, 검증 요약, 검증 JSON, SHA256 목록. 실행 TXT는 ZIP 안에도 동일하게 포함했습니다.
