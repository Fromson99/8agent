1. 실제 업로드한 TRANSFER 폴더에서 시작
ZIP과 별도 RUN.txt를 실제 TRANSFER에 올립니다. 그 폴더를 현재 작업 위치로 유지합니다.
TRANSFER 절대 위치를 추정하지 않으며 설치를 위해 먼저 DEV로 이동하지 않습니다.
아래 /workspace는 앞선 현장 사진의 기존 Git checkout 실경로입니다.
현재 기존 DEV checkout 실경로가 다르면 --root를 확인한 경로로 바꾸십시오.

python3 -m zipfile -e ./GENOS_MAIN90_RESEARCH_20261020_R1.zip ./GENOS_MAIN90_RESEARCH_20261020_R1
bash ./GENOS_MAIN90_RESEARCH_20261020_R1/GENOS_MAIN90_RESEARCH_20261020_R1_RUN.txt check --root /workspace
bash ./GENOS_MAIN90_RESEARCH_20261020_R1/GENOS_MAIN90_RESEARCH_20261020_R1_RUN.txt apply --root /workspace
bash ./GENOS_MAIN90_RESEARCH_20261020_R1/GENOS_MAIN90_RESEARCH_20261020_R1_RUN.txt status --root /workspace

별도 첨부 RUN.txt는 ZIP 옆에서 bash ./GENOS_MAIN90_RESEARCH_20261020_R1_RUN.txt check --root /workspace로
실행해도 됩니다. 이 경로는 압축 해제 전부터 main90-research-r1-logs에 로그와 종료 코드를 남깁니다.
Python 3.11 이상이 필요하며 실제 실행 파일과 버전을 기록합니다.
sqlglot 30.23.0이 없을 때만 같은 RUN.txt의 deps --root /workspace를 먼저 실행합니다.
외부 인터넷 설치 없이 첨부 wheel을 사용합니다. 기존 다른 의존성은 이전 누적본 기준을 유지합니다.

2. 적용 대상과 보존·재개
코드는 기존 Git checkout에 백업 후 적용됩니다. 푼 패키지 폴더만 수정하는 방식이 아닙니다.
01_DATA 원문·색인·기존 generation, .env, .venv, .git, TRANSFER와 별도 사용자 파일을 보존합니다.
기존 GENOS_SERVING_PATHS 설정은 별도 보존해 APPLIED_CODE.zip에 결속합니다.
STATUS.json / LAST_FAILURE.json / 로그를 유지하며 중단된 apply는 백업으로 복구 후 재적용합니다.
동일 패키지 재적용은 해시를 확인하고 이후 사용자 변경·변조는 거절합니다.
이번 코드 적용으로 데이터 재구축·Oracle 조회 채널 변경·리비전 배포를 수행하지 않습니다.

3. 실제 checkout의 검토·commit·게이트·push·리비전
기존 checkout에서 git diff --check와 변경 목록을 검토하고 설치 receipt의 units 및
CODE_MANIFEST.json을 기준으로 코드만 commit합니다. .env·로그·백업·데이터를 추가하지 않습니다.
그 뒤 TRANSFER에서 실행합니다.

bash ./GENOS_MAIN90_RESEARCH_20261020_R1/GENOS_MAIN90_RESEARCH_20261020_R1_RUN.txt gate-code --root /workspace

게이트는 같은 Git 추적 checkout과 HEAD, APPLIED_CODE.zip의 모든 파일을 대조합니다.
통과한 commit을 기존 원격에 push하고 같은 commit의 새 코드서빙 리비전을 배포합니다.
기존 시작 명령은 python3 main_router.py입니다. 스크립트가 push/배포를 자동 실행하지 않습니다.
코드를 추가로 바꿨으면 새 commit과 게이트가 필요합니다.

그렇지 않으면 기존 워크플로우 Python 단계에 전체 내용을 반영하고 저장합니다.

이전 버전의 미완료 실행을 강제로 새 코드로 재개하지 말고 원장을 보존한 뒤 새 채팅으로 확인합니다.

이미 검증된 조회 release/channel과 외부 NFS 실행 이력 설정을 유지합니다.

조회 데이터 적재·활성화와 코드 설치는 별도입니다. 이 설치는 데이터 게시/이관을 실행하지 않습니다.
