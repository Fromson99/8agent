GENOS BASIS_IDENTITY 403 수정 — 확정 연결은 그대로 유지

대사 시작 전에 별도의 관계 관리용 사용자 검사를 호출하던 코드가 원인입니다.
이번 수정은 대사가 기존 팀·세션·문서 권한을 구성한 뒤 내규를 조사하고,
그 내규에 연결된 외규를 조회하도록 기존 경로를 사용합니다.
일반 세션 RAG도 이미 준비한 실행 주체를 사용합니다.
관계 관리 API의 인증/승인 권한, 문서 접근권한, 원문/DB/상태 해시 검사는 유지합니다.

지금 실행할 것 — 기존 BATCH R4 코드가 적용된 실제 TRANSFER 폴더에서:
python3 -m zipfile -e ./GENOS_BASIS_ENTRY_FIX_20261020_R1.zip ./GENOS_BASIS_ENTRY_FIX_20261020_R1
bash ./GENOS_BASIS_ENTRY_FIX_20261020_R1/GENOS_BASIS_ENTRY_FIX_20261020_R1_RUN.txt check
bash ./GENOS_BASIS_ENTRY_FIX_20261020_R1/GENOS_BASIS_ENTRY_FIX_20261020_R1_RUN.txt apply
bash ./GENOS_BASIS_ENTRY_FIX_20261020_R1/GENOS_BASIS_ENTRY_FIX_20261020_R1_RUN.txt gate

여기 apply는 코드 수정입니다. SQLite 확정 연결 4건을 다시 적용하는 명령이 아닙니다.
기존 ~/DEV의 실제 Git checkout에 app.py와 그 해시를 참조하는 manifest/pin만 적용합니다.
~/DEV가 /workspace를 가리키는 현장 연결을 지원합니다. TRANSFER 절대경로는 가정하지 않습니다.
전체 원문/색인/관계 SQLite/후보 JSON/실패 이력/설정/로컬 MAIN 포인터를 바꾸지 않습니다.
check는 알려진 R4 코드 또는 이번 수정 바이트만 허용하며, 다른 수정은 덮어쓰지 않습니다.
재실행은 같은 결과를 확인합니다. backup, INSTALL_STATE.json, ROOT_BINDING.json을 보존하세요.
기존 확정 연결 R5를 다시 실행하거나 DB 이관 ZIP을 다시 적용하지 마세요.

코드 적용 후 실행 중인 프로세스에 반영
- 코드스페이스의 기존 Python 프로세스가 service.application을 캐시했다면 그 프로세스를 재시작해야 합니다.
- 코드서빙은 기존 배포 절차대로 ~/DEV 변경 검토 → commit → 아래 release-gate → push → 같은 커밋의 새 리비전 배포가 필요합니다.
  COMMIT_PATHS.txt는 이번 변경 파일 목록입니다. 기존 다른 작업/스테이징을 임의 포함하지 마세요.
bash ./GENOS_BASIS_ENTRY_FIX_20261020_R1/GENOS_BASIS_ENTRY_FIX_20261020_R1_RUN.txt release-gate
- release-gate는 commit한 checkout과 code.zip/필수 의존성, 설정의 실제 generation 및 검색 자산을 검사합니다.
  큰 NFS 데이터 검증은 시간이 걸릴 수 있습니다. 검사와 모델 실행을 병렬로 돌리지 마세요.
- 워크플로우 Python 편집기 코드는 이번에 변경하지 않았습니다. 기존 팀·세션 전달 설정을 유지합니다.
- 워크플로우 테스트 화면에서 새 대사 질문으로 확인합니다. 코드서빙 직접 테스트 UI/API는 요구하지 않습니다.

성공 확인: BASIS_IDENTITY 없이 내규 조사 진입 → 내규 원문 확보 → 해당 승인 연결 외규 조회 → 대사 결과.
패치 gate PASS는 실제 내부 모델의 대사 품질이나 서빙 리비전 배포 성공을 뜻하지 않습니다.

전체 조사 도구는 나중에 — 지금 자동 실행하지 않음
수정 후에는 이전 BATCH R4/확정 연결 R5의 고정 코드 게이트가 다른 해시를 감지합니다.
그 검사를 고치거나 무시하지 말고, 이번 묶음에 함께 들어 있는 같은 조사 실행기를 사용합니다.
이전 interrupted 작업은 코드에 결속되어 있으므로 그대로 보존합니다. 이번 새 기본 job은
runtime/basis-batch/pilot-review-entryfix-20261020-r1 이며 기존 PLAN/STATE/후보를 수정하지 않습니다.
새 계획은 새 조사/예산이고 이전 조사 결과를 자동 승계하지 않습니다. DB에 적용한 4건은 유지됩니다.
대사 확인이 끝나고 사용자가 일반 조사를 시작할 때만:
bash ./GENOS_BASIS_ENTRY_FIX_20261020_R1/GENOS_BASIS_ENTRY_FIX_20261020_R1_RUN.txt plan --count 3
bash ./GENOS_BASIS_ENTRY_FIX_20261020_R1/GENOS_BASIS_ENTRY_FIX_20261020_R1_RUN.txt run
이 명령은 문서 3개 조사이며 전체 문서 전수를 뜻하지 않습니다. 모델 후보는 JSON에만 저장합니다.
같은 새 작업 중단 후: 같은 RUN.txt resume (최초 기한/사용량 보존)
보고서: 같은 RUN.txt report --output ./후보검토_수정본.html
이관: 같은 RUN.txt export --output ./BASIS_REVIEW_ENTRY_FIX
생성 폴더의 LINKS.html → APPLY_RELATIONS.txt review --all/--ids → check → apply → status 순서입니다.
기존 R4에서 내보낸 묶음은 R4 코드에 고정돼 있습니다. 새 후보 이관에는 이번 export 결과를 사용합니다.

원복
bash ./GENOS_BASIS_ENTRY_FIX_20261020_R1/GENOS_BASIS_ENTRY_FIX_20261020_R1_RUN.txt rollback
이번 코드만 이전 R4 바이트로 원복합니다. 관계 DB/원문/후보/이력은 삭제하지 않습니다.
다른 수정이 섞이면 원복도 덮어쓰지 않고 중단합니다. 서빙 리비전 복귀는 별도입니다.
