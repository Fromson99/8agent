현장 MAIN193 뒤 로컬에서 만든 4개를 한 번에 담았습니다: 193 첫 질문 준비·진행 표시, 194 조문 목록 미리 적재,
195 SQLite 걷어내기, 196 기록 층 정리·코드 해시 검사 경량화. 워크플로우 파일은 바뀌지 않았습니다(편집기 교체 불필요).

0. 무엇이 바뀌나
  ■ SQLite 걷어내기 (질문당 SQLite 문장 약 1,720 → 0)
    - 원문 조회: SQLite 문법을 Oracle로 번역하던 SQL 대신 Oracle SQL을 바로 보냄.
    - 채팅 기록(숏컷·대화 기억): 기존 에이전트 표 SIDDA.LGL_AGT_REC_A / LGL_AGT_BODY_A / LGL_EXEC_ST_A의 행으로 저장.
      그 채팅을 처음 열 때 한 번 읽고, 질문이 끝날 때 바뀐 것만 Oracle 호출 1번으로 저장. 새 표·DDL 없음.
    - 질문 처리 중 작업 기록: 서버 메모리의 기록 표로 처리하고, 질문 끝에 채팅 저장본에 같이 저장(Oracle 쓰기 횟수 그대로).
    - Oracle 쿼리 계획 635개 → 388개.
  ■ 속도
    - 요청마다 하던 엔진 코드 파일 475개 해시 확인(경로 풀기·정의 파일 다시 읽기, 로컬 80ms, NFS면 더 김) → 0.7ms.
      코드 파일이 바뀌면 거절하는 동작은 그대로입니다.
    - 서버 시작 때 문서 목록·조문 목록·형태소 등을 미리 준비하고, 준비 중 들어온 질문은 "자료를 준비하고 있습니다" 카드로 기다렸다 처리.
    - 진행 화면에 "관련 문서 찾기 / 선택한 원문 확인 / 근거 검토·답변 작성" 단계가 바로 보임.
    - 동시 질문은 6건까지 처리하고, 넘으면 대기 카드 후 자동 실행.
  ■ 메모리·저장본
    - 채팅은 마지막 사용 2시간 뒤 메모리에서 내림(다음 질문 때 Oracle에서 다시 읽음).
    - 채팅 저장본은 최신 1개만 남기고 이전 것을 지움 → 서빙 계정에 BODY 표 DELETE 권한이 필요합니다(아래 1).
      권한이 없으면 경고 로그 1번(memory.chat.snapshot_cleanup_off) 뒤 지우지 않고 계속 동작합니다.
    - 채팅 저장본 크기 약 40% 감소(로컬 질문 1개당 약 410KB → 240KB, 압축 후).

1. 적용 전 (선택, 권장)

  조절이 필요할 때만: GENOS_MAX_ACTIVE_QUESTIONS(기본 6), GENOS_PRELOAD_WAIT_SECONDS(기본 300),
    GENOS_MEMORY_CHAT_TTL_SECONDS(기본 7200), GENOS_METADATA_PRELOAD_MIB(기본 1024, =off로 끔),
