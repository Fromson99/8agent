코드 구성
선택 MAIN 제품420파일 중 비활성 관리화면3자산을 제외한417파일입니다.
엔진30개와 PIPELINE의 해당 의존 목록·해시31개만 파생하며 Python·스키마·프로필·워크플로우는 선택 MAIN과 같은 바이트입니다.
기존 세대 검사 명령의 의존성과 serving requirements 등 운영 보조16파일을 별도 AUXILIARY_MANIFEST에 기록합니다.
전체검사433파일, 전달·적용대상433파일을 모두 ZIP에 넣었습니다. 이전 코드 ZIP 없이 누락파일 복원이 가능하며 기존 동일파일은 건너뜁니다.

SOURCE_BINDING.json은 선택 MAIN과 제품·운영 보조를 구분합니다. 코드 ZIP과 중첩 ZIP에 .js/.jsx/.mjs/.cjs는 없습니다.
운영 보조의 기존파일이 알려진 바이트와 다르면 자동 덮어쓰지 않고 check에서 중단합니다.

적용 방법
첨부를 실제 업로드한 TRANSFER 폴더를 현재 작업 위치로 두고 실행합니다. TRANSFER 절대 위치를 추정하지 않습니다.
압축해제부터 로그와 종료코드를 보존합니다.

mkdir -p ./main104-navigation-sql-r1-logs
python3 -m zipfile -e ./GENOS_MAIN104_NAVIGATION_SQL_20261027_R1.zip ./GENOS_MAIN104_NAVIGATION_SQL_20261027_R1 > ./main104-navigation-sql-r1-logs/extract.log 2>&1
TASK_EXTRACT_RC=$?
printf '%s\n' "$TASK_EXTRACT_RC" > ./main104-navigation-sql-r1-logs/extract.exit
if [ "$TASK_EXTRACT_RC" -ne 0 ]; then cat ./main104-navigation-sql-r1-logs/extract.log; else
  bash ./GENOS_MAIN104_NAVIGATION_SQL_20261027_R1/GENOS_MAIN104_NAVIGATION_SQL_20261027_R1_RUN.txt check
fi

check 성공 후 같은 TRANSFER 위치에서:
bash ./GENOS_MAIN104_NAVIGATION_SQL_20261027_R1/GENOS_MAIN104_NAVIGATION_SQL_20261027_R1_RUN.txt apply
bash ./GENOS_MAIN104_NAVIGATION_SQL_20261027_R1/GENOS_MAIN104_NAVIGATION_SQL_20261027_R1_RUN.txt gate

기본 대상은 기존 ~/DEV Git checkout입니다. 다른 checkout이면 --root /실제/DEV/경로를 명시합니다.
실제 경로를 ROOT_BINDING.json에 고정하고 backup/과 INSTALL_STATE.json을 보존합니다.
동일 apply 재실행은 적용된 바이트를 확인하고 남은 작업을 이어갑니다. 파일이 달라졌으면 중단합니다.
.env·기존GENOS_SERVING_PATHS.json·검색 선택JSON·원문·색인·Git 이력은 유지합니다.

워크플로우와 배포
GENOS_WORKFLOW_PYTHON.txt는 별도 워크플로우 Python 편집기에 적용하는 파일입니다.
SHA256: 91dd6a113cdb573e70feff5a9cc7ec1e1d9bd27609b419a14893c9ad1b39c995
MAIN102와 같은 workflow1.20.8이면 재교체할 필요가 없습니다. 실제 편집기 반영 상태는 별도로 확인합니다.
DEV의 COMMIT_PATHS.txt 목록에 해당하는 변경을 검토하고 git diff --check 후 해당 파일만 커밋합니다.
다른 staged 작업을 함께 커밋하지 않습니다. 같은 TRANSFER 위치에서:
bash ./GENOS_MAIN104_NAVIGATION_SQL_20261027_R1/GENOS_MAIN104_NAVIGATION_SQL_20261027_R1_RUN.txt gate-code
통과한 커밋을 push하고 같은 커밋의 코드서빙 리비전을 배포합니다. 코드가 바뀌면 다시 커밋하고 검사합니다.

기존 SQLite generation 환경에서만 별도 읽기전용 데이터 검사:
bash ./GENOS_MAIN104_NAVIGATION_SQL_20261027_R1/GENOS_MAIN104_NAVIGATION_SQL_20261027_R1_RUN.txt gate-sqlite
이 명령은 실제 선택 generation을 검증하며 데이터를 만들거나 복원하지 않습니다. 큰 파일 해시에 시간이 걸릴 수 있습니다.
실제 generation 절대경로와 manifest SHA256을 기록합니다. Oracle 조회 환경에서는 이 SQLite 검사를 실행하지 않습니다.
Oracle의 선택 데이터 버전·권한·조회 원문은 현장 워크플로우 결과로 확인합니다.

현장 최종 확인은 워크플로우 테스트 화면에서만 합니다. 코드서빙 직접 테스트 UI/API를 요구하지 않습니다.
