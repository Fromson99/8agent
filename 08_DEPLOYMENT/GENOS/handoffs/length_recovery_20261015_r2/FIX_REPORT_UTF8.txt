GENOS LENGTH_RECOVERY R2 — 설치 전 기존 스키마 충돌 수정

사진에서 확인한 실패
R1 check/apply는 prepared()에서 다음 오류로 코드 쓰기 전에 중단했다.
Unrecorded new module already exists; preserved: 00_SYSTEM/SCHEMAS/pipeline-v1.schema.json
이어 실행한 verify는 미적용 상태를 보고했다. 재시도나 이전 두 패치 적용으로 해결되는 오류가 아니다.
기존 체크아웃 파일과 배송 CODE_MANIFEST의 목록이 다를 수 있는데, 기존 검사는 목록에 없는 모든 파일을 새 충돌로 처리했다.
현장 파일의 실제 해시/내용은 사진에 없으므로 특정 버전이라고 단정하지 않는다.

수정 계약
- 복구 담당: 동일 설치기의 prepared()와 apply(); 모델 호출 및 자동 재시도 0회.
- 허용 범위: pipeline-v1.schema.json 및 pipeline-engine-v1.schema.json 두 경로만.
- 기존 파일은 보존한 Git 리비전 또는 봉인된 R1 목표 파일의 정확한 SHA-256/크기와 일치해야 한다.
- 기존 전체 코드 inventory, 엔진 pin, 목표 output signature 검사는 그대로 유지한다.
- 일치하면 물리적으로 존재하는 원본을 백업하고 manifest 목록에 포함한다.
- 원본 바이트·권한과 목록의 원래 누락 상태를 별도로 기록하고 undo에서 모두 복원한다.
- 알 수 없는 파일, 변조, 심볼릭 링크, 디렉터리, 검사 후 변경은 거부하며 파일을 덮어쓰지 않는다.
- 알 수 없는 파일은 경로·실제 SHA-256·크기를 로그에 남긴다. 원문·인증값은 출력하지 않는다.
- 정상/실패/이미 적용/원복과 코드 반영·배포·현장 실행 성공을 구분한다.

제품 코드
도구 전수 점검·부모 읽기·실패 복구·length 복구는 봉인된 R1과 같은 코드/프로필/엔진 결과를 사용한다.
로컬 MAIN66 및 데이터 generation은 변경하지 않는다. 이번 작업은 결정적 설치 결함 수정이며 모델 효과 실험이 아니다.
현장 기존 스키마 해시가 허용 목록과 다르면 여전히 중단한다. 강제 덮어쓰기나 파일 삭제로 우회하지 않는다.
기존 R1 메일/ZIP/실패 기록은 그대로 보존한다. R1을 이미 성공적으로 적용한 현장은 이 설치기 수정만을 위해 재설치할 필요 없다.
