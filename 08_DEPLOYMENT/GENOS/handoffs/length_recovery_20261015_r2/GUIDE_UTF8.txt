GENOS 길이 복구 누적 R2 — 기존 DEV 스키마 파일 충돌 수정

사진처럼 R1 check/apply가 Unrecorded new module already exists로 중단된 경우 이 R2를 사용한다.
R1에서 코드 쓰기 전에 실패했으므로 그 실패 자체를 되돌리는 undo는 필요 없다.
앞선 TOOL_AVAILABILITY/TOOL_RECOVERY 수정과 length 복구가 포함되어 있어 세 패치를 순서대로 실행하지 않는다.
선행 조건은 SCHEMA_RECOVERY R1 이상 알려진 코드 구성이다. R1 성공 적용 상태에는 설치기 수정을 위한 재설치가 필요 없다.

1. 실제 업로드한 TRANSFER 폴더를 현재 위치로 두고 아래를 한 단계씩 실행한다.
TRANSFER 절대 위치를 추정하지 않는다. 코드 적용 대상은 기존 ~/DEV이며 실제 다른 checkout일 때만 GENOS_DEV_ROOT를 지정한다.

python3 -m zipfile -e ./GENOS_LENGTH_RECOVERY_20261015_R2.zip ./GENOS_LENGTH_RECOVERY_20261015_R2
bash ./GENOS_LENGTH_RECOVERY_20261015_R2/GENOS_LENGTH_RECOVERY_20261015_R2_RUN.txt install

install은 사전 검사 → 백업 → 적용 → 검증을 한 번에 수행하며 실패 시 즉시 중단한다.
이미 적용돼 있으면 동일 파일을 확인하고 끝난다. ZIP 안과 별도 첨부 RUN.txt는 완전히 같다.
독립 TXT 사용 시: bash ./GENOS_LENGTH_RECOVERY_20261015_R2_RUN.txt install
검사만 할 때: bash ./GENOS_LENGTH_RECOVERY_20261015_R2/GENOS_LENGTH_RECOVERY_20261015_R2_RUN.txt check
처음부터 현재 TRANSFER/length-recovery-r2-logs에 로그와 exit 상태를 남긴다.
현장 python3의 실제 경로/버전, 해석된 기존 checkout 경로/commit을 기록한다.

KNOWN_UNRECORDED_SCHEMA는 확인된 기존 스키마를 백업 후 목록에 반영한다는 진단이다.
UNRECORDED_FILE_UNKNOWN이면 아무 코드도 바꾸지 않고 실제 해시를 출력한다. 해당 로그로 추가 확인해야 한다.
실패했을 때 기존 스키마를 삭제하거나 CODE_MANIFEST/해시를 수동 변경하지 않는다.
apply/install이 출력한 BACKUP 및 APPLIED_CODE_ZIP 절대경로를 보관한다.

2. 기존 DEV에서 변경 내용을 검토하고 receipt에 나온 파일과 CODE_MANIFEST.json을 commit한다.
다른 미완료 변경은 함께 stage하지 않는다. git diff --check 및 실제 변경 범위를 확인한다.

3. 실제 TRANSFER에서 아래 두 따옴표 안을 현장 출력/설정의 실제 절대경로로 바꿔 gate를 실행한다.
bash ./GENOS_LENGTH_RECOVERY_20261015_R2/GENOS_LENGTH_RECOVERY_20261015_R2_RUN.txt gate "실제 BACKUP 절대경로" --generation "현재 선택된 generation 절대경로"

gate는 같은 committed DEV checkout과 적용본 전체 코드 ZIP, 실제 generation을 대조한다.
위 한글 예시 값을 그대로 실행하지 않는다. gate 이후 코드/pin 변경 시 다시 commit하고 gate를 실행한다.
gate 통과 commit을 push → 그 commit의 새 코드서빙 리비전 배포 → 같은 코드로 SSE 프로세스 재시작.
원문/NFS 데이터 재구축과 이번 패치를 위한 워크플로우 편집기 변경은 필요 없다.

4. 워크플로우 테스트 화면에서 기존 성공 질문과 length 실패 질문을 재실행한다.
정상 max_tokens=6400 유지, 법령 탐색 length의 기존 수정 1회에만 최대 12800이다.
최종 답변 발행, request ID, 실제 cap/usage/finish_reason, 코드 commit/리비전/generation을 남긴다.
현장 내부 모델의 실제 성공은 외부 모의 검사로 확인하지 않았다.

5. 원복이 필요하면 진행 중 요청을 정리한 뒤 출력된 BACKUP 경로를 사용한다.
bash ./GENOS_LENGTH_RECOVERY_20261015_R2/GENOS_LENGTH_RECOVERY_20261015_R2_RUN.txt undo "실제 BACKUP 절대경로"
기존 물리 스키마 파일과 원래 CODE_MANIFEST를 복원한다. 이후 수정은 보존한 채 거부한다.
필요한 commit/push/이전 검증 리비전 배포·SSE 재시작은 별도로 진행한다.
데이터·실패 기록·기존 R1 자료는 삭제하지 않는다.
