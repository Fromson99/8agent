MAIN169 — 벡터 검색 후보를 화면에 표시 (MAIN168 대체)

현재 로컬 릴리스: vector-card-20261106-r1 / MAIN169, 서빙 536파일.
MAIN168(RECALL 1만 행 수정)과 MAIN167(Oracle 게시 자료 메모리 캐시)을 그대로 포함하고, 그 위에 제품 2파일만 바꿨습니다.
바뀐 것: semantic_runtime/progress.py, semantic_runtime/vector_navigation.py + SQL 출처 메타데이터(oracle_query_plans.py, 줄 번호만)·PIPELINE.json·엔진 pin 30개.
실행 SQL 642개, 테이블 매핑, 탐색 호환 등록표, 워크플로우는 MAIN168과 같습니다.
MAIN168을 아직 적용하지 않았다면 이 MAIN169만 적용하면 됩니다(MAIN168 수정 포함).

0. 왜 교체하나
개발계에서 VCTR_HEAD 1행을 넣고 GENOS_RAG_INITIAL_SEARCH=vector 로 질문했을 때,
화면에는 질문 이해 단계의 "본문 검색어: ..."만 보여서 벡터 검색을 했는지 알 수 없었습니다.
("본문 검색어"는 모델이 정한 검색 표현을 보여주는 칸이라 벡터 모드에서도 똑같이 뜹니다.)

1. 이번 수정 — 화면 표시만
첫 검색을 벡터로 한 질문은 "자료 검색" 카드가 이렇게 나옵니다.
  벡터 후보 100개 · 가까운 순
  상법 · 제447조의4(감사보고서)
  ...                         (가까운 조문 최대 5개, 문서명·조문 각 60자까지)
  외 95개
- 이 경우 그 카드에 붙던 "본문 검색에 사용한 단어" 줄은 빠집니다.
- 키워드 본문검색으로 찾은 질문(모델이 다른 단어로 다시 찾기를 고른 경우 등)은 지금 표시 그대로입니다.
- 권한 밖 문서는 개수·목록에서 빠집니다.
- 후보 조문, 검색 SQL, 권한 범위, 답변 내용은 바뀌지 않습니다. 벡터 후보는 근거가 아니라 읽을 목록입니다.

2. 전제 — 환경변수는 지금 값 그대로
  DP=oracle
  GENOS_ORACLE_TABLE_MAPPING=development_g19_1
  DP_QUERY_CHANNEL=g19_7c1f8f4931c8be61b914f5bc
  GENOS_RAG_INITIAL_SEARCH=vector (auto 권장. auto면 벡터를 못 쓸 때 키워드 검색으로 넘어갑니다)
  임베딩 설정(GENOS_EMBED_ID/TOKEN)과 VCTR_HEAD 1행은 지금 상태 유지. 새 환경변수는 없습니다.

3. GENOS 코드스페이스 적용 (MAIN168과 같은 절차)
같은 TRANSFER 폴더에 MAIN169_FULL_20261106_R1.zip, MAIN169_ONECLICK_R1.txt 를 두고 그 폴더에서 실행합니다. ZIP은 미리 풀지 않습니다.
  bash MAIN169_ONECLICK_R1.txt
완료 표시: MAIN169_ONECLICK_DONE, MAIN169_EXIT=0
확인·스테이징: bash MAIN169_ONECLICK_R1.txt status / stage, git -C ~/DEV diff --cached --stat / --check
  MAIN168이 적용된 checkout이면 스테이징 대상은 다음과 같습니다.
    02_BACKEND/semantic_runtime/progress.py
    02_BACKEND/semantic_runtime/vector_navigation.py
    02_BACKEND/semantic_runtime/oracle_query_plans.py      (SQL 출처 줄 번호만, 실행 SQL 642개 동일)
    00_SYSTEM/PIPELINE.json, 엔진 pin(02_BACKEND/ENGINES/...) 30개, CODE_MANIFEST.json
  MAIN167 이하가 적용된 checkout이면 MAIN168 변경 파일(memory_rag.py, unit_relations.py 등)도 함께 바뀝니다. 그대로 적용하면 됩니다.
기존 절차로 commit 후: bash MAIN169_ONECLICK_R1.txt gate-code → push → 그 commit의 새 코드서빙 리비전 배포
시작 명령: python3 08_DEPLOYMENT/GENOS/start_sse.py

4. 워크플로우 편집기
MAIN169_WORKFLOW.py 는 MAIN168_WORKFLOW.py 와 같은 바이트입니다. 이미 붙여 넣었다면 바꿀 필요가 없습니다.
새 카드는 기존 "판단 카드" 표시를 그대로 씁니다.

5. 확인 (부탁드립니다)
새 리비전 배포 후 워크플로우 테스트 화면에서 질문합니다.
  - "자료 검색" 카드에 "벡터 후보 N개 · 가까운 순"과 조문 목록이 나오면 적용된 것입니다.
  - 카드가 기존처럼 "본문 검색에 사용한 단어"로 나오면 그 질문은 키워드 본문검색으로 간 것입니다.
    벡터 검색 실행 여부는 컨테이너 로그의 sql_sha256 3b93c0d9... (벡터 검색 SQL) 로도 확인할 수 있습니다.
  - 오류가 나면 실패 단계·발생 위치(파일:줄)를 사진으로 보내 주세요.
