GENOS 요청 전체 과정 로그 / 2026-10-16 R1

적용 기준: 앞서 전달한 GENOS_MAIN_FULL_20261016_R1 전체 반입본이 기존 ~/DEV에 설치된 상태.
그 전체 반입본의 MAIN76 기능·최신 문서 선택·GENOS 출력 상한 제거를 유지하고 로그만 추가합니다.
구버전 또는 모르는 수정이 있으면 check/apply가 중단하며 기존 파일을 덮어쓰지 않습니다.
코드서빙 리비전 배포와 현장 내부 모델 확인은 아직 수행하지 않았습니다.

1. 실제 파일을 업로드한 TRANSFER 폴더를 현재 위치로 두고 실행

python3 -m zipfile -e ./GENOS_READABLE_TRACE_20261016_R1.zip ./GENOS_READABLE_TRACE_20261016_R1
bash ./GENOS_READABLE_TRACE_20261016_R1/GENOS_READABLE_TRACE_20261016_R1_RUN.txt check
bash ./GENOS_READABLE_TRACE_20261016_R1/GENOS_READABLE_TRACE_20261016_R1_RUN.txt apply

각 단계의 READABLE_TRACE_EXIT=0을 확인한 다음 진행합니다.
별도 첨부 RUN.txt도 ZIP 안과 동일한 완전한 실행 파일이며 ZIP 없이도 check/apply를 실행할 수 있습니다.
기본 대상은 기존 ~/DEV입니다. 다른 checkout을 운영할 때만 GENOS_DEV_ROOT에 실제 경로를 지정합니다.
~/DEV가 mount/symlink여도 최종 경로를 출력하여 확인하며 내부 파일 symlink는 임의로 따라가지 않습니다.
Python은 python3를 사용하고 실제 sys_executable/python/code_root/generation을 출력합니다.
입력·출력 계약과 모델 설정은 유지하며 추가 의존성 설치나 데이터 generation 재구축은 없습니다.

TRANSFER/readable-trace-r1-logs에 시작부터 로그와 .exit가 누적됩니다.
TRANSFER/readable-trace-r1-state/backup-...에 원본·receipt.json·APPLIED_CODE.zip이 남습니다.
BACKUP= 및 APPLIED_CODE_ZIP= 출력은 보관합니다. 이 ZIP은 실제 현장 설정을 포함한 적용 코드 검증용입니다.
check는 전체 코드 inventory·엔진 pin을 검증하고 apply는 원본을 백업한 다음 적용합니다.
apply 성공 시 CODE_APPLIED를 출력합니다. 재실행은 이미 적용한 파일을 검증하며 중복 덮어쓰지 않습니다.
중단되었다면 같은 TRANSFER 위치에서 같은 apply를 재실행합니다. PREPARED/APPLIED receipt를 검증해
원본을 복구한 뒤 적용을 재개합니다. 중단 뒤 다른 사람이 수정한 파일이 있으면 중단하여 보존합니다.

2. 기존 ~/DEV에서 변경 파일을 검토하고 commit

git -C ~/DEV status --short
git -C ~/DEV diff --stat

receipt.json의 files에 기록된 코드·엔진 manifest·PIPELINE.json·CODE_MANIFEST.json 변경만 검토해 stage/commit합니다.
.env, runtime, 백업·로그, 관련 없는 변경은 포함하지 않습니다. 실제 대상이 다르면 ~/DEV 대신 그 경로를 씁니다.
동일한 TRANSFER 폴더에서 아래 gate를 실행합니다. 이 명령이 고정 설정의 실제 generation과 동일 checkout,
동일 Python, 적용된 APPLIED_CODE.zip 및 commit을 함께 검증합니다.

bash ./GENOS_READABLE_TRACE_20261016_R1/GENOS_READABLE_TRACE_20261016_R1_RUN.txt gate

GENOS_RELEASE_GATE PASS와 READABLE_TRACE_EXIT=0을 확인합니다.
검증한 commit을 push하고 그 commit으로 코드서빙 새 리비전을 배포한 다음 SSE를 재시작합니다.
이번 로깅 패치에는 워크플로우 Python 편집기 변경이 없습니다. 이전 MAIN_FULL에서 요구한 편집기 반영은 별도입니다.
배포 commit·코드서빙 리비전 ID·gate receipt를 함께 보관합니다.

3. 워크플로우 테스트 화면에서 질의 후 vi로 확인

GENOS_SHARED_LOG_DIR이 설정된 기존 공유 로그 폴더에서 요청별 *.trace.txt를 엽니다.
RAG: $GENOS_SHARED_LOG_DIR/YYYY-MM-DD/<team>/legal_agent/<request>-<suffix>.trace.txt
AD : $GENOS_SHARED_LOG_DIR/YYYY-MM-DD/<team>/ad_mode/<request>-<suffix>.trace.txt
기존 요약 .txt와 .json에도 상세 파일 경로가 표시됩니다. 기존 .llm_raw.jsonl은 원시 원장으로 유지합니다.
vi에서 :e로 누적 기록을 다시 읽고 다음 문자열로 검색합니다.
/실제 LLM 입력
/프롬프트에 들어간 정보
/찾은 정보
/답변 속도
/오류 요약
/ERR-0001

각 agent/서비스 지점, 실제 전송 프롬프트와 LLM 응답, 검색·열람 결과, 검증·수정·재시도,
입력·출력·합계 토큰, 호출 시간과 누적 사용량을 문단으로 남깁니다.
검색한 모든 정보와 실제 프롬프트에 들어간 정보는 별도 표시합니다.
같은 traceback은 최초 한 번 전체를 기록하고 이후에는 오류 번호를 참조합니다.
서로 다른 호출·오류·상태 이벤트는 생략하지 않습니다. 기존 SQL·JSON 원장은 보존합니다.
기존 .log도 중복 traceback 대신 같은 오류 번호를 표시합니다.
토큰 미제공은 0이 아니라 미확인으로 표시합니다. 표시 속도는 출력 토큰/전체 호출 시간입니다.
RAG는 실행 중 누적되고 AD 상세 내용은 기존 계약에 따라 작업 종료 뒤 작성됩니다.
SAMPLE.trace.txt는 실제 작성기로 만든 모의 형식 예시입니다. 현장 질의 결과가 아닙니다.
사진에 보인 약 180초 모델 전송 timeout의 원인을 고친 것은 아니며 오류 표시·중복만 개선했습니다.
강제 종료·공유 저장소 장애·기존 보고서 용량 제한 시 파일이 불완전할 수 있으며 SQL/JSON이 원장입니다.

4. 검증·원복

bash ./GENOS_READABLE_TRACE_20261016_R1/GENOS_READABLE_TRACE_20261016_R1_RUN.txt verify

원복은 apply가 출력한 정확한 BACKUP 경로를 마지막 인자로 넣습니다.
bash ./GENOS_READABLE_TRACE_20261016_R1/GENOS_READABLE_TRACE_20261016_R1_RUN.txt undo /실제/BACKUP/경로

원복 전 현재 파일과 백업 해시를 모두 검사합니다. 이후 다른 수정이 생겼으면 임의로 지우지 않고 중단합니다.
원복은 코드만 복구합니다. 이미 배포했다면 이전 commit/리비전으로 재배포하고 SSE를 재시작해야 합니다.
기존 NFS generation·최신 문서 선택·요청 로그는 이 패치 적용/원복에서 변경하지 않습니다.

검증 범위와 남은 제한은 VALIDATION.json 및 WORKING_VALIDATION.json을 참고합니다.
