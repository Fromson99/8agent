RAG 코드 ZIP의 자동 commit/push 경계 — 2026-10-30 사용자 요청

범위: 기존 R3 MAIN123 제품492파일은 동일 바이트. RAG 코드스페이스 ~/DEV/main에서 패키지가 봉인한 경로만 커밋하고, 사진의 risk_team/623.git과 financial_team/701.git main에 동일 커밋을 전달한다. pipeline/Dataiku 배포는 대상이 아니다.
복구 담당: 기존 R3 installer는 파일 적용·백업·원복만 담당한다. genos_rag_git_publish.py는 commit/게이트/두 push 상태를 PUBLISH_STATE.json으로 관리한다. bootstrap은 순서만 연결한다.
인증: ID TD8461. 비밀번호는 숨김 입력 또는 현장 환경변수; host/port/username 정확 일치 askpass, redirect 금지, credential-cache 메모리8시간. 소스/패키지/명령행/설정/로그에 저장하지 않는다. 비네트워크 Git·게이트 자식에는 비밀번호 환경변수를 전달하지 않는다.
사전 중단: 원격 URL/복수 push URL/URL rewriting 불일치, main 아닌 브랜치, merge/rebase 중, 대상 밖 추적 수정/스테이지, 원격 분기, 패키지/대상 hash 불일치. 자동 force/merge/reset 없음. 알 수 없는 새 원격 main을 자동 생성하지 않는다.
커밋: 명세 경로만 stage. Git 필터/줄끝 변환으로 index와 패키지 바이트가 다르면 commit 전 중단. hook이 다른 파일을 추가하면 push 전 중단. 제품 원래 줄끝 공백은 명세 hash가 같은 상태에서 검사 기록을 보존한다.
재개: commit 전 상태·부모SHA·패키지 표식을 저장한다. commit 후 저장 직전 중단은 단일 자식/허용경로/정확바이트를 확인한 경우만 복구. 그 외 새 HEAD/코드 수정은 자동 채택하지 않는다.
push: 각 원격별 intended SHA/시도 상태를 먼저 저장하고 일반 push 1회 후 ls-remote로 확인한다. 응답 유실도 read-only 조회로 먼저 정리한다. 확인 실패는 unconfirmed이며 같은 TXT의 명시적 재실행에서만 재개. 다른 원격 성공 상태와 기존 커밋은 유지한다.
검증/배포: 같은 checkout에서 commit 후 코드 게이트를 실행한다. --generation을 명시한 경우 해당 실제 세대의 E2E/assets 게이트도 수행한다. generation 미지정은 코드만검증으로 기록하며 Oracle/NFS/코드서빙 리비전/실제 법률답변 성공으로 확대하지 않는다.
롤백: commit 전 기존 installer 원복 지원. commit 이후 자동 이력 재작성·remote rollback 없음; 별도 검토한 Git revert로 처리한다.
