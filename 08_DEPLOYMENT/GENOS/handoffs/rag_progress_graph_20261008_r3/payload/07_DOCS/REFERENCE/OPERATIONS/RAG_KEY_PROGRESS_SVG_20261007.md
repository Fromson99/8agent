작업 코드의 직접 `/chat` JSON·SSE와 분리 Python 워크플로우에 같은 표시 함수를 연결했다. 최종 답변의 기존 코드 생성 Mermaid 블록은 백엔드에서 직접 생성한 SVG 이미지로 바꿨다. 별도 Mermaid CLI, 브라우저, 외부 모델 및 네트워크 호출을 사용하지 않는다. 임의의 모델 생성 Mermaid 문법을 변환하는 범용 엔진은 아니다.

직접 경로는 `main.py /chat → semantic_runtime.chat_adapter.chat → service.service`다. 현재 작업 코드의 chat adapter가 현재 코드 번들의 `08_DEPLOYMENT/GENOS/workflow/genos_rag_chat.py`를 읽는다. JSON의 `agentFlowExecutedData`와 SSE token에 같은 핵심 진행 표시를 연결하고, 최종 `data.text`에는 SVG 이미지 태그와 기존 답변·출처·판단 토글을 반환한다. 이 표시 경로는 선택된 로컬 RAG 모델/검색 릴리스와 별도다.

분리 경로는 기존 `/stream`의 진행 이벤트를 `_ChatProgress.flow_events`에 모으고, 워크플로우 최종 JSON에 진행 카드와 SVG를 반환한다. Socket.IO 송신은 계속 비활성이다. 이 경로의 진행 기록은 최종 JSON에서 확인하며, 별도 워크플로우가 실시간 화면에 송신한다고 보지 않는다.

현재 `_judgment_flow`는 질문 ID·revision·route·단계별 판단 참조와 `judgment_view.content_sha256` 검증 후 현재 기록의 검색 개념·법령·원문·판단·답변 관계를 만든다. 원문→판단→답변은 source_id와 ASSESS/COMPOSE의 정확한 판단 쌍을 따른다. 진행/복귀의 시간 순서는 SVG에 중복해서 그리지 않는다. 실행/재사용 상태와 복귀 이유는 진행 카드 및 기존 판단 토글에 남는다. 원문 인용은 수정하지 않는다. 이미지의 텍스트를 XML escape하며, script·외부 URL·foreignObject는 생성하지 않는다.

`judgment_flow` 메타데이터에는 SVG MIME type·생성 코드 revision·SHA-256·바이트·개체/관계 수·근거 판단 해시·실측 생성 시간(ms)을 남긴다. 기존 `node_count`/`return_count`는 핵심 진행/복귀 기록 수이며, 실제 그래프 개체 수는 `entity_count`다. 현재 R9는 `layout=law-centered-evidence-clusters`, `theme=graphite-evidence`, `external_assets=false`, `process_nodes_visible=false`, `execution_trace_visible=false`, `concept_table_grouped_by_usage=true`, `answer_body_repeated=false`를 반환한다.
