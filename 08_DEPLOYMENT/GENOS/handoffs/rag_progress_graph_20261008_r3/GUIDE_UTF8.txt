2. ZIP 해제와 코드 적용 — 기존 ~/DEV
ZIP은 실행 TXT·표시 소스·명세·전체 워크플로우·안내·검증·모의 PNG를 포함합니다.
ZIP을 DEV 루트에 덮어 풀지 않습니다. 아래대로 TRANSFER에 해제하고 RUN이 기존
DEV의 파일을 백업한 뒤 해당 설치 코드에 맞는 변경만 반영하도록 합니다.
ZIP의 CODE_MANIFEST는 반입 패키지 목록입니다. 실제 배포 코드의 manifest/전체 ZIP은
RUN이 적용한 checkout에서 별도로 만들어 BACKUP 위치에 보존합니다.

python3 -m zipfile -e ~/DEV/TRANSFER/GENOS_RAG_PROGRESS_GRAPH_20261008_R3.zip ~/DEV/TRANSFER/rag-progress-graph-r3-delivery
cd ~/DEV/TRANSFER/rag-progress-graph-r3-delivery
sha256sum -c PACKAGE_SHA256SUMS.txt
bash GENOS_RAG_PROGRESS_GRAPH_20261008_R3_RUN.txt

별도 첨부 RUN TXT만 TRANSFER에 올렸으면 bash로 실행해도 됩니다. 실행 TXT는
필요한 코드·명세·로그 수집기를 같은 해시로 내장합니다. 인자 없이 실행하면 apply와
설치 코드 검증을 수행합니다. check/apply/verify/undo/gate 모드도 사용할 수 있습니다.
DEV 선택은 GENOS_DEV_ROOT → GENOS_DEV → ~/DEV 순서이며 루트 링크를 해결합니다.
Python은 현장의 python3를 사용하고 실제 실행 파일과 버전을 로그에 남깁니다.

bash GENOS_RAG_PROGRESS_GRAPH_20261008_R3_RUN.txt check
bash GENOS_RAG_PROGRESS_GRAPH_20261008_R3_RUN.txt verify

출력에서 다음 세 항목을 확인하십시오.
- RAG_DISPLAY_ALL_PROFILES PASS
- DISPLAY_WIRING: 실제 읽힌 genos_rag_chat.py의 절대경로
- DISPLAY_REVISIONS: 진행 R1 / chat adapter R9 / judgment SVG R9
BACKUP, APPLIED_CODE_ZIP, CODE_ZIP_SHA256과 최종 CODE_APPLIED를 보관합니다.
같은 apply 재실행은 전체 코드/결속 확인 후 ALREADY_APPLIED입니다.

가장 초기 검색 캐시/시스템 로그 설치본에 DB 상세 로그 롤백 R3가 아직 없으면
기존 파일 결속 때문에 R3 check가 거부될 수 있습니다. 함께 넣은 이전 검증 TXT로
check/apply/verify를 마친 뒤 위 R3를 실행합니다. 이미 CM 또는 표시 코드를
적용한 상태에서 R3 check가 통과하면 이 선행 TXT를 다시 실행하지 않습니다.

bash GENOS_DB_LOG_ROLLBACK_20261007_R3_RUN.txt check
bash GENOS_DB_LOG_ROLLBACK_20261007_R3_RUN.txt apply
bash GENOS_DB_LOG_ROLLBACK_20261007_R3_RUN.txt verify

CHECKOUT_DRIFT, 알 수 없는 코드 지문 또는 generation 연결 오류는 임의 rehash로
넘기지 않습니다. 현재 파일과 로그를 보존해 실제 적용 상태를 확인해야 합니다.

3. Git push와 코드서빙 리비전 — 코드 적용과 별도
작업 전에 있던 다른 변경을 섞지 말고, BACKUP/receipt.json의 files에 있는 적용
파일을 검토해 실제 DEV checkout에 commit합니다. 새 로그 모듈, engine JSON,
PIPELINE, CODE_MANIFEST도 포함합니다. git diff --check와 git status를 확인합니다.

현장 출력으로 채울 값:
TASK_BACKUP = 이번 apply가 출력한 BACKUP 절대경로
GENOS_GENERATION = 코드서빙이 실제 선택한 기존 generation 절대경로
CM을 적용한 경우 00_SYSTEM/GENOS_SERVING_PATHS.json의 generation과 manifest 해시를
사용하되 실제 코드서빙이 같은 경로를 선택하는지 별도로 확인합니다.

export TASK_BACKUP='/이번_apply가_출력한_BACKUP_절대경로'
export GENOS_GENERATION='/현재_코드서빙의_선택_generation_절대경로'
bash GENOS_RAG_PROGRESS_GRAPH_20261008_R3_RUN.txt gate "$TASK_BACKUP" --generation "$GENOS_GENERATION"

gate는 commit된 동일 DEV와 APPLIED_CODE.zip의 파일을 대조하고 그 checkout의
Python으로 generation E2E와 verify_assets를 실행합니다. 다른 후보 폴더의 PASS를
push할 코드의 PASS로 옮기지 않습니다. 통과 후 수정하면 다시 commit/gate합니다.
통과한 commit을 기존 origin에 push한 뒤 새 코드서빙 리비전을 배포합니다.
그 리비전의 commit, 선택 generation 절대경로·manifest SHA, 표시 R9를 확인합니다.
apply, commit, gate, push, 리비전 배포, 화면 성공은 각각 별도 상태입니다.
