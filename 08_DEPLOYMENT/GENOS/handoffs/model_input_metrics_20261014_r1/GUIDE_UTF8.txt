GENOS MODEL_INPUT_METRICS R1 — 입력 길이 측정과 최종 실패 로그 복구

적용 목적
- 매 물리 모델 호출의 시스템/사용자 메시지 문자 수, UTF-8 바이트, 전체 메시지 JSON 및 응답 스키마 크기를 기록합니다.
- 응답의 실제 prompt_tokens/completion_tokens, 요청 max_tokens, finish_reason을 같은 attempt_id와 source_stage로 연결합니다.
- length_diagnosis=output_cap_reached: length 종료이며 실제 출력 사용량이 요청 출력 상한 이상입니다.
- length_diagnosis=length_stop_cause_unknown: length 종료이지만 출력 상한 도달을 입증하지 못했습니다.
- context_limit_known=false: 내부 모델의 실제 컨텍스트 설정을 아직 모릅니다. 입력 문자 수나 JSON 바이트를 토큰 수로 간주하지 않습니다.
- request_bytes는 canonical_json 기준의 재현 가능한 요청 크기입니다. HTTP 전송 인코딩/프로바이더 채팅 템플릿의 실제 바이트/토큰과 다릅니다.
- input_content_chars는 메시지 내용 합계이며 response_format 크기는 별도입니다. 모델 입력에는 시스템 지침·문서·메뉴·수정 요청도 포함됩니다.

최종 로그 수정
최근 실패 응답의 message/answer_status/failure_reason/error_code가 기존 최종 로그에서 빠지던 문제를 수정합니다.
SERVICE OUTCOME을 서비스 반환 시 비동기 로그 큐에 넣고, FINAL RESPONSE / ANSWER와 최종 TXT에도 상태와 실패 안내를 보존합니다.
answer_present=false와 final_text_kind=failure_guidance를 통해 실패 안내를 생성한 법률 답변으로 혼동하지 않게 합니다.
공개 실패 응답에 run_id가 없어도 같은 request_id의 수집 이벤트에서 실행 원장을 찾아 상세 JSON에 연결합니다.
다른 요청의 최신 파일을 추측해 연결하지 않습니다. delivery_confirmed=false는 플랫폼 화면 도착을 서버가 인증하지 않았다는 뜻입니다.

원문·프롬프트·출력 한도·모델·재시도 정책·검증 및 최종 답변 정책은 변경하지 않습니다.
이번 패치는 length의 원인 진단과 로그 누락 수정이며, 해당 GENOS 질의의 성공을 인증하지 않습니다.
로컬 작업 코드와 현장 인계본만 변경합니다. 로컬 선택 MAIN61과 GENOS 현장 배포는 별도입니다.

선행 상태
AD_REQUEST_LOGS R2와 ASSESSMENT_GAP_ACTION R2가 적용된 기존 ~/DEV를 대상으로 합니다.
SUCCESSFUL_SHORTCUT R1 및 PUBLIC_FAILURE_GUIDANCE R1 적용 여부를 각각 지원하며 기존 설정과 조사 예산을 보존합니다.
1320개 알려진 코드 inventory 외의 수정은 덮어쓰지 않고 거부합니다.
PUBLIC_FAILURE_GUIDANCE R1을 함께 설치할 예정이면 그 패치를 먼저 적용한 뒤 이 패치를 적용하세요.
원문/NFS generation 재구축, DB 변경, 워크플로우 편집기 교체는 없습니다.

1. 기존 ~/DEV에 백업 후 적용
업로드 위치가 ~/TRANSFER인 예입니다. ZIP 위치만 실제 경로로 바꿉니다.

python3 -m zipfile -e ~/TRANSFER/GENOS_MODEL_INPUT_METRICS_20261014_R1.zip ~/DEV/TRANSFER/model-input-metrics-r1-package
bash ~/DEV/TRANSFER/model-input-metrics-r1-package/GENOS_MODEL_INPUT_METRICS_20261014_R1_RUN.txt check
bash ~/DEV/TRANSFER/model-input-metrics-r1-package/GENOS_MODEL_INPUT_METRICS_20261014_R1_RUN.txt apply

독립 RUN.txt는 ZIP을 풀지 않고도 실행할 수 있는 같은 설치기입니다.
첫 단계부터 지속 로그와 실패 종료 상태를 기록합니다. Python 경로/버전, CHECK PASS, CODE_APPLIED, EXIT=0,
BACKUP 및 APPLIED_CODE_ZIP 경로를 보관하세요. 재실행은 ALREADY_APPLIED로 종료합니다.
소스 네 파일과 사용하는 엔진 pin/PIPELINE/CODE_MANIFEST를 함께 갱신합니다.
미확인 파일 변경을 강제 rehash하거나 승인된 inventory처럼 만들지 않습니다.

2. 같은 checkout에서 commit 및 generation 검증
cd ~/DEV
git diff --check
git status --short

BACKUP/receipt.json의 변경 파일을 검토하고 같은 checkout에 commit합니다.
다음 값은 apply 출력과 실제 선택된 generation의 절대경로로 바꿉니다.

TASK_METRICS_BACKUP='/실제/apply/출력의/backup-경로'
TASK_METRICS_GENERATION='/현재/선택된/generation/절대경로'
bash ~/DEV/TRANSFER/model-input-metrics-r1-package/GENOS_MODEL_INPUT_METRICS_20261014_R1_RUN.txt gate "$TASK_METRICS_BACKUP" --generation "$TASK_METRICS_GENERATION"

같은 committed checkout과 APPLIED_CODE.zip·선택 generation이 게이트를 통과한 뒤 그 commit을 기존 팀 remote로 push합니다.
그 commit/generation을 선택한 새 코드서빙 리비전을 배포하고 별도 SSE 서버도 같은 코드로 재시작합니다.
Git push, 코드서빙 리비전, SSE 재시작, 실제 질의 성공은 각각 별도 상태입니다.

3. 워크플로우 테스트 화면에서 확인
기존 실패 질문을 새 요청으로 실행합니다. 기존 완료 원장/실패 이력은 삭제하지 않습니다.
같은 요청의 legal_agent 공유 로그에서 다음 항목을 확인합니다.
- model.attempt.started: input_metrics_revision=model-input-metrics-20261014-r1, input_content_chars, max_tokens, attempt_id, source_stage
- model.attempt.received 및 model.output.invalid: prompt_tokens, completion_tokens, prompt_plus_max_tokens, finish_reason, length_diagnosis
- SERVICE OUTCOME / FINAL RESPONSE / ANSWER: answer_present, final_text_kind, answer_status, message, failure_reason
- 같은 이름의 .llm_raw.jsonl: input_metrics 및 모델 수신 원문
- 같은 이름의 .json: run_id_basis=captured_event인 실패에도 journal.status=FOUND인지 확인
실제 입력 토큰은 응답 usage가 있어야 확인됩니다. 응답이 없거나 usage가 누락되면 null/미확인으로 남습니다.
finish_reason=length만으로 입력 컨텍스트 초과를 확정하지 않습니다. 해당 모델의 실제 서빙 컨텍스트 설정과 함께 판단합니다.
HTTP 200/transport_status=SUCCEEDED는 전송 성공입니다. 탐색의 ADOPT/FINISH 원응답이나 실패 안내를 검증된 최종 답변으로 간주하지 않습니다.

실제 commit, generation 절대경로/manifest SHA256, 코드서빙 리비전, 요청 ID와 최종 로그를 함께 보관하세요.
이 외부 Codex 세션에서는 GENOS에 접속하지 않았으며 현장 내부 모델과 배포 결과는 미확인입니다.

4. 원복
현재 코드가 적용 결과와 같을 때만 백업을 원복합니다. 후속 수정이 있으면 덮어쓰지 않고 중단합니다.

bash ~/DEV/TRANSFER/model-input-metrics-r1-package/GENOS_MODEL_INPUT_METRICS_20261014_R1_RUN.txt undo "$TASK_METRICS_BACKUP"

이전 검증 commit의 코드서빙 리비전으로 복귀하고 SSE도 맞춥니다. 데이터 generation과 실패 이력은 유지합니다.
