GENOS 데이터 분할 → DEV → NFS → 워크플로우 목록: ZIP 인계 R3

이번에는 R3 ZIP을 사용하세요. 이전 R1 TXT 단독 인계를 대신하는 포장 변경입니다.
실행 코드와 NFS 경로는 검증한 R1 그대로입니다. ZIP 내부 RUN.txt와 별도 첨부
RUN.txt는 같은 바이트입니다. 별도 TXT를 Bash가 읽지 못하면 ZIP을 코드스페이스에
올리고 거기서 해제한 내부 RUN.txt를 사용합니다. 확장자는 .txt 그대로 둡니다.
코드 ZIP 안에는 실행 TXT, 안내, 분할/병합 TXT, 코드 manifest, SHA256SUMS.txt가 있습니다.
운영 데이터는 이 코드 ZIP에 포함하지 않습니다. 기존 데이터 .zip.parts 폴더를 별도로
~/DEV/TRANSFER에 올리고 모든 조각과 PARTS.sha256, ORIGINAL.sha256을 보존하세요.

1. 첨부 GENOS_TRANSFER_NFS_LIST_20261007_R3.zip을 대상 코드스페이스의 ~/DEV/TRANSFER에 올립니다.
   Windows에서 해제/재저장하지 않고 코드스페이스 터미널에서 해제합니다.

cd ~/DEV
python3 -m zipfile -e TRANSFER/GENOS_TRANSFER_NFS_LIST_20261007_R3.zip TRANSFER/GENOS_TRANSFER_NFS_LIST_20261007_R3
(cd TRANSFER/GENOS_TRANSFER_NFS_LIST_20261007_R3 && sha256sum -c SHA256SUMS.txt)

2. ZIP 안에서 꺼낸 실행 TXT로 검사합니다. 질문에는 실제 .zip.parts 폴더 이름을 입력합니다.

bash TRANSFER/GENOS_TRANSFER_NFS_LIST_20261007_R3/GENOS_TRANSFER_NFS_LIST_20261007_R3_RUN.txt inspect

사진에 있던 데이터 폴더를 그대로 사용한다면:
bash TRANSFER/GENOS_TRANSFER_NFS_LIST_20261007_R3/GENOS_TRANSFER_NFS_LIST_20261007_R3_RUN.txt inspect genos-rag-data-20261007T002029Z-7c0b050f.zip.parts

3. 변경 보고서를 검토하고 대상 RAG/AD 쓰기를 정상 종료한 뒤 복원/준비/push합니다.

bash TRANSFER/GENOS_TRANSFER_NFS_LIST_20261007_R3/GENOS_TRANSFER_NFS_LIST_20261007_R3_RUN.txt all --writers-stopped --accept-live-archive

실제 팀 문서명을 확인하려면 --team-id 실제팀명 을 추가합니다.
경로: /nfs-root/diamo/8-agent
generation: /nfs-root/diamo/8-agent/term-releases/financial-risk-success-20261005-schema-r2/generation
runtime: /nfs-root/diamo/8-agent/runtime
별도 state: 미설정

출력된 RUN_DIR/STATUS.json과 commit을 확인합니다. 코드서빙은 해당 commit으로
새 리비전을 배포하고 SERVING_ENV_PATHS.txt를 반영합니다. WORKFLOW_PASTE_ALL.txt
전체를 워크플로우 Python 단계에 별도로 붙여 넣고 워크플로우 테스트 화면에서 확인합니다.
기존 GENOS_BASE_URL, GENOS_CODESERVING_ID, 인증키 설정을 사용합니다.
코드 적용, NFS 복원, push, 코드서빙 리비전, 워크플로우 결과는 각각 확인합니다.

분할/병합 스크립트는 ZIP 안에 함께 넣었습니다. 이들은 기존 R4의 같은 바이트입니다.
bash TRANSFER/GENOS_TRANSFER_NFS_LIST_20261007_R3/SPLIT_TRANSFER_ZIP.txt
bash TRANSFER/GENOS_TRANSFER_NFS_LIST_20261007_R3/JOIN_TRANSFER_ZIP.txt "TRANSFER/자료.zip.parts"

기존 검증 코드의 기능 결과는 아래 R1 상세 안내를 따릅니다. R3는 포장 변경이며
ZIP 해제 뒤 해시/구문/실행 검사를 추가합니다. GENOS 현장 DRM/실행 성공은 미확인입니다.

----- 같은 실행 코드의 R1 상세 안내 (실행 경로는 위 R3 경로를 사용) -----
GENOS DEV -> NFS -> 코드서빙 -> 워크플로우 데이터 목록 확인

이번 R1 RUN TXT는 완전한 실행 스크립트입니다. TXT 확장자를 바꾸지 않습니다.
기존 ZIP 분할 R4의 .part000000 조각과 PARTS.sha256, ORIGINAL.sha256을 사용합니다.
이미 합친 데이터 ZIP을 지정해도 됩니다. 분할 전 원본과 내려받은 조각은 보존합니다.

최신 확인 경로를 그대로 사용합니다.
  NFS root: /nfs-root/diamo/8-agent
  generation: /nfs-root/diamo/8-agent/term-releases/financial-risk-success-20261005-schema-r2/generation
  runtime: /nfs-root/diamo/8-agent/runtime
  별도 state: 미설정
이 값은 GENOS.md의 현장 경로 확인 기록과 최종 NFS R7 인계에 근거합니다.
코드스페이스의 오래된 .env/CURRENT를 따라 선택하지 않습니다.

1. 대상 코드스페이스에 업로드

  ~/DEV/TRANSFER/GENOS_TRANSFER_NFS_LIST_20261007_R1_RUN.txt
  ~/DEV/TRANSFER/실제데이터.zip.parts/
      실제데이터.zip.part000000
      실제데이터.zip.part000001 ... 모든 조각
      PARTS.sha256
      ORIGINAL.sha256

DEV 바로 아래에 업로드해도 됩니다. 질문에는 DEV 기준 상대경로를 입력합니다.
위처럼 TRANSFER에 올렸으면 실제데이터.zip.parts 이름만 입력할 수 있습니다.
기존 데이터 ZIP 도구가 만든 DATA_MANIFEST.json/payload 구조가 있는 ZIP을 사용합니다.
임의 문서 ZIP은 이 복원 계약의 입력이 아닙니다.

2. 합치기/압축 해제와 보고서 확인

  cd ~/DEV
  bash TRANSFER/GENOS_TRANSFER_NFS_LIST_20261007_R1_RUN.txt inspect

질문이 나오면 실제 .zip.parts 폴더 이름 또는 실제 데이터 ZIP 파일명을 입력합니다.
모든 조각을 확인하여 ZIP을 합친 뒤 CRC를 검사하며 안전하게 압축을 풉니다.
실행 중 출력되는 SOURCE_CHANGES 보고서와 ARCHIVE_RESTORE_ELIGIBLE을 확인합니다.
터미널 보고서는 앞 12,000자 미리보기입니다. 보고서가 길면 출력된 SOURCE_CHANGES_REPORT
경로의 TXT 전체를 열어 검토합니다. 누락/세대 해시 오류가 있으면 복사 전에 차단합니다.
이 단계에서는 NFS 복사, 코드 수정, commit/push를 수행하지 않습니다.
해제 위치는 ~/DEV/TRANSFER/RAG_DATA_UNPACK/<ZIP의 전체 SHA256>/<묶음폴더>/입니다.
이전 Windows/PowerShell 분할의 JSON manifest와 R4 GNU 체크섬은 혼용하지 않습니다.

3. NFS 복원 + 진단 코드 적용 + commit/push

대상 RAG/AD 요청과 작업자의 쓰기를 정상 중지한 뒤 실행합니다.
--writers-stopped는 쓰기 중지 상태를 선언하며 프로세스를 자동으로 종료하지 않습니다.
변경 허용 R2 ZIP은 위 보고서를 검토했을 때만 --accept-live-archive를 지정합니다.

  bash TRANSFER/GENOS_TRANSFER_NFS_LIST_20261007_R1_RUN.txt all --writers-stopped --accept-live-archive

같은 ZIP/.zip.parts 이름을 질문에 입력합니다. 이미 합친/해제한 결과는 해시로 확인해 재사용합니다.
팀의 문서명까지 확인하려면 해당 실제 팀 폴더명을 추가합니다. risk_team이 대상인 예:

  bash TRANSFER/GENOS_TRANSFER_NFS_LIST_20261007_R1_RUN.txt all --writers-stopped --accept-live-archive --team-id risk_team

팀을 생략하면 generation/runtime의 실제 파일·폴더 목록을 표시합니다.
팀을 지정하면 같은 generation store.sqlite의 document 표에서 그 팀과 aliases에 속한
문서 ID/이름을 페이징해 표시합니다. 다른 팀 문서명은 포함하지 않습니다.
팀 선택은 접근권한을 새로 부여하지 않으며 기존 코드서빙 호출 권한 안에서 검사합니다.
존재하지 않는 팀은 커밋 전에 실패합니다. 팀 이름을 날짜/폴더명으로 추측해 선택하지 않습니다.

이 실행은 기존 복원 도구를 사용해 payload/nfs-root/diamo/...를 동일 절대경로에 복사합니다.
복사 전에 전체 입력 해시·기존 대상 파일 충돌을 검사합니다. 동일 파일은 유지하고,
다른 내용의 기존 파일, 링크, DB sidecar, 복원 불가 ZIP은 보존한 채 중단합니다.
manifest/DB 내부 경로/SHORTCUT_CURRENT 등은 기존 바이트대로 보존합니다.
실제 /nfs-root/diamo의 NFS 마운트가 보이지 않으면 로컬 폴더를 만들어 복원하지 않습니다.
GB 데이터는 합치기·해시·해제·복사에 시간이 걸립니다. 원본/합친 ZIP/해제본/대상 복사 공간이 필요합니다.

코드는 기존 DEV Git checkout에 백업 후 작은 NFS 진단 훅과 helper만 적용합니다.
R1/R2/R6/R7의 알려진 helper 바이트를 허용하며 임의의 현장 수정은 덮어쓰지 않습니다.
기존 RAG 코드, 원문, 데이터 generation/CURRENT, 모델 설정은 새 버전으로 재구축하지 않습니다.
관련 없는 Git staged 파일/추적 파일 수정이 있으면 보존하고 중단합니다.
기존 Git 사용자 설정·브랜치·origin 인증을 사용하며 force push는 하지 않습니다.

4. 출력된 정확한 commit을 코드서빙 리비전으로 배포

RUN_DIR/STATUS.json의 steps.prepare.status=PREPARED_AND_COMMITTED,
steps.push.status=PUSHED를 각각 확인합니다. commit 값은 터미널과 STATUS에 나옵니다.
push만으로 코드서빙이 바뀌지 않습니다. 코드서빙 화면에서 그 commit을 선택해 배포합니다.
기존 실행 진입점은 유지합니다. 기존 /json -> service(config,data)의 NFS_DATA_PROBE를 사용합니다.

같은 RUN_DIR에 생성한 SERVING_ENV_PATHS.txt를 해당 코드서빙 리비전 환경변수에 반영합니다.
  GENOS_GENERATION=<위에 적힌 정확한 generation>
  GENOS_RUNTIME_DIR=/nfs-root/diamo/8-agent/runtime
  GENOS_STATE_DIR=빈 값
  GENOS_AUTO_WARMUP=0
  AD_WORKER_ENABLED=0
  GENOS_NFS_LIST_TEAM_ID=<지정한 팀, 생략했다면 빈 값>

코드서빙에도 같은 NFS 볼륨을 /nfs-root/diamo에 연결하고 읽기 권한을 확인합니다.
코드스페이스에만 마운트하거나 경로 문자열만 설정해도 코드서빙에 자동 공유되지 않습니다.
기존 LLM/임베딩·코드서빙 키를 삭제하지 않습니다. 진단 중에는 모델을 호출하지 않습니다.
검사가 끝나 실제 RAG 운영을 재개하면 기존 warmup/AD 설정을 복원합니다.

5. 별도 테스트 워크플로우에서 목록 호출

같은 RUN_DIR의 WORKFLOW_PASTE_ALL.txt 전체를 워크플로우 Python 단계에 붙여 넣습니다.
진입점은 run(data)입니다. TXT는 그 실행의 검사 ID와 commit을 이미 포함합니다.
코드스페이스의 Python 파일 복사나 Git push로 워크플로우 편집기가 바뀌지는 않습니다.
기존 운영 워크플로우 Python은 백업하고 별도 테스트 워크플로우를 사용합니다.

워크플로우 실행 환경에는 기존 실제 값을 설정합니다.
  GENOS_BASE_URL: 기존 내부 플랫폼 base URL
  GENOS_CODESERVING_ID: 위 commit을 배포한 코드서빙 ID (모델 ID 아님)
  GENOS_CODESERVING_TOKEN 또는 GENOS_CODE_KEY: 그 코드서빙 인증키
키를 코드·메일·로그에 붙이지 않습니다. URL/ID/키는 현장 값이며 인계본에서 임의로 만들지 않았습니다.

워크플로우 테스트 화면에서 임의 문장을 입력하고 실행합니다.
Python 단계가 /api/gateway/code_serving/<ID>/json에 NFS_DATA_PROBE 요청 한 번을 보내고
읽기 검증 및 파일/폴더 목록, 지정한 팀의 문서 목록을 최종 text로 반환합니다.
입력 문장이나 내부 원문 본문은 진단 요청/메일로 보내지 않습니다.
기본 문서 페이지는 offset=0, limit=100이고 상한은 200입니다. Python 단계 입력에
offset/limit 정수가 들어오면 해당 페이지를 조회합니다. 원문 본문은 화면/메일로 반환하지 않습니다.
generation/runtime 폴더는 바로 아래 항목을 상한 내에서 표시하고 잘린 목록은 표시합니다.

PASS 기준:
  화면 첫 줄: NFS 데이터 읽기 검사 PASS
  nfs_probe_pass=true
  코드 해시=준비 commit의 바이트=NFS에 보관한 코드 바이트
  실제 코드서빙 generation/runtime/team 환경=준비 설정
  generation/navigation/fulltext/glossary metadata·SQL 읽기 성공
  generation/runtime 목록 표시, 팀 지정 시 실제 해당 팀 문서명 표시
HTTP 200, Git push, 코드스페이스 성공만으로 현장 전체 PASS라 하지 않습니다.
실제 코드서빙 리비전 ID와 워크플로우 요청 ID/결과를 현장 완료 기록에 남깁니다.

6. 재개/실패/복귀

RUN_DIR/RUN.log, STATUS.json, EXIT_STATUS.json에 시작부터 단계와 실패 상태를 남깁니다.
NFS 복원이 중단됐으면 원본/부분 결과를 유지하고 같은 명령으로 재검사합니다.
복원만 반복하려면 all 대신 restore, 이미 복원한 NFS에서 코드 준비만 하려면 deploy를 씁니다.
준비된 같은 commit push만 재시도하려면 push를 씁니다.
코드스페이스 목록 재검사는 list-local입니다. --no-push는 코드 준비까지만 실행합니다.
prepare를 다시 하면 새 검사 ID/commit을 만들므로 새 WORKFLOW_PASTE_ALL.txt를 사용합니다.
설치 전 코드는 RUN_DIR/install/before에, 변경 파일 해시는 STATUS의 steps.install에 남습니다.
데이터 충돌/해시 실패를 파일 삭제나 manifest/해시 수정으로 우회하지 않습니다.
배포 문제는 이전 코드서빙 리비전·기존 환경변수·백업 워크플로우 Python으로 복귀합니다.
원본 데이터와 진단 폴더, Git 이력은 자동으로 삭제하지 않습니다.

검증 범위:
로컬 모의 ZIP/NFS/Git remote/HTTP 게이트웨이로 실행 스크립트와 연결을 검증했습니다.
실제 GENOS 접근, 실제 데이터 복원, 현장 push/리비전 배포/워크플로우 화면은 미확인입니다.
간이 검사는 파일·SQL 읽기와 코드/선택 경로 대조이며 RAG 답변 품질·내부 모델 성능·
NFS 다중 서버 쓰기 내구성 인증을 대신하지 않습니다. 코드서빙 직접 테스트 UI/API는 요구하지 않습니다.
