GENOS 채팅의 접이식 에이전트 행위 로그 복구 R2 — 2026-10-08

이번 적용 위치는 기존 분리 워크플로우의 Python 편집기입니다.
기존 R5 코드 ZIP과 별도 SSE 서버를 유지하고 편집기의 전체 Python만 교체합니다.
실행 중 에이전트 행위를 agentFlowExecutedData / Visible Reasoner 카드로 보내며
최종 답변 전에 접어서 확인할 수 있는 기존 송신 경로를 복구했습니다.
자료 준비를 기다리는 AD_PROBE 전에 첫 '준비 중' 카드가 나옵니다.
SVG R10과 현재 판단 상세 R2는 포함합니다.

1. 인계 파일 준비
ZIP 또는 별도 PREPARE TXT를 기존 ~/DEV/TRANSFER에 올립니다.
완전한 실행 TXT를 아래처럼 실행하면 ZIP 바이트를 검증하고 편집기용 파일을
~/DEV/TRANSFER/workflow-live-cards-r2-editor에 준비합니다.

bash ~/DEV/TRANSFER/GENOS_WORKFLOW_LIVE_CARDS_20261008_R2_PREPARE.txt

ZIP을 직접 풀어도 동일합니다. unzip 설치가 필요하지 않습니다.
python3 -m zipfile -e ~/DEV/TRANSFER/GENOS_WORKFLOW_LIVE_CARDS_20261008_R2_EDITOR.zip ~/DEV/TRANSFER/workflow-live-cards-r2-editor
bash ~/DEV/TRANSFER/workflow-live-cards-r2-editor/VERIFY_EDITOR_FILES.txt

PREPARE의 EDITOR_FILES_READY / VERIFY의 EDITOR_FILES_VERIFIED / EXIT=0을 확인합니다.
PREPARE 로그는 TRANSFER/workflow-live-cards-r2-logs에 지속 저장합니다.
파일 준비는 편집기 저장·서버 배포·실제 화면 성공과 별도입니다.
기존 다른 바이트나 링크가 있으면 보존 후 중단합니다.

2. 워크플로우 Python 전체 교체
먼저 현재 편집기 Python 전체를 원복용으로 저장합니다.
GENOS_WORKFLOW_LIVE_CARDS_20261008_R2_PASTE_ALL.txt 전체를 같은 Python 편집기에
붙여넣고 저장합니다. 진입점 run(data)는 유지합니다.
ZIP 적용·Git push만으로 편집기 Python이 갱신되지 않습니다.

Python 단계의 환경 설정:
GENOS_RAG_PROGRESS_UI=socketio

변수가 없으면 socketio가 기본입니다. 기존 on 값도 socketio로 연결합니다.
socketio는 처리 중 접이식 카드와 최종 답변을 보냅니다.
socketio-inline은 이전의 본문 진행 문구까지 함께 보내는 선택입니다.
final-cards는 완료 후 카드만, socketio-final은 최종 본문만, off는 진행 표시 끄기입니다.
실시간 카드를 원하면 socketio 또는 socketio-inline을 선택합니다.

화면 카드 송신은 기존 GENOS Python 워크플로우 런타임의
main_socketio.sio_server.emit과 채팅 입력의 socketIOClientId를 사용합니다.
입력 ID를 임의 생성하지 않습니다. 기존 채팅 앱과 워크플로우 연결을 유지합니다.
별도 SSE 서버의 endpoint/ID/token/port/시작 명령과 코드서빙 옵션은 기존 값을 유지합니다.

3. 워크플로우 테스트 화면에서 확인
WORKFLOW_SETTINGS를 입력합니다.
workflow_revision=rag-v6-live-cards-20261008-r2
live_progress_revision=workflow-live-cards-20261008-r2
progress_mode=socketio / socketio_enabled=true를 확인합니다.
socket_client_id_present는 실제 채팅 입력의 socketIOClientId 존재 여부입니다.
SSE_CHECK에서 sse_ready=true와 route=/stream을 확인합니다.

실제 질문을 입력해 최종 답변 전에 '준비 중' 카드가 나오고, 이후 원문 확인·
근거 선택·현재 판단 카드가 접어서 볼 수 있는 형식으로 추가되는지 확인합니다.
반환된 workflow_progress_delivery.emitted_card_events는 실제 카드 송신 횟수입니다.
socket_error_type이 있으면 워크플로우의 workflow.progress.socket_failed 로그를 확인합니다.
code_serving_transport.progress_events는 SSE 수신 횟수이므로 카드 송신과 구분합니다.
워크플로우 테스트 런타임에 socketIOClientId가 없는 경우에는 최종 카드 JSON만
반환할 수 있습니다. 필드는 실제 입력/출력으로 확인합니다.
현장 질의와 warmup은 워크플로우 테스트 화면에서만 수행합니다.

4. 원복과 범위
원복은 2번에서 저장한 이전 편집기 Python 전체를 같은 단계에 다시 붙여 저장합니다.
이번 PREPARE/VERIFY는 TRANSFER에 편집기용 파일을 준비하는 작업입니다.
기존 DEV backend·NFS generation/CURRENT·DB·CM·조사 예산·오류 로그·MAIN45는 유지합니다.
코드서빙 리비전이나 NFS 데이터 재구축은 이번 편집기 복구의 적용 단계가 아닙니다.
로컬 모의 검증은 VALIDATION_SUMMARY.txt와 VALIDATION.json에 있습니다.
GENOS 실제 편집기 저장·채팅 카드 렌더링 성공은 아직 미확인입니다.
