1. 워크플로우 Python 편집기
WORKFLOW_REVIEW_FOLLOWUP_PASTE_ALL.txt의 전체 내용을 기존 코드와 교체한 뒤 저장·배포합니다.
원문은 출처 버튼 → 개별 원문 클릭으로 펼쳐집니다. 정상 답변은 먼저 표시합니다.
검토 실패 시 실패한 항목과 같은 대화에서 보낼 재검토 요청 문장을 표시합니다.
실제 사건 사실이 필요한 항목은 별도로 표시합니다. 자동 재송신은 하지 않습니다.

2. 최신 MAIN140 코드서빙을 사용 중이면 백엔드도 함께 반입
MAIN140에는 상세 검토 실패의 멀티턴 전달과 일부 검토 연결 수정이 빠져 있습니다.
워크플로우만 교체하면 서버가 제공하는 기존 실패 설명까지 표시할 수 있으나,
상세 실패 분류와 ASSESS 재개 문맥을 함께 적용하려면 다음 두 파일을 TRANSFER에 넣습니다.
REVIEW_FULL_ORACLE_20261104_R1.zip
REVIEW_ONECLICK_R1.txt

해당 TRANSFER 폴더에서 실행:
bash REVIEW_ONECLICK_R1.txt

기존 ~/DEV가 가리키는 checkout에 백업 후 적용·엔진 검증합니다.
완료 표시는 REVIEW_ONECLICK_DONE입니다. 설치 후 기존 commit/push와 코드서빙 새 리비전 배포를 진행합니다.
설치 자체가 Git push나 현장 배포를 대신하지 않습니다.
시작 명령은 python3 08_DEPLOYMENT/GENOS/start_sse.py 그대로입니다.
기존 Oracle/LLM/임베딩 환경변수와 원문 데이터는 유지합니다.

선택 기능:
bash REVIEW_ONECLICK_R1.txt check
bash REVIEW_ONECLICK_R1.txt status
bash REVIEW_ONECLICK_R1.txt stage
bash REVIEW_ONECLICK_R1.txt gate-code

3. 워크플로우 테스트 화면에서 확인
SSE_CHECK 결과의 answer_display_revision: workflow-review-followup-20261104-r1
같은 채팅에서 질문 → 검토가 실패하면 화면의 실패 항목 확인 → 안내된 재검토 문장을 새 메시지로 전송합니다.
예: 방금 실패한 답변 검토를 이미 확보한 원문을 재사용해서 다시 해줘. 주장과 근거의 연결을 확인하고, 질문에 대한 설명과 남은 미확인을 함께 알려줘.
같은 chatId/session_id를 유지해야 이전 질문과 실패 기록을 이어받습니다.
같은 request_id 재조회는 기존 결과 조회이며 재검토가 아닙니다. 채팅의 새 메시지는 새 요청입니다.
권한·근거·기한·예산 검증을 통과한 범위에서 재개하며 재검토 성공을 보장하지 않습니다.
