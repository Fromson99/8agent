GENOS urllib 전송 전환 — 변경 경계와 실패 계약

입력/소비자: 기존 genos.request_json과 GenosTransport의 모델 목록·JSON·임베딩·SSE를
stdlib_http로 연결한다. gateway, 모델 파서, 검증기, 답변 표시/저장 소비자는 기존 계약을 사용한다.
모델·URL·권한·프롬프트·출력 상한을 바꾸는 실험이 아니라 기존 검증 전송의 현장 통합이다.

인증서/호스트명: Python 기본 CA 정책으로 검증하며 미신뢰·이름 불일치는 요청을 차단한다.
자동 CA 추측·검증 해제·다른 endpoint/model fallback은 하지 않는다.
HTTP 3xx: 다른 주소로 인증값을 전달하거나 POST를 다시 보내지 않는다.
HTTP 4xx/5xx: 상태/원문/Retry-After를 원래 실패 envelope에 보존한다.
timeout/연결 종료: 전송 결과 불명을 유지하며 전체 deadline 이후 추가 send와 토큰 송신을 막는다.
SSE: 기존 ModelEventStream의 DONE/EOF/length/content_filter/오류 계약을 보존한다.
부분 전송 후 실패: 이미 송신된 이벤트·사용량·실패 원장을 남기며 재생성 답변을 이어 붙이지 않는다.
전송 보정: 허용된 의미 보정 없음. 모델 제안/JSON/근거/상태 검증은 변경하지 않는다.

재시도 책임: GenosTransport의 send_once/send_stream_once는 각각 한 물리 전송이다.
에이전트 재시도는 기존 gateway가 같은 요청 예산·deadline 안에서 결정한다.
공통 genos.request_json은 기존 설정의 유한한 max_retries/429·5xx 정책을 유지한다.
새 재시도 계층을 추가하거나 실패를 성공으로 변환하지 않는다.

설치: 전체 선행 inventory/hash/엔진 pin/스키마 연결을 확인한 후 변경한다.
백업 및 PREPARED receipt를 첫 코드 쓰기 전에 생성한다. 중단/재실행/원복은 같은 바이트로 검증한다.
알 수 없는 코드·기존 helper·후속 수정·변조된 백업을 강제로 덮어쓰지 않는다.
같은 committed checkout의 코드 ZIP/generation gate 이후 별도 리비전 배포와 SSE 재시작을 진행한다.

검증: 실제 localhost TLS로 신뢰 CA 성공·미신뢰 거부·호스트명 오류, JSON/SSE,
redirect/중복 send/timeout/부분 실패를 검사한다. 인계 설치본의 service.service에서
미신뢰 TLS 부팅 실패와 올바른 CA 지정 후 HEALTH/모델 목록 조회 성공을 검사한다.
외부망과 실제 GENOS 내부 모델에는 접속하지 않는다. 현장 성공은 워크플로우 화면 검증 전까지 미확인이다.

남은 범위: 실제 GENOS CA 저장소/리비전/내부 모델, 운영 전체 복구 경로와 기존 테스트 불일치,
이전 실패 기록의 의미 판정, 데이터 품질은 이번 패치의 완료/인증 범위가 아니다.
