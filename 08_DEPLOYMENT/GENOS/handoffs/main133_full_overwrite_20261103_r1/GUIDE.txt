4. 코드서빙 배포
실행기의 기본 동작은 코드 적용까지입니다. 기존 배포 절차에 따라 변경을 확인합니다.
  git -C ~/DEV diff --check
  git -C ~/DEV diff --stat
선택된 코드 바이트를 임의 정리하거나 엔진 pin을 다시 쓰지 않습니다.
TRANSFER의 COMMIT_PATHS.txt에 든 516개 대상만 기존 DEV에서 stage/commit합니다.
아래 명령은 TRANSFER에서 실행하며, 대상 밖 staged 변경이 있으면 먼저 멈춥니다.

python3 - <<'PY'
import json, subprocess
from pathlib import Path
package = Path('GENOS_MAIN133_FULL_OVERWRITE_20261103_R1')
root = Path.home().joinpath('DEV').resolve(strict=True)
paths = json.loads((package / 'PACKAGE.json').read_text())['patch']
staged = subprocess.check_output(['git','-C',str(root),'diff','--cached','--name-only','-z']).decode().split('\0')
if set(filter(None, staged)) - set(paths):
    raise SystemExit('대상 밖 staged 변경이 있습니다. 기존 작업을 확인하세요.')
subprocess.run(['git','-C',str(root),'add','--',*paths],check=True)
subprocess.run(['git','-C',str(root),'diff','--cached','--stat'],check=True)
PY

검토 후 기존 절차로 commit합니다. 이미 동일 커밋이면 빈 커밋을 만들지 않습니다.
  git -C ~/DEV commit -m 'Apply MAIN133 scenario-cumulative-20261102-r1'
  bash ./GENOS_MAIN133_FULL_OVERWRITE_20261103_R1_RUN.txt gate-code
GENOS_RELEASE_GATE PASS 및 CODE_CHECK PASS의 commit/manifest hash를 기록합니다.
기존 실제 NFS generation을 사용하는 환경에서는 같은 checkout으로 추가 검사합니다.
아래 실제_GENERATION_절대경로만 사용자가 현재 선택 경로로 바꿉니다.
  python3 ./GENOS_MAIN133_FULL_OVERWRITE_20261103_R1/genos_release_gate.py --code-zip ./GENOS_MAIN133_FULL_OVERWRITE_20261103_R1/code.zip --deploy-root ~/DEV --generation '실제_GENERATION_절대경로'
Oracle 환경에 로컬 SQLite generation 경로를 억지로 지정하지 않습니다.
기존 원격으로 검증한 commit을 push하고, GENOS 코드서빙 화면에서 같은 commit으로
리비전을 배포합니다. 원격 주소·리비전·generation 경로는 현장 값을 사용합니다.
현재 설정 DP, Oracle 매핑·권한, NFS 로그 경로, 내부 모델 설정을 유지합니다.
신규 DB DDL이나 데이터 재적재는 이번 실행에 포함되지 않습니다.
