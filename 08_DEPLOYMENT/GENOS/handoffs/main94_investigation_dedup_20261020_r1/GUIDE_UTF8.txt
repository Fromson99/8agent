MAIN94 — 반복 검색·자동 추가 조사 수정
2026-10-20 / GENOS_MAIN94_INVESTIGATION_DEDUP_20261020_R1

이번 ZIP은 MAIN93 누적본에 대사 workflow 1.20.1 수정을 반영한 MAIN94입니다.
앞서 발송한 GENOS_MAIN93_INTERNAL_ANCHOR_20261020_R1 코드 ZIP 대신 사용합니다.
MAIN93을 아직 적용하지 않은 기존 checkout에도 누적 적용하며 이전 기능을 포함합니다.
기존 데이터·승인 관계·조사 기록·환경 설정은 보존합니다.

수정한 세 가지
1. 대사 전용 원문 조사도 일반 RAG와 같은 중복 검색 검사를 거칩니다.
   같은 검색어/같은 범위는 실행 전에 차단하고 기존 한 번의 수정 기회만 사용합니다.
   계속 잘못 제안하면 확보 원문과 미확인 내용을 반환하며 예산을 초기화하지 않습니다.
2. 미확보 설명만으로 검색 과제를 자동 생성하지 않습니다.
   부모가 명시한 추가 조사만 실행하며 원문과 미확보 상태는 표/기록에 보존합니다.
3. 같은 근거의 인용 문구/범위 변경을 새 자료 확보로 취급하지 않습니다.
   실제 다른 근거·버전과 명시한 새 원문 조사는 기존 권한/예산 안에서 가능합니다.

대사 흐름
질문 → 관련 내규 원문 → LLM이 내규 개념·조항 범위 선정
→ 승인된 연결 외규 원문 우선 읽기 / 내규 원문을 단서로 외규 조사
→ 필요한 외규 간 참조·정의·조건·예외를 선택하여 추가 탐색
→ 내규 출처·조항 / 개념·확인 내용 / 내규 원문 /
   연결 외규 출처·원문 / 비교 해석·미확인 표.
승인 연결은 조회 대상을 정합니다. 외규 적용·부합 여부는 원문을 보고 판단합니다.
미승인 배치 후보는 조사 단서이며 승인 근거로 바뀌지 않습니다.
연결 전부를 무한히 읽지 않고 같은 요청의 시간·호출·중복·권한 검사를 유지합니다.

실행 위치와 적용 대상
ZIP과 TXT를 실제 업로드한 TRANSFER 폴더를 현재 위치로 두세요.
TRANSFER의 절대 위치를 가정하지 않습니다. 압축을 풀기 위해 DEV로 이동하지 않습니다.
설치 대상은 기존 ~/DEV Git checkout이며 링크이면 검증한 실제 경로로 적용합니다.
다른 checkout을 사용하는 경우 확인한 경로를 각 명령 뒤 --root /실제/checkout 에 지정합니다.
코드 ZIP은 원문·색인·관계 DB·실행 상태를 포함하지 않습니다.
기존 GENOS_SERVING_PATHS.json, 환경 설정, 데이터와 런타임은 유지합니다.

TRANSFER에서
python3 -m zipfile -e ./GENOS_MAIN94_INVESTIGATION_DEDUP_20261020_R1.zip ./GENOS_MAIN94_INVESTIGATION_DEDUP_20261020_R1
bash ./GENOS_MAIN94_INVESTIGATION_DEDUP_20261020_R1/GENOS_MAIN94_INVESTIGATION_DEDUP_20261020_R1_RUN.txt check
bash ./GENOS_MAIN94_INVESTIGATION_DEDUP_20261020_R1/GENOS_MAIN94_INVESTIGATION_DEDUP_20261020_R1_RUN.txt apply
bash ./GENOS_MAIN94_INVESTIGATION_DEDUP_20261020_R1/GENOS_MAIN94_INVESTIGATION_DEDUP_20261020_R1_RUN.txt status

python3 3.11 이상과 기존 requirements 의존성을 사용합니다.
실제 실행 Python 경로·버전은 로그로 남습니다.
sqlglot 30.23.0이 없을 때만 check 전에 아래 동봉 wheel 설치를 실행합니다.

인터넷 설치나 내부 모델 호출을 이 명령이 수행하지 않습니다.

apply는 기존 checkout의 검증 가능한 백업을 만든 뒤 코드를 적용합니다.
같은 명령 재실행은 적용 상태를 확인하며, 설치 중단은 기록된 백업으로 복구합니다.
이후 수정된 파일·손상된 백업은 덮어쓰지 않고 중단합니다.
TRANSFER/main94-investigation-dedup-r1-logs 에 첫 단계부터 로그와 .log.exit를 남깁니다.
패키지 폴더의 STATUS.json과 기존 checkout의 BACKUPS를 보존하세요.

현장 배포 — 코드 적용과 별도
1. 기존 checkout에서 변경 파일을 검토하고 필요한 코드만 commit합니다.
   다른 작업을 섞는 git add -A나 ignored 원문을 넣는 git add -f는 사용하지 않습니다.
   과거 코드 목록의 agent6/corpus 빌드 자료 6개는 이번 코드 목록에서 제외했습니다.
2. TRANSFER로 돌아와 commit한 실제 checkout을 검사합니다.
bash ./GENOS_MAIN94_INVESTIGATION_DEDUP_20261020_R1/GENOS_MAIN94_INVESTIGATION_DEDUP_20261020_R1_RUN.txt gate-code
3. 현재 현장이 명시된 SQLite/NFS generation을 사용하는 경우 같은 세대도 검사합니다.
   GENOS_SERVING_PATHS의 선택 세대가 있으면:
bash ./GENOS_MAIN94_INVESTIGATION_DEDUP_20261020_R1/GENOS_MAIN94_INVESTIGATION_DEDUP_20261020_R1_RUN.txt gate-sqlite
   설정이 없다면 확인한 실제 generation 경로를 --generation 인자로 지정합니다.
   Oracle 직접 조회 현장은 gate-code 뒤 현장의 기존 Oracle 연결·조회 릴리스 설정을
   유지하고 워크플로우 테스트에서 조회를 확인합니다. 전체 로컬 복원을 요구하지 않습니다.
4. 게이트를 통과한 같은 commit을 push하고 같은 commit의 코드서빙 리비전을 배포합니다.
   데이터 generation 생성·Oracle 채널 변경·push·리비전 배포는 설치기가 실행하지 않습니다.
5. 동봉 GENOS_MAIN94_INVESTIGATION_DEDUP_20261020_R1_WORKFLOW_PASTE_ALL.txt 전체를
   워크플로우 Python 단계 편집기에 반영하고 저장합니다. Git push와 별도 단계입니다.
   이미 MAIN93의 동일 편집기 본문을 적용했다면 내용은 같습니다.
   팀·세션 설정과 기존 인증 정보를 유지합니다.
6. 현장 검증은 워크플로우 테스트 화면의 새 채팅에서만 합니다.
   예: 대사: 유동성비율 관련 외규가 위험관리기준시행세칙에 어떻게 반영되어 있나요?
   내규 원문 → 개념·범위 → 연결 외규 → 대사표의 실제 양쪽 원문을 확인합니다.
   명시한 새 조사 없이 남은 미확보가 자동 재검색으로 이어지지 않는지 확인합니다.
   연결이 없는 항목은 조사 또는 미확인으로 남고 외규 부재로 단정하지 않아야 합니다.
   서빙 revision, commit, Python, 데이터/조회 릴리스, 요청 ID와 결과를 보관하세요.
