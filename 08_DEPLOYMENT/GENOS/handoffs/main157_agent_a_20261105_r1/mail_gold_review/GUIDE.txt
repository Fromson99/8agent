MAIN157 — Agent 기록 테이블을 모두 _A로 통일

현재 로컬 릴리스: agent-a-unified-20261105-r1 / MAIN157
MAIN156의 운영 Gold 수정과 기존 멀티턴 기능 위에 Agent 매핑만 변경했습니다.
제품 3파일 + 엔진/파이프라인 pin 31파일, 서빙 532파일입니다.
Gold 13테이블·원문 데이터·모델·기존 설정은 유지합니다.

1. Dataiku Oracle
첨부 AGENT_A_CREATE_ALL_R2.txt 전체를 Dataiku SQL 노트북의 새 Query 하나에 붙여넣고 부분선택을 해제한 뒤 RUN합니다.
R2는 DKU_END_STATEMENT로 PL/SQL 생성·검증 블록과 결과 조회를 분리합니다. 이전 R1 대신 이번 R2를 사용합니다.
이미 같은 _A 구조가 생성되어 있으면 동일 구조를 확인하고 기존 행을 유지합니다.
SIDDA.LGL_AGT_BODY_A / LGL_AGT_REC_A / LGL_AGT_RUN_A / LGL_EXEC_ST_A를 생성·검증합니다.
기존 _A_1 테이블과 행은 보존하고 자동 이관하지 않습니다.
기존 _A가 있으면 구조를 검증한 뒤 그대로 사용합니다.

2. GENOS 코드스페이스
다음 두 파일을 사용자가 올린 같은 TRANSFER 폴더에 둡니다.
  MAIN157_FULL_20261105_R1.zip
  MAIN157_ONECLICK_R1.txt
그 폴더에서 실행합니다. ZIP은 미리 풀지 않습니다.
  bash MAIN157_ONECLICK_R1.txt
기존 ~/DEV를 실제 checkout으로 해석하고 백업·코드 적용·엔진 검사를 수행합니다.
완료 표시는 MAIN157_ONECLICK_DONE 및 MAIN157_EXIT=0입니다.

변경 확인과 스테이징:
  bash MAIN157_ONECLICK_R1.txt status
  bash MAIN157_ONECLICK_R1.txt stage
  git -C ~/DEV diff --cached --stat
  git -C ~/DEV diff --cached --check
기존 절차로 commit한 뒤 확인합니다.
  bash MAIN157_ONECLICK_R1.txt gate-code
검증한 commit을 기존 절차로 push하고 그 commit의 새 코드서빙 리비전을 배포합니다.
설치 TXT는 Git push나 플랫폼 배포를 자동 실행하지 않습니다.
시작 명령:
  python3 08_DEPLOYMENT/GENOS/start_sse.py

코드서빙 환경변수에 다음을 명시합니다. 값은 실제 운영 연결에 맞춥니다.
  DP=oracle
  GENOS_ORACLE_TABLE_MAPPING=gold
  GENOS_ORACLE_GOLD_OWNER=<실제 운영 Gold 소유자>
기본 mapped는 별도 매핑입니다. ORDS_SCHEMA는 ORDS 별칭이며 Gold 소유자와 동일하다고 가정하지 않습니다.
GENOS ORDS 연결 계정이 _A 4개에 조회·저장할 수 있어야 합니다.
워커/워크플로우가 호출하는 코드서빙 ID와 이번 리비전의 서비스 ID가 같아야 합니다.
MAIN157_WORKFLOW.py는 기존 MAIN156 워크플로우와 같습니다. 이번 매핑 변경으로 편집기 교체는 필요하지 않습니다.
이전 MAIN152 등 더 오래된 워크플로우 사용 중이면 이 전체 파일로 편집기를 업데이트할 수 있습니다.

3. 확인과 원복
기존 워크플로우 테스트 화면에서 새 요청 ID로 질문합니다.
모든 매핑 모드의 Agent 대상은 _A입니다. 예전 _A_1 대화가 자동 이관되지는 않습니다.
코드와 DB 검사를 제거한 것이 아니므로 구조/권한 불일치는 계속 오류로 표시합니다.
원복이 필요하면 설치 출력의 백업 폴더를 지정합니다.
  bash MAIN157_ONECLICK_R1.txt undo --backup '출력된 백업 폴더 절대경로'
플랫폼 리비전은 기존 절차로 이전 리비전으로 되돌립니다.
SQL은 기존 테이블을 삭제하지 않으며 코드 원복과 DB 이력 선택은 별개입니다.

4. 범위
로컬 검증과 현장 배포는 별도입니다. 현장 GENOS/Dataiku에 직접 접속하거나 실행하지 않았습니다.
인증정보·원문 데이터는 ZIP에 없고, 기존 JavaScript 파일 1개는 해시만 확인합니다.
검증 상세 및 해시: VERIFICATION.json / SHA256SUMS.txt
