최근 스크린샷과 해결 범위 — 2026-10-14

1. hit has no own original blocks
원인: 자체 원문이 없는 구조 부모를 자기 본문 읽기로 실행하던 조건 불일치.
수정: 같은 source의 실제 자식 원문을 요청 subtree 범위 안에서 읽는다.
로컬 합성 원문과 API 정상 읽기/답변·중복 요청 검사를 통과했다. MAIN63과 이번 ZIP에 포함.
실제 사진의 source/hit/generation 및 현장 재질의 성공은 아직 미확인이다.

2. 원문 없는 DEPENDENCY / 잘못된 source_quote / 조사 미완료
수정: 전달된 원문이 없는 단계에서는 의존 조사 선택을 제한하고 원문 ref와 정확 인용을
검증한다. 허용된 담당만 한도 안에서 교정하고, 소진하면 원래 원인·상태를 유지한다.
잘못된 제안을 통과시키거나 법률 결론을 자동으로 만들어 해결하지 않는다.
MAIN63과 이번 ZIP에 앞선 의존 관계 복구 수정까지 포함했다.

3. JSON/schema/서로 충돌하는 판단과 finish_reason=length
기존 엄격 파싱·한 차례 교정·원문/상태 검증·부분 송신 UNKNOWN 계약을 유지한다.
이번 도구 실패 정책은 모델 gateway의 재시도를 중복 수행하지 않는다.
길이 제한 자체를 바꾸지 않았고 출력 압축은 보류했다. 모든 의미 오류가 사라졌다고 할 수 없다.

4. 현재도 남은 구형 검사 실패
결과 불명 호출의 자동 재실행 기대, 구 PIPELINE schema의 확장 필드 거부,
공개 응답의 내부 run_id 기대, 기본 구현 v5 기대 등4개는 이전 코드에서도 같은 원인이다.
이번 수정으로 해결했다고 보고하지 않는다. 전체 ADR graph의 과거8오류도 별도다.

5. 설계 후속 범위
사실 부족 질문의 새 terminal, 부분 사건 변경 멱등 receipt, 취소/전달 수명 관리,
출력 압축/부분 JSON 보정은 이번 P1~P3에 포함되지 않는다.

결론: 사진과 연결된 확인된 실행 조건 결함은 코드와 로컬 검사에서 고쳤다.
GENOS 배포 완료나 동일 질문의 실제 내부 모델 성공은 현장 워크플로우 재검증이 필요하다.

설치 모의 검사의 추가 확인: 구형 진행 화면이 허용 문서의 진단을 표시하는 기존 정책은
유지했다. 현재 compact-public 정책을 기대하는 검사1개가 두 구성 모두 패치 전/후
동일하게 실패한다. 다른 문서의 비공개 진단은 계속 제외된다. 이 실패를 통과로 바꾸지 않았다.
