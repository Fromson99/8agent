- 실행 오류, 미실행, 권한 거부, 결과 불명을 구분하고 원래 원인과 receipt를 남긴다.

- 실패한 읽기를 원문 부재나 성공 관측으로 저장하지 않는다. 읽기 사용량은 복원한다.
- 37개 선택 정책을 메뉴/실행/재개에 연결하고 예산/권한/원문/상태 검증을 보존한다.
- 사진의 hit has no own original blocks는 같은 source의 실제 자식 원문 subtree로 읽는다.
- 원문 없는 DEPENDENCY, 잘못된 인용과 과거 메뉴는 제한 교정 또는 명시 중단한다.
- 기존 공개 오류 안내, TLS 전송, 답변 SSE, 캐시, 숏컷 정책과 현장 예산을 유지한다.
- 현장에서 비활성인 wiki recall은 켜지 않는다. 그 미배송 모듈 변경은 이 패치에서 제외한다.

적용 위치
ZIP과 독립 RUN.txt를 실제 업로드한 TRANSFER 폴더를 현재 작업 위치로 둔다.
TRANSFER 절대 위치를 ~/TRANSFER나 ~/DEV/TRANSFER로 가정하지 않는다.
코드 적용 대상만 기존 Git checkout ~/DEV이며 GENOS_DEV_ROOT가 있으면 그 명시 경로다.
압축 해제/설치기 실행을 위해 먼저 DEV로 이동하지 않는다.

python3 -m zipfile -e ./GENOS_TOOL_RECOVERY_20261014_R1.zip ./tool-recovery-r1-package
bash ./tool-recovery-r1-package/GENOS_TOOL_RECOVERY_20261014_R1_RUN.txt check
bash ./tool-recovery-r1-package/GENOS_TOOL_RECOVERY_20261014_R1_RUN.txt apply
bash ./tool-recovery-r1-package/GENOS_TOOL_RECOVERY_20261014_R1_RUN.txt verify

한 단계라도 실패하면 다음 단계로 진행하지 않는다.
실행 시작부터 현재 TRANSFER/tool-recovery-r1-logs에 지속 로그와 exit 상태를 남긴다.
실제 Python 경로/버전, checkout 경로/commit, generation 정보를 기록한다.
apply가 출력한 BACKUP 절대경로를 저장한다. 이는 적용 대상 DEV 아래 백업 기록이다.
재실행 apply는 이미 적용된 파일을 확인하며 새 적용/백업/사용량 초기화를 하지 않는다.
ZIP 내부와 별도 첨부 RUN은 동일하며 전체 설치기와 해시 고정 패치가 들어 있다.
기존 원문 데이터·실패 원장·모델 설정을 삭제하거나 초기화하지 않는다.
원문/NFS generation 재구축은 필요하지 않다.

Git commit·generation gate·배포
1. 코드 적용 후 기존 DEV에서 git diff --check와 변경 내용을 검토한다.
   BACKUP/receipt.json의 files에 나오는 변경만 stage/commit한다. 다른 변경은 섞지 않는다.
2. 실제 선택 generation 절대경로를 확인한다. 파일명/날짜로 최신 generation을 고르지 않는다.
3. 다시 실제 TRANSFER에서 아래 두 따옴표 값을 현장 실제 값으로 바꿔 실행한다.

bash ./tool-recovery-r1-package/GENOS_TOOL_RECOVERY_20261014_R1_RUN.txt gate "apply가 출력한 실제 BACKUP 절대경로" --generation "현재 선택된 실제 generation 절대경로"

gate는 같은 DEV의 committed 코드와 BACKUP/APPLIED_CODE.zip, generation manifest/자산을 확인한다.
부분 패치 ZIP을 전체 코드 ZIP인 것처럼 게이트에 넣지 않는다. RUN gate가 올바른 ZIP을 사용한다.
검사 후 코드나 pin이 바뀌면 새 commit으로 gate를 다시 실행한다.
4. gate를 통과한 commit을 push하고 그 commit의 새 코드서빙 리비전을 배포한다.
   별도로 실행하는 답변 SSE 서버도 같은 코드로 재시작한다.
5. 새 리비전의 commit·generation 절대경로/manifest SHA-256을 기록한다.
코드 적용, commit, gate, push, 리비전 배포, 실제 질의 성공은 각각 별도 상태다.

현장 검증
질의/warmup은 워크플로우 테스트 화면에서만 실행한다.
이번 backend 패치로 워크플로우 Python 편집기를 추가 교체할 필요는 없다.
기존 성공 질문, 최근 사진의 실패 질문, 같은 실패 요청 재개를 각각 확인한다.
request ID, 실제 코드/프로필/데이터/스키마 binding, 도구 원인/실행/저장 상태,
미완료 대상, 누적 사용량과 최초 deadline이 유지되는지 기록한다.
정상 답변이 계속 발행되는지, 실패/일부 송신 답변을 성공 숏컷으로 저장하지 않는지 확인한다.
권한/해시/상태/결과 불명은 무조건 재호출하지 않는다.

남은 범위
finish_reason=length 자체 제거·모든 모델 의미 판단 성공은 보장하지 않는다.
출력 압축/부분 JSON 교정은 보류했다. 실제 사실 질문 terminal·부분 사건 변경 receipt·
명시 취소/연결 끊김/전달 수명 관리의 신규 구현은 후속 범위다.
기존 구형 검사4실패와 전역 ADR graph 과거8오류도 해결 항목으로 계산하지 않는다.
현장 내부 모델/동일 사진 질문의 성공은 이 로컬 검증으로 인증하지 않는다.

원복
새 요청 유입을 제한하고 진행 중 worker를 정리한 후 다음을 실행한다.

bash ./tool-recovery-r1-package/GENOS_TOOL_RECOVERY_20261014_R1_RUN.txt undo "apply가 출력한 실제 BACKUP 절대경로"

현재 파일이 적용 후 해시와 같을 때만 복원한다. 이후 변경이 있으면 보존한 채 거부한다.
원복 후 이전 검증 commit/리비전과 기존 generation을 다시 선택한다.
새 정책으로 기록한 진행 중 요청을 구 reader로 무조건 재개하지 않는다.
원문·실패 이력·사용량·저널은 삭제하지 않는다.

증거
CODE_MANIFEST.json / SOURCE_BINDING.json / VALIDATION.json / SHA256SUMS.txt.
ZIP SHA-256, 실제 검증 checkout, commit, generation 경로/manifest, 리비전과 현장 request ID를
하나의 인계 기록으로 남긴다. 외부 세션에서 현장에 접근하지 않았으며 미확인 값은 추정하지 않는다.

설치 모의 검사의 추가 확인: 구형 진행 화면이 허용 문서의 진단을 표시하는 기존 정책은
유지했다. 현재 compact-public 정책을 기대하는 검사1개가 두 구성 모두 패치 전/후
동일하게 실패한다. 다른 문서의 비공개 진단은 계속 제외된다. 이 실패를 통과로 바꾸지 않았다.
