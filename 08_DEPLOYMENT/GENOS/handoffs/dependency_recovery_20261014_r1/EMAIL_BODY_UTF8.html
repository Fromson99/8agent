사진에서 확인한 원문 의존 조사 오류와 재개 경로의 후속 수정본입니다.

이번 첨부 GENOS_DEPENDENCY_RECOVERY_20261014_R1을 사용하세요.
앞서 보낸 GENOS_SCHEMA_RECOVERY_20261014_R1 질의 패치가 적용된 기존 DEV 위에 설치하는 후속 패치입니다. 이미 적용한 선행 패치를 다시 실행할 필요는 없습니다. 새 패치 적용 뒤 구 패치를 재실행하지 마세요.

모델 HTTP 200 뒤의 SELECT 검증에서, 실제 전달 원문이 없는 상태의 DEPENDENCY 선택/부정확한 인용이 반복돼 중단했습니다. 이전 MAIN62는 공통 JSON·복구 처리를 추가했지만 이 조사 범위 제약은 남아 있었습니다. 사진만으로 실제 현장 배포 해시는 확정할 수 없습니다.

  • 현재 원문이 없으면 DEPENDENCY를 선택지에서 제외하고, 보정 요청에 잘못된 대상·필드·허용 원문을 구체적으로 전달합니다.
  • 최종 중단에 실제 원인을 남기고, 이미 소진한 보정·재개 예산을 유지합니다.
  • 같은 실패 요청의 검증된 재개에서 불필요한 최초 분류 호출을 막습니다.
  • 설치본 검사에서 추가로 발견한 현장 진단 소비자의 거절 내역/중단 사유 연결 누락도 복구합니다. 기존 traceback 표시 설정은 그대로 유지합니다.

정상 원문 인용·DIRECT 조사·기존 서빙/TLS/표시/로그/CM/숏컷/예산 설정을 보존합니다. 잘못된 제안을 임의로 바꾸거나 부족한 근거를 만들어 성공 처리하지 않습니다.

실제 ZIP을 업로드한 TRANSFER 폴더에서 실행
압축 해제 위치와 코드 적용 대상은 다릅니다. 설치기는 기존 ~/DEV에 적용합니다.

python3 -m zipfile -e ./GENOS_DEPENDENCY_RECOVERY_20261014_R1.zip ./dependency-recovery-r1-package
bash ./dependency-recovery-r1-package/GENOS_DEPENDENCY_RECOVERY_20261014_R1_RUN.txt check
bash ./dependency-recovery-r1-package/GENOS_DEPENDENCY_RECOVERY_20261014_R1_RUN.txt apply
bash ./dependency-recovery-r1-package/GENOS_DEPENDENCY_RECOVERY_20261014_R1_RUN.txt verify

각 단계가 성공한 뒤 다음으로 진행하세요. 처음부터 로그를 남기며, apply가 출력하는 BACKUP 경로를 보관합니다. 지원 inventory/해시가 다르면 현재 코드를 보존하고 중단합니다. 독립 실행 TXT도 별도 첨부했고 ZIP 안의 실행 TXT와 동일합니다.

이후 GUIDE_UTF8.txt의 순서대로 기존 DEV에서 변경 검토·commit → 같은 checkout의 generation gate → 검증 commit push → 새 코드서빙 리비전 배포/SSE 재시작 → 워크플로우 테스트를 진행합니다. 데이터 generation 재구축이나 워크플로우 Python 편집기 추가 교체는 요구하지 않습니다. 원복 명령도 가이드에 있습니다.

검증: 작업 코드 986개 통과/1개 건너뜀/0개 실패. 현장 설치 형식 2조합에서 각각 117개, 합계 234개 계약/API 검사 통과. 실제 실행 TXT의 적용·재적용·원복·변조 거부, localhost TLS 부팅, 동일 committed checkout generation gate를 확인했습니다. 알려진 선행 inventory 330개를 지원합니다.

상태: 로컬 MAIN62 선택 포인터는 그대로입니다. 망분리 GENOS 반입·commit/push·실제 generation/리비전 선택·내부 모델 질문 성공은 아직 미확인입니다. 현장 확인은 워크플로우 테스트 화면에서 진행해야 합니다.

첨부: 코드 ZIP, 전체 실행 TXT, 적용/검증/원복 가이드, 검증 요약, 상세 검증 JSON, SHA-256 목록.
ZIP에는 수정 보고서·코드·해시 명세도 포함했습니다.
