적용 — 실제 업로드한 TRANSFER 폴더를 현재 작업 위치로 사용
ZIP과 별도 RUN.txt를 업로드한 그 폴더에서 실행하세요. TRANSFER의 절대 위치는 가정하지 않습니다.
코드 적용 대상은 기존 Git checkout ~/DEV입니다. 다르면 모든 명령에 같은 --root /실제/checkout 을 추가하세요.

python3 -m zipfile -e ./GENOS_NAVIGATION_DELIVERY_20261021_R1.zip ./GENOS_NAVIGATION_DELIVERY_20261021_R1
bash ./GENOS_NAVIGATION_DELIVERY_20261021_R1/GENOS_NAVIGATION_DELIVERY_20261021_R1_RUN.txt check
bash ./GENOS_NAVIGATION_DELIVERY_20261021_R1/GENOS_NAVIGATION_DELIVERY_20261021_R1_RUN.txt apply
bash ./GENOS_NAVIGATION_DELIVERY_20261021_R1/GENOS_NAVIGATION_DELIVERY_20261021_R1_RUN.txt gate

check/apply는 실제 checkout과 Python 경로·버전, 코드 상태를 기록합니다.
apply는 백업 후 적용합니다. .env·ignore·현장 경로·데이터·기존 작업 명령은 보존합니다.
로그는 현재 TRANSFER의 navigation-delivery-r1-logs에 첫 명령부터 남습니다.
코드 변경을 검토하고 실제 checkout에서 COMMIT_PATHS.txt의 변경과 git diff --check를 확인하여 commit합니다.
그다음 TRANSFER에서 실행하세요.

bash ./GENOS_NAVIGATION_DELIVERY_20261021_R1/GENOS_NAVIGATION_DELIVERY_20261021_R1_RUN.txt gate-code

현재 SQLite/NFS 운영이면 실제 선택 generation을 같은 checkout에서 검증합니다. Oracle 모드에는 이 명령을 사용하지 않습니다.
bash ./GENOS_NAVIGATION_DELIVERY_20261021_R1/GENOS_NAVIGATION_DELIVERY_20261021_R1_RUN.txt gate-sqlite

PASS한 commit을 push하고 동일 commit으로 코드서빙 리비전을 배포하세요.
코드 적용·Git push·리비전 배포는 별도 단계입니다. 이 패치는 데이터 generation을 생성하거나 교체하지 않습니다.
서빙 코드/세대/리비전은 실제 현장 로그로 확인해야 합니다.

새 코드서빙 리비전에서 실패했던 질문을 새 요청으로 실행하세요.
전달 원문이 있는 경우 판단·답변으로 이어지는지, 원문 인용이 실제 내용과 일치하는지,

원문이 없거나 권한/무결성 검증이 실패한 경우에는 여전히 중단합니다.
구 코드에 결속된 실패 요청·기록을 임의 변경하거나 새 코드로 강제 재개하지 않습니다.
