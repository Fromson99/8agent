GENOS AD 긴 표·구간별 모델 읽기 R2 (2026-10-06)

반입: GENOS_AD_LANGUAGE_20261006_R2.zip, GENOS_AD_LANGUAGE_20261006_R2_APPLY.txt, GENOS_AD_LANGUAGE_20261006_R2_PASTE_ALL.txt.
AD R1의 검증한 코드에 이번 AD 변경만 합친 누적 반입본이다.
동시에 진행된 relation_reading 등 다른 작업 코드는 보존하고 이 반입에 합치지 않았다.
현장에 이미 다른 후속 반입이 적용됐다면 해시 검사에서 중단한다. 강제 덮어쓰지 않는다.

변경
스크롤용 HTML 표: 최대 높이 480px, 가로·세로 스크롤, 고정 헤더, 안전한 원문 escape.
서버 Markdown은 보존하고 workflow 및 /chat에서 HTML을 기본 표시한다.
큰 값/배열/복잡한 구조는 미리보기와 cursor로 전달한다. 전체 자료는 서버에 보존한다.
필요할 때 같은 턴의 내부 LLM이 8행/2000문자씩 추가로 읽는다.
매 후속 호출은 최근 구간 하나와 짧은 메모만 받으며 이미 읽은 원문을 재누적하지 않는다.
최대 32회 안에 최종 계획이 없으면 AD_CONTEXT_INCOMPLETE 오류로 범위를 좁히게 한다.
각 호출의 입력/출력/usage/시간/해시는 ad_language_call에 보존한다.
번호·목록 같은 간단한 요청은 추가 구간을 읽지 않고 한 번의 LLM 해석으로 처리할 수 있다.
새 Excel 수집기를 만든 변경은 아니며 기존 SQL 표·상세 자료에 구간 읽기를 연결했다.

현장 적용: 기존 ~/DEV
진행 중 AD 요청이 끝난 뒤 ZIP/APPLY TXT를 ~/DEV/TRANSFER에 업로드:
  bash TRANSFER/GENOS_AD_LANGUAGE_20261006_R2_APPLY.txt check
  bash TRANSFER/GENOS_AD_LANGUAGE_20261006_R2_APPLY.txt apply
현장 Python은 python3다. 경로/버전/진행/실패는 ad-language-r2-logs에 지속 기록한다.
기존 파일은 정확한 해시로 검사·백업하고 재실행 시 이미 적용된 바이트를 확인한다.
원문/DB/.env/.git/CURRENT는 덮어쓰지 않는다. 알 수 없는 변경은 보존하고 중단한다.
TEAM_ID와 GENOS_LLM_* 내부 모델 설정을 유지한다. 새 라이브러리 설치는 없다.
선택한 기존 완료 세대의 절대경로를 GENOS_GENERATION에 지정한 환경에서:
  bash TRANSFER/GENOS_AD_LANGUAGE_20261006_R2_APPLY.txt verify
변경 파일/diff를 검토해 같은 ~/DEV에서 commit한 뒤:
  bash TRANSFER/GENOS_AD_LANGUAGE_20261006_R2_APPLY.txt gate
게이트 통과 commit을 push하고 같은 generation의 새 코드서빙 리비전을 배포·연결한다.
파일 적용, Git push, 코드서빙 배포, 워크플로우 변경은 각각 별도다.

워크플로우 편집기
GENOS_AD_LANGUAGE_20261006_R2_PASTE_ALL.txt 전체를 기존 Python 코드 대신 붙여 넣고 저장/적용한다. run 진입점을 유지한다.
R2 스크롤용 HTML 선택에는 편집기 교체도 필요하다. R1 편집기는 Markdown 표를 표시한다.
GENOS가 HTML/CSS를 제거하면 스크롤이 동작하지 않으므로 현장 화면에서 확인해야 한다.
이 경우 workflow 설정 GENOS_AD_TABLE_FORMAT=markdown으로 기본 표로 되돌린다.
스크롤 완성에는 GENOS 채팅 프런트의 HTML/CSS 또는 표 컨테이너 지원이 필요하다.
