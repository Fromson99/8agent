3. Git commit → 동일 checkout/generation gate → push → 새 리비전
RUN 적용만으로 실행 중인 코드서빙 리비전이 바뀌지는 않습니다.
적용 후 실제 DEV에서 변경을 검토하고, BACKUP/receipt.json의 files만 commit합니다.
적용된 main_workflow.py·분리 workflow 파일·code_ship.py·표시 의존성과 변경된
engine/PIPELINE/CODE_MANIFEST를 포함합니다. 다른 staged 변경을 섞지 않습니다.

아래 두 값은 현장 실제 출력/선택 경로로 채웁니다.
export TASK_BACKUP='/이번_R4_apply가_출력한_BACKUP_절대경로'
export GENOS_GENERATION='/코드서빙이_현재_선택한_generation_절대경로'

CM이 있으면 00_SYSTEM/GENOS_SERVING_PATHS.json의 generation·manifest SHA와 실제
코드서빙 선택을 대조합니다. 기존 선택 경로와 manifest를 임의 수정하지 않습니다.

cd ~/DEV
python3 - "$TASK_BACKUP/receipt.json" <<'COMMIT_PY'
import json,subprocess,sys
receipt=json.load(open(sys.argv[1],encoding='utf-8'))
paths=[row['path'] for row in receipt['files']]
subprocess.run(['git','diff','--check','--',*paths],check=True)
subprocess.run(['git','add','-f','--',*paths],check=True)
subprocess.run(['git','commit','--only','-m','Apply GENOS main_workflow SVG display R4','--',*paths],check=True)
COMMIT_PY

bash ~/DEV/TRANSFER/rag-progress-graph-r4-delivery/GENOS_RAG_PROGRESS_GRAPH_20261008_R4_RUN.txt gate "$TASK_BACKUP" --generation "$GENOS_GENERATION"
git rev-parse HEAD
git push

RUN TXT만 TRANSFER에 올린 경우 gate 명령의 RUN 경로는 그 실제 TXT 위치를 씁니다.
gate는 실제 설치 DEV의 APPLIED_CODE.zip과 Git 추적 committed checkout의 모든 파일을
대조하고, 같은 Python/02_BACKEND에서 generation E2E·verify_assets를 실행합니다.
게이트 후 파일을 바꾸면 다시 commit/gate합니다. 기존 origin에 통과한 commit을
push한 뒤 새 코드서빙 리비전을 그 commit과 같은 generation으로 배포합니다.
Run은 기존 GENOS_MAIN_MODE와 main_router.py 설정을 유지합니다. workflow 모드에서는
main_workflow:app이 새 표시 생산자입니다. main_workflow.py만 필요하면 기존 ASGI
설정의 main_workflow:app으로 실행합니다. Socket.IO를 새로 켜지 않습니다.
코드 적용·commit·gate·push·새 리비전·실제 질문 성공은 각각 별도 상태입니다.
