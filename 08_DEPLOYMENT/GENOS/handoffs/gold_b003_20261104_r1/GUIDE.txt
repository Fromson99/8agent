GENOS Gold B003 연결 추가 — MAIN140 기반 R1

기존 Gold R5 매핑 파일을 코드서빙에 포함하고 ORDS 선택 경로를 연결한 반입본입니다.
선택 로컬 MAIN140은 유지하며, 병행 작업의 멀티턴·최종검토 변경은 이 반입본에 포함하지 않았습니다.

1. 아래 두 파일을 실제 업로드하는 TRANSFER 폴더에 함께 넣습니다. 압축을 풀지 않습니다.
GOLD_B003_FULL_ORACLE_20261104_R1.zip
GOLD_B003_ONECLICK_R1.txt

2. TRANSFER에서 실행:
bash GOLD_B003_ONECLICK_R1.txt

기존 ~/DEV 링크를 실제 경로로 풀어 백업·코드 적용·엔진 검증합니다.
완료 표시: GOLD_B003_ONECLICK_DONE
로그: 실행 TXT 옆 gold_b003-install-logs
백업: 실제 DEV의 09_ARTIFACTS/BACKUPS/code-replacement

3. 반영한 DEV에서 기존 Git commit/push 절차를 진행하고 새 코드서빙 리비전을 배포합니다.
전달 파일만 stage하려면 TRANSFER에서:
bash GOLD_B003_ONECLICK_R1.txt stage
commit 후 전달 파일 일치 검사:
bash GOLD_B003_ONECLICK_R1.txt gate-code

4. ENVIRONMENT.txt의 Gold 설정을 코드서빙에 등록합니다.
시작 명령은 기존 python3 08_DEPLOYMENT/GENOS/start_sse.py 그대로입니다.
워크플로우 테스트 화면에서 준비 상태 → 원문 조회 → 검색·질문을 확인합니다.
설정한 Gold 채널/게시ID에 해당하는 원문과 검색 결과가 나오는지 확인합니다.
테이블·컬럼·권한 오류 시 실제 Gold 테이블/권한/기록 테이블을 확인합니다.

중단 뒤 같은 명령을 재실행할 수 있습니다. 실패 로그와 백업 경로를 보존합니다.
코드 원복이 필요하면 로그에 찍힌 실제 백업 경로로 실행합니다:
bash GOLD_B003_ONECLICK_R1.txt undo --backup '<실제 백업 절대경로>'
이후 이전 커밋/리비전·환경설정을 함께 복원합니다.

로컬 검증과 망분리 현장은 별개입니다. 현장 배포·Oracle 권한·실제 모델 결과는 아직 미확인입니다.
