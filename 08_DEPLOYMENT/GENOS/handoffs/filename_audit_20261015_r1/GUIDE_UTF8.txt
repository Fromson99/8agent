GENOS 내규 파일명·날짜 비교 R1 — 2026-10-15

1. 실행
첨부 ZIP과 TXT를 실제 업로드한 TRANSFER 폴더에서 터미널을 엽니다.
그 위치에서 아래를 실행합니다. TRANSFER의 절대 위치를 추정하거나 DEV로 이동하지 않습니다.

python3 -m zipfile -e ./GENOS_FILENAME_AUDIT_20261015_R1.zip ./GENOS_FILENAME_AUDIT_20261015_R1
bash ./GENOS_FILENAME_AUDIT_20261015_R1/GENOS_FILENAME_AUDIT_20261015_R1_RUN.txt check
bash ./GENOS_FILENAME_AUDIT_20261015_R1/GENOS_FILENAME_AUDIT_20261015_R1_RUN.txt compare

별도 첨부 TXT도 완전한 실행본입니다. ZIP이 정상 해제되면 위의 ZIP 내부 TXT를 사용하면 됩니다.
필요 패키지: Python3.10 이상 표준 라이브러리만. pip 설치·모델 호출·문서 재변환 불필요.

2. 자동으로 읽는 대상
기존 ~/DEV의 00_SYSTEM/GENOS_SERVING_PATHS.json 고정 generation을 우선합니다.
그 파일이 없으면 기존 generation 선택 helper의 GENOS_GENERATION / GENOS_DATA_ROOT / .env / CURRENT 설정을 읽습니다.
고정 설정이 있으면 과거 GENOS_DATA_ROOT보다 우선하며 manifest 해시를 확인합니다.
임의의 최신 폴더를 고르지 않습니다. 설정 충돌·해시 오류·읽기 실패는 실패로 종료합니다.
DEV가 다른 곳이면 compare 뒤 --root '/실제/기존/DEV'를 지정할 수 있습니다.
명시 generation이 필요하면 --generation '/실제/선택/generation'을 붙입니다. 기존 고정 설정과 충돌하면 거부합니다.

store.sqlite의 document 메타데이터에서 내규 파일명·원본경로·별칭을 모두 읽습니다.
현재 검색 제외 설정을 적용하기 전의 전체 구조화 내규가 왼쪽에 나타납니다.
전체 RAW가 아닌 선택된 구조화 generation에 들어 있는 문서 범위입니다.
원본 폴더 전체와 비교하려면 별도 실행:
bash ./GENOS_FILENAME_AUDIT_20261015_R1/GENOS_FILENAME_AUDIT_20261015_R1_RUN.txt compare --raw-root '/사용자가확인한/전체내규폴더'
위 경로만 실제 내규 루트로 바꿉니다. 모든 하위 파일 이름만 읽으며 파일 본문은 읽지 않습니다.
외규가 섞인 상위 폴더를 지정하지 않습니다. RAW 모드와 구조화 generation 모드는 별도 결과입니다.

3. 결과 보기
터미널의 RESULT_DIR= 경로 아래에 결과가 생성됩니다.
기본: 현재 TRANSFER/FILENAME_AUDIT_RESULTS/실행시각_고유번호/
COMPARE.html: 왼쪽 전체 내규 / 오른쪽 필터링 후 남은 내규. 원본 펼치기로 파일명·사유 확인.
Jupyter에서 HTML을 다운로드한 뒤 브라우저로 열면 나란히 볼 수 있습니다. Excel에서는 아래 CSV를 엽니다.

ALL_INTERNAL.csv: 전체 내규를 문서명,날짜 두 열로 정리(동일 두 값은 중복 제거).
RETAINED_INTERNAL.csv: 최신 유지 + 판정 불명 검토 보존, 문서명,날짜 두 열.
LATEST_ONLY.csv: 날짜가 확정되고 가족 내 모호성이 없는 최신 문서명,날짜 두 열.
AUDIT_DETAIL.csv: 원본 파일/경로별 판정, 날짜 전체, 제외 사유, 문서ID.
OLDER_CANDIDATES.csv: 구버전 제외 후보 상세.
REVIEW.csv: 날짜 없음/잘못된 날짜/복수 날짜/제목 불명 등 검토 대상.
AUDIT.json, SUMMARY.json: 코드·generation·해시·집계·원본별 상세 기록.
RUN_STATUS.json: COMPLETE, COMPLETE_WITH_REVIEW 또는 FAILED.
지속 로그: 현재 TRANSFER/FILENAME_AUDIT_RUNS/각실행/console.log, exit_status.txt.
재실행은 새 결과 폴더에 저장하고 기존 결과를 보존합니다.

4. 추출 규칙
문서명과 날짜만 판본 비교 키로 사용합니다. 폴더·팀·확장자·별첨번호는 키에서 버립니다.
YYYYMMDD / YYMMDD / YYYY.MM.DD / YYYY-MM-DD / YYYY_MM_DD / YYYY년 M월 D일 등을 위치와 무관하게 추출합니다.
6자리 260320은 2026-03-20입니다. YY00~69는2000~2069, YY70~99는1970~1999로 고정합니다.
달력상 불가능한 날짜는 최신으로 고르지 않습니다. 서로 다른 날짜가 둘 이상이면 모두 기록하고 검토 보존합니다.
이름은 규정·준칙·지침·시행세칙 등 문서 제목 어미까지 추출하고, .gul.docx 같은 중복 확장자와 부가설명을 제거합니다.
문서명 내부 공백·밑줄·하이픈 차이는 비교 키에서 통일합니다.
예: 업무위탁 운영지침_[별첨6] 중점관리 위탁계약 선정 기준_260320.docx
    -> 업무위탁 운영지침 / 2026-03-20
예: 20160823_위험관리시스템 운영준칙.gul.docx
    -> 위험관리시스템 운영준칙 / 2016-08-23

동일 최신 날짜에 본문·별첨6·별첨7이 있으면 전부 남깁니다. 별첨 내용은 삭제하지 않습니다.
~$로 시작하는 Office 임시파일은 제외 후보입니다.
같은 이름 가족에 날짜가 없거나 잘못된 파일이 있으면 가족 전체를 검토 보존합니다.
리스크관리위원회와 위험관리위원회처럼 이름 자체가 다른 문서는 자동으로 같은 문서라고 추정하지 않습니다.
날짜는 파일명 판본 날짜이며 실제 시행일/현재 유효성의 법률 판단이 아닙니다.
이름 어미·부가표기가 새 형태이면 결과를 보고 후속 규칙을 보완해야 합니다.

5. 이번 실행의 범위
진단 결과만 생성합니다. 기존 DEV 코드·RAW·SQLite·색인·SEARCH_SELECTION·CURRENT·RAG는 변경하지 않습니다.
apply 명령, Git commit/push, 코드서빙 리비전 배포, 워크플로우 편집기 변경은 이번 검증에 필요 없습니다.
구버전이 실제 RAG에서 안 나오게 하는 적용은 비교 결과를 확인한 다음 별도 단계입니다.
로컬 계약 검증과 GENOS 현장 실행은 다릅니다. 현장 실제 문서 수·추출 정확도는 이 실행으로 확인해야 합니다.
SAMPLE 폴더는 사진에서 읽을 수 있는 대표 이름과 모의 사례를 사용한 예시이며 GENOS 전체 결과가 아닙니다.
