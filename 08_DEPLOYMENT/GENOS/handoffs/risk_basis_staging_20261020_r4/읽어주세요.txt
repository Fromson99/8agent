지금 돌리는 GENOS_BASIS_ARTIFACTS count3 작업에 확정 연결만 추가 — 확정 연결 R4

대상은 GENOS_BASIS_ARTIFACTS_20261020_R1로 생성한 JSON 검토 작업입니다.
count 3은 내규 문서 3개 선택이고, 확정 4건은 위험관리기준시행세칙의 연결 4건입니다.
조사 작업을 중단/재시작하거나 stage-plan --count 3을 다시 실행하지 마세요.
기존 GENOS_BASIS_ARTIFACTS 폴더/코드/PLAN/STATE/후보를 그대로 사용합니다.
이번 R4는 확정 연결 도구만 교체합니다. GENOS_BASIS_BATCH_R4로 바꾸라는 뜻이 아닙니다.

기존 확정 연결 R3는 조사 도구와 다른 basis_batch.py 버전을 포함한 포장 결함이 있었습니다.
그래서 코드 게이트가 통과해도 RISK_STAGE_JOB으로 같은 JSON 검토 작업을 거부할 수 있었습니다.
이번에는 실제 발송한 ARTIFACTS R1 ZIP에서 공통 파일을 바이트 그대로 가져옵니다.
해시 검사는 유지하고, 기존 PLAN.json의 해시/도구 정보는 변경하지 않습니다.

1. 지금 TRANSFER 폴더에서 새 확정 연결 ZIP만 풀기
python3 -m zipfile -e ./GENOS_RISK_BASIS_REVIEW_20261020_R4.zip ./GENOS_RISK_BASIS_REVIEW_20261020_R4

2. 기존 검토 작업으로 위치 확인 후 확정 연결 추가
bash ./GENOS_RISK_BASIS_REVIEW_20261020_R4/GENOS_RISK_BASIS_REVIEW_20261020_R4_RUN.txt inspect-fixed
bash ./GENOS_RISK_BASIS_REVIEW_20261020_R4/GENOS_RISK_BASIS_REVIEW_20261020_R4_RUN.txt stage-fixed

성공은 INSPECTED 다음 STAGED 또는 STAGED_REUSED, published_to_sqlite=false입니다.
기본 작업 위치는 기존 GENOS_SERVING_PATHS.json runtime의
basis-batch/pilot-review-20261020-r1/CANDIDATES.json으로 ARTIFACTS R1 stage-plan과 같습니다.
다른 --job으로 조사했다면 위 두 명령에도 --job 실제작업폴더를 똑같이 추가합니다.
~/DEV가 실제 checkout으로 연결된 경우도 지원하며 checkout은 수정하지 않습니다.

일반 조사가 실행 중이어도 같은 JSON에 추가할 수 있습니다.
그 순간 후보를 쓰는 잠금이 겹치면 CANDIDATE_BUSY로 종료하며 조금 후 같은 stage-fixed를 다시 실행합니다.
3개 문서 조사 자체를 중단하거나 다시 시작할 필요는 없습니다.
확정 4건은 한 번에 저장되며 이미 같은 연결이 있으면 ID/출처/이력을 유지합니다.
신규 확정 내규가 조사 목록에 없더라도 HTML에 같이 나타납니다. 조사 PLAN/STATE는 유지됩니다.
위험관리기준시행세칙의 RAG 최신 판본 한 문서와 지정 조항/외규 원문을 다시 확인합니다.
새로운 의미 매칭이나 모델 조사는 하지 않습니다.

3. 기존 GENOS_BASIS_ARTIFACTS에서 일반 후보와 확정 연결을 같이 확인
bash ./GENOS_BASIS_ARTIFACTS_20261020_R1/GENOS_BASIS_ARTIFACTS_20261020_R1_RUN.txt report --output ./전체연결검토.html
bash ./GENOS_BASIS_ARTIFACTS_20261020_R1/GENOS_BASIS_ARTIFACTS_20261020_R1_RUN.txt export --output ./BASIS_REVIEW_ALL

같은 report/export를 이번 확정 연결 R4 RUN.txt로 실행해도 됩니다.
기존 조사 도구와 공통 소스/저장소/코드 요구사항이 동일합니다.
이미 BASIS_REVIEW_ALL이 있으면 새 이름을 사용하세요.
실행 중 HTML은 그 시점의 저장분입니다. 조사 종료 후 다시 report/export하면 최종 저장분을 확인합니다.
여기까지 SQLite에 확정 연결을 반영하지 않습니다.

4. HTML 확인 후 기존 검토/일괄 이관
bash ./BASIS_REVIEW_ALL/APPLY_RELATIONS.txt review --all
일부만 선택: --all 대신 --ids 연결ID1 연결ID2 ...
생성된 BASIS_REVIEW_ALL_REVIEWED.zip 하나에 선택 데이터와 적용 코드가 들어 있습니다.

운영 TRANSFER에서:
python3 -m zipfile -e ./BASIS_REVIEW_ALL_REVIEWED.zip .
bash ./BASIS_REVIEW_ALL/APPLY_RELATIONS.txt check
bash ./BASIS_REVIEW_ALL/APPLY_RELATIONS.txt apply
bash ./BASIS_REVIEW_ALL/APPLY_RELATIONS.txt status

검토 기록/원문 세대/코드/권한/상태를 확인한 뒤 같은 SQLite 트랜잭션으로 추가합니다.
동일 ID/이력의 중복 적용은 건너뜁니다. 다른 ID의 의미 중복을 자동 통합하지 않습니다.
원복: bash ./BASIS_REVIEW_ALL/APPLY_RELATIONS.txt rollback
신규 반영분만 REVOKED 이력을 추가하며 원래 데이터/이력은 보존합니다.

오류 시 기존 risk-fixed-review-logs/*.log 및 .exit와 job의 RISK_FIXED_FAILURE_*.json을 보존합니다.
RISK_STAGE_JOB이 남으면 PLAN을 편집/삭제하지 마세요. --job 경로 및 실제 실행 도구 버전을 확인해야 합니다.
현장 GENOS/NFS 및 내부 모델 품질은 외부 세션에서 검증하지 않았습니다.
원문/전체색인/MAIN 변경, 코드 설치, Git push, 리비전 배포는 하지 않습니다.
