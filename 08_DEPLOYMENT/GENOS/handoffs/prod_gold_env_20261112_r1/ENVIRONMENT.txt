    기본값이 mapped라서 안 넣으면 Gold 표를 안 봅니다.

    운영 Gold 13표(IDD_B003_LGL_*) 소유자. 대문자. 비우면 "gold requires GENOS_ORACLE_GOLD_OWNER".
    (개발계는 SIDDS — 이 값만 개발계와 다름. 11-09 운영 실행 때 SIDDG 사용 확인)
ORACLE_ORDS_SCHEMA=<운영 ORDS 별칭>
ORACLE_ORDS_CLIENT_ID=<운영 OAuth ID>

    셋 중 하나라도 없으면 "DP_CONFIG: missing ...". 개발계 값을 그대로 쓰지 않습니다.
    ORDS 별칭은 표 소유자(SIDDG)와 다른 값입니다.

    운영에는 main이 없어서 시작에 실패합니다. DP_QUERY_RELEASE_ID와 둘 중 하나만.

답변 모델(내부 LLM)
SEMANTIC_LLM_BACKEND=genos
    코드 기본값이 anthropic이라 반드시 명시.
GENOS_BASE_URL=<운영 GENOS 플랫폼 주소>
GENOS_LLM_SERVING_ID=<운영 답변 모델 서빙 ID>
GENOS_LLM_KEY=<운영 답변 모델 키>
    (대신 GENOS_LLM_URL=<모델 서빙 주소> + GENOS_LLM_KEY 방식도 가능. URL이 있으면 BASE_URL/SERVING_ID보다 우선)
GENOS_LLM_MODEL=<모델 ID>   — 선택. /models에 모델이 하나면 비워도 자동으로 찾음.

임베딩(초기 검색에 벡터를 쓸 때 필수)
GENOS_EMBED_ID=<운영 임베딩 서빙 ID>
GENOS_EMBED_TOKEN=<운영 임베딩 서빙 토큰>
    주소는 GENOS_BASE_URL을 같이 씀. 운영 Gold 벡터(11-09 기준 140,182행)를 적재할 때 쓴 것과
    같은 임베딩 모델이어야 함(차원이 다르면 질문 실패).
GENOS_EMBED_TENANT_ID=<값>  — 운영 게이트웨이가 요구할 때만.
GENOS_RAG_INITIAL_SEARCH=hybrid
    권장(MAIN182 이후 현장 기준). 기본 auto = 벡터만(벡터 게시가 없으면 본문 검색).
    hybrid/vector로 두면 운영에 벡터 게시가 없을 때 질문이 실패하므로 벡터 적재 확인 후 사용.
    임베딩을 못 쓰는 상황이면 keyword.

E. 환경변수로는 못 바꾸는 것 — DB 쪽에서 맞아야 함
==================================================================
1. Agent 기록 4표 소유자는 코드에 SIDDA로 고정(gold 모드):
   SIDDA.LGL_AGT_RUN_A / LGL_AGT_REC_A / LGL_AGT_BODY_A / LGL_EXEC_ST_A
   11-09 운영 시작 때 Gold 13표·Agent 4표 구조 검사는 통과(그 다음 판본 선택에서 멈춤) → 표는 보임.
   쓰기 권한(INSERT/UPDATE/DELETE)은 미확인. BODY DELETE가 없으면 옛 저장본 정리만 경고 후 중단.
   운영 Agent 소유자가 SIDDA가 아니면 코드 수정이 필요합니다.
2. Gold 판본 선택(SEARCH_SELECTION): 11-09 QUERY_SELECTION 503의 원인. R7f 보완 레시피 실행 결과(현장)
   확인 전이면 같은 503이 납니다.
3. Gold 벡터 머리(VCTR_HEAD)가 지금 채널의 검색 게시와 연결돼 있어야 vector/hybrid가 동작.

시작 명령은 그대로: python3 08_DEPLOYMENT/GENOS/start_sse.py (포트는 플랫폼 PORT 등 기존 값)
