GENOS 법령 경로 줄바꿈·원문 확인 묶음 표시 R1 — 2026-10-13

적용 파일
GENOS_WORKFLOW_SOURCE_CARDS_20261013_R1_PASTE_ALL.txt

변경 내용
1. 검색한 법령 path를 한 항목씩 줄을 나누어 표시합니다.
   Markdown 목록과 빈 줄로 구분하며, 제목을 중복 출력하지 않습니다.
2. 연속된 원문 확인 알림을 하나의 로그로 모읍니다.
   예: 원문 확인 · 확인 대상 12곳
       - external > financial_team > law > 모의법A · 제1조
       - external > financial_team > krx > 모의규정B · 제2조
   8개를 넘는 묶음도 수신한 목록을 생략하지 않습니다.
3. 다른 진행 단계, 전달된 모델 대기 알림, 요청/실행 변경이 나오면 묶음을 닫습니다.
   답변 첫 토큰 직전 또는 요청 종료/오류 시에도 남은 목록을 표시합니다.
   완료된 카드만 한 번 송신하므로 읽는 동안 문서별 카드가 추가되지 않습니다.

묶음의 의미
서버는 여러 원문을 확보해 모델에 전달하고 필요하면 추가 선택/검토를 수행합니다.
기존 화면 이벤트에는 모델 호출 ID가 없고 호출 경계 일부가 전달되지 않습니다.
따라서 이번 묶음은 연속된 화면 알림 기준이며, 'LLM 1회 호출'이나
'목록 전체가 모델에 전달됨'을 의미하지 않습니다. 원문 확보와 모델 입력은 구분합니다.
묶음은 다음 단계가 수신될 때 표시되며, 다음 이벤트가 없으면 답변/종료 시 표시됩니다.

적용 순서
1. 현재 GENOS 워크플로우 Python 편집기 전체 내용을 원복용 파일로 저장합니다.
2. PASTE_ALL.txt를 텍스트 편집기로 열고 전체를 복사합니다.
3. 기존 분리 워크플로우의 같은 Python 단계 내용을 전체 교체하고 저장합니다.
   진입점은 기존 run(data)입니다. 부분 코드만 추가하지 않습니다.
4. 워크플로우 테스트 화면에서 WORKFLOW_SETTINGS를 실행합니다.
   workflow_revision=rag-v6-source-cards-20261013-r1
   live_progress_revision=workflow-source-cards-20261013-r1
   progress_display_revision=rag-source-cards-20261013-r1
   progress_mode=socketio / socketio_enabled=true를 확인합니다.
5. 실제 질문으로 검색 path가 목록으로 분리되는지, 연속된 원문 확인이
   한 카드에 나오는지, 답변 본문에는 진행 로그 없이 최종 답변이 나오는지 확인합니다.
   기존 socketIOClientId, URL, token, port, 환경변수는 그대로 사용합니다.

이번 파일은 발송된 R4 전체 편집기 코드에 표시 수정만 결합한 인계입니다.
기존 최종 답변 토큰 스트리밍, 판단 상세, 그래프, 진단 로그는 유지합니다.
ZIP을 풀거나 Git push를 하는 것만으로 워크플로우 편집기가 갱신되지 않습니다.
이번 표시 수정에 코드서빙 재배포, SSE 서버 재시작, 원문/색인 재구축은 필요하지 않습니다.
이전 요청의 모델 스트림 종료 오류를 수정하는 파일은 아닙니다.

원복
1번에서 저장한 이전 Python 전체를 같은 편집기에 다시 붙여 넣고 저장합니다.

검증과 현재 상태
모의 이벤트·SSE·Markdown·답변 스트리밍 및 기존 R4 편집기 계약을 로컬에서 확인했습니다.
자세한 결과는 VALIDATION_SUMMARY.txt와 VALIDATION.json에 있습니다.
실제 GENOS 편집기 저장과 브라우저 화면은 미확인입니다.
로컬 MAIN56 선택 포인터와 봉인 R4, 기존 backend, NFS 세대는 변경하지 않았습니다.
SHA256SUMS.txt는 전달 파일 무결성 확인용이며, 실제 화면 적용의 증거는 아닙니다.
