team_raw 또는 genos_corpus의 전체 후보 수집 → 파일명 판본 선택 → 기존 형식 선택/해시 중복 제거
→ STRUCTURE → 기존 document-release 병합/용어/참조/fulltext → 새 검색 세대.
본문을 변경하거나 기존 검색 결과를 사후에 숨기는 기능이 아니다.

같은 물리 부모 폴더, 출처, 팀, body/attachment 역할, NFC 정규화 문서명을 묶는다.
끝의 유효한 (YYYYMMDD)를 비교한다. 파일 수정시간·LLM·문서 의미 유사도는 사용하지 않는다.
최신 날짜 DOCX+PDF는 기존 형식 우선순위로 선택하며 구버전은 aliases/PDF references로 넣지 않는다.
날짜 없음/6자리 날짜와 8자리 날짜가 같은 문서명으로 혼재, 잘못된 달력 날짜,
최신 날짜 동일 형식의 다른 내용은 입력 오류다. 6자리만 있는 가족은 추정 없이 유지한다.
다른 이름·다른 폴더는 합치지 않는다. 파일명 날짜를 법률상 현행 시행일로 인증하지 않는다.
구버전 RAW/기존 STRUCTURE/완료 세대는 삭제하거나 덮어쓰지 않는다.

선택된 행에는 input_version_policy를 결속하며 구조화 지문·receipt를 거쳐 재현한다.
filename_version 메타데이터는 원문 SQLite에 남는다.
inventory-*.json과 기존 문서 상태 원장은 제외 파일 해시·선택 날짜/파일·사유를 소비한다.
filename-version-selection.json은 같은 run의 선택 지문 변경과 옵션 생략 재개를 거부한다.
새 정책을 이전 구조화 run에 추가할 때도 새 run ID를 요구한다.
파서 실패 시 기존 구조화 원장에 FAILED; 구버전으로 자동 복귀하지 않는다.
오류 검출 담당은 select_latest_internal, 실행/중단 담당은 기존 단계 CLI.
자동 수정/모델 호출/재시도는 0회. 입력 정정 후 새 run ID로 재개한다.
해시·권한·기존 실행 검사는 그대로 사용한다.

기존 base generation을 합치면 구버전이 재유입될 수 있어 본 옵션과 함께 사용하지 못한다.
composed_build는 구축 전 차단하고 document_release도 실제 구조 receipt에서 재확인한다.
전체 서비스용 후보는 유지할 외규를 포함한 전체 RAW 범위로 새 구축한다.
--only-internal/--team은 해당 범위만의 후보이며 전체 기존 서비스를 대체하는 목록이 아니다.
명시/기본 BUILD_SCOPE 선택 및 PDF-only 진단과는 혼용하지 않는다.
팀 레이아웃이 있으면 기존 계약대로 *_team 아래를 읽는다. 사진 폴더가 목록에 실제 있는지
check-only 보고서로 확인해야 한다. 임의 RAW 이행이나 팀/권한 변경은 이번 패치가 하지 않는다.

변경된 기존 구축 파일 7개는 작업 코드에 통합한다. 기존 서비스 코드/엔진/프로필/모델 설정은 수정하지 않는다.
