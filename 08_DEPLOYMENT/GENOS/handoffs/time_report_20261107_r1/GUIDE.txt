GENOS 처리 시간 보고 R1 (2026-11-07) — 방금 실행한 질문에서 어디에 시간이 걸렸는지

왜
  "내부 회계 관리자는 누가 지정하나요?" 질문이 서버 처리 253.13초, 그중 모델 호출 5회 합계 19.25초였습니다.
  나머지 약 234초가 모델 밖입니다. 이 명령으로 그 234초가 Oracle SQL인지, 어느 단계인지 나눠 봅니다.

무엇을 하나
  코드서빙은 질문마다 요청 보고서(JSON)를 공유 폴더(GENOS_SHARED_LOG_DIR)에 자동으로 남깁니다.
  이 명령은 그 파일 하나만 읽어서 요약합니다.
  - 코드서빙·코드·워크플로우·DB·모델·환경변수를 바꾸지 않습니다. 재배포·재시작이 필요 없습니다.
  - Oracle에 접속하지 않고 모델도 부르지 않습니다.
  - 질문·답변·원문·SQL 본문·바인드 값은 화면에 나오지 않습니다(시각·시간·횟수·단계 이름·SQL 해시만).
  - 파일 하나(GENOS_TIME_REPORT_R1.txt)에 전체 코드가 들어 있어 압축 해제가 필요 없습니다.

실행 — GENOS_TIME_REPORT_R1.txt를 올린 TRANSFER 폴더에서 (다른 폴더로 이동하지 않습니다)
  1) 방금 질문이 몇 번인지 확인
       bash ./GENOS_TIME_REPORT_R1.txt list
     최근 요청이 번호·요청 시각·서버 처리 시간과 함께 나옵니다. 서버 처리 "253.1초"인 줄의 번호를 봅니다.
  2) 보고 (1번이 방금 질문이면 번호 생략 가능)
       bash ./GENOS_TIME_REPORT_R1.txt 1
     마지막 줄에 "종료=0"이 나오면 완료입니다.
  요청 보고서 위치가 기본(/nfs-root/diamo/8-agent/rag-request-reports)과 다르면 두 명령 끝에
  --root /실제/GENOS_SHARED_LOG_DIR값 을 똑같이 붙입니다.
  예: bash ./GENOS_TIME_REPORT_R1.txt list --root /nfs-root/diamo/8-agent/rag-request-reports

사진
  화면 맨 위 "GENOS 처리 시간 보고 R1"부터 맨 아래 "종료=0"까지 찍어 주세요(보통 2~4장, 많아도 5장).
  같은 내용이 ./GENOS_TIME_REPORT_RESULTS/REPORT-날짜시각.txt 에도 저장됩니다.

화면 읽는 법
  [1] 전체 시간을 모델 호출 / Oracle SQL / 그 외로 나눔. SQL은 횟수와 1회 평균(ORDS 왕복 포함)도 표시.
      SQL 세부: 쓰기 횟수, 가장 느린 1회, 공유캐시 적중/미적중. 원장 저장(대화·조사 기록) 횟수·시간.
  [2] 순서대로 M(모델 호출)과 G(모델 호출 사이, 모델 밖)를 보여줌. "◀ 김"은 전체의 15% 넘는 구간.
      긴 G 구간 아래 └ 줄: 그 구간의 느린 SQL, 원장 저장, 시간 많이 쓴 단계, 원장에 남은 행동 기록.
  [3] 시간 많이 쓴 SQL 종류 상위 3(해시·횟수·합계·평균), 느린 SQL(기본 1초 이상) 상위 10(언제, 어느 구간, 직전 단계).
  [4] 시간 많이 쓴 단계 상위 12. "대기"가 크면 SQL·네트워크를 기다린 시간입니다.
  [5] 모델 밖에서 기록 없이 흐른 긴 시간 상위 6(앞뒤 기록 이름으로 위치를 알 수 있음).
  [6] 한 줄 판정(예: "Oracle SQL이 전체의 83% (1,800회 × 평균 117ms) → 짧은 SQL을 아주 많이 보냄").

오류
  종료=2  위치·인자 문제: 폴더 없음, 번호 범위 밖 → --root 또는 list로 번호 확인
  종료=3  보고서 없음/읽기 실패: 방금 끝난 질문이면 보고서를 쓰는 중일 수 있으니 10~20초 뒤 다시 실행
  "요약 줄(oracle.sql.summary) 없음"이 나오면 현장 코드가 MAIN167 이전이거나 DP=oracle이 아닌 것입니다.

(선택) 다음 단계 — 어떤 SQL인지 더 자세히 보고 싶을 때만
  지금 기록은 1초 이상 걸린 SQL만 하나씩 남고, 나머지는 요청 끝의 합계 한 줄입니다.
  코드서빙 환경변수에 GENOS_ORACLE_SQL_SLOW_MS=200 을 넣고 재시작한 뒤 같은 질문을 한 번 더 하고
  같은 명령을 실행하면 0.2초 이상 걸린 SQL이 모두 [2]·[3]에 구간별로 나옵니다. 끝나면 변수를 지우고 재시작합니다.
  이번 사진만으로 원인이 보이면 이 단계는 필요 없습니다.
