GENOS DEV 선택 JSON 복구 R1 — 앞서 보낸 NFS 복원 방식 대신 이번 패키지를 사용합니다.

바뀌는 것
기존 NFS 원문·SQLite·색인은 그대로 사용합니다. 최신 문서 선택 JSON만
~/DEV/00_SYSTEM/SEARCH_SELECTION/generation.json 에 생성하고 Git 코드와 함께 배포합니다.
서빙은 /app/src/service 등 실제 배포 코드 폴더 기준으로 이 파일을 읽습니다.
~/DEV 절대경로를 서빙 컨테이너에서 찾는 방식이 아닙니다.
기존 NFS SEARCH_SELECTION 폴더에 JSON이 없어도 이번 경로가 동작합니다.
JSON은 현재 NFS 문서 메타데이터와 기존 승인 판본 선택 규칙으로 자동 생성합니다.
따라서 이전 DATA ZIP이나 build-receipt.json을 따로 준비할 필요가 없습니다.
코드 2파일과 그 파일을 참조하는 엔진 해시만 변경합니다. 현장 워크플로우 등 다른 수정은 유지합니다.
선택 JSON과 GENOS_SERVING_PATHS.json도 반드시 커밋·배포되어야 합니다.

1. 첨부 ZIP/TXT를 실제 업로드한 TRANSFER 폴더에서 터미널을 엽니다.
TRANSFER 절대경로를 추측하거나 먼저 DEV로 이동하지 않습니다.
처음 한 번만 실행:

python3 -m zipfile -e ./GENOS_DEV_SEARCH_SELECTION_20261021_R1.zip ./GENOS_DEV_SEARCH_SELECTION_20261021_R1
bash ./GENOS_DEV_SEARCH_SELECTION_20261021_R1/RUN_DEV_SELECTION.txt check
bash ./GENOS_DEV_SEARCH_SELECTION_20261021_R1/RUN_DEV_SELECTION.txt apply

기존 ~/DEV가 실제 Git checkout의 링크인 경우 실제 경로를 확인해 그 checkout에 적용합니다.
별도 후보 코드 폴더에만 설치하는 것이 아닙니다.
기존 00_SYSTEM/GENOS_SERVING_PATHS.json에 고정된 generation/runtime을 우선 보존합니다.
기존 설정이 없으면 사용자 사진의 아래 경로를 사용합니다. 디렉터리가 실제 존재해야 합니다.
generation=/nfs-root/diamo/8-agent/term-releases/financial-risk-success-20261005-schema-r2/generation
runtime=/nfs-root/diamo/8-agent/runtime
다른 환경은 check부터 --root /실제/DEV --generation /실제/generation --runtime /실제/runtime 을 명시합니다.
기존 설정과 다른 generation/runtime을 조용히 바꾸지 않습니다.
현장 코드가 검증한 선택 모듈 버전과 다르거나 기존 엔진 해시가 깨져 있으면 원인을 로그에 남깁니다.

2. APPLY 성공 후, 생성 파일과 코드 변경을 커밋하고 동일 checkout을 검증합니다.

bash ./GENOS_DEV_SEARCH_SELECTION_20261021_R1/RUN_DEV_SELECTION.txt commit
bash ./GENOS_DEV_SEARCH_SELECTION_20261021_R1/RUN_DEV_SELECTION.txt gate

commit은 이번 파일만 추가하고 커밋합니다. 별도 작업의 이미 staged 된 파일은 함께 넣지 않습니다.
gate는 실제 DEV의 커밋 바이트와 APPLIED_CODE.zip을 비교한 후 같은 checkout에서
genos_generation_e2e.py 및 term_serving_bundle.verify_assets를 순차 실행합니다.
NFS 전체 해시 확인에는 시간이 걸릴 수 있습니다. 다른 무거운 작업과 동시에 실행하지 않습니다.
gate-code는 코드 확인만 하므로 gate의 대체가 아닙니다.
기존 다른 tracked 변경이 있다면 검토·커밋하여 checkout을 정리한 다음 gate를 다시 실행합니다.

3. gate가 GENOS_RELEASE_GATE PASS로 끝난 뒤 실행합니다.

git -C "$HOME/DEV" push

GENOS 코드서빙 화면에서 위 커밋으로 새 리비전을 배포합니다.
DEV 파일만 고친 채 기존 리비전을 계속 쓰면 503이 남습니다.
이 패치는 워크플로우 Python 단계 변경이 필요하지 않습니다.
워크플로우 테스트 화면에서 기존 warmup/HEALTH를 실행한 뒤 최신 내규 원문을 묻는 질문을 실행합니다.
선택 generation, 코드 커밋, 새 리비전 번호, 실제 요청 ID와 답변을 함께 기록합니다.
코드서빙 직접 테스트 UI/API를 사용할 필요가 없습니다.
별도 요청의 '멀티턴에는 대화 세션 식별자가 필요합니다' 오류는 이 패치와 별개입니다.
그 오류가 남으면 워크플로우 호출에 실제 대화 session_id가 전달되는지 확인해야 합니다.

재실행·실패·원복
모든 명령은 추출 폴더의 logs/에 Python 경로·버전·시작·종료 상태를 남깁니다.
INSTALL_STATE.json과 blobs/를 지우지 말고 같은 추출 폴더를 유지하세요.
적용 중 끊겼으면 같은 apply를 다시 실행합니다. 적용 전후의 정확한 파일만 재개합니다.
파일이 다른 변경으로 바뀌면 덮어쓰지 않고 오류와 복구 상태를 남깁니다.
원복 명령:

bash ./GENOS_DEV_SEARCH_SELECTION_20261021_R1/RUN_DEV_SELECTION.txt rollback

원복은 이번 코드·설정·선택 JSON의 원래 바이트/권한을 복구하며 NFS 원문을 건드리지 않습니다.
이미 배포했으면 GENOS에서 이전 리비전과 원래 검증된 generation으로 복귀해야 합니다.
원래 NFS 선택 JSON이 없던 배포는 원복 후 최초 503 원인도 그대로 남습니다.
이전 패키지의 RESTORE_NFS.txt와 이번 패치를 섞어서 실행하지 않습니다.

경계
이 패키지는 사진에서 확인한 NFS 서빙의 즉시 복구용입니다. Oracle 조회형 전환 완료를 뜻하지 않습니다.
로컬 합성/API/설치 검사 결과와 현장 NFS·내부 모델·새 리비전 결과는 별도입니다.
현재 외부 세션에서는 GENOS에 접속할 수 없어 실제 배포 성공은 현장 실행 로그로 확인해야 합니다.
