GENOS compact 원문·단위 색인 서빙 로더 수정 R1 — 2026-10-06

사진의 runtime.bootstrap.failed / HTTP 503 원인:
GENOS_GENERATION has an unsupported manifest
서빙 root service.py가 새 term-source-generation-v2를 거부한다.
같은 입구의 PeCab 검사도 semantic-unit-fulltext-v1을 거부하므로 함께 수정한다.

수정 대상: 기존 ~/DEV/service.py. service/service.py adapter와 데이터는 보존한다.
정확한 reference-build R1 코드 반입본을 기준으로 만든 작은 패치다.
기존 R4와 reference R1의 확인된 service.py 해시만 이행 허용하며,
그 밖의 배선·계약·runtime 의존성은 reference R1의 해시를 유지한다.
전체 최신 로컬 코드를 덮어쓰는 ZIP이 아니다. SQL AD 등 새 기능은 포함하지 않는다.
v1/v2 원문과 조/최소 단위 전문색인 모두 허용하지만 원문·색인·용어집 해시 검증은 유지한다.
데이터 재구축, NFS 재발행, CURRENT 변경은 필요 없다.

1. 아래 ZIP과 TXT 두 파일을 ~/DEV/TRANSFER에 저장한다.
   GENOS_COMPACT_LOADER_20261006_R1.zip
   GENOS_COMPACT_LOADER_20261006_R1_APPLY.txt
   ZIP은 직접 풀 필요가 없다. TXT와 같은 폴더에 두면 된다.

2. 코드스페이스 터미널에서 적용한다.

cd ~/DEV
bash TRANSFER/GENOS_COMPACT_LOADER_20261006_R1_APPLY.txt apply
bash TRANSFER/GENOS_COMPACT_LOADER_20261006_R1_APPLY.txt verify

기본 모드도 apply다. 미리 보기만 하려면 check를 사용한다.
현장 명령은 python3이며 /venv/bin/python3가 있으면 기존 방식으로 선택한다.
Python 3.11 이상 필요. 실제 실행 파일과 버전을 로그에 남긴다.
처음부터 TRANSFER/compact-loader-logs에 로그와 LOADER_EXIT 상태를 남긴다.
apply는 기존 파일 백업·적용만 수행하고 배포하지 않는다.
재실행 시 ALREADY INSTALLED로 검증하며 예상 밖 변경을 덮어쓰지 않는다.
CHECKOUT_DRIFT가 나오면 파일을 보존하고 중단한다. 해시를 억지로 바꾸지 않는다.
verify는 실제 service/service.py 진입점의 데이터 선택·PeCab 검사를 먼저 수행하고
같은 checkout/Python의 원문·navigation·전문색인 E2E 검사를 수행한다.
verify의 SERVICE_LOADER_CONTRACT PASS, GENERATION_E2E PASS와 LOADER_EXIT=0을 확인한다.

3. 변경을 검토·커밋한 뒤 같은 checkout에서 새 패치의 게이트를 실행한다.

git diff --check
git diff -- service.py
git add -- service.py
git commit -m "Fix GENOS compact source and unit fulltext bootstrap"
bash TRANSFER/GENOS_COMPACT_LOADER_20261006_R1_APPLY.txt gate

이전 반입 코드에 아직 미커밋 파일이 있다면 gate는 중단한다.
기존 reference R1의 CODE_MANIFEST.json에 있는 files와 required_files의 코드도
Git 추적·커밋 상태여야 한다. 관계없는 로컬 변경을 일괄 add하지 않는다.
GENOS_RELEASE_GATE PASS 뒤 통과한 커밋을 git push한다.
구 reference-build TXT의 gate 대신 이 새 TXT의 gate를 사용한다.

4. GENOS 코드서빙 상세 → 새 리비전 환경 설정에서 선택한다.

GENOS_GENERATION=/nfs-root/diamo/8-agent/term-releases/financial-risk-success-20261005-schema-r2/generation
GENOS_RAG_IMPLEMENTATION=legal-agent-unified-v6

기존 내부 LLM 접속·runtime·서명·로그 설정을 유지한다.
위 generation은 이번 사진의 NFS 발행 경로이며 verify/gate 기본 선택값이다.
다른 경로를 검증하려면 verify/gate 뒤에 정확한 generation 절대경로를 넣는다.
코드서빙 리비전은 게이트가 출력한 Git commit을 사용해 새로 배포한다.
Git push, 코드서빙 새 리비전 배포, 환경변수 저장은 각각 별도 단계다.
이 코드 수정에는 워크플로우 Python 교체가 필요하지 않다.
기존 워크플로우가 해당 코드서빙을 호출하는지 바인딩을 확인한다.

5. 실제 확인은 워크플로우 테스트 화면에서 한다.

{"API_TYPE":"WARMUP"}
{"API_TYPE":"WARMUP_STATUS"}

요청 ID, 실제 배포 commit·리비전, generation manifest SHA-256,
warmup/질문 결과를 현장에 보존한다. 코드서빙 직접 테스트를 요구하지 않는다.
