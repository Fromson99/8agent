GENOS 확인 범위 안내 R2 — 현장 코드 구성 누락 수정

사진의 FACT_REASON R1 설치 중단을 고친 교체본입니다. 기존 R1 대신 이 R2를 사용합니다.
현재 LENGTH_RECOVERY R2 코드는 재설치하지 않습니다. 추가 진단 실행도 필요 없습니다.
누락된 검증 구성660개를 추가해2310개를 지원합니다. 사진의 코드 지문을 재현해 검사합니다.
기존1650개 입력/출력과 제품 문구 바이트는 R1과 동일합니다.
검사를 우회하지 않으며 알려지지 않은 파일/코드 조합은 기존 파일을 보존하고 중단합니다.

변경 내용
이전: 추가 사실 확인이 필요합니다.
변경: 해당 사안에 적용할 결론을 하나로 확정하려면 추가 사실 정보가 필요합니다.

조건별 기준을 이미 설명했더라도 개별 사건의 결론을 특정하려면 사실 정보가
필요할 수 있다는 목적을 안내한다. 답변 본문의 '확인 범위'와 단계별 상세의
'추가 확인할 사항'이 사용하는 공통 MISSING_FACT 문구 한 줄을 바꾼다.
답변 내용·사실 부족 분류·PARTIAL 상태·검색/복구 예산·모델·데이터는 변경하지 않는다.
추가 정보의 구체 항목을 새로 추론하거나 일반 질문의 완료 판정을 바꾸는 수정은 아니다.

적용 순서
기존 SCHEMA_RECOVERY R1 이후 검증된 코드 구성과 후속 dependency/tool/length
복구 적용 구성을 지원한다. 미확인 코드 구성은 쓰기 전에 차단하고 로그를 남긴다.
이번 ZIP은 R1과 같은 문구 수정 및 설치기 지원 목록 보완을 포함한다. 앞서 받은 LENGTH_RECOVERY R2 등 복구 패치를
적용할 예정이면 그 작업을 먼저 완료하고 이 FACT_REASON R2를 마지막에 적용한다.
기존 ZIP과 기록은 보존한다. 이 패치를 적용한 뒤 앞선 설치기를 다시 적용하지 않는다.

1. 실제로 첨부파일을 올린 TRANSFER 폴더에서 아래를 순서대로 실행한다.
TRANSFER의 절대 위치를 추정하지 않으며 먼저 DEV로 이동하지 않는다.
코드 적용 대상은 기존 Git checkout인 ~/DEV다. 실제 checkout이 다른 경우에만
GENOS_DEV_ROOT를 그 경로로 지정한다. 현장 실행은 python3를 사용한다.

python3 -m zipfile -e ./GENOS_FACT_REASON_20261015_R2.zip ./GENOS_FACT_REASON_20261015_R2
bash ./GENOS_FACT_REASON_20261015_R2/GENOS_FACT_REASON_20261015_R2_RUN.txt install

위 install 한 번으로 사전 검사 → 백업 → 문구 적용 → 관련 pin 결속 → 설치본 검증을 수행한다.
같은 install을 다시 실행하면 이미 적용된 정확한 파일을 검증하고 끝난다.
검사만 하려면 install 대신 check를 사용한다.
독립 실행 TXT도 같은 파일이다: bash ./GENOS_FACT_REASON_20261015_R2_RUN.txt install
로그와 종료 상태는 시작부터 현재 TRANSFER/fact-reason-r2-logs에 남는다.
BACKUP, APPLIED_CODE_ZIP, CODE_ZIP_SHA256 출력과 실제 Python/checkout 정보를 보관한다.
실패하면 로그의 원인을 확인한다. CODE_MANIFEST나 해시를 수동으로 바꾸지 않는다.

2. 기존 ~/DEV에서 변경 파일을 검토하고 commit한다.
제품 코드 변경은 completion_contracts.py 한 파일이다. 관련 엔진 manifest,
PIPELINE.json, CODE_MANIFEST.json이 함께 갱신된다.
git diff --check를 수행하고 이번 receipt에 나온 변경 파일만 검토·stage·commit한다.
다른 미완료 변경은 별도로 보존한다.

3. 실제 TRANSFER에서 같은 committed checkout의 generation gate를 실행한다.
다음 두 한글 자리표시자는 현장에서 확인한 실제 절대경로로 바꾼다.

bash ./GENOS_FACT_REASON_20261015_R2/GENOS_FACT_REASON_20261015_R2_RUN.txt gate "apply가 출력한 BACKUP 절대경로" --generation "현재 선택된 generation 절대경로"

gate는 apply가 기존 DEV에서 만든 APPLIED_CODE.zip을 같은 Git checkout 및
실제 선택 generation과 비교한다. 인계용 부분 패치 ZIP을 전체 코드 ZIP으로 넣지 않는다.
gate 통과 뒤 코드를 변경했으면 다시 commit하고 gate를 실행한다.
통과한 commit을 push하고 그 commit의 새 코드서빙 리비전을 배포한다.
분리 SSE 프로세스를 사용 중이면 같은 코드로 재시작한다.
원문/NFS 데이터 재구축과 이번 패치용 워크플로우 Python 편집기 변경은 필요 없다.

4. 워크플로우 테스트 화면에서 새 요청으로 재질의한다.
조건별 답변과 '확인 범위'의 새 문구, 단계별 상세 화면을 확인한다.
기존 저장 답변과 같은 request ID의 결과를 소급 변경하는 패치는 아니다.
request ID, 실제 commit/코드서빙 리비전/generation, 표시 결과를 남긴다.
외부 검증은 모의 데이터·모의 모델 응답이며 현장 내부 모델 성공은 미확인이다.

5. 필요하면 출력된 정확한 BACKUP으로 원복한다.

bash ./GENOS_FACT_REASON_20261015_R2/GENOS_FACT_REASON_20261015_R2_RUN.txt undo "apply가 출력한 BACKUP 절대경로"

원래 파일 바이트·권한·inventory를 복원한다. 이후 별도로 바뀐 대상 파일이나
변조된 백업은 덮어쓰지 않고 거부한다. 코드의 commit/push·이전 리비전 배포와
SSE 재시작은 별도로 확인한다. 데이터와 실패 기록은 삭제하지 않는다.

상태 구분
로컬 작업 코드의 문구 수정과 모의 검증을 인계한다. 로컬 활성 MAIN66은 유지한다.
GENOS 반입·commit/push·리비전 배포·워크플로우 질의 성공은 현장 확인 전 미확인이다.
