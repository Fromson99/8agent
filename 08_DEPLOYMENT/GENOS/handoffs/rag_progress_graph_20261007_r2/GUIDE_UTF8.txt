2. 코드 범위와 기존 기능 보존
306파일 전체 코드 ZIP은 시스템 로그 R1 + DB 상세 로그 롤백 R3 + 핵심 근거
shortcut R1 위에 최신 표시를 결합한 대표 코드입니다.
실제 적용에는 ZIP을 DEV에 덮어 풀지 말고 독립 RUN TXT를 사용하십시오.
RUN은 현재 CODE_MANIFEST 전체를 확인하고 해당 선행 코드 계열에 맞는 변경만 적용합니다.
검색 계측 R3/R4 또는 시스템 로그 R1에 DB 로그 롤백 R3가 적용된 상태와,
그 위에 shortcut R1까지 적용한 상태 등 18개 알려진 inventory를 지원합니다.
각 계열의 검색 캐시·순위·권한·세션·일반 로그·DB 상세 로그 롤백 상태를 보존합니다.
shortcut이 아직 없는 지원 상태에는 동일하게 검증한 shortcut R1 변경도 함께 적용합니다.
이전 계열에 없는 로그 수집 모듈은 검증한 원본을 함께 설치합니다.
원문, 용어집, NFS generation/CURRENT, 기존 SQL 데이터와 .env를 변경하지 않습니다.
알 수 없는 현장 수정은 덮어쓰지 않고 중단합니다.

3. 저장 및 코드 적용 — 기존 ~/DEV checkout
첨부 ZIP, RUN TXT, WORKFLOW TXT, GUIDE, 검증 요약, SHA 파일을 같은 폴더에 저장하십시오.
예: ~/DEV/TRANSFER/rag-progress-graph-r2
DEV 선택은 GENOS_DEV_ROOT → GENOS_DEV → ~/DEV 순서입니다. 루트 링크를 해결하며
코드 내부의 링크나 알 수 없는 해시는 중단합니다. 실제 Python 경로/버전을 로그에 남깁니다.

cd ~/DEV/TRANSFER/rag-progress-graph-r2
sha256sum -c SHA256SUMS.txt
bash GENOS_RAG_PROGRESS_GRAPH_20261007_R2_RUN.txt check
bash GENOS_RAG_PROGRESS_GRAPH_20261007_R2_RUN.txt apply
bash GENOS_RAG_PROGRESS_GRAPH_20261007_R2_RUN.txt verify

check가 'Known recent GENOS inventory required'로 끝난 경우에만 아래를 확인하십시오.
DB 로그 롤백 R3 미적용의 알려진 코드이면 함께 첨부한 선행 TXT로
check/apply/verify를 마친 뒤 위 R2 check부터 다시 실행합니다.
이미 shortcut R1을 적용해 R2 check가 통과했다면 선행 로그 롤백 TXT를 재실행하지 않습니다.
CHECKOUT_DRIFT나 다른 오류는 임의 rehash/원복으로 넘기지 말고 기존 파일과 로그를 보존합니다.

bash GENOS_DB_LOG_ROLLBACK_20261007_R3_RUN.txt check
bash GENOS_DB_LOG_ROLLBACK_20261007_R3_RUN.txt apply
bash GENOS_DB_LOG_ROLLBACK_20261007_R3_RUN.txt verify

apply는 변경 전 백업과 receipt를 먼저 만듭니다. 출력된 BACKUP, APPLIED_CODE_ZIP,
CODE_ZIP_SHA256을 보관하십시오. 같은 apply 재실행은 해시 확인 후 ALREADY_APPLIED입니다.
모든 RUN 작업의 stdout/stderr/예외 원문은 로그 수집기로 기록합니다.
기본 NFS 위치는 /nfs-root/diamo/8-agent/logs/system/<run_id>입니다.
GENOS_SYSTEM_LOG_DIR로 다른 절대경로를 지정할 수 있습니다.
NFS_COMPLETE False이면 출력된 SPOOL을 보존하고 현장 NFS 복구 후 재전송하십시오.

4. 같은 checkout의 코드·generation 배포 게이트
apply/verify 후 변경 목록을 검토하고 실제 push할 DEV에 필요한 변경만 commit하십시오.
새 로그 모듈, CODE_MANIFEST.json, 갱신한 engine JSON/PIPELINE도 Git에 포함되어야 합니다.
다른 작업을 섞지 말고 git diff --check 및 git status를 확인합니다.

사용자가 현장 기록으로 채울 값:
TASK_BACKUP = apply가 출력한 BACKUP 절대경로
GENOS_GENERATION = 코드서빙이 실제 선택한 기존 generation 디렉터리의 절대경로

export TASK_BACKUP='/현장_apply가_출력한_BACKUP_절대경로'
export GENOS_GENERATION='/현장_코드서빙의_실제_선택_generation_절대경로'
bash GENOS_RAG_PROGRESS_GRAPH_20261007_R2_RUN.txt gate "$TASK_BACKUP" --generation "$GENOS_GENERATION"

RUN이 생성한 APPLIED_CODE.zip은 해당 계열의 실제 설치 코드입니다.
대표 첨부 ZIP의 검사 결과를 다른 계열 checkout의 결과로 옮기지 않습니다.
게이트는 commit된 동일 checkout 코드와 APPLIED_CODE.zip을 비교하고 그 checkout의
Python으로 generation E2E와 verify_assets를 실행합니다. 새 모델 호출은 없습니다.
통과 후 코드/pin을 바꾸면 다시 commit/gate하십시오. 통과한 commit을 push한 뒤
새 코드서빙 리비전의 commit·선택 generation 경로/manifest 해시를 별도로 확인합니다.
적용, Git push, 리비전 배포, 환경변수 저장, 화면 질의 성공은 각각 별도 상태입니다.

5. 채팅 연결별 적용
직접 통합: python3 main.py /chat 또는 기존 integrated 연결을 사용합니다.
해당 기존 모드/포트/플랫폼 연결 설정을 임의로 바꾸지 않습니다.
직접 JSON과 명시적 SSE 모두 같은 진행 카드·최종 SVG 표시를 사용합니다.
Socket.IO 송신은 이번 변경에서 켜지 않습니다.

분리 Python 워크플로우: 첨부 GENOS_RAG_PROGRESS_GRAPH_20261007_R2_WORKFLOW_PASTE_ALL.txt
전체를 기존 Python 단계 편집기에 반영하십시오. ZIP 적용/Git push만으로 편집기가
바뀌지 않습니다. 로그 모듈을 같은 해시로 내장했으며 기존 SSE 연결을 사용합니다.
멀티턴은 기존 memory 설정 및 사용자/대화/팀 식별자가 유효해야 이어집니다.

최종 질의/warmup 검증은 GENOS 워크플로우 테스트 화면에서만 수행합니다.
기존 공개 예시: '상법 제4조의 상인 정의를 설명해 주세요.'
대기 로그 제거, 한 줄 한 법령, 검색값, 법령 읽기/복귀 이유와 답변 바로 아래의
접힌 그래프를 확인한 뒤 후속 질문/조건 정정에서 현재 판단이 표시되는지 확인합니다.
실제 화면 결과와 요청 ID를 보관하십시오. 코드서빙 직접 테스트 UI/API를 요구하지 않습니다.
