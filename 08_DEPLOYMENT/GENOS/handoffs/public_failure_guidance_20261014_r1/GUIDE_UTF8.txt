GENOS PUBLIC_FAILURE_GUIDANCE R1 — 예외 안내 통합 / 로컬 MAIN61

사용할 버전: 이 메일의 PUBLIC_FAILURE_GUIDANCE R1 ZIP, RUN.txt, PASTE_ALL.txt.
기존 ASSESSMENT_GAP_ACTION R2 다음에 적용하는 추가 패치입니다.
PASTE_ALL은 기존 SOURCE_PROVIDER R2 편집기 코드를 대체하는 전체 붙여넣기 코드입니다.
사용자 화면의 출처 카드·한국어 기관명·정상/제한 답변·답변 토큰 스트림을 유지합니다.

검토 미완료와 기술 예외를 구분합니다.
- 근거를 갖춘 최종 답변을 만들지 못한 경우:
  현재 충분한 법률 검토를 하지 못했습니다. 검토할 법률 쟁점이나 상황을 조금 더 구체적으로 질문해 주세요.
- 통신/서버/시간 초과:
  현재 충분한 법률 검토를 하지 못했습니다. 잠시 후 다시 요청해 주세요. (503 또는 timeout 등)
- 401/403 접근 권한, 409 처리 중/상태 충돌, 413 분량 초과, limit 처리 한도는 맞는 안내.
HTTP 상태·실패 상태·요청 ID는 유지하며 상세 원인은 내부 로그에 보존합니다.
실패 원인 자체가 해결됐거나 실패가 정상 성공으로 바뀐 것은 아닙니다.
프로세스 종료/플랫폼 응답 차단 등 코드가 실행되지 못하는 장애는 이 표시 코드만으로 처리할 수 없습니다.

선행 상태
MODEL_STREAM_FIX R1 → (AD_REQUEST_LOGS R2 → SUCCESSFUL_SHORTCUT R1) → ASSESSMENT_GAP_ACTION R2 → 이 패치.
괄호 안 기능은 이미 적용된 경우 보존하며 없는 기능을 임의로 활성화하지 않습니다.
현재 성공 shortcut 패치를 함께 적용할 예정이면 shortcut R1을 먼저 적용한 뒤 gap R2와 이 패치를 적용하세요.
과거 설치기는 신규 파일을 모르므로 적용 순서를 거꾸로 실행하면 중단됩니다.
알려진 선행 inventory와 정확히 일치하는 상태만 허용합니다. 미확인 현장 수정은 강제 덮어쓰지 않습니다.
현재 원문 generation·조사 예산·캐시·DB/실패 원장은 보존하며 데이터 재구축은 없습니다.

1. 기존 ~/DEV에 백업 후 적용
ZIP을 ~/TRANSFER에 업로드한 예입니다. 업로드 위치가 다르면 ZIP 경로만 바꿉니다.

python3 -m zipfile -e ~/TRANSFER/GENOS_PUBLIC_FAILURE_GUIDANCE_20261014_R1.zip ~/DEV/TRANSFER/public-failure-guidance-r1-package
bash ~/DEV/TRANSFER/public-failure-guidance-r1-package/GENOS_PUBLIC_FAILURE_GUIDANCE_20261014_R1_RUN.txt check
bash ~/DEV/TRANSFER/public-failure-guidance-r1-package/GENOS_PUBLIC_FAILURE_GUIDANCE_20261014_R1_RUN.txt apply

별도 첨부 RUN.txt는 ZIP 안의 파일과 같은 완전한 실행 코드입니다.
RUN은 기본 기존 ~/DEV를 대상으로 하며 첫 단계부터 지속 로그와 실패 종료 상태를 남깁니다.
실제 Python 경로/버전, CHECK PASS, CODE_APPLIED, EXIT=0과 BACKUP/APPLIED_CODE_ZIP 경로를 보관하세요.
반복 실행은 ALREADY_APPLIED로 끝나며 변조·선행 불일치는 보존 후 중단합니다.
실제 변경 파일은 BACKUP/receipt.json과 CODE_MANIFEST.json에 기록합니다.
app/chat/SSE의 오류 소비 부분과 현재 MAIN의 워크플로우 표시 생산자/소비자를 연결합니다.
ZIP payload는 검증 정본 대조용이며 직접 덮어쓰지 않고 RUN 설치기를 사용합니다.
현장 app/전송/로그 설정은 차이가 있으므로 SOURCE_BINDING.json의 field_variants로 각각 결속합니다.

2. 같은 checkout의 commit 및 generation 검증
cd ~/DEV
git diff --check
git status --short

BACKUP/receipt.json의 소스·엔진 pin·PIPELINE·CODE_MANIFEST 변경을 검토하고 함께 commit합니다.
다음 값은 apply 출력과 실제 현재 선택된 generation 절대경로로 바꿉니다.

TASK_GUIDANCE_BACKUP='/실제/apply/출력의/backup-경로'
TASK_GUIDANCE_GENERATION='/현재/선택된/generation/절대경로'
bash ~/DEV/TRANSFER/public-failure-guidance-r1-package/GENOS_PUBLIC_FAILURE_GUIDANCE_20261014_R1_RUN.txt gate "$TASK_GUIDANCE_BACKUP" --generation "$TASK_GUIDANCE_GENERATION"

게이트는 그 checkout/추적 commit/APPLIED_CODE.zip과 선택 generation 및 원문 자산을 검사합니다.
PASS인 같은 commit을 기존 팀 remote로 push하고 그 commit/generation을 선택한 새 코드서빙 리비전을 배포합니다.
별도 SSE 서버도 같은 코드로 재시작합니다. Git push와 새 리비전 배포는 별도 단계입니다.
기존 main_workflow 또는 stream_app 실행 위치/설정을 유지합니다.

3. 워크플로우 Python 편집기 전체 교체
GENOS_PUBLIC_FAILURE_GUIDANCE_20261014_R1_PASTE_ALL.txt의 전체 내용을 기존 Python 단계에 붙여 넣고 저장합니다.
코드 ZIP 적용이나 Git push만으로 플랫폼 편집기 내용이 바뀌지 않습니다.
PASTE_ALL에는 같은 public-display-v4와 독립 실행에 필요한 진단 모듈이 포함됩니다.
기존 플랫폼 환경변수/서빙 주소/인증/Socket.IO 설정을 유지합니다.
PASTE_ALL은 편집기용 Python이며 bash 실행 파일이 아닙니다.

4. 워크플로우 테스트 화면 확인
현장 테스트는 워크플로우 테스트 화면에서만 실행합니다.
- 정상 근거 질문의 답변/출처 카드/초기 토큰 표시가 유지되는지 확인합니다.
- 기존 실패 질의를 새 요청으로 실행해 공통 법률 검토 안내와 괄호의 503/timeout/limit 등을 확인합니다.
- 검토 미완료는 질문 구체화 안내, 권한/분량/처리 한도는 각각 해당 안내인지 확인합니다.
- 원시 오류·내부 경로·traceback이 답변에 표시되지 않는지 확인합니다.
- 일부 토큰 뒤 실패하면 최종 실패 상태가 남고 성공 답변/shortcut으로 저장되지 않아야 합니다.
실제 commit, generation 절대경로/manifest SHA256, 코드서빙 리비전, 편집기 버전,
요청ID, 최종 결과, 내부 오류 로그를 함께 기록합니다. 503만으로 발생 위치를 단정하지 않습니다.
외부 WSL 검증과 GENOS 내부 모델/현장 검증은 별도입니다.

5. 롤백
현재 코드가 적용 상태와 동일할 때만 백업 원복을 허용합니다. 후속 수정은 강제 삭제하지 않습니다.

bash ~/DEV/TRANSFER/public-failure-guidance-r1-package/GENOS_PUBLIC_FAILURE_GUIDANCE_20261014_R1_RUN.txt undo "$TASK_GUIDANCE_BACKUP"

이전 검증 commit/코드서빙 리비전으로 별도 배포하고 SSE를 맞춥니다.
편집기는 교체 전에 보관한 기존 SOURCE_PROVIDER R2 전체 코드로 되돌립니다.
데이터 generation/DB/실패 이력은 유지합니다.
