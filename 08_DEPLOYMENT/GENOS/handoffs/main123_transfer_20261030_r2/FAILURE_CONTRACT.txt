입력/소비자: 실제 업로드 TRANSFER의 R1 ZIP을 정확한 SHA256으로 확인한 R2 준비 코드가 기존 MAIN123 설치기 check/apply/gate를 호출한다.
원인: R1은 DEV의 모든 하위 설치 패키지를 금지하여 실제 /workspace/TRANSFER 구조에서 중단했다.
수정: 설치 패키지와 실제 code 대상/Git 메타데이터의 겹침만 금지한다. 현장 ~/DEV alias를 그대로 검증하고 적용한다.
복구 담당: 파일 적용/중간 상태/원복은 기존 runner 1곳. 새 준비 코드는 코드 대상에 직접 쓰지 않는다.
예산: 모델/네트워크0, 자동 재시도0. 동일 명령은 기존 상태와 백업을 유지한 재진입이다.
상태: 원래 R1 폴더/실패 로그 보존. R2 결정적 폴더/ROOT_BINDING/INSTALL_STATE/backup 및 TRANSFER 로그를 유지한다. 기존 R1의 설치 상태가 있으면 새 설치 시작 전 중단한다.
실패: ZIP/패키지 변조, 기존 로컬 수정, JS 불일치, 대상 변경, 동시 실행, 원복 후 재적용 거절. 부분 적용은 원래 before/after 해시 범위만 계속하며 원복을 제공한다.
완료: 실제 적용과 기존 code gate 통과 후만 APPLIED. 현장 Git/push/리비전/워크플로우는 별도다.
검증: 전달 TXT의 기본 명령을 실제 Bash/Python/Git 임시 checkout에서 실행, 사진 중첩 경로와 외부 TRANSFER, 재실행/백업 보존/원복/변조/충돌/중간 적용 재개를 검사한다.
