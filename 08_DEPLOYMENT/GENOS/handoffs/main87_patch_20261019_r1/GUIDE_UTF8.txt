선택된 MAIN87(cm-read-continuity-20261019-r1)의 누적 코드 적용본입니다.
이전 MAIN84/83/82 및 MAIN81 R2 대신 이번 MAIN87 패치를 사용하세요. 앞선 패치를 순서대로 다시 적용할 필요는 없습니다.
선택 서빙 370파일은 검증한 MAIN87과 동일하며 대사 workflow 1.10.0과 근거 발견 1.0.0을 포함합니다.
출력 압축·시스템 고정값 조립, 본문 읽기 유지와 참조 조사 복귀, 후속 조사 상태, 평가 입력 축약과 저장/표시 일치를 포함합니다.
기존 Oracle DP 연결·GENOS 출력 상한 제거·근거 원장·예산/재개 계약을 유지합니다.
기존 ~/DEV의 패키지 목록 안 코드를 백업 후 교체하고 목록 밖 파일, .env, Git, NFS 데이터·검색 선택표·현장 설정은 보존합니다.
부분 파일 몇 개만의 diff가 아니라, 구버전과 섞이지 않도록 필요한 실행 파일을 함께 묶은 누적 패치입니다.
DP를 새로 켜거나 Oracle 이관, 원문 재구축 또는 데이터 generation 교체를 실행하는 패키지는 아닙니다.
이미 실행 중인 대사 요청을 마친 뒤 설치하고 새 버전에서는 새 요청 ID로 시작하세요.

현재 확인된 한계
- 외부 Qwen3.8로 실제 CM 8문항은 응답 8/8, 핵심 답변 7/8이며 CM003 의미 판단은 남아 있습니다.

- 참조 내규 미확보·적용범위 오판·반복 설명이 남으며 실제 사용자 답변은 21,685자였습니다. 짧은 답변이나 모든 판단의 정확성을 보장하지 않습니다.
- 위 결과는 로컬 외부 모델 검증이며 GENOS 내부 모델의 timeout 해소, 현장 배포/질의 성공은 미확인입니다.

1. 파일을 업로드한 실제 TRANSFER 폴더에서 실행
TRANSFER의 절대 경로는 가정하지 않습니다. 먼저 DEV로 이동하지 마세요.

python3 -m zipfile -e ./GENOS_MAIN87_PATCH_20261019_R1.zip ./GENOS_MAIN87_PATCH_20261019_R1
bash ./GENOS_MAIN87_PATCH_20261019_R1/GENOS_MAIN87_PATCH_20261019_R1_RUN.txt check
bash ./GENOS_MAIN87_PATCH_20261019_R1/GENOS_MAIN87_PATCH_20261019_R1_RUN.txt apply
bash ./GENOS_MAIN87_PATCH_20261019_R1/GENOS_MAIN87_PATCH_20261019_R1_RUN.txt status

기본 적용 대상은 기존 ~/DEV입니다. 다를 때만 위 명령 뒤에 --root /실제/DEV를 지정합니다.
python3 3.11 이상과 기존 GENOS 의존성을 사용하며 실제 실행 파일·버전을 로그에 남깁니다.
/venv/bin/python3가 있으면 사용합니다. 필요 시 GENOS_PYTHON_DIR=/사용할/파이썬/bin을 설정합니다.
ZIP 안 RUN.txt와 별도 첨부 RUN.txt는 같은 완전한 실행 파일입니다.

check/apply/status는 코드 및 작은 GENOS_SERVING_PATHS/manifest를 확인합니다.
NFS 원문 DB·색인·기존 검색 선택표를 읽거나 수정하지 않고 데이터 재구축도 하지 않습니다.
.env, .venv, Git 이력, 기존 GENOS_SERVING_PATHS, 코드 목록 밖 파일을 보존합니다.
코드 목록 안 파일은 검증한 MAIN87 인계본으로 교체하며 원본은 ~/DEV/09_ARTIFACTS/BACKUPS/code-replacement에 백업합니다.
MAIN87_CODE_APPLIED와 종료코드0은 코드 적용 완료이며 현장 대사 성공을 의미하지는 않습니다.
로그: 현재 TRANSFER/main87-patch-r1-logs/*.log 및 *.log.exit
상태: 현재 TRANSFER/main87-patch-r1-state/STATUS.json
실패: 같은 state/LAST_FAILURE.json 및 백업 receipt.json
적용 도중 중단됐으면 같은 TRANSFER에서 같은 RUN의 apply로 복구·재개합니다.
중복 적용은 설치한 코드와 receipt가 같으면 재사용합니다.

아래 코드 목록만 add하며 .env, 실행 로그, 백업, unrelated 작업은 포함하지 않습니다.
이 단계의 작업 위치만 기존 DEV입니다. TRANSFER 원래 위치는 따로 기억해 두세요.

관련 없는 staged 변경이 있으면 함께 commit하지 말고 먼저 분리합니다.

3. 원래 TRANSFER로 돌아가 검증한 checkout과 코드 ZIP 결속 확인

bash ./GENOS_MAIN87_PATCH_20261019_R1/GENOS_MAIN87_PATCH_20261019_R1_RUN.txt gate-code

gate-code는 코드만 검사합니다. 데이터·서비스 검증 완료로 표시하지 않습니다.
아래 gate는 같은 committed DEV에서 선택 generation의 DB/색인/해시까지 읽는 전체 검사입니다.
현장에서 대규모 NFS I/O를 제한하고 있다면 실행을 미루고 CODE_GATE_PASSED_GENERATION_UNVERIFIED 상태를 남깁니다.
데이터 읽기를 허용한 시점에 실행하고, 통과한 commit과 generation을 새 리비전에 사용합니다.
기존 최신 문서 선택표 또는 원본의 최신 표시가 있어야 MAIN87가 서빙됩니다. 이번 코드 적용은 이 데이터를 새로 만들지 않습니다.
gate에서 'latest document selection required'가 나오면 기존 데이터의 표시가 준비되지 않은 상태입니다.
데이터 읽기가 허용된 시점에 기존 search-selection 경로로 보강한 뒤 gate를 다시 실행합니다.
이를 참조 문서 부재나 대사 의미 판단 실패로 해석하지 않습니다.

bash ./GENOS_MAIN87_PATCH_20261019_R1/GENOS_MAIN87_PATCH_20261019_R1_RUN.txt gate

gate 통과 후에는 코드/pin을 다시 바꾸지 않습니다. 바뀌면 새 commit으로 다시 검사합니다.
기존 DEV에서 해당 commit을 git push하고 같은 commit으로 코드서빙 새 리비전을 배포합니다.
GENOS_SERVING_PATHS의 generation/runtime, DP/Oracle 연결 설정, 내부 LLM·임베딩 설정을 유지하고 SSE를 새 코드로 재시작합니다.
DP=oracle 사용 시 전체 generation gate는 기존 NFS generation 검사이며 Oracle 연결/선택 릴리스 성공을 증명하지 않습니다.
실제 Oracle provider/release/cache 선택은 워크플로우 테스트에서 확인하고, Oracle 모드 오류를 NFS로 바꾸어 우회하지 않습니다.
STATUS.json의 commit/generation/manifest 해시와 실제 코드서빙 리비전/선택 경로를 함께 기록합니다.
새 리비전·실제 generation·내부 모델 결과는 로컬 검사만으로 확인되지 않습니다.

5. 원복

적용 후 사용자가 수정한 코드가 있으면 덮어쓰지 않고 보존하며 그 파일을 알립니다.
