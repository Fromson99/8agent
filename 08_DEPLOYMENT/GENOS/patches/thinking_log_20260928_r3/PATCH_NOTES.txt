GENOS thinking log R3 — installed request_report compatibility fix (2026-09-28)

R1/R2 대신 GENOS_THINKING_LOG_20260928_R3_APPLY.txt 하나를 사용합니다.
사진의 R2 unsupported installed version; no changes는 코드 쓰기 전에 중단된 상태입니다.
R3는 기존 ~/DEV의 request_report.py 전체 hash를 특정 전달본 목록에 제한하지 않습니다.
먼저 실제 설치 코드와 엔진 등록 hash의 일치를 확인하고, Python 구문 트리로 로그
출력 목록/표시 함수의 계약을 확인한 뒤 필요한 표시 구문만 변경합니다.
그 외 기존 코드 바이트는 보존합니다. 현장 파일 전체를 백업해 before/after hash를 남깁니다.
형식이 호환되지 않거나 다른 코드/엔진 hash가 다르면 덮어쓰기 전에 중단합니다.

bash GENOS_THINKING_LOG_20260928_R3_APPLY.txt

기본 기존 ~/DEV. 필요할 때만 DEPLOY_ROOT/PYTHON_BIN 지정. 별도 ZIP 불필요.
첫 단계부터 /tmp/genos-thinking-log-r3-*.log에 지속 로그와 종료 상태를 남깁니다.
INPUT_CHECK: 파일별 실제 SHA/크기. STRUCTURAL_CHECK_PASS: 구문 검증 및 before/after SHA.
BACKUP_READY -> APPLIED. 재실행은 ALREADY_APPLIED. 성공 표식을 확인합니다.
R1/R2 모델 진단/숫자 필터가 이미 있으면 유지하고, 지원되는 미적용 바이트만 누적 적용.

적용 diff 검토·commit → MODE=verify GENOS_GENERATION='/실제/선택/generation' bash TXT
→ 검증한 commit push → 새 코드서빙 리비전 배포 → 워크플로우 테스트 화면에서 새 질문.
코드서빙 직접 테스트 UI/API를 요구하지 않습니다. 데이터 generation/CURRENT,
워크플로우 Python, 모델 설정은 변경하지 않습니다.

새 공유 .log 확인 표식: live_diagnostics_version=thinking-live-20260928-r3
thinking_requested=false, prompt_tokens, completion_tokens, reasoning_tokens,
thinking_observation가 보입니다. 모델 진단 생산자 diagnostics_version=r1은 유지합니다.
서버가 추론 정보를 주지 않으면 null/unknown으로 표시하며 OFF/0으로 판정하지 않습니다.
새 진단 줄에 추론 원문/질문/원문/프롬프트/인증키를 출력하지 않습니다.

원복: MODE=rollback ROLLBACK_FROM='/BACKUP_READY/경로' bash TXT
이후 수정이 있으면 덮어쓰기 거절. 원복 commit/push/이전 리비전 복귀는 별도입니다.
실제 현장 적용/리비전/새 로그/모델 thinking 상태는 사용자 현장 확인 전까지 미확인입니다.
