요청 준비 반복 비용 수정: GENOS_REQUEST_PREPARE_20260929_R1

1. 기존 ~/DEV Git checkout에 아래 실행 TXT로 적용합니다.
   bash GENOS_REQUEST_PREPARE_20260929_R1_APPLY.txt
   다른 checkout이면 DEPLOY_ROOT=/실제/Git/checkout 으로 지정합니다.
   MODE=check 는 사전 확인만 수행합니다.
   Python은 checkout/.venv/bin/python, 없으면 기존 python3를 사용합니다.
   전체 로그는 첫 줄의 /tmp/genos-request-prepare-r1-*.log에 계속 저장됩니다.

2. 적용 내용: 요청 원장 초기 표·색인·트리거·버전·run/budget를 한 트랜잭션으로 저장합니다.
   PRAGMA synchronous=FULL, foreign_keys=ON, journal_mode=DELETE 및 기존 SQL 스키마를 유지합니다.
   요청마다 별도 원장과 연결을 계속 만듭니다. 출처·약칭 projection과 PIPELINE의 재읽기는 검증 캐시를 사용합니다.
   파일 상태/해시, 세대·store 바인딩, 범위·원문·근거 검증을 유지합니다.
   session.prepare.timings는 준비 시작~READY의 총시간/스레드 CPU와 6개 단계의 wall/CPU를 기록합니다.
   서로 포함 관계에 있는 상위·하위 시간을 더하지 않습니다. wall-CPU는 I/O 단독 지표가 아닙니다.

3. 전제: 이전 RESPONSE_OVERHEAD R3의 검증 캐시 함수가 있어야 합니다.
   함수가 없거나 알려진 구현과 다르면 파일을 쓰기 전에 중지합니다.
   unknown preparation function은 현장 다른 수정과 다르다는 뜻입니다. 강제 덮어쓰지 않습니다.
   승인된 4개 함수만 교체하며 다른 함수·현장 추가 코드·설정·데이터 pin을 보존합니다.
   사용하는 엔진 manifest와 PIPELINE의 코드 해시만 함께 갱신합니다.

4. 재실행은 ALREADY_APPLIED로 확인합니다. BACKUP_READY 경로를 보관합니다.
   MODE=rollback ROLLBACK_FROM=/실제/BACKUP_READY/경로 bash GENOS_REQUEST_PREPARE_20260929_R1_APPLY.txt
   적용 후 별도 수정이 있으면 롤백도 거부합니다.

5. 코드스페이스 적용으로 실행 중인 코드서빙 리비전이 변경되지는 않습니다.
   changed_files만 검토·commit한 후, 실제 선택 generation으로 배포 게이트를 실행합니다.
   MODE=verify GENOS_GENERATION=/실제/generation bash GENOS_REQUEST_PREPARE_20260929_R1_APPLY.txt
   통과한 커밋 push → 같은 generation의 새 코드서빙 리비전 → 워크플로우 테스트입니다.
   generation을 추측하거나 CURRENT를 변경하지 않습니다. 새 색인 작업·야간 실행과 별도입니다.

6. 준비 로그 확인: 워크플로우 테스트 완료 보고 JSON의 실제 경로를 지정합니다.
   REPORT_JSON=/실제/요청보고.json bash GENOS_REQUEST_PREPARE_20260929_R1_CAPTURE.txt
   질문·본문·LLM 답변을 출력하지 않고 준비 단계 수치만 표시합니다.
   session.prepare.timings가 없다면 이 수정이 그 실행 경로에 반영됐는지는 미확인입니다.
   초기 캐시 로딩과 실제 검색/LLM 시간은 남습니다. 현장 준비 시간 감소율은 아직 미측정입니다.

상태 구분: 작업 코드 수정/로컬 계약 확인 ≠ Git main 반영 ≠ GENOS 리비전 배포 ≠ 현장 성능 확인.
