SSE 서버 시작 수정 R1: 기존 SSE R1/R2 시작 파일 두 개에만 적용합니다.
실행: bash ~/DEV/TRANSFER/GENOS_SSE_STARTUP_20260928_R1_APPLY.txt
사전 확인: MODE=check bash ~/DEV/TRANSFER/GENOS_SSE_STARTUP_20260928_R1_APPLY.txt
Run은 python 08_DEPLOYMENT/GENOS/start_sse.py 그대로 유지합니다. Build 변경은 없습니다.
HTTP 시작과 SSE_CHECK에서 데이터 준비를 시작하지 않습니다. /와 /health는 HTTP 생존만 확인합니다.
최초 질문 또는 WARMUP에서 기존 service를 적재하며 기존 파일 해시와 데이터 검증은 유지합니다.
WEB_CONCURRENCY와 무관하게 worker 1개를 사용하며 동시 질문 제한을 추가하지 않습니다.
수정 전 세 가지 동작을 재현했고 관련 회귀 검사 52개가 통과했습니다. 현장 원인은 아직 미확인입니다.
원문, generation, CURRENT, 엔진 pin, 워크플로우는 변경하지 않습니다.
설치 후 두 파일만 검토하여 commit합니다:
  git add -- 08_DEPLOYMENT/GENOS/stream_app.py 08_DEPLOYMENT/GENOS/start_sse.py
  git diff --cached --check
  git commit -m 'Fix SSE HTTP startup resource initialization'
출력된 gate_zip을 같은 checkout의 06_TOOLS/COMMANDS/genos_release_gate.py로 검사합니다.
같은 GENOS generation 검사는 기존 release gate의 자동 선택을 사용합니다. 검사 commit을 push하고 새 리비전을 배포합니다.
기동 수정 선택: 워크플로우 테스트에서 {"question":"SSE_CHECK"}를 보내 stream_startup_revision=sse-startup-20260928-r1을 확인합니다.
자료 준비: 같은 화면에서 {"API_TYPE":"WARMUP"}, {"API_TYPE":"WARMUP_STATUS"}로 별도 확인합니다.
자료 준비 비용 자체는 남습니다. HTTP 생존 결과는 데이터/모델 검증 성공이 아닙니다.
원복: MODE=rollback ROLLBACK_FROM='<BACKUP_READY 경로>' bash ~/DEV/TRANSFER/GENOS_SSE_STARTUP_20260928_R1_APPLY.txt
원복 후 이전 Git commit과 코드서빙 리비전을 다시 선택합니다. 후속 변경 파일은 자동 덮어쓰지 않습니다.
ZIP 반입, Git commit/push, GENOS 리비전 배포, 자료 준비, 실제 질문 성공은 각각 별도 상태입니다.
