- 질문에서 확인할 사항, 실행한 도구의 결과, 기록된 검토 결과를 표시합니다.
- 모델 수신/형식 검증 반복 알림을 생략하고 30초 간격 대기 안내는 유지합니다.
- 문서명은 서버가 확인한 해당 요청의 문서 범위에 한정합니다.

1. 기존 DEV 적용
   cd ~/DEV
   bash TRANSFER/GENOS_CHAT_FLOW_20260928_R2_APPLY.txt
TXT에는 필요한 ZIP이 내장되어 있습니다. 별도 압축 해제 없이 실행합니다.
사전 확인만 하려면 MODE=check를 붙입니다. 원본 백업·첫 단계부터의 지속 로그와
실패 상태를 기록합니다. 알 수 없는 기존 파일 버전은 덮어쓰지 않습니다.
DEPLOY_ROOT를 생략하면 기존 ~/DEV를 사용합니다. Python은 그 checkout의 .venv/bin/python,
없으면 python3을 사용합니다. PYTHON_BIN으로 실제 현장 Python 경로를 지정할 수 있습니다.

수정 소스는 다음 네 파일입니다.
   02_BACKEND/semantic_runtime/progress.py
   02_BACKEND/semantic_runtime/legal_agent/source_tools.py
   08_DEPLOYMENT/GENOS/stream_app.py
   08_DEPLOYMENT/GENOS/workflow/genos_rag_chat.py
설치기는 그 파일을 참조하는 엔진 manifest와 PIPELINE 코드 해시도 함께 갱신합니다.
그 외 코드·스키마의 기존 pin은 확인하며 다른 변경을 새 코드로 승인하지 않습니다.
generation·CURRENT·모델/인증 설정·Run/Build 값은 유지합니다.

2. 적용한 파일 검토·commit·검증 후 배포
적용 출력의 changed_files 목록에 있는 파일만 git add합니다.
   git diff --cached --check
   git commit -m 'Show readable scoped agent progress in GENOS chat'
같은 checkout의 Python을 사용해 생성된 gate ZIP과 현재 선택 generation을 확인합니다.
   <현장 Python> 06_TOOLS/COMMANDS/genos_release_gate.py --code-zip TRANSFER/chat-flow-20260928-r2/applied-code.zip --deploy-root "$PWD"
generation 옵션을 생략하면 기존 설정/CURRENT에서 선택합니다.
통과한 commit을 push하고 그 commit·기존 generation을 사용하는 코드서빙 리비전을 배포합니다.
실제 선택 generation 절대경로·manifest 해시·commit·서빙 리비전은 현장 기록에 남깁니다.

3. 워크플로우 Python 편집기 별도 교체
GENOS_CHAT_FLOW_20260928_R2_WORKFLOW_PASTE_ALL.txt 전체를 실제 사용하는 워크플로우의
Python 단계에 붙여 넣고 저장·배포합니다. 이 TXT는 Python 본문이며 Bash 실행 파일이 아닙니다.
GENOS_RAG_PROGRESS_UI=socketio를 사용합니다. 기존 TEAM_ID·서빙 ID·주소·인증·대기 설정을 유지합니다.
DEV 적용·Git push·코드서빙 재배포만으로 저장된 워크플로우 Python은 바뀌지 않습니다.

같은 질문으로 다른 팀의 문서명이 표시되지 않는지도 확인합니다.
최종 법률 검토가 설정상 생략된 경우에는 생략 상태를 표시합니다.
각 팀 채팅이 새 워크플로우를 사용하고 있는지 확인합니다.
워크플로우 테스트 자체에 채팅 socket ID가 없으면 실시간 화면 표시는 실제 채팅에서 확인합니다.
