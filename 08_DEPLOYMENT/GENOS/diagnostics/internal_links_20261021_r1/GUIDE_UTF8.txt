1. 가장 짧은 실행 방법

메일의 ZIP과 실행 TXT를 실제 TRANSFER 폴더에 업로드합니다.
그 TRANSFER 폴더를 현재 작업 위치로 두고 아래 명령을 실행합니다.
TRANSFER의 절대 위치를 추정하거나 먼저 DEV로 이동하지 않습니다.

python3 -m zipfile -e ./GENOS_INTERNAL_LINK_AUDIT_20261021_R1.zip ./GENOS_INTERNAL_LINK_AUDIT_20261021_R1
bash ./GENOS_INTERNAL_LINK_AUDIT_20261021_R1/RUN_INTERNAL_LINK_AUDIT.txt check
bash ./GENOS_INTERNAL_LINK_AUDIT_20261021_R1/RUN_INTERNAL_LINK_AUDIT.txt run

기본 대상은 risk_team 내규 전체이며 신상품도 지정 용어로 찾습니다.
DEV의 00_SYSTEM/GENOS_SERVING_PATHS.json에 고정된 generation과 hash를 읽습니다.
파일이 없으면 GENOS_GENERATION 환경변수 또는 아래 명시 옵션을 사용합니다.
이것은 코드스페이스의 DEV 설정 확인이며 실제 배포된 리비전 확인을 대신하지 않습니다.
선택된 파일이 없다고 최근 폴더나 예전 사진의 경로를 임의로 선택하지 않습니다.

GENERATION_REQUIRED가 나오면 실제 서빙 선택값을 확인하여 아래 경로만 바꾸세요.

bash ./GENOS_INTERNAL_LINK_AUDIT_20261021_R1/RUN_INTERNAL_LINK_AUDIT.txt run --generation /실제/선택된/generation/절대경로

DEV 위치가 다르면 --code-root /실제/DEV 를 추가합니다.
DEV 설정과 명시 generation이 다르면 실행을 거부합니다. 이 경우 실제 선택을 먼저 확인합니다.
Oracle 모드(DP=oracle/1/true)는 거부합니다. 이 점검은 기존 불변 generation용이며,
실제 Oracle publication 점검을 위해 과거 NFS를 대신 선택해서는 안 됩니다.
서빙 안에 데이터를 복원/저장하는 도구가 아닙니다.

2. 사진 사례와 검색 표현

사진에서 신상품 정의에 '관련 준칙에서 정한 바에 따라'라는 표현이 보입니다.
사진만으로 관련 준칙 자체의 부재나 실제 연결 누락을 확정할 수는 없습니다.
기존 구조 파서의 참조 서술어 사전은 다음을 사용합니다.
준용, 따른다, 따라, 따라서, 정한, 정하는, 정하여, 규정, 의한다, 의하여,
의거, 갈음, 준하여, 적용한다, 명시된, 기재된.

이 사전은 구조 마커 판별용이며 관계를 모두 자동 생성한다는 뜻은 아닙니다.
이번 점검은 위임/준용/준하여/따름/정함/의함/갈음/적용/참조/별도 정함/
불특정 규정/보충 규정/명시 좌표 등 13가지 표현 묶음과 '신상품'을 원문에서 찾습니다.
'따라서' 등 일반 문장, 소제목의 번호도 후보로 잡힐 수 있습니다. 법적 위임 판정기가 아닙니다.
문서명·조문 좌표가 생략된 관련 준칙/별도 지침은 연결 누락 검토 우선 지점입니다.

상품위원회 문서만 먼저 보려면:
bash ./GENOS_INTERNAL_LINK_AUDIT_20261021_R1/RUN_INTERNAL_LINK_AUDIT.txt run --document-contains 상품위원회

용어를 추가하려면: --keyword 신상품심사 --keyword 상품승인
다른 팀 자료는 그 팀의 점검 권한이 있을 때만 --team 정확한팀ID 로 지정합니다.
기본 risk_team과 external 분류의 자료만 대상 원문으로 출력합니다.
대상 팀이 다르거나 분류를 확인하지 못하면 본문을 출력하지 않습니다.
이 관리자 점검의 팀 필터는 실제 사용자 ACL/판본 선택 정책을 재현하는 검사가 아닙니다.

3. HTML 내려받기와 보는 순서

실행 끝의 DOWNLOAD_ZIP 경로 파일을 GENOS 코드스페이스 파일 탐색기에서 내려받습니다.
내부 PC에서 압축을 풀고 index.html을 열면 됩니다. 대상 원문 HTML도 같이 풀어야 합니다.
외부 웹사이트·CDN·모델·네트워크는 필요 없습니다. 표 검색과 상태 필터는 브라우저에서 동작합니다.
생성된 보고서에는 내부 원문이 있으므로 허용된 내부 환경에서 보관·열람합니다.
메일에 첨부한 도구 ZIP에는 실제 내규 데이터나 모델 키가 들어 있지 않습니다.

먼저 검색창에 '신상품' 또는 '관련 준칙'을 입력합니다.
각 행에서 내규 문서/조항 → 검색 표현과 실제 원문 → 저장된 정의 용어 → 참조 상태
→ '실제 원문' 링크를 열어 대상 문서·구조·판본 메타데이터·원본 SHA256을 확인합니다.
정확한 문자 구간이 저장된 연결은 선택 구간과 주변 블록 원문을 구분해 보여 줍니다.

- 참조 레코드 없음: 그 표현 구간에서 대응 참조를 찾지 못함. 규정 부재/법률 오류의 증명 아님.
- 같은 문장에 연결 존재: 저장된 연결·원문·색인은 맞지만 해당 표현과의 의미 대응은 검토 필요.
- 대상 미확정/부분 연결: 저장된 미해결/일부 연결을 보존. 없는 대상을 추정하지 않음.
- 원문·구조·색인 불일치: source/target 원문·hash·좌표·역참조/target 표 오류를 검출.
- 대상 권한 범위 밖/분류 미확인: 대상 원문을 내보내지 않음.
- 구형 계약: 해당 버전에 없는 검사를 통과로 처리하지 않음.

용어 정의 레코드가 있어도 문서 간 연결이 자동으로 있다는 뜻은 아닙니다.
문장 내 인접한 인용을 위임 대상이라고 확정하지 않습니다. 최종 의미는 원문을 보고 검토합니다.

4. 결과·실패·재실행

index.html: 검색/필터 가능한 점검표
대상 원문 HTML: 중복 대상은 한 파일로 공유
summary.json: 완료/미완료·건수·0건 문서·자원 사용·미검사 범위
findings.jsonl: 원문 구간·검색 표현·정의·참조·실패 사유 전체 기록
inputs.json: 검사한 코드와 generation/DB의 SHA256
internal-link-audit-logs/run-.../run.log, exit.json: 시작부터 지속 로그와 종료 상태

종료 0: 자동 검사 완료. 연결 없음/미확정/의미 검토가 남을 수 있습니다.
종료 1: 검사 완료, 원문·구조·색인 불일치 발견. HTML을 열어 확인합니다.
종료 2: 경로·스키마·hash·자원·실행 오류. 미완료 상태이며 성공으로 간주하지 않습니다.
종료 130: 사용자 중단. 가능한 경우 부분 보고서를 보존합니다.
실패 후 같은 명령을 실행하면 새 시각/프로세스 번호 폴더를 사용합니다.
기존 보고서와 실패 이력을 덮어쓰지 않습니다. 부분 기록은 완료로 합치지 않습니다.

원본 SQLite는 immutable read-only로 열고 시작/종료 hash를 비교합니다.
WAL/SHM/journal이 있으면 완료된 불변 세대가 아니므로 중단합니다.
원본과 겹치는 출력 경로는 거부합니다. schema v1/v2, navigation v2~v7 지원입니다.
한 번에 하나만 실행하세요. 기본 RSS 512MiB·주소공간 1GiB·보고서 200MiB·1시간 제한입니다.
한 문서씩 순차 읽으며 embedding/fulltext 로딩·모델 호출·전체 DB 복제는 하지 않습니다.
대형 DB hash를 시작/종료에 순차 읽으므로 저장장치에 따라 시간이 걸립니다.
원문/색인/MAIN/CURRENT/DEV 코드/워크플로우/배포에는 변경이 없습니다.
원복할 서비스 변경은 없습니다. 점검 중지는 Ctrl+C입니다.

5. 확인 범위와 이번 코드 검토 결과

추가 모델 참조 해석/용어 정의/관계 원장의 존재와 실제 배선은 별도입니다.
