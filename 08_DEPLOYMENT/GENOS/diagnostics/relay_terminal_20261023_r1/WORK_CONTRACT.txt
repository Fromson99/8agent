대상: GENOS 터미널 프로세스에서 승인된 중계 HTTPS 목적지의 연결과 법령 본문 수신 확인.
사용자 전달 2026-10-23: GENOS 구간 방화벽은 해제되었다고 안내받음. 현장 실측 완료와 구분한다.
변경된 목표 흐름: Dataiku 일일 배치 -> GENOS 파이프라인 코드서빙 -> 중계 원문 수집/구조화 -> Dataiku 반환/DB 적재.
이번 범위는 통신 진단 하나이며 파이프라인 통합/배포/DB/MAIN은 변경하지 않는다.
실행: python3 ./GENOS_RELAY_CHECK_20261023_R1.txt. 기본 TCP + HEAD; --body는 GET 1회 추가.
등록 개발계 45.101.64.86:8443/law/DRF; target_url 헤더와 GET OC/ID/type 분리. 운영 주소로 추정하지 않음.
공포일 기준 target=law / ID=010513 / 자본시장과 금융투자업에 관한 법률 1건.
기존 relay_check.py의 XML 검증 함수 5개를 그대로 재사용. 기존 Notebook/파이프라인은 불변.
통신: 직접 연결, 환경 HTTP 프록시 및 .netrc 자동 인증 미사용. TLS 검증 사용; 자동 리다이렉트/우회/재시도 없음.
자격: OC/Cookie는 getpass 비표시 또는 기존 환경변수. TTY 없는 비표시 입력 실패 시 중단.
원응답 전체 해시와 자격값 제거 저장본 해시를 구분. 저장본은 gzip, 결과/로그 권한 0600, 작업 폴더 0700.
복구 담당: Run 한 곳. TCP 1시도, HEAD 1시도, GET 1시도. 동일 run-id는 실패도 재사용하며 자동 재호출 금지.
한도: 새 실행 15분; TCP 10초/HEAD 20초/GET 60초 실시간 상한; 각 연결8초, HEAD읽기10초/GET읽기20초.
응답 최대 12MiB(+크기초과 검출1바이트). 불변 원문 데이터/색인 로드/모델 호출 없음.
중단: 호출 전 IN_FLIGHT와 횟수/기한 보존. SIGINT는 INTERRUPTED, 강제 종료는 IN_FLIGHT를 그대로 보존.
동시 실행: 파일 잠금. 코드/주소/CA/조회 설정 변경은 동일 run-id로 재개할 수 없음.
실패: TCP/DNS/연결/TLS/HTTP/응답 XML/ID·이름/로컬 저장 오류 구분. 빈 본문·오류 XML·HTML200은 성공 아님.
HEAD401/403/404/405 등은 HTTP 응답 수신만 의미. GET200+XML ID/명칭/조문 검증 통과만 BODY_OK.
재개: 같은 run-id에서 network 완료 후 --body 추가 가능(최초15분 안). 이미 시도한 단계는 호출하지 않음.
최종: network 성공 exit0은 HTTP 수신만; --body 성공 exit0은 BODY_OK. 실패2/사용자중단130.
저장 실패를 성공으로 바꾸지 않음. 마스킹되지 않은 예외/요청 URL/토큰은 콘솔에 출력하지 않음.
검증: 최종 TXT를 localhost TLS 서버에 실제 실행해 헤더/쿼리/단계/반환/로그/중복·실패를 검증.
터미널 성공은 해당 실행 노드의 증거다. 다른 코드서빙 컨테이너·리비전의 방화벽/연동 성공으로 확대하지 않음.
