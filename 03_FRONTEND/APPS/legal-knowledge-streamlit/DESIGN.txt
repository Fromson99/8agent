2026-10-21 / 사용자 확정한 0~5번 업무를 기준으로 재구성

목적
배치 상태 확인 → 구조화 누락 승인 → 숏컷 승인 → 위키 관리 → 온톨로지 관리 → 시뮬레이션 → 문제 조건 수정.
운영자가 지식의 생성·승인·사용·검증을 한 화면 흐름에서 관리하도록 설계했다.
app.py 단일 파일을 Dataiku Streamlit 편집기에 붙여 넣는다. 외부 자산이나 별도 서버·에이전트를 추가하지 않는다.

0. 배치 모니터
- 첫 화면: 확인 필요한 배치, 구조화·숏컷 대기, 지식 검토 필요 건수.
- 중계서버 → Dataiku 수집 → 구조화 → 색인·연결 → Oracle 적재의 단계별 상태.
- 고정 예시: 24건 수집, 21건 구조화·적재 완료, 3건 검토 분리. 실제 운영 건수가 아니다.
- 실행 선택·로그·재개 계획과 오늘 처리할 승인 대기 목록.
- 검토 이력에서 현재 세션의 승인·보류·반려·초안 저장·시뮬레이션 미리보기를 확인.
- 실제 재처리 버튼은 배치 API 미연결로 비활성. 승인 예시만으로 배치가 재실행됐다고 표시하지 않는다.
- 기존 AIDP Oracle 조회 예시는 Oracle 점검 탭으로 이동했다.

1. 구조화 누락 승인
- 대기 목록 → 원문 / 기존 구조화 결과 → 보완 제안 → 영향 범위 → 검토 의견.
- 표 각주 누락, 항·호 분리, 명시 참조 연결의 가상 문서 3개를 제공.
- 원문·버전·적용 범위 확인 및 사유 입력 후 승인. 보류·반려에는 사유 필수.
- 승인 시 대기 집계와 세션 이력만 변경하며 원문은 보존. 중복 승인 이벤트를 만들지 않는다.
- 실제 승인 후 선택 대상의 구조화·참조 보완과 하위 색인 재처리를 연결해야 한다.

2. 숏컷 승인
- 사용 중 축적된 실행 기록의 원래 질문, 조사 경로, 확보 근거, 버전, 재사용 범위를 확인.
- 완료 예시와 원문 미확보·부분 완료 예시를 나란히 제공.
- 불완전한 숏컷은 승인 비활성. 보류·반려와 이유 기록은 가능.
- 승인 대상은 경로와 재사용 조건이다. 과거 답변을 정답으로 승인하지 않는다.
- 실제 사용 시 현재 권한·원문 버전·질문 범위를 다시 검사하는 기존 숏컷 저장소에 연결한다.

3. Legal Wiki
- 문서 보기 / 편집 / 근거·연결 / 버전 이력.
- 게시됨·검토 필요·상충 확인 상태를 표시. 적용 범위와 원문 참조를 함께 확인.
- 제목·본문·적용 범위·변경 사유를 초안에 저장하고 검토 요청할 수 있다.
- 초안과 게시 버전을 분리해 보존한다. 실제 게시 버튼은 미연결 상태로 비활성.
- 연결된 온톨로지로 이동 가능. 기존 위키 컴파일러나 저장소를 복제하지 않는다.

4. 온톨로지 관리
- 생성 후보 목록 → 개념·입력·조건·결과의 관계도.
- 적용 조건 / 미확인 처리 / 제외·재개 / 근거 연결을 선택해 확인.
- 업무 범위, 기준일 필요 여부, 부족한 정보 처리, 제외·재개 기준을 수정해 새 초안 버전 저장.
- 선택 버전으로 시뮬레이션 설정 화면에 이동.
- 실제 법률 의미 판정이나 조건 컴파일을 수행하지 않는다. UI에서 관계 구조를 보여주는 예시다.

5. 시뮬레이션
- 온톨로지 후보 버전 + 시나리오 묶음을 선택.
- 정상, 기준일 누락, 범위 밖, 예외, 원문 버전 변경, 누락 자료 확보 후 재개를 비교.
- 기대 동작 / 관찰 결과 예시 / 일치·불일치·미확인을 같은 표에서 확인.
- 불일치 사례 → 연결된 온톨로지·문제 항목으로 이동 → 조건 편집 → 다시 검증 흐름.
- '결과 화면 미리보기'는 고정된 합성 결과를 표시한다. 실제 엔진·LLM·검색·품질 실험 실행이 아니다.
- 결과는 선택 당시 후보 버전·내용 지문·시나리오 묶음에 결속하고 이전 결과를 보존한다.
- 후보 수정 후 이전 결과는 현재 버전의 검증 결과가 아님을 표시한다. 대상·묶음 변경도 따로 표시한다.
- 실제 실행·게시 API는 미연결이다. UI의 예시 일치 수를 정확도나 운영 검증 통과로 보고하지 않는다.

실제 연결 지점 — 전부 후속 연결 필요
배치: 기존 중계서버 수집 기록·Dataiku 배치 실행·단계 산출물·Oracle 적재 receipt.
구조화: 원문 위치·해시·구조화 후보 버전·보완 승인·선택 범위 재처리.
숏컷: 기존 실행 저널·숏컷 authority의 완료 상태와 재사용 승인.
위키: 기존 위키 compiler/store와 공통 지식 계약·게시 API.
온톨로지: lawrag/legal_knowledge 계약·서비스·Oracle adapter, 조건/참조의 게시 시 정리.
시뮬레이션: 버전 고정된 지식·원문·질문 묶음·예산을 기존 실행 경로에 결속.
현재 /v1/legal-knowledge의 objects/documents/source-reference/commands/operations/preview/impact는 기존 관리 경계다.
이 시안은 해당 API를 호출하지 않으며, 미구현된 배치·승인 API가 존재한다고 가정하지 않는다.
Dataiku 인증에서 신뢰할 수 있는 서버 principal·팀·문서 권한을 전달해야 한다.
브라우저 체크박스를 실제 권한·원문 검증으로 사용하지 않는다. 실제 승인 시 서버에서 재검증한다.
문서/지식 버전, CAS, 멱등 요청 ID, receipt, 실패/부분 성공/중단/재개 상태는 기존 계약을 유지한다.
UI rerun이 게시·배치·시뮬레이션을 자동 중복 실행하지 않도록 실제 호출 경계를 별도 연결해야 한다.

Oracle 점검의 기존 계약
기존 streamlit_oracle_smoke_20261021_r1 조회 예시를 유지한다.
Dataiku SQLExecutor2 / AIDP, 읽기 전용 SELECT. 자동 실행·자동 재시도·전체 다운로드 없음.
테이블 최대 201개 조회/200개 표시, 열 41개 조회/40개 표시, 데이터 최대 20행, 텍스트/CLOB 300자.
BLOB 등 미지원 형식 제외. 순서·전체 건수·원문 전체를 검증하지 않는다.
실행 계정의 DB 권한을 사용하며 문서별 사용자 권한은 미연결. 개발자용 웹앱 접근 범위에서만 사용.
연결/스키마/접두어 변경 시 이전 목록·데이터·연결 성공 상태 제거.
목록 갱신·데이터 조회 실패 시 이전 결과 제거, 실패 번호·ORA 코드만 화면 표시.
원인 traceback은 Dataiku 백엔드 로그. 실패를 빈 결과 성공으로 바꾸지 않는다.
요청당 연결 1회, 목록 1회, 미리보기 최대 2회 SQL. timeout은 현장 연결 설정을 따른다.
