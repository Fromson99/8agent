# 구조 해석 검수 서비스

```bash
docker compose up -d --build
open http://localhost:5566
```

## 화면

| 영역 | 내용 |
|---|---|
| 왼쪽 | 구조 트리. 클릭하면 해당 구역의 블록이 페이지에서 강조되고 그 쪽으로 스크롤한다 |
| 가운데 | 원본 PDF 페이지 위에 청킹 범위를 겹쳐 그린다. 색 = 계층 깊이(L0~L6) |
| 오른쪽 | 적합도 분해, 유도된 사다리, 사다리 결함, LLM 배치 결과, 잔여 목록 |

- **점선 박스** = 그 구역에 속한 블록(청크 범위)
- **실선 박스 + 라벨** = 구역을 여는 마커
- **빨간 테두리** = 잔여(결정론이 못 가른 것). 오른쪽 목록을 클릭하면 그 자리로 간다
- 박스에 마우스를 올리면 블록 원문·마커·판정 사유가 뜬다

## 힌트 주입

상단 `힌트` 를 열어 넣는다. 무엇을 주든 관측은 계속 돌고, 어긋나면 오른쪽에 경고가 뜬다.

| 칸 | 예 | 뜻 |
|---|---|---|
| 좌표 최상위 | `kr_article` | 이보다 얕은 계열을 L0 으로 접는다 (`제19조/제3항` 규약) |
| 어휘 제한 | `dot_number, roman` | 이 계열의 제안자만 발화 |
| 층 지정 | `dot_number:1; dot_number:2; circled` | 층을 통째로 지정(유도 건너뜀) |
| 부분 순서 | `kr_장>kr_절, kr_절>kr_article` | 증거가 얇은 쌍만 못박기 |

`LLM 해소` 를 켜면 결정론이 못 가른 잔여만 모아 **문서당 배치 1콜**로 묻는다.
`ANTHROPIC_API_KEY` 가 없으면 이 단계만 건너뛰고 결정론 경로는 그대로 돈다.

## 왜 이런 구성인가

- **페이지를 서버가 PNG 로 렌더한다.** PDF.js 를 붙이면 CDN·번들에 묶인다. PyMuPDF 는
  파싱 때문에 이미 있고, 이렇게 하면 망 없이 컨테이너 안에서 돈다.
- **좌표는 0~1 비율로 준다.** 화면 배율이 바뀌어도 그대로 곱하면 되고 서버가 배율을 모른다.
- **`TORCHDYNAMO_DISABLE=1`.** slim 이미지에 g++ 가 없어 docling 의 `torch.compile` 이
  죽는다. 컴파일러를 넣으면 이미지가 ~200MB 커지는데, 추론 정확도는 eager 로도 같고
  문서당 한 번만 파싱하므로 끄는 쪽을 택했다.

## 운영

```bash
docker compose logs -f
docker compose ps
docker compose down          # 볼륨은 남는다
docker volume rm 8-agent_structure-data                       # 올린 문서까지 지울 때
```

| 환경변수 | 기본 | 뜻 |
|---|---|---|
| `PORT` | 5566 | 호스트 포트 |
| `BAKE_MODELS` | 1 | 빌드 시 docling 모델을 이미지에 굽는다. 0 이면 빌드가 빠르고 첫 요청이 느리다 |
| `MAX_UPLOAD_MB` | 40 | 업로드 상한 |
| `STRUCTURE_RENDER_SCALE` | 2.0 | 페이지 PNG 렌더 배율 |
| `ANTHROPIC_API_KEY` | — | 없으면 LLM 해소만 비활성 |

볼륨 `structure-data` 에 올린 PDF·해석 결과·페이지 캐시가 남는다.
