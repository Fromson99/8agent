GENOS 채팅 전달 형식 및 요청 시간 진단 인계 (2026-09-23)

1. 현재 작업 코드에서 확인한 전달 형식

채팅 화면 -> 워크플로우 Python run(data) -> 코드서빙 JSON 게이트웨이 ->
service.py의 LEGAL_AGENT -> POST /v1/rag/ask -> 결과 body.answer.text ->
워크플로우 반환 {"text": "최종 답변", "answer_status": ..., "run_id": ...,
"request_id": ..., "tm_code_serving": 초, "tm_total": 초}.

워크플로우 입력의 최상위 question 또는 chatInput 등에 실제 질문이 있어야 한다.
코드서빙에는 {"API_TYPE":"LEGAL_AGENT","question":"...","team_id":"risk_team",...}
형태로 보낸다. 정상 게이트웨이 응답은 {"status":200,"body":{"answer":{"text":"..."}}}다.
모델의 choices[].message.content JSON은 중간 응답이며 프론트로 직접 반환하는 형식이 아니다.
사진만으로 현장 워크플로우/코드서빙 리비전과 화면 수신 여부는 확인할 수 없다.
작업 코드의 기본값은 워크플로우 코드서빙 대기 120초, v5 요청 상한 300초다.
현장에도 그대로 적용됐다면 화면 쪽 대기가 먼저 끝날 수 있다. 현장 설정과
workflow.request.crashed/code_serving.response.received 시각을 확인해야 한다.

2. 현장 JSON에서 시간 TXT 생성

코드서빙 환경에 GENOS_SHARED_LOG_DIR을 설정하고 새 요청을 실행하면 날짜별
요청 JSON과 기본 읽기용 TXT가 생성된다. 내부 질문/원문이 포함된 JSON은 외부로
보내지 말고 GENOS 내부 코드스페이스에서 다음을 실행한다.

python3 06_TOOLS/COMMANDS/genos_request_timing.py \
  --report /nfs-root/diamo/8-agent/rag-request-reports/YYYY-MM-DD/<run_id>-<suffix>.json \
  --output /nfs-root/diamo/8-agent/rag-request-reports/YYYY-MM-DD/<run_id>-timing.txt

파일 이름을 모르면 같은 요청의 run_id로 조회한다:
find /nfs-root/diamo/8-agent/rag-request-reports -type f -name '<run_id>-*.json'

워크플로우 컨테이너의 JSONL 로그를 별도 파일로 내보낼 수 있으면
--workflow-log <경로>를 더한다. 그러면 같은 request_id의 수신/완료 이벤트를 붙인다.
없으면 코드서빙 완료와 화면 전달 여부를 분리해 '미확인'으로 표시한다.

시간 TXT에는 코드서빙 전체 시간, 부팅 단계, 모델 호출별 시간, 재시도/수정 횟수,
최종 gate와 답변 길이만 기록한다. 단계 시간이 중첩되므로 단순 합산하지 않는다.
원본 질문, 원문, 프롬프트, 모델 응답, 인증키는 TXT에 복사하지 않는다.

3. 현장 확인 순서

- 화면 질문이 워크플로우 입력의 question/chatInput에 실제로 들어갔는지 확인한다.
  'Type Your Message'가 입력값으로 전달되었다면 화면 입력 배선을 점검한다.
- 워크플로우 로그의 request_id와 코드서빙 요청 JSON의 request_id를 맞춘다.
- workflow.request.finished와 tm_total이 없으면 화면으로 반환되기 전 문제다.
- code_serving.response.received가 없고 timeout이면 코드서빙 또는 게이트웨이 지연이다.
- 코드서빙 JSON에서 긴 model.attempt 단계/HTTP 오류/SEMANTIC_REPAIR를 확인한다.
- gate=CLARIFY여도 answer.text가 비어 있으면 되묻기 문장 생성/표시 계약을 점검한다.

현장 JSON과 워크플로우 로그는 이 외부 개발 환경에서 접근할 수 없어 실제 요청의
소요 시간·원인은 아직 측정하지 않았다. 이 인계는 현장 실행 스크립트와 계약 점검 결과다.
