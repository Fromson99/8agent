# internal-legal-search 1.0.0 적용 설계

2026-09-22. 요청된 공개 검색 방식과 내부 실패 기록을 통합한 **제품용 스킬 명세 완성본**이다. 런타임 연결·모델 효과 비교·MAIN 승격은 미실행이다. 소형 모델도 사용할 수 있도록 기존 단계와 도구 안에서 행동을 고르게 설계했으며, 특정 모델 크기에서의 성공을 보증하지 않는다.

## 최종 구성

| 구성 | 결정 | 적용 내용 |
|---|---|---|
| 질문 전체 역매칭 | 유지 | 질문의 법령명·좌표·본문 용어를 훼손하지 않는 후보 생성. 모델의 검색어 추출로 대체하지 않음 |
| 좌표·전문·용어 검색 | 유지 | 단서에 따라 경로 선택. 역매칭을 모든 질문의 강제 첫 단계로 만들지 않음 |
| 짧은 요구 관리 | 유지·보강 | v5 question_plan 재사용. 요구와 배경 분리, 계획 불변 시 null. 새 대형 장부 없음 |
| 검색→읽기 전환 | 보강 | 관련 후보가 있으면 읽기 우선. 미리보기·후보 수를 근거 확보로 계산하지 않음 |
| 읽기→선택→인용 전환 | 보강 | 전달된 출처를 명시적으로 선택. compose의 허용 근거 확인 |
| 예외·준용 확인 | 보강 | 결론에 관련되는 참조만 따라가되 필요한 출발·대상 원문은 모두 확보 |
| 오류 복구 | 보강 | 새 검색은 새 커서, 부분 성공 보존, 잘못된 필드·인용·선택 상태를 실제 수정 |
| 검토 | 유지·보강 | 주장·요구별 원문 대조, 정확 구절 복사, 수정이 실제 초안에 반영되는지 확인 |
| 대형 범용 조사 프롬프트 | 제외 | 새 연구계획 단계·고정 출처 개수·모든 도구 순회·다중 에이전트 없음 |
| HyDE·상상 답변 기반 검색 | 제외 | 현재 법률 원문 검색에 가상 규정을 섞지 않음 |
| 벡터 검색·전용 DB | 이번 버전 제외 | 현재 도구 계약에 없음. 어휘 차이로 남는 회수 실패가 확인되면 별도 후보로 비교 |
| 예산 확대 | 제외 | 10만자 작업 프로필은 다른 작업의 변경. 이 스킬은 프로필 값을 수정하지 않음 |
| 자동 스킬 학습·배포 | 제외 | 실패 기록으로 사람 검토 가능한 개정안을 만들되 평가 후 명시적으로 반영 |

## 현재 연결 상태

확인한 로컬 활성 포인터는 `legal-agent-v5-20260922-r3`, generation 20, `quality_certified=false`다. 선택된 코드와 작업 코드는 별개이며 GENOS 현장은 미확인이다. 현장 접근은 시도하지 않았다.

| 구분 | 확인 결과 |
|---|---|
| 기존 실행 | service/API → 선택 릴리스의 legal-agent v5 → ObligationSession/TiersSession → ModelGateway |
| 기존 모델 입력 | `question_obligations.SYSTEM/PROMPTS`, 도메인, 현재 view, output_schema, 번호 변환 계약 |
| 새 스킬 소비자 | 향후 같은 ModelGateway의 단계별 지침. **현재 파일 자동 탐색·로더 없음** |
| 보관 위치 | 제품에 동봉할 명세이므로 저장소 `00_SYSTEM/LEGAL_AGENT/skills`에 보관. Codex 개인 스킬 설치와 구분 |
| 모델 추가 호출 | 스킬 설계에 별도 모델 단계 없음. 실제 총 호출·지연·토큰 변화는 미측정 |
| 원문·색인 | 이번 파일 작성으로 새 세대·재색인·스키마 이행 없음 |
| 실험 후보 0507/0508 | 우선순위·좌표·보존 수정의 격리 후보. 해당 구현을 활성 릴리스 기능으로 취급하지 않음 |

코드 근거: [gateway.py](../../../../../02_BACKEND/semantic_runtime/legal_agent/gateway.py), [question_obligations.py](../../../../../02_BACKEND/semantic_runtime/legal_agent/question_obligations.py), [workflow_tiers_policy.py](../../../../../02_BACKEND/semantic_runtime/legal_agent/workflow_tiers_policy.py), [obligation_protocol.py](../../../../../02_BACKEND/semantic_runtime/legal_agent/obligation_protocol.py), [relations_protocol.py](../../../../../02_BACKEND/semantic_runtime/legal_agent/relations_protocol.py).

## 도입 시 계약

1. 적용할 정확한 기준 릴리스·코드·프로필·데이터를 먼저 고정한다. 현재 작업본 전체를 활성 코드로 간주하지 않는다. `package.json`의 파일 해시는 이 작성 시점 근거이며 운영 registry가 아니다.
2. 모델 입력에는 SKILL 본문의 공통 규칙과 현재 단계 지침을 넣는다. 탐색에는 복구·종료도 포함한다. 유지보수 참조·실패 문항·gold는 제품 입력에서 제외한다. 기존 기본 계약과 출력 스키마를 유지하며 중복 설명 정리는 별도 검증 대상이다.
3. 현행 ModelGateway의 `system`/`prompts` 입력 경계를 재사용한다. 별도 실행기·벡터 서비스·새 phase를 만들지 않는다. 저장소의 논리 root resolver로 스킬 경로를 찾고, 누락·해시 불일치 시 해당 후보의 로딩 실패를 명시한다. 조용히 다른 스킬이나 모델로 대체하지 않는다.
4. 실제 통합 시 [legal_agent_contracts.py](../../../../../06_TOOLS/COMMANDS/legal_agent_contracts.py)의 동결·검증 범위와 release manifest에 지침 파일·로더·프로필 해시를 함께 결속한다. 현재 strict 프로필에 임의 `skill_path` 키를 추가하면 호환되지 않는다. 배선 변경을 별도 코드 변경으로 검증한다.
5. 번호는 요청마다 매핑되므로 예시 ID를 지침에 박지 않는다. 현재 계약은 `actions` 배열, `source_selection.choices`, 빈 `assessments`/`relation_assessments`를 유지한다. `question_refs`에는 현행 v5가 허용하는 demand refs만 사용한다. ADR0508의 배경 참조 허용 변경을 현재 계약으로 혼용하지 않는다.
6. 검증 후 승격은 기존 MAIN 절차를 따른다. 지침·코드·데이터·프로필을 하나의 release로 결속하고 apply/rollback receipt를 남긴다. 되돌릴 때는 이전 전체 release 결속을 복원한다. GENOS는 별도 반입·내부 모델 검증 대상이다.

## 스킬과 별도로 필요한 서버 보강

| 우선 | 변경 경계 | 필요한 동작 | 스킬만으로 해결되지 않는 이유 |
|---|---|---|---|
| 1 | workflow_tiers_views.build | 검색 영수증·미완료 범위·마지막 실행 결과를 모델에 전달 | 모델은 누락된 결과를 읽을 수 없음 |
| 1 | 같은 view의 원문 packing·선택 화면 | 실제 전달 여부, 부분 범위, 미전달 원문과 재개 행동을 보존. 선택 화면 밖 기존 출처 유지 | 서버에서 읽은 것과 성공한 모델 호출에 제시한 것은 다름 |
| 1 | selection → compose → review | 선택·허용 출처를 동일하게 보여주고 오류에 현재 가능한 수정 행동 제공 | 유효한 번호라도 인용 자격이 없을 수 있음 |
| 2 | navigation_match / term_occurrences / search preview | 명시 좌표와 본문 관련성을 함께 정렬하고 적중 구절 표시 | 단순 source ID 순서·본문 앞부분 preview는 판단 단서가 약함 |
| 2 | session 진전·복구 제어 | 새 결과 제시/읽기 대기를 진전과 구분하고 중복 행동의 복구 경로 제공 | 서버가 조기 종료하면 모델 지침을 실행할 기회가 없음 |
| 후속 | vector 후보 회수 | 현행 경로에서 놓친 의미 유사 표현에 한해 비교, 기존 권한·판본·원문 연결 유지 | 설치 자체가 관련성·읽기·선택·최종 답변을 보장하지 않음 |

위 항목은 구현 완료 표시가 아니다. 상세 배선은 [앞선 검색 설계](../../../../../07_DOCS/REFERENCE/REPORTS/LEGAL_SEARCH_SKILL_DESIGN_20260922/README.md)를 따르되 최신 활성 포인터를 다시 확인한다.

## 검증과 완료의 의미

이번 완료 범위는 SKILL 문법, 참조 링크, 실제 v5 필드·도구와의 정적 대조, 출처·파일 해시 보존이다. 모델 호출·과거 실행 재채점·성능 비교는 하지 않는다. `validation.json`은 이 정적 검증만 기록한다.

실제 효과 비교를 시작할 때는 [실험 지침](../../../../../04_EXPERIMENTS/LEGACY_ADR/EXPERIMENT_AGENT_PROMPT.md)과 [표준](../../../../../04_EXPERIMENTS/LEGACY_ADR/STANDARD.md)을 끝까지 읽고, 같은 scope reservation 확인 및 새 ADR 선점부터 수행한다. 이 문서는 미실행 비교를 이미 동결한 PLAN으로 대신하지 않는다.

| 검증 대상 | 후속 ADR에서 사전 고정할 기준 |
|---|---|
| 비교 조건 | 같은 기준 릴리스·데이터·모델·예산에서 기준/스킬 후보. 서버 수정은 별도 arm으로 분리 |
| 실패 재현 | 좌표·약칭, 문맥+요구 분리, 후보만 찾고 미읽기, 커서 변경, 부분읽기, 미선택 출처 인용, 예외 누락, AND/OR, 인용 복사 오류 |
| 회수 단계 | 발견 → 읽기 → 실제 모델 전달 → 선택 → 최종 인용을 source_id로 각각 기록 |
| 실제 결과 | 근거 있는 최종 답변 완료율과 요구 충족·조건 보존을 확인. 형식 통과·후보 수·호출 감소를 성공 대신 쓰지 않음 |
| 허용 회귀 | 권한·판본·인용 무결성 위반 0. 품질·회수·호출·지연의 수치 기준은 결과 확인 전에 정함 |
| 과적합 방지 | 여기 읽은 실패 문항은 설계 자료. 신규 holdout을 별도 고정하고 평가 원문은 제품에 노출하지 않음 |
| 최종 환경 | 외부 실험 허용 scope와 ExperimentClient 정책 확인. 실제 내부 자료는 GENOS 내부 모델로 검증 |

현재 최종 사용 품질은 미확인이다. 정확도 개선율·소형 모델 성공률·비용 절감률을 추정치로 제시하지 않는다.
