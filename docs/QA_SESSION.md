# QA 세션 질문지 — 신탁계약서 자동검증 과제

> 요구사항(수탁 업무 효율화를 위한 신탁계약서 자동검증 체계 구축)과
> 현재 구현(agent1: 신탁계약서 ↔ 투자설명서 대사)을 대조해 뽑은 확인 사항.
> ★ = 답에 따라 설계가 갈리는 최우선 질문.

---

## 0. 헤드라인 — 요구사항과 구현의 간극

| # | 간극 | 현재 상태 |
|---|---|---|
| 1 | 요구사항의 비교 대상은 **핵심상품설명서**, 구현은 **투자설명서**(B1055656A, 66p 펀드 투자설명서) | 핵심상품설명서 실물을 본 적이 없음 |
| 2 | 기능 2 **변경대비표 ↔ 신탁계약서** 대사 | **전혀 미구현** — 용어집·형식·rule 없음 |
| 3 | 비교 항목에 **투자대상** 명시 | 운용방법 체크박스(√) 검출은 v3로 미룬 항목 — 그리드가 24조각으로 흩어짐 |
| 4 | 전달 채널 = **메일(MCP or API)** | FastAPI + 검수 화면만 있음. 메일 송수신 어느 쪽도 없음 |
| 5 | 사용자 직접 업로드 → 실물은 날인 **스캔본** 가능성 | born-digital 전제, OCR 금지. 스탬프 값이 인쇄 문구와 분리되는 문제 실측됨 |

---

## A. 비교 대상 문서 정의 ★

1. **핵심상품설명서 실물 샘플을 받을 수 있는가?** 몇 장짜리 어떤 양식인가?
   투자설명서(수십 페이지)와 다른 문서라면 용어집·형식을 새로 컴파일해야 한다.
2. 핵심상품설명서 양식은 **표준화**되어 있는가, 운용사·판매사마다 다른가?
   양식 종류 수 = 형식 컴파일 횟수다. 수십 종이면 컴파일 국면 자동화(LLM 형식 유도)가 선행 과제가 된다.
3. 신탁계약서 쪽은 특정금전신탁 외에 어떤 유형이 오는가? (재산신탁·유언대용신탁 등)
   유형별 계약서 양식 수는?
4. "내용(투자대상, 과제 등) 일치"에서 **비교 항목 확정 목록**을 받을 수 있는가?
   현재 rule은 보수·기간·금액·지급조건 중심 12개다. 수탁팀이 실제로 눈으로 대조하는 항목 체크리스트가 있으면 그대로 rule로 옮긴다.

## B. 변경대비표 (기능 2) ★

5. **변경대비표 실물 샘플** 확보 가능한가? 표준 양식(변경 전/후 2열 표)인가?
6. "변경대비표가 정답"의 정확한 의미는? —
   (a) 대비표에 적힌 변경사항이 새 계약서에 **반영됐는지만** 확인하면 되는가,
   (b) 대비표에 **없는 조항이 바뀐 것**(무단 변경)도 잡아야 하는가?
   (b)라면 문서 전체 diff가 필요해서 난이도가 한 단계 다르다.
7. 변경 전 계약서 원본도 함께 업로드되는가, 아니면 대비표+새 계약서 두 개만 오는가?

## C. 판정 기준과 오류 허용치 ★

8. 어느 쪽 오류가 더 치명적인가 — **불일치를 놓치는 것**(false MATCH) vs **일치를 불일치로 오탐**(false alarm)?
   현재 설계는 애매하면 전부 NEEDS_REVIEW(사람 검토)로 빼는데, 이 비율이 높으면 효율화 효과가 줄어든다. 허용 가능한 검토 비율은?
9. AI 검증을 통과한 문서는 담당자 검토를 **생략**하는가, 아니면 어디까지나 보조 도구인가? (책임 소재·감사 대응)
10. 표기 차이 허용 기준 합의 — 예: `금 1억원정 (₩100,000,000)` ≡ `100,000,000원`은 일치로 처리 중. 현업 기준과 맞는지 확인 필요.

## D. 입력 데이터 실물 ★

11. 업로드되는 파일 형태는? — **날인·서명된 스캔 PDF 비중**이 얼마나 되는가? HWP·워드도 오는가?
    현재는 텍스트 레이어 있는 PDF 전제(OCR 금지). 스캔본이 주류면 OCR 도입 + 정확도 기준을 다시 세워야 한다.
12. 체결본의 수기·스탬프 기입값(계좌번호, 기간, 금액)이 어느 정도인가?
    실측에서 스탬프 값이 인쇄 문구와 분리돼 나오는 문제(`20 년 월 일부터 … 6 3 27 6 2`)가 확인됨.
13. 검증된 **정답 쌍**(계약서–설명서, 계약서–대비표)을 몇 건이나 받을 수 있는가?
    현재 골든 쌍의 설명서는 합성 문서다 — 비교 로직은 검증됐지만 실물 추출 정확도는 미검증. 기대 판정(정답 라벨)은 누가 만들어 주는가?
14. 월 처리 건수와 건당 기대 처리 시간은? (신규 계약 건수, 변경 계약 건수)

## E. 전달 채널 — 메일 (MCP or API) ★

15. **입력도 메일인가?** — 담당자가 메일에 첨부해 보내면 자동 실행되는 그림인가, 별도 업로드 API를 호출하는 그림인가?
16. 결과 리포트를 메일 **본문 표**로 넣는가, 첨부(PDF/Excel)로 주는가?
    현재 산출물은 JSON — 사람이 읽을 리포트 양식을 새로 만들어야 한다. 현업이 원하는 리포트 양식 샘플이 있는가?
17. 사내 메일 시스템 연동 방식은? (SMTP 직접? 사내 메일 API? MCP 서버가 이미 있는가?)
    보안 결재·수신자 제한 등 절차 확인.
18. 향후 SCS 적용 시 인터페이스 규격이 정해져 있는가? (지금 API 응답 스키마를 그쪽에 맞춰둘지)

## F. LLM 사용과 보안 ★

19. 계약서에는 고객 실명·계좌번호가 있다. **외부 LLM API(Anthropic) 호출이 허용되는가?**
    망분리·개인정보 규정상 불가라면 — 사내 LLM(GenOS)으로 대체해야 하는데, 판정 품질 재검증이 필요하다.
20. 현재 판정 단계에 LLM이 상시 개입하는 경로가 기본이다(증거 ID 인용 강제로 출처 위조는 차단).
    같은 입력에 판정 문구가 달라질 수 있는데(비결정론), **감사·검사 대응 관점에서 수용 가능한가?**
    수용 불가면 결정론 경로(core/reconcile.py)로 운영하고 LLM은 보조로 내려야 한다.
21. LLM 호출 비용·건수 제한이 있는가? (건당 호출량은 rule 수에 비례)

## G. 운영·확장

22. 새 양식(형식 미등록 문서)이 들어오면 현재는 **격리**하고 사유를 보고한다.
    격리된 문서의 후속 처리 프로세스는? (담당자 수동 검토? 형식 추가 요청?)
23. 5번 과제(장외파생상품 계약서)와 코어를 공유하는 그림인가? 일정·담당 조율 필요.
24. 자산운용보고서 확대 시점은? (주기 문서라 형식은 안정적일 가능성 — 컴파일 국면 검증 기회)

## 내부 리스크 (질문은 아니지만 QA에서 역질문 대비)

- **형식 파일이 규칙 기반 초안(--no-llm), 신뢰도 low.** LLM 컴파일 경로는 코드·스키마만 있고 실호출 미검증.
- **홀드아웃 부족.** 스펙은 샘플 3+홀드아웃 2를 요구하나 현재 빈 템플릿+체결본 2개뿐 — 형식이 이 두 문서에 과적합됐을 수 있다.
- **체크박스(√) 검출 미구현** — 요구사항이 명시한 '투자대상' 비교와 직결. v3로 미뤄둔 상태.
- **rule 파일이 두 벌(스키마 상이)** — 결정론 엔진용과 LLM 판정용. 운영 경로를 하나로 정하지 않으면 규칙 이중 관리가 된다.
- **비교 로직은 검증, 추출 정확도는 미검증** — 골든 설명서가 합성(md)이라 실물 PDF에서의 값 추출 성능 수치가 없다.
