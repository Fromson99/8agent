# 규칙 루프 — 연역·귀추·귀납, 그리고 정착(공리)

자가 규칙(self-rule) 루프 설계. 사람이 무한히 수정할 수 없고, 새 데이터를
pull받으면 같은 문제가 좌표만 바뀌어 재발하기 때문에 — 승인된 수정 사례를
문서 무관 규칙으로 일반화해 시스템이 스스로 반복을 끊는다.

핵심 한 문장: **LLM은 귀추(진단)와 귀납(일반화)에만 등장하고, 연역(적용)은
100% 결정적이며, 공리성은 명제의 속성이 아니라 규칙이 획득하는 역할이다.
그리고 이 전체는 스위치 하나로 오늘의 시스템으로 되돌아간다.**

---

## §1 추론 지도 — 네 양식이 코드 어디에 앉는가

| 양식 | 하는 일 | 실행자 | 시점 | 코드 |
|---|---|---|---|---|
| **연역** | 이론(정의+규칙)을 데이터에 적용해 결론을 끌어냄 | 결정적 코드 | 질의·색인·인제스트 (런타임) | `rules.apply_edge`(신규), `verdicts.redirect_map`, `fitness_gate`, `router` |
| **귀추** | 이상 관측의 최선 설명 — 결함 진단, 교정 가설 | LLM, 닫힌 후보만 | 답변 직후 백그라운드 | `audit`(4갈래 지문), `answer.repair_landings`, `judge.settle_cross` |
| **귀납** | 확정 사례 군집 → 일반 규칙 후보 | LLM(닫힌 술어 DSL) + replay 검증 | 오프라인 배치 (컴파일 타임) | `core.rag.induce`(신규) |
| **공리화** | 규칙의 역할 전환 — 의심의 방향 뒤집기 | 사람 (보고서는 결정적) | 승격/강등 결정 시 | `rules.promotable / demotable`(신규) |

SPEC 핵심원칙 ①("stochastic은 컴파일 타임에 가둔다")의 확장이다:
**stochastic 추론 양식(귀추·귀납)은 런타임 밖에, 연역만 런타임에.**
퍼스(Peirce)의 삼분법 그대로 — 귀추가 가설을 낳고, 연역이 결과를 끌어내고,
귀납이 가설을 시험해 이론에 편입한다. 이 레포에서 "이론"은 파일이다.

## §2 자산의 4층 — 무엇이 무엇에서 태어나는가

```
정의 (선언 커널)     registry.yaml · format 선언 · 술어 어휘 · 임계 상수
                    → 귀납되지 않는다. 사람이 코드+테스트로 바꾼다. 반례로 수정 안 됨.

사례 (확정 인스턴스)  edge_rules.json · links.json · structure_fixes.json
                    → 귀추(LLM 진단) + 승인의 산물. 좌표에 묶임. 문서가 개정되면 죽는다.

규칙 (귀납층)        data/rules/general_rules.json
                    → 귀납의 산물. 술어로 쓰여 문서 무관. 반증 가능. 이 문서의 주인공.

정착 (역할)          규칙의 status 값 — 별도 파일이 아니다
                    → 공리화의 산물. 반례가 왔을 때 피고가 규칙이 아니라 데이터가 된다.
```

두 불변식이 이 층들을 안전하게 만든다:

1. **행동 어휘 폐쇄** — 규칙의 then 은 사람 승인이 남길 수 있는 행동
   (suppress/redirect/demote/entry_block/link/계층교정/용어상태)뿐이다.
   규칙은 "일반화된 승인"이며, 승인이 못 하는 일은 규칙도 못 한다.
2. **술어 어휘 폐쇄** — when 은 `rules.PREDICATES` 에 등록된 이름만 쓴다.
   전부 색인이 이미 가진 값(surface·kind·marker·부모자손·질의 특징)으로
   계산되는 문서 무관 신호다. doc_id·노드 좌표 리터럴은 적재 시점에 거부
   (`FORBIDDEN_KEYS`) — structure/registry.py 의 FORBIDDEN_ATTRS 와 같은 규율.

## §3 한 사이클 — 착지 교정 사례로

```
연역   질의 → 참조 간선이 제2조(조 전체)에 착지한 답이 나감
귀추   사후 감사 LLM: "표면은 제2조 제3항까지 말했다 — 착지가 얕다"
       → verdicts.jsonl kind:"교정" (기록만, 반영 없음)
승인   사람(후엔 자동 부검)이 확정 → edge_rules.json redirect[] 사례 1행
귀납   같은 모양 사례 7행 군집 → LLM이 술어로 일반화:
       when: {edge.surface_has_ordinal:"항", edge.dst_kind:"조",
              dst.child_matching_surface_ordinal:"유일"}
       then: {redirect:"그_자손"}
       → replay: 근거 7건 재현(홀드아웃 2건 포함) + 전 간선 대조에서
         suppress·정답피드백과 충돌 0 → 잠정
승격   잠정→규칙(자동, replay 녹색) → 발동 시작, via:"규칙" 태그
정착   4기준 충족 → 사람이 승격 → 인제스트 게이트로도 발동,
       반례는 규칙이 아니라 데이터를 심판
재발동  개정판 pull → doc_id 바뀜 → 사례 7행은 죽은 좌표.
       규칙은 새 간선에서 술어를 다시 평가해 그대로 발동.
       LLM 0회, 사람 0회 — 루프가 여기서 닫힌다.
```

## §4 상태 사다리와 자동화

```
잠정 ──자동(replay 녹색 + 근거 최소건수)──▶ 규칙 ──사람(4기준 보고서)──▶ 정착
  ◀──────자동(반증 카운트)──────────────────┘        ◀──사람(영향 분석 첨부)──┘
```

| 상태 | 발동 | 반례의 피고 | 수정 |
|---|---|---|---|
| 잠정 | 안 함 (replay 성적만) | — | 자동 |
| 규칙 | 색인·질의 | **규칙** → 규칙 백로그 | 백로그 승인 1회 |
| 정착 | 색인·질의 + **인제스트 게이트** | **데이터** → 구조교정·재추출 큐 | 강등 절차 선행 필수 |
| 강등/보류 | 안 함 | — | 재유도 대상 |

**승격 4기준** (전부 기존 append-only 로그의 파생 뷰 — 새 가변 상태 없음):

1. **통계적 성숙** — 발동 N회↑, 뒤집힘율 < ε, 스코프 ≥ 2 문서군/형식.
   (한 문서군에서만 완벽한 규칙은 그 문서군의 로컬 규칙 — format tier 로 강등)
2. **구조적 안정** — 최근 K발동 동안 본문 무수정, 수정 간격 수렴.
   when 에 예외 술어 3개↑는 역신호(술어 어휘 개정 검토).
3. **의존 하중** — 포섭한 사례 수 + 이 규칙이 옮긴 간선을 근거로 삼은 승인 수.
4. **반례 부검** — 최근 반례의 fault 딱지 비율. 규칙이 마지막으로 진 날짜가
   오래됐고 이후 반례가 전부 "데이터 결함"이면, 승격은 사후 승인일 뿐이다.

**자동화 사다리** — 사람의 역할을 게이트에서 감사자로:

```
자동   유도(induce 크론) · 잠정→규칙 승격 · 규칙 강등 · 결정적 부검
         (그 노드에 구조교정이 붙음 → fault:"데이터",
          규칙의 착지를 사람이 재억제 → fault:"규칙")
LLM    잔여 반례의 부검 딱지 (confidence 게이트, 저신뢰는 사람 큐)
사람   규칙→정착 승격 · 정착 강등 · 자동 결정 표본 감사(기본 10%)
```

자동화가 안전한 이유 = §2 두 폐쇄 + append-only(뒤집기가 레코드 한 줄) +
replay 게이트(승격의 결정적 근거). 임계 상수(최소 근거건수·표본감사율·ε)는
문서 무관 상수로 fitness_gate 처럼 정의층에 선언한다.

## §5 적중 원장 — 규칙이 증거를 심판한 모든 사건

`data/rag/rule_hits.jsonl` (append-only):

```json
{"kind": "적중", "rule": "gr-0003", "ts": "…",
 "대상": {"doc_id": "…", "edge": {"src": 41, "dst": 12}, "path": "제2조"},
 "행동": {"redirect_to": 15},
 "시점": "색인" | "인제스트" | "답변" | "그림자",
 "qid": "q-…", "status": "미검"}
```

적중의 생애: `미검 → 확정`(부검이 규칙 손 들어줌) 또는 `미검 → 뒤집힘`(사람이
데이터 손 들어줌 → 그 규칙에 fault:"규칙" 반례 append).

원장 하나가 네 가지 일을 한다:

1. **반례 풀** — 뒤집힘이 곧 반례. 정착 규칙도 뒤집힘이 쌓이면 `demotable()`
   보고서가 강등 권고로 뒤집힌다. 증거가 규칙에 "걸렸다"는 사실 자체가
   미래에 그 규칙을 공격할 탄약으로 보존된다.
2. **강등 영향 분석** — 강등 시 그 규칙이 유죄 판결한 사례 전부가 쿼리
   한 번으로 재심 큐가 된다.
3. **화면 배지** — 적중된 노드/간선에 뷰어 배지("gr-0003 적중, 미검").
   structure_fixes 와 같은 겹쳐 읽기 — result.json 은 건드리지 않는다.
4. **규칙 통계의 단일 원천** — 발동수·뒤집힘율·스코프가 전부 이 원장의 파생 뷰.

**파괴적 쓰기 금지**: 정착 규칙이라도 자동 "정정"은 없다 — 자동은
격리+표시까지, 정정은 언제나 오버레이(재지정·교정 레코드)로, 원본 보존.
적중이 뒤집힐 가능성이 0이 아닌 한, 파괴적 쓰기는 원장의 재심 능력을 죽인다.

## §6 스위치 — 잘 작동 안 하면 끈다

끄기는 부가 기능이 아니라 설계 전제다. **끄면 오늘의 시스템과 비트 단위로
같아야 한다.** 이것이 성립하는 이유: 규칙층은 별도 파일이고, 소비 지점이
셋뿐이고(색인 간선·인제스트 게이트·화면 배지), 효과는 전부 via:"규칙" 태그가
붙은 오버레이이며, 사례층(edge_rules 등)은 규칙층과 무관하게 계속 작동한다.
**끄기 = 로드 중단. 마이그레이션·복구 작업 0.**

### 3단 스위치

```
마스터   RAG_RULES_MODE = off | shadow | on          (코드 기본값: off)
층별     RAG_RULES_INDUCE      = on|off   유도 크론
         RAG_RULES_AUTOPROMOTE = on|off   잠정→규칙 자동 승격
         RAG_RULES_AUTOPSY_LLM = on|off   부검 LLM 딱지 (결정적 부검은 항상 허용)
규칙별   status: 보류                      규칙 하나만 끔
```

- **off** — 파일을 로드조차 안 한다. 비용 0, 로그 0.
- **shadow(그림자)** — 술어를 평가하고 적중을 `시점:"그림자"`로 기록하되
  간선은 건드리지 않는다. 켜기 전엔 근거 수집("켜면 무슨 일이 일어났을까"),
  끈 후엔 진단("여전히 무슨 일을 하려고 하는가")이 이 모드에서 나온다.
- **on** — 발동.

유효 모드 = min(env, 차단기). 소비 지점은 `rules.mode()` 한 함수만 본다.
`general_rules.json`·`breaker.json` mtime 이 색인 서명에 들어가 전환은
재시작 없이 다음 질의부터다.

### 차단기(circuit breaker) — 자가 강하

```
data/rules/breaker.json: {"state": "정상"|"강하", "reason": "…", "ts": "…"}

조건: 최근 W건 적중 중 뒤집힘율 > B  (W=200, B=10% — 정의층 상수)
동작: on → shadow 자동 강하 + 로그·알림. off 로는 자동으로 안 감(그림자
      증거는 계속 모아야 원인을 안다).
복귀: shadow → on 은 사람만. 차단기를 밟은 이유가 해소됐다는 판단은
      의심의 방향을 되돌리는 행위라 자동화하지 않는다.
```

### 폭발 반경 보증 (스위치와 무관하게 항상 성립)

1. 규칙은 승인 어휘 밖의 행동을 할 수 없다 (§2 폐쇄 ①)
2. 규칙은 원본을 쓸 수 없다 — 오버레이만 (§5)
3. 규칙의 모든 효과는 태그가 붙는다 — 발동 무기명 금지
4. 사례층·정의층은 규칙층이 없어도 완전하다 — 의존 방향은 규칙→사례·정의 단방향

## §7 구현 순서와 현황 (2026-08-12)

```
1. core/rag/rules.py      ✅ 술어 어휘 3종 + 평가기 + mode() + 검증 + 원장 + 차단기
                          (redirect 한 종. kind 추가는 어휘 등록만)
2. core/rag/replay.py     ✅ 근거 재현 + 충돌 대조(억제재생·사례상충·정답피드백)
   core/rag/induce.py     ✅ 군집화(결정적) → 기계/LLM 일반화(위반 1회 재시도) → replay
                          CLI: python -m core.rag.induce · API: POST /v1/rag/rules/induce
3. 원장·shadow·차단기     ✅ data/rag/rule_hits.jsonl + 3단 스위치 + 자동 강하
   색인 훅                ✅ cross_refs 마지막 단 + 서명에 파일 mtime·유효 모드
   API                    ✅ GET/POST /v1/rag/rules{,/resolve,/hits,/hits/resolve,/breaker}
4. 백로그 UI 확장         ✅ /links 연동(규칙 칩·pill 귀속·해제 조건) +
                          **전용 화면 /rules/ "공리 루프"** — 사다리(잠정→규칙→
                          정착 AXIOM)에 카드가 상태대로 앉고, 4기준 게이지가
                          승격 진행을, 타임라인이 생애(등재→승격→반례→강등)를
                          그린다. 적중 원장 부검(확정/뒤집힘)·차단기 해제·귀납
                          실행 버튼 포함. 상단 이동에 "공리" + 승격 대기 배지.
5. 자동화                 ◐ 잠정→규칙 자동 승격 · 규칙별 자동 강등(뒤집힘 누적→보류) ·
                          반증 자동 배선 완료 — 부검 LLM 딱지·표본 감사 ⬜
6. 정착 동작              ⬜ 인제스트 게이트 — 마지막. 그 전까지 정착은 상태값만
```

**반증 배선 (2026-08-12 추가)** — 반례는 일어나는 자리에서 세어진다:
  · 규칙은 억제된 좌표로 옮기지 않는다 — 시도 자체가 자동 뒤집힘(사람의 끊기가 이긴다)
  · 규칙이 옮긴 좌표 위의 인스턴스 재지정이 이긴다 — 덮인 착지는 자동 뒤집힘, 원좌표(규칙_전)로 귀속
  · 화면의 끊기(지문 승인)·재교정(교정 승인)이 규칙 간선을 겨누면 라우터가 원장에 뒤집힘을 나른다
  · 규칙 산출 위에서 태어난 교정 사례는 `출처`가 새겨져 귀납 표본에서 빠진다(자기확증 방지)
  · 그림자 적중은 성숙 판정에서 빠진다 — 효과가 없어 뒤집힐 기회가 없는 증거는 옳음의 증거가 아니다
  · first-match 는 "좁은 when 우선"으로 정렬되고, 중첩 쌍은 적재 시 경고 + /rules 에 노출된다

## §8 이 설계 자체의 반증 조건

규칙 루프도 반증 가능해야 한다. 다음이 관측되면 설계가 틀린 것이다:

| 관측 | 뜻 | 그러면 |
|---|---|---|
| 가동 후에도 같은 유형 백로그가 새 문서마다 재발 | 귀납이 일반화를 못 잡음 | 술어 어휘가 그 유형을 표현 못 하는지 검토 — 정의층 개정 |
| 뒤집힘율이 임계 위에 머묾 (차단기 반복 강하) | 귀납이 과일반화 | 승격 임계 상향, 홀드아웃 강화. 해소 안 되면 off |
| 규칙 수정이 수렴 안 하고 예외 술어만 증식 | 어휘가 현실을 못 담음 | 그 도메인은 규칙층 대상에서 제외(사례층 유지) |
| 사람 처리 건수가 안 줄어듦 | 자동화가 일을 옮겼을 뿐 | 루프 유지 비용 > 절감이면 off — 사례층만으로 복귀 |

off 로 되돌려도 잃는 것은 없다 — 사례는 계속 쌓이고, 원장은 남고,
설계가 고쳐지면 shadow 부터 다시 시작한다.
