# Haiku 전용 법률 답변 방법론 실험

## 결론

메인 배선은 변경하지 않는다. 동결 51건에서 법률 해석 프롬프트, 2단 규칙표,
반대규칙 감사, 조문 압축 신규작성, Wiki 주입, 보수적 rescue 선택기를 모두
Haiku로 비교했으나 답변 비열등성이 재현되지 않았다.

가장 유망했던 `focused_fresh`는 조정에 사용한 17건에서 Haiku 재채점
7/17 → 9/17이었지만, 규칙을 동결한 나머지 34건에서 18/34 → 15/34로
회귀했다. 합계는 baseline 25/51, candidate 24/51이다. 이 수치는 기존
Sonnet 의미채점 35/51과 채점기가 달라 직접 비교하면 안 된다.

## 실험 계약

- 검색 결과와 기존 답변은 동결했다.
- 제품 호출과 의미 채점 호출을 모두 `claude-haiku-4-5-20251001`로 고정했다.
- 사례 ID, 골든 답변, 골든 좌표를 제품 프롬프트에 넣지 않았다.
- 일반 법률 구조만 사용했다: 규범 위계, 주체·행위·요건·효과, 본문·단서,
  배제·준용, 수치·기간·산식, 시점·경과조치, 출처 연혁.
- 어떤 실험도 운영 `answer.synthesize` 배선에 연결하지 않았다.

## 가설과 관측

| 가설 | 방법 | 관측 |
|---|---|---|
| 문언 연산자 누락이 주원인 | `operator_one_pass` | 어려운 3건 0/3. 1회 감사만으로 원문 포섭 오류를 못 고침 |
| 법률 삼단논법을 먼저 컴파일하면 개선 | `matrix_render` | 3건 0/3. 첫 단계의 오독이 두 번째 단계에서 증폭됨 |
| 반대규칙·특별규정 선탐색 | `counterrule` | 3건 0/3. 입력이 길면 명시적 예외도 놓침 |
| 일반 해석 Wiki가 반대규칙 탐색을 보조 | `counterrule_wiki` | 3건 0/3, 비Wiki와 동률이며 더 느림 |
| 정답 조문 주변만 압축하면 Haiku가 안정 | `focused_fresh` | 개발 9/17(+2), 동결 홀드아웃 15/34(-3), 합계 -1 |
| 압축 원문에 Wiki를 더하면 추가 개선 | `focused_fresh_wiki` | 개발 9/17로 동률. 서로 다른 2건씩을 살리고 망가뜨려 방향 불안정 |
| 회피 답변만 후단 선택기로 구조 | `focused_rescue` | 대상 4건에서 3/4 → 3/4. `cm-001` 구조, `cm-030` 신규 회귀로 순증 0 |

## 비용

### 동결 baseline 51건

- 입력 1,859,800 tokens
- 출력 21,157 tokens
- p50 5.810초, p95 10.369초
- 기존 Sonnet 의미채점 기록 35/51

### `focused_fresh` 51건

- 입력 586,511 tokens: baseline 대비 약 68.5% 감소
- 출력 25,963 tokens
- p50 6.017초, p95 11.053초
- Haiku 의미채점 baseline 25/51, candidate 24/51
- 선택 원문 문자수 p50 6,619자, p95 13,405자

입력은 크게 줄었지만 신규 답변이 더 길고 Haiku 호출 변동도 있어 지연은 개선되지
않았다.

### Wiki의 증분 비용 — 개발 17건

- 비Wiki 입력 190,339 tokens, p50 6.695초, p95 9.595초
- Wiki 입력 293,209 tokens, p50 7.497초, p95 15.032초
- 정확도는 양쪽 모두 9/17

Wiki는 이 분할에서 입력을 약 54% 늘렸고 p95를 약 57% 늘렸지만 총점을 올리지
못했다.

## 법률 도메인 진단

### 1. 조문 회수와 포섭은 별개다

`cm-003`에는 시행세칙 제23조 제4항 제2호가 그대로 들어 있었다. Haiku는
"벤처금융 또는 전문투자자가 취득한 경우"가 상장규정 제26조 제1항 제3호의
명시적 제외임을 읽고도, 재무적투자자를 별도 범주로 유보하여 제4호 적용을
확정하지 못했다. 문제는 법률 지식의 양보다 용어 포섭과 특별규정 적용이다.

### 2. 적용범위의 주체 한정이 결론을 뒤집는다

`cm-030`에서 같은 `focused_fresh`가 한 실행에서는 상장 전 발행인에게 분기보고서
의무가 없다고 맞췄고, rescue 반복에서는 금융기관·주권상장법인 한정을 IPO
발행인에게 확장해 틀렸다. 동일 방법의 Haiku 반복 변동이 확인됐다.

### 3. 부재 답변은 항상 회피가 아니다

`cm-025`의 정답은 이미 과세된 저가분을 별도로 조정하는 명시 규정이 확인되지
않는다는 것이다. "자료에 없다" 패턴만으로 재작성하면 올바른 제한적 부재 결론을
적극적 오답으로 바꿀 수 있다.

### 4. 출처 계층과 연혁을 분리해야 한다

`cm-045`의 기존 답은 경로 상위 관(款)의 `<신설 2001.7.24>`를 제341조의4의
신설일로 복사했다. 실험 코드는 상위 편·장·절·관 연혁을 별도 필드로 분리하고,
문서 revision/enforcement 메타를 따로 표시했다. 이 출처 정규화는 일반 규칙으로
유효하지만, 그 하나만으로 전체 답변 정확도는 보장되지 않는다.

### 5. Haiku 단독 의미채점은 체계적 오판이 있다

`cm-024` 원문 시행령 제31조의3 제3항 제2호는 명시적으로 `3억원`이다. 제품 답도
이를 정확히 썼지만 Haiku는 기준답변의 "제2호의 금액"을 앞서 인용한 제1항
제2호로 잘못 되돌려 여러 차례 false를 냈다. 검증 원문과 법령 인용 범위 규칙을
추가해도 오판이 남았다. 또한 일부 실행에서는 기준답변에 없는 정확한 추가 설명을
오류로 취급했다.

따라서 Haiku만 사용해야 한다면 의미 LLM 점수 하나로 출시 판단을 하면 안 된다.
3회 다수결과 함께 수치·날짜·조문 참조범위·본문/단서 연결에 대한 결정론 검사를
병행해야 한다.

## LLM Wiki 판단

현재 실행 설정에는 이미 `wiki_context=True`, `issue_spot=True`,
`issue_spot_pre=True`가 켜져 있다. 따라서 이번 `focused_fresh_wiki` 비교는 전체
파이프라인의 Wiki off/on 실험이 아니라, 기존 초안 뒤의 Haiku 단계에 Wiki 카드를
한 번 더 주입했을 때의 **증분 효과** 실험이다.

현재 Wiki는 "단서 읽기", "정의 우선", "준용과 경과조치" 같은 해석 방법 카드다.
이런 카드는 모델이 무엇을 확인할지 알려 주지만, `재무적투자자`가 해당 규정의
`벤처금융 또는 전문투자자`에 포섭되는지 같은 업무 도메인의 승인된 용어 매핑이나
특정 규정의 적용사실을 제공하지 않는다.

따라서 현재 형태의 Wiki를 모든 답변에 주입하는 것은 권하지 않는다.

- 일반 방법 카드는 필요한 쟁점에만 짧게 조건부 주입한다.
- 실체 법률지식은 Wiki 자유서술이 아니라 출처·시점·적용범위를 가진 구조화된
  `용어 정의/동의어`, `일반규정-특별규정`, `본문-단서`, `주체 한정`,
  `시행·경과` 간선으로 관리한다.
- Wiki의 문장은 증거가 아니라 탐색·검사 지시로만 사용한다.

## 다음 권고

후단 LLM 라우터보다 먼저 `법률 명제 컴파일러`를 shadow로 만드는 편이 낫다.
회수 원문에서 다음 필드를 좌표와 함께 결정론 또는 Haiku 구조출력으로 만들고,
누락·충돌만 검사한다.

1. 적용 주체와 자격
2. 행위·대상
3. 발생 조건과 누적/대안 관계
4. 본문·단서·예외·재예외
5. 법적 효과와 강행/재량 양태
6. 수치·기간·산식의 비교 연산
7. 적용 시점·시행일·경과조치
8. 각 명제의 정확한 조·항·호 좌표

이 구조가 준비되기 전에는 main answer를 덮어쓰지 말고 shadow 불일치 로그만
수집한다. 다음 평가는 기존 51건과 분리한 신규 문제로 프롬프트를 동결한 뒤 해야
한다.

후속 shadow 컴파일러 구현과 17건 결과는
`docs/HAIKU_LEGAL_COMPILER_SHADOW.md`에 기록했다. 명제표는 일부 오류를 고쳤지만
7/17 동률, 회귀 2건으로 최종 답변 비열등성을 통과하지 못했다.
