# 구조 해석기 개발 문서 (Structure Interpreter)

> 범용 계층구조 인식 엔진. 법령·약관에 국한하지 않고, 구분자로 계층을 표현하는 모든 구조화 문서를 대상으로 한다.

---

## 0. 목적과 스코프

**목적.** Docling으로 파싱된 문서에서 계층 구조(장/조/절·다단 점번호·열거 등)를 인식해 트리로 복원한다. 산출물은 (a) 이 문서의 구조 트리, (b) 재현 시 재사용 가능한 구조형식(frame)이다.

**스코프.** 구분자 기반으로 계층이 표현되는 임의의 구조화 문서. 특정 문서 종류(법령 등)에 하드코딩하지 않는다.

**설계 원칙 (상위 아키텍처와 일관).**
- 결정론 우선. LLM은 결정론이 못 가른 잔여에만, 문서당 배치 1콜(대개 0콜).
- 인식(recognition)과 제약(constraint)의 분리. 구분자·가드는 인식 어댑터이지 도메인 공리가 아니다.
- 용어집은 **닫힌 어휘**. "마커가 어떻게 생겼나"만 담고 "몇 번째 레벨이냐"는 담지 않는다(레벨은 문서가 유도).
- 재사용 단위는 통짜 포맷이 아니라 primitive. 새 문서는 대체로 "룰 추가"가 아니라 "어휘의 다른 조합".
- 미리 크게 짓지 않는다. 실제 문서가 요구하는 primitive만 만들고 나머지는 error-driven 추가.

**비스코프.** OCR(born-digital 전제), 표 셀 내부 구조 파싱(별도), 의미 추출(별도 reconciliation 레이어).

## 1. 아키텍처 개요

### 1.1 네 개의 role = 파이프라인 네 단계

| role | 하는 일 | 시그니처 | 시점 |
|---|---|---|---|
| 제안자(proposer) | 구조 가설 후보 생성 | `text → 후보[]` | S0 |
| 국소 가드(local guard) | 후보 하나를 주변만 보고 채점 | `후보 → score` | S1 |
| **계열 정합(family coherence)** | **한 계열 안에서 구조/인용 가르기** | **`계열의 후보[] → 생존[]`** | **S2** |
| 전역 정합성(global) — 바깥 | 생존 후보에서 레벨 순서 유도 | `생존 계열들 → 레벨사다리` | S3 |
| 전역 정합성(global) — 안쪽 | 레벨 고정 후 후보 활성/기각 | `후보집합+컨텍스트 → 트리` | S4 |

> **주의(카테고리 에러 방지).** 카테고리는 **셋**이다. 초판은 둘로 보고 "서수 일관성은 레벨 정해진 뒤"라고 못박았는데, 실측이 그 전제를 뒤집었다 — **서수 비교는 같은 계열 안에서만 일어나므로 레벨을 몰라도 된다.** 계열은 제안자가 이미 알려 준다. 그래서 계열 정합(S2)이 사다리(S3) **앞에** 온다.
>
> **초판 순서가 만든 실패(실측).** 레벨을 먼저 정하면 등재 심사가 "양수 후보 비율"로 계열을 걸러야 한다. 조(條)는 본문에서 제목과 **같은 글자**로 인용되므로 금소법에서 후보 251건 중 159건이 인용이었고, 가드가 그것을 *정확히* 깎아낼수록 비율이 낮아져(0.37) 조 계열이 통째로 탈락했다. 탈락 → 레벨 없음 → 스코프 없음 → 제55조와 제51조가 만나지 못함 → 서수 규칙이 영영 발동하지 않음. 잘 잡아낸 것이 벌점이 되는 구조였다.

### 1.2 여덟 신호 → role 매핑

| 신호 | role | 단계 |
|---|---|---|
| 구분자(separator) | 제안자 | S0 |
| 블록 위치 | 국소 가드 | S1 |
| 조사 | 국소 가드 | S1 |
| construction | 국소 가드 | S1 |
| **연속 단위(run) · 위치 정당성(anchor)** | **계열 정합** | **S2** |
| **들여쓰기(indent)** | **전역(바깥)** | **S3** |
| 형식 일관성 | 전역(바깥) | S3 |
| 서수 일관성 · 계층성 | 전역(안쪽) | S4 |

> **S2 의 두 신호는 반드시 함께 쓴다(실측).** `run` 만 쓰면 오름차순으로 나열된 다른 법률 인용(`제161조`, `제336조`, `제640조`)이 전진으로 보여 통과한다 — 서수는 역행을 잡지 전진하는 인용을 못 잡는다. `anchor` 만 쓰면 `제8조(…) ① …` 처럼 조 제목 줄에 붙어 온 제1항 173건이 죽는다.

### 1.3 파이프라인

```
문서 → Docling 파싱
     → S0 발화 탐지 (후보 수집)
     → S1 국소 채점 (s(cand))
     → S2 계열 정합 (사다리 없이 구조/인용 가르기)
     → S3 레벨 유도 (정제된 후보로 사다리)
     → S4 전역 선택 (DP → 트리)
     → S5 fitness 게이트 (정상 / cold 라우팅 / 잔여 LLM 배치)
     → S6 저장 분기 (문서결과 항상 / frame 등재는 재현 게이트)
```

## 2. 데이터 모델 (개념)

- **Candidate**: `{ id, family, surface, ordinal(정수 또는 정수배열), block_idx, offset, s(국소점수) }`
- **Family**: 마커 계열 식별자 (예: `dot_number`, `circled`, `kr_jang`, `hangul_jamo`)
- **Ladder(레벨 사다리)**: `[L0, L1, L2, ...]`, 각 L에 배정된 family(들) + reg_score
- **ScopeStack**: DP 상태. 레벨별 `{ 마지막 활성 서수, 부모 노드 포인터 }`
- **Node**: `{ level, ordinal, span, children[], activation_reason }`
- **StructureResult**: `{ tree, fitness_score, audit_log, fingerprint }`
- **Fingerprint**: 발화 family 집합 + 유도된 중첩순서(재현빈도 판정용 키)

## 3. 컴포넌트 계약

> 각 신호는 role별 시그니처를 따르는 순수 함수. **파일 1개 = 함수 1개**, role 태그 부착. 관리소(용어집)는 이 함수들을 role로 등록만 한다. **core 파이프라인은 고정, 신호는 plug-in.** 새 신호 추가 = 파일 떨궈 등록, 파이프라인 코드 불변.

### 3.1 제안자

```
propose(text, docling_blocks) -> [Candidate]
  # 표면 패턴 매칭 + 서수 추출만. 판단·레벨의미 없음.
```

각 제안자 엔트리가 아는 것: **표면 패턴** + **서수 추출법** + **family**. 레벨 의미는 절대 담지 않는다.

### 3.2 국소 가드 (독립, 병렬 가능)

```
guard_block_pos(cand, doc)     -> float   # 블록 여는 자리냐, 흐르는 텍스트 속이냐
guard_particle(cand, doc)      -> float   # 마커 뒤가 명사로 부려먹는 문법환경이냐(=참조)
guard_construction(cand)       -> float   # 통짜 마커 형태로 깨끗이 잡혔냐

s(cand) = Σ guards
```

- 하드컷(boolean) 금지. **방향 있는 점수**로 반환해 다른 신호가 상쇄/보강할 여지를 남긴다. (Docling이 헤더+본문을 한 블록으로 붙이는 등 파싱 품질 편차 대응.)
- **언어별 파일 분리**: 조사 가드는 한국어 계열만 발화. 영문 계열은 전치사 대응물(`of`/`under`)을 별도 가드로.

### 3.3 계열 정합 (S2) — 사다리 없이

```
anchored(cand, block_cands)  -> ok | 사유   # 블록 첫머리 / 중간이면 1로 시작 + 앞에 다른 계열
advances(cand, prev_ordinal) -> ok | 사유   # 자기 계열 수열에서 전진 또는 1로 리셋
select(candidates)           -> 생존[]      # 계열별로 위 둘을 순서대로 건다
```

- **레벨을 참조하지 않는다.** 후보의 `family` 만 있으면 돈다. 이것이 단계 재배치의 근거다.
- 리셋(`1로 시작`)은 여기서 무조건 통과시킨다. 진짜 리셋인지 인용인지는 `anchor` 와 `reg_score.outliers` 가 나눠 맡는다. 리셋을 인용으로 오인해 죽이면 장마다 조가 1부터 시작하는 문서가 반 토막 나고, 그 결과는 번호가 완벽히 연속이라 fitness 게이트조차 못 잡는다.
- `anchor` 의 "앞에 **다른** 계열" 조건이 핵심이다. 같은 계열이 앞에 있는 것은 리셋을 정당화하지 못한다 — 골든 §8 의 c8(`2.1 운용방법 (1.1의 …)`)이 이 조건으로 걸러진다.

### 3.4 힌트 주입 (사람이 아는 것을 넣는 통로)

문서군의 생김새를 이미 안다면 유도를 기다릴 것 없이 넣는다. §7 frame 의 **수동 주입**이며, 강도가 넷이다.

```
families      어휘 제한. 이 계열의 제안자만 발화. 후보가 애초에 안 생긴다.
partial_order 특정 쌍의 순서만 못박음. 증거가 얇아 못 정하는 쌍에 한 줄.
ladder_hint   층을 통째로 지정. 유도를 건너뛰므로 순환·순서미정이 사라진다.
root          좌표 최상위. 이보다 얕은 계열은 level 0 으로 접힌다.
```

- **무엇을 주든 관측은 계속 돈다.** 힌트가 `장 > 조` 인데 관측이 반대면 시끄럽게 알린다 — 힌트와 다른 양식의 문서가 들어왔을 수 있다. 힌트에 없는데 발화한 계열도 남긴다.
- 어휘(§6)에는 여전히 레벨이 없다. 여기 들어오는 것은 **어휘가 아니라 이 문서군에 대한 입력**이다.

### 3.5 전역 정합성

```
# 바깥 (S3) — 레벨 정하기.  **생존 후보만 받는다.**
reg_score(family, survivors)      -> float          # 런의 결: 생존 ÷ (생존 + 런 개수)
induce_ladder(survivors)          -> Ladder         # 네 증거로 순서 유도

# 안쪽 (S4) — 후보 거르기
check_nesting(cand, scope_stack)  -> ok | FORBID    # 계층성: 목이 조 없이 튀어나오면 금지
check_ordinal(cand, scope_stack)  -> ok | penalty   # 서수 단조
```

`reg_score` 는 더 이상 "양수 후보 비율"이 아니다. 인용은 S2 에서 이미 빠졌으므로 분모가 오염되지 않는다. 대신 **런의 결**을 잰다 — 계열이 진짜 구조라면 번호가 길게 이어지고, 후보마다 런이 끊기면 우연이다. 리셋을 감점하지 않으면서 불규칙만 잡는다.

## 4. 파이프라인 단계별 명세

### S0 · 발화 탐지
용어집 전 제안자를 문서에 훑어 발화한 family 집합 + raw 후보 전량 수집. **판단 0, 순수 수집.**

### S1 · 국소 채점
후보마다 `s(cand)` = 가드 합산. 블록중간+조사부착 후보는 여기서 이미 바닥. **병렬, 순서 무관.**

### S2 · 계열 정합 (사다리 없이)
계열마다 후보를 읽기순으로 훑으며 **위치 → 연속 단위** 순서로 건다.

1. **anchor(위치)**: 블록 첫머리면 통과. 블록 중간이면 **1로 시작하고 같은 블록 앞쪽에 다른 계열 마커가 있을 때만** 통과. 여기서 떨어진 것은 **수열 계산에 들어가지도 않는다** — 머리글의 날짜(`[시행 2026. 1. 2.]`)가 점번호로 잡혀 뒤의 호 번호를 통째로 어긋내는 것을 막는다(실측 78건).
2. **run(연속 단위)**: 한 칸씩 이어지는 **묶음**을 찾는다. 묶음에 낀 것이 구조, 못 낀 것이 인용.
3. 떨어진 후보는 `reject(mention)` 으로 확정되고 사유가 감사 로그에 남는다. **DP까지 가지 않는다.**

> **직전 번호(prev) 하나로 걷지 않는 이유.** 인용 하나가 수열 전체를 오염시킨다.
> `1조 2조 3조 [20조] 4조 5조` 에서 prev 를 20 으로 밀면 뒤가 죽고, 3 에 묶어 두면
> 파싱이 ② 를 빠뜨렸을 때 ③④⑤ 가 줄줄이 죽는다. 실측에서 두 방식 모두 수십 건을
> 잘못 죽였다. **수열은 상태 하나가 아니라 묶음**이라서다. 여러 묶음을 동시에 열어
> 두고 각 후보를 자기가 이어갈 수 있는 묶음에 붙이면 둘 다 풀린다.

> 실측(금소법 KSB): 조 후보 251 → 생존 75(연속 단위 4개), 절 6건(연속 단위 2개 — 장마다 리셋), 장 8건(1개). 준칙(KOFIA-R): 조 206 → 생존 0 — 준칙은 조를 인용만 하고 자기 조가 없는 문서이며, 그 판정이 정확하다.

### S3 · 레벨 유도 (바깥) — 생존 후보만
1. **자기계열 depth**: 점번호 `1./1.1/1.1.1`은 dot-depth가 곧 계층 → 관측 없이 확정.
2. **들여쓰기(기하 증거)**: 문서가 계층을 눈에 보이게 그린 그대로를 읽는다. 계열이 몇 건이든, 번호가 리셋되든 말든 잰다. 동률이면 간선을 놓지 않고 다른 증거에 넘긴다.

   > **왜 필요한가.** 아래 두 증거에 각각 구멍이 있다. **리셋 정렬은 통번호 계열에 안 통한다** — 한국 법령의 조 번호는 장·절이 바뀌어도 리셋되지 않는다(실측 KSB: 장 1~8, 절 `1,2,3|1,2,3`, 조 1~69 연속). 조가 리셋을 안 하니 장→조 를 영영 못 잡는다. **덮음·사이-끼임은 희소 계열에 안 통한다** — 절 6건은 자기 구간이 5개뿐이라 덮음이 20%밖에 안 나와, 실측에서 `장↔절` 이 네 증거 모두 침묵해 순서 미정으로 남았다.
   >
   > 실측 들여쓰기(페이지 폭 대비 왼쪽 x 중앙값): KSB `장 0.050 · 절 0.050 · 조 0.057 · 항/호 0.084 · 목 0.101`. 세 문서 모두 순서가 계층과 일치했고, 이것을 넣자 순서 미정이 7/21 → 1/21 로, 적합도가 83% → 94% 로 올랐다.

3. **리셋 정렬(주 수열 증거)**: B의 번호가 되감기는 자리마다 A의 마커가 놓여 있으면 B는 A 안에 산다. 밀도가 아니라 **구조**를 재므로 1표 차가 나지 않는다. 계열 정합을 통과한 후보 위에서만 계산할 수 있다 — 인용이 섞이면 리셋 위치가 오염된다.
4. **덮음**: A가 연 구간 중 몇 할이 B를 품는가. 담는 쪽은 자기 구간 절반 이상을 채워야 한다. **마지막 열린 구간은 세지 않는다** — 세면 뒤에 오는 모든 것을 삼켜 방향이 뒤집힌다.
5. **사이-끼임(최후)**: A의 두 출현 사이에 B가 들어앉은 횟수. 밀도만 재므로 촘촘히 섞인 두 계열에서 거의 무승부가 된다(실측: 52:51, 29:28, 6:6). 위 셋이 침묵할 때만 쓰고, 마진 1 이상을 요구한다.
6. **reg_score 문지기**: 런의 결로 등재 여부 결정. 리셋 뒤가 안 이어지는 후보에는 **"미배정, S4 문맥판정"** 딱지.
7. **갈래 A vs B**: 관측으로 순서가 읽히면 그대로 확정(대부분). 네 증거가 모두 침묵하면 같은 칸에 두고 사실만 남긴다. 갈래 B(배열 열거)는 미구현 — 실제로 필요한 문서가 나타나면 만든다.

### S4 · 전역 선택 (DP)
후보를 읽기순으로 놓고 왼→오 1회 훑기(=최단경로/Viterbi). **완전탐색 아님, exact.**

- **상태** = 위치 + ScopeStack(레벨별 마지막 서수 / 부모 포인터). 깊이 ~5라 상태 작음.
- **전이** = 각 후보 `reject | activate`
  - `activate` 허용: `check_nesting == ok` **and** `check_ordinal == ok`. 위반 시 FORBID 또는 벌점.
  - `activate` 시 ScopeStack 갱신(해당 레벨 서수↑, 하위 레벨 스코프 닫음).
  - `reject` 시 후보는 mention으로 버려지고 스택 불변.
- **목적** = `Σ 활성 s(cand) − Σ 벌점` 최대 경로.
- **S2에서 떨어진 후보는 DP에 들어오지 않는다.** 자기 계열 수열·위치가 이미 "구조가 아니다"라고 말했다. 감사 로그에는 남는다.
- **미배정 후보(S3 딱지)**: 여러 레벨 배정을 시도해 문맥상 최고점 위치에 앉힘(같은 글리프가 문맥 따라 다른 층에 배치되는 케이스 해결).
- **갈래 B**: S3가 준 배열 후보마다 DP 1회씩 돌려 총점 비교, 최고 채택(수십 개 × 가벼운 훑기 = 전수 열거, 솔버 불필요).

산출: 트리 + 후보별 활성/기각 경로 로그(감사 근거 그대로).

### S5 · fitness 게이트 + 잔여 처리
- 총점(커버리지 × 정합 × **사다리품질**) ≥ threshold → 정상 구조 확정.
- < threshold → **cold 라우팅**: 보편 skeleton + bounded LLM, 룰 축적 0.
- 사다리품질은 순환 절단·순서 미정·미등재 계열을 벌한다. 후보 하나하나의 정합만 보면 사다리가 틀린 것을 못 본다 — 실측에서 순환 7개를 이름 순으로 끊은 문서가 99%를 받았다. 점수와 **별개로** 결함마다 경고를 낸다.

**잔여 = 신호가 서로 모순되는 후보.** "DP가 근소차로 못 가른 것"만 재던 초판 정의는 세 문서에서 0건을 냈다 — 실제로 틀린 자리는 마진이 아니라 신호 충돌에 드러난다.

| 종류 | 조건 |
|---|---|
| `가드↔수열` | 가드가 확실한 헤더(s ≥ 1.5)라는데 계열 정합이 인용이라고 했다 |
| `손해활성` | DP가 전이 음수를 감수하고 활성시켰다 — 다른 선택지가 더 나빴다는 뜻 |
| `근소차` | 최선(활성)과 차선(기각=0)의 차 ≤ margin |

### S5b · 잔여 해소 (문서당 배치 1콜)
- 위 목록만 모아 **한 번** 묻는다. 잔여 0건이면 호출 자체가 없다. per-후보 루프 금지.
- 답은 `structure | mention | unsure` 셋뿐이고 **후보 id 로만** 가리킨다. 목록에 없는 id 는 버린다.
- 판정을 심고 **S3·S4를 다시 돌린다.** 마커 하나가 살아나면 그 계열의 수열과 사다리가 통째로 달라져서, 트리만 손보면 앞뒤가 안 맞는다.
- 판정을 받은 후보는 **표시해 두고 다시 잔여로 올리지 않는다.** 안 그러면 두 번째 콜이 같은 질문을 반복하고 목록이 수렴하지 않는다.
- 호출이 실패하면 결정론 판정을 그대로 두고 시끄럽게 남긴다. `llm=None` 이면 이 단계가 통째로 건너뛰어져 경로가 완전 결정론이다.

> **한계.** 이 단계만 비결정론이다. 실측에서 `제8조 생략`(부칙 타법개정)이 회차에 따라 structure/mention 로 갈렸다 — 사람이 봐도 애매한 자리다. 재현이 필요한 경로는 `llm=None` 으로 돌리거나 응답을 녹화해 재생한다.

### S6 · 저장 분기
- **문서 해석 결과**: 항상 저장(다운스트림용).
- **재사용 frame 등재**: 같은 fingerprint가 2~3개 쌓였을 때만 freeze. singleton엔 frame 안 만듦("N=1 룰 추가" 방지).

## 5. 스코어링 정의 (구현 착수 전 확정 대상)

> **이 수치가 파이프라인 전체를 지탱한다.** S3 DP, S4 게이트, S2 배열비교가 전부 여기서 파생. 코딩 전 가장 먼저 못 박을 것. 아래는 시작값 — 골든 테스트로 조정.

### 5.1 국소 가드 (합산 → s)

| 가드 | 조건 | 점수 |
|---|---|---|
| 블록위치 | offset 0 (블록 여는 자리) | +0.8 |
| | 블록 중간 (텍스트 흐른 뒤) | −0.7 |
| | 괄호/인라인 내부 | −0.9 |
| 조사 | 뒤에 제목명사/개행 (clean) | +0.3 |
| | 마커 직후 조사 부착 | −0.9 |
| | + 참조 서술어 근접(준용/따른다/정한) | 추가 −0.4 |
| construction | 완전형(제N장 / 1. / ①) | +0.7 |
| | 파편(제 3 장 / 3장) | −0.3 |

### 5.2 DP 전이 벌점

| 위반 | 벌점 |
|---|---|
| 중첩 위반(부모 레벨 없이 등장) | FORBID (경로 배제) |
| 서수 역행(같은 스코프 감소) | −1.5 |
| 서수 gap(건너뜀) | −0.3 |
| 새 레벨 도입(novelty) | −0.2 |

### 5.3 fitness threshold
- 정상 확정 / cold 라우팅 경계값 = **T** (골든셋으로 캘리브레이션).
- 동일 스칼라가 조합 선택·freeze 판정·cold 게이트에 공용. 별도 점수 만들지 말 것.

## 6. 용어집 / 관리소 스키마

```
marker_id:   circled_num
role:        proposer            # proposer | local_guard | global_outer | global_inner
surface:     "[①-⑳]"            # 표면 패턴
ordinal_fn:  원문자 → 정수        # 서수 추출
family:      circled
lang:        any                 # 가드는 ko | en 등으로 분리
# level 없음. 절대 넣지 않음 — 레벨은 문서가 유도.
```

- 각 엔트리는 순수 인식 부품. 계층 지식 0.
- 계층은 런타임에 문서별로 유도되어 그 문서의 StructureResult에 저장(용어집엔 기록 안 함).
- **진짜 어휘 추가가 필요한 유일한 순간**: 세상에 없던 새 표면 패턴 첫 등장(예: 로마숫자 `ⅰⅱⅲ` 미등재). 유한하고 금세 수렴. "이 문서에선 1.이 상위네" 같은 배치는 절대 등재 금지.

### 6.1 제안자 초기 카탈로그 (실제 발화하는 것만 우선 구현)

- **한국 법령/약관**: `제N편/장/절/관`, `제N조`, `제N조의M`, `①…⑳`, `1. 2. 3.`, `가. 나. 다.`, `(1)/1)`
- **범용 점번호**: `1. / 1.1 / 1.1.1`
- **영문/기술**: `Article/Section/Clause N`, `(a)/(b)`, `(i)/(ii)`, `A./B.`
- **로마숫자**: `Ⅰ Ⅱ Ⅲ` / `ⅰ ⅱ ⅲ`
- **부속(role axis 직결)**: `[별지 N]`, `[별표 N]`, `[서식 N]`, `부칙`
- **레이아웃 유래(약한 제안자)**: 표 헤더 반복, 들여쓰기 depth

> 미리 다 만들지 말 것. 대상 문서가 요구하는 것부터. 나머지는 misfit 시 error-driven 추가.

## 7. 티어링 & 저장 정책

| 티어 | 케이스 | 처리 | 결정론 |
|---|---|---|---|
| Hot | 양식 + 반복 | frozen frame 라우팅, 런타임 disambiguation 0 | 완전 |
| Warm | 양식인데 조금씩 다름 | base frame + primitive-diff, LLM은 델타만 | 대부분 |
| Cold | N=1 / 양식없음 | 보편 skeleton + bounded LLM, 룰 축적 0 | 아님 |

- 라우팅 = fingerprint → 후보검색 → (필요시)LLM verify.
- **compile은 재현빈도가 결정.** N=1엔 frozen frame 금지. 같은 fingerprint 2~3개 → hot 승격.
- **near-identical false match 주의(엣지케이스 "false match risk").** 95% 같고 5% 다른 두 포맷에서 그 5%가 핵심 필드 위치를 뒤집을 수 있음. verify는 "충분히 비슷"으로 통과 금지 — **판별 primitive**(두 포맷을 가르는 그 몇 개)를 반드시 체크. 핵심 필드엔 fitness gating 강하게.

## 8. 골든 테스트 (구현 검증 픽스처)

### 8.1 입력

```
[b1]  1. 총칙
[b2]    1.1 목적
[b3]      ① 이 약관은…
[b4]      ② 수탁자는…
[b5]    1.2 정의
[b6]  2. 운용
[b7]    2.1 운용방법 (1.1의 원칙을 준용)
[b8]      1. 국내채권
```
함정A: b7의 `1.1`은 참조(mention). 함정B: b8의 `1.`은 최상위가 아니라 2.1 하위 열거.

### 8.2 S1 국소점수 기대값

| 후보 | 마커 | 위치 | s |
|---|---|---|---|
| c1~c7, c9 | 각 마커 | offset0 | +1.8 |
| c8 | `1.1` @b7 | 괄호 | −1.5 |

### 8.3 S2 유도 사다리 기대값
```
L0 = 점번호 depth1 (1., 2.)
L1 = 점번호 depth2 (1.1, 1.2, 2.1)
L2 = 원문자 (①②)
c8 = S2 계열 정합 탈락 (확정 기각)
c9 = 미배정(S4 문맥판정)
```

> **초판에서 바뀐 부분.** 초판은 c8·c9를 둘 다 "미배정"으로 두었다. 단계 재배치 뒤 둘이 갈린다 — c8은 계열 정합에서 확정 기각된다(괄호 속 `1.1`은 리셋인데 같은 블록 앞에 다른 계열 마커가 없다). 판정이 더 이르고 사유가 더 구체적이며, **§8.4의 최종 결과(c8 기각, 경로 총점 14.2)는 동일하다.**

### 8.4 S3 DP 결정 기대값

| 후보 | 결정 | 근거 |
|---|---|---|
| c1~c7 | activate | 단조 증가, 위반 0 |
| c8 | **reject (mention)** | activate net −3.0 < reject 0 |
| c9 | **activate (2.1 하위)** | ⒝ +1.6 > ⒜ L0 +0.3 (서수역행 −1.5) |

경로 총점 = 14.2.

### 8.5 최종 트리 기대값
```
1. 총칙
├─ 1.1 목적
│  ├─ ① …
│  └─ ② …
└─ 1.2 정의
2. 운용
└─ 2.1 운용방법        (괄호 "1.1" = 본문 텍스트)
   └─ 1. 국내채권
```

### 8.6 S4/S5 기대
- fitness 상회 → 정상 확정, LLM 콜 0.
- fingerprint 최초 → 문서결과 저장, frame freeze 안 함.

### 8.7 감사 로그 기대(예)
```
c8:1.1 → reject(mention) | 근거: 괄호+조사(의)+참조서술어(준용), s=−1.5
c9:1.  → activate as child-of-2.1 | 대안 L0 reject: 서수역행 −1.5
```

## 9. 개발 순서 (error-driven)

1. **스코어링 수치 확정** (§5). 다른 모든 게 여기 매달림.
2. 데이터 모델 + 용어집 등록 골격(§2, §6). role 태그 스키마 먼저.
3. **제안자** — 대상 문서가 실제 발화하는 것만(§6.1).
4. **국소 가드 3종**(§3.2). 골든 §8.2 통과.
5. **S2 계열 정합**(anchor + run). 사다리 없이 도는지 확인.
6. **S3 갈래 A만**(관측 유도). 골든 §8.3 통과. — 대부분 문서 여기서 끝.
7. **S4 DP**(§4). 골든 §8.4~8.5 통과.
8. **S5 게이트 + cold 라우팅**(§4). threshold 캘리브레이션.
9. **S6 저장/재현 게이트**(§7).
9. 이후 확장은 전부 misfit 발생 시:
   - 새 표면 패턴 → 제안자 추가
   - S2 갈래 B(배열 열거) → 관측으로 순서 미정 문서 실제 등장 시
   - grammar-constrained decoding → 판별을 더 밀 필요 실증 시(결정론 트레이드 감수)

> 5번(갈래 A)부터 시작. 갈래 B·LLM 배치를 미리 만들면 등장 안 할 모호성 처리하느라 over-engineering.
