# 법령 도메인 안내 — 처음 보는 사람을 위한 지도

이 시스템은 금융 법령·규정 위에서 검색(RAG)을 돌린다. 법령 문서는 일반 문서와
전혀 다른 구조 문법을 갖고 있고, **그 문법을 아는 것이 곧 검색 품질**이다.
아래 예시는 전부 이 저장소의 실제 코퍼스에서 뽑은 것이다.

---

## 1. 법령의 위계 — 문서가 한 장이 아니라 사슬인 이유

한국 금융 규제는 **변경 속도가 다른 층의 사슬**이다. 자본시장법군 실물:

```
 제정 주체         변경 속도      실제 문서 (구조화 마디 수)
 ─────────        ────────      ──────────────────────────────────────
 국회              년 단위        자본시장과 금융투자업에 관한 법률   (6,261 마디)
   │ "…은 대통령령으로 정한다"                │
   ▼                                        ▼
 국무회의          월 단위        동법 시행령                        (8,096 마디)
   │ "금융위원회가 정하여 고시하는"            │
   ▼                                        ▼
 금융위원회        주 단위        금융투자업규정 [고시]              (5,674 마디)
   │ "감독원장이 정한다"                      │
   ▼                                        ▼
 금융감독원        수시           금융투자업규정시행세칙             (4,434 마디)
```

원칙(안정)은 위에, 수치·기준(가변)은 아래에 — 금리 기준 하나 바꾸는 데
국회를 소집하지 않기 위한, 소프트웨어의 config 분리와 같은 공학이다.

**검색 함의: 질문 하나의 답이 거의 항상 여러 층에 흩어진다.**
"OO 해도 되나요" = 법률(원칙) + 시행령(범위) + 규정·세칙(수치)을 함께 봐야 완전.

### 위계는 트리가 아니라 DAG 다

행정규칙 하나가 여러 모법을 섬긴다. 실측(법제처 체계도):

```
 자본시장법 ──┐                  지배구조법 ──┐
             ├──▶ 금융투자업규정              ├──▶ 지배구조 감독규정
 외국환거래법 ─┘                  상법 ────────┘
```

"부모 하나"를 가정한 코드는 반드시 깨진다. 가족 지도의 정본은
`data/law_index.json`(가족 11개·문서 38건, `python -m core.lawnet` 로 재생성).

## 2. 문서 내부 계층 — 편·장·절·조·항·호·목

```
 자본시장과 금융투자업에 관한 법률
 ├─ 제1편 총칙
 │   ├─ 제1조(목적)      ◀─ "이 법은 자본시장에서의 금융혁신과 공정한 경쟁을
 │   │                       촉진하고 투자자를 보호하며 …"  ← 문서의 공식 한 줄 요약
 │   ├─ 제2조(국외행위에 대한 적용)
 │   └─ 제3조(금융투자상품)
 │        ├─ ①  (항)
 │        │   ├─ 1.  (호)
 │        │   └─ 2.
 │        │       └─ 가.  (목)
 │        └─ ②
 ├─ 제2편 금융투자업
 │   └─ … 제49조(부당권유의 금지) …     ◀─ 조 = 개념의 단위 (제목 있음)
 ├─ 부칙  ◀─ 개정마다 하나씩 쌓인다 (KRX 상장규정은 54개, 2005~2026)
 └─ 별표·별지
```

### 함정 ① — 조번호 체계가 둘이다

```
 법률·시행령:   제34조,  제34조의2 (가지조문)
 규정·세칙류:   제1-2조, 제3-70조의2 (편-조 체계 — 금융투자업규정 실물)
```

### 함정 ② — 본문과 부칙의 번호가 겹친다

개인정보 보호법에서 "제2조"를 좌표로 받으면 후보가 넷이다(실물):

```
 "제2조" ──┬──▶ 제1장 총칙 ▸ 제2조 (정의)                          ← 본문
           ├──▶ 부칙 <제10465호, 2011> ▸ 제2조 (다른 법률의 폐지)
           ├──▶ 부칙 <제11990호, 2013> ▸ 제2조 (주민등록번호 처리 제한 경과조치)
           └──▶ 부칙 <제13423호, 2015> ▸ 제2조 (손해배상 적용례)
```

밖에서 부칙 조를 부를 때는 반드시 "**부칙** 제2조"라 쓴다 → 맨 "제2조"는
본문이다(본문우선 규칙, §5). 반대로 기계 좌표 해소에서 부칙·별표 자손을
후보에서 빼지 않으면 오해소가 난다(실측으로 잡은 버그).

## 3. 연결관계 — 조문 사이의 간선

조문들이 서로를 가리키는 방식은 문면 관용구로 갈리고, **의미와 위험이 다르다**:

```
                        ┌────────────────────────────────────────────┐
                        │              어떤 조문 하나                  │
                        └────────────────────────────────────────────┘
   내려가는 간선                     올라오는 간선              옆으로 가는 간선
   ──────────────                   ──────────────            ──────────────
   위임 "대통령령으로 정한다"          수임 "제N조에서 '…'이란"    준용 "제N조를 준용한다"
   → 답의 반쪽이 아래층에 있다        → 위임을 받은 쪽이 위층      근거 "제N조에 따라"
                                      좌표를 되가리킨다          인용 (그 밖의 언급)
                        ⚠ 배제 "제N조에도 불구하고 / 적용하지 아니한다"
                          — 방향 불문, 누락되면 정반대 답이 나가는 유일한 간선
```

### 3-1. 위임에는 주소가 없다 — 그래서 데이터가 필요하다

시행규칙 제2조(인가심사기간에 넣지 않는 기간)의 실물:

```
 원문:  "… 감독기관 등에 의한 조사·검사 등의 절차가 진행되고 …
         금융위원회가 정하여 고시하는 ◀── 어느 문서 몇 조인지 문면에 없다!
         기간 …"
                    │
                    │  법제처 편집 데이터(lsDelegated)가 채운다
                    ▼
 위임 간선:  시행규칙 제2조 ──[위임행정규칙]──▶ 금융투자업규정 (문서 수준)
             src.anchor = "제2조제3호" ◀── 조항호목은 대상이 아니라 출발 위치다
                                          (실측 1,251건 중 1,250건 = 99.9%)
```

전사 결과 `data/delegation.json` — 간선 27,318개:

| 위임구분 | 간선 수 | 뜻 |
|---|---|---|
| 인용법령 | 23,352 | 수평 인용 (참고용 — 검색 확장에는 안 씀) |
| 시행령 | 2,283 | 법률→시행령 수직 위임 (**조 단위 해소 99.7%**) |
| 위임행정규칙 | 1,251 | 법령→고시·규정 (대상은 **문서 수준까지만**) |
| 시행규칙 | 129 | 법률→총리령 |

### 3-2. 행정규칙 대상의 빈칸은 수임이 역방향으로 채운다

위임 데이터가 "금융투자업규정 어딘가"까지만 줄 때, **아래층이 스스로 좌표를
쓴다**. 증권의 발행 및 공시 등에 관한 규정의 실물:

```
 자본시장법 시행령                       증권의 발행 및 공시 등에 관한 규정
 ┌──────────────────────┐              ┌──────────────────────────────────┐
 │ 제118조의16           │   위임        │ "① 영 제118조의16제1항제2호 각 목  │
 │ (온라인소액증권발행인의 │ ──────────▶  │  외의 부분 단서에서 '금융위원회가   │
 │  조치사항 등)          │  (주소 없음)  │  정하여 고시하는 사항'이란 다음 각  │
 │                      │              │  호의 사항을 말한다."              │
 │                      │ ◀──────────  │        ▲                         │
 └──────────────────────┘   수임        └────────│─────────────────────────┘
                          (조·항 좌표!)     이 문장 자체가 위임의 구체 내용
```

수임 구문의 신호는 "**에서**" 바로 뒤의 여는 따옴표. 코퍼스에서 수임 간선
**950개** 확정 — 시행령→규정 수직 사슬의 조 단위 좌표는 이것이 유일한 원천이다.

### 3-3. 배제 — 누락의 비용이 다른 간선

개인정보 보호법 제24조의2의 실물:

```
 제24조(고유식별정보의 처리 제한)     제24조의2(주민등록번호 처리의 제한)
 ┌─────────────────────────┐        ┌─────────────────────────────────┐
 │ ① …고유식별정보를 처리할   │  배제   │ ① 제24조제1항에도 불구하고 ◀──── │
 │   수 있는 경우: 1. 동의…  │ ◀───── │   …주민등록번호를 처리할 수 없다  │
 └─────────────────────────┘        └─────────────────────────────────┘

 제24조만 읽고 답하면: "동의 받으면 주민등록번호 처리 가능" ← 정반대 오답!
```

다른 간선은 놓치면 답이 **불완전**해질 뿐이지만, 배제를 놓치면 **틀린 답을
확신**한다. 코퍼스 전체에서 105건(문서 안 89 + 문서 사이 16) = 0.4% 뿐이라
전부 실어도 비용이 없다 → 검색은 배제를 예산 경쟁 없이, **역방향까지** 싣는다.

### 3-4. 대용어는 저자가 선언해 뒀다

하위 법령이 상위를 "법 제34조"처럼 부르는 대용어 — 그 뜻은 문서 첫머리가
스스로 정의한다. 금융투자업규정시행세칙 제1-1조 실물:

```
 "이 세칙은 「자본시장과 금융투자업에 관한 법률」(이하 "법"이라 한다),
  같은 법 시행령(이하 "영"이라 한다), 같은 법 시행규칙(이하 "규칙"이라 한다),
  「금융투자업규정」(이하 "규정"이라 한다), …"
        │
        ▼  전사하면 문서 스코프 별칭 테이블이 된다
 {법 → 자본시장과 금융투자업에 관한 법률, 영 → 동법 시행령,
  규칙 → 동법 시행규칙, 규정 → 금융투자업규정}
```

선언은 개념 별칭까지 간다 — 자본시장법 시행령은 **30개**를 선언한다
('침해사고'→정보통신망법, '보험회사'→보험업법, '준법감시인'→지배구조법…).
이 전사 하나가 대용어 참조 5,874건을 발명 없이 확정했다.

단 하나의 예외: **동법·같은 법**은 선언으로 풀면 안 된다 — "「수수료규정」
… 동법 제12조"의 동법은 직전 인용(수수료규정)이다. 문맥이라 판정 몫.

## 4. 간선이 실제로 얼마나 서는가 — 해소 파이프라인

문서 사이 참조 14,111건이 규칙을 통과하며 이렇게 갈렸다(실측):

```
 문면 참조 14,111
   │
   ├─ 이름 대조   「자본시장법」 제N조 → 이름이 맞는 문서    확정 1,667  (via 이름대조)
   ├─ 선언        '법'·'영' → 그 문서의 선언 테이블         확정 5,874  (via 선언)
   ├─ 본문우선    한 문서 안 본문·부칙 중복 → 본문           확정 1,454  (via 본문우선)
   ├─ 추정        이름 없는 참조인데 후보가 하나뿐            확정   598  (via 추정)
   │                                                      ──────────
   │                                                       9,593 (68%)
   └─ 보류        후보 여럿 — 판정(LLM settle·사람) 몫       4,518
                   '법'/'영'인데 선언 없음 2,536 · 같은 법 326 · 번호 경합 등
```

확정 간선의 관계(rel) 분포: 인용 4,346 · 근거 2,802 · **수임 950 · 배제 16 ·
준용 18** · 의제 7. 문서 안 간선은 별도로 15,131건(준용 118 · 배제 89 포함).

경위(via)와 관계(rel)는 links 검수 화면에 배지로 뜨고, 자동 분류가 틀리면
사람이 간선 단위로 정정한다(rel_fixes) — 관측은 안 고치고 조립에서 덮는다.

## 5. 검색이 간선을 쓰는 방식 — 두 층 회수

```
 질의 ──▶ 착지 (벡터·승인 용어)
            │
            ▼
 ┌─ 결정론 바닥 ──────────────────────────────────────────┐
 │  판단 없이 무조건 동반 (판단에 맡기면 안 되는 간선들):     │
 │   배제  — 역방향 포함. §3-3                             │
 │   위임  — delegation.json 좌표. "답의 반쪽"             │
 │   수임  — 역방향. 아래층의 구체 내용                     │
 │   준용  — 문면 간선                                     │
 └────────────────────────────────────────────────────────┘
            │
            ▼
    무차별 참조 닫힘 (깊이 제한)
            │
            ▼
 ┌─ LLM 항해 ─────────────────────────────────────────────┐
 │  남은 자리의 배분만 판단 문제다. LLM 은 본문이 아니라       │
 │  간선 카드 {rel, from, to, 표면형} 만 보고 열 것을 고른다. │
 │  걸음은 kind="항해" 경위로 진단 튜플에 남는다.            │
 └────────────────────────────────────────────────────────┘
```

실제 동작(스모크 실측): 금융복합기업집단법 **제2조(정의)** 에 착지하면 바닥이
시행령 **제2조(금융회사의 범위)** 와 **제3조(특수관계인의 범위)** 를 위임으로
동반한다 — 법만 읽으면 "금융회사"의 범위를 모른다.

### 자동 규칙은 전부 사용자 스위치다

해소 3종(선언·본문우선·추정)과 회수 5종(배제·위임·준용·수임 동반·항해)은
규칙 화면 상단에서 켜고 끈다(`data/rules/engine.json`, `GET/POST
/v1/rag/switches`). 끄면 다음 질의부터 확정은 보류로, 동반은 회수 제외로.
**사람이 확정·정정·억제한 것은 판정이라 스위치와 무관하다.**

## 6. 실측으로 배운 함정 목록 (새로 손대는 사람 필독)

1. **law.go.kr 검색은 공식 명칭 완전일치만** — "자본시장법"(약칭) 불가.
   TARGETS 추가 후 `collect.py --dry-run` 으로 먼저 검증.
2. **MST(법령일련번호)는 개정판마다 바뀐다** — 조인 정본 키는 법령ID·명칭.
   위임 데이터 속 대상 MST 는 편집 시점 구판이다(실측: 283193 vs 238305).
3. **행정규칙 XML 은 두 꼴** — 조문형식여부 N(한 덩어리) / Y(조마다 요소
   반복). Y 형을 첫 요소만 읽으면 문서가 통째로 사라진다(실측: 11개 문서가
   제1조+부칙만 남은 채 조용히 깨져 있었다).
4. **lsDelegated 조항호목 = 출발 쪽 위치** (§3-1) — 대상 조를 여기서
   지어내면 같은 번호 우연 일치 오해소가 난다(실측 154건을 걷어냈다).
5. **좌표 해소는 부칙·별표 자손 제외** (§2 함정 ②).
6. **KOFIA·KRX 는 HWP 보다 조문 HTML** — HWP 는 스타일 전무(추론 필요),
   같은 본문의 조문 HTML 은 구조가 클래스로 명시(결정적 이관,
   `core/structure/rulehtml.py`). 별표·서식만 HWP 몫.
7. **번호 표기 변형** — 항 16 이상은 `<16>`, 호 가지 "10의2.", KOFIA 는
   "1)"·"(1)"·"※" 도 쓴다. 마커 정규식을 좁게 잡으면 조용히 빠진다.
8. **요약하지 말고 전사하라** — 문서 요약은 제1조(목적), 조문 요약은 조
   제목, 위계는 체계도, 별칭은 선언. 저자가 이미 다 써 놨고, LLM 재작성은
   잘 되면 본전, 틀리면 법적으로 다른 말이다.
