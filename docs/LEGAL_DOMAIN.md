# 법령 도메인 안내 — 처음 보는 사람을 위한 지도

이 시스템은 금융 법령·규정 위에서 검색(RAG)을 돌린다. 법령 문서는 일반 문서와
전혀 다른 구조 문법을 갖고 있고, **그 문법을 아는 것이 곧 검색 품질**이다.
이 문서는 그 문법(위계·계층·연결관계)을 먼저 설명하고, 시스템이 그것을
어떻게 데이터로 만들었는지, 실측으로 배운 함정이 무엇인지 순서로 안내한다.

---

## 1. 법령의 위계 — 왜 문서가 한 장이 아니라 사슬인가

한국 금융 규제는 하나의 문서가 아니라 **변경 속도가 다른 층의 사슬**이다:

```
법률 (국회 — 개정에 년 단위)          "원칙"        예: 자본시장과 금융투자업에 관한 법률
  └ 시행령 (대통령령 — 월 단위)       "범위·기준"    예: 동법 시행령
      └ 시행규칙 (총리령)             "절차"        예: 동법 시행규칙
          └ 행정규칙 (금융위 고시)     "수치·목록"    예: 금융투자업규정
              └ 시행세칙 (금감원)      "서식·세부"    예: 금융투자업규정시행세칙
```

원칙(안정적)은 위에 고정하고 수치·기준(가변적)은 아래로 내려보낸다 — 금리
기준 하나 바꾸는 데 국회를 소집하지 않기 위한, 소프트웨어의 config 분리와
같은 공학이다. **검색에 주는 함의: 질문 하나의 답이 거의 항상 여러 층에
흩어져 있다.** "OO 해도 되나요"의 답은 법률(원칙) + 시행령(범위) +
규정·세칙(수치) 세 층을 함께 봐야 완전하다.

주의: 이 위계는 트리가 아니라 **DAG** 다. 금융투자업규정은 자본시장법과
외국환거래법 두 체계도에 걸리고, 지배구조 감독규정은 상법 체계도에도
나타난다. 행정규칙 하나가 여러 모법을 섬기므로 "부모 하나"를 가정하면 안 된다.

코퍼스의 가족 지도(무엇을 보유했나)는 `data/law_index.json`(재생성:
`python -m core.lawnet`)이 정본이고, law.go.kr 체계도(lsStmd)에서 전사한다.

## 2. 문서 내부 계층 — 편·장·절·조·항·호·목

법령 한 편의 내부는 명시적 계층이다:

```
편 > 장 > 절 > (관) > 조 > 항(①②) > 호(1. 2.) > 목(가. 나.)
+ 부칙 (개정마다 하나씩 쌓이는 경과규정 — 오래된 법은 50개 이상)
+ 별표·별지 (표·서식 — 본문 밖 부속물)
```

**조(條)가 개념의 단위다** — 조 하나 = 주제 하나, 제목 있음("제49조(부당권유의
금지)"). 검색 착지·간선 좌표의 기본 단위도 조다.

유심히 봐야 할 것 둘:

- **조번호 체계가 둘이다.** 법률은 `제34조`, `제34조의2`(가지조문). 그런데
  금융투자업규정류 행정규칙은 **편-조 체계** `제1-2조`, `제3-70조의2` 를 쓴다.
  좌표 해소·정규식이 두 체계를 다 받아야 한다.
- **본문과 부칙의 번호가 겹친다.** 부칙마다 제1조(시행일)·제2조(경과조치)가
  있어서, "제2조" 좌표의 후보가 본문 1 + 부칙 N 으로 갈라진다. 밖에서 부칙
  조를 부를 때는 반드시 "부칙 제N조"라 쓰므로, **맨 "제N조"는 본문이다**
  (→ 본문우선 규칙, §4). 반대로 좌표를 기계 해소할 때 부칙·별표 자손을
  후보에서 빼지 않으면 오해소가 난다(실측).

## 3. 연결관계 — 조문 사이의 간선, 그리고 유심히 봐야 할 것들

법령 조문들은 서로를 가리키는데, **가리키는 방식마다 의미와 위험이 다르다.**
전부 문면의 관용구로 갈리므로 결정론 분류가 가능하다(LLM 불필요).

| 관계 | 문면 신호 | 뜻 | 검색에서의 무게 |
|---|---|---|---|
| **위임** | "**대통령령으로 정한다**", "금융위원회가 정하여 고시하는" | 세부 내용을 하위 법령에 맡김 — 대상 조문이 이 조문 내용의 일부 | **필수 동반** — 없으면 반쪽 답 |
| **수임** | "제N조**에서 "…"이란** ~을 말한다" | 위임을 받은 쪽의 정의구문 — 이 조문이 곧 위임의 구체 내용 | **필수 동반(역방향)** — 아래층에서 위층 좌표를 잇는 유일한 선 |
| **준용** | "제N조를 **준용**한다" | 다른 규범을 필요한 변경 가해 적용 (복붙 대신 호출) | 필수 동반 |
| **배제** | "제N조**에도 불구하고**", "**적용하지 아니한다**" | 일반칙을 뒤집는 예외 — **부정 간선** | ⚠ 최고 위험 — **누락되면 정반대 답이 나간다.** 역방향 포함 무조건 동반 |
| **의제** | "~한 것**으로 본다**" | 간주 | 조건부 |
| **근거** | "제N조**에 따라/의하여**" | 조건·근거 표시 | 맥락 따라 |
| **인용** | 그 밖의 언급 | 관련 표시 | 보수적으로 |

세 가지를 특히 유심히:

1. **위임에는 주소가 없다.** "대통령령으로 정하는 바에 따라" — 어느 시행령
   몇 조인지 문면 어디에도 없다. 법제처 편집 데이터(lsDelegated)가 법령
   대상은 조 단위로 채워 주지만, **행정규칙 대상은 문서 수준까지만** 준다.
   그 빈칸을 아래층의 수임 구문이 역방향으로 채운다 — 위임(위→아래 데이터)과
   수임(아래→위 문면)이 합쳐져야 수직 사슬이 완성된다.
2. **배제는 누락의 비용이 다르다.** 다른 간선은 놓치면 답이 불완전해질
   뿐이지만, 배제 조항을 놓치면 시스템이 **틀린 답을 확신**한다. 그래서
   배제만은 검색 예산 경쟁 없이 무조건 싣고, 역방향(나를 배제하는 조항)까지
   찾는다. 코퍼스 전체에서 0.4% 뿐이라 비용도 없다.
3. **대용어는 저자가 선언해 뒀다.** 하위 법령은 모법을 "법 제34조"처럼
   대용어로 부르는데, 그 대용어는 문서 첫머리가 스스로 정의한 것이다 —
   "「자본시장과 금융투자업에 관한 법률」(**이하 "법"이라 한다**)". 이 선언을
   전사하면 대용어 참조의 대부분이 발명 없이 결정론으로 풀린다. 단,
   **동법·같은 법은 선언으로 풀면 안 된다** — 직전 인용 문맥을 가리키는
   말이라 판정 몫이다.

## 4. 시스템은 이것을 어떻게 데이터로 만들었나

### 자산 지도

| 자산 | 내용 | 만드는 법 |
|---|---|---|
| `corpus/` | 수집 원문 (law.go.kr XML · KOFIA/KRX 조문 HTML·HWP) — 불변 | `python collect.py --source law` (공식 명칭 완전일치) |
| `corpus/law/relations/` | 위임(lsDelegated)·체계도(lsStmd) XML 원본 | 재수집 스크립트 (멱등) |
| `data/structure/` | 구조화 스토어 — 결정적 이관(추론 없음, fitness 1.0) | `python ingest_lawxml.py` · `python ingest_rulehtml.py` |
| `data/delegation.json` | 위임 간선 (좌표 해소 포함) | `python -m core.lawnet` |
| `data/law_index.json` | 문서 인덱스 — 종별·시행일·제1조(목적) 전사·가족 트리 | 〃 |
| 참조 간선 (rel 포함) | 문면 참조 + 관계 분류 — 색인 로딩 때 재계산 | `core/rag/refs.py` |
| `data/links.json` | 사람·LLM 판정으로 고정된 문서 간 연결 + 관계 정정(rel_fixes) | links 검수 화면 |

원칙: **요약하지 않고 전사한다.** 법령은 저자가 이미 압축본을 다 써 놨다 —
문서의 한 줄 요약은 제1조(목적), 조문의 요약은 조 제목, 위계는 체계도.
LLM 재작성은 잘 되면 본전, 틀리면 법적으로 다른 말이 된다.

### 검색이 간선을 쓰는 방식 — 두 층

```
착지(벡터·용어) → [결정론 바닥] 배제(역방향 포함)·위임·준용·수임 무조건 동반
              → [무차별 참조 닫힘] 깊이 제한
              → [LLM 항해] 남은 자리는 간선 카드(관계·대상·표면형)를 보고 LLM이 선택
```

판단이 필요 없는(맡기면 안 되는) 간선은 바닥이 보장하고, "이 인용이 이번
질문에 결정적인가"라는 판단만 LLM 몫이다. 항해의 걸음은 진단 튜플에 경로로
남아 반복되는 경로가 규칙으로 승격되는 연료가 된다.

### 자동 규칙은 전부 사용자 스위치다

해소(선언 확정·본문우선·추정 연결)와 회수(배제·위임·준용·수임 동반·항해)의
자동 규칙 8종은 **규칙 화면 상단 스위치**로 켜고 끈다(`data/rules/engine.json`,
`GET/POST /v1/rag/switches`). 끄면 다음 질의부터 반영. 사람이 확정·정정·억제한
것은 규칙이 아니라 판정이라 스위치와 무관하다. links 화면의 경위 배지
(선언/본문우선/추정/이름대조)와 관계 배지(수임/준용/배제…)로 각 규칙의 산출을
눈으로 검수하고, 간선 단위 정정(관계 셀렉트)·끊기(억제)도 그 화면에서 한다.

## 5. 실측으로 배운 함정 목록 (새로 손대는 사람 필독)

1. **law.go.kr 검색은 공식 명칭 완전일치만** — "자본시장법"(약칭) 불가.
   새 문서는 `collect.py` TARGETS 에 공식 명칭으로 추가하고 `--dry-run` 으로
   먼저 검증한다.
2. **MST(법령일련번호)는 개정판마다 바뀐다** — 간선·조인의 정본 키는 법령ID
   또는 명칭. 위임 데이터 안의 대상 MST 는 편집 시점 구판이라 못 쓴다.
3. **행정규칙 XML 은 두 꼴이다** — 조문형식여부 N(조문내용이 한 덩어리) /
   Y(**조마다 요소 반복**). Y 형을 첫 요소만 읽으면 문서가 통째로 사라진다
   (실측: 11개 문서가 제1조+부칙만 남은 채 조용히 깨져 있었다).
4. **lsDelegated 의 조항호목은 출발 쪽 위치다** — 대상 좌표가 아니다
   (실측 99.9%). 대상 조를 여기서 지어내면 같은 번호 우연 일치의 오해소가 난다.
5. **좌표 해소는 부칙·별표 자손을 빼고** — 부칙의 제N조가 본문 좌표를
   가로챈다.
6. **KOFIA·KRX 는 HWP 보다 조문 HTML** — HWP 는 스타일이 전무해 추론이
   필요하지만, 같은 본문의 조문 HTML 은 구조가 클래스·마커로 명시돼 있어
   결정적 이관이 된다(`core/structure/rulehtml.py`). 별표·서식만 HWP 몫.
7. **번호 표기 변형** — 항이 ①…㊿ 를 넘으면 `<16>`, 호 가지 "10의2.",
   목은 "가.~하.", KOFIA 는 "1)"·"(1)"·"※" 도 쓴다. 마커 정규식을 좁게 잡으면
   조용히 빠진다.

## 6. 처음 와서 한 바퀴 돌아보기

```bash
# 수집 → 이관 → 관계망 (전부 멱등)
python collect.py --source law --dry-run          # 대상 확인
python collect.py --source law                    # 수집
python ingest_lawxml.py                           # 법령 XML → 구조 스토어
python ingest_rulehtml.py --source krx            # 조문 HTML → 구조 스토어
python -m core.lawnet                             # 위임 간선 + 문서 인덱스

# 시험
python -m pytest tests/core tests/rag -q

# 화면 (scripts/serve.sh 로 기동 후)
#   /links/   참조 검수 — 간선·경위·관계 배지, 정정
#   /rules/   공리 루프 — 엔진 규칙 스위치
#   /rag/     질의 — 사다리에 "필수 동반"·"간선 항해" 단이 보인다
```
