# 골든 쌍 — Part B 정합성 검증 테스트 데이터

SPEC §B11 완료 기준을 자동 검증하기 위한 (체결 계약서, 요약서, 기대 리포트) 세트.

## acct_001 — 무엇이 근거이고 무엇이 지어낸 값인가

| | 출처 |
|---|---|
| **필드 집합** | `dataset/ss2207_special_trust.pdf` 의 실제 `[별지1] 신탁계약 세부내역` 을 파싱해 그대로 사용 |
| **계약서제N조 링크** | 원본에 있는 그대로 (제2조/제3조/제7조/제12조/제13조/제15조) |
| **중도해지수수료 4단 조건** | 원본 문구 그대로 |
| **운용방법 1~24 그리드** | 원본 라벨 그대로 |
| **채워진 값** | **전부 지어낸 것** — 실제 체결 건이 아니다 |

원본 별지1 필드는 SPEC §B1 이 나열한 목록과 정확히 일치했다:
계좌번호 · 신탁금액 · 신탁기간 · 운용내역 통지여부 · 신탁보수(기본/수익) ·
이익계산 및 지급(지급주기/원금지급비율/지급기간/지급계좌) · 중도해지수수료 ·
신탁자금 운용방법 · 세부 운용지시.

## 파일

```
acct_001/
  contract.chunks.json        Part A 출력 형식(facet-v1). 별지1 값이 채워진 체결본
  summary.md                  짝이 되는 투자요약서. 일부러 어긋나게 만든 항목 포함
  expected.reconcile.json     기대 판정 13행 + stats
```

계약서를 PDF 가 아니라 `chunks.json` 으로 둔 이유: Part B 의 입력은 SPEC §B2 상
"Part A 파이프라인으로 얻은 chunks.json" 이다. 파싱 경로는 `ss2207_special_trust.pdf`
가 이미 검증하므로, 여기서는 **정합성 로직만** 독립적으로 시험한다.

## 무엇을 검증하는가

### 5종 verdict 를 전부 덮는다 (§B8)

| verdict | 해당 필드 | 심어 둔 상황 |
|---|---|---|
| `MATCH` ×7 | 계좌번호, 신탁금액, 신탁기간, 수익보수, 원금지급비율, 지급기간, 운용방법 | 포맷·순서만 다름 |
| `VALUE_MISMATCH` ×2 | 지급주기(매월↔분기), 중도해지수수료(0.3%↔0.2%) | 진짜 불일치 |
| `MISSING_IN_SUMMARY` ×2 | 운용내역 통지여부, 지급계좌 | 요약서에 항목 자체가 없음 |
| `UNMAPPED` ×1 | 세부 운용지시 | 요약서에 '투자전략' 으로 **값은 있는데** 별칭이 없어 못 찾음 |
| `NEEDS_REVIEW` ×1 | 기본보수 | 계약서 값이 "기타특약사항에 기재" 라는 참조라 대조 불가 |

### §B11-3 포맷 차이가 MATCH 로 나오는지

- `금 일억원정 (₩100,000,000)` ↔ `100,000,000원` — 한글 단위 + 콤마
- `2024년 6월 3일부터 2027년 6월 2일까지` ↔ `24.6.3 ~ 27.6.2` — 2자리 연도
- `(15)%` ↔ `15.00%` — 소수점 자릿수

### 값 비교기별 커버리지 (§B7)

`number` · `date_range` · `percent` · `range_tiers` · `option_set` · `account_no` · `text` 전부 최소 1건씩.

### 판정 종류를 구분하는지

`MISSING_IN_SUMMARY`(요약서에 값이 없음)와 `UNMAPPED`(이름을 못 찾음)는
사람이 취할 조치가 다르다 — 전자는 요약서 수정, 후자는 `aliases.yaml` 보강.
뭉뚱그리면 안 된다.

### aliases.yaml 로 UNMAPPED 가 해소되는지

`config/aliases.yaml` 의 `세부 운용지시` 항목이 **일부러 비어 있다.**
주석 처리된 `- 투자전략` 을 살리면 그 행이 `UNMAPPED` → `MATCH` 로 바뀌어야 한다.
코드 수정 없이 설정만으로 매핑이 늘어나는지를 확인하는 항목이다.

### 파생값 (§B7 말미)

요약서의 `만기일 2027-06-02` 는 별지1에 직접 없고 `신탁기간` 종료일과 같아야 한다.
`동일` 이 아니라 **`계산상 일관`** 으로 판정하고 계산식을 note 에 남긴다.
`expected.reconcile.json` 의 `_derived_check` 참조.

## 한계 — 이건 실물 검증이 아니다

값은 전부 합성이다. 검증되는 것은 **정합성 로직**이지 실제 문서에서의 추출 정확도가 아니다.
실물 검증을 하려면 값이 채워진 진짜 체결본과 그 짝인 요약서가 필요하다.

또한 요약서를 마크다운으로 뒀다. 실제 요약서는 PDF 이고 표 레이아웃이 흔들리므로,
T9(요약서 파서)의 난이도는 이 파일이 보여주는 것보다 높다.
