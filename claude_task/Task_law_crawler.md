## 1. 배경

금융 규정/계약 문서 대상 AI 에이전트의 코퍼스를 구축 중이다.
법령·행정규칙(자본시장법, 금융투자업규정 등)은 국가법령정보센터 OPEN API로
이미 수집된다(`law_crawler.py`). 이번 작업은 **API가 없는 협회·감독기관 규정**을
같은 출력 계약에 맞춰 수집하는 어댑터 추가.

코퍼스는 최종적으로 조문 단위 청킹 + 결정적 검색에 쓰인다.
**원문 파일 보존과 출처·버전 메타데이터가 본문 텍스트보다 중요하다.**
파싱·변환은 이 작업의 범위가 아니다. 수집과 메타데이터까지만.

---

## 2. 실행 환경

**아웃바운드 네트워크 전면 개방된 테스트 환경이다.**

- 임의 도메인 HTTP/HTTPS 접근 가능. 프록시·화이트리스트 없음.
- PyPI/npm 접근 가능. 필요한 패키지는 승인 없이 설치해도 된다.
- 따라서 **모든 조사는 실제 요청으로 검증한다.** 추측한 스키마나 셀렉터를
  코드에 넣지 말 것. 확인 안 된 건 확인하고 오면 된다.

**유일한 실패 원인은 상대 서버의 차단이다.** 이 전제 위에서 설계할 것.
"접속이 안 됨"은 대부분 내 환경 문제가 아니라 (a) TLS 협상 실패,
(b) User-Agent/헤더 거부, (c) 레이트 리밋, (d) 세션 쿠키 미보유 중 하나다.
바로 포기하지 말고 Phase 0의 진단 순서를 따른다.

## 5. Phase 0 — 접속 프로파일 확보

각 도메인에 대해 **어떤 조건으로 요청해야 200이 오는지**를 먼저 확정한다.
국내 기관 사이트는 표준적이지 않은 경우가 많아서, 이걸 안 잡고 크롤러를 짜면
원인 불명의 실패에 시간을 다 쓴다.

### 진단 순서

1. `curl -sSv https://<domain>/` — 응답 코드, 리다이렉트 체인, 쿠키 확인
2. **TLS 실패 시** (`SSLError`, `dh key too small`, `unsafe legacy renegotiation`):
   국내 기관 사이트에서 흔하다. 인증서 검증을 끄지 말고 SSL 컨텍스트를 완화한다.

   ```python
   import ssl, requests
   from requests.adapters import HTTPAdapter
   from urllib3.util.ssl_ import create_urllib3_context

   class LegacyTLSAdapter(HTTPAdapter):
       def init_poolmanager(self, *a, **kw):
           ctx = create_urllib3_context(ciphers="DEFAULT@SECLEVEL=1")
           ctx.options |= 0x4  # OP_LEGACY_SERVER_CONNECT
           kw["ssl_context"] = ctx
           return super().init_poolmanager(*a, **kw)
   ```

   `verify=False`는 쓰지 말 것. 실패 원인을 가려서 나중에 디버깅이 불가능해진다.
3. **403인데 브라우저로는 열리는 경우**: UA 거부다. 일반 브라우저 UA +
   `Referer`, `Accept-Language: ko-KR` 를 붙여서 재시도.
4. **빈 응답/리다이렉트 루프**: 세션 쿠키가 필요하다. 메인 페이지를 먼저 GET해서
   쿠키를 받은 뒤 같은 `Session`으로 대상 URL 호출.
5. 위로도 안 되면 JS 렌더링이 필요한지 판단. Playwright 설치해서 확인한다.

### 산출물 — `docs/access_profile.md`

도메인별로: 필요한 헤더, TLS 설정, 세션 선행요청 여부, robots.txt 내용,
확인된 레이트 리밋(있다면), 재현 가능한 `curl` 한 줄.

## 6. Phase 1 — 사이트 구조 조사 (코드 작성 금지)

**실제 요청을 보내서 응답을 확인한다.** 조사 단계이므로 스크래퍼를 만들지 않는다.

### 지시

1. **HTML 파싱 전에 XHR/JSON 엔드포인트를 먼저 찾는다.** 조문 뷰어형 사이트는
   대개 본문을 별도 JSON으로 가져온다. 있으면 그게 훨씬 안정적이다.
   페이지 소스의 `fetch(`/`ajax`/`.do?` 패턴을 grep.
2. Playwright는 정적 요청으로 안 되는 게 확인된 경우에만. 가용성 문제가 아니라
   **속도와 취약성** 때문이다. XHR이 있으면 그걸 쓴다.
3. 목록 API를 찾았으면 **파라미터를 바꿔가며 호출해서 동작을 파악한다.**
   페이지 크기 최대값, 정렬, 검색 필드가 뭔지 실증할 것.

### 산출물 — `docs/site_survey.md`

각 사이트별로:
- 목록 조회: URL, 메서드, 파라미터, 응답 형식, 페이지네이션
- 본문 조회: URL, 식별자가 무엇인지(규정ID? 일련번호?), 응답 형식
- 첨부파일: 다운로드 URL 패턴, 파일 형식, `Content-Disposition` 실제 값
- 버전 정보: 시행일·개정일이 어느 필드에 있는지. **없으면 없다고 명시**
- 신구조문대비표: 별도 게시물인지 첨부인지, 본문과 어떻게 연결되는지
- 실제 응답 샘플 3건 (원문 그대로, 요약 금지)

추측한 부분은 `[미확인]`으로 표시. 확인 가능한 환경이므로 `[미확인]`이
많으면 조사가 덜 된 것이다.

## 7. Phase 2 — 어댑터 인터페이스 설계

조사 결과 승인 후 진행.

### 원칙

소스별 수집 로직과 공통 파이프라인을 분리한다. 사이트마다 다른 건
"어떻게 목록을 얻고 어떻게 파일 URL을 얻는가"뿐이고, 다운로드·재시도·저장·
manifest 기록은 공통이다. 섞으면 사이트 하나 바뀔 때 전체가 깨진다.

```python
class SourceAdapter(Protocol):
    source_id: str                    # "kofia" | "fss" | "krx"

    def session(self) -> requests.Session:
        """Phase 0의 접속 프로파일이 적용된 세션."""

    def discover(self, target: Target) -> list[DocumentRef]:
        """대상 규정을 식별하고 다운로드 참조 목록 반환. 파일 저장은 하지 않음."""

    def fetch(self, ref: DocumentRef, dest: Path) -> FetchResult:
        """단일 문서를 dest에 저장."""
```

`DocumentRef` 최소 필드:
`title`, `url`, `role`(`body` | `attachment` | `comparison_table`), `version_hint`, `file_ext`

`role`을 명시 필드로 두는 이유: 신구조문대비표는 좌우 2단 표라 본문과 파서가
완전히 다르다. 파일명으로 구분하면 하위 파이프라인에서 반드시 사고난다.

`docs/adapter_design.md`에 인터페이스와 각 어댑터의 구현 계획 기술. 멈추고 보고.

## 8. Phase 3 — 금투협 어댑터 구현

### 구현

- `sources/kofia.py`에 `KofiaAdapter`
- 출력: `corpus/kofia/<규정명>/` — 본문, `별표서식/`, `신구조문대비표/`
- manifest는 소스별 파일로 분리하고 병합 스크립트를 둔다. 스키마는 §3과 동일,
  `source` 필드로 출처 구분.

### 필수 동작

1. **멱등성**: 재실행 시 받은 파일 건너뜀. `--force`로 무시 가능.
2. **부분 실패 허용**: 한 문서 실패가 전체를 중단시키지 않는다.
   manifest에 `status: "error"` + 사유 기록하고 계속.
3. **차단 감지 및 회복** — 이 환경의 주된 실패 모드다:
   - 동시 요청 1개. 병렬화하지 말 것.
   - 요청 간 최소 1초.
   - `429`/`503` → 지수 백오프 (2s → 8s → 32s), 3회 후 해당 문서 실패 처리
   - **연속 3회 `403` 또는 캡차 페이지 감지 → 즉시 전체 중단하고 보고.**
     계속 두드리면 IP 차단으로 번져서 다음 실행까지 막힌다.
   - HTML 응답에 차단 문구가 섞여 오는 경우가 있으므로, 200이어도
     기대한 콘텐츠 타입/크기인지 검증한다.
4. **원문 보존**: HWP를 텍스트로 변환하지 않는다. 원본 그대로 저장.
   변환은 별도 파이프라인 책임. (라이브러리 설치는 자유지만 수집기에 넣지 말 것)
5. **파일명 처리**: `Content-Disposition`의 한글 파일명이 EUC-KR로 인코딩 안 된 채
   오는 경우가 많다. UTF-8 디코딩 실패 시 EUC-KR/CP949로 폴백. 그래도 깨지면
   목록에서 얻은 제목으로 파일명을 만들고, 원본 헤더 값을 manifest에 남긴다.
6. **확장자 신뢰 금지**: 매직바이트로 실제 형식을 판정한다.
   HWP 5.0은 OLE(`D0 CF 11 E0`), HWPX는 ZIP(`50 4B`), PDF는 `%PDF`.
   `.hwp`로 내려받았는데 실제로는 HWPX거나 PDF인 경우가 흔하다.
   판정 결과를 manifest의 `actual_format`에 기록.
7. **무결성**: 파일별 sha256을 manifest에 기록. 시행일 필드가 없는 규정은
   해시 비교가 개정 감지의 유일한 수단이 된다.

### 금지

- 로그인이 필요한 페이지는 수집하지 않는다. 발견 시 보고하고 건너뜀.
- DRM 우회 시도 금지.
- 응답을 못 받았는데 그럴듯한 값으로 manifest를 채우지 않는다. 빈 값은 빈 값으로.

### 수용 기준

- [ ] `python collect.py --source kofia --dry-run` 이 받을 파일 목록 출력
- [ ] 4개 대상 규정 본문이 실제로 열린다 (크기 0 아님, 매직바이트 정상)
- [ ] 신구조문대비표가 하나 이상 `role: comparison_table`로 수집됨
- [ ] 재실행 시 네트워크 요청 없이 skipped
- [ ] 의도적 오류 URL 하나 넣었을 때 나머지 정상 완료
- [ ] 429를 강제 유발했을 때(또는 모의했을 때) 백오프 후 복구

## 9. 공통 규칙

- Python 3.11+. 의존성 설치 자유. 다만 `requests` + 표준 라이브러리로 되는 걸
  굳이 무거운 프레임워크로 하지 말 것.
- 타입 힌트 필수. `except: pass` 금지.
- 커밋은 Phase 단위 분리.
- 테스트는 Phase 1에서 저장한 실제 응답을 픽스처로 쓴다.
  테스트가 네트워크를 치지 않게 할 것.
- 모든 HTTP 요청/응답 코드를 `logs/`에 남긴다. 차단 원인 추적에 필요하다.
