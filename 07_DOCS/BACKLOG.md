## 입력·구조화 — 작업 코드 연결, 현장 검증 대기

- 입력 manifest를 요구하는 계약을 해제하고 파일·폴더로 입력받는다.
- 같은 문서의 여러 표현본은 **XML이 있으면 XML → 없으면 PDF → 둘 다 없으면 DOCX·HWP 등**의 순서로 선택한다. 서로 다른 문서는 각각 처리한다.
- PDF에는 **LLM 구조화 틀 생성 → 코드로 구조 적용 → VLM의 원본 페이지 검수·보정** 경로를 사용한다.
- PDF 경로는 기존 `recipe_runtime`에 연결되어 있다. 2026-09-12 규칙 부재 시 자동 생성 → 원문 검증 → 재구축·VLM 검수 → 문서별 저장·재사용을 작업 코드에 반영했다. [동작·제한](REFERENCE/OPERATIONS/GENOS_RECIPE_VLM.md).
- 합성 테스트로 연결을 확인했다. GENOS 실호출·배포, 수집 사전 PDF 전수 용어 추출은 미실행이다. 2026-09-13 파일 기반 입력·동일 문서 형식 우선 선택·구조화 뒤 새 용어집 연결을 구현했다. 현행 진입점은 `pipeline.py build-data-stages`다.

- 후속 품질 비교를 실행할 때 ADR·검증 기준을 별도로 연결한다.

## BL-001 · XML 이외 문서의 구조화에 용어집 활용 실험

- 등록일: 2026-09-11
- 상태: 대기 — 미실행, ADR 미생성
- 질문: **XML이 아닌 형식을 구조화할 때 용어집을 사용하면 더 효과적으로 구조화할 수 있는가?**
- 대상: PDF·DOCX·HWP 등 비XML 문서. PDF는 위 LLM 틀 생성·VLM 검수 경로를 기준으로 한다.
- 비교안: 같은 문서·모델·설정에서 용어집 없이 구조화한 결과와, 관련 용어를 힌트로 제공한 결과를 비교한다.
- 활용 후보: 제목·절 경계·항목 소속 판단, 구조화 틀 생성, VLM 검수에 용어집을 제공하는 방식. 구체적인 주입 위치는 실험 설계 때 결정한다.
- 확인할 것: 계층·부모 연결·표/첨부 소속·누락/잘못된 분할과 토큰·호출 수·처리 시간. 효과가 있다고 미리 가정하지 않는다.
- 실행 전 준비: 사용할 용어집 버전·문서 표본·성공 기준을 고정하고 ADR을 연결한다. 용어 힌트로 원문을 바꾸거나 법률 의미를 확정하지 않는다.
- 환경: 공개 또는 모의 자료로 외부 검증을 준비한다. 실제 내부 문서·GENOS 내부 모델 검증은 현장에서 수행하며 현재 Codex에서는 GENOS 세션에 접근할 수 없다.
- 결과/ADR: 미정

- 근거: [ADR0367](../04_EXPERIMENTS/ADR/ADR-0367-glossary-article-equality-pdf-audit/README.md). 공개 PDF2개 모두 초기 recipe 오류로 검수 전 중단. 스캔 표본은 한글 누락도 관측.

- 2026-09-14 추가 반영: 공백으로 끊긴 별표 참조 조사, 같은 블록의 조·항 글자 위치 검사, 반복 머리말·쪽번호의 제목 오인식, 무효 구조 수정 피드백을 보완했다. 작업 코드 회귀181개 통과. [ADR0372](../04_EXPERIMENTS/ADR/ADR-0372-pdf-running-furniture/README.md).
