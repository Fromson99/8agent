# 아리아드네(실마리) 용어집

## 이름의 뜻

이 RAG 경로의 사람용 이름은 **아리아드네(Ariadne)**, 한국어 표시명은
**실마리**로 한다. 그리스 신화에서 아리아드네의 실이 미궁의 경로를 잃지 않게 한
것처럼, 질문의 작은 단서에서 시작해 승인된 개념과 사실을 거쳐 원문 근거까지 추적한다는
뜻이다.

신화 이름은 제품·파이프라인 수준에서만 쓴다. 내부 구성요소까지 인물 이름으로 바꾸면
처음 보는 사람이 기능을 추측하기 어려우므로, 화면·로그·문서에서는 아래의 일상적인
한국어 기능명을 쓴다. Python 클래스명과 JSON 필드는 기존 호환성을 위해 유지한다.

## 핵심 용어

| 사람에게 보이는 이름 | 코드명 | 뜻 |
|---|---|---|
| 실마리 | Concept-first RAG | 질문의 구조·용어·본문 조각을 원문 좌표로 연결하는 전체 경로 |
| 단서 | `QuerySpan` | 질문에서 실제로 잘라낸 연속 문자열 |
| 단서 자리 | `Span role` | 단서가 질문에서 하는 일 |
| 근거 주소 | `StructureAnchors` | 법령명·조·항·호와 확정된 문서/노드 좌표 |
| 표준 개념 | `Concept` | 여러 표현을 하나로 묶는 승인된 의미 단위 |
| 개념 번호 | `concept_id` | 표준 개념의 변하지 않는 기계 식별자 |
| 대표명 | `label` | 표준 개념을 사람에게 보여 주는 기본 이름 |
| 별칭 | `alias` | 대표명과 같은 뜻으로 승인된 다른 표현 |
| 발견 표현 | `surface`, `matched` | 질문 또는 데이터에서 실제로 발견된 문자열 |
| 개념 종류 | `Concept type` | 사람·조직·문서·행위 등 개념의 고정 분류 |
| 개념 연결 | `ConceptRelation` | 두 표준 개념 사이의 승인된 관계 |
| 본문 조각 | `LiteralFragment`, `query_cue` | 용어로 올리기 어려워 본문에서 잘라 둔 조건·행위·효과 표현 |
| 출현 자리 | `role` | 한 개념이나 본문 조각이 해당 본문에서 맡는 자리 |
| 추출 묶음 | `Assertion` | 과거 추출 행과 승인 provenance를 보존하는 호환 형식; 검색 교집합 키가 아님 |
| 정의 별칭 간선 | definition `A→B` | 질문의 A를 선언 문서 안에서 이후 B 사용 좌표로 확장하는 방향성 연결 |
| 후보 카드 | `Part` | 한 단서에 대해 검색된 표준 개념 후보와 일치 정보 |
| 후보 목록 | `SpanMenu` | 단서별로 LLM에 보여 주는 닫힌 후보 카드 집합 |
| 연결안 | `mapping` | 단서와 후보 카드를 어떤 사실 자리에 놓을지 낸 제안 |
| 맞춤 조립기 | `Composer` | 여러 연결안을 하나의 실제 사실문으로 맞추는 단계 |
| 조립 결과 | `PartAlignment` | 확정된 개념·자리·근거 주소와 판정 기록 |
| 조립 결정 | `decision` | 연결 확정 또는 연결 불가 처리 결과 |
| 질문 종류 | `intent` | 사실 조회인지 개념 정의인지 나타내는 분류 |
| 뜻 판별기 | Predicate verifier | 표면이 다른 두 행위가 문맥상 같은지 확인하는 단계 |
| 뜻 판정 | `verdict` | 같은 뜻·다른 뜻·불확실 중 하나의 판정 |
| 검문 규칙 | validation gate | 잘못된 연결안이나 근거를 코드에서 차단하는 규칙 |
| 조회 설계도 | OQL plan | 확정된 개념 번호와 근거 주소만 담은 실행 요청 |
| 일반검색 인계 | fallback | 실마리가 확정하지 못한 질문을 기존 RAG로 넘기는 것 |
| 추적 기록 | audit/proposal | 어떤 후보와 규칙이 결정에 영향을 줬는지 남긴 기록 |

`라벨`이라는 말은 코드의 `label`, 즉 **대표명**에만 쓴다. `actor`, `action`,
`MATCH`처럼 닫힌 목록에서 고르는 값은 각각 **자리**, **종류**, **판정**으로 부른다.

## 닫힌 목록의 표시명

### 단서 자리 14개

| 코드값 | 표시명 |
|---|---|
| `actor` | 행위자 |
| `predicate` | 행위 |
| `object` | 대상물 |
| `target` | 상대·도착점 |
| `method` | 방법 |
| `modality` | 의무·가능성 |
| `condition` | 조건 |
| `effect` | 결과·효과 |
| `subject` | 관련 주제 |
| `document` | 법령·문서 |
| `toc` | 목차 항목 |
| `heading` | 본문 제목 |
| `locator` | 조문 주소 |
| `unknown` | 자리 미정 |

출현 자리에는 위 목록 중 본문 의미 요소에 쓰는 9개(`ACTOR`부터 `SUBJECT`까지)만 있다.
코퍼스의 문서 제목, 목차, Heading, 조문 주소는 구조 객체로 착지하고, 같은
`document` 자리라도 투자설명서처럼 본문 안의 문서 개념이면 `SUBJECT`로
착지한다. `unknown`은 분해 시점에만 쓰며 실제 사실 자리로 발행하지 않는다.

### 처리 결과

| 코드값 | 표시명 | 사용자에게 설명할 말 |
|---|---|---|
| `SELECT` | 연결 확정 | 승인 사실과 근거를 찾음 |
| `NO_MATCH` | 연결 불가 | 확정하지 못해 일반검색으로 인계 |
| `MATCH` | 같은 뜻 | 질문 행위와 승인 행위가 문맥상 같음 |
| `MISMATCH` | 다른 뜻 | 서로 다른 행위이므로 차단 |
| `UNSURE` | 불확실 | 명시적 불일치는 아니므로 다른 구조 규칙과 함께 통과 |

## 코드 검문 규칙 10종

| 표시명 | 확인하는 것 |
|---|---|
| 글자 검문 | 단서가 질문에 실제로 존재하는 연속 문자열인가 |
| 주소 검문 | 명시된 법령·조문이 하나의 실제 근거 주소로 해소되는가 |
| 후보 검문 | 선택한 개념 번호가 해당 단서의 닫힌 후보 목록 안에 있는가 |
| 번호 검문 | Span 번호를 유일하게 해석할 수 있는가 |
| 종류·자리 검문 | 행위 개념을 행위 자리에 놓는 등 종류와 자리가 맞는가 |
| 최소 단서 검문 | 사실을 열 만큼 서로 다른 근거 단서가 있는가 |
| 사실 합류 검문 | 선택한 개념들이 같은 실제 사실문에 함께 등장하는가 |
| 단일 근거 검문 | 경쟁하는 사실문 중 하나가 유일하게 우세한가 |
| 행위 뜻 검문 | 질문의 행위와 승인 행위가 명시적으로 다른 뜻은 아닌가 |
| 무주소 오염 검문 | 주소 없는 범용 질문이 여러 문서의 사실을 임의로 열지 않는가 |

## 평가 용어

| 표시명 | 뜻 | 전체 성능을 말할 수 있는가 |
|---|---|---|
| 전체 프로세스 판정 | `/ask`와 법률검토 실제 E2E를 합쳐 답·근거·비용·채널·단계를 검사 | 예 |
| 질의응답 E2E | 운영 `/ask` 검색부터 최종 답·인용까지 검사 | 해당 제품 흐름에 한해 예 |
| 법률검토 E2E | 사실 추출부터 요건·포섭·최종 basis까지 검사 | 해당 제품 흐름에 한해 예 |
| E2E canary | 적은 고정 문항으로 전체 흐름의 큰 고장을 빨리 탐지 | 아니오, 릴리스판을 대신하지 않음 |
| Concept 진입 부품검사 | Concept/OQL 진입과 근거 좌표만 검사 | 아니오 |
| 근거 shadow | 기존 질문에 새 근거 오염이 생기는지만 검사 | 아니오 |

`골든`만 단독으로 부르지 않는다. 사람이 동결한 정답 데이터는 모두 골든일 수 있어
범위를 숨긴다. 보고할 때는 `질의응답 E2E`, `법률검토 E2E`, `Concept 진입
부품검사`처럼 무엇을 끝까지 검사했는지 붙인다.

양성·음성은 짧지만 사용자에게는 의미가 모호하므로 보고서에서는 다음처럼 쓴다.

| 기존 표현 | 권장 표현 |
|---|---|
| 양성 문항 | 찾아야 하는 문항 |
| 음성 문항 | 막아야 하는 문항 |
| true positive | 근거 회수 성공 |
| false negative | 근거 누락 |
| true negative | 오염 차단 성공 |
| false positive | 오염 진입 |
| precision | 진입 정확도 |
| recall | 근거 회수율 |

후보 수·문자 길이·점수 문턱처럼 성능을 바꾸는 코드 값은 **성능 손잡이**라고 부른다.
흐름도에는 해당 손잡이의 등록 키와 기준값을 표시하고, 여러 채널이 각자 가진 수를
더한 값은 **가산 예산**, 다른 상한 밖에서 붙는 수는 **별도 예산**이라고 구분한다.

예: “음성 49/50”보다는 “막아야 하는 문항 50개 중 49개 오염 차단”이라고 쓴다.
