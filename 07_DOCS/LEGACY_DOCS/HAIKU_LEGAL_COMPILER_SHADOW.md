# Haiku 법률 명제 컴파일러 shadow 실험

## 결론

법률 명제 컴파일러는 일부 포섭 오류를 고쳤지만 최종 답변기로는 비열등성을
입증하지 못했다. 17건 개발 분할에서 기존과 후보가 각각 7/17로 동률이었고,
기존 정답 2건을 잃는 대신 오답 2건을 고쳤다. 운영 배선에는 연결하지 않으며
나머지 34건도 실행하지 않았다.

이 결과는 현재 문제가 단순한 미회수 하나가 아님을 보여 준다. 불필요하거나 적용
범위가 다른 조문이 함께 회수되면 Haiku가 그것을 지배규범에 섞는 문제가 있고,
정확한 조문만 있어도 불명확한 문언을 확정적으로 포섭하는 문제가 함께 존재한다.

## 구현 구조

1. 동결된 전체 회수 조문을 inventory로 보존한다.
2. 원문을 줄·항·호 단위 clause card로 만든다.
3. 카드에 문서, 경로, 법원 종류, 규범 역할, 참조 표면형, 요건 종류를 붙인다.
4. Haiku가 `주체 → 행위 → 대상 → 조건 → 예외 → 효과` 명제표를 만든다.
5. 코드가 모든 rule과 conclusion의 실제 `E#:L#` 원문 좌표를 검증한다.
6. 검증된 명제표만 다른 Haiku가 답변으로 렌더링한다.

모든 모델 호출은 `claude-haiku-4-5-20251001`로 고정했고, 골든과 사례별 규칙은
제품 입력에 넣지 않았다.

## 입력 구조 수정

스모크 과정에서 두 가지 결정론 입력 버그를 수정했다.

- 모든 회수 조문에 대표 카드를 강제하여 핵심 조문의 하위 호가 밀리던 문제:
  전체 목록은 inventory로만 보존하고, 첫 착지 조문 전체와 질문 관련 단서·배제·
  준용 블록을 카드 예산에서 우선하도록 변경했다.
- 상위 관의 `<신설 2001.7.24>`가 제341조의4 연혁으로 오인되던 문제:
  감사 artifact에는 원값을 남기되 Haiku 입력에는 날짜를 가리고
  `상위 경로 연혁—해당 조문 연혁 아님`만 전달했다.

28개 단위·회귀 테스트와 `py_compile`, `git diff --check`가 통과했다.

## 성능

### 대표 실패 5건

- 첫 구현: baseline 1/5 → compiler 3/5
- 카드 배분 수정 후 반복: 1/5 → 3/5
- 동일 구조 다음 반복: Haiku 생성·채점 변동으로 자동점수 0/5

마지막 반복의 `cm-045` 답변은 원문상 정확했으나, Haiku 채점기가 기준답변보다
상세하다는 이유로 false를 낸 사례가 포함된다. 따라서 5건 점수 자체보다 같은
입력에서도 포섭과 채점이 흔들린다는 관측이 중요하다.

### 동결 개발 17건

| 지표 | 결과 |
|---|---:|
| baseline | 7/17 |
| compiler | 7/17 |
| 신규 정답 | 2 |
| 신규 회귀 | 2 |

| 유효 compilation | 15/17 |

기존 답변 생성 p50 약 5.6~5.8초보다 훨씬 느리고, 정확도 순증도 없다.

## 사례 진단

### 개선: `cm-036`

외부감사법은 내부회계관리자를 상근이사 또는 그 업무집행자로 규정할 뿐
`등기임원`을 명시적으로 요구하지 않는다. 컴파일러가 주체 자격과 명시 요건을
분리하여 기존의 등기임원 단정을 고쳤다.

### 개선: `cm-045`

제341조의4 본문 전체를 첫 착지 조문으로 보존하고 상위 경로 연혁을 가린 결과,
1년 내 소각의무, 5가지 예외, 매년 주주총회 승인, 보유처분계획 기재사항을 정확히
복원했다.

### 회귀: `cm-009`

질문 대상 조문의 면제사유와 별도 시행세칙의 다른 예외를 한 목록으로 합쳤다.
이는 회수된 보조 조문의 법적 연결 역할이 `지배규범의 직접 예외`인지 단순 문맥인지
타입으로 고정되지 않은 문제다. 잘못 회수된 자료가 답을 오염시키는 실제 사례다.

### 회귀: `cm-033`

문언의 `최초의 사업연도`가 연결기준 전환 법인에 적용되는지 해석상 불명확한데도
60일 제출기한을 확정했다. 이는 정답 조문 회수와 무관한 순수 포섭·해석 과잉이다.

## 판단

현재 오류는 다음 두 축이다.

1. **근거 정밀도·역할 문제**: 적용범위가 다른 보조 조문을 지배규범의 예외로 섞음.
2. **법률 포섭 문제**: 명확하지 않은 주체·시점·용어 관계를 확정하거나, 명확한
   `각각`·주체 한정을 불필요하게 유보함.

따라서 `50/51 골든 조문 회수`만으로는 충분하지 않다. 조문이 포함되었다는 recall과
그 조문이 이번 질문에서 `지배·정의·직접 예외·간접 참고` 중 무엇인지는 별도다.

## 사용 가능한 범위

컴파일러를 최종 답변 덮어쓰기에는 쓰지 않는다. 다음 shadow 신호에는 사용할 수 있다.

- 기존 답과 명제표 결론이 반대인 사례 수집
- 주체 한정, 예외, 시점, 수치가 기존 답에서 빠진 사례 표시
- 둘 이상의 문서군 규칙이 하나의 결론에 섞인 사례 표시
- 상위 경로 연혁을 조문 연혁으로 복사한 사례 표시
- 명제 결론에 실제 원문 좌표가 없는 사례 차단

다음 구현 우선순위는 LLM 프롬프트가 아니라 **타입이 붙은 근거 간선**이다. 최초
착지 조문에서 보조 조문으로 이동한 경위를 `직접 예외·배제·준용·위임·정의·단순
참고`로 코드가 고정하고, 명시적 간선이 없는 보조 조문은 결론 규칙으로 승격하지
못하게 해야 한다.

## 타입 근거 간선 51건 감사

동결된 51건 회수 결과에서 문서 내·문서 간 조문 참조 간선을 재구성하고,
각 근거를 세 단계로 분류했다.

- `A_governing`: 첫 착지, 질문이 명시한 조문, 배제·준용·위임·근거·정의로
  직접 연결된 조문
- `B_candidate_support`: 단순 직접 인용, 구조 검색 착지, 질문과 조문 제목이
  강하게 일치하는 후보. 원문의 주체·행위·대상·시점을 검토한 뒤에만 사용
- `C_context_only`: 간접 인용, supplemental closure, 평행 키워드 문맥

| 지표 | 결과 |
|---|---:|
| 선택 조문 | 808 |
| A | 199 (24.6%) |
| A+B | 441 (54.6%) |
| C로 강등하는 조문 | 367 (45.4%) |
| 골든 선택 | 69/70, 50/51건 |
| A만의 골든 보존 | 45/70, 31/51건 |
| A+B의 골든 보존 | 69/70, 50/51건 |

엄격한 A 필터는 선택 문맥의 75.4%를 줄이지만 골든도 25개 잃으므로 안전하지
않다. A+B는 회수된 골든을 모두 보존하면서 45.4%를 문맥 전용으로 강등했다.
그러나 이 기준도 동일한 51건에서 확인했으므로 미관찰 법률 질문에서 검증해야 한다.

`cm-031`은 골든인 코스닥시장 상장규정 제5조가 선택되지 않은 유일한 실제 회수
누락이다. 유가증권시장 시행세칙 제5조만 첫 착지로 들어와 후단 라우터로는 복구할
수 없다.

## 3단계 Haiku shadow 스모크

오염 반례와 첫 착지 실패를 포함한 6건에서 A+B 정책을 Haiku 명제 컴파일러에
적용했다. 모든 생성과 채점은 `claude-haiku-4-5-20251001`만 사용했다.

- baseline 0/6 → candidate 0/6
- 수정 채택 0건, 모두 보수 가드로 기존 답변 유지
- 제품 호출 6회, 입력 145,743 tokens, 출력 10,401 tokens
- p50 15.381초, p95 16.720초

회귀를 막는 안전 가드로는 의미가 있지만, 현재 구조는 정확도 향상값이 0이고 지연이
크다. 따라서 A+B 분류도 운영 배선이 아니라, 새 평가셋에서 검증할 shadow 신호로만
남긴다.
