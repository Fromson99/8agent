# 가이드 조사 루프 (D1)

기준: MAIN181 (`definition-priority-20261109-r1`), 2026-11-09. 코드를 직접 읽어 정리했으며 실행 추적은 하지 않았다. 설명은 `수정사항.md`의 결정(자료 구분은 GENOS에서 준 값, 과거 기록 후보 없음)을 반영한 기준이다.

## 한 줄 요약

첫 검색이 끝난 뒤, **모델이 "다음에 무엇을 할지" 하나를 고르고 서버가 그것을 실행하는 일을 반복**하며 원문을 모으는 단계다. 모델은 메뉴를 보고 고르기만 하고, 원문을 실제로 찾고 읽는 것은 서버다. 정해진 한도에 닿거나 모델이 답변을 고르면 멈추고 답변 단계(E1)로 넘어간다.

## 언제 실행되나

- 현재 현장 설정이 가이드 모드다(`profile-unified-v6.json`: `guided_loop: true`, `answer_presentation: guided-conversation-v1`).
- 일반 질문에서만 쓴다. 대사 워크플로우의 하위 조사에서는 쓰지 않는다(`guided_navigation.enabled`).
- 순서: 첫 요청 분류(B1) → 첫 검색(C) → **가이드 조사 루프(D1)** → 가이드 답변(E1).

## 한 바퀴의 흐름

```
① 서버가 메뉴를 만든다 (읽을 후보, 연결 대상, 검색 도구, 지금까지 읽은 원문 등)
② 모델이 행동 하나를 고른다 (모델 호출 1회)
③ 서버가 그 행동을 실행한다 (원문 읽기·연결 조회·검색)
④ 한도·멈춤 조건을 확인하고 ①로 돌아가거나 멈춘다
```

코드: `law_navigation.py`의 `Investigation.run` 반복문이 ①~④를 돈다. 가이드 모드 전용 지침·메뉴 변환·한도는 `guided_navigation.py`와 `law_navigation.py` 끝부분(`guided_limit_state` 등)에 있다.

## 세부 기능

### 1. 루프 시작 전 (모델 호출 0)

| 기능 | 하는 일 |
|---|---|
| 첫 원문 미리 읽기 | 질문이 지목한 조문, 정의 질문이면 정의 조문 등 첫 검색 결과에서 바로 읽을 원문을 읽어 둔다(`definition_entry.acquire_initial`). 정의 질문이 아니면 정의 미리 읽기는 보류(MAIN181) |
| 이어서 읽기 | 직전 답변이 "이 조문을 이어서 읽어볼까요?"라고 제안했고 사용자가 이어서 하라고 했으면, 그 위치를 검색·모델 호출 없이 바로 읽는다(`preread`) |

### 2. 모델이 고르는 행동 (다섯 가지)

| 행동 | 뜻 | 한도 차감 |
|---|---|---|
| `READ` | 메뉴의 읽기 후보 중 필요한 본문을 읽는다. 한 번에 최대 4개까지 같이 고른다 | **차감 없음** |
| `FOLLOW` | 읽은 조문의 연결(인용·준용 등)을 따라간다 | 차감 |
| `SEARCH` | 문서·조문·제목으로 구조를 찾거나 본문 검색, 목록 페이지 이동, 다른 문서 열기 | 차감 |
| `ASK_USER` | 대상·사실이 불명확하거나 판단이 엇갈려 사용자가 방향을 골라야 할 때 묻는다(최대 2문항). 질문 종류: 사실(FACT)·조사 대상(SCOPE)·자료(SOURCE)·해석 선택(DECISION) | — (루프 멈춤) |
| `ANSWER` | 확보한 원문으로 답할 수 있거나 조사를 마칠 때 | — (루프 멈춤) |

지침의 핵심 규칙(`guided_navigation.PROMPT`):
- 위치가 확인된 후보가 질문에 필요하면 "읽어볼까요?"라고 묻지 말고 바로 READ한다.
- 미리보기는 근거가 아니다. 확보한 원문은 이번 조사에서 READ·FOLLOW로 실제 읽은 것뿐이다.
- 질문에 가장 필요한 대상부터 읽는다. 한도 때문에 미리 묻지 않는다(한도에 닿으면 확보한 원문으로 답하고 사용자가 이어서 요청할 수 있다).
- 이전 질문·답변 기록은 같은 조사를 이어가는 데 쓰지만, 과거 모델 의견을 정답이나 원문으로 쓰지 않는다.

### 3. 모델에게 보여 주는 메뉴

| 항목 | 내용 |
|---|---|
| 읽기 후보 | 검색·연결로 위치가 확인된 미열람 조문(미리보기 포함, 근거 아님), 페이지 이동 가능 |
| 읽은 원문 | 이번 조사에서 확보한 조문 본문 |
| 연결 | 읽은 조문이 인용하는 조문, 거꾸로 인용하는 조문. 연결 성격 표시(구체화·특칙/예외·준용·차용·경과) |
| 같은 절 조문 | 읽은 조문과 같은 절의 조문 제목 목록(본문 아님) |
| 같은 절 제목 일치 | 같은 절에서 제목에 질문 단어가 들어간 조문(최대 8개) → 바로 읽기 후보로 제시 |
| 같은 장 제목 일치 | 같은 장의 다른 절에서 제목에 질문 단어가 들어간 조문(최대 24개). 예: 상법 제368조(보통결의)와 제434조(특별결의)처럼 서로 인용하지 않는 관련 규정 |
| 검색 기록 | 실제로 쓴 검색어와 범위 |
| 약칭 | 검색어 속 이름이 원문에서 무엇을 가리키도록 선언됐는지(예: 외감법 = 「주식회사의 외부감사에 관한 법률」) |
| 남은 행동 수 | 이번 요청에서 남은 검색·연결 조회 횟수 |
| 대화 기록 | 이전 질문·답변·행동, 직전 답변이 제안한 이어서 읽기 |

### 4. 서버가 자동으로 하는 읽기 (모델 호출 0)

| 기능 | 하는 일 |
|---|---|
| 연결 자동 읽기 | 연결을 조회하면 정방향 연결 최대 6개, 역방향 중 구체화·특칙/예외 최대 3개를 자동으로 읽고, 그 조문의 정방향 연결 1단계를 더 읽는다(요청당 12,000자). 준용·차용·경과 역방향은 개수만 알린다 |
| 같은 절 자동 읽기 | 10조 이하 절에서 절 제목 핵심어가 모두 든 조문 최대 2개를 자동으로 읽는다 |
| 미확인 연결 기록 | 읽지 않은 연결은 출발 조문·관계·읽지 않은 이유와 함께 남겨, 답변 끝 "미확인 조문" 안내와 다음 턴 이어서 읽기에 쓴다 |

### 5. 한도와 멈춤

현재 설정(`profile-unified-v6.json` `candidate_navigation`):

| 설정 | 값 | 뜻 |
|---|---|---|
| `guided_action_limit` | 6 | 한 요청에서 검색·목록 이동·연결 조회 횟수 |
| `guided_reads_free` | true | READ는 위 횟수에서 빼지 않는다 |
| `guided_read_rounds` | 4 | 한 요청에서 READ 결정 횟수 상한(한 번에 여러 개 가능) |
| `guided_answer_read_rounds` | 6 | 답변 단계가 "이것도 읽어야 한다"고 고른 위치를 다시 읽는 횟수 |
| `guided_section_title_matches` | true | 같은 절·같은 장 제목 일치 후보 제시 |

한도에 닿았을 때:
- 검색·연결 조회 6회를 다 쓰면 **읽기 전용** 상태가 된다. 이때는 이미 위치를 찾은 원문 READ와 ANSWER만 실행한다. 모델이 새 검색을 고르면 실행하지 않고 멈춘다. 읽을 후보가 없으면 모델을 부르지 않고 멈춘다.
- READ 결정 4회를 다 쓰면 멈춘다.

멈춤 사유(모두 오류가 아니라 "여기까지 확보한 원문으로 답하고 사용자가 이어서 요청할 수 있음"으로 처리한다. 확보한 원문은 그대로 답변에 넘어가며, 못 찾은 것을 "없다"고 단정하지 않는다):

| 사유 | 뜻 |
|---|---|
| `GUIDED_ACTION_LIMIT` | 위 행동 한도에 닿음 |
| `USER_GUIDANCE_REQUIRED` | 모델이 ASK_USER를 고름 → 질문을 보여 주고 사용자 답을 기다림 |
| `MODEL_PENDING` | 모델이 보류를 고름 |
| `NO_PROGRESS` | 새로 읽은 원문·판단 없이 같은 상황이 정해진 횟수만큼 반복 |
| `NO_ANSWER_PROGRESS` | 답변 진척 없음 |
| `INVESTIGATION_BUDGET` | 요청 전체의 모델 호출 예산이 답변에 쓸 몫만 남음 |
| `FINALIZATION_TIME_RESERVE` | 남은 시간이 답변에 쓸 몫만 남음 |
| `MODEL_DECISION_UNRESOLVED` | 모델 선택이 형식·조건에 맞지 않아 보완 후에도 실행할 수 없음 → 확보한 원문이 있으면 그것으로 제한 답변 |

### 6. 답변 단계와의 왕복

- 루프가 멈추면 가이드 답변(E1)이 확보한 원문으로 설명과 추가 질문을 쓴다.
- 답변이 "이 위치도 읽어야 한다"(`next_reads`)고 고르면, 서버가 **같은 요청 안에서** 루프로 돌아가 그 위치를 검색·모델 호출·차감 없이 읽고 답변을 다시 쓴다(`forced_reads`, 최대 6회).
- 답변이 "○○법 제N조를 확인해야" 하고 남긴 조문도 서버가 찾아 읽는다(MAIN181).

## 가이드 모드에서 쓰지 않는 것

- 조사 감독(`investigation_supervisor.py`): 가이드 모드에서는 꺼진다(`enabled`가 가이드 모드면 false). 별도 감독 모델 호출 없음.
- 판단 이유-결정 검토(`reason_decision_review.py`): 가이드 모드에서는 생략.

## 수정할 때 주의

- 지침(`guided_navigation.PROMPT`)을 바꾸면 모델의 행동 선택이 바뀌므로 실모델 실험으로 확인한다.
- 한도 값은 프로필(`profile-unified-v6.json`)에서 바꾼다. 행동 한도는 0~40만 허용된다(0이면 한도 없음).
- 같은 장 제목 일치처럼 문서 구조를 넓게 훑는 기능은 Oracle에서 1만 행 한도에 걸릴 수 있다. 바꾸면 Oracle 규모 점검을 통과해야 MAIN에 반영한다.
- 파일을 바꾸면 `02_BACKEND/ENGINES/` 해시 고정값을 다시 만들고 `main_release.py`로 반영한다.
