## 1. 화면 접두어 분리 제거 → GENOS에서 준 값으로

### 현재 상황 (MAIN181)

GENOS 화면의 mode 값은 따로 전달되지 않고, **질문 글자 앞에 붙은 접두어로 전달**된다.

1. GENOS 화면 드롭다운이 mode 값을 준다(`applied_fields.mode`: 전체 법령 / 내규 / 외규 / 대사 / 문서 대사).
2. 워크플로우(`08_DEPLOYMENT/GENOS/workflow/genos_rag_chat.py` `_selected_question`)가 그 값을 질문 앞에 `내규: ` 처럼 **붙여서** 보낸다. mode가 비어 있으면 붙이지 않는다.
3. 백엔드는 매번 질문 글자에서 접두어를 **다시 떼어 내** 자료 구분으로 바꾼다(`pipeline.py` `route_question`).

#### 멀티턴에서 지금 접두어가 하는 일

| 상황 | 지금 동작 | 코드 |
|---|---|---|
| 첫 질문 | 접두어로 자료 구분을 정하고, 그 구분의 문서만 범위에 남기고, 모델에게는 접두어를 뗀 질문을 준다 | `request_entry.py`, `pipeline.py` `plan` |
| 후속 질문 — 새 질문·목적 변경·검색 다시 하기 | 모델 결정을 검사하기 **전에** 접두어 값으로 자료 구분을 덮어쓴다. 모델이 "그대로"를 골라도 사용자가 바꾼 mode가 적용된다 | `corrected_memory.py` 498행, `case_repository.py` 141행 |
| 같은 대화에서 mode를 바꾼 경우(예: 내규 → 전체) | 바뀐 자료 구분을 조사 상태에 먼저 넣어, 이전 범위로 한 조사 결과를 버리고 다시 조사한다 | `unified_rag.py` `scope_state` |
| 문서 목록 요청 | 접두어로 목록의 자료 구분을 거른다 | `case_repository.py` 194행 |
| 이전 질문 목록을 모델에게 보여 줄 때, 되묻기 문구 | 저장된 원문에서 접두어를 떼고 보여 준다 | `corrected_memory.py` 557·721행 |
| 대사·문서 대사 | `대사:`·`문서 대사:` 접두어로 워크플로우를 고른다 | `workflow/contracts.py` `route`, `chat_adapter.py` |
| 접두어가 없는 후속 질문(mode 미선택) | 자료 구분은 이전 상태를 그대로 쓰거나(모델이 "그대로" 선택), 모델이 질문 글을 보고 정한다 | `corrected_memory.py` |

#### 문제

- mode가 **질문 글자 안에만** 있다. 대화 기록에도 접두어가 붙은 원문으로만 저장되고, mode를 따로 저장하지 않는다.
- 그래서 백엔드의 접두어 분리만 지우면 mode가 아예 전달되지 않는다. 이전 턴의 mode도 알 수 없다.
- 같은 접두어 해석이 14곳에 흩어져 있다.

### 바꾸는 방법 (제안)

**① 전달: GENOS에서 준 값을 그대로 보낸다**
- 워크플로우는 질문을 건드리지 않고, 요청 본문에 `mode` 필드로 GENOS 값을 그대로 넣는다(미선택이면 넣지 않음).

**② 해석: 요청이 들어올 때 한 곳에서만**
- 요청 입구에서 `mode`를 한 번 읽어 자료 구분(전체 법령 → ALL, 내규 → internal, 외규 → external) 또는 대사 워크플로우로 바꾸고, 요청 정보에 담아 아래 단계로 넘긴다.
- 지금 `route_question`을 부르는 14곳은 질문 글자 대신 이 값을 받는다.
- 첫 요청 분류의 "접두어는 문서명이 아니다" 지침과 검사(`validate_source_marker`)는 지운다.

**③ 멀티턴 규칙 — 지금 동작을 그대로 유지**

| 상황 | 규칙 |
|---|---|
| 이번 턴에 GENOS가 mode를 줌 | 그 값이 이번 턴의 자료 구분. 모델 판단보다 우선한다 |
| mode가 이전 턴과 다름 | 이전 범위로 한 조사 결과를 버리고 새 범위로 다시 조사한다 |
| 이번 턴에 mode가 없음 | 이전 턴의 자료 구분을 그대로 쓴다. 대화의 첫 질문이면 전체(ALL) |
| 대사·문서 대사 | mode 값으로 워크플로우를 고른다(지금도 `workflow_id`로 고르는 길이 있음) |

**④ 저장: 요청마다 mode를 함께 저장**
- 대화 기록에 질문 원문과 그 턴의 mode를 따로 저장한다.
- 이전 질문 목록이나 되묻기 문구에는 원문을 그대로 쓰면 된다(접두어 떼기 불필요).
- 이전 턴의 mode는 저장된 값으로 안다.

**⑤ 옛 기록 호환**
- 이미 저장된 대화의 요청 원문에는 접두어가 붙어 있다. 옛 기록을 읽을 때만 쓰는 호환 함수 하나를 남겨, 저장된 mode가 없는 옛 요청에서만 접두어를 해석한다.

### 정해야 할 것

- **mode가 없을 때 모델이 질문 글을 보고 자료 구분을 정하게 둘지.** 지금은 질문에 "내규에서 찾아줘"라고 쓰면 모델이 internal로 정할 수 있다. GENOS 값만 쓰기로 하면 모델의 자료 구분 판단을 빼고, 위 ③ 규칙만 남긴다.
- 사용자가 질문에 직접 `내규:`를 쳐도 이제는 그냥 질문 글자로 취급된다. 이 동작이 맞는지.
- GENOS 화면이 턴마다 mode 값을 유지해서 보내는지, 사용자가 바꿀 때만 보내는지(현장 화면 동작 확인).
- 워크플로우 파일이 바뀌므로 코드 적용과 별도로 **GENOS 워크플로우 편집기에도 붙여 넣어야** 한다.

## 2. 과거 기록 후보 제거

### 현재 상황 (MAIN181)

- 질문마다 비슷한 과거 질문 기록을 모델에게 보여 주고, 모델이 최대 2개를 골라 조사 출발점으로 쓴다(`history_ids`). 기본 켜짐.
- 첫 요청 분류와 후속 질문 판단 두 곳에서 쓴다.

### 바꿀 곳

| 위치 | 지금 | 바꿀 내용 |
|---|---|---|
| `legal_agent/request_entry.py` | 후보 제시·선택(`offer`, `augment`, `choose`), 지침, `history_ids` | 삭제 |
| `legal_agent/wiki_execution.py` | 후속 질문 판단 때 후보 제시(13~19행), 고른 기록 사용(96~98행) | 삭제 |
| `legal_agent/shortcut_repository.py` | 답변 저장 때 후보 색인 기록 | 삭제 |
| `lawrag/pipeline/unified_memory.py` | 후보 색인 다시 만들기 | 삭제 |
| `legal_agent/wiki_recall.py` | 기능 본체 | 파일 삭제 |
| `00_SYSTEM/PIPELINE.json`, `unified_runtime.py` | 켜고 끄는 설정(`bounded_recall`) | 삭제 |

### 주의

이 기능을 끄면 대신 동작하도록 만들어 둔 **이전 방식**이 있다(과거 질문 목록 안내, 저장된 조사 절차 다시 실행). 지금 설정으로는 이 이전 방식이 켜진 상태라, 이 기능만 지우면 이전 방식이 다시 동작한다. 함께 끄거나 지운다.
