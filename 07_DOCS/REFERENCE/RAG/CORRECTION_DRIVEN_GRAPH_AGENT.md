# 교정을 재사용하는 온톨로지 탐색 에이전트 — 설계 제안

2026-09-08 사용자 요구를 기록한다. 상태: **설계 제안, 미구현·미배포**.
기존 의미 정본은 `00_SYSTEM/LEGAL_SCHEMA.json`과 `legal-semantic-v2`다.
이 문서는 별도 스키마·승인 기록·실험 성공 선언이 아니다.

## 1. 설계의 기준

시스템은 처음에는 틀릴 수 있다. 그러나 근거와 적용 범위를 검증한 교정은
다음 동일 조건의 탐색·설명에 실제로 적용되어야 한다. 교정을 프롬프트에 적어 두는
것으로 끝내지 않고, 지식 수정과 실행 제약, 재발 방지 테스트로 연결한다.

지식그래프는 특정 분야의 정답만 보관하는 닫힌 사전이 아니다. 수집·사용 권한이 있는
원문 전체를 주소화하고 개념·명제·규칙·단서·근거·문서 간 연결을 표현하는 기반이다.
온톨로지는 그 공간의 타입·관계·제약을 정의하며, 질의별 탐색 경로와 인덱스가 이를
이용해 작은 부분 그래프부터 찾는다. 아직 의미를 추출하지 못한 원문도 검색 가능해야 한다.

‘모든 공간을 span’한다는 말은 미수집 정보까지 안다거나 모든 해석이 완성됐다는 뜻이
아니다. 미수집·미모델링·미확인·상충 상태를 구분하고 확장 가능한 구조를 뜻한다.
검색 실패는 법적 부존재가 아니며, 특정 온톨로지 경로가 실패해도 다른 허용 경로는 남긴다.

## 2. 조회 흐름

1. 질문을 쟁점·사실·표현·시점·문서 범위로 분해한다. 모델의 분해는 후보이며 정답이 아니다.
2. 승인된 교정/검색 shortcut의 범위·버전·근거·권한을 검증한다.
3. 용어의 의미 후보와 직접 조문 좌표를 출발점으로 삼는다. 범위가 다른 동음이의 개념을 합치지 않는다.
4. 본문·정의·기본 규칙·조건·단서·위임/참조 관계를 따라 필요한 근거 묶음을 조립한다.
5. 부족한 항목을 분류한다. 사용자 사실 부족은 질문, 본문 근거 부족은 원문/인접 관계 탐색,
   법적 표현의 의미 미해결은 조건부 판례 검색/원문 확인으로 보낸다.
6. 판례의 정확한 원문 위치에서 얻은 법명/표현을 검색 힌트로 사용해 현재 법령을 다시 찾는다.
   판례의 구법 조문 번호를 현재법 정답으로 이식하지 않는다.
7. 출처·조건·예외를 검증한 근거로만 설명한다. 미해결은 드러내고 근거 없는 결론은 보류한다.

온톨로지 영역·유사도는 탐색 우선순위다. 사용자 범위·접근권한·금지 요청은 강제 경계다.
부분 그래프가 부족하면 허용 범위 안에서 인접 영역 및 원문 lexical/dense 검색으로 확장한다.
일률적인 top-k/고정 hop 때문에 필수 예외가 빠지면 ‘완료’가 아니라 미해결로 기록한다.

## 3. 교정이 남겨야 할 정보

다음은 요구 필드의 개념 설명이며 현재 존재하는 JSON 계약으로 가장하지 않는다.

| 항목 | 저장할 내용 |
|---|---|
| 교정 대상 | 실패 실행, 쟁점, 객체/필드, 잘못 선택한 의미 또는 경로 |
| 올바른 의미 | 해당 범위에서의 Concept/Rule/Clause 연결; 자유문장 정답 캐시 아님 |
| 필수 근거 | 문서 버전, 조문/블록/구간, 원문 hash, 검토 기록 |
| 적용 조건 | 법령·시점·쟁점·필수 사실·의미 구분·접근 범위 |
| 실행 제약 | 필수로 읽을 본문, 금지할 오연결, 근거 충족 시 생략할 판례 탐색 |
| 반례·무효화 | 유사하지만 다른 의미, 법 개정/근거 변경/충돌 시 재검토 조건 |
| 검증 사례 | 원래 실패 질문, 표현 변형, 적용되지 않아야 하는 반례 |

예를 들어 ‘표현 X는 이 범위에서 본문 Y로 해결된다’는 교정은
‘X가 나오면 어떤 질문에서도 판례를 금지한다’가 아니다.
본문 Y를 다시 읽고 현재 쟁점이 해결됐다는 조건이 충족될 때만 해당 쟁점의 판례 경로를 생략한다.
다른 쟁점이나 다른 사실관계에 대한 필요한 판례 탐색을 막지 않는다.

## 4. 실행 제약과 지식의 분리

- **법률 지식:** Concept/Mention/Clause/Rule/Proviso/LegalRelation/Evidence를 정본에서 재사용한다.
- **조회 제약:** 어떤 도구를 언제 호출/생략하는지는 control-plane 정책으로 둔다.
  ‘판례 호출 금지’를 법률의 금지 Rule로 저장하지 않는다.
- **근거 충족 기록:** 어떤 쟁점의 어떤 필수 슬롯을 무엇으로 충족했는지 추적한다.
  구조적으로 슬롯이 찼다는 사실을 법률적 완전성으로 승격하지 않는다.
- **학습 경로:** Feedback → 진단/수정 후보 → 원문·범위 검토 → 회귀/분리 평가 → 승인 → 새 release.
  교정자의 말만으로 정본을 덮어쓰지 않으며 상충하는 교정은 심사 대상으로 남긴다.

같은 대화 안에서는 교정을 사용자 제공 제약/가설로 명시해 즉시 고려할 수 있다.
다음 세션·다른 사용자·일반화된 질문에 재사용하려면 승인된 범위와 버전 계약을 통과해야 한다.

## 5. 기존 객체와의 대응 및 부족한 연결

- `legal-semantic-v2`: 개념·문맥별 명제·조건·단서·원문 근거를 재사용한다.
  Concept.aliases의 문자열 배열만으로 문맥별 의미 교정을 해결하려 하지 않는다.
- `FeedbackChange`: 객체/필드/근거를 지정한 제안에 사용한다. 자동 정본 갱신 기능이 아니다.
- `query-shortcut-v2`: 승인된 질문 signature와 세대가 일치할 때 검증된 착지점을 재사용한다.
  답변을 외우지 않으며, 유사도만으로 다른 질문에 강제 적용하지 않는다.
- DefinitionProjection: 여러 질문에 재사용하는 범위 제한 판단 경로라는 설계 취지를 따른다.
  현재 legacy projection의 READY를 일반적인 의미·규칙 완전성으로 간주하지 않는다.
- 새로 연결할 부분: 교정의 의미/경로 진단, 조건부 실행 제약, 근거 충족 검사,
  영향받는 투영/인덱스의 재구축·무효화, 다음 실행에서의 강제 적용 및 감사.

현재 `02_BACKEND/semantic_runtime/feedback.py`는 EVENT/PROPOSAL을 남기지만
`semantic_feedback`와 `proposed_artifact`는 null이다. 이 경로만으로 지속적인 교정 적용이
완성됐다고 할 수 없다. 별도 `lawrag/feedback/shortcuts.py`의 세대/권한 검증 부품은 재사용 대상이다.

## 6. 역할 분리

| 역할 | 책임 |
|---|---|
| Query Interpreter | 쟁점·사실·시점·표현의 후보 해석 |
| Ontology Navigator | 교정 및 개념/관계 기반의 출발점·부분 그래프 탐색 |
| Evidence Planner | 부족한 항목별 다음 도구 결정; 판례는 조건부 도구 |
| Grounded Writer/Verifier | 근거·조건·예외를 보존한 설명과 주장별 검증 |
| Correction Compiler | 피드백을 지식 수정 후보·실행 제약·테스트로 변환 |

모든 역할을 별도 LLM sub-agent로 띄울 필요는 없다. 버전·권한·근거 구간·호출 금지 같은
강제 조건은 코드가 검사하고, 의미 해석과 다음 조사 가설에만 모델을 사용한다.
제품 경로의 모든 모델 역할은 저장소 정책상 `claude-haiku-4-5-20251001`을 사용한다.

## 7. ‘다음에는 틀리지 않음’의 검증 가능한 정의

- 등록된 같은 조건/버전의 교정 사례는 필수 근거·의미 연결·도구 제약을 만족해야 한다.
- 이 등록 사례에서 재발하면 새 release를 막는다. 단순히 LLM이 기억하길 기대하지 않는다.
- 표현 변형 및 별도 표본으로 일반화를 평가하되, 범위 밖 반례에 교정이 새 오류를 만들지 않아야 한다.
- 근거가 바뀌면 기존 교정을 stale로 만들고 재탐색한다. 충돌/미해결이면 확인 없이 단정하지 않는다.
- 자연어 전체와 모든 미래 사실관계에 무오류를 보장할 수는 없다. 보장 가능한 실행 제약과
  측정해야 할 의미/설명 정확도를 구분한다.

관련 관찰: ADR0275는 기존 조문 recall61/112를 유지했으나 미해결 용어2건 모두 판례 읽기 뒤
실제 조문 확장으로 연결하지 못했다. 이 기록은 교정 학습 계층의 성공 증거가 아니다.
후속 구현·실험은 새 ADR에서 사전 동결하며 이 설계 제안만으로 MAIN을 변경하지 않는다.
