## 멘탈 모델 3가지
1. **모든 것은 "리비전 → 배포 → 컨테이너"**. 코드/설정의 버전(리비전)을 만들고, 배포하면 쿠버네티스 Pod로 뜬다.
2. **서비스는 인증·승인 뒤에 있다**. 배포/중지는 결재(운영>승인, 권한 있으면 자체승인 — 모달 버튼 "예"), 외부 호출은 인증키+게이트웨이.
3. **LLM은 "서빙"으로 붙인다**. 플랫폼 관리 모델 서빙에 연결하면 raw API 키 없이 사용.

## 3대 배포 단위
| 단위 | 무엇 | 진입점 | 용도 |
|---|---|---|---|
| 코드서빙 | 임의 Python → HTTP API | `async def service(config, data)` | 로직 서비스. 게이트웨이 `POST /api/gateway/code_serving/{id}/json` + Bearer 인증키. **V1.8.6 실측(9/1): `/json`이 아니라 FastAPI 경로가 그대로 프록시된다** — `…/code_serving/{id}/chat` |
| 워크플로우 | 단계(step) 파이프라인 | Python 단계 `async def run(data)` / Flowise 단계 | 채팅형 서비스. **응답 규약이 버전마다 정반대 — 아래 ★ 참조** |
| (모델) 서빙 | LLM·임베딩 추론 엔드포인트 | — | 내부 LLM 제공. 워크플로우 노드가 붙음 |

우리 패턴: **코드서빙(판정 로직) + 워크플로우 Python 단계(채팅 브릿지+스트리밍) + 채팅 앱(사용자 화면)** 2층 구조.

## ★ GenOS에는 **런타임 코드 공유가 없다** — 모듈화의 상한선 (2026-09-05)

과제 간 공통 로직을 "한 벌 두고 여러 과제가 import"하는 구조는 **플랫폼이 지원하지 않는다.**
근거 4가지 (9/5 모듈화 기획안 작성 중 정리):

| 사실 | 뜻하는 것 |
|---|---|
| **코드서빙 저장소가 서로 격리** | 과제 A의 코드서빙이 과제 B의 코드를 참조할 수 없다 |
| **패키지 레지스트리 없음** | 사내 배포용 공통 라이브러리를 올려 두고 `pip install`로 당겨 쓸 자리가 없다 (사내 Nexus 미러는 **외부 PyPI 대용**이지 우리 패키지 게시처가 아니다 — [필드노트](https://github.com/infoczAI/agent8/blob/7b42bc4cbf9b7ccef6dfea522d20370cedb237ce/docs/field-notes/2026-09-02-nexus-pip-installs.md)) |
| **워크플로우 = 단일 파일** | Python 단계는 콘솔에 붙여넣는 한 덩어리라 공통 모듈로 쪼갤 수 없다 |
| **CI 없음** | 공통 코드를 고쳤을 때 소비 측 과제들을 자동 검증할 파이프라인이 없다 |

⇒ **결론: GenOS에서 "모듈화"는 런타임 재사용이 아니라 `표준 계약 + 템플릿`이다.**
같은 인터페이스 규약(입출력 스키마·에러 규약·env 이름)을 정해 두고, 구현은 과제별로 **복제해서**
가져가는 형태가 이 플랫폼에서 가능한 최대치다. 8/26 김수석의 "재사용성 있게 module화" 요청
([`../project/overview.md`](https://github.com/infoczAI/agent8/blob/7b42bc4cbf9b7ccef6dfea522d20370cedb237ce/docs/project/overview.md) §6)에 대한 답도 이 선을 전제로 잡아야 한다.

> 적용: 9/5 모듈화 기획안은 고객 매트릭스 **5개 엔진유형**(문서비교 3 · RAG 2 · 체크리스트 1 ·
> 문서생성 1 · NL2SQL 1)을 축으로, 이 제약 위에서 스코프를 현실화했다.
> 출처는 조동국 9/5 온사이트 로그 + 노션 모듈화 페이지(저장소에는 요약만).
> ⚠️ 위 4가지는 **현장 관찰 기반 정리**이고 콘솔에서 반증 실험을 돌려 본 것은 아니다.

## 코드서빙 배포 7단계
생성(내장 Git repo 생김) → 코드 push → 리비전(도커+커밋) → 환경변수 주입(LLM_* 등; **배포 중 리비전은 잠김 — 미배포에서**) → 배포+자체승인 → **트래픽 100%**(안 하면 옛 리비전으로 감) → 인증키 발급·게이트웨이 호출.

## ★ 개발 루프는 배포를 거치지 않는다 — 코드 스페이스에서 진입점 직접 구동 (2026-09-06, 과제2·7)

위 7단계를 **한 줄 고칠 때마다** 다시 서면 개발이 안 된다(리비전→배포→승인→기동). 그래서 과제2·7이
같은 해법을 브랜치에 넣었다 — **코드서빙에 올리지 않고, 코드 스페이스 안에서 진입점을 그대로 부른다.**

```text
[코드서빙 배포]  curl → 게이트웨이 → 컨테이너 → service(config, data)   ← 매번 리비전·배포·승인·기동
[코드 스페이스]  curl →   (건너뜀)  → devserve → service(config, data)   ← 같은 함수·같은 응답
```

- 게이트웨이가 하는 일은 **주소 라우팅과 토큰 검사뿐**이라, 우리 로직을 보는 데는 없어도 된다.
  한 줄 고치고 결과 보는 시간이 **수 분 → 수 초**.
- **코드 스페이스는 온프렘 안**이라 LLM·임베딩·벡터DB 게이트웨이는 **실제로 부른다** — `.env`에
  맥에서 쓰던 로컬 값이 아니라 **운영과 같은 값**을 적는다. `LLM=genos`·`EMBEDDER=genos`로 **못박을 것**
  (`auto`면 설정 하나가 비었을 때 조용히 다른 길로 샌다 — 임베딩 이식 함정과 같은 계열,
  [`../onprem/rag-quality.md`](https://github.com/infoczAI/agent8/blob/7b42bc4cbf9b7ccef6dfea522d20370cedb237ce/docs/onprem/rag-quality.md) 2순위).
- 라우트를 게이트웨이와 같은 `/json`으로 두면 **나중에 올려도 요청 몸통이 한 글자도 안 바뀐다**
  (주소와 `Authorization` 머리말만 붙는다).
- 구현체는 **표준 라이브러리만** 쓴다 — 사내망 PyPI가 막혀도 서버는 뜨고, 무엇이 없어 무엇을 못 하는지는
  부팅 자체 점검이 적어 준다(`boot.finished | ok=True … missing=['docling']`).
  질의만 볼 거면 설치할 것이 거의 없다(적재 의존성은 그때만).

**이 방식으로 확인되지 않는 것** — 여기까지 하려면 결국 한 번은 올려야 한다:

| | 코드 스페이스 | 코드서빙 배포 |
|---|---|---|
| 우리 로직·프롬프트·검색·적재 / GenOS 게이트웨이 호출 | 확인된다 | 같다 |
| 인증(Bearer)·게이트웨이 라우팅 / 워크플로우·채팅앱 배선·스트리밍 / 영속 볼륨·리비전 재배포 | **안 된다** | 여기서만 |
| 인스턴스 자원 한계(CPU 1 / 메모리 1Gi) | 다르다 — 코드 스페이스가 대개 더 넉넉 | 여기서만 |

⚠️ 마지막 줄이 사고를 낸다 — **코드 스페이스에서 잘 돌던 적재가 코드서빙에서 OOM으로 죽는다.**
무거운 적재를 올리기 전에 인스턴스 크기를 함께 본다.
⚠️ 토큰이 `.env`에 들어간다. 커밋은 안 되지만 **코드 스페이스 볼륨에는 남는다** — 자리를 뜰 때 지운다.
⚠️ SQLite 경로에 `{codeserving_id}` 자리표를 쓰면 코드 스페이스엔 그 번호가 없어 예외가 나거나
**내장 Git에서 번호를 주워 와 배포된 코드서빙과 같은 파일을 연다.** 비워서 이 스페이스 몫으로 떨어뜨린다.

## ★ 워크플로우 Python 단계 채팅 응답 규약 (하드런, 가장 중요) — **버전마다 정반대다**

**먼저 자기 환경의 버전을 확인하고 해당 블록만 따라라.** 반대 규약을 쓰면 둘 다 "판정은 성공하는데
채팅만 실패"로 나타나므로 증상만으로는 구분이 안 된다.

### 데모 v1.9.1 — async generator로 **yield**
- 채팅 앱은 SSE 스트리밍만 렌더. Python 단계가 값을 `return`만 하면 파이프라인 성공해도 채팅엔 "답변 생성 실패".
- 프레임워크(`run_util_v2.py token_stream()`)는 **yield한 항목을 `json.loads()`** 후 Flowise 어댑터로 넘김.
- **정답: async generator로 Flowise SSE 이벤트를 yield**
```python
yield json.dumps({"event": "token", "data": 조각}, ensure_ascii=False)  # 반복
yield json.dumps({"event": "end", "data": ""})                          # 종료
```
- 평문 문자열 yield ❌ (JSONDecodeError) / `sio_server.emit` 방식 ❌.

### 실환경 V1.8.6 — dict를 **return** (2026-09-01 실측)
- **정답: `run()`이 dict를 반환한다.** generator로 yield하면 `error_code 000200003`
  (`Workflow API Validate Response Failed: 응답에 데이터 또는 text/json 필드가 없습니다`).
```python
async def run(data):
    return {"text": report}     # ← 이게 전부
```
- 원인: 검증기가 **`run()`의 반환값**을 본다. generator 함수는 제너레이터 객체를 돌려주므로 그 안에
  data/text/json 필드가 없다 — **yield된 항목에 `data` 키가 있어도 소용없다.**
- ⚠️ **`run()` 안에 `yield`가 하나라도 남으면** 파이썬이 통째로 제너레이터로 만들어 `return`이 사라진다 → 같은 실패.
- 확인된 키는 **`text` 하나뿐**. `data`/`json`도 될 가능성이 있으나 미검증.
- ~~대가: 스트리밍이 아니므로 판정이 끝날 때까지 화면이 조용하다가 리포트가 한 번에 뜬다(과제6 최악 ~540s).~~
  **9/7 갱신: 대가는 없앨 수 있다** — dict 반환은 그대로 두고 소켓 emit을 **보조 채널**로 병행하면
  진행 상황·진행 블록이 뜬다(아래 §진행 단계). 판정 정확성에는 영향 없음.

### V1.8.6 — 진행 단계(“조리 단계”) 노출: dict 반환 + 소켓 emit **병행** (2026-09-07 실측 · **9/8 조건 5 추가로 완결**, 과제8)

dict 반환 규약은 "스트리밍을 못 한다"는 뜻이 아니었다. **답은 dict로 반환하면서, 진행 상황은
`sio_server.emit`으로 따로 밀어 넣는 것이 정답**이다(데모 v1.9.1의 "emit ❌"는 그 버전 얘기).
근거는 **현업 기존 오퍼링 서비스 워크플로우(사내 참조 구현)의 `run()` 대조 + 브라우저 DevTools 실측**.

- ⚠️ **emit은 워크플로우 런타임에서만 된다.** 코드서빙 컨테이너에는 `main_socketio`가 **없다**
  (`No module named` — 9/7 프로브로 확정). 그래서 코드서빙은 근거 데이터만 반환하고,
  **워크플로우 Python 단계가 그것을 진행 블록으로 재구성해 emit**하는 브릿지 구조가 된다
  (원본: `08-offering/genos/workflow_progress_bridge.py`, `fde/dongkuk/nltosql` 9/7).
- ★ **채팅 UI가 진행 블록을 렌더하려면 네 조건이 전부 맞아야 한다.** 하나라도 빠지면 소켓
  프레임은 정상으로 나가는데 화면에는 아무것도 안 그려진다(오류 없음 — 9/7에 넷을 하나씩 벗겼다):
  1. **답 텍스트를 `token`으로 청크 emit** — 이게 없으면 채팅이 **스트리밍 렌더 모드에 들어가지
     않아** 소켓 블록을 통째로 무시한다. dict로만 반환하면 진행 블록은 버려진다.
  2. **`agentFlowExecutedData` 항목마다 `nodeId` + `status:"FINISHED"`** — 이 둘이 없는 블록은
     렌더 조건에 걸리지 않는다.
  3. **`run()`의 최종 반환 dict에도 `agentFlowExecutedData`를 실어야 한다** —
     `{"text": …, "agentFlowExecutedData": blocks}`. 소켓으로 보낸 것과 **응답에 담는 것이 별개**다.
  4. **마지막에 `emit("end", "end", room=sid)`** — 채팅은 `end`를 받고서야 스트리밍 내용(토큰·블록)을
     최종 커밋·렌더하는 구조로 보인다.
  5. ★★ **블록 «모양»이 화이트리스트에 걸려야 한다 — `nodeLabel == "Visible Reasoner"` +
     `content == {"visible_rationale": <문자열>}`** (2026-09-08 실측, 사내 참조 구현 워크플로우
     **514의 `make_agentflow_payload` 렌더 대조**). **커스텀 `nodeLabel`·커스텀 `content`는 소켓으로
     프레임이 정상으로 나가도 UI가 그냥 무시한다**(오류 없음·워크플로우 종류 무관).
     ⚠️ **9/7의 1~4는 «필요조건이었지 충분조건이 아니었다»** — 넷을 다 맞춰도 안 그려지던 잔여 원인이
     이것이다. 즉 채팅 '추론' 패널은 **임의의 진행 블록을 그려 주는 범용 장치가 아니라,
     «Visible Reasoner»라는 한 가지 블록만 아는 전용 패널**이다.
     ⇒ 우리 단계를 띄우려면 **단계마다 사람이 읽을 문자열 하나(`visible_rationale`)로 눌러 담아
     Visible Reasoner 블록으로 위장**해야 한다(구조화된 dict를 그대로 실을 자리가 없다).
     원본: `08-offering/genos/workflow_progress_bridge.py` `_block()`, `fde/dongkuk/nltosql` 9/8.
- 진행 블록에 담을 것은 **근거**다(과제8은 coverage·applied_terms·sql·vote를 **3단계 문자열**로 재구성 —
  「질의 해석·커버리지」·「SQL 초안 생성」·「실행·검증」). 코드서빙 쪽은 손대지 않아도 된다 —
  브릿지가 응답을 읽어 블록으로 바꾼다.
- ⇒ **결론(9/8): 프론트엔드 없이 워크플로우만으로 추론 단계 노출이 된다.** 동국 채널 공지
  "Genos 추론단계 노출성공 (프론트없이 workflow 만으로 가능)". **전 과제 재사용 가능한 기법**이다.

### 어느 쪽인지 2분에 가리는 법 (버전 불문 권장)
본코드를 붙이기 전에 Python 단계에 **`async def run(data): return {"text":"hello"}`만** 넣고 배포 →
채팅에 hello가 뜨면 return 규약, "답변 생성 실패"면 yield 규약. V1.8.6 확정도 이 방법으로 했다.

### 공통
- 채팅 입력 키는 `data["question"]`.
- ⚠️ **브릿지가 예외를 글자로 바꿔 항상 200으로 끝나면 어느 컨테이너 로그에도 원인이 남지 않는다.**
  V1.8.6 규약 위반은 코드서빙 로그·워크플로우 로그 모두 정상(200)이었고 **브라우저 네트워크 탭**에서만
  `000200003`이 보였다. 채팅만 실패할 땐 네트워크 탭을 먼저 열어라.

## ⚠️ 재배포 사이클 (연결 잠금)
채팅 앱이 워크플로우에 연결(운영)돼 있으면 워크플로우 재배포가 막힌다. 코드 1줄 수정에도:
**① 단계 코드 저장(새 리비전) → ② 채팅앱 중지+승인 → ③ 워크플로우 재배포 → ④ 채팅앱 새 버전 생성(현 리비전 재바인딩) → ⑤ 배포+승인 → ⑥ 테스트.**
채팅 앱 버전은 특정 워크플로우 리비전 ID에 핀 고정되므로 재배포마다 재바인딩 필요.

## 디버깅 3종
- **이용 로그**: 요청별 Success/Failed + 소요시간. 0.1초 Success=조기 리턴(입력 못 읽음), 수십 초 Success=로직 실행됨(화면만 실패면 스트리밍 형식 문제), 0.1초 Failed=전송 전 오류.
- **컨테이너 로그**: 진짜 스택트레이스. (스트리밍 json.loads 규약도 이걸로 발견)
- **테스트 다이얼로그**: 채팅 없이 로직 검증. 입력 JSON 예 `{"question": "..."}`.

## 정석 경로 실환경 실측 — 전처리기 · 벡터DB (2026-09-02, 과제2 ELS)

9/1이 **커스텀 경로**(코드서빙→워크플로우→채팅, 과제6)를 실환경에서 완주했다면, 9/2는 **정석 경로**의
앞단(GenOS 전처리기 → 임베딩 → 벡터DB)이 실환경에서 처음 열린 날이다. 아래는 과제2가 부딪혀 확인한 규약이다
(원본 = `fde/seungho/integration` 브랜치 9/2 커밋 `7daa8d52`·`8d321418`·`9dc2a32b`·`5a33db22`).

- ★ **전처리기는 벡터 청크만 반환할 수 있다 — RDB로 나가는 반환 경로가 없다.** 상품 카드·문서 버전처럼
  정형으로 남겨야 하는 것은 전처리기 안에서 DB를 직접 붙는 대신 **전처리기가 코드서빙 API를 따로 호출**해
  적재한다(전처리기 파드는 DB가 아니라 **게이트웨이만** 부르면 된다). 문서는 그래도 **한 번만 파싱**된다.
- **컬렉션 이름이 곧 그 벡터DB의 인증키(토큰)** 다 — 짐작할 수 없으므로 설정값으로 받아야 한다.
- **본문(`text`)과 `name`이 AES-256-GCM으로 암호화**돼 저장된다(키는 PBKDF2 유도). 평문인 배포도 있으므로
  복호화 실패 시 원값을 그대로 쓰는 이중 처리가 안전하다. ⚠️ 키가 어긋나면 **"청크 전부 누락"처럼 보인다.**
- **`chunk_id`도 `content_hash`도 속성에 없다.** 대조는 **복호화한 본문 내용으로** 해야 한다.
  기본 속성은 20개이고 **이름이 복수형**(`n_chars`·`n_words`·`n_lines`·`n_pages`·`n_chunk_of_pages`) —
  단수로 보내면 조용히 `null`로 들어간다.
- 전처리기는 **`file_hash` 자리에 `document_id`를 넣는다**(문서 단위로 좁힐 때 이용 가능).
- ⚠️ **GenOS가 원본 파일명을 `Document-38423` 형태로 넘긴다** — 파일명에서 코드·문서유형을 파싱하는 로직은
  실환경에서 그대로 깨진다. 파일명이 규칙에 안 맞으면 **본문에서 다시 찾는 폴백**이 필요하다.
- 적재 경로가 **둘(우리 컬렉션 / GenOS 전처리기 컬렉션)** 이면 검증·뷰어도 양쪽을 봐야 한다 —
  한쪽만 보면 "한 건도 없다"로 나온다. 벡터 차원은 못 박지 말 것(임베딩을 GenOS가 하므로 달라도 정상).
- ⚠️ **`GENOS_VDB_URL`을 비우면 게이트웨이로 내려가 404**다(9/7). 벡터DB 주소는 못박아 둘 것 —
  안 그러면 "적재는 됐는데 검색만 0건"과 구분이 안 된다.

**검색 방식 — 9/7 갱신(과제2, 원본 `fde/seungho/integration` `ce749317`)**

- ★ **GenOS 전처리기 컬렉션에서도 `vector`·`keyword`·`hybrid`가 다 된다.** 9/2~9/6에는
  "본문이 암호화돼 색인되니 BM25가 읽을 글자가 없다 → genos 백엔드는 vector만"이라고 코드에
  못박아 뒀는데, **근거 없는 단정이었다**. 현업 리트리버는 같은 컬렉션에 lexical retriever를
  `encrypted_fields={"text","name"}`로 붙여 쓴다.
- **암호화는 «배포를 타는 사실»이지 이 경로의 성질이 아니다** (위 AES-256-GCM 항의 "평문인 배포도
  있다"와 같은 줄기). 판단 방법: 검색 결과 본문이 암호문으로 보이면 그때 경고를 남기고, 안 뜨면
  keyword·hybrid로 바꿔도 된다. 기본값을 vector로 두는 이유는 **그게 실제로 답이 나온 조합**이기
  때문이지 다른 방식이 안 되어서가 아니다.
  ⚠️ 암호화된 배포에서 키워드를 쓰면 BM25가 **암호문을 토큰으로 잡아** 한국어 질문이 영영 안 걸린다 —
  오류가 아니라 **0건**이라 "문서에 근거가 없다"로 읽힌다(같은 부류의 조용한 실패).
- ★ **hybrid는 거리를 주지 않고 융합 점수만 준다.** 그 값은 **정규화 랭킹값**이라 절대 임계를 걸 수
  없다(같은 0.7이 질의마다 다른 뜻). 임계를 쓰려면 **저장 벡터를 함께 받아 코사인을 직접 재고**,
  점수는 순위용 / 유사도는 임계용으로 나눠 실어야 한다.
- `keyword`는 **alpha=0인 hybrid**로 보내면 필터·속성 목록이 hybrid와 갈라지지 않는다(임베더 불필요).
  BM25가 볼 본문 속성을 지정하지 않으면 Weaviate가 **식별자까지 훑어** 키워드 점수가 망가진다.
