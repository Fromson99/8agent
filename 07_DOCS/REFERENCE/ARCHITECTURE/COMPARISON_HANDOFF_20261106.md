## 1. 대사가 하는 일

사용자가 조회 방식을 "대사"로 고르고 질문하면 아래 순서로 돈다. 내규·외규 조사는 기존 RAG를 "읽은 원문만 돌려받기" 모드로 부른다.

1. 질문 분석 → 2. 내규 조사 → 3. 내규 원문으로 개념 정하기 → 4. 개념별 외규 조사 → 5. 항목 대조 → 6. 필요하면 추가 조사 → 7. 쌍 만들기 → 8. 비교 → 9. 보고서

시험에 쓴 질문과 합성 문서(실제 내규·외규가 아니다):

```text
대사: 모의 유동성리스크 관리지침의 유동성비율 유지 기준, 기준 미달 시 조치, 위기상황분석 주기가 외규와 맞는지 양쪽 원문을 제시하여 비교해 주세요.
```

```text
[내규] 모의 유동성리스크 관리지침
제1조(목적) 이 지침은 「모의 금융투자업 감독규정」 제12조에 따라 회사의 유동성리스크 관리 기준과 절차를 정함을 목적으로 한다.
제2조(정의) 이 지침에서 "유동성비율"이란 잔존만기 3개월 이내 유동성자산을 잔존만기 3개월 이내 유동성부채로 나눈 비율을 말한다.
제3조(유동성비율의 유지) ① 회사는 유동성비율을 100분의 110 이상으로 유지하여야 한다. ② 유동성비율이 100분의 110에 미달한 경우 리스크관리부서장은 지체 없이 리스크관리위원회에 보고하여야 한다.
제4조(위기상황분석) 리스크관리부서는 매 분기 1회 이상 유동성 위기상황분석을 실시하고 그 결과를 대표이사에게 보고하여야 한다.
제5조(한도 초과 거래의 승인) 유동성 한도를 초과하는 거래는 리스크관리위원회의 사전 승인을 받아야 한다. 다만, 긴급한 경우에는 대표이사의 승인을 받아 거래한 후 다음 영업일까지 리스크관리위원회에 보고할 수 있다.

[외규] 모의 금융투자업 감독규정
제12조(유동성리스크 관리) ① 금융투자업자는 유동성리스크 관리에 관한 내부기준을 마련하여야 한다. ② 금융투자업자는 유동성비율을 100분의 100 이상으로 유지하여야 한다.
제13조(유동성비율의 산정) 유동성비율은 잔존만기 3개월 이내 유동성자산을 잔존만기 3개월 이내 유동성부채로 나누어 산정한다.
제14조(위기상황분석) 금융투자업자는 반기 1회 이상 유동성 위기상황분석을 실시하고 그 결과를 이사회에 보고하여야 한다.
제15조(기준 미달 시 보고) 유동성비율이 제12조제2항의 기준에 미달한 금융투자업자는 미달한 날부터 5영업일 이내에 그 사실과 개선계획을 감독원장에게 보고하여야 한다.
제16조(한도 초과 거래) 금융투자업자는 유동성 한도를 초과하는 거래를 하려는 경우 위험관리위원회의 사전 승인을 받아야 한다.

[외규, 관계없는 문서] 모의 전자금융 감독규정
제5조(접근통제) 금융회사는 전산실 출입자를 통제하고 출입 기록을 1년 이상 보관하여야 한다.
제6조(비밀번호 관리) 금융회사는 이용자 비밀번호를 암호화하여 보관하여야 한다.
```

심어 둔 차이는 세 가지다: 유동성비율 110%와 100%, 미달 시 보고(위원회와 5영업일 내 감독원장), 위기상황분석(분기·대표이사와 반기·이사회).

## 2. 고친 것과 그 근거

### 2.1 첫 단계에서 멈추던 문제 (감독 승인)

실제 오류:

```text
native action lacks current supervisor authorization
```

- 대사가 부르는 "원문만 돌려받기" 모드는 감독 승인을 받지 않고 행동을 고른다. 그런데 실행 직전 검사는 감독 승인을 요구했다.
- 일반 채팅은 가이드 모드라 감독이 꺼져 있어 문제가 없었고, 대사 안에서는 가이드 모드가 꺼지면서 감독이 켜졌다.
- 기존 대사 테스트는 탐색 설정을 테스트용으로 통째로 바꿔 감독이 꺼진 채 돌아서 이 오류를 한 번도 만나지 않았다.
- 고친 내용: 원문 반환 모드에서는 감독과 원문 목표 관리를 적용하지 않는다. 이 모드는 법률 판단을 하지 않고, 판단은 상위 대사 단계가 한다.

### 2.2 항목 대조가 5건 중 1건만 통과하던 문제

첫 실모델 실행(ADR-1429)에서 쟁점 "유동성비율 유지 기준"(항목은 "조건" 1개)을 묻는 호출에 모델이 3건을 냈다:

```text
1) 내규는 110% 이상, 외규는 100% 이상으로 유지 기준 수치가 다름.
2) 보고 대상(내부위원회 vs 감독원장), 기한(지체 없이 vs 5영업일 이…
3) 내규의 위기상황분석 주기 원문을 확보하지 못하여 비교 불가.
```

2번과 3번은 다른 쟁점의 내용이다. 세 건이 모두 같은 항목으로 묶여 거절됐고, 보완 요청에는 아래 문구만 전달돼 모델이 같은 형태로 다시 냈다:

```text
workflow decision: duplicate field-side patch
Correct the entire proposal using the same evidence and scope.
```

고친 내용:
- 첫 검토에서는 그 쟁점의 항목 수만큼만 제출할 수 있다(응답 형식에 개수 제한).
- 넘치면 이 문구로 거절한다: `too many items: this call reviews only the given issue. Submit at most one item for each requested field (condition); 3 were submitted. …`
- 중복 거절 문구에 어느 항목인지 넣었다: `duplicate field-side patch: field condition has more than one judgment for the same side; …`
- 지시문에 "이 호출은 issue에 적힌 쟁점 하나만 검토한다. … fields의 항목마다 item은 하나"를 추가했다.

결과(ADR-1433): 보완 호출 없이 5/5건 통과.

### 2.3 내규에 적힌 외규 이름으로 바로 읽기

- 원래는 **질문**에 문서 이름이 있을 때만 그 문서를 먼저 읽었다. 내규 제1조에 "「모의 금융투자업 감독규정」 제12조에 따라"라고 적혀 있어도 외규 조사는 검색부터 했다(ADR-1429에서 6회).
- 1차 수정: 개념이 **인용한** 내규 원문에 등록된 외규 이름이 있으면 먼저 읽는다. → ADR-1433에서 발동하지 않았다. 모델은 제2~4조를 인용했고 이름은 제1조(목적)에 있었다.
- 2차 수정: 개념이 인용한 **내규 문서에서 읽은 원문 전체**에서 이름을 찾는다. → ADR-1435에서 발동했다. 외규 조사의 첫 모델 호출 입력에 감독규정 제12~16조가 이미 들어 있었고, 모델은 한 번에 "추가 조사 대상 없음"으로 끝냈다.
- 이름이 겹치면 긴 이름을 우선한다. "모의법 시행령"만 적혀 있으면 "모의법"은 고르지 않는다.
- 조문 위치(제12조)까지 바로 읽는 것은 아직 안 했다. 문서가 작으면 전문을 읽고, 크면 목차만 보여 준다.

### 2.4 범위 밖 문구

ADR-1433 보고서의 "추가 확인 사항"에 실제로 남은 문구:

```text
외규(「모의 금융투자업 감독규정」) 원문이 아직 확보되지 않아 실제 비교는 불가하며, 내규 원문만 제시함.
위기상황분석 주기에 대한 외규 원문이 제공되지 않아 비교가 불가합니다.
```

- 첫째는 개념 단계(외규 조사 전)에 모델이 쓴 것이다. "쓰지 말라"는 지시문을 넣었지만 그대로 썼다. → 2차 수정: 이 단계의 메모 앞에 `내규 개념 정리 단계 메모(외규 조사 전): `을 붙여 시점을 알 수 있게 했다.
- 둘째는 첫째 쌍의 비교 호출이 쓴 것이다. 그 주제는 둘째 쌍이 실제로 비교했다. → 2차 수정: 비교 지시문에 "이 호출은 이 쟁점 하나만 판단한다"를 추가했다.
- ADR-1435 결과: 첫째 메모는 `내규 개념 정리 단계 메모(외규 조사 전): 외규 원문은 아직 확보되지 않아 내규와의 직접 비교는 불가`로 시점 표시가 붙어 남았다. 외규를 모두 비교한 보고서의 "추가 확인 사항"에 여전히 들어 있으므로, 외규를 확보한 뒤에는 빼는 것이 다음 할 일이다. 비교 4쌍은 모두 다른 쌍의 미확보를 적지 않았다.

## 3. 실제 모델 실행 결과

| | ADR-1429 (감독 수정만) | ADR-1433 (+항목 수 제한 등) | ADR-1435 (+2차 수정) |
|---|---|---|---|
| HTTP / 상태 | 200 / partial | 200 / partial | 200 / partial |
| 항목 대조 | 1/5건 (보완 소진) | **5/5건** (보완 0회) | **4/4건** (보완 0회, 개념 4개) |

| 호출 / 시간 / 비용 | 13회 / 121초 / 0.046달러 | 14회(429 두 번 포함) / 88초 / 0.026달러 | 12회(429 없음) / 94초 / 0.028달러, 입력 토큰 121,147→58,847 |
| 결과 불명 | 0 | 0 | 0 |

ADR-1435는 개념 수가 2→4로 달라져 항목·비교 호출이 각각 2→4회가 됐다. 전체 호출·시간 차이를 개선율로 쓰지 않는다. 심어 둔 차이 3개는 모두 보고서에 나왔다(실행자 읽기, 채점 아님). 단, 내규가 더 엄격한 두 차이(110 대 100, 분기 대 반기)도 "상충"으로 표기했다.

ADR-1435에서 새로 남은 것: concept-2(유지 기준 수치) 항목 검토가 외규 제13조(산정)를 "유지 기준 비교의 전제"로 **사용** 선언하고 어느 항목에도 인용하지 않았다. 서버는 이를 "반영 미완료"로 보존했고, 보고서에는 `확보 원문의 항목 반영 추가 확인 필요 — 사용 선언에 대응하는 항목 인용이 없어 반영 추가 확인 필요로 보존했습니다.`라고만 나온다. 어느 원문·어느 항목인지 없고 문구가 겹친다. 상태 partial은 이 문구와 개념 단계 메모, 두 추가 확인 사항이 남은 상태다.

ADR-1433의 실제 항목 대조표:

| 쟁점 | 항목 | 내용 상태 | 차이 |
|---|---|---|---|
| concept-1 | 정의 | MATCH | 내규 제2조와 외규 제13조 모두 잔존만기 3개월 이내 유동성자산을 … 나누어 산정 |
| concept-1 | 의무 | DIFFERENT | 내규는 리스크관리위원회에 지체 없이, 외규는 5영업일 이내 감독원장에게 보고 |
| concept-1 | 조건 | DIFFERENT | 내규는 100분의 110 이상, 외규는 100분의 100 이상 |
| concept-2 | 의무 | DIFFERENT | 내규는 '대표이사', 외규는 '이사회'에 보고 |
| concept-2 | 조건 | DIFFERENT | 내규는 '매 분기 1회 이상', 외규는 '반기 1회 이상' |

심어 둔 차이 3가지가 모두 표에 나왔다. 실행자가 읽어서 확인한 것이고 채점은 아니다. 합성 문서, 같은 질문, 각 1회라서 반복 안정성과 실제 내규에서의 동작은 모른다.

## 4. 바로 이어서 할 일

### 4.1 2차 수정본 회귀 결과 (완료)

같은 테스트 파일 36개를 MAIN165 코드와 수정본 사본에서 각각 돌려 테스트 이름으로 대조했다. 모델 호출은 0회다.

| | 통과 | 실패 |
|---|---|---|
| MAIN165 | 585 | 122 |
| 수정본(2차, 제품 8개 파일) | 594 | 115 |

- 새로 실패한 테스트 0.
- 실패에서 통과로 바뀐 것 7(선택 프로필로 대사가 표까지 도는 테스트 2, 항목 수 제한·거절 문구·긴 이름 우선·이름으로 먼저 읽기 5).

### 4.3 MAIN 반영

2. 패치를 적용한다(8개 파일). MAIN166에는 그대로 적용되는 것을 확인했다.
3. 워크플로우 등록 정보와 고정값을 다시 계산한다. 워크플로우 버전은 선택 MAIN보다 한 단계만 올린다(1.20.8 → 1.20.9).
4. 그 사본에서 대사 테스트 3개 파일과 관련 회귀를 돌려 새 실패가 없는지 본다.
5. 공식 승격 절차(준비 → 적용)로 올리고, 실제 서비스 진입점에서 대사 요청이 도는지 확인한다.
6. 작업 폴더에 나머지 6개 제품 파일을 넣는다. 작업 폴더의 고정값은 다른 세션이 수정 중일 수 있으니 건드리기 전에 확인한다.

## 5. 아직 시작하지 않은 개발

사용자와 정한 방향이다. 순서는 위에서 아래다.

### 5.1 문서 확정과 되묻기
- 사용자가 "이 문서로 대사해 줘"라고 하면 내규 목록에서 찾는다. 하나로 정해지면 진행하고 보고서 맨 위에 문서명을 적는다.
- 여러 개이거나 불확실하면 후보를 번호로 보여 주고 묻는다. 작업 전이라 물어도 버리는 것이 없다.
- 못 찾으면 "등록된 내규 중에 없음"이라고 알린다. 없다고 단정하지 않는다.

### 5.2 문서 전체 대사
- 구현 계획: [문서 대사 모드 구현 계획](DOCUMENT_COMPARISON_MODE_PLAN_20261106.md). GENOS 조회 방식에 "문서 대사"를 따로 두고 기존 "대사"는 질문 대사로 유지한다. 문서 하나 추정 350~600회·45~75분이라 묶음 단위 저장·이어 가기가 필요하다.
- 확정된 문서의 가장 작은 구조 단위까지 전부 확인한다.
- 기록은 최소 단위 행으로, 읽기는 묶음으로 한다. 묶음은 서버가 크기와 행 수로 자르고 상위 제목·머리 문장·꼬리 문장을 붙인다. 어떤 행들이 한 대사 단위인지는 모델이 정한다.
- 묶음을 만드는 코드와 테스트는 작업 폴더에 있다(미연결). 내규 11개 문서에서 323묶음, 6,970행, 누락·중복 0이다.
- 내규 11개 중 "제○조" 형식은 2개뿐이고 나머지는 "1. / 가. / (1) / ①" 번호 체계다. 조·항 이름이 아니라 구조 트리와 문단 소유자로 다뤄야 한다.
- 실제 모델 확인(ADR-1425, 공개 문서 654행): 30행 묶음은 첫 응답 31/32, 보완 뒤 32/32. 60행 묶음은 17/17. 123묶음 중 101에서 자원 보호 장치로 멈춰 권장 한도는 판정하지 못했다. 남은 22묶음은 후속 실험이 필요하다.
- 한 턴에 끝나지 않으므로 묶음 단위로 저장하고 이어 가는 작업으로 만든다. 채팅에서 "계속"으로 이어 갈지, 한 번 돌려 저장해 두고 결과만 볼지는 사용자가 아직 정하지 않았다.

### 5.3 애매한 것은 보류하고 끝에서 번호로 묻기
- 대사 도중에는 멈추지 않는다. 애매한 것은 "이건 이래서 보류"로 기록한다.
- 보고서 끝에 번호를 붙여 한꺼번에 묻는다. 사용자가 한 턴에 "1. 포함 2. 금융투자업규정 3. 증권사"처럼 답하면, 저장된 대사 결과를 이어받아 영향받는 항목만 다시 찾는다.
- 지금은 다음 대사 질문이 처음부터 다시 돈다. 같은 대화의 다음 턴을 직전 대사에 연결하는 부분이 새로 필요하다.

### 5.4 그 밖에 알려진 것
- **외규 조문 위치까지 바로 읽기**: 내규에 "제12조"까지 적혀 있을 때 그 조문을 바로 읽는 것. 큰 법령에서 필요하다. 데이터에는 내규→외규로 이미 연결된 참조가 186건 있다.
- **외규 조사가 NO_PROGRESS로 끝남**: ADR-1433에서 원문 5개를 확보하고도 상태가 partial이었다. ADR-1435에서는 이름으로 먼저 읽어 completed로 끝났다. 이름이 내규에 없는 경우는 여전히 검색 경로를 탄다.
- **갱신 검토의 중복 제출**: 첫 검토는 개수를 제한했지만, 새 원문이 들어온 뒤의 갱신 검토는 28건까지 받는다. 같은 항목·같은 쪽을 두 번 내면 여전히 거절된다(문구는 구체화됨).
- **낡은 테스트**: 대사 관련 테스트 115건이 수정 전후 모두 실패한다. 그중 82건은 `latest document selection required` 준비 데이터 문제다.
- **내규 근거 조사 워크플로우**: 같은 원문 반환 모드를 쓰므로 감독 오류의 영향을 같이 받았을 것이다. 수정 뒤 따로 돌려 보지 않았다.

## 6. 작업할 때 걸리는 것들

- **작업 폴더에서는 서비스 테스트가 돌지 않을 수 있다.** 여러 세션의 수정과 고정값이 섞여 있어 고정값 불일치로 먼저 실패한다. 선택 MAIN 코드의 사본을 만들어 그 사본을 지정해 테스트한다(부록 C).
- **선택 MAIN이 자주 바뀐다.** 이 작업 중에도 164 → 165 → 166으로 바뀌었다. 시작할 때와 반영 직전에 확인한다.
- **실모델 실행은 한 번에 하나만.** 다른 실험의 실행기가 돌고 있으면 기다린다. 서로 상대를 기다리는 대기 스크립트끼리 멈춰 있을 수 있다.
- **호스트 스왑이 꽉 차 있다**(8.0/8.2GiB, 오래 떠 있는 Java 프로세스와 Oracle). RAM은 여유가 있어도 "남은 스왑" 기준에 걸린다. 스왑 추가는 sudo 비밀번호가 필요해 사용자만 할 수 있다.
- **테스트 준비 코드가 실험 도구 폴더를 검색 경로 앞에 넣는다.** 어느 폴더의 `inspect.py`가 표준 모듈을 가려 `module 'inspect' has no attribute 'signature'`가 난다. 표준 모듈을 먼저 불러오면 된다.
- **내규 원문은 공개 허용 목록에 없다.** 모델을 직접 부르는 실험에는 보낼 수 없다. 성격이 비슷한 공개 문서로 「금융투자회사의 리스크관리 모범규준」 등이 허용 목록에 있다.
- **실험 절차**: 결과를 본 뒤의 재실행은 새 ADR로 한다. 호출 전에 코드·자료·기준을 동결하고, 동결 뒤 고친 것은 사유와 함께 남긴다.
