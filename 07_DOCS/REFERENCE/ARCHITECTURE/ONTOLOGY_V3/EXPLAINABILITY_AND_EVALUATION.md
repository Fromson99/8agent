<a id="v3-19"></a>

## 19. 설명가능성: 사람이 검토할 근거와 의존관계를 보여준다

<a id="v3-19-1"></a>

### 19.1 실제로 보여줄 수 있는 범위

LLM이 생성한 설명을 곧바로 실제 내부 판단 과정으로 간주할 수는 없다. Turpin 등의 연구는 모델의 설명이 출력에 영향을 준 편향 요인을 드러내지 않고 그럴듯한 이유를 제시할 수 있음을 보였다. 이 결과를 모든 설명이 무의미하다는 뜻으로 확대하지 않되, 설명의 문장과 실행 증거를 구분한다. [설명의 충실성 연구](https://papers.nips.cc/paper/2023/hash/ed3fea9033a80fea1376299fa7863f4a-Abstract-Conference.html)

우리의 설명 대상은 다음과 같은, 외부에서 확인 가능한 근거와 의존관계다.

```text
답변의 주장
  → 적용 대상으로 제시한 개념·검토 항목
  → 실제 확보하고 판단 입력에 제공한 원문
  → 선택한 관계와 적용 조건
  → 수행한 계산·형식 규칙 또는 LLM의 적용 해석
  → 결론이 의존하는 조건과 남은 미확인
```

추가로 다음을 구분해야 한다.

| 기록 | 입증할 수 있는 것 | 그 기록만으로 입증할 수 없는 것 |
|---|---|---|
| 도구 조회 성공 | 특정 버전의 원문을 확보함 | 모델이 그 원문을 읽고 올바르게 이해함 |
| 모델 입력 결속 | 원문이 해당 요청의 입력에 포함됨 | 그 원문이 출력에 실제로 어떤 영향을 줌 |
| 모델이 선택한 인용·관계 | 모델이 해당 근거·관계를 사용했다고 명시함 | 내부 사고의 충실한 재현, 적용의 정확성 |
| 계산·규칙 실행 기록 | 기록된 입력과 규칙으로 결과를 재현할 수 있음 | 입력 사실과 규칙의 법적 적용성이 옳음 |
| 답변 후 근거 대응 | 완성된 주장과 출처의 지지 관계를 사후 검토함 | 답변 생성 당시 실제 경로와 같음 |

따라서 실행 중 기록한 선택과 답변 후 재구성한 설명에는 출처·시점 차이가 드러나야 한다. 인용을 붙였다는 이유로 ‘이 자료 때문에 모델이 결론을 냈다’는 내부 인과를 주장하지 않는다. 실제 실행 기록이 없는 연결은 설명을 위해 재구성한 것이라고 표시한다.

<a id="v3-19-2"></a>

### 19.2 거래 사례에서 검토 지점을 보여주는 방법

다음 표는 [10.2절](RELATION_DISCOVERY.md#v3-10-2)의 가상 사례다. 금액과 규정은 설명용이며 실제 사건에서 확인한 사실이 아니다.

| 판단 요소 | 근거와 처리 | 제시할 상태 |
|---|---|---|
| 승인 기준은 10억 원이다 | 해당 판본의 규정에서 기준 확인 | 원문에서 확인한 규칙 |
| 계약금액은 각각 8억·4억 원이다 | 현재 사건의 계약 자료에서 확인한다고 가정 | 사건 자료에 근거한 입력 사실 |
| 두 계약은 합산 대상이다 | 동일 프로젝트·상호 이행 조건과 거래 분류 규정을 대조 | LLM의 적용 해석, 반대 사실·미확인 검토 필요 |
| 합산금액은 12억 원이다 | 두 계약을 합산한다는 조건 아래 8 + 4 실행 | 입력과 연산 재현 가능 |
| 위원회 승인이 필요하다 | 합산 대상이라는 판단과 기준 비교에 의존 | 위 적용 해석과 다른 조건이 성립할 때의 결론 |

이 표의 가치는 숫자 하나의 신뢰도를 부여하는 데 있지 않다. 사용자가 **‘두 계약을 합산 대상으로 본 부분을 먼저 검토하면 된다’**고 알 수 있게 한다.

계산이 맞아도 합산 대상 해석이 틀리면 최종 결론은 바뀔 수 있다. 따라서 12억 원을 계산한 기록과 두 계약을 합산해도 된다는 해석의 근거를 함께 보여준다.

<a id="v3-19-3"></a>

### 19.3 새롭게 얻는 기능: 수정의 영향을 좁힌다

주장과 근거를 의존관계로 연결하면, 관계 하나가 수정될 때 무엇을 다시 볼지 제안할 수 있다. 예를 들어 ‘두 계약은 상호 이행 조건이 아니다’라는 사실이 확인되면 합산 판단과 이에 의존한 금액·승인 결론을 재검토 대상으로 표시한다. 10억 원 기준의 원문 자체가 틀린 것으로 바꾸지는 않는다.

이는 답변에 대한 정정과 규정 개정 모두에 도움이 될 수 있다. 다만 등록된 의존관계를 따라 찾은 영향 범위이며, 기록되지 않은 모든 영향을 포괄한다는 뜻은 아니다. ‘영향 후보 발견’, ‘재검토 필요’, ‘새 결론 확인’은 별도 상태로 둔다. 변경을 발견했다는 이유로 과거 결론을 자동으로 반전시키지 않는다.

<a id="v3-20"></a>

## 20. 온톨로지 적중과 근거의 지지를 분리한다

<a id="v3-20-1"></a>

### 20.1 hit이라는 말부터 분해한다

온톨로지 적중률은 재사용·검색에 관한 관찰값이 될 수 있다. 그러나 무엇에 적중했는지 먼저 정해야 한다.

1. 현재 질문과 비슷한 용어·관계 후보가 검색되었다.
2. 그 후보가 현재 판본·범위·권한·검토 상태에서 재사용 가능하다.
3. 이번 판단에서 그 관계를 실제 선택했다는 기록이 있다.
4. 이번 사안에 그 관계를 적용한 해석이 근거에 의해 지지된다.

이 단계들을 하나의 hit으로 합치면 검색 성공과 적용 정확성이 섞인다. 특히 4번은 의미·적용성 평가가 필요하므로 단순 색인 일치로 확정할 수 없다. 제품 지표를 정한다면 각 단계의 단위와 분모를 명시한다.

적중했어도 구판·잘못된 관계·잘못된 적용 때문에 틀릴 수 있다. 미적중이어도 새로운 원문 조합이 올바를 수 있다. LLM이 새롭게 해석했다는 이유만으로 자의적 판단이 되는 것도 아니다. 그러므로 **할루시네이션율을 `1 − 온톨로지 적중률`로 계산하지 않는다.**

<a id="v3-20-2"></a>

### 20.2 생성 경로와 지지 상태의 두 축

| 축 | 기록할 내용 |
|---|---|
| 판단의 생성 경로 | 검토된 관계 재사용, 새로운 근거 조합, 새로운 적용 해석, 명시적 계산·규칙 실행 |
| 근거의 지지 상태 | 충분히 지지, 일부 지지, 미지지, 원문과 모순, 판정 불가·미확인 |

여기서 생성 경로의 값들은 반드시 하나만 고르는 등급이 아니다. **검토된 B→C 관계를 재사용하면서, 이번 사안이 B 조건에 해당하는지는 LLM이 새롭게 해석할 수 있다.** 따라서 답변 전체에 하나의 꼬리표를 붙이기보다 주장·관계·적용 단계별로 기록한다.

예를 들어 다음 두 상태를 모두 표현할 수 있어야 한다.

- 새 근거 조합이며, 현재 원문과 조건으로 충분히 지지된다.
- 기존 검토 관계에 적중했지만, 현재 판본과 모순된다.

‘충분히 지지’도 평가에 사용한 근거·범위·시점 아래의 상태다. 모든 반대 근거를 완전히 탐색했다거나 법률적 정답을 보증한다는 뜻은 아니다. 누가 어떤 자료를 보고 판단했는지도 함께 남긴다.

<a id="v3-20-3"></a>

### 20.3 새로운 연결을 불리하게 평가하지 않는다

미적중에 자동 감점을 주면 [10절](RELATION_DISCOVERY.md#v3-10)의 창의적인 B-C-A 연결이 구조적으로 불리해진다. 새로운 경로는 새롭다는 사실을 표시하고, 기존 경로와 동일하게 근거·범위·조건·예외로 검토한다.

반대로 새 경로가 원문 몇 개를 인용했다는 이유만으로 검증된 것도 아니다. 각 간선과 합성 과정이 지지되는지를 본다. 유사성에 따른 탐색 힌트, 근거 있는 새 해석, 아직 확인되지 않은 가설은 구분한다.

<a id="v3-21"></a>

## 21. 할루시네이션·누락·해석 의존을 평가하는 방법

<a id="v3-21-1"></a>

### 21.1 답변의 주장을 분리하되 법적 해석의 성격을 보존한다

FActScore는 생성된 답변을 작은 사실 주장으로 나누고 출처가 지지하는 비율을 평가한다. ALCE는 답변의 정확성과 인용 품질 등을 평가하며, RAGTruth는 검색 자료에 의해 지지되지 않거나 모순되는 출력에 대한 사람의 주석을 제공한다. 이는 주장·근거를 분리해서 본다는 참고 근거다. 이 논문들이 법률 해석의 정답률이나 우리 시스템의 평가기를 검증한 것은 아니다. [FActScore](https://aclanthology.org/2023.emnlp-main.741/), [ALCE](https://aclanthology.org/2023.emnlp-main.398/), [RAGTruth](https://aclanthology.org/2024.acl-long.585/)

우리의 평가는 원문에 적힌 내용, 사건 사실, 계산 결과, 규칙의 적용 해석, 최종 결론을 구분할 필요가 있다. 원문의 직접 지지 여부로 평가할 수 있는 문장과, 사실·예외를 종합해야 하는 적용 해석을 같은 방식으로 판정하지 않는다.

<a id="v3-21-2"></a>

### 21.2 우선 사용할 지표와 분모

아래는 설계 제안이며 현재 계산·운영 중인 지표가 아니다. 실제 실험 전에 주장 분해·라벨링·집계 규약을 고정해야 한다.

| 지표 | 제안하는 정의 | 함께 보고할 것 |
|---|---|---|
| 근거 미지지 주장 비율 | 지지 여부를 판정한 주장 중, 검토한 근거가 해당 단정을 지지하지 않는다고 판정한 주장 비율 | 평가 근거의 범위, 일부 지지 비율, 판정 불가 비율 |
| 원문 모순 주장 비율 | 지지 여부를 판정한 주장 중, 적용 가능한 판본의 원문과 모순된다고 판정한 주장 비율 | 판본·대상 범위, 해석 이견과 실제 모순의 구분 |
| 핵심 검토 항목 누락률 | 해당 문제에 적용된다고 별도 검토한 핵심 항목 중, 판단·답변에서 다루지 않은 항목 비율 | 필수 항목 목록의 출처·검토 상태, 알려진 목록의 한계 |
| 해석 의존 지점 | 결론을 좌우하는 적용 해석과 그 근거·미확인 목록 | 자동 오류율로 바꾸지 않고 검토 위치로 제시 |
| 평가 가능 범위 | 전체 평가 대상 주장 중, 지지 여부를 판정할 수 있었던 주장 비율 | 미확인·이견·평가 자료 부족의 수와 이유 |

‘일부 지지’를 완전 지지나 완전 오류로 몰아넣지 않는다. ‘평가 자료가 부족해 판정할 수 없음’과 ‘확보한 자료가 단정을 지지하지 않음’도 별도 라벨로 둔다. 어떤 자료 범위를 기준으로 판단했는지가 없으면 이 둘의 구분은 재현하기 어렵다.

불명확한 항목을 분모에서 조용히 제거하면 수치가 좋아 보일 수 있다. 따라서 판정 완료 주장만의 비율을 제시하더라도 전체 주장 수와 판정 불가 비율을 함께 보고한다. 평가 가능한 주장이 0개인 경우 0% 오류라고 표시하지 않는다.

이 비율은 근거에 대한 지지 평가다. 확보한 근거 밖에서 실제로 참일 수 있는 주장, 사실이 아직 확인되지 않은 사안, 법적 해석이 갈리는 사안을 구분하므로 곧바로 법률 정답률이나 할루시네이션 확률이라고 부르지 않는다.

<a id="v3-21-3"></a>

### 21.3 주장 비율만으로는 중요한 오류가 가려질 수 있다

사소한 사실 열 개가 맞고 핵심 적용 해석 하나가 틀려도, 주장 단위 평균은 높게 나올 수 있다. 답변을 잘게 나누는 방식에 따라서도 비율이 달라진다. 그래서 다음을 함께 본다.

- 주장 분해의 규약과 중복 주장 처리.
- 최종 결론을 바꾸는 핵심 오류가 있는 답변의 비율.
- 질문이 요구한 중요한 항목을 실제로 다루었는지.
- 조건부 설명과 미확인 표시가 적절한지.
- 사람이 핵심 해석을 찾아 검토·수정하는 데 걸리는 시간.

핵심 항목 목록도 온톨로지 자체만으로 완결하지 않는다. 온톨로지에 빠진 항목을 동일한 온톨로지로 평가하면 발견하지 못할 수 있다. 평가용 목록은 독립적인 원문 검토를 통해 마련하고, 아직 승인되지 않은 질문 자료를 정답 자료처럼 사용하지 않는다.

<a id="v3-21-4"></a>

### 21.4 확률 점수에는 별도의 검증이 필요하다

‘이 답변의 할루시네이션 확률은 10%’라고 말하려면 먼저 오류의 정의와 단위를 정해야 한다. 주장 하나의 오류, 핵심 결론의 오류, 답변 안에 오류가 하나라도 있을 사건은 서로 다르다.

그다음 독립적으로 검토한 자료에서 같은 점수 범위의 실제 오류 빈도를 확인하고 보정해야 한다. 표본 수와 적용 업무 범위도 함께 관리한다. 모델·프롬프트·규정·질문 분포가 바뀌면 기존 보정의 유효성을 다시 검토한다.

생성 모델이 만든 온톨로지와 동일 모델의 자기평가만으로 확률을 정하면 오류를 공유할 수 있다. 평가 프롬프트를 나누거나 다른 모델을 썼다는 사실만으로 독립성이 확보되는 것도 아니다. 별도의 원문 기반 검토·정답 자료와 비교하고, 해석 이견은 이견으로 남긴다.

미확인이나 낮은 점수가 새 조사 루프의 자동 시작 조건이 되어서는 안 된다. 추가로 확인할 구체 항목이 있을 때 조사하고, 그렇지 않으면 현재 근거와 한계를 전달한다. 중대한 권한·출처·해시·상태 오류의 처리와 일반적인 해석 불확실성은 기존 정책대로 구분한다.

<a id="v3-22"></a>

## 22. 기존 v3 구조에 추가하는 설계와 확인 과제

기존의 공통 확인 규칙과 조문별 숏패스는 유지한다. 여기에 조직의 검토 이력과 개별 답변의 주장·근거 의존관계를 연결하는 것이 제안이다.

```text
조직이 검토한 개념·관계·적용 범위 + 근거 판본·검토 이력
                         ↓
       진입 후보·공통 확인 규칙·조문별 숏패스
                         ↓
       현재 질의의 확보·전달·선택·해석·실행 기록
                         ↓
       주장 ↔ 원문·사건 사실·계산·적용 조건의 연결
                         ↓
          답변·미확인·사람이 검토할 지점 표시
                         ↓
       수정 후보·영향받는 관계와 판단의 재검토
```

기록을 위해 필요한 것은 모델의 모든 내부 생각이 아니다. 검토에 필요한 주장 ID, 원문 범위·버전, 사건 사실의 출처, 선택된 관계, 적용 조건, 실행한 계산, 해석과 미확인, 기록의 생성 시점과 담당을 구분하는 것이다. 원문 본문은 기존 근거를 참조해 중복 저장을 줄인다. 이는 확정 스키마나 새 실행기를 선언하는 것이 아니다.

검증할 때는 효과의 원인도 나누어야 한다. 다음 비교는 향후 ADR을 위한 가설이며 이번에 실행하지 않았다.

| 비교 대상 | 확인하려는 효과 |
|---|---|
| 같은 모델에서 기존 흐름과 상태 연결 보완 | 반복 조사·근거 전달 누락이 상태 관리로 줄어드는가 |
| 같은 상태 관리에서 검토된 지식·숏패스의 유무 | 조직의 검토 지식이 검색·근거 확보·적용 검토를 더 돕는가 |
| 같은 원문·질문에서 각 모델별로 위 조건 비교 | 모델이 좋아져도 추가 효과가 남는가 |
| 실제 검토 과정에서 주장·의존관계 표시의 유무 | 사람이 중요한 오류를 찾고 수정하는 시간·정확도가 개선되는가 |

자료의 동결, 평가 정보의 제품 입력 분리, 동일한 비교 조건과 비용 기록, 신규 후보의 ADR 절차를 따른다. 모델 하나를 바꾼 결과와 온톨로지의 효과를 섞어 보고하지 않는다. 정의·관계 검토와 개정 관리 비용도 함께 본다.

이번 추가의 결론은 설명가능성이라는 이름을 붙이는 것이 아니다. **어떤 근거와 해석이 어떤 결론을 지지하는지 확인하고, 잘못된 부분을 좁혀 고치며, 그 검토 결과를 다음 모델과 다음 질문에 재사용할 수 있게 하는 것**이다. 현재 구현 여부와 실제 효과는 별도 확인 과제로 남는다.
