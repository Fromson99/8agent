# 방향과 기업 지식 통제

[전체 목차](../ONTOLOGY_V3.md)

원래 논의의 절 번호를 유지했습니다. 설계 제안과 구현·검증 상태는 각 절의 구분을 따릅니다.

<a id="v3-1"></a>

## 1. 무엇을 해결하려는가

이 논의의 목표는 그래프의 용어나 관계 수를 늘리는 것이 아니다. **에이전트가 판단에 필요한 근거를 빠뜨리지 않고, 이미 알게 된 탐색 경로를 재사용해, 전체를 다시 탐색하는 것보다 빠르게 적절한 답에 도달하게 하는 것**이다.

후속 논의에서 여기에 **모델이 바뀌어도 조직의 검토 기준과 근거·해석·미확인 이력을 유지하고, 사람이 답변을 검토·정정할 위치를 찾게 한다**는 목표가 추가되었다. 빠른 검색과 루프 감소는 측정할 효과이며, 조직의 지식과 판단 근거를 관리하는 체계는 그 효과를 뒷받침하는 기반이다. 지속 가치가 실제로 있는지도 관리 비용과 검토 시간까지 포함해 확인해야 한다.

제품의 방향은 **“온톨로지는 기업의 지식을 통제 가능하게 만들어준다”**로 정리한다. 전체 기능을 **기업지식 통제 시스템**이라 부르고, 온톨로지는 그 안에서 개념·관계·조건·제약을 정의하는 지식 모델을 담당한다. 어떤 지식을 채택하고 어디에 적용했으며, 수정하면 무엇을 다시 검토해야 하는지 관리하는 구현을 함께 갖춰야 한다.

사용자가 설명한 대표 상황은 다음과 같다.

> 에이전트가 판단하면서 “거래금액 산정 부분이 빠져 있다”고 한다. 이때 “거래금액 산정 부분은 어떻게 찾았더라, 다른 것은 어떤 식으로 되어 있었더라”라는 기억을 떠올려 빠르게 찾아야 한다.

여기서 기억할 대상은 과거 질문과 최종 답변만이 아니다. **판단 중 생긴 근거의 필요, 그 근거를 찾았던 위치와 경로, 그 경로를 다시 사용할 수 있는 조건**이다. 동일한 문제뿐 아니라 비슷한 문제에도 도움이 되어야 한다.

문제는 세 단계로 나뉜다.

| 단계 | 현재 논의에서 해결하려는 질문 | 필요한 기능 |
|---|---|---|
| 최초 진입 | 질문을 받았을 때 어느 조문부터 볼 것인가? | 질문의 판단 목적과 조건에 맞는 진입 후보 찾기 |
| 진입 이후 조사 | 이 판단에 무엇이 필요하며, 어디서 바로 가져올 것인가? | 원문별 검토 사항·관계 + 근거 숏패스 + 확보·전달 상태 |
| 확장된 연결 | 직접 찾은 A 외에, B→C→A가 결론을 바꾸는가? | 관계의 의미와 조건을 보존한 다단계 탐색·검증 |

초기 논의에서는 두 번째를 중심으로 정리했다. 후속 논의는 [공통 묶음의 역할과 온톨로지 구성](CLUSTERING_AND_CONSTRUCTION.md), [질문·원문에서의 진입](QUESTION_MATCHING.md)으로 구체화했다. 이 설계 전체의 구현·효과 검증은 남아 있다.

<a id="v3-2"></a>

## 2. 논의가 발전한 순서

| 순서 | 사용자의 문제 제기 | 정리된 관점 |
|---|---|---|
| 1 | 우리의 법률 온톨로지는 어떻게 만들어지는가? | 용어집·원문 구조·정의·명시 참조를 먼저 확인하고, 현재 색인과 의미 추론을 구분한다. |
| 2 | 일반적인 온톨로지보다 행동 지침 모음집에 가깝지 않은가? | 대상 세계의 개념, 법적 규칙, 조사 방법, 실행 제어가 섞여 있다. 역할을 구분해야 한다. |
| 3 | 용어 관계는 만들겠지만 정의·공리를 어떻게 매핑하고 컴파일하는가? | 범위와 조건을 명시한 형식화는 실행할 수 있다. 자연어 법령의 의미를 자동으로 확정하는 문제는 별도다. |
| 4 | “금액 산정이 부족하다”는 판단에서 기억을 떠올려 빨리 찾고 싶다. | 질문 전체보다 작은 ‘근거 필요와 해결 경로’를 기억 단위로 삼는다. |
| 5 | 너무 추상적이면 LLM이 다시 이해해야 하고, 너무 구체적이면 데이터마다 기억해야 한다. | 공통 확인 규칙을 공유하고, 개별 조문에는 위치·역할·조건을 연결한다. |
| 6 | 같은 조문에 있어도 금액 부분을 딕셔너리로 명시하면 중요성을 놓치지 않는다. | 위치뿐 아니라 판단상 역할을 드러낸다. 같은 원문을 중복 저장하거나 반복 조회할 필요는 없다. |
| 7 | 추상 규칙이 필요한 이유는 중요한 근거 누락과 불필요한 추가 조사 루프다. | 확인 항목과 근거 상태를 연결해 무엇이 확보되었고 무엇이 실제로 더 필요한지 보여준다. |
| 8 | 이제 최초 조문 진입점을 빨리 찾고, B-C-A처럼 생각하지 못한 연결도 찾을 수 있는가? | 진입 색인과 조건부 의존관계 탐색을 제안한다. 새 경로의 발견과 새 법적 사실의 확정은 구분한다. |
| 9 | 모델이 좋아진 뒤에도 남는 가치는 무엇인가? | 일반 지침의 추가 효과와 별개로, 조직이 검토한 정의·범위·판본·관계·판단 이력을 관리한다. |
| 10 | 설명가능성과 온톨로지 hit을 할루시네이션 평가에 쓸 수 있는가? | 근거·실행의 추적과 내부 사고 설명을 구분한다. 관계 재사용, 적용 해석, 근거의 지지 상태를 분리하고 주장별로 평가한다. |
| 11 | 기업 지식을 통제 가능하게 만든다는 방향에서 현재 코드를 바꿔야 하지 않는가? | 숏컷 저장·원문 검증·기존 관리 기반을 보존하면서 독립 지식 ID, 개별 검토, 실제 적용 기록, 변경 영향을 연결한다. |
| 12 | 추상적인 개념 대신 실제 구현 단위로 이름을 정하라. | 현재 파일과 함수에 대응하는 12개 단위를 명명하고 목표 경로·입출력·호환·이행 범위를 구체화한다. |
| 13 | DB 아키텍처도 설계하라. | 기존 원문·지식·근거·경험 원장을 연결하고 지식 버전, 검토·게시, 실제 사용, 변경 영향의 관계형 저장과 조회를 설계한다. |
| 14 | 질문을 통해 찾은 지식은 원문에 붙여 다른 질문에도 쓰자. | 일차 저장 단위를 원문 판본·조항·span과 개념으로 두고 질문은 발견 이력으로 남긴다. |
| 15 | 법 질문마다 계산이 다른데 공통 판단의 가치는 무엇인가? | 일반 지침의 효과를 가정하지 않는다. 사용자용 클러스터와 지식 정리 틀로 두며 구체적 계산·조건은 규정별로 관리한다. |
| 16 | 이 재료로 온톨로지를 어떻게 만드는가? | 원문 검토 사항에서 개념·의미 관계·조건 후보를 만들고 근거·범위 검토 후 게시한다. 클러스터 소속만으로 관계를 확정하지 않는다. |
| 17 | 만들어서 적용하면 속도와 정확도가 좋아질 수 있는가? | 근거 탐색·누락 감소가 기대 원리다. 사전 구축·갱신 비용과 오적중을 포함해 실제 효과를 확인한다. |
| 18 | 실제 질문과 온톨로지는 어떻게 매칭하는가? | 질문→지식 후보와 검색 원문→연결 지식의 두 진입을 결합하고, 검색 매칭과 현재 사안의 적용 판단을 분리한다. |

이 문서는 앞선 표현의 한계도 함께 보존한다. 예를 들어 “공리로 가지치기해야 온톨로지다”는 요구의 방향은 이해할 수 있지만, 학술적 정의로는 너무 좁다. 또한 법률 조문 사이의 모든 연결을 ‘인과관계’라고 부르는 것도 정확하지 않다. 두 구분은 아래에서 설명한다.

<a id="v3-17"></a>

## 17. 이번 논의에서 남기는 중심 문장

**원문에 개념·검토 사항·관계를 붙이고, 공통 클러스터와 표현 틀로 이를 찾아보고 정리한다. 의미 관계와 조건을 구체화한 지식은 질문 또는 확보한 원문에서 조회해 현재 사안에 적용한다. 실행 상태는 이미 확보한 것을 다시 찾는 루프를 줄이고, 조건이 있는 관계 탐색은 현재 판단을 바꿀 수 있는 다른 근거를 발견하게 한다.**

공통 검토 틀은 자료의 정리·재사용을 돕는다. 클러스터 하나를 모든 질문에 적용되는 판단 절차로 바꾸지 않으며, 현재 질문에 필요한 항목을 원문과 함께 선택한다.

이 구조의 가치는 온톨로지라는 이름 자체보다, 필요한 근거의 누락을 줄이고 전체 탐색보다 빠르게 타당한 답변에 도달하는지로 판단한다.

후속 논의까지 포함하면 중심은 **모델이 무엇을 근거로 어디까지 판단했으며, 어떤 연결부터 검토해야 하는지 드러내는 법률 지식 체계**다. 여기서 ‘판단했다’는 표현은 시스템의 기록과 명시된 해석을 가리키며, 모델 내부 사고 전체를 관찰했다는 뜻은 아니다.

<a id="v3-18"></a>

## 18. 모델이 좋아진 뒤에도 무엇이 남는가

<a id="v3-18-1"></a>

### 18.1 일반 지침의 가치와 상태 관리의 가치를 분리한다

‘금액이 나오면 산정 기준을 확인하라’는 지침의 추가 효과는 모델이 좋아지면 줄어들 수 있다. 반면 모델이 같은 근거를 반복해서 찾는 이유가 확보·전달·검토 상태를 잃기 때문이라면, 지침을 더 많이 추가하는 것으로 해결되지 않는다. 이는 [8절](EVIDENCE_MEMORY.md#v3-8)에서 구분한 실행 상태의 문제다.

따라서 다음 책임을 분리하는 것이 이번 보완의 방향이다.

| 책임 | 관리할 내용 | 개선을 판단할 기준 |
|---|---|---|
| 조직의 지식·검토 이력 | 채택한 개념·범위·관계, 근거 판본, 검토자와 수정 이력 | 모델 변경 후 재사용, 개정 시 추적·재검토 가능성 |
| 조사 실행 상태 | 무엇을 요청·확보·전달·검토했는지 | 근거 누락, 중복 호출, 반복 조사 감소 |
| 개별 사안의 적용 | 이번 사실에 어떤 규칙·관계가 적용되는지 | 근거 있는 해석, 반대 근거와 미확인 설명 |
| 평가 | 주장·인용·핵심 항목·답변의 품질 | 독립 검토와의 일치, 검토·정정 시간 |

이들을 연결할 수 있지만, 전부를 온톨로지의 추론 효과로 설명하지 않는다.

<a id="v3-18-2"></a>

### 18.2 조직의 지식은 검토 이력과 함께 남긴다

모델 성능과 별개로 관리할 이유가 있는 정보는 다음과 같다.

- 우리 조직이 어떤 개념·정의·적용 범위를 검토하고 채택했는가.
- 어떤 판본의 어느 원문이 해당 정의·관계를 뒷받침하는가.
- 이번 답변은 기존 검토 결과를 어디까지 재사용했는가.
- 어디에서 새로운 연결 또는 적용 해석이 생겼는가.
- 아직 확인되지 않은 사실·근거·해석은 무엇인가.
- 원문이나 조직의 검토 의견이 바뀌면 어떤 관계·판단을 다시 볼 필요가 있는가.

‘조직에서 검토됨’은 적용 범위가 있는 상태다. 언제나 옳은 법률 명제라는 표시가 아니다. 검토자·역할, 검토 일자, 적용 대상·시점, 근거 버전, 판단 이유, 대체·보류·이견 이력을 남길 필요가 있다. 원문의 유효 시점과 조직이 검토한 시점도 다를 수 있다.

갱신할 때 과거 기록을 덮어쓰지 않고, 당시 근거와 해석이 무엇이었는지 보존한다. 현재 조회 권한도 계속 적용한다. 더 좋은 모델은 이 기록을 재사용하거나 새로운 검토 후보를 제안할 수 있지만, 기존 기록이 있다는 이유로 다른 해석을 금지하지 않는다.

<a id="v3-18-3"></a>

### 18.3 지속 가치는 유지 비용을 포함한 가설이다

모델에 덜 종속되는 지식이라도 추출·검토·개정 추적에 비용이 든다. 모델이 스스로 잘 찾는 일반 지침까지 모두 수작업으로 유지할 이유는 약할 수 있다. 반복되는 중요한 판단, 조직 고유의 적용 범위, 수정의 영향이 큰 관계부터 가치가 있는지 확인한다.

검증할 질문은 ‘모델이 약할 때 도움이 되었는가’에서 끝나지 않는다. **더 나은 모델에서도 같은 원문과 질문으로 핵심 누락·미지지 주장·검토 시간을 줄이는가, 그 효과가 관리 비용에 비해 충분한가**를 확인한다. 이는 향후 평가 제안이며 현재 성능 결론이 아니다.
