## 10. ‘창의적인 연결’은 무엇이며 가능한가

사용자의 정의는 다음과 같다.

> 조문 하나하나 단위에 연결되어 있는 내용들을 인과관계로 이어 붙여서 새로운 관계를 만드는 것. 어떤 문제를 해결하려고 A만 봤다면, 다른 곳에서 B-C-A 관계까지 봐서 미처 생각하지 못했던 것까지 보는 것.

**각 연결의 의미와 적용 조건을 확인할 수 있다면, 떨어져 있던 근거를 조합해 새 경로를 발견하는 것은 가능하다.** 그러나 모든 간선을 이어 붙였다고 유효한 법률 관계가 만들어지는 것은 아니다. 모든 중요한 경로를 반드시 찾는다는 보장도 없다.

여기서 ‘새롭다’는 것은 다음 중 하나일 수 있다.

- 이미 존재하는 규정들을 연결했지만, 현재 질문에서 아직 고려하지 않았던 경로를 발견했다.
- 각 조문에는 직접 적혀 있지 않은 간접적인 영향을, 규칙들의 조건부 합성으로 도출했다.
- 아직 근거가 확인되지 않은 연결 가설을 만들어 추가 조사의 출발점으로 삼았다.

첫째·둘째의 검증된 경로와 셋째의 가설은 같은 상태로 저장하면 안 된다. 유사 사례를 떠올린 것도 해당 규칙의 적용을 증명한 것은 아니다.

<a id="v3-10-1"></a>

### 10.1 모든 연결이 인과관계는 아니다

법률·규정 사이에는 다음과 같은 관계가 섞여 있다.

| 관계 | 예 |
|---|---|
| 정의 의존 | A의 ‘거래’라는 말은 B의 정의에 따름 |
| 계산 의존 | A 판단의 금액은 C의 계산식으로 정함 |
| 분류·범위 결정 | B 조건이 여러 계약을 하나의 거래로 묶음 |
| 예외·우선 적용 | B가 A의 일반 규칙 적용을 변경함 |
| 법적 효과 | 조건 충족 시 A에 따른 승인·보고 의무가 생김 |
| 사실적 인과 | 실제 사건 B가 현실의 상태 C를 변화시킴 |

이들을 모두 `related_to` 또는 `causes` 하나로 저장하면 어떤 연결이 합성 가능한지 판단하기 어렵다. B→C와 C→A가 있다고 일반적으로 B→A가 성립하지는 않는다. 관계의 종류, 대상, 시점, 조건과 규칙을 함께 확인해야 한다.

실용적인 탐색 질문은 다음과 같다.

> A의 결론을 좌우하는 입력·분류·범위는 무엇인가? 그것을 정하는 C는 무엇인가? 그 C의 결과를 바꾸는 B는 무엇인가?

탐색은 **A←C←B**처럼 거꾸로 진행하고, 적용 판단은 **B→C→A** 순서로 확인할 수 있다.

<a id="v3-10-2"></a>

### 10.2 예시 1: 계약의 묶음이 승인 기준을 바꾸는 경우

아래는 구조 설명을 위한 가상 규정이다. 실제 조문·금액 기준이 아니다.

| 노드 | 가상 규정의 내용 | 역할 |
|---|---|---|
| A: 승인 | 산정 거래금액이 10억 원 이상이면 위원회 승인 필요 | 최종 판단 |
| C: 금액 산정 | 하나의 거래로 분류되는 계약들의 금액을 합산 | A에 넣을 금액 계산 |
| B: 거래 분류 | 동일 프로젝트이며 계약 이행이 서로 조건이 되는 계약들을 하나의 거래로 분류 | C의 합산 범위 결정 |

현재 계약은 8억 원이고, 이전 계약은 4억 원이라고 하자.

```text
A만 봄:
  현재 계약 8억 원 < 기준 10억 원
  → 승인 기준에 미달한다고 판단할 수 있음

B→C→A 확인:
  B: 두 계약이 동일 프로젝트이고, 이행이 서로 조건이라는 사실까지 확인
  C: 하나의 거래로 분류되므로 8억 + 4억 = 12억 원
  A: 12억 원 ≥ 10억 원 → 위원회 승인 필요
```

발견한 간접 관계는 **계약 이행의 조건 관계가 합산 범위를 거쳐 승인 필요 여부에 영향을 줄 수 있다**는 것이다. B가 승인이라는 단어를 포함하지 않아도 중요할 수 있다.

‘동일 프로젝트’만 확인하고 나머지 조건을 생략하면 이 연결은 검증되지 않는다. 이전 계약이 해당 기간·대상 범위에 포함되는지도 실제 규정에서 확인해야 한다. 사실이 부족하면 적용 가능성을 설명하되 12억 원이라는 산정 결과를 확정하지 않는다.

<a id="v3-10-3"></a>

### 10.3 예시 2: 신규 거래 없이도 신용등급 변화가 보고 판단을 바꾸는 경우

아래 역시 가상 규정이다. 실제 담보 인정비율이나 보고 의무를 나타내지 않는다.

| 노드 | 가상 규정의 내용 | 역할 |
|---|---|---|
| A: 보고 | 순위험액이 6억 원 이상이면 추가 보고 필요 | 최종 판단 |
| C: 위험액 산정 | 순위험액 = 대출잔액 − 담보평가액 × 인정비율 | A에 넣을 값 계산 |
| B: 인정비율 | 정해진 신용등급 하락 조건에서 담보 인정비율을 80%에서 40%로 변경 | C의 계산 입력 변경 |

대출잔액은 12억 원, 담보평가액은 10억 원으로 동일하다고 하자.

```text
등급 하락 전: 12억 − 10억 × 0.8 = 4억 원 → 6억 원 미만
등급 하락 후: 12억 − 10억 × 0.4 = 8억 원 → 6억 원 이상
```

발견한 관계는 **신규 거래나 잔액 증가가 없어도, 신용등급 변화가 담보 인정비율과 위험액을 거쳐 보고 필요 여부를 바꿀 수 있다**는 것이다.

이 경로를 적용하려면 실제로 B의 등급 하락 조건이 충족되었는지, 해당 담보에 적용되는지, 비율 적용 시점과 보고 판단 시점이 맞는지를 확인한다. 과거의 80%와 현재의 40%를 한 시점의 규정처럼 혼합하지 않는다.

<a id="v3-10-4"></a>

### 10.4 저장할 것은 조건이 있는 경로

새 연결을 발견했을 때 ‘B는 A를 발생시킨다’만 저장하면 중간 근거와 예외가 사라진다. 적어도 다음을 보존하는 것이 필요하다.

- B·C·A 각각의 원문 위치와 버전.
- 각 연결의 의미와 합성 이유.
- 적용에 필요한 사실·범위·시점과 예외.
- 현재 확인된 조건과 미확인 조건.
- 검증된 적용 경로인지, 검토할 가설인지, 유사 사례에 따른 탐색 힌트인지.

계약금액·잔액·위험액처럼 모두 ‘금액’으로 표현되더라도 같은 변수가 아니다. 단위뿐 아니라 무엇을 측정하는 값인지와 계산 범위를 연결해야 한다.

새 경로가 현재 질문에 유효하다고 확인되어도, 모든 상황에 적용되는 보편적 법률 관계로 자동 승격하지 않는다. 피드백 후보로 남기고 재사용 범위를 검토한다.

<a id="v3-11"></a>

## 11. 빠른 답변과 넓은 연결 탐색을 함께 다루기

기억을 통한 숏패스는 탐색을 줄인다. 새로운 연결을 찾으려면 탐색을 넓혀야 할 수 있다. 따라서 ‘창의적 연결을 많이 할수록 항상 빠르고 정확해진다’고 말할 수는 없다.

제안하는 기준은 **현재 결론을 바꿀 수 있는 구체적인 미확인 입력·조건에 우선순위를 주는 것**이다.

예를 들어 A에 금액을 넣어야 하는데 합산 범위가 불명확하면 C·B로 확장할 이유가 있다. 반면 동일한 원문과 사실을 가진 상태에서 ‘다른 중요한 것이 있을지도 모른다’만 반복하면 추가 조사 이유가 구체화되지 않은 것이다.

확인된 경로는 재사용하고, 다른 경로는 근거 있는 후보로 제시한다. 확장 깊이·호출 예산·후보 수·종료 방식은 실행 계약으로 관리하되, 이 문서에서는 임의의 최적 숫자를 확정하지 않는다.

전체 관련 규정의 완전한 탐색을 증명하지 못했더라도, 확보한 근거에 따른 답변과 남은 미확인을 전달할 수 있다. 불확실성 자체를 무조건 중단·재작성 사유로 삼지 않는 기존 정책을 유지한다.

<a id="v3-12"></a>

## 12. 다른 연구들은 이 문제를 어떻게 다루는가

아래 자료는 설계의 참고 근거다. 논문 또는 외부 시스템의 성능을 우리 법률 RAG의 성능으로 옮겨 적지 않는다.

| 연구·표준 | 이 논의와 연결되는 점 | 그대로 해결해 주지 않는 부분 |
|---|---|---|
| FOLaw / LRI-Core | 법률의 대상 개념과 문제 해결 지식의 구분 | 현재 프로젝트의 구체적인 기억·조회 구현 |
| SKOS / OWL | 용어 체계와 형식적 의미·추론의 구분 | 법률 자연어의 자동 해석과 조사 종료 |
| LegalRuleML / Catala / DMN | 법적 조건·효과와 의사결정의 명시적 표현 | 원문의 올바른 해석을 무검토로 보증하는 일 |
| Swanson의 undiscovered public knowledge | 떨어져 있는 지식 조각을 연결해 미처 보지 못한 관계 발견 | 임의 경로의 인과성·법적 유효성 보장 |
| HippoRAG / HippoRAG 2 | 그래프와 연상적 검색으로 여러 단계의 근거 연결 | 법률 버전·권한·예외·계산의 정확성을 자동 보증 |
| IRCoT | 추론 중 필요한 근거가 바뀌며 검색과 추론을 교차 수행 | 우리 기억 경로의 검증·승격·종료 계약 |
| GraphRAG | 그래프와 집단 요약을 이용한 넓은 범위의 질의 응답 | 특정 조문·산정 근거의 정확한 숏패스 자체 |
| DRIFT | 넓은 맥락과 국소 탐색을 연결한 후속 조사 | 우리 데이터에서의 적정 탐색 예산과 성능 |

Swanson의 논의는 개별 문헌에 흩어진 지식이 함께 읽히지 않아 발견되지 않는 문제를 다룬다. 이번의 B-C-A 구상은 그 발상과 닿아 있다. 법률 적용에서는 논리적 연결 외에도 문서 범위·시점·예외 확인이 추가로 중요하다. [Swanson, 1986](https://www.journals.uchicago.edu/doi/abs/10.1086/601720)

HippoRAG 계열은 지식그래프와 연상적 회수를 결합한 여러 단계의 검색을 다룬다. 이는 사용자가 말한 ‘연결을 떠올려 빠르게 찾아가기’와 관련이 있지만, 특정 규정의 필수 근거를 빠짐없이 확보하는 것과는 평가 과제가 다르다. [HippoRAG, NeurIPS 2024](https://proceedings.nips.cc/paper_files/paper/2024/hash/6ddc001d07ca4f319af96a3024f6dbd1-Abstract-Conference.html), [HippoRAG 2, ICML 2025](https://proceedings.mlr.press/v267/gutierrez25a.html)

IRCoT는 검색을 처음 한 번만 수행하는 대신, 중간 추론에 따라 필요한 검색을 이어 가는 접근이다. ‘금액 산정 근거가 부족하다는 판단이 생긴 바로 그 순간에 기억·검색을 호출한다’는 요구에 참고할 수 있다. [IRCoT, ACL 2023](https://aclanthology.org/2023.acl-long.557/)

GraphRAG의 전역 요약과 DRIFT의 넓은 맥락·국소 탐색 결합은 최초 진입과 확장에 참고할 수 있다. 다만 특정한 법률 근거의 회수에는 원문 위치와 관계의 역할을 직접 다루는 설계가 추가로 필요하다. [GraphRAG](https://www.microsoft.com/en-us/research/publication/from-local-to-global-a-graph-rag-approach-to-query-focused-summarization/), [DRIFT](https://www.microsoft.com/en-us/research/blog/introducing-drift-search-combining-global-and-local-search-methods-to-improve-quality-and-efficiency/)
