# 랜딩 — 질문에서 첫 조문으로

[v4 목차](../ONTOLOGY_V4.md) · [핵심 MVP](MVP.md) · [지식 축적](CONTROLLED_KNOWLEDGE.md) · [멀티턴](MULTITURN_LEGAL_AGENT.md)

2026-10-24 사용자와 정한 랜딩 설계다. 아직 구현하지 않았다.

## 문제

컴파일은 맞는 조문에 도착한 뒤에야 효과가 있다. 그런데 첫 도착이 자주 틀린다.

| 기록 (2026-09, 당시 MAIN 기준) | 내용 |
|---|---|
| ADR-0461 | CM 51문항에서 결정 조문을 실제로 읽은 비율 0.253 → 0.627 (전문 검색 정렬 개선 후에도 약 37%는 못 읽음) |
| ADR-0462 | 끝까지 돌린 정답 26/51, 정답 조문만 주면 같은 모델 44/51. 오답 25건 중 11건은 결정 조문을 못 찾았고 14건은 찾고도 틀림 |
| 판례 다리 측정 (`09_ARTIFACTS/AUDITS/20260918-precedent-bridge-eval`) | 정답 조문은 항상 후보 안에 있었고(질문당 중앙값 1.7만 개), 문제는 순서였다 |

조문은 고정이라 온톨로지로 만들 수 있다. 질문은 매번 다르다. 그래서 **바뀌는 질문을 고정된 것(승인된 용어, 과거 착지 기록)에 맞춰** 첫 조문 후보를 앞으로 올린다.

## 착지 후보를 만드는 갈래

```text
사용자 질문
 → 첫 모델 호출(기존): 질문 요지 1문장 + 핵심 표현 2~4개
 → 갈래별 후보 (모두 코드, 모델 호출 없음)
    ① 용어집 바꿔 넣기: 질문 속 표현 → 승인된 용어·별칭 → 법률 용어로도 검색
    ② 착지 예시: 요지가 비슷한 과거 사례 k건 → 그 사례들이 실제로 인용한 조문
    ③ 전문 검색·용어 역매칭 (현행)
    ④ 법령명·조문 번호를 직접 말했으면 → 정확한 조문 조회
 → 합친 후보 카드 (어느 갈래에서 왔는지 표시) → 모델이 첫 착지를 고름
 → 착지 조문이 온톨로지 묶음에 속하면 묶음 전체를 컴파일
```

온톨로지 묶음에 속한 조문은 **어느 것에 닿아도** 묶음 전체를 컴파일한다. 출발 조문을 정확히 맞히지 않아도 되므로 착지 대상이 넓어진다. 예: 검색이 "자본적지출액"으로 시행령 제163조에 먼저 닿아도 제97조 제1항 제2호와 제3항 본문 조건까지 묶는다.

## 용어집 — 별도 도구

용어집은 온톨로지의 일부가 아니라 **언제나 바꿔 넣어 쓸 수 있는 도구**다. 같은 개념을 다른 말로 쓴 것을 맞춘다. 예: 스톡옵션 → 주식매수선택권.

| 있는 것 | 없는 것 |
|---|---|
| 용어집 역매칭: 질문 속 등록 표기·별칭·번역 → 개념 → 출현 조문 (`navigation_match.ReverseMatcher`) | 사용자가 승인한 용어·별칭 |
| 법제처 공식 일상용어 동의어 다리 (예: 숏 → 공매도). 데이터 세대 안에 있음 | 승인된 별칭이 검색어에 들어가는 경로 |
| 문서 별칭(약칭) | 대화 중 사용자가 알려준 용어의 기록·후보화 |

### 흐름

```text
대화 중 용어 관찰 → 에이전트 레이어에 기록
  · 사용자가 알려줌: "스톡옵션은 주식매수선택권 말하는 거야"
  · 사용자가 정정: "그 용어 말고 ○○로 찾아"
  · 에이전트가 첫 검색에 실패하고 다른 표현으로 찾아 답에 썼을 때 (자동 관찰)
 → 같은 세션 안에서는 바로 적용 (그 세션에만)
 → 개념 묶음 작업에서 용어 후보로 정리: "스톡옵션 → 주식매수선택권, 관찰 3건, 근거 발화·조문"
 → Streamlit '용어' 탭: 승인 / 수정(대상 용어·적용 범위) / 반려
 → 승인 → 적재 SQL → 골드의 용어·별칭 (다른 지식과 같은 절차)
 → 골드에 들어간 뒤부터 모든 요청의 검색에 적용
```

### 규칙

- **치환이 아니라 추가.** 원래 표현도 그대로 검색한다. 내규는 "스톡옵션"이라고 쓸 수도 있다.
- **적용 범위.** 팀·문서군 단위로 둔다. "PF"처럼 뜻이 여럿인 말 때문이다.
- **모델은 별칭을 만들지 않는다.** 승인된 것만 쓴다. 모델이 낸 것은 후보다.
- **승인 때 정합성 검사.** 같은 말이 이미 다른 용어에 붙어 있음, 별칭이 그 자체로 법률 용어임, 법제처 공식 동의어와 다름을 화면에 보여준다.
- **표시와 기록.** 답변에 "'스톡옵션'을 '주식매수선택권'으로도 검색했습니다"를 보여주고, 적용한 별칭과 그 판본을 실행 기록에 남긴다.
- **적용 위치.** 용어 역매칭(`ReverseMatcher`)의 씨앗과 전문 검색어 양쪽.

## 착지 예시

```text
착지 예시 = (과거 질문의 요지, 그 질문이 실제로 근거로 쓴 조문)
```

용어집과 하는 일이 다르다.

| | 하는 일 | 예 |
|---|---|---|
| 용어집 | 같은 개념의 다른 말을 바꿔 넣음 | 스톡옵션 → 주식매수선택권 |
| 착지 예시 | 말은 달라도 같은 쟁점이었던 과거 사례가 어느 조문으로 갔는지 빌려 옴 | "채무조정 전담인력 업무 수행" → (비슷한 사례) "준법감시인 겸직" → 지배구조법 제29조 |

### 출처

| 출처 | 인용 조문이 있는 건수 / 전체 | 요지로 쓰는 부분 |
|---|---:|---|
| 금융위 회신사례 (`01_DATA/wiki/raw/fsc`) | 310 / 521 | 질의요지 + 제목. 첨부 회신문만 가리키는 211건은 제외 |
| 법제처 해석례 (`01_DATA/wiki/raw/expc`) | 180 / 180 | 질의요지 + 제목 |
| 판례 (`01_DATA/wiki/raw/prec`) | 227 / 472 (단순 추출 기준) | 판시사항 |
| 우리 대화 | 쌓이는 만큼 | 승인된 것만 |

공개 사례는 원문 데이터와 같이 골드에 둔다. 우리 대화에서 나온 착지 기록은 에이전트 레이어에 원료로 남고, 승인·적재된 것만 골드에 들어간다. 기록 대상은 답에 실제로 쓰였고 사용자가 정정하지 않은 착지다. 정정되면 그 기록을 갱신한다.

### 동작 — 실제 데이터 시연 (2026-10-24, 단순 글자 겹침 점수, 같은 회신 제외)

**잘 된 경우 — fsc-hard-003**
- 질문: 상호저축은행의 준법감시인이 개인채무자보호법상 채무조정 전담인력 업무를 수행할 수 있는지
- 정답 근거: 지배구조법 제29조, 같은 법 시행령 제24조
- 비슷한 회신 2위: "준법감시인의 여신감리업무 겸직 가능 여부" → 인용 조문 **지배구조법 제29조**, 상호저축은행법 제11조, 지배구조법 제25조

질문에 "겸직"이 없어서 용어집으로는 닿기 어렵지만, 비슷한 사례의 인용 조문으로 바로 닿는다. 시행령 제24조는 지배구조법 제29조에 온톨로지 묶음이 있으면 컴파일이 가져온다.

**안 된 경우**
- cm-049(공동주관), cm-047(우리사주): 비슷한 회신이 없어 무관한 회신이 걸렸다. 1위 점수 약 20으로 낮다.
- fsc-hard-009: 질문이 길고 사실관계가 많아 무관한 회신이 1위가 됐다.

### 조건

1. **요지끼리 비교한다.** 긴 질문의 사실관계는 잡음이다. 첫 모델 호출이 사실관계를 뺀 요지를 만든다. 금융위 회신과 해석례에는 질의요지가, 판례에는 판시사항이 있다.
2. **기준점을 둔다.** 비슷함 점수가 기준점보다 낮으면 이 갈래를 쓰지 않는다. 판례 다리에서도 판례가 인용하지 않는 조문을 묻는 질문에서는 다리가 방해가 됐다.
3. **매칭 방식은 형태소 단어 매칭(BM25)으로 시작한다.** 판례 다리가 이 방식으로 첫 쪽 적중 49% → 84%(101건, 같은 판례 제외)를 냈다. 벡터는 바꿔 말한 표현을 잡는 두 번째 신호로 섞는다. GENOS에서는 내부 임베딩을 쓴다.
4. **후보 앞쪽 일부만 차지한다.** 판례 다리는 비슷한 사례 5건의 인용 조문을 앞쪽 8칸에 올렸다. 나머지 칸은 기존 검색 후보다.
5. **판례 조문 번호를 현행으로 맞춘다.** 판례 참조 조문은 판결 당시 번호라 구법 → 현행 대응이 필요하다.
6. **자료가 다루지 않는 주제와 내규**는 우리 대화의 착지 기록이 쌓여야 효과가 난다.
