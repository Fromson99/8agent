# 온톨로지에 대한 의문과 답변

[v4 목차](../../ONTOLOGY_V4.md) · 2026-10-29

[통합 TXT로 읽기](온톨로지_의문점_원문연결_모델입출력_통합.txt)

> 원문을 잘 골라 조합하는 기준을 원문 근거와 함께 저장·검토·재사용한다. 질문마다 반복되는 연결 해석과 조건 조립을 줄이는 것이 목적이다.

## 의문별 답변

| 의문 또는 공격 | 답변 | 근거와 한계 |
|---|---|---|
| 원문을 그냥 조합해서 주면 안 되나 | 가능하다. 단순 조합 뒤에도 모델은 적용 조건·계산 의존·예외를 다시 해석해야 한다. 온톨로지는 그 조립 기준과 결과를 재사용한다. | [실제 원문 연결](01_CM023_원문연결.md) |
| 결국 길어서 줄이려는 것 아닌가 | 길이보다 반복되는 해석·조립 부담이 핵심이다. 판단 단계 축소와 입력 토큰 감소는 별도 지표다. | CM023 선택 실험도 입력 40,868토큰. 입력 절감은 미입증. |
| 필요한 원문만 잘 골라 붙이면 되지 않나 | 그 선택·조합 기준에 조건·예외·원문 판본·검토 이력을 붙여 관리하는 것이 이 설계의 역할이다. | 간단한 단일 조문 질문은 직접 원문 제공으로 충분할 수 있다. |
| 온톨로지도 LLM이 읽어야 하지 않나 | 읽는다. 다만 사전 조립 방식은 연결을 처음부터 해석하고 법률 문장을 만드는 일을 줄이고, 필요한 업무 경로와 충분성을 판단하게 한다. | [실제 모델 입출력](02_CM023_모델입출력.md) |
| 지식그래프면 빠짐없이 찾을 수 있나 | 등록된 관계를 따라갈 수 있다. 관계 데이터의 완전성·필요한 원문의 전수 발견은 별도 문제다. | 관계 존재, 원문 확보, 질문에 대한 충분성을 구분한다. |
| 온톨로지가 더 정확하고 빠른가 | 아직 일반적인 우위는 입증하지 않았다. 같은 원문·질문·모델로 단순 조합 방식과 비교해야 한다. | 알려진 한 묶음의 경로 선택 확인을 전체 법률 품질·속도로 확대하지 않는다. |

## 방식별 책임

| 방식 | 데이터가 준비하는 것 | 질문 시 모델이 하는 것 |
|---|---|---|
| 지식그래프 탐색 | 원문과 등록된 연결 | 연결 선택 → 원문 읽기 → 적용·예외 해석 → 답변 조립 |
| 원문 묶음 제공 | 관련 원문을 한 번에 제공 | 원문 간 역할·계산 의존·조건·예외를 해석 → 답변 조립 |
| 사전 시나리오 방식 | 근거가 연결된 구성요소 → 조건·계산·결과·예외를 조립 | 필요한 경로 선택·충분성 판단, 부족하면 조사 복귀 |

사전 조립에도 잘못된 해석이 들어갈 수 있다. 원문 일치 검사는 의미 정확성을 보장하지 않으므로 내용 검토·승인·게시·판본 변경 시 재검토가 필요하다.
