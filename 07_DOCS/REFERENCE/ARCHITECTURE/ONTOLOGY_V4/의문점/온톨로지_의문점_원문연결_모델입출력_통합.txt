v4 의문점 문서 3개를 순서대로 모은 통합 TXT. 근거 경로는 저장소 루트 기준이다.

================================================================
1. 온톨로지에 대한 의문과 답변
================================================================

원문을 잘 골라 조합하는 기준을 원문 근거와 함께 저장·검토·재사용한다. 질문마다 반복되는 연결 해석과 조건 조립을 줄이는 것이 목적이다.

[의문별 답변]

- 원문을 그냥 조합해서 주면 안 되나
  답변: 가능하다. 단순 조합 뒤에도 모델은 적용 조건·계산 의존·예외를 다시 해석해야 한다. 온톨로지는 그 조립 기준과 결과를 재사용한다.
  근거와 한계: 실제 원문 연결 [근거 1]
- 결국 길어서 줄이려는 것 아닌가
  답변: 길이보다 반복되는 해석·조립 부담이 핵심이다. 판단 단계 축소와 입력 토큰 감소는 별도 지표다.
  근거와 한계: CM023 선택 실험도 입력 40,868토큰. 입력 절감은 미입증.
- 필요한 원문만 잘 골라 붙이면 되지 않나
  답변: 그 선택·조합 기준에 조건·예외·원문 판본·검토 이력을 붙여 관리하는 것이 이 설계의 역할이다.
  근거와 한계: 간단한 단일 조문 질문은 직접 원문 제공으로 충분할 수 있다.
- 온톨로지도 LLM이 읽어야 하지 않나
  답변: 읽는다. 다만 사전 조립 방식은 연결을 처음부터 해석하고 법률 문장을 만드는 일을 줄이고, 필요한 업무 경로와 충분성을 판단하게 한다.
  근거와 한계: 실제 모델 입출력 [근거 2]
- 지식그래프면 빠짐없이 찾을 수 있나
  답변: 등록된 관계를 따라갈 수 있다. 관계 데이터의 완전성·필요한 원문의 전수 발견은 별도 문제다.
  근거와 한계: 관계 존재, 원문 확보, 질문에 대한 충분성을 구분한다.
- 온톨로지가 더 정확하고 빠른가
  답변: 아직 일반적인 우위는 입증하지 않았다. 같은 원문·질문·모델로 단순 조합 방식과 비교해야 한다.
  근거와 한계: 알려진 한 묶음의 경로 선택 확인을 전체 법률 품질·속도로 확대하지 않는다.

[방식별 책임]

- 지식그래프 탐색
  데이터가 준비하는 것: 원문과 등록된 연결
  질문 시 모델이 하는 것: 연결 선택 → 원문 읽기 → 적용·예외 해석 → 답변 조립
- 원문 묶음 제공
  데이터가 준비하는 것: 관련 원문을 한 번에 제공
  질문 시 모델이 하는 것: 원문 간 역할·계산 의존·조건·예외를 해석 → 답변 조립
- 사전 시나리오 방식
  데이터가 준비하는 것: 근거가 연결된 구성요소 → 조건·계산·결과·예외를 조립
  질문 시 모델이 하는 것: 필요한 경로 선택·충분성 판단, 부족하면 조사 복귀

사전 조립에도 잘못된 해석이 들어갈 수 있다. 원문 일치 검사는 의미 정확성을 보장하지 않으므로 내용 검토·승인·게시·판본 변경 시 재검토가 필요하다.

[확인된 범위]

- 실험 자료
  상태: CM023 원문 28조각 → 구성요소 22개 → 시나리오 5개. Codex 작성 연구 자료, 자동 추출·사람 승인된 운영 지식 아님.
- 실제 선택
  상태: 8개 질문·11회 실행에서 사전 경로 선택 기준 통과. 신규 전체 검색을 포함하지 않은 보관 원문 선택 실험.
- 현재 제품
  상태: 2026-10-29 선택 MAIN115, 온톨로지 기본 OFF. MAIN114 이후 요구 검토 ON에서는 시나리오 선택만으로 종료하지 않고 기존 ASSESS에서 질문 전체를 검토.
- 추가 입증
  상태: 단순 원문 조합 대비 조건·예외 누락, 입력 토큰, 모델 호출, 전체 시간, 구축·갱신 비용. 새 실험 수행 전의 비교 항목이다.

[읽는 순서]

1. 원문 연결 [근거 1]: 어떤 조문과 계산·예외가 연결되는가.
2. 모델 입출력 [근거 2]: 실제로 무엇을 주고 무엇을 받았는가.
3. 생성·승인·게시 흐름 [근거 3]: 검토한 자료를 어떻게 사용하는가.

근거: 선택 실험 결과 [근거 4] · 현행 요구 검토 [근거 5] · 활성 포인터 [근거 6]

================================================================
2. CM023 원문에서 시나리오로 연결되는 구조
================================================================

질문: 상장차익 증여의제는 어떤 요건에서 성립하는가?

데이터: 저장 법령 판본의 원문 28조각·구성요소 22개·시나리오 5개. 아래 원문 번호 P1~P28은 실험 패키지 [근거 7]의 번호다. 이 레시피는 연구용 미승인 자료다.

[1 실제 등록된 조문 연결]

법 = 상속세 및 증여세법, 시행령 = 같은 법 시행령. 원문 묶음에 등록된 관계 4개는 모두 DELEGATES_TO다.

- 법 제41조의3 제10항
  연결 원문: 시행령 제31조의3 제1항
  확인할 내용: 상장이익 계산방법
- 법 제41조의3 제1항
  연결 원문: 시행령 제31조의3 제2항
  확인할 내용: 대상 증권시장
- 법 제41조의3 제1항 단서
  연결 원문: 시행령 제31조의3 제3항
  확인할 내용: 적용 제외 기준금액. 저장된 출발 좌표는 제1항.
- 법 제41조의3 제1항 제2호
  연결 원문: 시행령 제31조의3 제4항
  확인할 내용: 25% 이상 소유자의 범위

이 4개는 해당 묶음의 저장 관계 [근거 8]이며 전체 지식그래프의 관계 수가 아니다.

[2 원문을 읽고 조립해야 하는 의미]

- 적용 대상·취득 경로·상장 조건
  실제 근거: P1~P6, P19, P23
  함께 필요한 내용: 최대주주등·특수관계인·취득 경로·기간·시장
- 정산기준일
  실제 근거: P7, P9
  함께 필요한 내용: 상장일부터 3개월, 그 전 사망·증여·양도 시 기준일
- 평가가액·최초가액·기업가치 증가분
  실제 근거: P16~P18, P24~P26
  함께 필요한 내용: 평가 시점, 증가분 계산·서류·대체 계산 범위
- 상장이익 계산
  실제 근거: P15~P18
  함께 필요한 내용: 평가가액에서 최초가액과 기업가치 증가분을 차감한 뒤 주식 수를 곱함
- 기준금액 미달 제외
  실제 근거: P1, P20~P22
  함께 필요한 내용: 이익 계산식과 기준금액 계산식을 함께 사용
- 가액 하락 환급
  실제 근거: P8, P27
  함께 필요한 내용: 가액 하락·기준 충족·환급 가능 범위를 별도 경로로 확인
- 혼재재산 추정·담보 차입 간주
  실제 근거: P6, P10
  함께 필요한 내용: 같은 조문 안에서도 조건과 법률 효과가 다름

아래 화살표는 레시피에 명시한 선행 의존 → 사용 구성요소다. 위 4개 저장 관계와 구분한다.

정산기준일 → 평가가액·최초가액의 정의
정산기준일 → 기업가치 증가분 계산
평가가액·최초가액의 정의 + 기업가치 증가분 계산 → 상장이익 계산
평가가액·최초가액의 정의 + 기업가치 증가분 계산 → 기준금액 계산
상장이익 계산 + 기준금액 계산 → 기준금액 미달 여부
기준금액 미달 여부 → 성립 경로·제외 경로에 반영

근거: 레시피의 requires와 원문 인용 [근거 9]. 마지막 시나리오 반영은 레시피의 경로 구성이다.

[3 미리 조립한 5개 경로]

- PATH1 성립과 정산
  질문의 용도: 일반 성립 요건
  들어가는 내용: 대상·취득·상장 조건 + 정의·산식 + 정산 처리 + 확인 범위
- PATH2 기준금액 미달 제외
  질문의 용도: 적용 제외 여부
  들어가는 내용: 관련 조건 + 이익·기준금액 산식 + 제외 처리
- PATH3 가액 하락 환급
  질문의 용도: 환급 요건
  들어가는 내용: 하락 조건 + 계산 기준 + 환급 가능 범위
- PATH4 혼재재산 취득의 추정
  질문의 용도: 증여재산과 다른 돈이 섞인 경우
  들어가는 내용: 불분명한 취득 조건 + 추정 효과
- PATH5 담보 차입 취득의 간주
  질문의 용도: 증여재산을 담보로 빌린 돈으로 취득
  들어가는 내용: 담보 차입 취득 조건 + 간주 효과

28 → 22 → 5는 구성 단위의 변화이며 압축률이 아니다. PATH1에도 제외 조건 일부가 포함돼 있어 경로 간 내용은 겹친다. 신주·전환사채·부정행위·무상주 확장과 묶음 밖 세부 정의는 모두 펼치지 않았으며, 관련 질문은 추가 원문 확인이 필요하다.

[4 실제로 줄이려는 작업]

- 계산식에 필요한 조문을 다시 연결
  사전 조립 시점으로 옮기는 작업: 구성요소의 선행 의존 명시
- 성립·제외·환급 조건을 다시 구분
  사전 조립 시점으로 옮기는 작업: 업무별 경로와 확인 범위 작성
- 조건·산식·결과를 다시 문장화
  사전 조립 시점으로 옮기는 작업: 원문 인용을 붙인 본문 작성·검토

모델에는 이미 조립한 후보 경로를 주고 필요한 경로와 충분성을 판단하게 한다. 실제 입력과 선택 결과 [근거 2].

================================================================
3. CM023에서 실제로 모델에 준 내용과 받은 결과
================================================================

대상: ADR1150의 CM023 첫 실행. 보관된 원문으로 사전 시나리오를 선택한 실험이다. 현재 MAIN 전체 요청의 입력·호출 횟수를 뜻하지 않는다.

[1 실제 입력 구성]

- 질문
  실제 전달 내용: “상장차익 증여의제는 어떤 요건에서 성립하는가?”와 업무 문맥
- 쟁점
  실제 전달 내용: 질문에 대응하는 쟁점 1개
- 선택 지침
  실제 전달 내용: 일반 성립 질문은 성립과 제외·예외 경로를 함께 선택. 제시된 ID만 사용하고 본문을 다시 쓰지 않음. 충분하면 ANSWER, 부족하면 RESELECT 또는 SEARCH.
- 시나리오 후보
  실제 전달 내용: 5개 모두의 ID·제목·업무 용도·조립 완료 본문
- 근거
  실제 전달 내용: 조문 출처 항목 10개, 현재 원문 근거 선택지 120개
- 제어·출력 계약
  실제 전달 내용: 재선택 잔여 1회, 경로 선택·이유·부족 범위·부족 사실의 응답 스키마

근거: 선택 입력 [근거 10] · 실제 공급자 요청 [근거 11]

[2 모델이 읽는 조립 본문의 예]

PATH2 본문의 산식·처리 부분 발췌다. 실제 본문에는 적용 대상·취득 경로·상장 조건, 정산기준일, 기업가치 증가분 계산, 검토 범위와 출처도 들어간다.

이익 = (정산기준일 현재 1주당 평가가액 − 증여·취득일 현재 1주당 최초가액 − 1주당 기업가치 증가분) × 증여받거나 유상 취득한 주식등의 수.

기준금액 = 다음 두 금액 중 적은 금액: ① (1주당 최초가액 + 1주당 기업가치 증가분) × 증여받거나 유상 취득한 주식등의 수 × 30%, ② 3억원.

이익이 기준금액 미만인 경우에는 법 제41조의3제1항의 적용에서 제외한다. 다른 과세 규정의 적용까지 배제한다는 뜻으로 확대하지 않는다.

이 본문은 실험 전에 작성된 원문 기반 연구 자료다. 이번 요청의 모델이 새로 쓴 문장이나 승인된 운영 지식이 아니다. 전체 본문·원문 [근거 7]

[3 실제 모델 응답]

선택 결과의 핵심 필드 발췌:

{
  "issue_id": "Q1",
  "path_ids": ["PATH1", "PATH2"],
  "status": "GENERAL_RULE",
  "next_action": "ANSWER",
  "missing_scope": [],
  "missing_facts": []
}

선택 이유는 “일반 성립 요건”이므로 성립·산정 경로와 기준금액 미달 제외 경로가 함께 필요하다는 것이었다. 응답 원본 [근거 12]

사전 구성요소·의존 작성 → 코드가 경로 본문 조립
→ 질문 + 후보 경로 5개 + 원문 근거를 모델에 전달
→ 모델이 PATH1·PATH2 선택 → 선택 본문 그대로 발행

[4 측정값과 주장 범위]

- CM023 선택 모델 호출
  관찰: 1회
  의미: 준비된 자료에 대한 첫 응답으로 경로 결정
- 법률 문장 생성 / COMPOSE 모델 호출

  의미: 원문 해석의 법률적 정확성 인증은 아님

- 초기 묶음 방식의 입력 부담
  확인된 사실: ADR1105: 원문 28조각·묶음 관계 4개에 남은 연결 메타데이터 83행도 전달. 온톨로지 원문 3,609자, 전체 사용자 메시지 56,645자. 문자는 토큰과 다르며 83행은 전부 원문을 읽었다는 뜻이 아님.
- 위 실험과의 비교 한계
  확인된 사실: ADR1105의 문자 수와 ADR1150의 토큰 수로 압축률을 계산하지 않는다. 서로 다른 입력·실행 경로다.
- 현행 MAIN115
  확인된 사실: 온톨로지 기본 OFF. MAIN114 이후 요구 검토 ON에서는 온톨로지 입력을 기존 ASSESS에 유지하고 질문 전체 충족을 검토. 위 실험의 선택만으로 종료하는 경로와 다르다.
- 운영 사용 조건
  확인된 사실: 자료 생성 → 내용 검토·승인 → DB 게시 → 사용 ON 및 실제 조회 연결. 이 실험 자료의 운영 게시를 뜻하지 않음.
