# 개념과 설계 결정

[v4 목차](../ONTOLOGY_V4.md)

## 설명가능성과 온톨로지

지식그래프도 관계와 설명을 저장할 수 있다. v4에서 온톨로지의 역할은 객체·관계의 의미와 적용 범위를 명시하고, 어떤 연결을 어떤 조건에서 조합할 수 있는지 제한하는 것이다. 설명가능성은 그 구조와 실제 사용 기록을 사용자에게 드러내는 기능이다.

| 요소 | 의미 | 사용 예 |
|---|---|---|
| 원문·구조 | 문서 판본, 조·항·호·span | 제97조 제1항 제2호의 실제 문장 |
| 개념·역할 | 무엇을 가리키고 어떤 정보를 제공하는가 | 자본적지출액, 인정 범위, 증빙 조건 |
| 의미 관계 | 원문으로 뒷받침되는 연결 의미 | 범위를 위임함, 위임 내용을 구체화함, 상위 조건이 적용됨 |
| 공리·법적 규칙 | 범위가 명시된 사실·정의·조건과 효과 | 특정 조건이 성립할 때 특정 규정의 적용을 제외함 |
| 조사 방법 | 부족한 정보를 찾는 방법 | 선택한 범위의 구체화 근거를 가져옴 |
| 경험·설명 | 경로를 찾고 검토·정정한 이력 | 특정 호만 읽으면 상위 항 조건이 누락됐음 |
| 실행 상태 | 실제 제시·선택·확보·검토 여부 | 경로는 제시했으나 선택하지 않음 |

OWL의 공리는 온톨로지가 참이라고 단언하는 진술이며 개별 관계 사실도 포함할 수 있다. 설명 문장을 붙인 것만으로 형식적 의미나 실행 가능성이 생기지는 않는다. [W3C OWL Primer](https://www.w3.org/TR/owl2-primer/#Modeling_Knowledge:_Basic_Notions).

단서조항은 형식적 규칙의 재료다. 단서라는 문장 형식만으로 예외·제외를 확정하지 않는다. 적용 범위 제한, 조건 보완, 별도 계산 등 실제 역할을 검토한다. 법적 예외의 우선순위와 미확인 처리를 단순 참·거짓으로 축약하지 않는다.

## 질문을 처음부터 완벽하게 분해하지 않는다

질문 초기에는 조사 목적·대상·제공된 사실·시점과 불명확함을 파악한다. 고정 온톨로지 슬롯을 모두 채워야 검색을 시작하는 구조를 만들지 않는다. 초기 분해는 잠정적이며 읽은 원문과 사용자 정정에 따라 새 버전으로 갱신한다.

조문에 도달하면 문서 판본·선택 범위·개념을 기준으로 관련 지식을 회수한다. 이때 제시할 것은 모든 연결의 목록이 아니라 목적과 근거가 있는 경로 묶음이다. 질문의 표현이 달라도 같은 원문에 도달하면 검토 지식을 재사용할 수 있다. 잘못된 최초 조문에 도달했거나 관련 묶음이 없으면 기존 검색으로 돌아간다.

## 경로 묶음의 선택

다음은 실험 판본을 이용한 설계 예이며 현행법 해석 인증이 아니다.

> 자본적지출액의 인정 범위 확인: 제97조 제1항 제2호가 위임한 범위를 시행령 제163조 제3항에서 확인한다. 선택한 세부 항목에 적용되는 제3항 본문의 공통 조건도 함께 확인한다.

같은 묶음은 다음 두 표현을 가진다.

- 사용자·LLM에게: 목적, 포함될 정보, 연결 이유, 적용 범위, 미확인, 검토 이력.
- 실행기에게: 출발 원문·개념, 검토된 관계 ID와 버전, 목적 원문·최소 범위, 필요한 상위 조건, 허용 행동.

묶음을 선택하면 코드는 확정된 경로의 원문을 가져오고 이미 읽은 범위는 재사용한다. 새로운 적용 판단·다중 후보·미확인 조건이 등장하면 그 지점에서 다시 선택한다. 매 간선마다 별도 LLM 호출을 요구하지 않는다. 설명을 보고 선택하는 기존 판단 호출을 활용하고 새 호출 비용은 별도 계측한다.

이 기능은 대화 수정 이후에만 열리는 부가 기능이 아니다. 첫 조사에서 조문을 확보했을 때부터 관계를 회수하고 계획·설명을 자동으로 구성해야 한다. 실제 진입점과 설명/실행의 동일성 계약은 [조문 도착부터 원문 묶음까지](SOURCE_ENTRY_COMPOSITION.md)에 구체화한다.

등록된 경로 재사용과 새 경로 조합은 구분한다. 새 조합은 구성 관계가 유효하더라도 전체 경로의 적용 검토가 필요할 수 있다. A가 B를 준용하고 B가 C를 참조한다는 이유로 A에 C 전체를 적용하지 않는다. 일반 그래프 도달성과 법적 의존은 다르다.

## 최소 범위와 상위 조건

선택한 호·목의 직접 원문과 그 범위에 적용된다고 확인한 상위 본문·조건을 함께 가져온다. 상위 조의 모든 하위 조항을 자동으로 가져오지 않는다. 하위 항목을 제한하는 상위 조건과, 단순히 같은 조에 있다는 이유로 연결된 다른 항목을 구분한다.

원문이 대통령령 등을 언급하지만 정확한 대상이 아직 없으면 대상 미확인 후보로 남긴다. LLM이 생성한 조항 번호를 검증 없이 실행 경로로 쓰지 않는다. 실제 색인·구조 조회·원문 근거로 목적지가 확인된 뒤 경로에 결속한다.

## 근거 조회에서 변경 영향 분석으로

| 수준 | 필요한 구조 | 제공할 기능 |
|---|---|---|
| 근거 조립 | 목적·관계·원문 범위 | 필요한 자료를 한 묶음으로 읽기 |
| 영향 추적 | 조건·근거·판단의 의존관계 | 변경 시 다시 볼 판단과 답변 찾기 |
| 결과 재평가 | 명시된 식·조건·적용 판단 경계 | 변경 전후 결과·미확인 비교 |

설명 문장을 컴파일하는 것이 아니라, 검토된 의미와 의존관계를 실행 계획으로 바꾼다. 사람용 설명은 같은 계획과 실행 receipt에서 구성한다. 숨겨진 모델 내부 사고를 재현한다고 주장하지 않는다.

일반적인 사실·규칙 기반 조합은 [Datalog 예시](https://souffle-lang.github.io/tutorial), 의사결정의 의존관계·규칙 명세는 [OMG DMN](https://www.omg.org/dmn/)을 참고할 수 있다. 이 자료는 설계 참고이며 특정 엔진 도입이나 우리 성능을 증명하지 않는다.

## 이번 대화에서 채택한 방향

| 결정 | 이유 |
|---|---|
| 사용 중 조사·정정을 지식 생산의 중심으로 둠 | 문서 전체의 의미를 미리 완성해야 하는 부담을 피함 |
| 대화 표현과 게시 형식을 분리 | 자유로운 발견을 보존하면서 재사용·실행을 통제 |
| 질문보다 원문·개념에 지식 결속 | 다른 질문에도 같은 정정과 근거를 재사용 |
| 관계 묶음의 설명과 실제 실행을 결속 | 설명을 다시 해석하는 호출과 실행 불일치 억제 |
| 정정과 시나리오를 다른 변경으로 처리 | 잘못된 지식 수정과 가정 실험의 혼동 방지 |
| 영향 있음과 결론 변경을 구분 | 재검토 대상 발견만으로 결론을 반전시키지 않음 |

이 원칙은 지식의 완전성을 보증하지 않는다. 그래프 밖의 누락과 새로운 해석은 일반 조사·사용자 검토로 발견하고 후보로 추가한다.
