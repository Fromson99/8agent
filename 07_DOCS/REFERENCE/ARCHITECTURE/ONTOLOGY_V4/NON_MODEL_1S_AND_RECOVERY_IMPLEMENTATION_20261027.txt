최종 주장 연결 실패의 직접 원인과 복구 한계:
1120 실제 14·15번째 응답은 claims=[]인 채 J5/J6/J9를 CONDITIONAL로 표시했다. 앞선 요약의 USE라는 표현은 채택 계열을 뭉뚱그린 것으로, 해당 실제 값은 CONDITIONAL이다. 각 이유에는 추가 확인 필요·본문 미확보가 적혀 있었다. 모델 출력이 "최종 주장에 조건부 채택"과 "추가 확인을 위해 보류"를 구분하지 못한 것으로 해석되며 모델 내부 원인은 단정하지 않는다.
1125의 최소1개 참조 조건 이후에도 claims는 빈 배열이고 세 판단의 claim_refs에 C1/C2/C3만 추가됐다. 배열 형식 조건은 실제 다른 필드에 그 주장과 근거가 존재한다는 관계까지 보장하지 못한다. 런타임 검증은 이를 올바르게 거절했다.
completion_execution은 final_judgment.validate_review를 먼저 수행하고, 성공한 평가에 대해서만 gap 결속과 추가 조사 복귀를 실행한다. 보완1회 후 판단 연결이 계속 틀리면 InvestigationPending으로 종료하여 뒤의 ASSESS_GAP_REENTRY에 도달하지 못한다. 이 파일은 후보와 MAIN107이 동일하다. 후보의 independent_read_recovery는 조사 중 READ 판단 오류를 다루며 최종 ASSESS 판단 오류까지 분리 복구하지 않는다.
추가로 1120은 부족 이유에 제29조/시행령 제24조를 썼지만 missing_target에는 이미 읽은 제28조를 제출했다. 그 화면의 locator_options 42개에는 시행령 제24조가 있고 법률 제29조는 없었다. 실제 추가 조사 대상을 선택하는 오류도 남아 있어, 채택 상태만 바꾸면 반드시 완주한다고 단정할 수 없다.

현재 MAIN 반영 범위 재확인:
선택 MAIN107 / genos-mode-20261027-r1 유지. 1129 대비 제품·설정22파일과 엔진/PIPELINE31파일, 합계53차이가 있으며 해당 작업 경로53개 모두 활성 MAIN107과 동일(신규3파일은 작업 경로에 없음)하다.
MAIN에는 공통 최소입력,20개 표시 페이지,요청 원장 근거 SQL배치,GENOS 모드 연결이 이미 있다. 이번 후보의 현재20개만 상세 준비,법령명 전용 조회/검증기 재사용,원문 배치/길이 계산,검색 결과 재사용,조사 전체 고정번호,new_reviews/revisions,상세 오류,독립 읽기 복구,카탈로그 이름 결속은 미반영이다.
별도 온톨로지 후보의 원문 묶음→ASSESS 전달,의미 컴파일,사전 시나리오 조립·경로 선택·재선택/기존 탐색 복귀도 MAIN107에 미반영이다. 최신 관련1135는 실제 복귀·일반 답변 완료를 확인했으나 복수 경로 누락 등 사전 전체 기준 미달로 Rejected다. 다른 후보 성공을1129 성공 또는 MAIN 반영으로 합치지 않는다.
