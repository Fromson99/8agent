## 1. 현재 적용 기준

이 문서는 기존 상세 계획의 8절 입력·출력 계약과 9절 문자 상한, 그 상한에 의존하는 실패·완료 기준보다 우선한다. 원문 선택, 승인 온톨로지의 A1/A2 동일 정보, 부분 판단 보완, 미검토 보존 원칙은 기존 계획을 이어 사용한다. 과거 ADR의 스키마·한도·측정치·실패 결과는 바꾸지 않는다.

- 전체 적중 법령의 간결한 목록, 조문 후보 최대 20개와 더 보기를 유지한다. 후보는 원문을 읽었다는 증거가 아니다.
- `candidate_navigation.minimal_action_choices=true`로 새 계약을 사용하며 `task_local_navigation=true`가 필요하다. 기존 경로의 계약은 별도로 보존한다.
- 선택한 원문과 필요한 상위 조건을 읽고, 현재 작업에 필요한 원문·판단·미확인·실행 가능한 메뉴를 보낸다. 무관한 전체 이력은 서버에 보존한다.
- `candidate_navigation.enforce_input_character_limits=false`를 유지한다. 단계별 문자 상한과 최종 100,000자 앱 차단은 적용하지 않으며, 실제 요청 크기와 해시는 기록한다. 원문 페이지와 조사 범위 선택은 유지한다.
- 출력 토큰 상한은 없다. 기존 총 40회 물리 호출·1,024회 도구·1,800초와 보완·종료 예산은 공유한다. 제공자 자체 문맥 한도는 별도다.

## 2. 행동별 필요한 정보

아래 필드는 논리 계약이다. `choice`, `target`, 법령 번호 `law`는 단일 후보여도 명시적으로 선택한다. 그 외 현재 메뉴와 스키마로 값이 확정된 필드만 생략할 수 있으며 서버가 원래 객체로 복원한다. 여러 가능한 값이 있거나 새 의미를 결정해야 하면 모델이 반드시 선택한다. 조사 목적의 전송 이름은 `reason`이고 내부 canonical 이름은 `missing_need`다. `READ`에서는 `selections[*].reason`을 같은 방식으로 복원한다.

| 행동 | 모델이 볼 입력 | 모델이 결정할 내용 | 서버가 조립할 수 있는 내용 |
|---|---|---|---|
| 메뉴·법령·목차·다음 페이지 이동 (`OPEN_TASK`, `OPEN_LAW`, `BROWSE_STRUCTURE`, `NEXT_*`, `VIEW_SAVED_SOURCE` 등) | 현재 질문·쟁점, 현재 선택 가능한 메뉴와 대상, 출발 목적이 있으면 그 검증된 결속 | `choice`와 `target` 또는 법령 번호. 검증된 출발 목적이 없으면 `reason`과 필요한 쟁점 | 선택한 대상의 도구 좌표, 화면 식별자·revision. 단순 이동은 같은 검증된 출발 목적을 상속. 이동을 원문 확보나 검토로 표시하지 않음 |
| 원문 읽기 (`READ`, `READ_PARENT`, `READ_SCOPE` 등) | 후보의 위치·범위, 필요한 상위 문맥, 관련 출발 원문·판단, 현재 읽을 수 있는 대상 | 읽을 대상·범위와 `reason`. 아직 확정되지 않은 `issue_id`, `relation`, `source_ref`, `judgment_refs` | 선택한 대상의 도구 좌표, 검증된 departure의 쟁점·관계·출발 원문·판단 참조. 새 읽기 이유를 고정하거나 채택·충분성을 생성하지 않음 |
| 새 검색·정확한 위치 찾기 (`RESEARCH`, `SEARCH_BODY`, `LOCATE` 등) | 질문·실제 사용자 사실·관련 쟁점, 이전 검색과 결과 상태, 허용 검색·구조 필터 계약 | 행동·대상, 새 검색어 `queries`, 위치·범위 `structure_filter`, `reason`과 미확정 쟁점·출발점 | 허용 문서 범위와 선택한 도구 좌표, 검증된 departure의 쟁점·관계·출발 원문·판단 참조. 새 이유·검색어·범위는 만들지 않음 |
| 연결 따라가기 (`FOLLOW_CONNECTION` 등) | 선택 가능한 연결의 대상·범위·단서, 출발 원문과 관련 판단, 온톨로지의 미확보·남은 연결 | 어떤 연결·범위를 조사할지와 `reason`. 확정되지 않은 관계·출발 판단은 명시 선택 | 같은 검증된 departure의 쟁점·관계·출발 원문·판단 참조. 새 연결 이유를 고정하거나 연결 후보를 승인된 법률 결론으로 바꾸지 않음 |
| 현재 원문 판단 (`read_review`) | 현재 원문과 필수 조건·예외, 직접 관련된 기존 판단·미해결, 판단에 필요한 사용자 사실 | 원문을 어떻게 쓰는지, 이유·근거·부족·충돌과 필요한 변경분 | 불변 식별자·판본·span 결속, 기존 `KEEP` 판단의 원내용. 미제출 판단은 미완료로 보존 |
| 조사 마무리 (`FINISH`, `PENDING`) | 검토한 원문·판단, 미검토·미확보, 질문·조건·예외·남은 작업 | 사용할 근거·쟁점, 충분성 또는 중단·미확인의 이유 | 기존 근거 식별자와 검증된 상태. 충분성·법률 결론을 기본값으로 채우지 않음 |
| 판단 행 보완 | 지정 오류 행의 실제 원문·상위 조건, 관련 기존 판단, 구체 오류와 보류 행동의 목적 | 지정 행의 수정 내용 | 정상 행·보류 행동·허용 근거·기대 revision 고정. 전체 메뉴와 정상 판단을 다시 작성시키지 않음 |
| 최종 평가·답변 (`ASSESS`, `COMPOSE`) | 평가에는 필요한 실제 원문·검증된 판단·사용자 사실·미해결, 답변에는 검증된 주장·인용·한계 | 법률 적용·조건·예외·충돌·충분성 및 답변 표현 | 표시용 출처·인용 결속. 조사 완료와 답변 완성을 서로 대신하지 않음 |

메뉴 안내와 응답 스키마는 같은 현재 행동 집합에서 만든다. 다른 행동의 필드를 이번 행동의 필수 입력으로 요구하지 않는다. 실제 필드 이름과 허용값은 해당 후보의 canonical 계약이 정본이며, 이 표를 근거로 존재하지 않는 도구나 응답 필드를 추가하지 않는다.

## 3. 시스템 조립과 모델 판단의 경계

서버 조립은 현재 요청의 스키마 literal, 행동·대상 선택을 제외한 유일한 허용값, 모델이 이미 선택한 불변 메뉴 항목의 도구 좌표, 같은 상태에서 검증된 출발 정보에 한정한다. `READ.selections[*].target`도 단일 후보라는 이유로 없애지 않는다. 어떤 규칙과 메뉴·상태로 복원했는지 원제안과 함께 기록하고, 복원한 객체를 기존 canonical 스키마와 상태 검증에 통과시킨다.

다중 쟁점 중 하나를 임의로 고르거나, 새 `missing_need`·이유·검색어를 만들거나, 원문이 하나라는 이유만으로 의존 출발점으로 정하지 않는다. `DIRECT`·빈 `judgment_refs`를 일반 기본값으로 넣어 출발 판단 검사를 통과시키지 않는다. 근거 충분성·법률 판단·충돌 해소는 모델 책임으로 남는다.

검증된 departure가 있으면 `issue_id`, `relation`, `source_ref`, `judgment_refs`와 필요한 출발 원문·상위 조건을 같은 값으로 유지한다. `missing_need`까지 상속하는 것은 `NAVIGATION_CHOICES`에 속하는 단순 메뉴·페이지 이동뿐이다. `READ`, 새 검색, `LOCATE`, `FOLLOW_CONNECTION`에서는 모델이 현재 행동의 새 `reason`을 작성할 수 있다. 출발 쟁점·관계·원문·판단을 바꾸려면 출발 화면에서 명시적으로 새 선택을 한다. 다음 화면의 `sources`가 비었다는 이유로 `DEPENDENCY`를 `DIRECT`로 바꾸지 않으며, 같은 실패·같은 상태의 메뉴 왕복은 새 보완 예산이나 새 근거가 아니다.

## 4. 빈 검토와 미제출 판단

현재 원문이 없고 검토 스키마의 모든 관련 배열이 실제로 빈 값으로 확정된 경우에는 모델에 빈 `read_review` 재작성을 요구하지 않고 서버가 복원한다. **`sources=[]`만으로 기존 필요·충돌까지 비었다고 간주하지 않는다.** 남아 있는 판단·미해결이 허용하는 응답은 유지한다.

현재 원문이 있는 부분 검토 계약에서는 `read_review`를 선택 필드로 보낸다. 미제출이면 서버가 빈 검토 배열을 조립하고 시스템 상태를 `PENDING` 또는 `INCOMPLETE`로 남긴다. 빈 검토를 `DEFER`, 검토 완료, 채택 또는 부족 해소라는 모델 의견으로 만들지 않는다. 다음 행동의 출발 판단이 필요하면 그 판단이 유효해야 실행할 수 있다. 필요한 행은 기존 행 보완 경로로 처리하고, 다른 원문의 미검토는 전역 대기열에 보존한다.

## 5. 전송 형식과 보완

전송 스키마의 **행동별 분기는 각각 완전한 object**여야 한다. 각 분기에 실제 `properties`, `required`, `additionalProperties`를 둔다. 생성기가 상위 객체의 공통 속성을 분기에 합쳐 줄 것이라고 가정하지 않는다. 원래 의미 스키마와 허용 대상 검증은 서버에 그대로 둔다.

정상 요청, 전송 전 preview, 전체 객체 보완은 같은 compiler·decoder와 전체 현재 메뉴 참조를 사용한다. 여기서 전체 메뉴는 **현재 작업에서 선택 가능한 메뉴**이며 요청 전체의 과거 메뉴가 아니다. 응답에 쓰인 별칭·대상은 같은 메뉴와 화면·상태에 결속한다. 보완 때만 다른 스키마나 일부 참조표를 쓰지 않는다.

새 경로는 gateway의 추가 `navigation_cards/table_columns`·`navigation_values` 변환, `from_article_candidate`, 출력 키 별칭, schema 공유·`$defs`, 중복 minimal 변환을 적용하지 않는다. **법령 목록 `law_matches.rows`와 선택 범위 `action_scopes` 같은 명시적 목록 참조는 유지한다.** 행동별 필요 정보와 검증된 값의 복원으로 계약을 작게 만든다.

`read_review_patch.configure_choice_contract(wire_schema, decoder, prompt)`에 등록한 전체 선택 보완(`CURRENT_REVIEW_TASK`)은 정상 입력의 현재 후보·메뉴·범위·참조를 보존하고 같은 전송 스키마·프롬프트에 오류 진단만 추가한다. 같은 decoder 뒤 canonical 검증을 거친다. 판단 행 보완(`READ_REVIEW_ROWS`)의 정상 행·행동 고정 계약은 별도로 유지한다.

전체 객체 형식 오류는 기존 `bounded_decision/read-choice` 담당이 같은 view와 구체 오류로 1회 보완한다. gateway의 동일 스키마 오류 재시도는 추가하지 않는다. 판단 행 보완은 정상 행과 행동을 고정한 기존 경로를 사용한다. 반복 실패는 원인·미검토·사용량을 보존하고 종료하며, 없는 대상·원문/권한/해시 불일치·stale 상태는 모델 보완으로 우회하지 않는다.

## 6. 기존 실행·원문·온톨로지 연결

진입은 후보의 `service.py` → `POST /v1/rag/ask` → `unified-v6`다. 조사에서는 `law_navigation`의 현재 화면 → `decision_projection.choose_read` → `action_choice_contract.prepare` → `structured/gateway` → decoder와 원래 canonical 검증 → 검토 전이 `READY` → 기존 `execute_tool` 순서를 유지한다. 실제 읽기 뒤의 온톨로지 도착·확보·전달도 기존 경로를 따른다. 별도 조사 실행기나 상태 저장소를 만들지 않는다.

행동을 제안한 기록과 실제 도구 성공 receipt를 구분한다. 메뉴 이동은 원문 확보가 아니며, 원문 확보·모델 전달·검토·답변 사용은 각각 기록한다. 승인 묶음은 기존 권한·판본·span을 확인하고 같은 도착 상태의 A1/A2에 같은 원문·역할·관계·메모·미확보 정보를 제공한다. 이 계약은 묶음 저장 스키마나 승인·골드 적재 절차를 바꾸지 않는다. 원문 전달 전용 자식 경로도 기존 전달·미검토 계약을 유지한다.

## 7. 응답 예시

다음 ID는 설명용이다. 실제 응답은 그 요청의 메뉴에 제시된 ID만 사용할 수 있다. 예시에 없는 쟁점·출발점 필드가 생략되려면 현재 스키마에서 값이 확정됐거나 같은 검증된 departure에서 상속돼야 한다.

**원문이 없는 첫 목차 선택:** 현재 메뉴의 `T1`이 목차 작업으로 이동하는 `OPEN_TASK`이고, 현재 쟁점과 `DIRECT`·빈 출발점·빈 검토가 스키마로 확정됐으며 검증된 이전 목적이 없는 경우다. 대상이 하나여도 `target`을 쓰고 처음 조사할 이유를 낸다.

```json
{"choice":"OPEN_TASK","target":"T1","reason":"질문에 해당하는 조항의 위치를 확인한다."}
```

**검증된 출발 목적을 유지하는 다음 페이지:** `NEXT_ARTICLES`가 현재 메뉴에 있고, 같은 상태의 출발 쟁점·관계·원문·판단 참조·목적이 모두 유효한 경우다. 단순 이동이므로 목적은 상속한다.

```json
{"choice":"NEXT_ARTICLES","target":"T2"}
```

**새 검색과 필요한 쟁점·출발점 선택:** 검증된 departure가 아직 없고, 여러 쟁점과 현재 원문이 있어 선택이 필요한 경우다. `Q2`, `P1`, `J1`은 현재 메뉴와 유효한 판단에서 고른다. 이미 검증된 departure가 있다면 그 네 필드는 같은 값으로 복원하고, 새 검색어와 `reason`은 계속 모델이 작성한다.

```json
{"choice":"RESEARCH","target":"T3","queries":["보고 AND 예외"],"reason":"출발 조항이 위임한 예외 조건을 확인한다.","issue_id":"Q2","relation":"DEPENDENCY","source_ref":"P1","judgment_refs":["J1"]}
```

이 응답만으로 `P1`·`J1`이 유효해지는 것은 아니다. 실제 원문·판단·상태 검증을 통과해야 조사 도구를 실행한다.
