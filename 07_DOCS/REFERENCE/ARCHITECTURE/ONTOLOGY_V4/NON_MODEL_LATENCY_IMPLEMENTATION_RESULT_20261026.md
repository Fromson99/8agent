## 구현한 내용

- 기존 R2 수집기를 v3로 확장했다. 모델 호출 시도 구간의 합집합, 함수·구간별 wall/CPU, 스키마 준비·본문 검사·직렬화·원문·상태·초기 자원 준비를 나눈다. 작은 coarse 모드는 샘플러·GC 관찰을 켜지 않는다. 계측되지 않은 값은 0초로 해석하지 않는다.
- 초기 준비 함수21개, resource6단계, session7단계를 추가 연결했다. contextmanager는 생성 시점이 아니라 실제 내부 구간을 잰다. 서비스 반환 예정 시점과 비동기 보고서 enqueue/시작/cleanup 포함 완료도 별도 숫자로 기록한다. 이번 서비스 실험은 공유 보고서 finalizer를 켜지 않았으므로 그 비용은 미측정이다.
- 같은 스키마의 검사기 준비를 요청 내에서 재사용한다. 인스턴스·현재 state·권한 검사는 계속 수행하며, 스키마 키 삽입 순서와 오류 선택 순서를 보존한다. 캐시는 32개/추정4MiB로 제한하고 외부 참조 등 지원하지 않는 경우 기존 검사로 돌아간다.
- 같은 actions hash를 중복 계산하지 않고, 저장 view의 canonical JSON을 한 번 인코딩해 hash와 저장에 함께 사용한다. 실제 전송 준비 전체를 재사용하는 변경은 하지 않았다.
- 같은 원문을 재표시할 때 표시 ID만 달라져 온톨로지 receipt 충돌이 나던 부분을 수정했다. 과거 실제 전달 view와 해시를 확인한 뒤 표시 ID를 제외한 내용의 digest를 비교한다. 원문·좌표·판본·권한 변경은 허용하지 않으며 최초 receipt와 재전달 이력을 보존한다.

## 실패와 온톨로지 상태

ADR1067의 실모델 실행은 예정9셀 중 첫 A0 셀에서 중단됐다. 물리 호출1회, 토큰·비용 usage 미수신이며 0원으로 표시하지 않는다. A1/A2와 나머지8셀은 미실행이다. 추가 모델을 맹목 재호출하거나 제공자를 바꾸지 않았다.

오프라인 재생은 과거 요청과 현재 요청의 상태 결속 차이를 그대로 거부한다. 진단용 중단 예외가 Starlette에서 `No response returned.`와 묶여 반환되어1067·1068의 실행기는 실패 상태를 남겼다.1068은 이름 있는 초기 준비의98.266%를 실제로 기록했지만, 진단 종료 분류까지 성공한 것으로 표시하지 않는다. B1 서비스 진단은 미실행이다. 실패 run만 남으므로 두 ADR의 `validate --final`에서 complete run 없음 제약은 통과하지 못했다. 새 결과를 얻기 위해 중단 기록·예산을 지우지 않았다.

온톨로지의 표시 ID 충돌은 작은 재전달·변조 검사7개로 수정 확인했다. 이번 실모델은 온톨로지에 도달하기 전에 중단됐다. **온톨로지 개념이 실패했다거나 효과가 입증됐다고 결론 내릴 수 없다.** 기존1066에서 A1/A2 승인 묶음 전달이 관찰된 사실은 보존한다.

## GENOS와 비교할 수 있는 범위

GENOS10월22일 사진 전사에는 전체232.284초·모델131.839초·그 밖100.445초가 있다. 실제 현장 코드 해시·데이터 세대·DB 모드가 확인되지 않아 이번17.605초와 속도비를 계산하지 않는다. 내부 모델과 외부 Qwen3.8도 다르다. [근거별 비교](../../../../06_TOOLS/EXPERIMENTS/adr_1067/genos-comparison-notes.json).

신규 v3 프로브는 현재 실험 후보에 연결했다. 기존 GENOS R2 패키지는 변경하지 않았으며 새 ZIP·메일·현장 적용은 하지 않았다. GENOS에서는 필요한 자료만 Oracle/API에서 요청 중 사용해야 한다. 이번 로컬 초기 준비 결과를 근거로 전체 원문·색인을 GENOS 서버에 복제하는 최적화를 제안하지 않는다.
