조사 감시자 설계 — 실패 탐지·행동 차단·방향 전환
2026-10-28 / 설계 제안 / 구현·실험·MAIN 반영 아님

1. 결론과 적용 기준

서버가 매 행동의 반복·범위 누락·예산·계약 오류를 감지하고, 의미 판단이 필요한 때만 감시 모델을 호출한다. 감시 결과는 다음 도구 실행 전 서버 게이트가 집행한다. 감시자가 설명만 추가하거나 주 모델에게 같은 요청을 무한 재전송하는 구조로 만들지 않는다.

중지는 세 종류로 나눈다.
가. 행동 중지: 현재 제안한 반복 읽기를 취소하고 다른 조사 경로로 전환한다.
나. 조사 종료: 확보한 근거와 남은 쟁점을 기존 ASSESS 단계에 넘긴다. 답변 채택·법률적 충분성을 자동 선언하지 않는다.
다. 요청 중단: 권한·원문 결속·충족 불가능한 스키마·자원·예산 문제로 물리 호출을 차단한다. 감시 모델은 이를 해제할 수 없다.

기준은 ACTIVE_RELEASE generation 111, ontology-workflow-20261028-r1이다. 선택 코드 루트는 08_DEPLOYMENT/RELEASES/ontology-workflow-20261028-r1/code다. 아래 코드 경로는 이 루트 기준이다.
실패 관측은 ADR1161의 MAIN110 기반 ADR1155 rev002 격리 후보에서 발생했다. 이를 MAIN111 실제 실행 결과로 부르지 않는다. 후보 전체를 MAIN111에 덮어쓰지 않고 필요한 변경만 재결합한다.

2. 실패별 기존 방식 → 관측 → 변경 → 원하는 결과

[CM001: 실행할 수 없는 입력 계약]
기존: 전달된 근거가 없어도 ANSWERABLE 대안을 만들었다.
관측: basis_refs minItems=1/maxItems=0으로 제공자가 스키마 자체를 거부했다. 실행기는 오류 봉투를 모델/제공자 불일치로 잘못 분류했다.
변경: 전달·권한 검증된 근거가 없는 상태에서는 해당 대안을 생성하지 않는다. NEEDS_SOURCE 등 실행 가능한 대안은 남긴다. 실제 오류 본문을 분류하고 동일 스키마 재전송을 막는다.
원하는 결과: 모델 호출 전에 계약 오류를 잡는다. 감시 AI로 서버 버그를 우회하거나 근거를 만들어 넣지 않는다.
검증: 빈 근거/일부 근거/전체 근거 계약의 실제 충족 가능성 검사. 문법 검사 통과만으로 완료 처리하지 않는다.

[CM007: 부분 확보 후 다른 적용 범위 누락]
기존: 법령별 상위 8개와 전체 화면 20개를 보고 읽기·연결 탐색을 선택했다. 진전 없음 기록은 행동 중단으로 이어지지 않았다.
관측: 코스닥 제13조는 65.610초에 모델에 전달됐다. 연결 탐색 1회에서 반환된 28개에는 유가증권시장 제13조가 없었다. 유가증권시장 규정의 검색 건수는 92였으나 준비된 첫 8개에도 해당 조항은 없었다. 실제 행동은 READ 32회, FOLLOW_CONNECTION 1회였고 검색 변경·다음 페이지·법령 확장으로 넘어가지 않았다.
해석 한계: 전체 검색 순위에서 해당 조항의 위치와 전체 그래프의 연결 부재를 입증한 것은 아니다. 반환된 연결 목록을 확인했다는 것과 필요한 범위를 모두 조사했다는 것은 다르다.
변경: 쟁점별 적용 범위와 미확인 탐색 경로를 별도로 유지한다. 한 시장의 근거 확보를 다른 시장까지 답변 가능하다고 취급하지 않는다. 상위 목록 밖 후보로 이동하는 명시적 경로를 제공한다.
원하는 결과: 같은 종류의 무관한 원문 읽기를 잠시 막고, 미확인 범위에서 검색 수정·법령 확장·페이지 이동 중 근거 있는 경로를 선택한다.
검증: 등록 정답을 제품 입력에 넣지 않고 동일 누락을 재현한다. 사용자 질문이 특정 시장으로 한정된 경우에는 다른 시장을 강제로 추가하지 않는다.

[CM009: 진전 없음과 유효한 후속 조사 공존]
관측: 코스닥 제13조는 51.408초에 전달됐다. 진전 없음 2회가 입력에 나타난 시점은 141.969초이고, 연결된 제31조 전달은 198.371초였다. 이후 반복 조사가 지속돼 호스트 자원 보호로 중단됐다.
변경: 진전 없음 2회는 감시 요청 조건으로만 사용한다. 미해결 예외·위임·적용 조건과 연결된 새 원문은 제한적으로 계속 읽게 한다.
원하는 결과: 중복·무관한 읽기는 차단하고, 실제 필요한 제31조 같은 의존 원문 확보는 보존한다.
한계: 초기 원문 도착 시각을 최종 답변 가능 시각이나 감시자 도입 후 예상 종료 시각으로 사용하지 않는다. 호스트 스왑 증가를 이 요청 하나의 책임으로 단정하지 않는다.

[최종 판단 보완 실패]
관측: CM007의 실제 C1 근거와 J3/J9의 USE 연결이 맞지 않았다. 보완 입력 안에 거절 주장 C2와 오류 명세 키 C1이 함께 있었고, 보완 출력도 이전 출력과 구조적으로 같았다.
변경: 고정 번호의 값뿐 아니라 claim_evidence_refs 같은 참조용 사전 키까지 동일한 타입별 매핑으로 처리한다. 보완 전후 검증 오류 지문을 비교해 같은 오류의 무변경 반복을 종료한다.
원하는 결과: 잘못된 판단은 채택하지 않는다. 별도의 유효한 원문 부족 대상은 기존 독립 읽기 복구를 통해 조사할 수 있다.
한계: 번호 불일치가 반복 출력의 단독 원인이었다는 인과효과는 미검증이다. 감시자만 추가하면 근거 연결이 해결된다고 보장하지 않는다.

3. 감시자가 보는 상태

서버의 요청별 supervisor_state에 다음을 보관한다. 아래는 새 내부 계약 제안이며 현재 구현된 필드명이 아니다.
- request_key, state_revision, scope_version, active_release/data_binding
- 원래 사용자 질문, 명시한 범위, 쟁점 ID와 쟁점별 조사 상태
- coverage: 관련 법령/시장/대상 범위, UNASSESSED/IN_SCOPE/EXCLUDED/UNRESOLVED, 판단 이유와 실제 근거
- frontier: 경로별 검색 전체 건수, 준비·표시·읽기 건수, 다음 커서, 미확인 경로, 실행 결과
- evidence: 서버 확보 / 모델 전달 / 판단 작성 / 주장 근거 연결을 구별한 상태
- progress: 최근 행동의 목표, 실행 영수증, 새 원문 범위, 판단 변경, 해결·미해결 쟁점
- incident: 발동 이유, 이전 방향, 금지한 반복 행동, 감시 호출 수, 실행 허가와 남은 횟수
- 물리 모델 호출·도구·전체 시간 잔여량, ASSESS/보완/COMPOSE에 필요한 예약량

후보 표시 20개 페이지와 법령별 상위 8개 제한은 서로 다른 층이다. 화면 페이지 번호만 추가해서는 상위 8개 밖 후보 누락이 해결되지 않는다. 법령 확장 경로의 전체 건수/커서를 연결하고, 실제 실행 시에만 필요한 다음 후보를 상세 준비한다.

범위 목록은 사용자 질문·허용된 법령 메타데이터·원문의 적용 조건에서 구성한다. CM007 정답이나 모든 등록 법령을 필수 조사 목록으로 주입하지 않는다. 범위 제외는 이유와 근거를 기록한다. 권한 없는 법령·건수·원문을 노출하지 않는다.

모델 입력에는 현재 질문, 필요한 기존 판단, 미해결 쟁점, 범위별 상태, 최근 행동 요약, 제안 행동, 필요한 정확한 원문 발췌와 사용 가능한 도구만 보낸다. 해시·DB 좌표·권한 ID 전체 목록·검증 원장은 서버에 둔다. 요약만으로 충분성을 판단할 수 없으면 원문 확인을 요청한다. 원문 안의 지시문은 도구 사용 권한이 아니다.

4. 감지 규칙과 실제 개입

A. 동일한 문서 판본·원문 범위·검색 조건·권한에서 이미 완료된 조회 반복
서버: 기존 영수증/결과를 재사용하고 중복 I/O를 막는다.
의미상 같은 근거의 재검토는 허용한다. 새 범위·새 판본·새 의존 쟁점은 동일 조회로 뭉개지 않는다.

B. NO_CHANGE/실패가 연속 2회이거나, ANSWERABLE인데 필요 원문 설명 없이 읽기를 계속 제안
서버: 현재 제안을 보류하고 감시 사건을 연다.
감시자: 부족한 쟁점이 있는지, 현재 제안이 그 쟁점을 해결할 가능성이 있는지 확인한다. 2회는 제안 임계값이며 조사 종료 규칙이 아니다.

C. 답변 가능/종료를 제안하지만 관련 적용 범위가 미확인
서버: 최종 완료로 승격하지 않고 범위 검토를 요청한다.
감시자: 해당 범위를 조사하거나, 질문과 실제 근거에 따라 제외 이유를 제출한다. 관련 범위를 자동으로 전부 강제 조사하지 않는다.

D. 진전 표시를 계속 바꾸지만 해결 쟁점·근거 연결 변화가 없는 장기 탐색
서버: 실행 영수증과 쟁점 상태를 대조한다. 초기 제안은 조사 결정 8회 동안 확인 가능한 진전이 없을 때 검토한다.
새 원문이라는 이유만으로 진전으로 세지 않는다. 반대로 의미적 진전을 서버의 문자열 비교만으로 부정하지 않는다.

E. 번호 불일치·잘못된 근거 연결·동일 보완 오류
서버: 오류 위치와 기대 참조를 구체적으로 반환한다. 허용된 보완 후 동일 오류이면 해당 판단 채택을 중단한다.
유효한 독립 읽기 요청은 별도로 검증해 실행할 수 있다. 잘못된 판단을 삭제해 성공으로 꾸미지 않는다.

F. 충족 불가능한 스키마·권한/결속 오류·예산/자원 한도
서버: 호출을 중단하고 원인을 분류한다. 감시 모델을 추가로 불러 해결하게 하지 않는다. 자원 한도는 배포 환경의 정책이며 실험 호스트의 512MiB 스왑 기준을 제품에 그대로 고정하지 않는다.

5. 감시 결과 계약과 집행 흐름

내부 출력 종류:
CONTINUE_TARGETED: 현재 필요한 구체적 원문/연결 탐색을 제한적으로 허용.
REDIRECT: 다른 검색·법령 확장·미확인 페이지·연결 경로로 전환.
ASSESS_NOW: 확보 근거와 남은 범위를 기존 최종 판단 단계에 전달.
STOP_UNRESOLVED: 더 진행할 유효 경로나 예산이 없음을 기록. 정상 답변 성공을 뜻하지 않는다.

각 출력은 대상 쟁점, 미해결 사항, 현재 화면의 유효한 도구/대상 또는 허용된 검색 조건, 기대 변화, 허가 종료 조건, 근거 참조를 포함한다. 숨겨진 원문 ID를 추측해서 실행하지 않는다. 대상이 없으면 먼저 기존 카탈로그/법령 확장 도구로 후보를 확보하고 갱신된 상태에서 결속한다.

실행 순서:
(1) 주 모델의 다음 행동 제안 또는 루프 시작 상태 확인
(2) 서버 계약·예산 검사와 감시 조건 검사
(3) 필요시 기존 모델 게이트웨이를 통해 감시 호출
(4) 감시 결과를 현행 권한·도구·대상 계약으로 검증
(5) 기존 제안은 CANCELLED_BY_SUPERVISOR로 기록하고, 검증된 허가를 accepted 상태에 저장
(6) 기존 도구 실행 경로로 실행
(7) 실제 영수증으로 목표 달성 여부와 남은 범위 갱신
(8) 허가 소진 후 재평가 또는 ASSESS 전달

감시 결과를 주 모델에게 조언만 한 뒤 동일 행동을 허용하지 않는다. 이미 검증된 전환 행동은 기존 실행기를 통해 수행해 같은 의도를 다시 말하도록 만드는 추가 호출을 줄인다. 다단계 경로는 앞 단계 결과로 대상이 확정된 뒤 다음 단계를 검증한다.
초기 제안은 전환 허가당 도구 행동 최대 2회다. 법령 확장 후 읽기 등 결과에 의존하는 단계는 각각 검증하며 부족한 단계를 몰래 한 행동으로 묶지 않는다.
같은 사건은 request+issue+범위+분기+근거 상태로 식별한다. 검색 문구를 바꾸거나 번호를 다시 붙이는 것만으로 감시 예산을 초기화하지 않는다.

6. 호출 한도·실패·재개

감시자는 요청당 물리 호출 최대 2회를 초기 제안으로 둔다. 재시도·스키마 보완·429 재시도도 이 2회에 포함한다. 주 모델과 같은 기존 총 40회에서 차감하며 별도 무제한 예산을 주지 않는다. 총 도구 1024회·요청 1800초도 그대로 공유한다.

repository.reserve_attempt는 현재 phase=='investigate'일 때만 finalization_reserve를 뺀다. 새 supervisor phase를 단순 추가하면 최종화 예약을 소비할 위험이 있다. 조사 비용 범주에 명시적으로 포함하거나 동일한 예약 정책으로 결속해야 한다.
기존 finalization_reserve=3, tool_finalization_reserve=4, selection_time_reserve_seconds=30을 보존한다. 감시 호출 허용 전에 현재 최종화 경로의 ASSESS/필요 보완/COMPOSE 예약이 실제로 남는지 확인한다. 3회만 남으면 모든 보완까지 성공한다는 보장은 없다.

감시 모델 실패·무효 출력·허가 만료·추가 호출 한도 도달 시 보류한 반복 루프로 그대로 복귀하지 않는다. 이미 검증된 유효 허가가 있으면 남은 행동만 수행한다. 그 외에는 확보 근거와 미해결 쟁점을 ASSESS로 넘기거나 기존 제한/보류/실패 상태로 마감한다. 최종 검증을 통과하지 않은 문장을 정상 답변으로 게시하지 않는다.

요청 재개 시 incident, counters, permit, 예약된 물리 시도, accepted action, 완료 영수증을 기존 체크포인트와 함께 복원한다. 소유자/상태 리비전 검증으로 늦게 도착한 감시 결과를 거부한다. 이미 끝난 도구는 영수증을 재사용하고, 제공자 송신 여부가 불명확한 시도를 자동 재발송하지 않는다.
현재 run()의 accepted.before 복원 목록과 completion_budget.restore에 새 상태가 빠지면 재개 때 예산이 초기화될 수 있으므로 필수 변경·검증 지점이다.

GENOS에 별도의 영속 감시 작업 레지스트리를 만들지 않는다. 로컬은 기존 요청 저장소를 사용한다. 향후 현장은 Dataiku가 작업·진행·로그·취소를 관리하고 GENOS는 현재 계산을 수행한다. 감시 판단·이력은 에이전트 기록이며 승인된 온톨로지/골드로 자동 게시하지 않는다. 현장 배선 완료를 이 설계로 주장하지 않는다.

8. 검증·도입·롤백

1단계: 선행 오류와 탐색 누락 경로 수정

2단계: 저장 입력·로그 및 합성 계약 검사 — 새 모델 호출 0
- CM001의 실제 빈 근거 상태에서 불가능한 대안 없음.
- CM007의 주장 사전 키/값 왕복 후 같은 주장. 본문 숫자 불변.
- 연결 결과 28개 완료가 전체 적용 범위 완료로 바뀌지 않음.
- 상위 8개 밖 후보로 이동할 수 있고 권한/버전/페이지가 보존됨.
- CM009처럼 진전 없음 뒤 필요한 새 의존 원문은 허용.
- 차단된 제안은 실제 도구 실행 0회. 유효한 전환만 실행.
- 감시 실패/무변경/늦은 응답/재개/429에서 예산 증가·중복 실행 없음.
- 잘못된 최종 판단 채택은 막고 독립 읽기 복구는 유지.
- 특정 시장 질문에서 불필요한 전체 시장 확장 없음.
저장 로그로 감지 시점과 차단 계약은 검증할 수 있지만 새로운 전환 뒤 모델이 정답을 만드는지는 알 수 없다.

3단계: 별도 승인된 새 실험
실험 표준에 따라 새 ADR 예약·동결 후 MAIN111 기반 기준군과 변경군을 동일 데이터/모델/예산으로 비교한다. 알려진 3문항은 in-sample이다. 기준답변·필수근거는 제품 입력과 분리한다. 미사용 질문의 새 조사 경로를 별도로 확인한다.
shadow의 실제 감시 모델 호출도 비용과 물리 호출에 포함한다. 저장 로그의 규칙 shadow와 실제 모델 shadow를 구분한다. 이번 문서 작성은 어느 모델 실행도 승인·수행한 것이 아니다.

4단계: 실제 서비스와 MAIN
동일 검증 코드/데이터 결속 → 실제 서비스에서 원문 전달·판단·주장 근거·최종 답변·저장 상태 확인 → 승격 여부 결정. 선택 MAIN의 파일 해시와 서비스 소비 코드를 확인한다. 모의 HTTP 성공을 실제 모델 조사 성공으로 대체하지 않는다.

롤백:
신규 요청은 기능 OFF 또는 이전 검증 릴리스로 전환. 진행 요청은 고정된 코드/계약 버전에 유지하거나 안전한 체크포인트에서 중단한다. 진행 중에 새 상태만 제거하고 구버전으로 재개하지 않는다. 과거 로그·실패·예산 원장은 보존한다. 스키마/번호 오류 수정은 감시 기능 OFF와 독립적으로 유지할 수 있게 분리한다.

9. 효과·비용·판정 기준

측정할 것:
- 필요한 근거가 후보에 존재/표시/선택/전달됐는지 각각 측정.

- 유효한 연결 조사 오차단, 불필요한 범위 확장, 감시 무효 응답.
- 실제 주장 작성·근거 연결·완료/제한/기술 실패의 구분.
- 원문 일치·권한·고정 번호·재개·예산 위반.
- 요청 전체 시간과 모델 시간, 용어집만 제외한 전체 비LLM 시간. 감시 입력 준비·화면·검증·복구·저장 비용도 포함.

기술적 목표: 차단 후 금지 행동 실행, 예산 초과, 원문/권한 위반은 허용하지 않는다. 품질 평가는 미사용 질문에서 필요한 조사 오차단과 완성 답변을 따로 확인한다. 3문항 개선만으로 법률 품질 인증하지 않는다.

시간 절감 = 제거된 모델/도구/화면 시간 - 감시 모델/입력 준비/방향 전환 추가 시간.
비용 절감 = 제거된 호출의 실제 토큰 비용 - 감시 및 추가 경로의 실제 토큰 비용.
호출 수가 줄어도 큰 감시 입력 때문에 비용/시간이 늘 수 있다. 같은 Qwen 감시자도 주 모델의 의미 오류를 반복할 수 있어 독립된 정답 판정기로 간주하지 않는다.
1초는 용어집 제외 요청 전체 비LLM 시간의 기존 목표다. 이번 설계의 달성 예측치나 보장치가 아니다.

수치의 성격:
O1 관측: ADR1161 물리 호출 71=2+38+31, 최종 게시 답변 0. 전반적 정답률로 일반화 금지.
