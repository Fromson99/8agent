# 조문 도착에서 설명과 원문 묶음까지

[v4 목차](../ONTOLOGY_V4.md) · [프로토타입 구현](PROTOTYPE_DESIGN.md) · [컴파일과 변경 영향](COMPILATION_AND_SCENARIOS.md)

2026-10-23 사용자 추가 요구 반영. **이력 기반 정정과 별개로, 조문에 도착하면 관계를 회수하고 목적에 맞는 경로를 컴파일해 설명과 원문 묶음을 제공하는 기능을 프로토타입의 필수 구현 범위로 둔다.** 이전 대화·사용자 수정·시나리오가 없는 첫 조사에서도 작동해야 한다. 아래는 구현 설계이며 현재 제품에서 실행되는 기능이라고 보고하지 않는다.

## 사용자가 보게 될 흐름

~~~mermaid
flowchart LR
    A["조문 원문 확보"] --> B["해당 범위의 관계·개념 회수"]
    B --> C["목적별 경로 컴파일"]
    C --> D["동일 계획에서 설명 자동 생성"]
    D --> E["사용자 또는 조사 LLM의 묶음 선택"]
    E --> F["선택 경로 실행·확보 원문 재사용"]
    F --> G["목적 원문·상위 조건·경로·미확인 제공"]
    B --> H["관계 미확인·묶음 없음"]
    H --> I["기존 직접 탐색"]
    F --> J["새 분기·적용 판단 필요"]
    J --> D
~~~

관계 회수·후보 계획 작성·설명 렌더링은 조문 도착을 계기로 자동 수행한다. 필요 경로 선택은 현재 질문·원문을 보는 기존 조사 판단에서 수행할 수 있다. 사용자가 묶음을 명시적으로 선택한 경우에도 같은 실행기를 사용한다. 매 간선마다 사용자 승인을 요구하거나 별도 LLM 호출로 다음 번호를 생성하지 않는다.

자동이라는 말은 모든 연결을 무조건 끝까지 읽는 뜻이 아니다. 선택한 목적과 원문 범위 안에서 확정된 계획을 실행한다. 다른 목적·새 적용 조건·미해결 목적지가 나오면 그 부분만 선택 또는 직접 탐색으로 넘긴다. 예전의 고정 2단계 선읽기를 되살리는 요구로 해석하지 않는다.

위 비교는 코드 확인이며 새 전체 흐름의 실측은 아직 없다. 작업·선택 코드 차이는 [SOURCE_ENTRY_EVIDENCE.json](SOURCE_ENTRY_EVIDENCE.json)에 별도로 기록한다. 조문 진입점은 원문 저장 트랜잭션 안에서 외부 조회하지 않고, 저장 성공 후 기존 조사 실행기가 처리한다. 조회 실패로 이미 확보한 원문을 롤백하지 않는다. Investigation 외 읽기 진입도 같은 도착 계약에 매핑해 특정 화면에서만 작동하는 기능을 만들지 않는다.

## 회수와 컴파일의 입력

최초 질문을 완전한 규칙으로 분해할 필요는 없다. 도착한 조문에서 이번에 필요한 정보가 무엇인지 잠정 목적을 선택하고, 더 읽으며 구체화한다. 예를 들어 인정 범위, 상위 제한, 절차, 예외 중 어떤 내용을 더 확인할지 기존 조사 판단이 제안한다. 이는 실행 템플릿 선택이며 자유로운 질문 전체를 정적 슬롯에 강제하는 것이 아니다.

서버가 현재 source receipt에서 문서 판본·조항·span·권한·hash를 결속한다. 원문 anchor와 목적, 지식 release/revision, 시점·범위, 기존 확보 원문, 남은 예산으로 후보를 조회한다. 질문 문자열만 검색해서 과거 답변을 가져오는 경로로 대체하지 않는다.

회수 대상은 검토된 원문 중심 관계·METHOD와 현재 확인된 명시 참조다. 과거 정정 이력은 근거 중 하나이며 필수 입력이 아니다. 아직 검토되지 않은 의미 연결이나 목적지가 풀리지 않은 참조는 후보/부족으로 분리한다. 신규 대화에서 관계가 없으면 일반 원문 탐색으로 이어지고, 그 과정에서 발견한 관계는 기존 정규화 후보 절차로 축적한다.

## 원하는 관계까지의 경계

계획은 출발 anchor, 필요한 정보 역할, 허용 관계 합성, 목적 원문 범위, 필요한 상위 조건과 종료 조건을 갖는다. 단순히 두 번 이동하거나 연결된 모든 노드를 훑는 방식으로 목적을 대신하지 않는다.

| 단계 | 코드가 해야 할 일 | 남기는 결과 |
|---|---|---|
| 관계 후보 구성 | 출발 원문에 근거가 있는 간선·개념과 현재 지식 버전 결속 | 실제 관계/후보/미확인을 구분한 목록 |
| 경로 합성 | 등록된 합성 규칙으로 목적 역할까지 연결; 방향·개념·범위·판본 검사 | 실행 가능한 묶음, 일부만 가능한 묶음, 미지원 사유 |
| 최소 범위 구성 | 목표 항·호·목과 적용 상위 본문 조건을 포함, 무관한 형제 범위 제외 | 노드별 원문 범위 및 포함 이유 |
| 계획 고정 | 읽기 대상·도구·선행 의존·재사용·분기·종료 기준 결속 | plan ID/revision/hash와 사용자 설명 |
| 선택·실행 | 표시된 계획 ID 선택, 상태 재검증, 기존 원문 읽기 도구 실행 | 실제 확보·재사용·실패·대기 receipt |
| 완료 판단 | 선택한 필수 범위의 확보·전달 여부와 unresolved 확인 | 경로 확보 완료/부분 확보/검토 필요와 실제 원문 |

경로 확보 완료는 이번 묶음의 원문을 가져왔다는 뜻이다. 법률 적용·질문 전체의 근거 충분성이 확정됐다는 뜻은 아니다. 순환·예산·권한·해결되지 않은 목표가 있으면 영향을 받는 블록과 이미 확보한 원문을 보여준다. 계획 확대는 새 revision으로 기록하고 원래 선택 범위를 조용히 바꾸지 않는다.

## 설명도 컴파일 산출물이다

컴파일러가 만든 계획의 목적·관계·범위·조건·미확인을 정해진 표현 템플릿으로 렌더링한다. 관계를 설명하는 검토 문구가 있으면 그 버전에 결속해 사용한다. 사용자가 읽는 설명과 도구 실행이 같은 plan ID를 참조한다. 설명만 먼저 자유 생성하고 그 문장을 다른 LLM이 해석해 도구를 선택하는 단계를 두지 않는다.

설명에는 다음 네 가지가 반드시 들어간다.

1. 이 묶음으로 무엇을 확인하려는가.
2. 현재 조문에서 어떤 관계를 통해 어디까지 가는가.
3. 어떤 원문·상위 조건을 포함하며 무엇은 아직 미확인인가.
4. 현재는 실행 예정인지, 실제 확보·재사용·부분 실패한 결과인지.

컴파일과 기본 설명 생성에는 별도 LLM 호출이 필요하지 않다. 자연어 설명을 다듬는 선택 기능을 추가하더라도 새 사실·관계·필요성을 만들지 못하며 원 계획과 대응을 검증한다. 기본 구현의 필수 단계로 만들지 않는다. 초기 경로의 필요성 선택과 새 법률 해석은 기존 판단 호출에서 맡고 그 이유를 별도 기록한다.

## 우리 조문 흐름의 예

다음은 앞서 논의한 실험 판본을 사용하는 설계 예이며, 신규 실험·현행법 해석 확인이 아니다. 아래 관계와 범위가 해당 판본에서 확인·결속되어 있다는 전제다.

~~~text
도착: 제97조 제1항 제2호
현재 목적: 자본적지출액 등의 세부 범위 확인
관계 묶음: 범위 위임 → 대응 세부 규정 → 선택 범위에 적용되는 상위 본문 조건
목표: 시행령 제163조 제3항의 해당 항목과 적용 본문
~~~

실행 전에는 “이 조문이 위임한 자본적지출액 등의 범위를 확인하기 위해 시행령 제163조 제3항의 해당 항목과 공통 조건을 함께 가져옵니다”라는 설명을 계획에서 조립한다. 정확한 목적 항목이 아직 결정되지 않았다면 해당 항목을 확정한 것처럼 쓰지 않고 선택이 필요한 지점을 표시한다.

선택 후에는 실제 읽은 원문·조항·판본, 그 원문이 포함된 관계 경로, 상위 본문 조건, 제외/미확보 범위를 한 묶음으로 반환한다. 제163조 전체나 다른 비용 범주를 자동 포함하지 않는다. 반환 대상이 아직 검증되지 않았으면 조항 번호를 추정해 실행하지 않는다. 과거 ADR-1037이 이 경로를 완료했다고 표현하지 않는다.

사용자가 세부 범위를 요청해 조사 LLM이 이 묶음을 선택했다면 확정된 중간 관계는 코드가 이어서 읽는다. 새로운 적용 분기나 해석이 나타날 때만 해당 원문과 후보를 기존 판단 단계로 넘긴다. 성공한 조회를 설명 생성 때문에 다시 실행하지 않는다.

## 프로토타입 계약과 검증

최소 계약은 source-entry 입력, route candidate, 고정 실행 계획, 설명 projection, result bundle이다. 기존 v4 실행 계획·receipt를 확장하며 별도 골드 kind를 다섯 개 만드는 뜻이 아니다. 탐색 후보·선택·실행 기록은 Agent, 검토된 원문 중심 관계·METHOD는 Gold 책임을 유지한다.

프로토타입에서는 합성 원문 A의 위임 → B의 세부 항목 → B의 적용 상위 본문을 사용하고, 무관한 형제 항목 C를 둔다. 이전 대화 이력 없이 A에 도착하면 묶음 설명이 나타나고, 선택하면 B와 적용 본문만 확보돼야 한다. 필수 검사는 다음과 같다.

- 첫 방문·이력 없음: 지식과 원문 관계만으로 후보 계획·설명·읽기 완료가 연결된다.
- 설명-실행 일치: 설명에 포함한 확정 대상과 실제 계획이 일치하며 실행 후 실패 상태도 반영된다.
- 중간 판단 추가 없음: 확정 경로의 코드 조립·기본 설명·읽기 단계는 추가 LLM 호출 0회. 최초 선택과 새로운 의미 판단 호출은 별도 계수한다.
- 중복·재개: 같은 anchor/범위/지식/목적/상태의 재표시가 같은 조회를 반복하지 않는다. 목표·판본 변경 시 이전 계획을 재사용하지 않는다.
- 누락·분기: 상위 조건 미확보, 목적지 다중 후보, 관계 미지원, 예산 소진을 완료로 숨기지 않는다.
- 권한·무결성: 새로 권한이 철회되거나 hash가 달라지면 해당 경로를 재검증하며 무관한 확보 원문은 보존한다.
- 소비자: 기존 조사 LLM·사용자 화면·최종 답변이 같은 plan/receipt와 실제 원문 묶음을 소비한다.

근거 원문·조건을 가져오는 이 기능의 통과를 조건 변경 계산기의 통과로 대체하지 않는다. 반대로 이 흐름의 성공만으로 법률 정답률을 인증하지 않는다. 회수·컴파일·설명·실행의 지연과 토큰은 따로 측정한다. 관계가 많거나 대부분 미확인이면 추가 조회·설명 비용으로 악화될 수 있으므로 한도·부분 표시·직접 탐색 복귀를 함께 검증한다.
