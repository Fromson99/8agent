# 성능 주장의 검증 설계

[v4 목차](../ONTOLOGY_V4.md) · [멀티턴 Legal agent](MULTITURN_LEGAL_AGENT.md) · [구현 설계](PROTOTYPE_DESIGN.md) · [검증·도입](VALIDATION_AND_ROLLOUT.md)

2026-10-24 사용자 요구: 벡터 검색의 진입 이후 한계, 모델을 키운 에이전트와의 비교, 사용 중 축적한 온톨로지의 문제 해결·조건 변경 활용을 증거로 보여준다. **유리한 결론을 전제하지 않고 반증 가능한 주장으로 검증한다.** 이 문서는 평가 설계안과 기존 근거 정리다. ADR 선점·실행 계획 동결·새 모델 호출·기존 결과 재채점·제품 변경을 수행하지 않았다. 아래 비교군과 지표는 실행 완료나 사전 등록된 확정 실험이 아니다.

## 증명하려는 제품 가치

구체적인 업무에서 발견하고 수정한 필요·근거·조건·관계를 원문 중심 지식으로 보존하고, 이를 다른 질문의 조사·근거 조립·설명·정정·변경 재평가에 재사용한다. 처음부터 법률 지식이 완성돼 있다고 가정하지 않는다. 더 강한 모델과 검색을 활용하면서도 검토한 지식과 실행 상태가 다음 요청에 남는 구조를 목표로 한다.

| 사용자 문제의식 | 검증할 주장 | 반증·축소 조건 |
|---|---|---|
| 벡터는 진입점만 찾고 연결점을 못 찾는가 | H1: 선택한 과업·예산에서 단발 유사도 검색보다 관계를 활용한 처리가 필수 근거 묶음·상위 조건·예외를 더 안정적으로 확보한다 | 단발/강한 검색 기준군이 같은 정확도·비용을 보이면 해당 범위의 추가 이점 미입증 |
| 에이전트만 쓰거나 모델만 키우면 해결되는가 | H2: 같은 도구·자료·예산에서 모델 교체 효과와 검토 지식/상태 사용 효과가 구분되며, 강한 모델에도 후자의 추가 가치가 남는다 | 강한 모델 기준군과 정확도·검토 부담·비용 차이가 없으면 추가 가치 주장을 축소 |
| 문서만 보고 그래프를 만들면 되지 않는가 | H3: 사용 중 목적·교정이 있는 축적이 정해진 업무 범위에서 문서 단독 추출보다 유효한 재사용 지식을 만든다 | 단독 추출이 같은 검토 시간·비용에서 같거나 낫다면 사용 중 축적의 우월성 미입증 |
| 사람이 채운 지식이 다른 질문에도 쓰이는가 | H4: 한 사례의 교정이 같은 원문/개념의 별도 질문·다른 사건 조건에 정확히 전이되고, 무관 범위는 바꾸지 않는다 | 같은 문장의 재질문만 좋아지거나 새 질문에 잘못 일반화하면 재사용 주장 실패 |
| 값 하나를 바꾸면 영향이 계산되는가 | H5: 검토된 조건·입출력 의존 안에서 변경 결과와 영향 범위를 정확히 재평가하고, 새 조문/미등록 관계가 필요하면 미확인과 다음 조사를 표시한다 | 영향 누락·무관 판단 변경·미등록 경로를 계산 완료로 표시하면 해당 지원 범위 실패 |

“벡터로는 불가능”, “큰 모델은 법률 특화가 아니어서 안 됨”, “온톨로지를 쓰면 모든 문제가 해결”은 현재 근거로 주장하지 않는다. 유사도 검색도 연결된 조문 자체를 회수할 수 있고, 반복 검색·정확한 조항 조회·그래프 확장을 결합할 수 있다. 모델의 학습 규모·전문화 여부만으로 원인을 확정하지 않는다. 필요한 원문이 도구로 노출됐는지, 실제 입력에 전달됐는지, 선택·해석·제어·계약 중 어디서 실패했는지 나눈다.

| v4 설계·문서 검사 | 구현 경계와 검증 요구가 기록됨 | 새 프로토타입이 실제 작동하거나 품질이 개선됐다는 주장 |

ADR-1037에서 보인 source_ref 누락 같은 출력 계약 실패와 법률적 필요 판단의 실패를 분리한다. 하나의 모델·질문·실행에서 생긴 오류를 모델 크기나 비전문성의 인과 효과로 설명하지 않는다. 기존 실험 질문은 개발/진단 자료로 쓸 수 있지만 새로운 미사용 평가라고 부르지 않는다.

## 비교군: 약한 벡터만 이겨서는 부족하다

| 비교군 제안 | 입력·기능 | 분리하려는 효과 |
|---|---|---|
| R0 단발 dense 검색 | 질문 임베딩과 원문 청크 top-k, 동일 답변 모델 | 단발 유사도 회수 기준 |
| R1 강한 일반 검색 | lexical+dense, rerank, 개발 자료로 고정한 검색 설정 | 단순 검색 설정이 약해서 생긴 차이 제거 |
| A 반복 조사 에이전트 | R1·정확한 조항 조회·같은 원문/관계 조회 도구·동일 세션 이력/중복 방지, 공유 의미 지식은 없음 | 매번 모델이 다음 조사와 적용성을 구성하는 비용·누락 |
| G 명시 참조 그래프 | A + 문서의 확인된 인용/위임 대상·구조 관계 | 그래프 경로 자체와 검토된 의미/조건의 차이 |
| N 교정 메모 검색 | A + 동일 피드백·검토 내용을 자연어 메모/대화 기억으로 회수 | 정보를 더 준 효과와 구조화 재사용 효과 구분 |
| O v4 | 공통 조사·상태 기반 + 검토된 원문 관계·조건·방법 + 컴파일/영향/지식 정정 | 제한된 형식·실행·버전 있는 지식 재사용의 추가 효과 |

R0/R1만으로 전체 v4의 가치를 설명하지 않는다. A도 같은 조회 도구와 정상적인 멀티턴 이력·중복 방지를 사용할 수 있어야 한다. 이런 기반을 O에만 주면 상태 관리 효과를 온톨로지 효과로 잘못 부르게 된다. G가 충분하다면 해당 과업의 개선은 명시 참조 그래프 효과로 보고한다. N과 O에는 동일한 의미 정보·피드백을 제공하고 표현·소비 방식의 차이를 비교한다. 이와 별도로 신규 시스템 전체의 통합 성능을 측정할 수 있지만 단일 기능의 원인으로 설명하지 않는다.

기준군도 개발 세트에서 합리적으로 설정한다. top-k·청크 크기·임베딩·reranker·조항 조회·재질의 정책·문서 필터를 고정하고, O만 큰 문맥/시간을 받지 않게 한다. 한 모델의 문맥 한도에 맞춘 동일 입력 비교와 각 모델의 실용 설정 비교는 다른 결과로 표시한다. 대형 문맥에 원문을 충분히 넣는 강한 기준군도 제한된 문서 묶음에서 추가할 수 있다. 입력에서 정답 조문만 선별해 준 상한 진단과 원문 전체를 제공한 실용 비교는 구분한다.

## H1: 진입 적중과 연결 근거 확보를 분리한다

두 트랙을 함께 둔다.

1. **질문부터 시작:** 각 방법이 처음부터 검색한다. 진입 조문 적중, 이후 필요한 원문 확보, 실제 모델 전달, 최종 사용을 단계별로 측정한다.
2. **같은 진입점 제공:** 사전에 고정한 같은 출발 조문·원문을 모든 방법에 준다. 이후 필수 근거·상위 조건·예외 회수 능력을 비교한다. 성공한 진입 사례만 결과를 본 뒤 골라 비교하지 않는다. 대상 조문/정답 경로는 제공하지 않는다.

평가 단위는 조문 하나의 적중을 넘어 질문 목적에 필요한 근거 묶음이다. 정답 검토자는 필수 span·적용 범위·상위 조건·허용 가능한 대안 근거/경로를 사전에 작성한다. 특정 한 경로만 정답으로 강제하거나 온톨로지에 등록된 간선을 정답 목록으로 재사용하지 않는다. “비용의 대분류”와 “구체적 인정 범위”는 요구 수준이 다르므로 목적과 수용 답변 범위를 먼저 고정한다.

실험 판본의 제97조→위임 범위→시행령 세부 규정→상위 조건 사례는 알려진 진단 예다. 신규 평가는 정의, 위임, 준용, 예외, 상위 본문 제한, 별표/시점 등 다른 독립 조문 묶음으로 구성한다. 관계가 필요 없는 단순 질문도 넣어 쓸데없는 탐색 확대를 측정한다. 모든 새 연결을 명시 참조로 찾을 수 있다고 전제하지 않는다.

## H2: 모델 교체와 구조 효과를 교차 비교한다

| 모델 | A: 일반 조사 | G/N: 그래프 또는 메모 | O: v4 |
|---|---|---|---|
| 현행 외부 기본 모델 | 기준 실행 | 관계/메모 효과 | 같은 모델의 v4 효과 |
| 강한 비교 모델 | 모델 교체 효과 | 강한 모델의 관계/메모 효과 | 강한 모델에도 남는 v4 효과 |

핵심 비교는 같은 모델의 A↔O와, 각 구조에서 기본↔강한 모델이다. 기본 모델 O와 강한 모델 A의 비용·품질 비교도 유용하지만 모델 효과와 구조 효과를 분리하는 비교를 대신하지 않는다. 더 큰 모델을 자동으로 더 좋은 모델로 간주하지 않는다. 모델 ID·제공자·양자화·추론 설정·문맥·도구 지원·가격 기준일을 호출 전에 고정한다. 같은 비용/시간 예산 비교와 각 모델의 권장 사용 조건 비교를 따로 보고한다. 강한 모델의 추론 기능을 불합리하게 꺼 두고 우열을 주장하지 않는다.

현재 [외부 모델 정책](../../../../00_SYSTEM/EXPERIMENT_MODEL_POLICY.json)의 기본값은 qwen/qwen3.8-27b, Parasail FP8, reasoning none, fallback 없음이다. 사용자가 다른 모델 비교의 필요성을 제시했으므로 후속 실험에서 비교 모델·역할·범위를 명시적으로 정하되 이번 설계에서 전역 정책을 바꾸거나 임의 모델을 호출하지 않는다. 구체 비교 모델과 비용 한도는 아직 미정이다. 모델 자체 답변 비교는 격리 벤치마크, 도구를 사용하는 전체 에이전트 비교는 그 역할과 별도 scoped 정책을 정확히 동결한다. 기존 특정 ADR의 GENOS 대리 모델 승인을 새 모델 비교 전체로 확대하지 않는다. 현행 출력 토큰 상한 없음 정책을 유지한다.

오류는 회수 실패, 원문 전달 누락, 적용 범위/예외 판단, 잘못된 다음 행동, 상태 보존/계약 오류, 제공자 실패로 분류한다. 원문을 모두 준 오프라인 진단은 회수와 해석 병목을 구분할 수 있지만 제품 성능과 별도다. 코드·도구가 막은 행동을 모델의 법률 이해 부족으로 집계하지 않는다. 대형 모델이 모든 평가 과업을 잘 해결하면 그 사실을 인정하고 재사용·검토·비용·변경 관리의 추가 가치만 판단한다.

## H3/H4: 지식은 사용 중 채우고 다른 과업에 전이한다

두 종류의 비교를 분리한다.

- **생산 방식 비교:** 문서 단독 추출, 실제 사용·정정 기반 축적을 같은 원문/등록 타입·검증 경로에서 비교한다. 처리한 원문 범위, 사용자 피드백 양, 모델 비용, 사람 검토 시간을 기록한다. 동일 자원 비교와 실제 운영 방식 비교를 구분한다. 사용 중 축적만 전문가의 정답을 받고 비용을 제외하면 공정한 비교가 아니다.
- **표현·재사용 비교:** 같은 교정 내용과 근거를 A의 대화 이력, N의 검색 가능한 메모, O의 원문·조건·의존 구조로 저장한다. 같은 의미 정보에서 회수·적용·정정·변경 재평가 차이를 본다.

다음 단계는 각기 다른 사건·질문을 사용한다. 같은 원문을 재사용하는 목적 평가와 새로운 원문으로 일반화하는 평가를 혼동하지 않는다.

| 단계 | 허용하는 정보·행동 | 관찰 |
|---|---|---|
| 시작 | 공통 원문과 사전 지정한 seed 지식. 대상 관계가 없는 cold 영역도 포함 | 시작 지식량·구축 비용·범위 |
| 발견/교정 | 질문 Q1의 조사·오류·사용자 수정. 같은 피드백을 지정 비교군에 제공 | 유효한 후보 생성·정정 성공·미매핑·검토 시간 |
| 지식 동결 | 교정 후 K1 지식(골드 적재분 또는 고정한 S3 revision)/메모 버전 고정 | test gold를 보지 않은 지식 형성 계보 |
| 재사용 | 새 세션 Q2: 같은 원문/개념, 다른 질문·사실·확인 목적. Q1의 답을 그대로 복사해 풀 수 없게 설계 | 필수 근거·적용 정확성, 비용, 잘못된 일반화 |
| 새 범위 | Q3: 아직 축적하지 않은 조문/관계 | 부족 표시와 새 탐색, 미등록을 부재로 오인하는지 |
| 조건 변경 | Q4: 입력/한도/예외/관계의 명시적 변경 | 영향·재계산·새 조문·미확인·무관 부분 보존 |

Q2의 결과를 본 뒤 K1을 고쳐 같은 Q2를 독립 평가로 보고하지 않는다. 계속 학습하는 평가라면 매 시점의 공개 가능 정보와 평가 순서를 사전 고정하고 순차 평가로 표시한다. 여러 의역 질문·같은 조문 파생 문제를 독립 표본으로 부풀리지 않는다. 사용자 시뮬레이터는 미리 동결한 답변/피드백 계약을 사용하고 평가 정답을 임의로 전달하지 않는다. 실제 사람 사용성 검사는 별도로 검토자·순서·학습 효과를 통제한다.

지식 축적량의 증가가 목표 자체는 아니다. 유효한 재사용·틀린 지식 수정·다른 범위의 오염 억제·개정 시 재검토를 평가한다. 잘못된 사용자 교정·반대 근거·원문 개정도 포함한다. 동일 원문의 역할이 질문마다 다를 수 있으므로 한 사람의 선택을 보편적 필수 경로로 만들지 않는다.

## H5: 변경 영향·규칙 재평가를 입증한다

여기서 먼저 검증하는 것은 **형식화한 규칙과 의존관계 안에서의 변경 영향**이다. 법령 금액을 바꿨을 때 현실의 행동·경제·위험이 얼마나 달라질지 예측하는 인과 효과는 별도 실증 자료·인과 모델이 필요하다. 일반 그래프 간선을 인과관계로 부르지 않는다.

가상 규칙 A: 한도, B: 지급액=min(지출액, 한도), C: 지급액>100만 원이면 추가 승인, D: 독립된 보관 기간을 사용한다. 지출액150, 한도100→200이면 지급액100→150과 C의 조건 변경을 기대한다. C가 지출액을 읽는 변형에서는 한도 변경으로 C의 조건이 바뀌지 않는다. 아래는 검증 설계 예이며 실제 법률이나 현행 계산기의 min 지원·전체 실행을 입증하지 않는다.

| 변경/반례 | 평가할 결과 |
|---|---|
| 값만 변경, 등록 의존 있음 | B/C만 재평가, D 유지, 원본 지식은 불변 |
| 알려진 조건부 경로가 활성화 | 추가 승인 규정·상위 조건 조회와 후속 검토가 나타남 |
| 같은 숫자지만 다른 의미/단위/기간 | 지급액/지출액·원/만원·건별/연간 혼동 없음 |
| 의존 관계·예외·적용 범위 수정 | 영향받는 계획/판단 무효화·새 revision, 이전 결과 이력 유지 |
| 필요한 관계를 아직 모름 | 전체 영향 완료를 주장하지 않고 추가 조사·미확인을 명시. 발견률과 누락률 별도 측정 |
| 관계나 원문이 잘못됐다고 정정 | 변경 후보 검증·잘못된 결속 수정, 범위 밖 관계 보존 |
| 충돌·개정·권한 변경 | 유효한 판본/범위만 재평가, UNKNOWN/CONFLICT·접근 제한 전파 |
| 값 원복/같은 요청 반복 | 같은 버전·입력에서는 재현 가능한 결과, 중복 조회/부작용 억제 |

합성 규칙의 정확한 기대 결과는 검토자가 별도 작성한 표/독립 계산으로 확인한다. O의 실행 그래프를 그대로 정답으로 삼지 않는다. 검토 완료 그래프를 수동 제공한 검사는 엔진의 지원 범위 확인이고, Q1 대화에서 만들어 검토한 지식으로 같은 검사를 통과하는 것은 전체 축적 경로 검사다. 두 결과를 분리한다. A/N도 같은 원문·교정 내용·일반 계산 도구를 사용할 수 있어야 하며, O에만 정답 식을 주고 계산 우위를 주장하지 않는다.

## 지표와 판정

| 영역 | 지표·분모 | 함께 보고할 것 |
|---|---|---|
| 진입 | 사전 정의한 진입 원문 확보 사례/전체 사례 | 진입 제공 트랙과 질문 시작 트랙 구분 |
| 연결 근거 | 필수 근거 묶음 완성 사례/전체 사례; 필수 span recall·precision | 적용 상위 조건/예외 누락, 대안 근거 인정, 회수→전달→사용 단계 |
| 경로·해석 | 근거로 지지되는 관계/선택 관계; 질문 범위와 맞는 최종 판단 | 잘못된 연결·범위 확대·미해결 상태를 숨긴 완료 |
| 멀티턴 | 과업 완료 사례/전체 사례, 중요한 부족의 노출/실제 부족, 유효한 다음 행동 | 불필요한 사용자 질문, 사용자 턴·검토 시간, 중단된 사례·최종 실패 |
| 지식 재사용 | Q2의 정확한 적용·정정 반영, Q3의 부당 전이 | cold/warm, 기존/새 조문, 사용자 교정량·생산 비용 |
| 변경 영향 | 영향 대상 precision/recall, 전후 값·분기 정확성, 무관 노드 보존 | 규칙 누락과 실행기 오류 분리, 미확인 상태의 적절성 |
| 비용·실행 | 사례 전체 호출·입출력 토큰·사용료·총 지연·RSS·저장량 | 여러 턴·실패/보정·지식 생성·검토·인덱싱 비용 포함 |

ADR의 조문 root 기준 회수 원장은 유지하고 span/상위 조건의 정밀 지표를 추가한다. 정확한 후보 집합·탈락 이유·실제 전달 자료를 기록한 뒤 평가자가 gold를 결합한다. 반환한 자료 수만 늘리거나 항상 UNKNOWN이라고 답해서 점수를 올릴 수 없도록 정확성·유용성·미확인·응답률을 함께 보고한다. API 성공·스키마 통과·법률 정답·과업 완료를 다른 지표로 둔다.

사전 주 지표는 연결 조사에서는 필수 근거 묶음 완성, 재사용에서는 Q2의 근거와 적용이 맞는 과업 완료, 변경에서는 영향 대상과 결과의 정확성을 후보로 삼는다. 실제 채택 지표·최소 의미 있는 차이·비열등 허용치·비용 상한·표본 수·반복 수는 개발 자료에서 정한 뒤 새 ADR의 첫 호출 전에 수치로 동결한다. 현재는 그 값이 없으므로 실행 준비 완료나 우위 검증 완료로 표시하지 않는다.

동일 사례의 비교 결과는 O만 성공/A만 성공/모두 성공/모두 실패로 나눠 회귀를 숨기지 않는다. 조문·시나리오 가족을 독립 평가 단위로 정하고 반복·의역은 그 안에 묶는다. 표본 수에 맞는 paired 차이와 불확실성을 보고하며 여러 비교의 주/보조 가설을 미리 구분한다. 모델·프롬프트별 judge 편향을 원문 기반 사람 검토로 확인한다. 온톨로지를 만든 모델의 자기평가만으로 정답을 확정하지 않는다.

## 데이터와 실행 순서

외부 실험은 허용된 공개·합성 자료와 사용자가 반출을 승인한 질문만 사용한다. [risk_cm](../../../../01_DATA/GOLDEN/risk_cm/README.md) 105문항 자료와 CM 51문항은 2026-10-24 사용자 승인으로 외부 실험 모델에 전송할 수 있다([risk_cm 승인](../../../../01_DATA/GOLDEN/risk_cm/EXPORT_AUTHORIZATION_20261024.json), [CM 승인](../../../../01_DATA/GOLDEN/CM_EXPORT_AUTHORIZATION_20261024.json)). 외규 표시는 승인된 정답이 아니며, question_only의 판정 주석은 제품 모델에 넘기지 않는다. 내부 자료·실제 GENOS 모델 검증은 현장 범위이며 이 세션에서 접근을 시도하지 않는다.

1. 이번 문서: 주장·비교·미구현·근거를 정리한다. 새로운 실행·측정·재채점은 없다.
2. 구현 준비: 각 기준군의 실제 실행기·도구·모델 지원과 v4의 필수 소비 경로를 확인한다. 없는 기준군을 이름만 붙여 현재 MAIN이라고 하지 않는다. 통합 v4가 없는 상태에서 완성 온톨로지의 승리를 보고하지 않는다.
3. 실행 선점: 같은 scope reservation 확인 → 현행 `.venv/bin/python 06_TOOLS/run_tool.py adr_structure.py new --adr-root 04_EXPERIMENTS/ADR` 경로로 선점. 가설·지표·수치 기준·부모 arm·데이터·모델·비용·반복을 동결하고 snapshot/register/freeze로 후보 격리한다.
4. 소규모 개발 진단: 이미 알려진 실패·합성 규칙으로 연결·계측을 확인한다. 이 단계는 in_sample·decision_eligible=false이며 비교 우위의 최종 근거가 아니다.
5. 독립 평가: 결과를 보지 않은 조문/시나리오 가족과 별도 재사용 평가를 사전 분리해 실행한다. RAM 제한 때문에 실제 데이터·모델 실행은 하나씩 순차 수행하고 arm 순서는 사전 무작위화/교차 배치로 시간대·제공자 편향을 줄인다. 캐시 cold/warm 상태와 실패도 기록한다.
6. 판정·보고: 사전 기준과 회귀·비용·검토 부담에 따라 지원/미지원/미확인을 구분한다. 실패한 arm은 보존한다. 결과를 보고 만든 후보는 새 ADR이다. 완료 validate --final·graph를 거친 실제 결과만 성능 근거로 연결한다. MAIN 승격과 GENOS 반영은 별도다.

실험 표준의 실행 계약은 [EXPERIMENT_AGENT_PROMPT](../../../../04_EXPERIMENTS/LEGACY_ADR/EXPERIMENT_AGENT_PROMPT.md)와 [STANDARD](../../../../04_EXPERIMENTS/LEGACY_ADR/STANDARD.md)를 따른다. 위 문서의 역사적 경로·모델명은 현행 AGENTS와 모델 정책으로 해석한다. 이번 설계 문서를 frozen manifest로 대신하지 않는다.

## 결과가 나왔을 때의 설명 원칙

| 관측 결과 | 허용되는 설명 |
|---|---|
| R0만 실패, R1/A는 성공 | 단발 검색의 해당 한계. 온톨로지 필수라는 증거 아님 |
| A보다 G가 개선, O의 추가 개선 없음 | 명시 관계 탐색의 가치. 의미 온톨로지의 추가 가치 미입증 |
| 기본 모델 A는 실패, 강한 모델 A는 성공 | 모델 교체로 해당 사례 해결. 작은 모델의 실패를 전체 LLM 한계로 일반화하지 않음 |
| 강한 모델 A와 O의 정답률 동일, O가 반복 비용/검토 시간을 줄임 | 동일 품질에서 재사용·운영 비용의 가치. 모든 정확도가 우월하다는 설명 금지 |
| N과 O가 동일 | 교정 지식 제공의 효과는 있을 수 있으나 구조화/컴파일의 추가 가치 미입증 |
| Q1 교정 후 Q2 개선, Q3에서 부족을 정확히 표시 | 검토한 범위의 전이와 미등록 영역 관리. 전체 지식 완비 주장은 금지 |
| 지원 규칙에서 값·범위 변경이 정확히 전파됨 | 해당 규칙 체계의 변경 영향·재평가 가능. 현실의 인과 효과 예측 인증 아님 |
| 품질 개선보다 구축·검토 비용/회귀가 큼 | 대상 업무 축소·재설계 또는 도입 보류. 유리한 일부 사례만 대표 결과로 제시하지 않음 |

최종적으로 입증하려는 설명은 **“구체적 업무에서 검토하고 수정한 지식이 다음 질문과 변경 분석의 자산으로 남는가”**다. 모델이 향상될수록 그 모델이 사용할 수 있는 검토 지식도 함께 늘릴 수 있다. 다만 이 가치가 실제로 성립하는 범위와 비용은 위 비교 결과로 확정해야 한다.

## 확인한 외부 연구와 적용 한계

- [IRCoT, ACL 2023](https://aclanthology.org/2023.acl-long.557/): 중간에 얻은 정보로 후속 검색을 바꾸는 다단계 질의를 다룬다. 단발 검색만을 기준군으로 두지 않을 근거다. 모든 벡터 검색의 불가능성이나 우리 법률 시스템의 우위를 증명하지 않는다.
- [HippoRAG, NeurIPS 2024 / arXiv v3](https://arxiv.org/abs/2405.14831): LLM·지식그래프·그래프 탐색을 결합한 다단계 회수의 선행 연구다. 그래프 회수 자체를 우리만의 차별점으로 설명하지 않으며 해당 성능 수치를 우리 예상치로 전용하지 않는다.
- [LegalBench-RAG, 2024](https://arxiv.org/abs/2408.10343): 문서 적중을 넘어 최소한의 관련 원문 구간 회수를 평가한다. 원문 회수와 생성 품질을 분리하는 참고이며 한국 법령의 연결 근거 완전성 평가를 대신하지 않는다.
- [Hallucination-Free?, 2024](https://arxiv.org/abs/2405.20362): 당시 법률 연구용 RAG 도구에서도 오류를 관찰한 사전 등록 평가다. 법률용 도구라는 이름만으로 정확성이 보장되지 않는 역사적 근거이며 2026년 특정 대형 모델·현재 제품의 오류율로 사용하지 않는다.

이번 확인은 위 연구의 초록·출처 및 관련 목적 수준이다. 각 연구의 전체 재현이나 우리 데이터에서의 재평가는 수행하지 않았다. [근거 지문](EVALUATION_DESIGN_EVIDENCE_20261024.json)과 [문서 검사](VALIDATION_EVIDENCE_PLAN_20261024.json)는 설계와 기존 자료 보존만 기록한다.
