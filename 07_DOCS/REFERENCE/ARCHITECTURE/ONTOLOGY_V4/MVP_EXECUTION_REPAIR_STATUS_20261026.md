## 현재 개발 — ADR1066 행동별 최소 입력·응답 계약

사용자 후속 요청에 따라 미실행 ADR1066 후보의 개발 범위를 [행동별 최소 입력·응답 계약](ACTION_CHOICE_CONTRACT_20261026.md)까지 확장했다. `minimal_action_choices=true`는 `task_local_navigation` 위에서 행동별 필요한 필드만 요구한다. 행동·대상은 단일 후보여도 명시적으로 선택하고, 나머지 고정값·검증된 출발 정보와 도구 좌표는 서버가 복원한다. 조사 목적은 전송 `reason`에서 내부 `missing_need`로 복원하며, 목적 상속은 단순 메뉴 이동에 한정한다. 새 읽기·검색·위치·연결 행동의 이유는 모델이 작성한다. 다중 쟁점·의존 관계·법률 판단은 추정하지 않는다. 현재 원문의 미제출 판단은 빈 검토 배열로 복원하되 미완료 상태로 보존한다. 정상·preview·전체 객체 보완은 같은 compiler/decoder와 현재 메뉴를 사용한다.

ADR1065 최종 기록 검사는 통과했다. 전체 계보 graph의 기존 오류9개는 남아 있으며1065 관련 오류는 없다. 이는 제품 성공이나 품질 인증을 뜻하지 않는다.

이번에는 알려진3문항9셀만 사전에 동결했으며 추가102셀은 계획에 포함하지 않았다. `in_sample=true`, `decision_eligible=false`, 운영 기준 실패다. 관찰 완료·ADR 문서 검사와 제품 성공은 별개다. **후속 변경은 새 ADR에서 하며 MAIN103·GENOS·운영 골드는 변경하지 않았다.**

## 이전 구현·실험 — ADR1061~1064

사용자 2026-10-26 “이거 구현대로 만들고 실험해봐” 요청에 따른 이전 기록이다. **728파일 rev-001을 구현·동결하고 실제 첫9셀을 실행했지만, 제한 답변2·조사 중단7로 진행 기준을 통과하지 못했다. 나머지102셀은 미실행이다.** 아래 수치와 “현재” 표현은 ADR1063 당시 관찰을 설명한다.

## 구현 범위

- 전체 검색 법령·최대20개 조문 후보·더 보기와 선택 후 원문 읽기를 분리한다. 정의도 먼저 위치를 제시하며 선택 범위와 필요한 상위 조건만 확보한다.
- 실제 own-block 도착으로 승인 묶음을 확보하고, A1/A2는 같은 원문·메타데이터 집합에서 표시 순서만 바꾼다. 확보·전달·검토·답변 사용을 별도로 기록한다.
- 현재 검토는 최대3개 source 묶음, 전역 미검토는 별도 대기열이다. 정상 행을 독립 저장하고 출발 판단에 필요한 오류 행만 기존1회 보완 예산으로 고친다. 실패 행·부분 전달을 승인 판단으로 만들지 않는다.
- 최종 전송 요청의 ENTRY/CATALOGUE24,000·REVIEW48,000·REPAIR16,000·ASSESS64,000·COMPOSE32,000자 한도를 물리 예약 전에 검사한다. 작은 원문 페이지와 최소 구조 범위도 넘으면 pending을 보존한다. 전체 간결 법령 목록 자체가 너무 크면 기존 검증을 거치는 명시적 새 검색식을 받는다.
- 원문·권한·판본·해시·상태 revision, 중복 실행·재개·전체 예산을 재검사한다. 원문을 포함한 쟁점별 ASSESS를 사용하며 요약만으로 전체 정합성을 확정하지 않는다.

구현은 `02_BACKEND/lawrag/research/candidates/adr_1063/catalogue-projection-r1`에 격리했다. 실제 진입점은 같은 후보 코드의 `service.py` → `POST /v1/rag/ask`다. 생산 기본 registry·선택 MAIN은 바꾸지 않았다.

## 실행 조건과 미확인

37문항×A0/A1/A2의111셀을 호출 전에 동결했다. FSC005·CM023·FSC008의 첫9셀에서 실제 요청 한도, 원문·권한, 승인 묶음 도착과 허용 provision 전달, ASSESS 원문 전달을 검사한 결과 진행 기준에 실패했다. 세부 의미 오답만으로 중단한 것이 아니다. 질문·기준답변의 공개 승인과 제품 입력 분리는 유지했다.
