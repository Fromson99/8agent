## 현재 개발 — ADR1066 행동별 최소 입력·응답 계약

사용자 후속 요청에 따라 미실행 ADR1066 후보의 개발 범위를 [행동별 최소 입력·응답 계약](ACTION_CHOICE_CONTRACT_20261026.md)까지 확장했다. `minimal_action_choices=true`는 `task_local_navigation` 위에서 행동별 필요한 필드만 요구한다. 행동·대상은 단일 후보여도 명시적으로 선택하고, 나머지 고정값·검증된 출발 정보와 도구 좌표는 서버가 복원한다. 조사 목적은 전송 `reason`에서 내부 `missing_need`로 복원하며, 목적 상속은 단순 메뉴 이동에 한정한다. 새 읽기·검색·위치·연결 행동의 이유는 모델이 작성한다. 다중 쟁점·의존 관계·법률 판단은 추정하지 않는다. 현재 원문의 미제출 판단은 빈 검토 배열로 복원하되 미완료 상태로 보존한다. 정상·preview·전체 객체 보완은 같은 compiler/decoder와 현재 메뉴를 사용한다.

**743파일 rev-002에서 구현·동일 동결본 합성 계약/API 80개 검사를 완료했다.** 입력 문자 hard-stop 해제·출력 토큰 상한 없음과 기존 실행 예산을 유지한다. 실모델을 재개하지 않았고 MAIN103·GENOS·운영 골드는 미변경이다. 기존 rev-001과 아래 입력 한도 해제 검사 결과, ADR1065 실패 원기록은 보존한다. [호출 전 개발 기준](../../../../04_EXPERIMENTS/ADR/ADR-1066-ontology-input-unlimited/artifacts/ACTION_CONTRACT_IMPLEMENTATION_PLAN.md).

최종 revision 해시는 `0e9c03beda51b6fef8ba66cf4c2892553f9d70631680272a810c2449b54c9bbe`다. 같은 동결본의 집중 검사 80개가 12.43초에 모두 통과했고, 로드한 271개 제품 모듈 중 후보 밖 혼입과 검사 중 파일 변경은 각각 0건이다. 실제 API 진입점에 합성 모델을 연결해 A0의 원문 읽기·판단·완료·중복 요청 재사용, A1/A2의 승인된 단일 provision에 대한 동일 메타데이터·원문·전달 receipt를 확인했다. **실모델 호출은 0회이며 실제 Qwen의 생성 형식 호환성·법률 품질·온톨로지 성능은 확인하지 않았다.** [구현 결과](../../../../04_EXPERIMENTS/ADR/ADR-1066-ontology-input-unlimited/artifacts/ACTION_CONTRACT_RESULT.md) · [동일 동결본 최종 검사](../../../../04_EXPERIMENTS/ADR/ADR-1066-ontology-input-unlimited/artifacts/action-frozen-final-summary.json).

온톨로지 연결 검사에서는 `evidence_inventory.acknowledge`가 `document_id`를 빠뜨려, 승인된 basis가 확정 전달 기록을 덮을 때 reconcile이 불일치로 판단하는 결함을 수정했다. 새 receipt는 문서 ID를 보존한다. 과거 receipt의 누락 값은 같은 branch·source·scope·spans의 확정 전달 기록이 있을 때만 복원하며 명시적인 문서 ID 불일치는 계속 거부한다. 이 경계의 회귀 검사 5개는 위 80개에 포함된다.

새 행동 경로에서는 gateway의 추가 입력 표·값 재조합, 출력 키 별칭·schema 공유·중복 minimal 변환을 적용하지 않는다. 법령 목록 `law_matches.rows`와 범위 참조 `action_scopes`는 유지한다. 응답 예시는 [계약 7절](ACTION_CHOICE_CONTRACT_20261026.md#7-응답-예시)에 있다.

## 최신 재실험 — ADR1065

사용자 “한번 수정하고 다시 실험” 요청에 따라 현재 작업별 선택지·원문·판단을 분리하고, 중복 후보 필드를 정확히 복원 가능한 참조로 바꿨다. **736파일 rev-002로 3문항×A0/A1/A2 총9셀을 모두 관찰했지만, 9개 모두 답변 전 중단했다. 수정 성공이나 온톨로지 효과를 확인하지 못했다.** [결과](../../../../04_EXPERIMENTS/ADR/ADR-1065-ontology-task-local-navigation/artifacts/RESULT.md) · [원인별 진단](../../../../04_EXPERIMENTS/ADR/ADR-1065-ontology-task-local-navigation/artifacts/POST_RUN_DIAGNOSIS.md).

- 기존 실패 화면9개를 새 코드로 구성한 전송 전 검사는16,615~23,310자로 모두 기존 한도 안에 들어왔다. 현재 원문·법령 목록·조문 후보를 보존했다. 이 결과는 새 검색 결과와 이후 화면의 한도 보장이 아니다.
- 실제 최초 실패는7개가 불완전한 행동 응답,2개가 후보 입력 초과다. 불완전 응답7개 중5개는 보완 입력도17,099~18,272자로16,000자 한도를 넘었다. 나머지2개는 보완 후 목차 탐색까지 실행했지만 다음 화면이35,339·35,341자로24,000자 한도를 넘었다.

- 원문 확보·전달·인용과 승인 묶음 확보·전달은0건이다. 의미 판정은 모두unknown이며, A1/A2 효과를 평가할 수 없다. 평가 절차3건은 종료했지만 채점 모델 호출은0회다.
- 전체 회귀1,028개 통과·기존 실패8개·새 실패0개, 동일 동결본 서비스/계약104개 통과였다. 합성 검사와 저장 입력 검사가 실모델 성공을 보장하지 못한 사례로 보존한다.

## 구현 범위

- 전체 검색 법령·최대20개 조문 후보·더 보기와 선택 후 원문 읽기를 분리한다. 정의도 먼저 위치를 제시하며 선택 범위와 필요한 상위 조건만 확보한다.
- 실제 own-block 도착으로 승인 묶음을 확보하고, A1/A2는 같은 원문·메타데이터 집합에서 표시 순서만 바꾼다. 확보·전달·검토·답변 사용을 별도로 기록한다.
- 현재 검토는 최대3개 source 묶음, 전역 미검토는 별도 대기열이다. 정상 행을 독립 저장하고 출발 판단에 필요한 오류 행만 기존1회 보완 예산으로 고친다. 실패 행·부분 전달을 승인 판단으로 만들지 않는다.
- 최종 전송 요청의 ENTRY/CATALOGUE24,000·REVIEW48,000·REPAIR16,000·ASSESS64,000·COMPOSE32,000자 한도를 물리 예약 전에 검사한다. 작은 원문 페이지와 최소 구조 범위도 넘으면 pending을 보존한다. 전체 간결 법령 목록 자체가 너무 크면 기존 검증을 거치는 명시적 새 검색식을 받는다.
- 원문·권한·판본·해시·상태 revision, 중복 실행·재개·전체 예산을 재검사한다. 원문을 포함한 쟁점별 ASSESS를 사용하며 요약만으로 전체 정합성을 확정하지 않는다.

구현은 `02_BACKEND/lawrag/research/candidates/adr_1063/catalogue-projection-r1`에 격리했다. 실제 진입점은 같은 후보 코드의 `service.py` → `POST /v1/rag/ask`다. 생산 기본 registry·선택 MAIN은 바꾸지 않았다.

## 실행 조건과 미확인

37문항×A0/A1/A2의111셀을 호출 전에 동결했다. FSC005·CM023·FSC008의 첫9셀에서 실제 요청 한도, 원문·권한, 승인 묶음 도착과 허용 provision 전달, ASSESS 원문 전달을 검사한 결과 진행 기준에 실패했다. 세부 의미 오답만으로 중단한 것이 아니다. 질문·기준답변의 공개 승인과 제품 입력 분리는 유지했다.
