CM 조사 조기 종료·목표 집행 수정 계획
작성: 2026-10-28 / 계획만 작성 / 새 모델 호출 0회 / MAIN112 유지

1. 목표와 현재 판단

목표는 이미 필요한 원문이 특정된 경우 서버가 그 원문을 확보하고, 확보 후에 모델이 적용·제외·답변 충분성을 판단하게 만드는 것이다. 같은 모델에게 오류 설명을 반복하며 올바른 행동을 기다리는 비용을 줄인다.

현재 확인된 사실:
- ADR1172의 Qwen3.8/Chutes 저장 입력 검사에서 CM001은 2회 모두 NEEDS_SOURCE를 남기면서 FINISH를 제출했다. 한 응답은 읽지 않은 시행세칙이 관련 없다고 판단했고, gap 해결 이유는 한 글자였다.
- 같은 검사에서 CM007은 2회 모두 유가증권시장 상장규정 제13조와 정확한 LOCATE 대상을 지정했다.
- 위 검사는 다음 행동 출력과 스키마 검사다. 전체 서버의 의미 검증·원문 실행·최종 답변·저장 성공을 확인한 것은 아니다. CM001의 FINISH가 실제로 채택되어 종료됐다고 확대하지 않는다.
- CM001 저장 입력에는 material=true / MISSING_SOURCE / EXACT로 결속된 '코스닥시장 상장규정 시행세칙 제23조'가 있다. 새 추측이나 기준답변 주입 없이 재사용할 기존 조사 대상이다.
- 원문 목표 제어 후보는 77개 기술검사를 통과했지만 MAIN에는 미반영이다. 현재 선택은 MAIN112다.
- 신규 외부 실험 공급자는 Chutes FP8이며 확정429에만 Near AI FP8로 한 번 전환한다. 공급자 검사25개는 별도 검사다. MAIN112 내장 전송기의 Parasail 고정은 그대로다.
- GENOS 재현용122B 비교는 사용자 취지에 맞지 않았으므로 더 좋은 모델의 비교 결과로 사용하지 않는다.

코드에서 확인한 연결상의 취약점:
A. decision_projection.choose_read에서 expand → 판단 검증·원래 행동 검증 → 판단 기록 → supervisor.gate → source_goal_control.resolve 순서다. 기존 목표 제어가 초기 검증 오류보다 뒤에 있다.
B. independent_read_recovery.plan은 READ_JUDGMENT_INVALID이면서 제출 행동이 READ인 경우만 복구한다. FINISH를 낸 모델 때문에 기존의 별도 확정 원문 읽기까지 보완 경로에 묶일 수 있다.
C. request_repair.validate_resolutions는 NOT_NEEDED를 이유만 보존하는 재판단으로 취급하며, validate_unattempted_gap_finish는 이 상태를 조사 시도 의무에서 제외한다. 별도의 source_goal_control은 미확보 목표를 유지하므로 두 계약을 통일해야 한다.
D. supervisor 경로는 answer_progress.validate_review(..., check_action=False)를 사용한다. 현재 후보 프로필은 supervisor_mode=enforce이고 answer_progress_control은 켜지지 않았다. 다른 모드의 FINISH/NEEDS_SOURCE 충돌 검사가 이 경로에도 적용된다고 가정하면 안 된다.

A~D는 코드·설정 관측이다. CM001 새 출력이 실제 어느 검증에서 멈추는지는 아래 단계0의 재생으로 확정한다.

2. 수정 순서와 완료 조건

단계0 — 저장 응답을 실제 소비자까지 재생
기존/실제: 최근4개 출력은 JSON·스키마와 정확 목표 선택까지 검사했다.
변경: 동일 질문·원문·권한·프로필과 당시 저장 상태를 복원해, 원래 응답을 번호 복원 → expand → 판단 검증 → gate → 기존 원문 실행기까지 재생한다. 단계별 통과/거절/실행 receipt를 기록한다.
원하는 결과: '모델이 잘못 제안함', '서버가 거절함', '보완 때문에 독립 읽기가 막힘', '실제로 잘못 종료함'을 구분한다.
통과: CM001 두 출력과 CM007 두 출력의 최초 실패 또는 허용 지점을 재현한다. 합성 상태로 보완한 부분은 실제 저장 상태 재생과 구분한다. 추가 모델 호출은 없다.

단계1 — 확정된 원문 목표를 행동 선택보다 먼저 처리
기존/실제: CM001의 EXACT 부족이 이미 있는데도 모델에게 다음 행동을 다시 골라 달라고 했고 FINISH가 나왔다.
변경: 현재 요청에 결속된 ASSESS 부족·이전에 검증된 source_goal을 조사 상태 준비 시 먼저 등록한다. 승인된 문서·판본·좌표·권한과 현재 메뉴/도구 예산을 확인한 뒤, 이미 읽었으면 재사용하고 아니면 기존 정확 조회 → READ를 집행한다. 목표를 알아내기 위한 추가 감시 호출은 만들지 않는다.
연결: source_goal_control에 준비/집행 계획 책임을 두고 Investigation.run/_request_decision의 실제 호출 지점에 연결한다. decision_projection의 표시 변환에서는 SQL이나 원문 읽기를 실행하지 않는다. Investigation.execute와 기존 read_plan/receipt를 재사용한다.
통과: 같은 저장 상태에서 새 행동 선택 호출 없이 대상 조회/READ가 실행되고, 실제 원문 receipt가 생긴 뒤에만 ACQUIRED가 된다. 조회 목록·제목·도구 선택만으로 원문 확보로 세지 않는다.
범위: 확정된 필수 대상만 적용한다. 문서·판본·좌표가 모호하면 기존 검색/범위 선택으로 넘기고 임의 조문을 고르지 않는다. 관련 법령 전체를 강제로 읽지 않는다.

단계2 — 판단 보완과 독립 원문 조사를 분리
기존/실제: 현재 복구는 모델이 유효한 READ 대상을 함께 제출해야 한다. FINISH나 판단 오류가 먼저 나오면 이미 저장된 목표 제어에 도달하지 못할 수 있다.
변경: 잘못된 새 판단·잘못된 FINISH는 거절·기록한다. 그 응답과 독립적으로 이전 상태에서 검증된 미확보 목표가 있으면 그 목표의 조회/읽기는 계속할 수 있게 한다. 실패한 응답의 문장이나 잘못된 도구 번호를 해석해 새 대상을 만들어 내지 않는다.
연결: decision_projection.expand의 검증 책임을 유지하면서, output_contract/independent_read_recovery와 source_goal_control의 복구 소유자를 하나로 정한다. 새 원문은 pending 판단으로 저장하고 기존 판단 head를 덮어쓰지 않는다. 필요한 판단 보완은 기존 다음 검토 단계에서만 처리한다.
통과: 잘못된 판단 채택0, 독립 목표의 실제 읽기 성공, 같은 실패에 대한 중첩 보완0. 유효한 이전 목표가 없거나 권한/무결성 오류이면 원래 제한 복구·중단 계약을 지킨다.

단계3 — 목표 종료 사유와 최종 종료를 같은 계약으로 연결
기존/실제: CM001은 미확인 내용을 남긴 채 종료를 선택하고, 읽지 않은 세칙을 불필요하다고 서술했다. 기존 NOT_NEEDED와 source_goal_exclusions의 요구 근거도 다르다.
변경:
- 읽기 완료: 정확 대상의 실제 전달 범위 receipt로만 기록한다. 법률 주장 성립·충분성은 별도 판단이다.
- 해결: 현재 원문 근거와 해당 쟁점의 판단에 연결한다. 다른 문서를 읽었다는 사실만으로 해결하지 않는다.
- 불필요 재판단: 읽은 근거 또는 사용자가 명시한 질문 범위 변경, 대상과 무관하다는 구체적 이유를 구조화해 기록한다. 제안은 모델 의견이며 서버가 법률적으로 맞다고 인증하는 것은 아니다. 제목·미리보기·상상만으로 닫지 않는다. 해당 대상 자체를 읽지 않고도 다른 실제 원문으로 명확히 제외할 수 있는 경우는 허용한다.
- 조회 실패/예산 소진/권한상 접근 불가: 미해결로 보존한다. 원문 부재나 조사 완료로 바꾸지 않는다.
- 핵심 미해결이 있고 실행 가능한 경로가 남으면 충분한 답변으로 종료할 수 없다. 유효한 경로/예산이 없으면 기존 LIMITED_ANSWER/PARTIAL 또는 INSUFFICIENT로 인계하며 검증된 주장만 반환한다.
연결: request_repair.validate_resolutions / validate_unattempted_gap_finish, answer_progress, source_goal_control, completion_execution.finish_assessment가 동일한 현재 목표 상태와 근거를 사용하게 한다.
통과: FINISH·ANSWERABLE·NOT_NEEDED의 표현만 바꿔 미확보 목표를 지울 수 없다. 반대로 정상 제외·실제 사실 질문·제한 답변까지 무조건 추가 조사로 돌리는 회귀가 없어야 한다. 미해결 때문에 무한 탐색하지 않는다.

단계4 — 모델 선택 입력과 응답의 중복 책임 축소
기존/실제: 문서명·조항·도구 번호를 함께 맞춰야 했다. 이전122B는 설명D5와 실제D4 도구를 혼동했다. Qwen도 형식은 맞지만 조사 필요와 종료 행동이 충돌했다.
변경: 이미 저장된 목표는 목표 ID만으로 참조하고 서버가 현재 도구 번호에 연결한다. 새 목표는 허용 문서 ID와 구조화 좌표로 제안하며 도구 번호를 중복 작성시키지 않는 계약을 후보로 만든다. 문서·좌표 선택의 의미는 모델이 판단하고 서버가 권한·제시 범위·실제 대상 동일성을 검사한다.
입력: 현재 질문, 현재 원문, 해결해야 할 목표, 필요한 기존 판단/미확인 사항, 방금 실행한 실제 결과, 지금 가능한 선택을 제시한다. 과거 의견·원문 확보·법률 충분성을 구분한다. 해시·좌표 검증 자료·실행 전체 이력은 서버에 보존한다.
연결: decision_projection, navigation_input, compact_model_input과 동일한 보완/페이지/감시 스키마를 함께 변경한다. 정상·보완·NEXT/PREV 뒤 메뉴가 서로 다른 계약을 쓰지 않게 한다.
통과: 같은 질문·원문·문서 선택을 유지하면서 중복 표현이 줄어든다. 원문·쟁점·부족 삭제로 입력을 줄이지 않는다. 정해진 글자 수를 맞추기 위한 근거 절단은 하지 않는다.

단계5 — 공급자 정책을 실제 서빙 경로에도 연결
기존/실제: 연구 클라이언트는 Chutes→429시Near AI지만 MAIN의 LocalQwen38Transport는 Parasail 고정이다.
변경: 공급자 허용 목록·FP8·실제 응답 공급자 검증의 공통 정책을 순수 모듈로 공유한다. 서빙에서 research 실행기를 import하지 않는다. 실제 물리 재시도 책임은 gateway 한 곳에 두고, 어댑터는 한 번만 전송한다. 확정429일 때만 남은 예산 안에서 요청당 한 번 다음 공급자를 선택하고, 사용량·현재 공급자는 같은 요청의 재개 상태에 보존한다. 다른 요청에 전환 예산을 섞지 않는다. 연구 클라이언트의 자체 전환 루프를 서빙 gateway 아래에 그대로 중첩하지 않는다.
연결: local_gemma, gateway/transport의 요청·429 분류·실제 시도 원장, 모델/공급자 설정, 릴리스 서빙 목록과 엔진 pin. 새 정책 hash를 요청 binding에 결속하고 데이터 반출 승인 범위는 바꾸지 않는다.
통과: 모의429에서 공급자가 바뀐 두 HTTP 요청이 원장에도 물리2회로 기록된다. 타임아웃·응답 불명·500·형식 오류·다른 모델 응답에는 전환하지 않는다. MAIN의 실제 새 질문에서 사용 공급자 영수증까지 확인한다.
범위: 외부 Qwen용 경로이며 GENOS 내부 생성 모델 공급자 정책과 분리한다. 현재 연구 설정을 바꿨다는 이유만으로 MAIN에 이미 적용됐다고 보고하지 않는다.

3. 처리 순서와 저장 계약

현재 요청·권한·세대·저장 상태 검증
→ 기존의 검증된 필수 목표와 미확보 상태 확인
→ 정확 조회/READ 또는 이미 확보한 원문 재사용
→ 원문 전달 receipt 저장
→ 현재 원문으로 새 판단/필요한 보완
→ 목표 해결·제외·미해결 기록
→ 최종 주장과 근거·판단 번호 연결 확인
→ 기존 발행·저장·화면 표시 검증.

기존 investigation/source_goals/read_plans/gap/판단 원장에 책임을 연결한다. 병렬 원장이나 별도 조사를 새로 만들지 않는다. 새 상태 필드·wire 계약은 버전을 붙이고 기존 소비자와 함께 변경한다. 문서/판단/근거 번호와 request/presentation/binding을 보존한다.
데이터 원문·용어집·검색 색인 재구축은 예정하지 않는다. 과거 저널·실험·완료 요청은 이행 대상으로 삼지 않고 보존한다. 새 코드와 다른 binding의 진행 요청을 묵시적으로 이어 쓰지 않는다. 같은 코드·binding에서의 중단/재개는 기존 물리 예산·deadline·완료 receipt를 복원한다.

4. 실패와 한도

- 검증된 목표 + 새 판단 오류: 판단은 미채택, 독립 원문 확보 가능. 하나의 복구 담당만 사용.
- 새 목표의 잘못된 문서/좌표/ID: 그 목표를 집행하지 않음. 기존 유효 목표가 있으면 그것만 독립적으로 처리.
- JSON 훼손/불완전 응답: 실패 출력에서 대상을 추출해 실행하지 않음. 기존 승인 상태의 읽기와 분리.
- 검색0건/부분 조회/도구 실패: 원문 부재를 확정하지 않음. 실제 실패와 시도 범위 보존.
- 권한·세대·hash·상태 충돌: 자동 읽기와 모델 보완으로 우회하지 않음.
