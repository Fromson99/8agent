# 온톨로지 v4 조문 경로 조립·대화 축적·변경 영향 분석

2026-10-23 최초 설계, **2026-10-24 멀티턴 Legal agent 전환 반영**. **실제 사용자가 무엇을 원했고 어떤 자료를 필요로 했는지, 조사·선택·정정에서 관찰해 원문 중심 온톨로지를 보완한다. 에이전트는 그 온톨로지에서 경로를 조립하고, 확인한 답·미확인·다음 관계·행동 기록을 전달해 여러 턴에 걸쳐 조사한다. 조건 변경의 영향도 같은 근거와 계획에서 비교한다.**

v4는 이 설계 문서의 버전이다. 데이터 스키마 버전·MAIN 번호·배포 완료를 뜻하지 않는다. 이 작업은 설계 저장과 문서 검증이며 제품 구현·새 모델 실험·지식 게시·MAIN 변경·GENOS 적용을 수행하지 않는다. 기준 선택은 **로컬 MAIN103 / output-unlimited-20261023-r1**이다. [현재 코드와 관측 근거](ONTOLOGY_V4/CURRENT_STATE.md)를 따른다.

## 사용자가 하려는 일

1. 질문을 처음부터 온톨로지 틀에 완벽하게 분해하지 않아도 조사할 수 있다.
2. 어떤 조문에 도달하면 그 원문에 연결된 개념·판단·검토 경험을 찾는다.
3. 위임·준용·세부 범위·상위 조건 등을 목적 있는 경로 묶음으로 제시한다. 설명을 보고 묶음을 선택하면 필요한 원문을 가져온다. 맞는 묶음이 없으면 직접 탐색한다.
4. LLM이 무엇을 판단했고 왜 그렇게 보았는지, 실제 근거와 미확인을 사용자에게 전달한다. 사용자에게 보여준 버전과 실제 실행 기록을 연결한다.
5. 사용자가 잘못 찾은 규정·수치·연결을 지적하면 그 대상을 정정하고 영향을 받는 판단을 다시 검토한다. 수정 전 기록과 이견은 보존한다.
6. 이렇게 보완한 원문 중심 지식으로 그래프를 구성한다. 사용자는 현재 한도 100만 원을 가정상 200만 원으로 바꾸고 영향·결과·미확인을 한 화면에서 비교한다.
7. 대화 중 표현은 자유롭게 유지하되 재사용 온톨로지와 실행 계획에 반영하는 형식은 제한한다. LLM은 스키마·관계 유형·실행 도구를 임의로 신설하지 않는다.
8. 미확인 사항이 남으면 어떤 경로에서 무엇을 더 확인할 수 있는지 짧게 안내하고, 실제로 한 행동·하지 않은 이유·다음 권장 행동을 구분해 보여준다. 사용자는 선택·정정·범위 구체화로 같은 조사를 이어간다.
9. 조사 제어·원장·응답·화면·다음 턴 재개·지식 후보 연결을 같은 계약으로 함께 전환한다. 단계별 개발과 운영에서의 통합 교체를 구분한다.

## 전체 흐름

세 가지 필수 기능은 조문 진입 후 근거 조립, 대화 판단·정정의 축적, 조건 변경의 영향 비교다. 이들을 **온톨로지를 사용하는 멀티턴 조사 계약**으로 연결한다. 한 턴의 응답 발행과 전체 조사의 완료는 별도다. 조문 진입은 이전 수정 이력이 없는 첫 대화에서도 작동해야 하며, 미확인·선택·정정을 다음 턴으로 이어야 한다. 이력 정정이나 금액 비교만 구현하고 v4 프로토타입을 완료했다고 하지 않는다.

## 핵심 통제 원칙

- **원문이 지식의 일차 저장 단위다.** 질문은 발견 이력이고, 질문별 답변을 골드 지식으로 복제하지 않는다.
- **사용 중 필요와 정정을 관찰한다.** 문서 전체의 핵심·관계를 사전 LLM 추출로 완성하는 것을 전제로 삼지 않는다. 구조·명시 참조 색인은 유지하고 의미 후보는 검토한다.
- **한 턴의 완료와 조사 완료를 분리한다.** 확인한 부분을 전달하며 새 의미 분기·미확인·다음 행동을 다음 턴에 연결한다. 명확한 같은 목적 조회를 매번 사용자에게 선택시키지는 않는다.
- **미읽은 대상의 내용은 만들어 요약하지 않는다.** 관계 근거에서 확인할 수 있는 조사 목적 안내와 실제 읽은 본문의 요약을 구분한다. 과거 행동과 사후 권장 행동도 분리한다.
- **설명과 실행은 같은 구조를 공유한다.** 실제 선택·원문·계산 기록에서 설명을 구성한다. 설명문을 다시 해석해서 실행하거나 사후 설명을 실제 실행 이력처럼 보이지 않는다.
- **등록된 부족은 빈 목록으로 사라지지 않는다.** 아직 등록하지 않은 부족까지 발견했다는 보장은 하지 않는다. 원문에 확인된 관계 후보와 LLM의 필요성 판단을 함께 보존한다.
- **지식 정정과 가정 변경을 구분한다.** 원문 자체는 불변이다. 사용자 정정은 연결·해석의 새 버전으로, 가정 변경은 별도 시나리오로 남긴다.
- **형식에 맞지 않는 의견도 버리지 않는다.** 대화 기록과 후보로 보존하고 자동 실행·게시에서만 제외한다. 불확실성을 이유로 확보 원문이나 제한 답변을 막지 않는다.
- **검토한 범위 안에서 점진적으로 보완한다.** 지식·관계가 늘었다고 법률 지식의 완전성이나 정답을 인증하지 않는다.

## 기존 문서와 관계

[v3](ONTOLOGY_V3.md)의 원문 중심 저장·개념·관계·근거 기억·설명가능성 설계를 이어받는다. [사용 중 판단 축적 설계](../REPORTS/ONTOLOGY_RETRIEVAL_IMPLEMENTATION_20261023/DESIGN.txt)의 생산자 원칙도 유지한다. 문서 반입 시 모든 의미 관계를 미리 추출하는 것을 선행 조건으로 만들지 않는다. 이전 문서의 관측 당시 MAIN 번호와 완료 실험 결과는 변경하지 않는다.

제품 구현의 정본은 현재 코드·선택 릴리스다. 이 문서에 등장하는 신규 함수·API·설정·계약은 명시적으로 **제안**이며 실제 지원 여부는 [프로토타입 설계](ONTOLOGY_V4/PROTOTYPE_DESIGN.md)의 이행 단계로 확인한다.

2026-10-24 변경의 문서·보존 검사는 [추가 검증 기록](ONTOLOGY_V4/VALIDATION_MULTITURN_20261024.json)에 둔다. 이전 검증 기록과 삼성으로 보낸 2026-10-23 PDF·Word는 당시 자료로 보존한다. 이번 변경은 해당 첨부의 재작성·재발송이나 제품 코드 수정이 아니다.

같은 날 후속 성능 입증 논의는 [검증 설계](ONTOLOGY_V4/PERFORMANCE_EVIDENCE_PLAN.md)와 [문서 검사](ONTOLOGY_V4/VALIDATION_EVIDENCE_PLAN_20261024.json)에 추가했다. 현재 비교 우위를 입증한 결과가 아니라, 모델·검색·지식 표현·교정·컴파일 효과를 분리해 확인할 설계안이다.
