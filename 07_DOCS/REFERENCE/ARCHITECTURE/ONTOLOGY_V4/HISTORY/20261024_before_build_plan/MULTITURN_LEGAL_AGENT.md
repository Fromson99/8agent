# 사용 중 지식 축적과 멀티턴 Legal agent 전환

[v4 목차](../ONTOLOGY_V4.md) · [프로토타입](PROTOTYPE_DESIGN.md) · [조문 경로](SOURCE_ENTRY_COMPOSITION.md) · [검증](VALIDATION_AND_ROLLOUT.md)

2026-10-24 사용자 설계 변경을 반영한다. **원문 중심 온톨로지를 사용하는 Legal agent를 기본 목표로 두고, 실제 질문·조사·사용자 정정에서 그 온톨로지를 보완한다. 에이전트는 매 요청에서 끝까지 답을 완성하려 하기보다 확인한 답, 미확인 사항, 진행 가능한 관계와 다음 행동을 전달하며 여러 턴에 걸쳐 조사한다.** 이 문서는 구현 제안이며 현재 MAIN103 또는 GENOS의 실행 방식이 바뀌었다는 뜻이 아니다.

## 왜 처음부터 문서 전체를 LLM으로 그래프화하지 않는가

사용자는 조문만 주고 핵심 내용·관계를 추출한 실험에서 결과가 불량했다고 보고했다. 이번 변경에는 해당 실험의 원시 결과가 추가 제공되지 않았으므로 실패율이나 원인을 확정하지 않는다. 질문 없는 문서 추출과 사용 중 축적의 품질 차이도 아직 측정하지 않았다.

다만 제품이 얻는 관측 정보는 다르다. 원문만 보면 이 사용자가 무엇을 결정하려는지, 어느 세부 내용까지 필요한지, 어떤 선택이 잘못됐는지 알 수 없다. 실제 사용에서는 다음을 함께 관찰할 수 있다.

| 관찰 대상 | 보존할 내용 | 확대 해석하지 않을 것 |
|---|---|---|
| 사용자의 목적 | 원래 질문, 후속 범위 구체화, 원하는 결과 | 조문마다 고정된 단 하나의 핵심 |
| 실제로 필요한 정보 | 어떤 판단을 위해 정의·범위·예외·절차가 필요했는지 | 질문 하나의 필요가 모든 사건에 필수라는 주장 |
| 선택과 실행 | 제시된 후보, 선택 이유, 읽은 원문, 실패·미실행 | 선택했다고 적합성이 입증됐다는 주장 |
| 사용자 정정 | 잘못 고른 대상, 누락한 조건, 수정 이유·근거 | 사용자의 클릭·침묵을 법률 승인으로 처리 |
| 다른 질문에서의 재사용 | 같은 원문·개념·범위에서 도움이 된 검토 사항 | 이전 질문의 사실·결론을 현재 답으로 복사 |

따라서 원문·문서 구조·명시 참조의 입력·색인은 계속 수행하되, 모든 조문의 의미와 핵심을 사전에 완성하는 것을 시작 조건으로 삼지 않는다. LLM 사전 추출을 쓰더라도 미검토 후보이며 정본 온톨로지로 자동 게시하지 않는다. 의미 지식 생산의 기본 경로는 **구체적 필요 → 원문 조사 → 외부에 설명한 판단 → 선택/정정 관찰 → 제한된 지식 후보 → 검토된 원문 지식**이다. 사용자는 선택·정정을 돕지만 모든 누락을 찾아낼 의무를 지지 않는다. 미사용 영역의 지식 부족·사용자 편향·잘못된 피드백은 계속 검증해야 한다.

## 온톨로지가 있다는 전제의 정확한 뜻

등록된 객체·관계 의미, 원문 anchor, 적용 범위, 허용 조회·계산 능력과 게시 버전을 사용할 수 있다고 가정한다. 모든 조문에 관계가 있거나 지식이 완비됐다는 가정은 아니다. 첫 사용은 구조화 원문·명시 참조와 소수의 검토된 관계/방법으로 시작할 수 있다. 현재 코드의 management=false, consumer=off 상태는 이 목표의 충족 상태가 아니다.

질문으로 원문에 도달하면 해당 범위의 온톨로지를 먼저 회수해 경로를 조립한다. 적용 가능한 지식이 없으면 기존 원문 검색·조회 능력으로 조사하며 미등록 영역임을 표시한다. 그 결과를 현재 대화에 원문 근거로 사용할 수 있는 것과, 공유 실행 지식으로 게시하는 것은 별도다. 새 의미 관계는 후보로 보존하고 검토 전 공유 컴파일 규칙으로 승격하지 않는다.

## 턴의 목표와 제어

목표는 이번 턴에서 사용자의 판단을 진전시키고 다음 행동을 선택할 수 있게 하는 것이다. 단순히 조사를 일찍 끊거나 모든 결정을 사용자에게 넘기는 방식으로 바꾸지 않는다.

| 상황 | 이번 턴의 처리 | 사용자에게 보일 결과 |
|---|---|---|
| 목적이 명확하고 검토된 경로가 유일하며 실행 가능 | 선택 목적 안의 최소 원문·상위 조건을 연속 조회 | 확인한 답과 실제 근거; 불필요한 매 간선 승인 없음 |
| 다음 관계가 여러 의미 분기로 갈라짐 | 현재 근거와 선택지·차이를 저장하고 턴 반환 | 무엇을 선택하면 어떤 부족을 확인하는지 |
| 필요한 원문은 알지만 조회 실패/예산 부족 | 성공 receipt 보존, 실패 부분과 재시도 조건 기록 | 부분 답, 미확보 범위, 실패 이유와 다음 행동 |
| 해석·적용이 불확실 | 양쪽 근거·의견을 유지하고 재검토 대상으로 표시 | 잠정 판단, 불확실한 이유, 추가 근거 또는 사실 질문 |
| 같은 상태·같은 대상의 행동 반복 | 동일성·실패 fingerprint로 재실행 억제 | 이전 행동 결과 재사용, 반복을 막은 이유 |
| 실제 사건 사실이 없어서 적용 불가 | 무엇을 알아야 하는지 특정해 질문 | 필요한 사용자 사실만 질문; 법령 확보를 떠넘기지 않음 |
| 근거가 전혀 없거나 관계를 못 찾음 | 무근거 결론 없이 현재 조사 범위와 검색 시도 표시 | 다른 범위로 검색하거나 사용자가 대상을 구체화할 수 있음 |

원문 읽기·계획 선택·의미 분기 뒤에 기존 조사 제어기가 계속 진행/턴 반환을 판정한다. 현재 목적·이미 선택한 경로·허용 범위 안의 결정적 조회는 수행하고, 새 목적·경로 확대·해석 선택·무진전 지점에서는 상태를 넘긴다. 후보 목록을 한 번 보여주는 일만으로 조사 완료를 선언하지 않는다. 알려진 모든 관계를 읽을 때까지 반환을 막지도 않는다.

코드는 표시·상태 저장을 위한 자원을 먼저 남기고, 선택 프로필의 턴별 행동·호출·시간 한도와 세션 누적 한도를 확인한다. 구체 한도는 구현 및 실험 호출 전에 동결할 설정이며 이번 문서에서 운영 값을 바꾸지 않는다. 기존 출력 토큰 상한 없음 정책을 유지한다. LLM의 자유로운 종료 문장이나 `gaps=[]`만으로 종료 상태를 결정하지 않고, 등록된 부족·관계 검토·실제 실행 상태를 함께 조립한다. 미등록 부족의 완전 발견을 코드가 보장한다고 주장하지 않는다.

## 한 턴의 반환 묶음과 화면

하나의 버전 있는 논리 봉투에 아래 항목을 둔다. 이는 확정 JSON Schema나 신규 Gold 객체 종류가 아니다. 기존 판단 원장·원문 receipt·계획·표시 계약을 확장한다.

| 항목 | 내용·소비자 |
|---|---|
| 확인한 답 | 실제 확보한 근거에 연결된 주장과 적용 범위. 주장이 없으면 확인한 원문·조사 상태만 표시 |
| 현재 목적·쟁점 | 이번 질문에서 무엇을 확인하려 했는지, 이전 턴과 달라진 범위 |
| 미확인 사항 | 부족/이견 ID, 관련 쟁점, 결론에 미치는 영향에 대한 의견, 해결 조건 |
| 다음 관계·경로 | 출발 원문, 정보 역할, 대상 확인 상태, 짧은 안내, 상위 조건, 선택 가능한 행동 |
| 행동 기록 | 제시·선택·시도·성공·실패·미실행, 당시 이유, 재사용 여부, 턴 반환 사유 |
| 후속 입력 결속 | case/turn/revision, plan/option ID, 표시 hash, 허용 행동·권한·원문/지식 binding |
| 축적 상태 | 대화 관찰/미매핑/검토 후보/공유 게시를 구분. 저장됐다고 승인됐다고 표시하지 않음 |

기본 화면은 확인한 답과 미확인 항목, 선택 가능한 경로의 짧은 설명이다. 상세 펼침에는 실제 원문, 판단 이유, 제외·보류 후보, 도구 실패, 정정 전후와 다음 권장 행동을 제공한다. 원장 전체를 매 턴 프롬프트·화면에 복제하지 않고 쟁점·변경분·참조 ID로 회수한다.

LLM이 제안할 항목은 현재 후보의 선택, 적용성 의견, 근거에 연결된 이유, 미확인, 다음 행동의 의미로 제한한다. 서버가 ID·판본·권한·실행 상태·계산·표시를 조립하며 기본 화면 갱신은 별도 모델 호출을 쓰지 않는다. 구조화 출력은 형식 통제 수단이며 의미 정확성의 증명이 아니다. 사용할 로컬/GENOS 모델의 지원 기능·실제 판단 품질은 향후 해당 환경에서 검증해야 한다.

그래프는 `확보 원문 → 위임된 세부 범위 → 미확보 대상/확인된 목적지 → 다음 행동`을 보여준다. 읽음·미읽음·검토됨·후보·실패·사용자 제외를 텍스트로 구분한다. UI가 그래프를 지원하지 않아도 같은 상태를 텍스트·표로 전달하고 번호/자연어로 선택할 수 있어야 한다. 사용자에게 내부 도구명이나 hash를 선택하게 하지 않는다. 대량 후보는 목적별로 묶고 페이지를 제공하며 생략 범위를 표시한다. 접근 불가 문서의 제목·내용·숨은 후보 수는 노출하지 않는다.

### 미읽은 조문을 짧게 안내하는 기준

- 현재 판본의 본문을 확보했다면 그 원문에 결속한 요약을 제공하고 읽은 범위를 표시한다.
- 대상 본문을 읽지 않았지만 원문 위임 문구나 검토된 관계 설명이 있으면 **확인하려는 정보**를 안내한다. 예: “자본적지출액의 세부 인정 범위를 확인할 경로 — 대상 본문 미확보.” 대상 조문의 내용을 요약한 것으로 표시하지 않는다.
- 제목/색인만 있으면 제목과 후보임을 표시한다. “이 조문이 해당 비용을 인정한다”처럼 효과를 채우지 않는다.
- 목적지조차 미확인이면 “대통령령의 대응 조문 찾기”처럼 탐색 과제를 표시한다. 모델이 만든 조항 번호를 조회 명령으로 넘기지 않는다.
- 과거 판본의 설명은 그 판본·검토 상태를 표시하고 현재 답의 근거로 재사용하기 전에 유효성을 확인한다.

### 실제 행동과 '어떻게 했어야 하는지'의 구분

당시 선택/실패는 실제 receipt와 당시 외부에 제출한 이유에서 구성한다. 당시 이유가 없으면 미기록으로 표시한다. 지금 제안하는 다음 행동과 사후 검토 의견은 별도 항목으로 남긴다. 현재 온톨로지 경로가 보여도 과거 실행 당시 그 경로를 알고 있었다고 기록하지 않는다. 숨겨진 모델 내부 추론을 복원한다고 설명하지 않는다.

## 최초 질문과 후속 대화 예

아래는 기존 실험 질문을 이용한 설계 시나리오이며 신규 실험이나 현행법 확인이 아니다. 정확한 조문 번호는 그 판본의 관계가 검증된 경우에만 표시한다.

1. 사용자가 양도가액에서 공제되는 경비를 묻는다. 에이전트는 제97조 원문과 그 범위의 온톨로지를 회수한다. 질문의 세부 범위는 잠정적이다.
2. 상위 범주는 확인했지만 시행령 세부 범위가 미확보인 상태에서 다음 선택이 필요해졌다면, 상위 범주만으로 충분하다고 숨기거나 모든 분기를 소진하지 않고 해당 상태를 반환한다.
3. 반환 예: “상위 규정의 비용 범주는 확인했습니다. 자본적지출액 등의 세부 범위는 아직 확인하지 못했습니다. 연결된 경로는 세부 범위와 적용 상위 조건을 함께 읽는 것입니다. 이번 턴에서는 해당 원문을 확보하지 않았습니다. 다음으로 이 경로를 확인하거나 다른 비용 범주를 선택할 수 있습니다.” 미실행 이유는 실제 기록에서 따로 붙인다.
4. 사용자가 “자본적지출액부터 봐줘”라고 하면 표시한 선택지를 같은 사건의 새 턴에 결속한다. 유효한 원문·판단은 재사용하고 선택한 범위만 조사한다. 경로가 이미 명확하고 최초 요청에 필요한 경우에는 2~3의 선택 대기 없이 이 조회까지 수행할 수 있다.
5. “그 조문 말고 이 항을 봐야 해”라는 정정은 대상 원문/관계의 revision에 연결한다. 기존 선택과 오류를 보존하고 새 원문을 검증한다. 사용자가 제외한 경로는 대화 범위 결정이지 그 관계의 보편적 부정이 아니다.
6. 목적·실제 가져온 자료·정정·근거가 연결된 후보를 Agent에 남긴다. 검토된 재사용 지식만 원문 중심 Gold에 반영한다. 다른 질문이 같은 원문에 도달하면 해당 방법·주의점을 회수한다.

## 상태·예산·재개 계약

한 턴의 응답 발행 완료와 조사 전체 완료는 다른 축이다. 전송/저장 완료, 근거 확보, 판단 확정, 추가 조사 필요, 사용자 선택 대기를 구분한다. 미확인 상태가 있다고 사용자에게 확보 원문을 전달하지 못하게 해서는 안 된다.

후속 턴은 같은 case에 새 turn/revision으로 이어지며 마지막 응답의 문장만 다시 읽어 상태를 복원하지 않는다. 목표·범위, 원문 receipt, 이전 판단과 이견, 부족, 선택/미선택 경로, 실패 fingerprint, 지식 판본, 사용량, 표시 이력을 기존 원장에서 회수한다. 새 빈 목록은 이전 부족을 해결하지 않는다. 해결·범위 제외·보류는 각각 이유와 대상 ID가 필요하다.

자연어 “두 번째”, “그거 계속”, “이 조건은 바꿔”는 표시한 선택지와 문맥에 결속한다. ID·revision·권한을 서버가 재검증하고 명확한 선택이면 별도 확인을 반복하지 않는다. 의미가 모호하거나 현재 상태와 충돌하면 제안을 보존한 채 짧게 확인한다. 단순 재표시·동일 버튼 중복은 모델 호출·조회·상태 변경을 발생시키지 않는다.

같은 요청의 네트워크 재개/재시도에는 최초 deadline과 누적 사용량·실패 한도를 그대로 적용한다. 사용자가 새 범위를 선택하거나 추가 조사를 명시한 새 턴은 별도 요청으로 예산을 부여할 수 있지만, 이전 사용량을 지우지 않고 세션 누적 한도를 적용한다. 새 turn ID나 “다시”만으로 동일 상태의 실패·중복 조회 한도를 초기화하지 않는다. 소진된 요청의 재개와 추가 작업 요청을 구분해 receipt에 남긴다. 게시에 필요한 최소 자원이 없으면 LLM 재생성 없이 저장된 원문/상태에서 결정적으로 부분 응답을 만든다.

## 한 번에 교체할 범위와 이행

사용자의 “한번에 교체”는 프롬프트만 교체하거나 화면만 먼저 켜는 방식 대신 **진입·조사 제어·원장·응답 발행·화면·후속 재개·지식 후보 연결을 하나의 호환 가능한 전환 단위로 출시**하는 것으로 반영한다. 기존 원문·조회·권한·저장 기능을 모두 새로 작성하는 뜻은 아니다.

개발·합성 검사는 P0~P5로 나눌 수 있지만 운영 활성화는 동일 코드·계약·프로필·지식 release·표시 소비자가 맞는 통합 후보에서 한 번에 수행한다. 기능별 flag는 개발 검사에 사용할 수 있으며 사용자 요청을 구 제어기와 새 표시 계약의 혼합 상태로 실행하지 않는다. 구 사건은 구 계약으로 읽고, 전환이 필요하면 원문·현재 상태를 검증해 새 revision으로 명시적으로 이행한다. 실행 중인 요청은 시작한 코드/계약 binding을 유지한다.

실제 절차는 통합 후보 검증 → 소비자 호환 확인 → 승격 plan/apply → 선택 포인터 → 실제 로컬 서비스 확인이다. GENOS는 별도 반입·리비전 배포·워크플로우 화면 검증을 거친다. 실패 시 코드와 계약·프로필 선택을 함께 되돌리고 새 후보·정정·실패 기록은 삭제하지 않는다. 롤백한 구 소비자가 새 상태를 오해하지 않도록 새 계약 기록은 별도 읽기 어댑터/보존 상태로 둔다. 이번 요청에서는 설계만 갱신한다.

## 수용 기준과 실패 경계

| 시나리오 | 향후 통과 조건 |
|---|---|
| 명확한 질문·유효한 경로 | 필요한 같은 목적 조회를 수행하고 불필요한 선택 대기 없이 근거 전달 |
| 일부 답·새 분기 | 부분 답·미확인·각 경로의 짧은 설명·미실행 이유·선택 방법이 모두 표시됨 |
| 처음 질문/정정 이력 없음 | 작은 검토 온톨로지로 원문 도착→경로 설명→조회가 작동함 |
| 관계 없음·새 관계 발견 | 검색 필요 표시와 후보 축적, 존재하지 않는 간선/조항 번호 실행 없음 |
| 미읽은 대상 안내 | 원문 요약과 조사 목적 안내가 구분되고 실제 효과·예외를 생성하지 않음 |
| 다음 턴 선택·정정 | 같은 사건/표시 revision에 결속, 유효 원문 재사용, 영향 판단만 갱신, 이전 이견 보존 |
| 반복·빈 gaps·사용자 보류 | 같은 상태 재조회/재보정 억제, 부족 보존, 보류를 해결·관계 부정으로 바꾸지 않음 |
| 네트워크 재개/새 턴 | 동일 operation 중복 0, 재개 deadline 불변, 새 요청은 이력·세션 예산 유지 |
| 원문 판본/권한/CAS 변경 | 낡은 선택 실행 차단, 허용된 부분만 재회수, 숨은 자료 노출 없음 |
| 모델 판단·표시 생성 실패 | 원문 receipt·원래 제안·실패 보존; 결정적 부분 응답 또는 명시적 실패. 성공으로 위장하지 않음 |
| 표시/스트리밍/저장 | 동일 snapshot에서 조립, 부분 송신을 완성 답으로 저장하지 않음, 다음 턴이 저장 상태와 일치 |
| 통합 전환/롤백 | 실제 service와 UI가 같은 계약, 구 기록 읽기·새 기록 보존, MAIN/GENOS 상태 별도 확인 |

기존 [실패 복구 정책](../../OPERATIONS/AGENT_FAILURE_RECOVERY_POLICY.md)의 단일 복구 담당·제한 보정·총 예산·근거 검증을 유지한다. 새 부족이 의미 불확실이라는 이유만으로 인용·원문 전달을 차단하지 않는다. 사용자 선택 대기는 정상적인 턴 결과로 설계하되 원문/권한/상태 무결성 실패를 정상 대기로 숨기지 않는다.

평가는 한 턴의 답 완성률만으로 하지 않는다. 목적·부분 답의 정확성, 사용자에게 전달된 미확인과 유효한 다음 행동, 정정 성공, 여러 턴의 과업 완료, 불필요한 선택 요구, 사람의 검토 시간, 누적 호출·토큰·지연을 함께 측정한다. 실제 사용자 목적이 붙으면 품질이 좋아질 것이라는 기대는 가설이며, 턴·설명·검토 비용이 늘거나 사용자가 잘못된 경로를 선택하면 악화될 수 있다. 무수정 대화 로그를 일괄 Gold로 변환하지 않는다. 실모델 품질 비교는 별도 ADR 절차로 수행하며 이번 문서 검사는 그 실증을 대신하지 않는다.
