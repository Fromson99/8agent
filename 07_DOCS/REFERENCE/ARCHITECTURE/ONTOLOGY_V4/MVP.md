## 2026-10-27 사용자 정정: 사전 조립한 시나리오에서 업무 경로 선택

## 2026-10-27 보완: 측정·산정·조건의 의미를 조립하는 MVP

사용자 지시로 [ADR1121](../../../../04_EXPERIMENTS/ADR/ADR-1121-ontology-semantic-compilation/README.md)을 선점했다. 아래는 기존 v3 의미 모델과 v4 컴파일 설계를 이번 구현 범위에 연결한 내용이다. 이전 실험과 완료 기록은 보존한다. **1121은 합성/API110검사 통과 후 실제 제안2회 모두 예외 방향 오류로 종료했고 답변 비교는 미실행**이다. 예외 방향과 오류 위치를 명시한 [후속 ADR1124](../../../../04_EXPERIMENTS/ADR/ADR-1124-ontology-explicit-exception-contract/README.md)에서 구현·111검사·실제 생성·답변 비교를 완료했다. 의미를 코드가 자동 반전하거나 실패 기록을 덮어쓰지 않았다.

### 무엇을 데이터로 만들어야 하는가

원문끼리의 연결에 더해 다음 의미를 원문에 붙인다. 일차 저장 단위는 질문별 정답이 아니라 문서 판본·조항·span이다.

| 항목 | 표현할 내용 |
|---|---|
| 측정 대상 | 계약금액·거래금액·잔액·위험액 등 무엇을 나타내는 값인가 |
| 산정 입력과 결과 | 어떤 개념·타입·단위의 입력으로 어떤 결과를 만드는가 |
| 산정 방식 | 합산·차감·비율 적용 등의 원문 식, 각 입력이 담당하는 역할 |
| 범위와 시점 | 합산·제외 범위, 각각/합산, 기준일·기간, 적용 대상 |
| 조건과 법적 효과 | 조건이 어떤 효과에 붙는가. 예외의 대상, 추정·간주 등 법적 표현을 구분 |
| 의존관계와 근거 | 앞 단계 결과를 쓰는 다음 단계, 원문 인용, 발견한 에이전트 판단 기록 |

예를 들어 기존 가상 규정의 **거래 범위 결정 → 계약금액 합산 → 승인 기준 비교**를 데이터에서 조립한다. 원문 관계를 모두 나열하거나 모든 가능한 경로를 미리 생성하는 방식이 아니다. 선택한 목적 노드에 필요한 의존관계를 거슬러 모으고, 선행 입력부터 제공한다. 원문 회수 연결과 계산·판단 의존을 구분한다. 현행 v0의 `value.basis`·`qualifier`만으로 일반 산식과 의존관계가 구현됐다고 설명하지 않는다.

### 판단에서 조립 가능한 지식으로

1. 실제 에이전트의 판단과 그 판단이 본 원문을 입력으로 받는다. 과거 판단은 오류를 포함할 수 있는 관찰이다. 기준답변·사후 채점·최종 정답 문구를 생성 입력에 넣지 않는다.
2. LLM이 측정·산정·조건·효과 노드와 입력 의존, 예외 대상, 인용 구절을 제안한다. ID·판본·해시·권한은 서버가 실제 원문과 결속한다.
3. 스키마·원문·판단 ID·의존 대상·순환을 검사한다. 형식 보완은 한 번만 허용하고 의미를 서버가 고쳐 채우지 않는다. 형식 통과와 의미 승인·운영 적재는 별개다.
4. 데이터 계층의 순수 컴파일 함수가 선택 목적의 의존관계를 조립한다. 현재 전달 가능한 원문과 결속된 내용만 제공하며 미확보 부분과 그 후속 의존은 명시한다.
5. A1의 기존 원문·연결 전달에 의미 계획을 붙여 ASSESS에 제공한다. 이번 질문의 적용성·충분성·추가 조사는 기존 에이전트가 판단하고 기존 COMPOSE까지 추적한다.

이번 소규모 구현은 식·입출력·의존관계의 **근거 조립**을 검증한다. 자유 텍스트 식을 `eval`하거나 현재 사건의 사실을 추정해 자동 계산하지 않는다. 일반 수치 실행, 운영 승인 UI, S3/Oracle 적재는 이 실험의 완료 범위가 아니다. 연구 제안은 실험용으로 명시하고 사람 승인된 운영 온톨로지로 표시하지 않는다. 개발계 저장 책임은 최신 SIDDS/SIDDA 정정을 따른다.

### 구현·비교와 실패 계약

- 기준은 선택 MAIN107의 코드·SQL·응답 계약에 ADR1105의 원문 확보와 직접 ASSESS 연결만 이식한 격리 후보다. 기본 작업 코드나 선택 MAIN을 변경하지 않는다.
- 알려진 CM023 한 문항에서 기존 A1과 의미 계획을 추가한 A1을 비교한다. 첫 질문 해석·READ 선택 두 응답은 같은 보관 응답을 현재 gateway로 재생하고, ASSESS부터 새 모델로 실행한다. 첫 착지 차이를 온톨로지 효과에 섞지 않는다. 전체가 새 호출인 서비스 실험과 구분한다.
- 원문 집합·출력 계약·예산을 같게 유지한다. 생성 비용과 질문 처리 비용을 분리한다. 원문 전달, 의미 계획 전달, 최종 답변 반영을 각각 센다.
- 사전 관찰 항목은 기준금액 미달에 따른 제외와 별도 환급 조건의 분리, 추정과 간주의 구분, 이익 산정 입력·범위 보존이다. 제품 입력에는 이 평가표를 넣지 않는다. 인샘플 한 쌍이므로 일반화·법률 품질·전체 속도 개선을 인증하지 않는다.
- 원문·권한·판본·해시 불일치는 기존 오류 경로로 차단한다. 미확보는 UNKNOWN/검토 필요로 보존하며 FALSE나 0으로 바꾸지 않는다. 구조 제안 실패 시 수작업 정답 그래프로 대체하지 않는다. 모든 실패·부분 실행과 호출 비용을 보존한다.

상세 동결 기준·예산·실행 순서는 [사전 기준](../../../../04_EXPERIMENTS/ADR/ADR-1121-ontology-semantic-compilation/artifacts/criteria.json)에 있다.

### 실제 결과와 다음 수정 근거

MAIN107 기반 격리 후보에서 기존 판단3개와 원문28조각으로 **의미 노드25개·의존관계23개를 생성하고, 목표에 필요한17노드를 조립해 ASSESS에 전달했다.** 컴파일 자체는 모델 호출0회다. 생성과 보완에는1124에서2회가 들었으며 연구 제안 상태(`EXPERIMENT_PROPOSAL_NOT_APPROVED`)다. [실제 생성 구조](../../../../04_EXPERIMENTS/ADR/ADR-1124-ontology-explicit-exception-contract/artifacts/의미구조_실제생성본.txt)에서 산정 입력·범위·시점·조건·효과·근거를 확인할 수 있다.

기존 A1과 의미 계획을 추가한 A1을 알려진 CM023 한 문항으로 비교했다. **사전3항목은 양쪽2/3, 최종 답변은 양쪽 PARTIAL/LIMITED_ANSWER로 품질 개선을 확인하지 못했다.** 실제 ASSESS 원문120옵션은 같았고, 원문416단위 대조에서 불일치·권한위반0이었다. 형식·출처 검증과 의미 정확성은 별개다.

- **제안 의미 오류:** 원문에 서로 다른 표현이 있어도 과거 판단의 추정·간주 혼동을 복제했다. 환급 가능 표현을 의무로 분류한 노드도 남았다.
- **의존 누락:** 생성한 핵심 조건4개가 효과 노드에 연결되지 않았다. 목표에서 의존을 따라 조립하자 이 조건들을 포함한8개 노드가 계획에서 빠졌다. 원문28조각은 그대로 전달했으며, 이 계획만으로 원문을 줄이는 방식은 아직 검증되지 않았다.
- **최종 서술 오류:** 기준금액 산식은 의미 노드와 ASSESS에 정확히 있었지만 COMPOSE가 기업가치 증가분을 생략했다. 의미 계획 전달만으로 최종 문장까지 보존되지는 않았다.

첫2응답은 보관 응답 재생이며, 의미 조건에서는 현재 판단번호 결속 차이로 원문 선택 보완1회가 더 발생했다. 보완 후 같은 원문을 받은 것은 확인했지만 전체 시간·호출 차이를 순수 온톨로지 효과로 해석하지 않는다. 이번 작업은 실패 생성까지 새 모델9회·평가모델0회다. **선택 MAIN107·GENOS·운영 지식 적재는 미반영**이다. [실험 결과와 한계](../../../../04_EXPERIMENTS/ADR/ADR-1124-ontology-explicit-exception-contract/artifacts/실험결과.txt).

후속 구현은 원문과 제안의 의미 대조, 생성된 조건과 효과의 연결 누락 확인, ASSESS에서 COMPOSE로 넘어가는 산정 입력·법적 표현 보존을 다뤄야 한다. 이는 이번 실험으로 발견한 후속 요구이며 구현 완료가 아니다.

## 현재 후보: 검색식 묶음과 공통 법령 선택 — ADR-1056

2026-10-26 사용자 요청 “한번 만들어보고 실행해봐 몇몇개의 질문으로”를 반영했다. [ADR1056](../../../../04_EXPERIMENTS/ADR/ADR-1056-grouped-fulltext-compact-laws/README.md)의702파일 rev-001이다. 관련 계약/API176개 및 같은 동결 경로 API·모델 결속2개를 통과했다. 확대 검사의11실패는 수정 전1055에서도 같은 실패를 재현했다.

- 기존 최초 AI 호출의 `queries` 문자열에서 공백/AND, OR, 따옴표, 괄호를 읽는다. **공백/AND는 모두 일치, OR와 여러 검색식은 대안**이다. 별도 검색어 생성 호출이나 응답 필드를 추가하지 않는다.
- 복합어·숫자를 분해한 토큰을 독립 OR로 합치지 않는다. 단어와 따옴표의 내용 토큰 순서를 한 구문으로 유지한다. 기존 형태소 색인의 연속 조건이므로 원문 문자열의 완전 일치 보장은 아니다. 숫자·단위·실제 인용은 읽은 원문에서 검증한다.
- 검색식은 같은 own-block에서 평가한다. 서로 다른 항·호에 흩어진 요건은 AI가 별도 식으로 조사해야 한다. 결과가 없거나 넓으면 현재 검색식·법령 수·조문 페이지를 보고 기존 RESEARCH/SEARCH_BODY와 예산 안에서 조정한다. 임의 OR 완화·추가 무제한 호출은 없다.

## 이전 후보: 판단 연결의 부분 보완 — ADR-1055

2026-10-25 사용자 요청: “누락정도는 짧은 턴을 통해서 해결가능하지 않을까 전체를 다 안주고”. [ADR1055](../../../../04_EXPERIMENTS/ADR/ADR-1055-judgment-link-delta-repair/README.md)에서1054 동결 구현을 이어 수정했다. 진행 중1054의 코드·조건·결과에 섞지 않는다.

- 실제 주장·원문을 먼저 독립 검증한 뒤, 보조 판단의 빈 주장 연결·잘못된 연결·원문 공유 불일치를 판단 ID와 필드 경로로 모은다.
- 기존 수정1회에서 **해당 판단 행, 연결 가능한 기존 주장, 그 주장과 판단의 현재 원문·필요한 사용자 사실**만 보낸다. 전체 평가·과거 판단·전체 검색 결과를 다시 보내지 않고, 출력도 해당 판단 행만 받는다.
- 서버가 원래 평가에 수정분을 합친 뒤 전체 스키마·주장·인용·권한·상태를 다시 검증한다. 다른 주장·미확인·충돌은 바꿀 수 없으며 모델이 명시하지 않은 연결이나 의미를 채우지 않는다.
- 반복 연결 오류는 거절 기록과 검토 미완료를 유지하고 독립 검증된 주장만 제한 답변으로 반환한다. 기존 및 새로 제기된 미확인을 보존한다. 다른 스키마·근거·권한·해시·상태 오류는 이 경로로 성공 처리하지 않는다.

관련 계약/API75개 통과 후698파일을 rev-001로 동결했다. 합성 API의 최초 전체 평가 요청37,704바이트에 비해 부분 보완 요청은6,624~7,152바이트였다. 이는 입력 예시의 요청 JSON 크기이며 실제 제공자 토큰·지연·정확도 개선치가 아니다. 실모델 호출0회, MAIN·GENOS 미반영이다. 동결 경로 재검사와 최종 기록은 ADR1055의 결과를 따른다. JSON 파손이나 모든 필수 필드 누락을 처리하는 범용 부분 수정기는 아니며, 그 오류는 기존 경로를 유지한다.

## 이전 후보: 매 단계 서버 상태 전달 — ADR-1053

사용자 승인: “적용해보고 우리 mvp문서에 반영 후 실험 해봐”. [실험 기록](../../../../04_EXPERIMENTS/ADR/ADR-1053-ontology-mvp-step-state/README.md)의 격리 후보에서 구현·검사한 뒤 새111셀을 순차 실행한다. 이전 ADR1049는44번째 셀에서 출력 공백 반복으로 중단됐으며 새 실행에 합치지 않는다.

모델이 상태 조회 도구를 선택하기를 기다리지 않고, 공통 모델 호출 경로가 매 논리 판단의 입력에 `step_state`를 넣는다. 별도 요약 모델은 호출하지 않는다.

| 전달 내용 | 생성·검증 책임 |
|---|---|
| 현재 단계·이번 단계의 할 일·요청 위치 | 서버가 호출 단계와 실제 입력 필드에서 조립 |
| 상태·근거 revision | 현재 저널과 요청 binding 대조; stale·불일치는 오류로 유지 |
| 마지막 실제 도구명·결과 상태 | 저장된 관찰 기록 사용; 실패·거절·미확보를 성공으로 바꾸지 않음 |
| 저장된 근거 수·이번 입력의 원문 위치 | 서버 사실만 전달; 확보 수는 충분성·인용 승인 판정이 아님 |
| 미확인·기존 판단·다음 선택지 위치 | 기존 입력 필드를 가리킴; 판단 문장·원문·좌표를 다시 복사하지 않음 |
| 남은 호출·도구 및 답변용 예약·현재 호출 시간 | 해당 판단 시작 시점의 저널 예산. 시간 값은 현재 모델 호출의 제한시간이며 전체1800초 잔여시간과 다를 수 있음; 전체 deadline과 재시도 차감은 기존 서버가 유지 |

적용 경로는 현재 법률 에이전트의 요청 파악·조사 계획·검색/원문 선택·평가·답변 작성과 수정 요청, 대사 부모의 단계별 모델 호출 및 같은 경로를 쓰는 내규/외규 자식이다. 과거 미사용 에이전트·수집/VLM 파이프라인·오프라인 채점기는 이번 적용 범위가 아니다. 대사 경로의 전달 계약 검증과 이번37문항의 실제 법률 RAG 품질 평가는 구분한다.

원문은 기존 입력에 그대로 두고 상태는 별도 항목으로 보낸다. 모델에게 상태 재작성을 요구하지 않는다. 기존 판단은 의견이며 근거 확보나 법률 정답으로 승격하지 않는다. 원문·인용·권한·범위·해시·revision·필수 판단·저장/표시 검증은 유지한다. 이미 승인된 판단의 재개 키를 바꾸지 않으며, 상태 안내 때문에 재호출하지 않는다. 상태 안내가 추가되므로 입력 토큰 감소나 정확도 개선은 사전에 단정하지 않는다.

검색은 검증한 ADR1052 후보를 이어 쓴다. **허용된 조사 범위에서 검색에 걸린 법령 전체의 이름·적중 단어를 얇게 보여주고, 조문 후보는 전체 최대20개씩 더 보기로 제공**한다. 조문을 선택하면 구조를 보여주고 필요한 항·호와 상위 공통 조건만 읽는다. 미선택 형제 항목·범위 밖 조항은 확보한 원문으로 취급하지 않는다.

세 조건 모두 같은 검색·상태 전달·모델·데이터·예산을 쓴다. A0 온톨로지 없음, A1 승인 묶음의 동일 원문을 조립 없이 전달, A2 결정적 컴파일이다. 따라서 이번 비교는 이 공통 실행 방식 아래의 온톨로지 효과이며, 중단된 ADR1049와의 차이를 상태 안내만의 인과 효과로 설명하지 않는다. 출력 상한 없음,40물리호출·1024도구·1800초와 승인된 동일 모델 제공자429 전환 정책을 유지한다. 누락 법령 추가·자동 셀 재실행·MAIN 승격은 하지 않는다.

현재 상태: ADR1053은 정책 해시 설정 불일치로 모델 호출 전에 중단(0호출)했다. 상태 전달 코드는 보존하고 [ADR1054](../../../../04_EXPERIMENTS/ADR/ADR-1054-ontology-mvp-state-binding/README.md)에서 설정 결속 수정·실제 어댑터 초기화 검사를 추가했다. 관련 계약/API140개, 실행기31개를 통과하고 동결 경로22개 재검사 후 **2026-10-25 14:31 KST 새111셀 실행을 시작했다.** 실행은2026-10-25 16:49 KST 종료됐다.111셀 중 서비스 완료15, 제한 종료96이며 이 중93은 첫 read-choice의100000자 입력 한도,3은 판단 연결 검증에서 막혔다. 외부177호출은 모두HTTP200이었다. 채점 자료 수집은 누락된 평가 모듈 import에서 멈춰 법률 정확도·품질 통과는 미확정이다. 이 기록은 보존하며1056으로 자동 재실행하지 않는다. 동결·실호출·완료 여부는 ADR1054의 `design-freeze.json`, `matrix-progress.json`, `service-status.json`으로 확인한다. 완료 전에는 품질 통과로 보고하지 않는다.

사용자 확정(2026-10-24): **온톨로지 묶음도 기존 조사 범위 안에서만 읽는다.** 승인된 묶음이라는 이유로 사용자 지정 조사 범위를 넓히지 않는다. 범위 밖 조항은 원문을 읽거나 내용을 요약하지 않고, 미확보와 그 사유로 표시한다. 문서 접근권한 검사도 유지한다. 따라서 일부 조항만 확보한 묶음은 부분 확보 상태로 전달한다.

| 단계 | 하는 일 |
|---|---|
| 회수 | 도착한 조항(문서명 + 조문 좌표)에 붙은 승인 묶음을 찾는다 |
| 원문 결속 | 묶음의 조항마다 현재 판본 원문을 읽고 해시를 검증한다. 원문이 바뀌었으면 그 묶음을 쓰지 않고 "온톨로지 확인 필요"로 표시한다 |
| 조립 | 연결 종류의 순서(법이 정한 것 → 위임받은 내용 → 공통 조건 → 예외)로 배열하고, 연결 종류별 정해진 문구를 붙인다. 묶음이 고른 호·목만 넣고 형제 항목은 넣지 않는다 |
| 남은 연결 | 이 조항의 실제 연결 중 묶음이 다루지 않은 것을 "남은 연결"로 붙인다 |
| 전달 | 원문 조각은 기존 근거로 확보하고, 조립된 묶음은 조사 화면에 하나의 카드로 넣는다 |

## 랜딩과의 관계

MVP-1은 맞는 조문에 도착한 뒤의 효과를 본다. 첫 도착을 잘하게 하는 용어집 바꿔 넣기와 착지 예시는 [랜딩](LANDING.md)에 있다. 온톨로지 묶음에 속한 조문은 어느 것에 닿아도 묶음 전체를 컴파일하므로 착지 대상도 넓어진다.

## MVP-1 실험: 컴파일이 더 잘 찾게 하는가

같은 코드, 같은 모델(Qwen3.8), 같은 질문으로 세 조건을 비교한다.

| 조건 | 에이전트가 받는 것 |
|---|---|
| A0 기준 | 지금과 같음. 온톨로지 없음 |
| A1 연결만 | 묶음과 **같은 원문 조각**을 확보해서 주되, 조립하지 않고 연결 목록·원문 조각을 따로 준다 |
| A2 컴파일 | 같은 원문 조각을 위처럼 조립한 묶음으로 준다 |

A1과 A2는 받는 정보가 같고 조립 여부만 다르다. 그래서 둘의 차이가 컴파일의 효과다. A0와 A1의 차이는 정보를 더 준 효과다.

| 지표 | 내용 |
|---|---|
| 필수 근거 확보·인용 | 질문의 기준 근거 조문(CM 근거 좌표, 현재 세대로 재결속)을 읽었는가, 답에 인용했는가 |
| 답 정확도 | 기준답변과 비교(평가 쪽에서만 사용) |
| 엉뚱한 읽기 | 질문과 무관한 조문을 읽은 수 |
| 이상 행동 | 출력 형식 오류, 같은 목록 반복 선택, 미확보를 부족으로 남기지 않음 |
| 비용 | 모델 호출 수, 입력 토큰, 시간 |

### 씨앗 조문과 문항 (2026-10-24 선정, 묶음31개 실험용 승인)

씨앗 묶음 = 일부 조문에 대해서만 만든 이상적인 온톨로지다. 조문 선정 기준은 "근거에 주 조문 외의 연결 조문(위임·준용·조건·예외·정의·별표)이 있어서, 연결을 따라가야 답할 수 있는 문항"의 출발 조문이다. 목록은 [SEED_ARTICLES_20261024.json](SEED_ARTICLES_20261024.json)에 있다.

| 항목 | 수 |
|---|---:|
| 씨앗 묶음(출발 조문) | 31 |
| 묶음이 다루는 조문(출발 + 연결) | 70 |
| 시험 문항 | 37 (기준답변 있음 34: CM 27·FSC 7, 근거 확보만 3: RISK-CM-029·030, ADR-1037 질문) |
| 묶음 안 연결 (묶음별 고유) | 조건·예외 18, 준용·편입 15, 정의 11, 위임 9, 별표 2 |

출발 조문 31개 중 27개는 문항이 1개라 문항끼리 거의 독립이다. 예외는 증권 인수업무 규정 제6조(3문항), 코스닥 상장규정 제13조·벤처법 제16조의3·지배구조법 제29조·모범규준 제6-15조(각 2문항)다.

연결 조문은 기준 근거의 역할 표시에서 왔다. 그래서 이 묶음으로 얻는 효과는 **이상적 온톨로지일 때의 상한**이다. 사용 중 축적으로 만든 온톨로지가 같은 효과를 내는지는 MVP-2에서 본다.

### 표본 수

사용자 확정(2026-10-24): **현재 선정된 37문항으로 진행한다.** 아래 확대 표본 설명은 한계 해석용이며, 이번 MVP에서 문항을 추가하지 않는다. 씨앗 31개 승인은 유지하며 FSC 7문항의 재검토 기준답변을 이번 실험 평가에 채택한다. CM 27개 기준답변과 근거 확보만 평가하는 3문항은 유지한다. FSC003의 누락 법령 두 개는 추가하지 않고, 실제 원문 미확보와 답변 의미 정확도를 별도로 평가한다. 미확보만으로 답변 전체를 자동 오답 처리하지 않는다. 설계 동결과 실행은 준비 중이다.

문항마다 세 조건을 같이 돌려 짝지어 비교한다(McNemar, 양측 0.05, 검정력 0.8, 반대 방향 변화 5% 가정).

| 확인하려는 차이 (예: 필수 근거 확보율) | 필요한 문항 수 |
|---|---:|
| 30%p (40% → 70%) | 33 |
| 25%p | 42 |
| 20%p | 57 |
| 15%p | 85 |

현재 37문항이면 A0 대비 A2의 **30%p 이상** 차이를 확인할 수 있다. A1 대비 A2(순수 컴파일 효과)는 차이가 더 작을 가능성이 커서, 확실히 보려면 57문항 이상이 필요하다. 문항을 늘린다면 공개 금융위 질의회신 원본 521건(`01_DATA/wiki/raw/fsc`)에서 연결이 필요한 사례를 골라 기준 근거를 작성해 추가한다.

실행: 37문항 × 3조건 = 111회. ADR-1037 기준 문항당 약 4분·약 0.06달러이므로 순차 실행 약 7.5시간·약 7달러. 이미 알려진 질문이므로 효과 탐색(`decision_eligible=false`)이다.

## MVP-2 실험: 없는 곳을 온톨로지화할 수 있는가

온톨로지가 일부만 있는 상태에서 돌린다.

1. 도착한 조항에 묶음이 있으면 컴파일하고, 남은 연결을 함께 준다. 묶음이 없으면 지금처럼 탐색한다.
2. 에이전트는 남은 연결을 직접 가서 읽고 판단한다(기존 동작). 판단 기록이 에이전트 레이어에 남는다.
3. 실행이 끝나면 **제안 단계**가 돈다. 이번 실행에서 에이전트가 온톨로지 없는 조항에 가서 읽고 답에 쓴 판단 기록을 모아, LLM이 조항마다 하나를 제안한다.
   - 기존 스키마 v0에 맞으면: 기존 묶음에 추가하거나 새 묶음을 채운 JSON (예: "시행령 제163조 제3항 제1호 → 제67조 제2항, 준용, 자본적 지출액 계산 방법")
   - 맞지 않으면: 새 필드 제안(`ontology-schema-proposal-v0`)과 그 이유
4. 사용자는 제안을 받아들이거나, 고치거나, 거절한다. 받아들인 것은 다음 컴파일에 쓰인다.
5. 같은 질문을 다시 돌려, 새로 온톨로지화한 부분이 컴파일 묶음에 들어가 결과가 나아지는지 본다.

| 지표 | 내용 |
|---|---|
| 제안 수용 | 받아들임 / 고쳐서 받아들임 / 거절 비율과 사유 |
| 스키마 적합 | 기존 스키마에 들어간 비율, 새 스키마 제안 비율 |
| 근거 정확도 | 제안의 조항·연결이 실제 원문과 판단 기록에 있는가(코드 검사) |
| 되돌림 효과 | 받아들인 제안을 컴파일에 넣고 다시 돌렸을 때 MVP-1 지표가 나아지는가 |

제안 단계의 LLM 출력은 형식·원문·판단 ID를 코드로 검사하고, 1회만 다시 요청한다([개념 묶음 작업](CONTROLLED_KNOWLEDGE.md#개념-묶음-작업)과 같은 규칙).

## 구현·실행 이력 — ADR-1041

시험37문항과 기존 조사 범위 유지 정책을 반영했다. 최종 격리 후보 `compiler-r4/rev-001`에서88개 합성 검사가 통과했고 A0/A1/A2의 실제 로컬 API 전달을 확인했다. [31개 씨앗 검토표](../../../../01_DATA/ONTOLOGY_WORK/review/ADR-1041/SEED_REVIEW.md)와 [구현·검증 기록](../../../../04_EXPERIMENTS/ADR/ADR-1041-ontology-mvp-37-compiler/artifacts/IMPLEMENTATION.md)을 참고한다. 씨앗 승인 전 실모델 실험은 하지 않았으며 제안 단계는 미구현이다. MAIN103·GENOS는 변경하지 않았다.

결정 이력: [31개 승인 기록](../../../../01_DATA/ONTOLOGY_WORK/review/ADR-1041/APPROVAL_20261024_MVP37_R1.json)을 저장했다. 이어 금융위 과거 회신과 현재 원문의 시점 차이를 확인하여 사용자가 [FSC 7문항 재검토를 위한 실험 보류](../../../../04_EXPERIMENTS/ADR/ADR-1041-ontology-mvp-37-compiler/artifacts/experiment-hold-fsc-reference-review.json)를 선택했다. 이 보류 기록과 과거 기준답변은 이력으로 보존한다.

[FSC 7문항 재검토표](../../../../04_EXPERIMENTS/ADR/ADR-1041-ontology-mvp-37-compiler/artifacts/FSC_CURRENT_REFERENCE_REVIEW.md)는 현재 답변·최소 핵심 기준·보충 설명·미확인을 분리한다. 당시 후속 질문에 대한 사용자 답변은 **“현재 데이터로 재개하고 미확보를 별도 평가”**다. 바로 앞의 법령 보충 선택은 대체됐고, 두 답변 사이에 데이터 반입·수정이나 모델 실행은 없었다([재개 승인 기록](../../../../04_EXPERIMENTS/ADR/ADR-1041-ontology-mvp-37-compiler/artifacts/execution-authorization-20261024-r1.json)). 현재 세대와 승인 묶음 31개를 유지하고, 검토 기준답변은 [평가 전용 자료](../../../../04_EXPERIMENTS/ADR/ADR-1041-ontology-mvp-37-compiler/artifacts/cases-evaluator-r1.json)에 결속했다. FSC003에 필요한 상호저축은행법·개인채무자보호법은 계속 미확보로 남긴다. [데이터 결속 기록](../../../../04_EXPERIMENTS/ADR/ADR-1041-ontology-mvp-37-compiler/artifacts/dataset-freeze-r1.json)은 `READY_FOR_DESIGN_FREEZE`이며 최종 설계 동결과 실행은 준비 중이다. 이 기록 시점의 실모델 호출은 0회다.


최종 실행 후보 보완: `compiler-r5/rev-001`의656파일로 A0/A1/A2를 연결하며102검사가 통과했다. 승인된 CM 질문을 공개로 잘못 표시하지 않도록 새 독립 세션의 반출 승인 연결을 보완했고, 기존 private history는 허용하지 않는다. 상세는 [구현 기록](../../../../04_EXPERIMENTS/ADR/ADR-1041-ontology-mvp-37-compiler/artifacts/IMPLEMENTATION.md)의 마지막 절을 따른다. r4와 이전 검사 이력은 보존한다.


실행 상태 갱신: 승인된 현재 데이터 선택과 FSC 기준답변으로 111회 순차 실험을 시작했다. [실행 동결](../../../../04_EXPERIMENTS/ADR/ADR-1041-ontology-mvp-37-compiler/artifacts/design-freeze.json)과 [실행 전 검사](../../../../04_EXPERIMENTS/ADR/ADR-1041-ontology-mvp-37-compiler/artifacts/execution-ready-r1.json)가 정본이다. 시작은 완료·성능 통과를 뜻하지 않으며, 실제 완료·중단 상태는 matrix-progress.json 및 matrix-stop.json에 기록한다.


ADR-1041 중단 당시 상태: 첫 문항 A0의12번째 모델 전송에서 연결 오류로 중단했다. 완료0/111이며 자동 재시도하지 않았다. 당시 사용자에게 같은 조건의 새 실험 기록으로 처음부터 재실행할지 확인했다. [중단 기록](../../../../04_EXPERIMENTS/ADR/ADR-1041-ontology-mvp-37-compiler/artifacts/STOP_REVIEW.md)은 보존한다.

### 실행 이력 — ADR-1042 중단

사용자가 동일 조건으로 111회 재실행을 승인하여 [ADR-1042](../../../../04_EXPERIMENTS/ADR/ADR-1042-ontology-mvp-37-restart/README.md)를 새로 선점했다. 동결·실행 전 연결 확인·ADR 검사를 마친 뒤 37문항 × A0/A1/A2의 순차 실행을 시작했다. 제품 코드·현재 데이터·승인 묶음 31개·평가 기준·모델·예산은 동일하며, 실행 식별자와 저장 경로를 분리했다. ADR-1041의 실패 기록이나 예산을 초기화하지 않았다.

[재실행 승인](../../../../04_EXPERIMENTS/ADR/ADR-1042-ontology-mvp-37-restart/artifacts/restart-authorization.json), [실행 동결](../../../../04_EXPERIMENTS/ADR/ADR-1042-ontology-mvp-37-restart/artifacts/design-freeze.json), [실행 전 확인](../../../../04_EXPERIMENTS/ADR/ADR-1042-ontology-mvp-37-restart/artifacts/execution-ready.json), [실행 도구 동일성](../../../../04_EXPERIMENTS/ADR/ADR-1042-ontology-mvp-37-restart/artifacts/runner-identity.json), [질문 인덱스](../../../../04_EXPERIMENTS/ADR/ADR-1042-ontology-mvp-37-restart/실험/README.md)를 따른다. 실행 경로는 `06_TOOLS/EXPERIMENTS/adr_1042/run_matrix.py`, 산출물은 `04_EXPERIMENTS/ADR/ADR-1042-ontology-mvp-37-restart/artifacts/`다.

첫 문항 A0의 12번째 모델 호출이 제공자 HTTP 400의 문맥 길이 초과 오류로 실패하여 실행을 중단했다. 완료 0/111, 제품 호출 시도 12회 중 정상 응답 11회이며 실패 호출의 사용량은 미확인이다. 평가 모델 호출은 0회다. 제공자 오류에는 `input at least 131073 + output 131072 > max 262144`가 표시됐다. 중단 당시 원인 분석과 다음 실행 방식에 대한 사용자 확인을 기다렸다. 이후 입력 구성 수정·검증 후 재실행 승인을 받아 ADR-1043으로 분리했고 출력 상한은 계속 없다. [중단 검토](../../../../04_EXPERIMENTS/ADR/ADR-1042-ontology-mvp-37-restart/artifacts/STOP_REVIEW.md)와 [결과 기록](../../../../04_EXPERIMENTS/ADR/ADR-1042-ontology-mvp-37-restart/artifacts/RESULT.md)을 따른다. 성능 비교 결과는 미확정이며 MVP-2·MAIN103 승격·GENOS 적용 상태도 바뀌지 않았다.

## 최신 실행 상태 — ADR-1043 스키마 간소화 범위 사용자 확인 대기

**현재 상태 — 2026-10-24 11:49:33 UTC:** 스키마 필수 응답 항목과 실패 처리의 **간소화 범위를 사용자에게 확인하는 중**이다. `matrix-stop.json`에 `SCHEMA_CONTRACT_DECISION_REQUIRED`를 기록하여 추가 모델 호출을 차단했다. 이는 사용자 확인을 위한 중단이며 제공자·실행기 장애로 분류하지 않는다. 6/111이 종료됐고, 그중 4개는 서비스 응답, 2개는 `NATIVE_BOUNDED_FAILURE`다. 서비스 응답은 의미 정확도 통과를 뜻하지 않는다. 7번째 실행은 중단 처리와 프로세스 회수를 완료했다. 부모 실행기는 exit 2로 종료됐고 시작한 7개 실행 모두 `process_reaped=true`를 확인했다. 중단 이후 추가 모델 호출은 0회이며 결과 보고서를 생성했다. **111회는 미완료이며 품질 비교도 미확정**이다.

첫 A1에서 공백·CR·LF가 반복된 미완성 JSON이 `finish_reason=length`로 끝난 사실은 확인했다. 스키마 자체 모순, 스키마 복잡성 또는 제공자 디코더가 이 반복을 일으켰다는 인과관계는 아직 확정하지 않았다. 사용자에게 제시한 범위는 중복 판단 설명 정리, 이미 선택한 근거 ID의 서버 합산, ASSESS 최종 검토의 변경분 중심 기록, 보조 검토 결속 오류의 분리 처리다. 이는 단순 표현 압축을 넘어 필수 응답 항목과 실패 처리 계약을 바꾸는 제안이며, [관찰·간소화 범위](../../../../04_EXPERIMENTS/ADR/ADR-1043-ontology-mvp-input-budget/artifacts/SCHEMA_CONTRACT_FOLLOWUP.md)를 따른다. 현재 동결 코드·기존 결과·평가 기준은 변경하지 않는다. 출력 상한 없음, 현재 데이터·조사 범위·승인 묶음 31개·37문항과 MAIN103·GENOS 상태를 유지한다. 사용자 확인 이후의 구현·검증·새 실험은 별도 기록한다.

사용자가 **출력 상한 없음**을 유지하며 입력 구성·스키마 최적화를 검증한 뒤 37문항 × 3조건을 새로 실행하도록 승인했다. [ADR-1043](../../../../04_EXPERIMENTS/ADR/ADR-1043-ontology-mvp-input-budget/README.md)에서 같은 현재 데이터·승인 묶음 31개·평가 기준·조사 범위를 유지한다. FSC003의 미확보 두 법률은 추가하지 않는다. ADR-1041/1042는 `abandoned`로 종료했고 실패 원문과 예산 이력을 보존한다.

새 후보 `compiler-r6`와 `compiler-a1-r6`의 동일 661파일을 `rev-001`로 동결했다. [제품/API 합성 검사 188개](../../../../04_EXPERIMENTS/ADR/ADR-1043-ontology-mvp-input-budget/artifacts/compiler-r6-contracts-01-validation.json)와 [보충 지표 검사 9개](../../../../04_EXPERIMENTS/ADR/ADR-1043-ontology-mvp-input-budget/artifacts/host-excerpt-metrics-validation.json), 총 **197개가 통과**했다. 사전 검증의 외부 모델 호출은 0회였으며 후보 밖 runtime import도 없었다. 과거 r5의 102개 통과를 새 후보 검증으로 상속하지 않았다.

저장된 ADR1042 실패 요청의 정적 비교에서 출력 스키마는 canonical UTF-8 **15,858 → 13,787바이트(13.06% 감소)**, 조사 화면 view는 **338,737 → 317,363바이트(6.31% 감소)**였다. 후자는 system/schema를 제외한 user view 측정이다. 바이트는 토큰이 아니며 이 결과만으로 실제 문맥 수용·토큰 절감·답변 품질을 확정하지 않는다.

기존 `max_context_chars=100000`을 이제 system·schema·수정 피드백·제공자 필드를 포함한 **최종 전송 요청의 canonical 문자 수**에 적용한다. 이전 부분 화면 검사보다 엄격한 동작 변경이다. 전송과 같은 preview로 물리 호출 예약 전에 검사하며, 초과 사유·남은 예산·deadline은 저장·재개 시 유지한다. 보내지 않은 원문을 모델 전달로 표시하지 않는다. ASSESS 입력 초과는 `INCOMPLETE`/법률 주장 0개와 검증된 원문 발췌만 남기고, COMPOSE는 스트리밍 전 이미 검증된 판단만 결정적으로 표시할 수 있다. 상세 [실패 계약](../../../../04_EXPERIMENTS/ADR/ADR-1043-ontology-mvp-input-budget/artifacts/DESIGN.md)을 따른다.

초기 실행 이력: [실행 설계](../../../../04_EXPERIMENTS/ADR/ADR-1043-ontology-mvp-input-budget/artifacts/design-freeze.json)를 동결하고 **111회 순차 실험을 시작했다**. 2026-10-24 11:23:40 UTC 확인 시 첫 A0는 제한 종료, A1 실행 중; 실행 종료 1/111이었다. 당시 호출 영수증에서 A0의 5회와 A1의 1회, 총 6회 물리 호출을 확인했다. 첫 A0는 `NATIVE_BOUNDED_FAILURE`로 종료한 것이며 정답·품질 통과를 뜻하지 않는다. 이후 진행·완료·중단은 `artifacts/matrix-progress.json`, 각 셀의 `result.json`, `matrix-stop.json`이 정본이다. 실행기는 `06_TOOLS/EXPERIMENTS/adr_1043/run_matrix.py`이며 중복 실행하지 않는다. **완료·품질 결과는 미확정**, MVP-2·MAIN103·GENOS 상태는 바뀌지 않았다.
