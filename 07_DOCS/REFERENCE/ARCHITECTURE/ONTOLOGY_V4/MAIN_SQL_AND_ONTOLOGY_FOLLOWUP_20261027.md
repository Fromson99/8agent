HTTP200·원문 일치·최종 발행은 법률 정답 판정이 아니다. 이 질문은 결론을 확정하지 못한 제한 답변이며 법률 정답률은 채점하지 않았다. 새 원문/코드/권한 무결성 문제로 SQL 개선을 롤백할 근거는 관찰되지 않았다.

실행·결과는 [ADR1074](../../../../04_EXPERIMENTS/ADR/ADR-1074-ontology-after-sql-main/README.md)에 보존한다. 3문항×A0/A1/A2의 9셀을 새로 동결했다. 1072 후보에 누락되어 있던 1067의 원문 재표시·스키마 준비 최적화 6파일을 선택 합성했고, **집중 계약/API 87개와 실행 보호 15개**가 통과했다. 후보 749파일은 3조건에서 동일하며 MAIN104의 두 SQL 함수와 AST가 같다.

## 반복 검증·추가 SQL 병목 — ADR1076·1078·1080·1081

실제1075에서 연결 범위마다 누적 원문 전체를 다시 검증하는 호출 경로를 확인했다. 한 화면의 `offer_choices` 호출 안에서 성공적으로 검증한 원문 범위만 재사용하고, 다음 화면에서는 새로 검증하는 후보를 격리했다. 권한·원문 메타·span값/타입/순서·세션·store 변경은 재사용을 무효화하며 cache hit에서도 세대 불변 검사를 수행한다. 메뉴·의미 판단·모델·프로필은 바꾸지 않는다.

ADR1076의 새 유한 상태 계약1,318쌍은 통과했으나 기준 재생은 마지막 답변 준비에서 실행마다 생성되는 선택ID 차이를 비교기가 처리하지 못해 실패했다. 앞선35개 화면은 모두 원본과 같았고 합계736.500초였다. 실패 실행의 전체 요청시간을 성공한 기준 응답시간으로 사용하지 않는다.

ADR1078은 별도로280개 연속 상태 변경 쌍을 고정·통과했다. 재생은35개 원래 화면이 모두 일치한 뒤 V1/V2 표시번호 차이로 중단됐다. 화면UUID와 미리보기ID를 함께 정렬하면서 번호가 바뀌는 경로를 원장·내용 hash로 확인했다. 제품 응답을 고쳐 통과시키지 않았으며 두 ADR의 실패 상태를 보존한다. 후보35개 화면 합계582.630초는 실패 실행의 부분 관측이다.

남은 비용을 SQL 실행계획으로 확인한 결과, `reference_end/target/candidate/candidate_end`의 허용 VIEW가 참조 전체를 `IN (SELECT id ...)`으로 다시 훑었다. [실행계획 근거](../../../../09_ARTIFACTS/AUDITS/20261027-navigation-reference-plan/README.md)를 보존하고 ADR1080에서 같은 허용 VIEW의 해당 참조ID를 `EXISTS`로 확인하도록 변경했다. DISTINCT·정렬·페이지 제한·권한 경계는 유지한다. 이 단계에서는 세 제품 파일을 격리 후보에서 검증했고 MAIN104를 유지했다. ADR1080은 합성 fixture가 같은 기본키를 중복 삽입하는 구성 결함으로 중단됐다. 기존·수정 코드 모두 같은 실패이며 제품 차이가 아니다. 이미 관측한1,345쌍은 보조 근거, 제품 조회 전 중단/미실행237조건은 신규 주계약으로 분리한 ADR1081에서 fixture 전체의 사전 무결성을 확인한 뒤 검증했다.
