# 여러 기관의 용어·일상표현을 연결하는 공통 용어집 설계

작성: 2026-09-12. 상태: **다기관 의미 연결은 설계안. 공개 사전 RAW 수집은 별도 CLI로 구현·실행; 원천별 완료/미완료 기록 보존**.
원천별 완료/미완료와 구조화 범위는 [수집 결과](../REPORTS/PUBLIC_GLOSSARY_COLLECTION_20260912.md)를 따른다.
현행 실행은 [용어집 운영 문서](../OPERATIONS/GLOSSARY_ALIGNMENT.md)를 따른다.
이 문서는 기관 간 의미 연결 API·스키마가 추가됐다는 뜻이 아니다. 공개 원문 수집 CLI는 별도로 연결됐다.

## 1. 목적과 범위

법제처의 법령용어·지식용어·일상용어를 기반으로, KRX·금투협·금융위와 내부 문서에서
확보한 용어·정의·관계를 같은 구조로 정리하고 원문과 연결한다.
2026-09-12 사용자 선택에 따라 첫 금융·법률 통합판은 법제처와 경제배움e·국세청의 구조화 데이터를 사용한다.
한국은행·금투협 사전 PDF 추출은 후속으로 미룬다. 보유 기관 규정은 문서 연결 근거로 유지한다.
초기 적용 범위는 명시적으로 선택한 보유 문서 세대다. 기관 전체 수집으로 자동 확장하지 않는다.
전용 사전은 그 범위에 필요한 항목을 추가하는 별도 입력이며 기관마다 API가 있다고 가정하지 않는다.

공통화할 것은 산출물과 처리 절차다. 모든 기관이 법제처와 같은 목록·정의·관계 API를
제공하거나 같은 수준의 관계 데이터를 가진다고 가정하지 않는다.

## 2. 기관별 적용 가능성과 입력

| 금투협 | 규정의 용어 정의, 업무 해설서·가이드라인 | 보유 HTML/HWP 구조에서 정의와 명시적 준용 참조 추출 | 통합 최신 사전·용어 관계 API. 별도로 금융투자사료의 증권 용어사전 PDF 수집 경로 확인 |

## 3. 전체 흐름: 준비된 용어집과 문서에서 새로 얻는 용어집

```text
법제처 용어·관계 / 기관의 별도 사전
             ↓ 원천별 수집·정규화
         기본 용어집 G0
             ↓ 여러 단계에서 참조
선택 문서 → Document Ingestion → 구조화된 문서 D
                                     ↓
                         정의·약어·참조·일상표현 후보 추출
                                     ↓
                    G0의 항목과 대조 → 연결 검토 → 용어집 G1
                                     ↓
                   문서–용어 연결 → 그래프·온톨로지·RAG
```

문서가 있어야 생성되는 정의는 ingestion 뒤에서 보강한다. 기본 용어집은 문서 없이 준비할 수 있다.
G0를 참조한 실행에서 얻은 G1을 같은 실행의 입력으로 소급 적용하지 않는다.
비XML 구조화에 용어집을 주입하는 효과는 [BL-001](../../BACKLOG.md)의 별도 실험 대상이다.
PDF 사전도 기존 ingestion의 구조화 경로를 재사용한다. 사용자 요청에 따라 2026-09-12
규칙이 없을 때 자동 생성하는 경로를 연결했다([동작·제한](../OPERATIONS/GENOS_RECIPE_VLM.md)).
긴 사전의 분할 처리·스캔 블록 확보·용어/정의 추출 연결과 전수 실행은 아직 남아 있다.

## 4. 공통 구조: 표현·의미·근거를 분리

아래 이름은 설계 설명용 필드/저장 책임이다. 새 법률 의미 스키마나 enum의 확정안이 아니다.
법률 의미는 [LEGAL_SCHEMA.json](../../../00_SYSTEM/LEGAL_SCHEMA.json)의 정본 계약과 매핑을 검토한 뒤 연결한다.

| 구성 | 필요한 정보 | 식별·연결 원칙 |
|---|---|---|
| 원천 항목 | 기관, 원천 ID, 원문 버전, URL/파일, 해시, 취득 방식 | 다른 기관의 ID는 충돌하지 않게 기관별로 구분 |
| 표현 | 표제어·일상표현·약어, 원문 표기, 검색용 정규화 표기 | 같은 문자열은 검색 후보를 공유할 수 있으나 의미를 합치지 않음 |
| 출처별 의미 | 정의/설명 본문, 정의 종류, 문서·조항·시행 시점·업무 범위 | 한 표현에 여러 출처·범위의 의미를 연결 |
| 근거 | 문서 버전, 조문/페이지/블록, 정확한 범위 또는 출처 항목 | 원문으로 되돌아갈 수 있어야 함 |
| 관계 주장 | 양 끝 항목, 관계 종류·방향, 원천/추출 방법, 근거, 검토 상태, 적용 범위 | 제공 관계와 추론 후보를 분리; 표기 일치만으로 의미 동일 관계를 만들지 않음 |
| 문서 출현 | 문서·블록·위치·원문 표현, 의미 후보 및 선택 근거 | 출현 사실과 특정 의미의 적용 판단을 구분 |
| 세대·범위 | 포함 원천 버전, 문서 세대, 처리 버전, 결손·제외 범위, 검토 결과 | 같은 선택 입력으로 재현 가능한 공통 산출물 발행 |

안정적인 ID가 없는 사전 항목은 등록 시 내부 ID를 부여하고 원천 URL·앵커·표제어와 연결한다.
앵커/표제가 변하면 원천 동일성을 확인한 이행 기록을 남긴다. 표제어 해시 하나를 영구 ID로 삼지 않는다.
의미의 안정적인 ID와 그 내용 버전을 분리하여 개정된 정의가 이전 판본을 덮어쓰지 않게 한다.

## 5. 정의·관계 추출과 검토

1. **구조화된 사전/API:** 제공한 항목과 관계를 코드로 변환하고 원천 ID·링크·정의를 보존한다.
2. **규정의 명시적 정의:** 정의 조항과 “이 규정에서 …란” 같은 표현을 찾아 후보를 만든다.
   정의가 여러 호·목·표·단서에 걸치면 구조화된 전체 범위를 묶는다. 첫 문장만 정의로 확정하지 않는다.
3. **준용·다른 규정 참조:** “정의는 ○○규정에 따른다”는 참조를 별도 기록한다.
   대상 규정의 명시된 버전/시점과 조항을 확인한다. 없거나 모호하면 미해결로 보존한다.
4. **해석 회신·교육 설명:** 설명·사례·인용을 구분한다. 회신 전체를 보편적 정의나 일반 동의어로 바꾸지 않는다.
5. **의미 추출이 필요한 부분:** 기존 LLM 작성·검토 흐름을 재사용하여 후보를 만든다.
   원문 span, 정의 경계, 부정·예외·참조를 검증하고 검토 결과를 남긴다. 생성 사실만으로 승인하지 않는다.

기계적 원문 정합성 확인과 의미 검토는 서로 다른 완료 상태다.
외부 모델 사용은 기존 원천/모델 승인 범위를 따르며, 실제 내부 문서와 현장 모델 검증은 GENOS에서 한다.
새로운 추출 방식의 품질 비교는 구현 시 저장소의 ADR 실험 절차를 적용한다. 이번 설계에서는 실행하지 않는다.

## 6. 일상용어까지 연결하는 방식

법제처 일상용어 목록을 공통 출발점으로 재사용한다. 기관별로 일상용어 사본을 새로 만들지 않는다.
기관 사전에 있는 쉬운 표현이나 약어는 출처를 가진 표현 항목으로 추가한다.

연결의 증거는 다음 순서로 확인하되 각 관계의 의미를 유지한다.
- 제공자가 명시한 공식 관계: 방향·관계 종류·제공자를 그대로 보존.
- 문서의 명시적 약칭·동의 표기·준용 참조: 해당 문서 범위의 관계로 기록.
- 표기 정규화·동일 표제어: 검색/정합성 후보 생성에 사용.
- 문맥·정의 유사성, LLM 제안: 근거를 첨부한 검토 후보로 저장.

예시 경로(설명용; 특정 관계가 실데이터에서 검증됐다는 뜻이 아님):

```text
일상표현 A ─공식 관련 관계→ 법제처 용어 B
                                  ↓ 표기 일치: 후보
                         KRX 규정 속 용어 B의 의미
                                  ↓ 정의 근거
                         해당 규정 버전의 정의 조항
```

상단의 공식 관계가 하단의 기관 간 후보 관계까지 승인하지는 않는다.
A–B와 B–C가 존재한다고 A–C를 동의어로 확정하지 않는다. 범위가 다른 정의는 후보를 병렬 유지한다.
의미 확인 전 후보는 기본 검색 확장·답변 근거 경로에 자동 투입하지 않는다.
공식적인 관련어와 동의어도 구별하며 반의어·상하위어를 동일어처럼 확장하지 않는다.

현재 `scope_definition`은 원문 정의 단서를 보존하지만 완성된 다기관 의미 사전은 아니다.
`moleg:`/`legal:`/`daily:`에 결속된 식별자와 사전/검색 소비자를 함께 이행해야 한다.
기존 법제처 ID·연결은 대응표로 보존하며 출처별 ID를 문자열 치환으로 합치지 않는다.
기존 불변 ZIP과 활성 세대는 유지하고 새 형식·소비자가 검증된 새 세대를 별도로 발행한다.
현재 사용자 입력에서 manifest를 요구하지 않는 설계를 따른다. 파일/폴더 또는 소스 선택으로 입력받고
버전·계보·반입에 필요한 메타데이터는 시스템이 생성한다. 내부 산출물 기록과 사용자 입력 요구를 구분한다.

## 8. 발행·GENOS·향후 갱신

초기에는 명시적 수집/파일 입력으로 실행한다. pulling 스케줄러는 이번 설계의 구현 범위가 아니다.
선택 문서/원천 범위별로 수집→정규화→추출→검토→문서 연결→발행의 완료·미해결·실패를 기록한다.
지원하지 않는 기능, 원천 결손, 아직 수집하지 않은 범위, 처리 실패를 별도 집계한다.
용어·의미·관계·문서 연결은 같은 세대에 결속하고 소비자 호환성을 확인한 뒤 선택한다.
수집 완료가 의미 검토 완료 또는 GENOS 배포 완료를 뜻하지 않는다.

외부 공개 사전은 외부에서 구축해 GENOS로 반입한다. 내부 용어·문서는 GENOS에서 같은 모델로 추가한다.
공개 용어와 연결돼도 내부 정의·관계·원문이 공개로 바뀌지 않는다. 외부 반출본과 현장 결합본을 구분한다.
현재 Codex 세션은 GENOS에 접근하지 않는다.

향후 변경분을 받을 때도 동일 입력 경로를 사용한다. 전체 스냅샷/부분 업데이트를 명시하고,
부분 입력에서 빠진 항목을 삭제로 해석하지 않는다. 용어 수정 시 그 의미·관계를 참조한 연결/검색 자료를
갱신하고 이전 세대로 되돌릴 수 있게 한다. 용어집 변경만으로 모든 PDF를 자동 재구조화하지 않는다.

## 9. 구현 순서와 완료 기준

1. 경제배움e·국세청의 구조화 4,747항목을 공통 원천 항목으로 적재하고 출처별 설명·ID를 보존.
2. 법제처 목록·확보한 정의·제공 관계와 대조해 표기별 연결 후보 생성. 금융 분류와 선택 문서 출현을 바탕으로 금융·법률 범위 선정.
3. 동음이의어·약어·출처별 의미·적용 범위를 검토하고 일상표현 및 원문 근거와 연결.
4. 같은 산출물을 기존 용어집 CLI와 GENOS 작성·관계·검색 소비자에 연결하고 새 선택 세대로 검증.
5. 이후 기관 규정의 복합 정의·준용 추출, PDF 사전 및 추가 원천으로 확장. PDF는 첫 통합판의 선행 조건으로 두지 않음.

필수 확인 사례:
- 같은 표제어가 다른 기관/규정에서 다른 정의를 가져도 둘 다 남음.
- 다중 호·목·단서에 걸친 정의의 범위가 보존되고 원문 위치로 복원됨.
- 다른 규정의 정의를 준용할 때 대상·버전이 없으면 미해결로 남음.
- 일상표현→법제처 용어→기관 용어의 한 연결이 미검토이면 경로 전체가 승인됐다고 보고하지 않음.
- 교육용 설명, 특정 회신의 해석, 규정의 정의가 구분됨.
- 기존 법제처 ID·관계와 검색 경로가 이행 중 끊기지 않음.
- 개정/삭제 시 영향받은 연결을 갱신하고 이전 세대를 재현할 수 있음.
- 내부 용어와 공개 용어의 연결이 원문 접근권한을 확대하지 않음.

원천/단계별 처리 건수·정의 및 연결의 근거 보유율·미해결 참조·검토 대기·대상 밖 항목을 보고한다.
정의 경계 정확도·의미 연결 정확도·잘못된 검색 확장은 기관별 검증 표본으로 평가한다.
실험 표본·목표 수치는 구현/실험 시작 전에 확정하며 지금 임의의 품질 달성률을 선언하지 않는다.


## 10. 금융·법률 용어집 첫 통합판 — 2026-09-12 설계 구체화

상태: 입력 우선순위 반영 및 기존 데이터의 읽기 전용 대조 완료. 통합 데이터 생성·의미 승인·운영 선택은 미실행.
별도 법률 의미 enum이나 Concept 정본을 만드는 문서가 아니며 구현 시 LEGAL_SCHEMA와 기존 소비자에 매핑한다.

### 입력과 범위

- 경제배움e 3,029항목: 금융 815, 경제 705, 경영 631, 공공 556, 과학 210, 사회 112.
- 국세청 1,718항목: 세무 설명, 제공된 한자·영문, 설명에 포함된 참조 조문을 보존.
- 법제처: 기존 목록 ID, 현재 확보한 출처별 정의·공식 관계·조문. 목록 존재와 상세 수집 완료는 별개다.
- 위 사전 설명은 현재 시행 법령의 정의로 자동 간주하지 않는다. 수집일과 정의/법령의 유효 시점도 구분한다.

원천 4,747항목은 모두 보존한다. 첫 금융·법률 사용 범위는 경제배움e 금융 분류를 출발점으로,
선택 금융 문서에 실제 등장하는 경제·경영·공공·세무·법률 용어 및 근거가 있는 관련 개념을 추가한다.
금융 분류 이외 항목을 일괄 삭제하거나 국세청 전체를 금융 전문 용어로 분류하지 않는다.
포함 근거와 범위 밖 항목을 기록하며, 관련어 확장은 범위를 고정해 무제한 재귀 확장을 피한다.

### 결합의 단위

하나의 표제어 화면 아래에 다음 정보를 나란히 조회하는 구조를 목표로 한다.

- 원문 표현·검색 표기·한자·영문·명시적 약어.
- 출처별 의미/설명: 경제 설명, 국세청 해설, 출처와 적용 범위가 확인된 법령 정의.
- 법령/기관 문서의 버전·조문·정의 span과 용어 출현 위치.
- 제공 관계와 검토한 의미 관계; 연결 근거·범위·검토 상태.
- 미확보 정의, 미해결 조문, 충돌/동음이의어 후보를 숨기지 않는 상태 표시.

법제처를 모든 금융 개념의 상위 개념으로 두지 않는다. 각 기관을 출처로 유지하고,
확인된 개념·범위에 설명과 근거를 연결한다. 통합 설명 한 문장으로 원천 정의들을 덮어쓰지 않는다.
출처 기관 우선순위만으로 법률 적용을 결정하지 않고 대상 문서·법령·시점과 정의 범위를 확인한다.

실데이터 사례: 법제처 지식용어 `채권`에는 `1311389`와 `1311885`라는 별도 ID가 있고,
비고는 각각 청구할 권리와 자금 조달용 증권을 설명한다. 국세청 `nts:100000000000056196`은
한자 `債權`을 제공한다. 표기 일치만으로 세 항목을 하나의 의미로 합치면 안 된다.
법제처 목록의 일부 동음이의어 플래그만 믿지 않고 원천 ID·비고·정의 내용을 함께 확인한다.

### 연결 순서와 LLM 책임

1. 코드로 원천 ID·원문 설명·출처·해시를 보존해 정규화한다. 기존 법제처 ID는 유지한다.
2. 동일 표기와 한자/영문/명시적 약칭으로 후보를 찾는다. 표기 일치는 검색용 묶음이며 의미 승인 아님.
3. 이미 확보한 공식 관계와 명시적 조문 참조를 원문 근거로 연결한다. 관계 종류·방향은 원천 그대로 유지한다.
4. LLM은 후보의 동일 의미/다른 의미/관련성·범위 차이를 원문 근거와 함께 제안한다.
   확보하지 못한 법령 정의나 적용 시점을 생성해 메우지 않는다. 저근거·충돌 항목은 검토 대기로 둔다.
5. 검토한 의미와 문서 문맥을 연결한다. 미검토 후보를 기본 RAG 검색 확장에 자동 투입하지 않는다.

법제처의 빈 정의 필드는 경제배움e 설명으로 채우지 않는다. 경제 설명은 자기 출처의 설명으로
즉시 보관·조회할 수 있으며, 법률 정의는 확보 여부를 별도로 표시한다. 필요한 결손은 대상 ID를
모아 기존 수집 경로의 선택 범위·재개 기능으로 처리하고 전체 수집 재시작을 기본으로 삼지 않는다.

### 실제 표기 대조 — 의미 정확도 평가 아님

2026-09-12 보유 JSONL의 표제어에서 공백을 제거해 기존 alignment.sqlite의 `terms.key`와 비교했다.

|---|---:|---:|---:|---:|
| 경제배움e | 3,029 | 274 | 524 | 572 |

각 열은 원천 항목 기준이며 열 간 중복이 있어 합산하지 않는다. 의미 동일성·상세 정의 확보·관계 승인 건수가 아니다.
경제배움e와 국세청 사이의 공백 제거 표제어 교집합은 123개다.
동일 표기가 없는 항목도 금융·법률 범위에 필요하면 독립 항목으로 유지한다.

### 첫 발행의 완료 기준

원천별 항목을 손실 없이 조회하고, 표제어 묶음에서 출처별 설명·원문으로 이동할 수 있어야 한다.
동음이의어가 분리되고 근거 없는 의미 병합이 없어야 한다. 문서별 출현과 적용 의미 후보를
구분하며, 기존 법제처 ID/공식 관계를 보존하고 미수집·미검토를 명시해야 한다.
입력 snapshot·코드·스키마·검토 상태를 한 세대로 묶고 기존 소비자 호환성을 확인한 뒤 발행한다.
검색 품질 향상은 별도 ADR 평가 전까지 미확인으로 남긴다.
