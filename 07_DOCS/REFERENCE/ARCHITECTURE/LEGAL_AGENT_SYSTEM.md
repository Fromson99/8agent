# 새 법률 질의 시스템 `legal_agent` 구조

- 작성: 2026-09-18
- 상태: **짓는 중.** 조립기(ADR-0465·0466), 색인·참조 해소(ADR-0467), 탐색 루프 v1(ADR-0468)·rev-002(ADR-0469)·rev-003(ADR-0472)까지 만들었다. CM 51에서 Gemini 40/51(루프 rev-003), Qwen 35/51(rev-003, 채택은 rev-002의 34 유지)이다(기존 26). 운영 MAIN·GenOS는 바뀌지 않았다.
- 설계 근거: [법률 질의 에이전트 하네스 설계 v2](../RAG/LEGAL_AGENT_HARNESS.md)
- 사용자 결정(2026-09-18): 기존 탐색 런타임에 덧붙이지 않고 새 패키지로 짓는다. 답변 조립기부터 시작한다.
  GenOS 모델은 Qwen3.5-122B-A10B-FP8이고, 실험은 OpenRouter FP8 대리로 한다.

---

## 1. 왜 새 패키지인가

지금 탐색 런타임은 실험마다 하위 클래스를 한 겹씩 덧붙인 구조다.

```
NavigationSession → StructuredSession → RoutedSession → LegalSession → BoundSession
→ InheritedSession → MultiSession → TypedSession → WorkSession → (document-navigation-v1)
```

각 층이 앞 층의 도구·스키마·프롬프트를 복사해 고쳐 쓴다. 새 설계의 중심 개념(확인 항목 장부, 서버 카드,
도메인 하네스, 에이전트 프로파일)이 어디에도 없어서, 얹으려면 11번째 층이 된다.

바깥 계약은 그대로 쓴다. 파이프라인 프로필(`legal-rag`)의 슬롯 retrieve → select → assemble → answer와
요청·응답 스키마(`runtime.request` / `runtime.result`)다. 새 시스템은 **같은 계약의 새 프로필**로 꽂는다.
그러면 API·화면·골든 러너가 바뀌지 않는다.

## 2. 전체 흐름

```
요청(runtime.request)
  │
  ├─ ① 앞단 분류기 ─ 기능·목록·직독·용어·범위 밖 → 바로 응답
  │        │ 법률 질문
  ├─ ② 계획기 ─ 도메인 하네스: 과업 유형 → 확인 항목 장부
  ├─ ③ 탐색 루프 ─ 에이전트 프로파일이 강도 조절
  │     ├ 모델: 다음 도구 선택
  │     ├ 법령 색인 API(결정론): 읽기·펼치기·목차·참조·역인용·위임·정의·검색·판례 다리
  │     └ 신호 엔진(도메인 하네스): 읽은 원문 → 카드 + 장부 항목
  ├─ ④ 종합 관문 ─ 장부 전부 "근거 있음" 또는 "원문에 없음 + 검색 기록"
  ├─ ⑤ 답변 조립기 ─ 자유 서술 + 근거 핸들                    ← ADR-0465 후보
  ├─ ⑥ 인용 렌더러 ─ 핸들을 좌표 라벨로, 인용 본문은 작업 기록으로 ← ADR-0465 후보
  ├─ ⑦ 결정론 검사기 ─ 수치·핸들 확인, 경고만                   ← ADR-0465 후보
  └─ ⑧ 작업 기록 → 응답(runtime.result) ── 사람 판정 → 피드백 원장
```

## 4. 부품 사이 계약

모든 부품은 아래 형태만 주고받는다. 한 부품을 바꿔도 나머지는 그대로 돈다.

```
근거 단위   { handle: "E1", source_id, document_name: "상법", heading: "제628조(납입가장죄등)", text, origin: "law" }
             → 사용자 라벨 "상법 제628조"
장부 항목   { task_type: "설명·개정", item: "요건(수치 포함)", status: "근거 있음" | "원문에 없음",
              handles: ["E2"], content: "원문에서 확인한 내용" }
답변        { text: 사용자 표시 답(좌표 라벨만), citations: [핸들 → 라벨·원문], findings: [검사 경고],
              composition: { mode, task_types, ledger, raw } }
```

인용문 본문은 모델이 쓰지 않는다. 모델은 `[E1]` 같은 핸들만 달고, 렌더러가 좌표 라벨로 바꾼다.
예를 들어 모델이 "…3개월로 한다 [E1]"이라고 쓰면 사용자에게는 "…3개월로 한다 (코스닥시장 상장규정 제26조)"로 보이고,
원문 전체는 작업 기록의 인용 목록에 남는다.

## 5. 모델과 GenOS 대리

| 프로파일 | 모델 | 쓰임 | 형식 처리 |
|---|---|---|---|
| `flash-lite-exp` | Gemini flash-lite | 실험 기본 | 엔진 구조화 출력 |
| `genos-qwen-proxy` | Qwen3.5-122B-A10B, OpenRouter FP8 제공자 고정(AtlasCloud·SiliconFlow), thinking off | GenOS 서빙 모델의 외부 대리 | 스키마를 프롬프트에도 싣고, 로컬 검증 실패 시 1회 수리 |

GenOS 대리를 이렇게 정한 이유:
- ADR-0463: AtlasCloud가 strict `json_schema`를 받고도 강제하지 않았다(`handles` 대신 `evidence_handles`).
- ADR-0464: 스키마를 프롬프트에 함께 싣자 6/6 통과했고 수리는 0회였다.
- 현장 GenOS 클라이언트도 `json_schema`가 400일 때만 프롬프트 방식으로 내려간다. 받아 놓고 강제하지 않는 엔진에는
  대비가 없으므로, 새 시스템의 모델 어댑터는 처음부터 "프롬프트 병기 + 로컬 검증 + 1회 수리"를 기본으로 한다.

**외부 전송 규칙**: 대리 모델에는 CM 질문과 공개 출처(`law`·`krx`·`kofia`) 원문만 보낸다.
기준답변, 내부 폴더(`internal/…`) 문서, 출처 불명 문서(예: 내부 패키지의 위험관리지침)는 보내지 않는다.
ADR-0465 재생 입력에서 이 규칙으로 11개 근거 단위(9문항)를 뺐다.

### 1단계 1차 결과 (ADR-0465, 인샘플)

같은 채택 원문(run1)으로 조립 방식만 바꿨다.

| 조립 | Gemini flash-lite | Qwen3.5-122B FP8 |
|---|---:|---:|
| 기존 종합(run1 답변) | 26 | - |
| 새 조립기 plain | **30** | 26 |
| 새 조립기 + 확인 항목 장부 | 26 | **29** |

- 조립 측 격차 10문항 중 최대 8개(Qwen 장부)가 회복됐다. 하지만 회귀가 5~6개라 사전 채택 기준(+5, 회귀 ≤3)에 못 미쳤다.
- 장부는 모델에 따라 반대로 작동했다. Gemini는 장부를 한 줄로 뭉쳤고(46건 중 10건), Qwen은 평균 5줄을 쓰다가
  존재 여부 질문(cm-005)에서 모든 칸을 채우려고 다른 규정 내용을 끌어왔다.
- rev-002에서 고칠 것: 장부 항목을 유형 틀로 enum 고정 + 빠짐 확인·수리, 존재 여부 질문의 "규정 없음" 규칙,
  원칙 조문 먼저, 검사기 날짜 정규화, 반복 실행으로 변동 폭 측정.


### 1단계 2차 결과 (ADR-0466, 인샘플, 2회 실행)

rev-001의 결함 셋을 고쳤다. 확인 항목을 도메인 목록으로 고정하고, 답을 먼저 쓴 뒤 확인표로 점검하고,
"원문에 없음"을 정상 상태로 뒀다.

| 조립 | Gemini | Qwen |
|---|---:|---:|
| 기존 종합(run1 답변) | 26 | - |
| rev-002 plain | **30 / 30** | 27 / 28 |
| rev-002 + 확인표 점검 | 30 / 30 | 27 / 27 |

- 확인표의 **손해는 사라졌다**(rev-001 Gemini 26 → 30). 항목 고정과 순서 반전 덕분이다.
- 그러나 **이득도 없다.** 호출은 3배(92 → 274~282회), Qwen 비용은 $0.11 → $0.76이다.
- 모델이 확인 항목을 다 채우지 못한다. 92 case-run 중 90회에서 서버가 누락을 잡아 되돌렸고, 그래도 292개(Gemini)가 비었다.
- Gemini는 2회 실행에서 뒤바뀐 문항이 0건이라 30과 26의 차이는 변동 범위 밖이다.

**결정**: 확인표를 답변 조립 단계에서 뺀다. 조립 단계는 도메인 규칙 + 자유 서술 + 코드 인용 + 결정론 검사로 간다.
확인표는 "무엇을 더 찾을지 정하는" 탐색 단계에서 다시 시험한다. 그때는 항목을 짧은 ID로 주고 한 번에 요구하는 수를 줄인다.
조립 개선은 30/51에서 멈췄고 정답 조문만 준 상한은 44/51이므로, 다음 우선순위는 회수(2단계)다.


### 2단계 결과 (ADR-0467, 모델 0회)

- 문서 간 참조 해소: 105,122건 중 19.7% → 88.7%. "법 제9조"는 그 문서가 선언한 약칭으로, "「상속세 및 증여세법」 제60조"는
  인용부호 문서명으로 풀었다. 표본 40건 오연결 0.
- 항 단위 읽기: 800자 넘는 결정 조문 56개에서 전달량 중앙 1,912자 → 500자(−68.7%), 항 지목 55/56.
  코스닥시장 상장규정 제26조는 제3항("제1항 및 제2항에도 불구하고")을 뒤집는 항으로 자동 표시한다.
- 참조 1홉만으로는 놓친 결정 조문 28개 중 9개만 닿는다. 대신 **놓친 것 상당수가 FTS 최상위에 있었는데 안 읽혔다**
  (cm-007 1·3위, cm-020 1위인데 0개 읽음). 병목은 찾기가 아니라 읽기 정책이다.

### 4단계 v1 결과 (ADR-0468, CM 51 E2E, 2회)

서버가 FTS 상위 8개를 항 단위로 먼저 읽어 카드로 주고, 모델은 채택·펼치기·재검색·종료만 고른다.

| | 1회 | 2회 |
|---|---:|---:|
| 기존 런타임 | 26 | - |
| 조립기만 교체 | 30 | - |
| **루프 v1 (Gemini)** | **36** | **36** |
| 루프 v1 (Qwen FP8) | 30 | 31 |

- 문항당 호출 중앙값 2회(기존 런타임 약 10회). 결정 조문 노출 0.787, 채택 0.547.
- 안 채택된 결정 조문 34개: 보였는데 안 고름 14, 카드로 안 나옴 16, 마지막 라운드에 붙어 못 봄 4.
- rev-002: 채택으로 새 카드가 붙으면 한 라운드 더 보여 주기, 원칙·세부 조문 짝 채택 유도, Qwen 회귀 8건 분석.

### 4단계 rev-002 결과 (ADR-0469, CM 51 E2E, 1회)

루프를 두 곳 고쳤다. ① 모델이 조문을 채택해 참조 카드가 새로 붙은 라운드에는 done을 한 번 보류하고 새 카드에 new 표시를
해서 한 라운드 더 보여 준다. ② "원칙 조문을 채택했으면 위임·인용한 세부 조문과 시행령·시행규칙·세칙 카드를 확인해
수치·산식·기간·예외·절차가 있으면 함께 채택한다"는 규칙을 넣었다. 조립 규칙은 v2(기존)와 v3를 따로 쟀다.
v3는 "예·아니오 먼저, 원문 요건·수치·기간·예외를 빠짐없이 옮기기, '규정 없음'은 원문 전체에 답이 전혀 없을 때만"이다.

| 루프 rev-002 | 조립 v2 | 조립 v3 |
|---|---:|---:|
| Gemini flash-lite | **38** (v1 대비 +2, 잃음 0) | 36 (+3, 잃음 3) |
| Qwen3.5-122B FP8 | 30 | **34** (+6, 잃음 2) |

- 새 카드 확인 라운드로 cm-007·cm-048을 되찾았다. cm-004에서는 시행세칙 제23조를 채택하자 붙은 증권 인수업무 규정 제5조를
  이번에는 모델이 봤다. 조립기 입력의 결정 조문은 41 → 44/75.
- 같은 v3 문구가 Qwen에는 +4, Gemini에는 −2였다. Qwen은 근거를 받고도 "규정 없음." 5자로 답하던 버릇(cm-011)이 줄었다.
  Gemini는 반대로 cm-025("증자 후 주가 변동에 따른 조정 규정이 있는가", 실제로 없음)에서 조정이 있다고 답했다.
- **결정**: 조립 규칙판(얼마나 자세히 옮기나, "규정 없음"을 언제 쓰나)은 도메인 불변 규칙이 아니라 에이전트 프로파일 값이다.
  Gemini 프로파일은 v2, GenOS(Qwen) 프로파일은 v3. 두 하네스 분리가 데이터로 확인된 첫 사례다.
- 채택률은 0.573~0.587로 기준 0.60에 못 미친다. 남은 결정 조문 31개 중 15개는 카드로 한 번도 뜨지 않았다
  (상속세 및 증여세법 시행령 제49조 3문항, 벤처기업법 제16조의5·시행령 제11조의4, 상법 제434조·제415조 등).

### 4단계 진입 경로 측정 (ADR-0470·0471, 모델 0회)

루프 rev-002가 카드로 한 번도 보여 주지 못한 결정 조문 15개(Gemini 궤적)를 대상으로 진입 경로를 쟀다.

| 경로 | 새로 닿음 | 비용 | 판정 |
|---|---:|---|---|
| FTS 9~40위 제목 목록 | 6 | 목록 32줄 | 채택 |
| 역참조(채택한 법 조문 → 그 조를 받는 시행령) | 3 | 채택당 2장 | 채택 |
| 참조 해소 수리(약칭+하위 법령, 인접 단서 우선, 바깥 법 미해소) | 2 | - | 채택(표본 오연결 0/40) |
| 조문 지목 해소(질문·재검색어) | 4 | 문항당 ≤ 3 | 정밀도 0.90으로 재측정 대기 |
| 판례 다리 | 0 (판례셋 +35/101) | 3장 | 보류 |
| 제목·정의·동의어 다리 | 0~1 | 2~3장 | 기각 |
| 준용 역참조 | 0 | 2장 | 보류 |

- 목록·역참조·수리·지목 해소를 합치면 15개 중 10개가 닿는다.
- 가장 뚜렷한 발견: 모델은 재검색어에 "상속세 및 증여세법 시행령 제49조", "상법 제388조"처럼 조문을 직접 쓰는데,
  FTS는 번호만 같은 다른 법 조문을 돌려준다. 조문 지목은 검색이 아니라 바로 열어야 한다.
- 남은 5개는 질문이 시장을 지정하지 않았거나(cm-031), 본문 인용 없이 개념으로만 이어지거나(cm-025), 준용 순서 문제(cm-043)다.

### 4단계 rev-003 결과 (ADR-0472, CM 51 E2E, 1회)

ADR-0470·0471에서 고른 진입 경로를 루프에 배선했다. 질문·재검색어가 조문을 지목하면 바로 열고, FTS 9~40위를 제목 목록으로
보여 주며, 채택 조문의 참조 카드는 질문 순위로 고르고 역참조 2장을 더한다. 조문 지목은 모델 0회 관문(판례셋 정밀도 0.96,
삭제 조문 0, 공식 약칭 오해소 0/24)을 넘은 뒤 켰다.

| | rev-002 | rev-003 | 카드에 보인 결정 조문 | 조립기 입력 결정 조문 |
|---|---:|---:|---:|---:|
| Gemini(조립 v2) | 38 | **40** | 60 → 68 | 44 → 47 |
| Qwen(조립 v3) | 34 | 35 | 57 → 65 | 44 → 52 |

- 새로 맞힌 예: cm-018 "상증세법 시행령 제49조 제1항의 구조는?"은 질문 지목으로 시행령 제49조가 첫 카드가 됐다(rev-002에서는
  모델이 같은 조문을 11번 재검색했지만 FTS가 돌려주지 않음). cm-016·cm-029는 목록에서 벤처기업법 제16조의5, 소득세법 시행령 제163조를 열었다.
- **병목이 "보이기"에서 "고르기"로 옮겨 갔다.** Gemini는 참조·역참조로 붙은 결정 조문 9개를 하나도 채택하지 않았고(Qwen은 6개),
  목록 핸들을 열지 않고 바로 채택해 무시된 경우가 4문항이다(cm-048은 이 때문에 잃음). Qwen은 cm-019에서 목록만 11개 열고 채택 0으로 끝났다.
- **결정**: Gemini 프로파일은 rev-003, GenOS(Qwen) 프로파일은 rev-002를 유지한다(+1은 변동 범위).
- 다음(rev-004): 목록 핸들 채택을 "열고 채택"으로 처리(공통 수리), 위임받은 시행령 조를 서버가 근거에 함께 넣기(Gemini 프로파일),
  목록 열기 총량 상한(Qwen 프로파일).

## 7. 코드 원칙

1. **상속 사슬을 만들지 않는다.** 변형은 프로파일 값과 부품 교체로만 한다.
2. 결정론 부품(색인 API, 신호 엔진, 렌더러, 검사기)은 모델 없이 테스트된다.
3. 장부·관문·ID는 서버가 가진다. 모델은 제안한다.
4. 응답 스키마는 필드를 **추가만** 한다(작업 기록, 장부). 기존 소비자가 깨지지 않게 한다.
5. 새 부품은 저장소 실험 표준대로 ADR 후보로 격리해 재고, 채택된 판만 `02_BACKEND/legal_agent/`로 옮긴다.
6. 프롬프트에 골든 문항의 정답 수치나 문구를 예시로 넣지 않는다. rev-001 작성 중 "3분의 1 이상" 같은 예시가
   cm-042 기준답변과 겹쳐 뺐다.
