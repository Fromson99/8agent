# 군더더기 없는 Oracle·검증·재개 코딩

2026-11-11 사용자 지시. 지금까지 넣은 검증 로직·중간 저장(이어가기) 로직·Oracle 접근 방식은 대부분 "진짜 필요해서"가 아니라 "어떻게든 동작하게 만든 차력쇼"였다. 11-10~11 이틀 동안 그것을 걷어낸 수정이 34건이고, 현장 한 질문이 454.9초 → 30.8초(SQL 205.8초 → 1.1초)가 됐다. 같은 코드를 다시 만들지 않는다.

진짜 필요하면 만들어도 된다. 단 아래 질문에 답할 수 있어야 한다.

## 코딩 전에 답할 질문 5개

새 SQL·검증·해시·재확인·중간 저장·잠금·커밋·폴링을 넣기 전에 답한다. 답이 안 나오면 넣지 않는다. 넣었다면 완료 보고에 답을 한 줄씩 남긴다.

1. **몇 번 도나?** 질문 하나에 몇 번 실행되나. 반복문·폴링·메뉴마다·응답마다 안에 있나.
2. **한 번에 얼마인가?** 현장 기준 ORDS 왕복 5~10ms, 커밋 약 130ms, 전체 해시·직렬화는 데이터 크기에 비례. 횟수 × 비용을 계산한다.
3. **무엇을 잡나?** 이 검증이 잡는 실패가 실제로 일어난 적이 있거나 일어날 경로가 있나. 놓치면 무슨 일이 생기나.
4. **이미 하고 있지 않나?** 같은 확인을 신뢰 경계·다른 단계·DB 제약에서 이미 하고 있나.
5. **다시 하면 되는 일인가?** 실패하면 사용자가 질문을 다시 하면 되나. 그렇다면 중간 저장·재개·영수증은 넣지 않는다.

## 핵심 규칙 (상세는 references)

Oracle·SQL — [references/oracle-sql.md](references/oracle-sql.md)
- 반복문 안에서 SQL을 보내지 않는다. 묶어서 한 번에 읽는다.
- 로컬 파일·SQLite 방식을 Oracle 위에서 흉내 내지 않는다.
- 쓰고 나서 다시 읽어 확인하지 않는다.
- 질문 처리 중 Oracle 커밋은 0, 질문 끝에 1번.
- 범위·문서 전체를 펼쳐 돌지 않는다(1만 행 한도).
- 질문과 무관한 공통 자료는 서버 시작 때 준비한다.

검증 — [references/verification.md](references/verification.md)
- 검증은 신뢰 경계(모델 출력·외부 입력·권한·판본)에서 1번.
- 이미 검증한 내부 객체를 다시 해시·검증하지 않는다.
- 바뀌지 않는 것은 프로세스당 1번만 검사한다.
- DB 제약·트리거를 코드로 흉내 내지 않는다.

이어가기·상태 — [references/resume-state.md](references/resume-state.md)
- 기본은 중간 저장 없음. 서버가 죽으면 그 질문을 다시 한다(사용자 허용).
- 진행 표시를 위해 커밋하지 않는다. 로그 이벤트로 보낸다.
- 잠금은 짧게, 프로세스 안에서 끝낼 수 있으면 DB 잠금을 쓰지 않는다.

실제 사례 34건(문제·원인·일어난 일·해결·숫자) — [references/cases-20261110.md](references/cases-20261110.md)

## 다른 지침과의 관계

- [에이전트 실패와 충돌 처리 지침](../AGENT_FAILURE_RECOVERY_POLICY.md)은 **모델 출력·외부 입력·사용자에게 보이는 최종 상태**에 적용한다. 내부에서 이미 검증한 값을 단계마다 다시 검증하라는 뜻이 아니다. 내부 반복 검증·중간 저장·재개 영수증의 범위는 이 스킬이 우선한다.
- 권한·원문 인용·판본 일치 검사는 끄지 않는다. 신뢰 경계에서 1번 하고, 그 결과를 같은 요청 안에서 재사용한다.
