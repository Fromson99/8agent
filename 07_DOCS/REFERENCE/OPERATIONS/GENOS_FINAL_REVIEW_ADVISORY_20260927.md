# 최종 답변 보존과 법률 검토 필요사항

2026-09-27 사용자 지시: 최종으로 작성한 답변을 모두 표시하고 마지막 검사에서
걸린 내용은 법률 검토자가 읽을 수 있는 확인사항으로 전달한다.

## 적용 경로

`service.py` → `/v1/rag/ask` → 기존 v5 `ObligationSession` (선택형
`BoundedSourceSession` 포함) → 최종 작성 → 검토 → `final_review_notes.finalize`
→ 기존 StageRunner/outbox → 워크플로우 `genos_rag_chat.render`.
새 실행기나 데이터 세대를 만들지 않는다. v1~v4의 검토 경로는 그대로다.

- 최종 작성해 저장한 현재 문장을 순서대로 표시한다. 검색한 전체 문서나 폐기된
  이전 초안을 답변으로 자동 채택하지 않는다.
- 관계 ID 누락, 원문/답변 인용 불일치, 조건·예외·범위 불일치, 질문 요구 누락,
  부정적 검토 의견, 검토 응답 실패가 문장을 삭제하지 않는다.
- 기존 strict 검사는 실제 통과한 결과만 검토 원장에 저장한다. 실패는
  `FINAL_REVIEW_ADVISORY`에 원래 응답과 오류·문장 버전을 기록한다.
  검토 미완료를 SUPPORTED/ANSWERED로 바꾸지 않는다.
- 최종 검토의 재작성/재탐색 요구는 확인사항으로 넘기며 문장을 다시 숨기거나
  의미 검토 재시도 루프를 시작하지 않는다. 전송/형식 복구는 기존 예산 안에서 수행한다.
- 원문 조회·선택·접근 범위·실제 전달·세대/해시 검증은 유지한다. 구조적으로
  저장되지 못한 초안이나 원문을 확보하지 못한 요청의 답을 임의로 만들지 않는다.

## 법률 검토자에게 보이는 내용

답변 본문 다음에 **법률 검토 필요사항**을 표시한다. 예를 들어 모의규정 제1조가
제2조를 준용하는 답변에서 관계 검토가 빠지면 “모의규정 제1조와 모의규정 제2조:
답변에 사용한 조문 사이의 적용·인용 관계에 대한 최종 대조가 빠졌습니다”라고 쓴다.
문서명과 조·항은 확보된 원문 마디의 위치에서 가져오며 추측하지 않는다.
근거 자체의 부재와 최종 대조 누락을 구분한다. 관계 ID·영문 오류·파일 경로는
법률 확인사항에 표시하지 않고 진단 기록에 보존한다.

`answer.claims`는 승인된 주장만을 뜻하지 않는다. 동일한 term-runtime-v1 형식의
`answer.text`·`answer.unresolved[].reason`에 확인사항을 싣고 provider receipt의
`final_review_policy=advisory`, `claim_review_status`로 검토 상태를 구분한다.
법률 품질 인증은 false다. 확인사항이 있으면 READY를 BOUNDED로 낮춘다.
기존 선택 근거 카드와 source bundle 검증·해시는 그대로 유지한다.

## GENOS 적용과 원복

사진에서 적용을 확인한 `GENOS_RAG_SQL_CHECK_20260927_R1` 다음 패치로 인계한다.
기존 `~/DEV`의 파일을 해시 검사·백업 후 적용하고 엔진/PIPELINE 결속을 검증한다.
현재 코드서빙과 같은 generation으로 배포 게이트를 통과한 커밋을 push·배포한다.
워크플로우 Python 단계는 제공한 전체 TXT로 별도 교체·저장·배포한다.
추가 환경변수나 의존성 설치, 데이터 재구축은 필요하지 않다.
기존 인용문 완화 변수 0/1 모두 최종 답변 표시는 advisory이며 strict 검토 기록은
기존 변수의 의미를 유지한다.

검증은 모의 원문과 고정 응답으로 관계 검토 누락의 기존 실패를 재현하고, 문장
보존·조문 표시·오류 비노출·검토 실패 기록·HTTP·워크플로우·기존 v3/v4 경로를
확인한다. 실제 내부 모델 품질 실험이 아니며 외부 모델 호출은 없다.
현장 검증은 워크플로우 테스트 화면에서만 수행한다. 이전 코드서빙/워크플로우
리비전과 설치 백업을 보존해 원복한다. 코드 변경·ZIP 적용·Git push·서빙 배포·현장
답변 성공은 각각 별도 상태이며 현장 성공은 아직 미확인이다.
