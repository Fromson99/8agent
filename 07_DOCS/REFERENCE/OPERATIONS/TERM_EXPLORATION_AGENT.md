# 용어 기반 탐색 에이전트 — MAIN 배선과 실험 기록

## 현재 결론

2026-09-15 기준, 용어·정의·인용/준용 원문으로 탐색하는 후보를 구현하고 Gemini `gemini-3.1-flash-lite`로 실행했다. 기존 Rule/Clause/Proviso 의미 스키마나 glue는 모델 입력에 넣지 않는다. 문서 구조 좌표와 기존 관계의 출처·locator만 탐색 단서로 사용한다.

**정의·참조 조회 동작은 확인했고, 전체 답변 품질은 승인하지 않았다.** 이후 사용자가 품질 미통과 상태의 MAIN 배선을 명시적으로 지시하여 로컬 generation 12 `term-agent-rag-20260915-v1`로 전환했다. GENOS 현장에는 배포하지 않았다.

[현재 배선·35개 검사·활성화·롤백 기록](../../../09_ARTIFACTS/AUDITS/20260915-term-agent-main/README.md)을 먼저 본다. 운영은 실제159문서의 조회 인덱스와 원문 정의8,533개를 소비한다. 아래137개 단위/54개 정의 및 ADR0415~0417 수치는 이전 연구 범위의 기록이다.

## 실험에서 사용한 데이터와 행동

| 입력 | 사용 방법 | 한계 |
|---|---|---|
| MOLEG 법률 표제어 144,170개 | 질문 표제어 제안 → 실제 ID 해석 → 용어 출현 기반 검색 | 동형어 ID를 합치지 않음. 문맥 동의어 승인 아님 |
| CONNECTED 관계 48,581개 | 검색한 용어 주변의 제한된 다음 후보 | 원래 방향·코드 유지, 의미 확정 아님 |
| 기존 corpus_definition 54개 | 원문 block·해시를 대조하고 정의 문맥 조회 | 이번 공개 코스닥 규정에 한정. 27개는 선택한 MOLEG 표제어 ID와 연결됨 |
| 참조 후보 414개 | 출발 조문과 대상 조문을 양방향으로 열기 | 207개만 같은 문서의 명시 조문으로 해석. 나머지는 미확인 |
| 원문 137개 단위 | 공개 코스닥 규정 133개 조문 + 명시 모의 내규 4절 | 실제 내부 문서나 전체 159개 문서 평가 아님 |

정의는 같은 단어라는 이유만으로 적용하지 않는다. `source_text`, `document_id`, `block_id`, 원문 해시, `scope_status`, `scope_hint`, 위치를 함께 전달한다. 원문 기반 정의 후보의 미검토 상태를 보존한다. 외부 사전 정의 전체를 법적 적용 근거로 주입하지 않는다.

참조는 기존 semantic relation의 entity target을 그대로 사용하지 않는다. 원문에 명시된 조문 번호를 선택 문서의 article 좌표와 다시 대조한다. 기존 관계 217개 후보에 출처 정보가 남아 있으며, 누락된 명시 참조는 원문 표면 단서로 보강했다. 외부 법령·세칙, 범위 참조, 동일 조문 내부 참조처럼 이 후보에서 확정하지 못하는 연결은 `UNRESOLVED`로 남긴다. 다른 문서까지 여는 동작과 버전 충돌 처리는 이번에 검증하지 않았다.

## 실행 흐름과 계약

1. `TermTools.resolve`: 계획 모델이 제안한 표제어를 존재하는 용어 ID로 해석한다.
2. `search`: 허용 문서 범위에서 표제어 출현으로 상위 원문 3개를 회수한다. 이미 읽은 원문은 후속 검색에서 제외한다.
3. 첫 검토 전 `prefetch`: 질문에 직접 등장한 정의 최대 2개와 질문의 용어가 제목에 겹치는 인접 조문 최대 3개를 조회한다. 각 실제 조회를 `bounded_prefetch.results`에 남긴다.
4. `navigation_menu`: 정의 후보 및 인용 출발/대상 조문 후보를 보여준다. 모델은 `NAVIGATE`와 후보 ID 최대 3개를 선택할 수 있다.
5. `navigate`: 선택 ID·범위·방향을 검사한 뒤 원문을 연다. 역방향은 현재 조문을 인용하는 출발 원문을 읽는 것이며 법적 효과의 역방향 적용이 아니다.
6. 검토 모델은 `findings / open_questions / evidence_ids / next_action`을 반환한다. `EVIDENCE`는 재검색, `USER_FACT`는 사용자 질문, 충돌/예산 소진은 미확인 종료로 연결한다.
7. 응답 계약 오류는 사례당 1회만 별도 기록한 수정 호출을 허용한다. 빈 후보 목록은 선택 배열 길이 0을 강제한다. 실행 실패는 과거 초안을 `failed_draft`로 격리하고 빈 근거의 STOP 결과를 반환한다.

선조회는 시스템의 결정적 행동이다. 실제 실험에서 모델이 자율적으로 정의/참조 도구를 선택했다고 해석하면 안 된다. 원문·조회 동작과 모델 판단의 정확성은 별개다.

## 실제 검증

- [ADR-0415](../../../04_EXPERIMENTS/ADR/ADR-0415-term-agent-definitions-references/RESULT.md): 27회 호출, 8질문. 선택 도구만 제공했을 때 정의/참조 조회 0회. 내용 대조 5/8. 실패 보존.
- [ADR-0416 실제 기록](../../../04_EXPERIMENTS/ADR/ADR-0416-term-agent-navigation-gates/TRACE.md): 37회 호출, 616,899토큰. 정의 조회 8회·참조 조회 5회(역방향 4회). 8질문 중 원문을 보존한 완성 답변 3건, 부분답변 3건, 실행 실패 2건. 완성 답변 성공률을 6/8로 해석하면 안 된다.
- [ADR-0417 회귀 검증](../../../04_EXPERIMENTS/ADR/ADR-0417-term-agent-empty-menu-contract/RESULT.md): 5회 호출, 25,421토큰. 이전에 실패한 모의 2건 모두 실행 성공, 내용 대조 1/2. 후보 계약 20검사와 실행 경계 검사 통과. 공개 6질문은 다시 호출하지 않았으므로 이전 결과와 합쳐 전체 8/8이라고 주장하지 않는다.

구체적으로 ADR-0416의 `d01`은 기존 ‘영업일’ 정의를 조회했다. `r01`은 제45·46조 등을 검색한 다음 역방향 참조를 통해 제80조를 열고, 최종 답변에 제80조와 제46조를 함께 인용했다. 이 내용은 고정된 공개 원문의 실험 기록이며 현재 법령 적용에 관한 별도 의견이 아니다.

## 남은 문제

- 모의 소액 구매 `m01`: 금액 예외 M2를 읽기 전에 근거 부족을 사건 사실 부족으로 분류하고 질문하며 종료했다. 금액 예외가 없다는 잘못된 단정도 남았다.
- 첫 회차 ASK_USER를 확정하기 전에도 빠진 예외·인접 근거를 조사하는 종료 제어가 필요하다. 단순히 상태 필드를 만드는 것으로 해결되지 않는다.
- 공개 질문 3건은 질문 밖 세칙·추가 제재 등을 조사하다 부분답변 STOP으로 끝났다. 판단에 필요한 조사와 부가 조사를 구분할 필요가 있다.
- 정의 원문을 포함한 전체 조문 재전송으로 문맥량이 크다. 근거 범위를 잃지 않는 조회 단위/캐시 개선은 후속 실험 대상이다.

## 과거 연구 재현·소비자·검증 상태

연구 실행 진입점은 `02_BACKEND/lawrag/research/candidates/adr_0417/run_agent.py`다. 입력은 해당 ADR의 동결 `product/*.json`, 코드는 명시된 candidate revision, 출력은 `results.json`과 원시 `calls/`다. 이 연구 runner 자체의 소비자는 보고서·감사기다. 운영은 연구 runner를 import하지 않고 `semantic_runtime/term_agent.py`로 옮긴 구현과 실제 세대 인덱스를 사용한다.

```bash
PYTHONPATH=02_BACKEND .venv/bin/python -B 04_EXPERIMENTS/ADR/ADR-0417-term-agent-empty-menu-contract/artifacts/contracts.py
.venv/bin/python -B 06_TOOLS/run_tool.py adr_structure.py validate --path 04_EXPERIMENTS/ADR/ADR-0417-term-agent-empty-menu-contract --final
```

완료 실행의 `calls/` 재사용은 금지한다. 재호출이나 후속 수정은 새 ADR로 분기한다. 사후 재채점·결과 수정도 새 ADR로 남긴다.

ADR-0415와 ADR-0417의 개별 최종 검사는 통과했다. ADR-0416은 실패 출력 제외 집계와 raw 단계원장의 presented 지표 4개가 불일치하는 최종 문서 검사 오류를 보존했다. 전체 graph에는 기존 ADR-0305 run purpose 및 ADR-0158 부모 누락 오류가 남아 있다. 이 결과는 품질 승격 근거가 아니다. 이후의 운영 연결은 별도 사용자 지시를 기록한 품질 예외 전환이다.
