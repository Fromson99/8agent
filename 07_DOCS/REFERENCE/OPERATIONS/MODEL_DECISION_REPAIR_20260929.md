# 판단 응답의 형식·참조 오류 수정 재요청

후속 사용자 지시로 이 기능을 새 immutable 릴리스에 결속하고 로컬 MAIN generation31로
활성화했다. 아래 최초 작업 코드 검증과 당시 상태는 보존하며,
현행 반영 상태는 [MAIN 적용 기록](MODEL_DECISION_REPAIR_MAIN_20260929.md)을 따른다.

2026-09-29 사용자 지시로 MAIN 작업 코드의 구조 기반 판단 경로에 오류 수정 재요청을 연결했다.
정상 판단은 추가 호출 없이 진행한다. 잘못된 판단은 이전 출력 일부와 실제 검증 오류,
같은 입력 view 및 허용 참조를 모델에 돌려주고 완전한 응답 객체를 다시 요청한다.

## 실행과 검증 위치

`service.py` → Pipeline → `BoundedSourceSession.structured` → `ModelGateway.generate` 경로다.
같은 gateway를 사용하는 작성 단계의 기존 JSON·스키마 수정도 유지한다.
bounded 판단의 `max_schema_repairs=0` 강제를 제거하고 선택 프로필의 설정을 사용한다.
현재 작업 v5 기본값은 1회이며 0이면 추가 수정 호출이 없다. 기본 모델·토크나이저는 바꾸지 않는다.

JSON 파싱·필수 필드·자료형·허용값·추가 필드 오류 외에 다음 판단 검증을 gateway 안에서 수행한다.

- 요청 분기: 검색에는 검색어가 필요하며 직접 답변과 검색 대상이 함께 존재할 수 없다.
- 원문 선별·누락 복구: 허용 후보, 중복 선택, 선택 수 제한, 공백뿐인 선정 이유를 검증한다.
- 질문 요구: 질문 참조의 누락·미등록 번호, 요구와 배경의 중복, 중복 요구, 공백뿐인 요구 문구를 검증한다.
- 목록의 다음 행동: 추천 답변과 검색 계획의 조건을 함께 검증한다.
- 목차를 볼 문서 선택: 기존 JSON Schema의 허용 문서 대상·선택 수 검증을 사용한다.

질문 요구 검증은 읽기 전용이며 성공한 응답만 `QUESTION_PLAN`으로 저장한다.
실패한 원문 선택도 채택 근거로 저장하지 않는다. 입력 view와 범위는 재요청 전후 동일하다.
기존 실제 원문·해시·세대·참조·발행 검증을 유지한다.

## 오류와 예산

저장소·SQL·출처 결속·오래된 view·시간·호출 예산 오류는 모델의 형식 수정으로 처리하지 않는다.
bounded 판단의 서버·네트워크 오류에는 이 정책으로 재시도를 추가하지 않는다.
일반 gateway의 기존 통신 재시도 설정은 별도다.

수정 호출은 `model_attempt` 원장에 새 물리 호출로 기록하며 같은 logical call, view,
deadline과 호출 예산을 사용한다. 수정 횟수 또는 전체 예산을 소진하면 기존 한계 처리로 끝난다.
같은 응답의 JSON Schema와 교차 필드 검증을 모두 통과해야 다음 단계로 진행한다.
작성 입력 크기 초과·모델의 문맥 한도 초과는 이 기능의 수정 대상이 아니다.

`OUTPUT_SCHEMA_INVALID`에는 검증 오류, 단계, 수정 예정 여부와 횟수를 남긴다.
GENOS 진행 표시 소비자인 `ProgressCapture`에는 수정 재요청 중/수정 횟수 소진을 전달한다.
진행 표시에는 잘못된 응답·원문·프롬프트·상세 오류를 보내지 않는다.
이미 표시한 작성 스트림을 취소할 수 없으므로 기존 정책에 따라 수정 응답은 buffered 방식으로 검증한다.

## 확인과 반영 범위

검사는 [계약 테스트](../../../../05_TESTS/CONTRACTS/test_model_decision_repair.py)에서
모의 입력·모의 응답으로 실행한다. JSON·스키마·판단 오류 주입과 수정, 반복 한도,
시스템 장애의 비재시도, 실제 전체 Pipeline의 수정 후 답변 발행을 포함한다.
검증·엔진 결속·복구 자료는 [감사 디렉터리](../../../../09_ARTIFACTS/AUDITS/20260929-model-decision-repair)에 보존한다.
신규 오류 복구 계약 36개가 통과했다. 관련 기존 검사까지 포함한 실행은 248개 통과·2개 실패이며,
그 2개는 변경 전 frozen MAIN에서도 동일하게 재현된다. 질문의 괄호 배경 분리와 초기 쟁점
병합에 관한 기존 실패로, 오류 수정 기능의 통과로 숨기지 않는다.
[검증 영수증](../../../../09_ARTIFACTS/AUDITS/20260929-model-decision-repair/validation.json)을 따른다.

MAIN 작업 코드와 이에 결속한 엔진 manifest·PIPELINE 해시를 갱신한다.
데이터 generation, 로컬 선택 frozen 릴리스 generation30, 과거 ADR0557과 그 결과는 변경하지 않는다.
실제 Qwen 품질 재실험·GENOS 내부 모델·SSE 화면 검증과 현장 리비전 배포는 이번 로컬 계약 검사와 별도다.
현장에는 검증한 작업 코드와 엔진 pin이 함께 들어간 새 리비전이 필요하다.
이 변경 자체는 데이터 재구축·워크플로우 Python 교체·추가 환경변수를 요구하지 않는다.

복구 시 해당 감사 디렉터리의 `before/`와 보존된 generation30 frozen 코드의 해시를 확인하고,
변경한 코드·엔진 pin을 함께 복구한다. 이후 다른 작업이 변경한 파일은 덮어쓰지 않는다.
