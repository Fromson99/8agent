# 80/90 선별·복구 후보의 MAIN 배선

2026-09-23 후속 로컬 릴리스 `legal-agent-local-gemma-20260923-r1`은 이 회수·선별 코드를
유지하면서 공개 범위의 Gemma 호출을 결속했다. [로컬 모델 분기·실행 결과](LOCAL_GEMMA_SERVING.md).
아래 활성 상태와 모델 미결속 설명은 `source-recovery-r1` 당시 이력이다.

2026-09-23 사용자 지시: ADR-0517을 기준선으로 먼저 연결하고, DB 구조화·연결 오류는 후속 후보에서 수정한 뒤 성능을 확인하여 교체한다. 품질 인증 승격이 아닌 사용자 지정 전환이며 `quality_certified=false`다.

## 선택과 실행 경로

| 항목 | 연결한 내용 |
|---|---|
| 코드 릴리스 | `legal-agent-source-recovery-20260923-r1` |
| 원문·관계 DB | 기존 `relation-subtree-main-serving-20260920-v1/generation` 유지 |
| 원문 회수 | ADR-0513 rev-001: 전체/선택 법령 검색과 관계 후보를 합치고 페이지를 읽음 |
| 원문 선별·복구 | ADR-0517 rev-001: 제목·회수 경로로 최대 16개 선택 → 선택 원문의 발췌와 보류 목록으로 최대 8개 추가 |
| 서비스 입력 | `/v1/rag/ask` / `pipeline.py run --profile legal-rag` → `ServingLegalAgent` → `BoundedSourceSession` |
| 후속 처리 | 기존 v5 질문 요구 → 초안 → 원문 대조 검토 → 출처 묶음·outbox 게시 |

`source_recall.py`, `source_recall_global.py`, `source_query_planning.py`, `source_selection.py`는 완료된 후보와 바이트가 같다. runtime은 연구 실행기나 저장된 정답·실험 출력을 읽지 않는다. `bounded_source_session.py`가 기존 요청 원장·모델 호출 예산·출처 계약에 연결한다. 기본 v5 프로필의 `bounded_source_selection_enabled=true`로 선택하며, 이전 v5 경로는 false로 명시 선택할 수 있다.

회수 상한은 후보 288개·도구 1024회·원문 160만 자·180초, 선별은 최대 두 번·16+8개다. 모델 입력과 페이지 처리에는 기존 요청 전체의 시간·문맥 예산도 적용된다. 회수·선별된 원문과 모델에 실제 전달된 원문은 구별하여 기록한다. 모델 오류가 나면 보관된 후보 전체를 최종 채택하지 않는다.

선택한 논리 원문은 최대 24개지만 한 원문이 여러 페이지이면 출처 카드가 24개를 넘을 수 있다. 출처 묶음의 예전 20개 제한을 제거했고, 원문 페이지와 조립 순서를 보존한다. 원문 선택은 `UNASSESSED`이며 법률 적용 승인이나 실제 답변 인용과 다르다.

## 80/90의 의미와 남은 한계

- 과거 Gemma 실험의 반복 사용 61문항에서 필수 원문 90개 중 최초 77개, 복구 3개로 80개를 보존했다. 답변 정답률이 아니다.
- 당시 1건은 HTTP 429였고, 나머지 누락도 남아 있었다. 원래 엄격한 성공 기준에 따른 Rejected 기록을 바꾸지 않는다.
- 과거 실험은 미리 계산한 회수 풀·질의 계획을 사용했다. 서비스에서는 같은 질의 계획 코드를 요청마다 호출하고, 추가로 기존 v5 답변·검토를 실행한다. 따라서 이번 연결 검사가 운영에서 80/90을 재현했다는 의미는 아니다.
- 신규 모델 실험·호출은 하지 않았다. 합성 모델을 이용한 구조·원문 보존·실패 처리·답변 게시 계약과 실제 DB의 source-only 부팅을 검사했다.
- 기본 모델 프로필은 여전히 미결속이다. 실제 LLM 요청에는 별도 명시 모델 결속이 필요하며, 과거 공개 법령용 외부 모델 승인을 제품 질문·문서로 확대하지 않는다.
- 선별 복구는 확보한 후보 안에서의 추가 선택이다. 답변 검토가 새로운 조사를 요구하면 현재 경로에서 미완료로 표시한다. 뒤늦게 후보 전체를 채택하거나 최신 재귀 확장으로 대체하지 않는다.
- 전체 원문이 답변 문맥 예산을 넘으면 기존 bounded 처리로 한계를 표시한다. 답변 품질과 실제 모델 문맥 수용 여부는 추가 확인 대상이다.

## 후속 DB 교체

현재 DB의 잘못된 연결은 이번에 수정하지 않았다. [연결 오류 수리 계획](../REPORTS/REFERENCE_CONNECTION_REPAIR_PLAN_20260922/PLAN.md)에 따라 항·호·목 좌표, 범위·동항 문맥, 별표와 가지번호의 오연결을 새 세대에서 고친다. 기존 세대와 실행 결과는 보존한다.

후속 실험에서는 이 기준선과 동일한 질문·회수/선별 조건을 고정하고, 필수 원문 누락·불필요한 연결량·실패/시간·답변 근거를 함께 비교한다. 90/90 달성을 임의 필수 조건으로 만들지 않는다. 연결을 추가할 때는 검증된 DB 관계, 명시한 DB 누락 가설, 새 검색 시작점을 구별한다. 개선 확인 후 새 코드·DB 릴리스를 명시 전환한다.
