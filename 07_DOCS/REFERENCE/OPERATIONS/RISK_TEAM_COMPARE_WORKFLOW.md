## 1.8.0 원문 반환과 비교

대사 부모가 기존 RAG에 신뢰된 `return_mode="sources"`를 설정한다. 외부 사용자 body가 이 모드를 직접 켤 수 없다. 짧은 지정 내규의 전문 및 기존 명시 참조를 기존 acquire/Investigation 경로에서 읽고, 모델은 제공된 target_id·query·reason으로 조사 행동을 선택한다. 자료가 부족해도 원문·조회 기록·미확보를 `SOURCE_HANDOFF`로 반환하며 자식의 ASSESS/COMPOSE를 거치지 않는다. 일반 내규·외규 질문의 판단·답변 경로는 유지한다.

`source-investigation-v1`, workflow result v3, source bundle v2를 사용한다. 기존 `comparison-research-v1` 조사 과제와 이전 읽기 결과 호환 경로는 유지한다. 자식 사건의 `SOURCES_RETURNED`와 실행 원장의 `COMPLETED/END`를 함께 확정하며 후속 조사에서는 이전 종료 선택을 재사용하지 않는다. 원문 반환을 성공 답변·법률 결론·경험 승인으로 저장하지 않는다.

부모의 항목 검토·추가 조사·비교는 유지하고 최종 표는 쟁점 이름·내규·외규·의견·이유/미확보를 함께 표시한다. 보류도 비교행으로 계산한다. 실제 선택 인용·내외규 구분·권한·해시·재개·예산은 검사하고, 충분성·적용성·차이는 모델의 의견으로 제시한다. GENOS의 기존 참조 연결을 우선 쓰며 로컬 조회 실패를 현장 문서 부재로 간주하지 않는다.

## 1.7.0에서 이어받은 실행과 판단의 분리

현행 `task_board.execute`는 질문 범위 → 내규·외규 조사 → 항목 검토 → 필요한 추가 조사 → 선택 근거 연결 → 비교 → 결과 저장 순서다. `VERIFY_BASIS`라는 저장 단계 이름은 호환성을 위해 유지하지만 여기서는 `basis.from_items`가 이미 선택된 원문을 연결할 뿐, 별도 모델 승인 호출을 하지 않는다. 비교의 의미·적용·예외 판단은 `COMPARE`가 맡는다.

조사 관리용 `gap_ids`와 `gap_resolutions`는 선택 사항이다. 생략한 부족 항목은 `UNRESOLVED`로 보존한다. `FINISH`에서 실제 전달받은 원문을 선택하면 별도의 `ADOPT` 기록 없이도 후속 검토로 넘길 수 있다. 출처 없는 ID, 원문 변조, 권한 위반, stale 상태, 실제 부재 조회가 없는 부재 증명은 계속 거절한다.

알려진 조사 미완료·예산·시간 오류가 나더라도 실제 읽은 검증 가능한 원문은 `READ_ORIGINALS`로 별도 전달한다. 자식 상태는 실패로 남고 주장 목록은 만들지 않는다. 기존 성공 결과와 최신 실패는 따로 저장한다. 추가 조사는 한 과제 수행 후 새 근거를 검토하고, 새 근거가 없는 같은 조사로 비교 예산을 소진하지 않는다.

## 1.4.2 항목별 조사와 실패 복구

비교 설정은 `02_BACKEND/workflow/risk_team_compare_workflow/comparison_fields.json`이다. 일반·절차·전결·비율 유형의 항목을 선택하고 쟁점별로 관리한다. 정답 조문과 수치를 질문별 설정에 넣지 않는다. 반대쪽 원문의 위치·정의·의무는 검색 단서이며, 자기 쪽 규정의 증거를 대신하지 않는다.

정확한 위치·정의·명시 참조를 받은 추가 과제는 기존 RAG의 원문 도구부터 실행한다. 같은 자료의 반복 실패, 실패 시도와 기존 성공, 원문 완전성과 항목 범위 충분성을 구분한다. 프로세스가 중단되면 부모와 사건 잠금을 가진 같은 요청만 기존 단계·원문·deadline·누적 예산으로 복구한다.

`comparison_items`에는 항목별 확인과 남은 부족을, `research_attempts`·`latest_rag_attempts`에는 수행 과제와 최근 실패를 반환한다. `item_validation_failures`는 원래 실패 제안을 보존한다. 첫 항목 검토가 실패하면 `unreviewed_sources`와 답변 본문에 기존 자식이 채택한 정확 원문을 ‘항목별 검토 미완료’로 표시한다. 탐색 중 본 모든 원문을 붙이지 않으며 법적 부합 판단은 보류한다. 저장 조회와 중복 요청도 같은 결과를 반환한다.

아래 MAIN75 이하 기록은 이전 구현·검증 이력이다. 실제 선택 정본은 `01_DATA/ACTIVE/local/ACTIVE_RELEASE.json`이다.

이전 로컬 MAIN75는 부모의1~12쟁점/사실을 자식에 재해석 없이 연결하고 인용·ID·정의 읽기·자식 조립·보류·중간 행 저장·표시를 시스템이 처리한다. 모델은 의미 선택·해석·차이·적용 판단을 맡는다. 최종 인용만 표시하며 비교행이 없을 때 전체 자식 근거를 대신 표시하지 않는다. [검증과 한계](../../../04_EXPERIMENTS/ADR/ADR-0809-system-mechanics-qualification/MAIN_RESULT.txt). GENOS 미반영.

이전 로컬 MAIN74의 workflow1.1.0은 답변이 채택한 정확 원문 span만 전달한다. 조사 기록 전체는 자식 원장에 남고 비교/표시는 현재 근거와 필요한 문맥만 사용한다. 최종 표의 인용만 표시하며 불완전한 조건·판본은 보류한다. [기능 검증과 실제 질의 실패](../../../04_EXPERIMENTS/ADR/ADR-0801-workflow-handoff-qualification/MAIN_RESULT.txt). GENOS는 미반영이다.

초기 도구 재사용 구현은 ADR-0785, 기존 RAG 전체 호출과 제한 답변 반환 복구는 ADR-0790이다. 후속 ADR-0791에서 재시작 결속을 수정했고 로컬 MAIN70 `risk-rag-orchestration-20261015-r3`에 반영했다. 실제 선택 정본은 `01_DATA/ACTIVE/local/ACTIVE_RELEASE.json`이다. 코드 통합, 로컬 MAIN 선택, GENOS 배포는 별도 상태다.

## 실행 경로

`service.py` → `semantic_runtime.app` → `workflow.api` → 공통 `Runtime` → `risk_team_compare_workflow.flow`로 실행한다. `대사:`는 기존 RAG 질문 API에서 내규·외규 접두어 처리와 메모리 진입 전에 분기한다. `내규:`와 `외규:`는 기존 RAG 경로를 사용한다.

ADR-0790의 업무 단계는 질문 범위 → `내규: 질문`과 `외규: 질문`을 기존 `Pipeline.run`에 각각 전달 → 두 답변·읽은 원문·조사 기록 수신 → 근거 관계 → 부족 부분의 같은 RAG 사건에 추가 질문 → 항목별 비교 → 리포트다. `semantic_runtime.workflow_rag`가 전체 RAG 호출을 담당한다. 별도 대사 조사 에이전트를 실행하지 않는다. 공통 실행부는 등록·권한·버전·잠금·체크포인트·총 예산을 담당하고, `SourceSession`은 반환된 원문 span 검증에 사용한다. 자식 RAG에서 대사 workflow를 다시 호출하는 재귀는 차단한다.

`PIPELINE.json.workflows.registered`에 해시가 고정된 manifest만 로드한다. 다른 워크플로우는 `02_BACKEND/workflow/<package>/`의 flow와 reporter, 버전·팀·파일 해시 manifest를 추가하고 PIPELINE 및 엔진 파일 pin을 갱신한다. 사용자 입력으로 모듈 경로를 지정할 수 없다.

## API

```json
{
  "workflow_id": "risk_team_compare_workflow",
  "workflow_version": "1.8.0",
  "question": "대사: 비교할 업무와 항목",
  "session_id": "stable-session",
  "request_id": "unique-request",
  "as_of": "2026-10-15",
  "use_llm": false
}
```

- `POST /v1/workflows/run`: 직접 실행. `POST /v1/rag/ask`의 `대사:`도 같은 실행부를 호출한다.
- `GET /v1/workflows/runs/{run_id}?session_id=...`: 상태와 저장 결과 조회. 반환 전에 결속과 원문을 재확인한다.
- `POST /v1/workflows/resume`: `run_id`, `session_id`, `expected_revision`으로 중단된 실행을 재개한다. 질문·문서·예산 변경은 허용하지 않는다.
- 서비스 JSON 진입점은 `WORKFLOW_RUN`, `WORKFLOW_STATUS`, `WORKFLOW_RESUME`를 지원한다. 기존 `LEGAL_AGENT`/`RAG_ASK`에도 `대사:`를 전달할 수 있다.
- 같은 사용자·팀·세션·request ID의 중복 실행은 같은 결과를 반환한다. 다른 입력으로 ID를 재사용하면 충돌이다. 상태 조회로 받은 revision으로 재개해야 한다.
- 선택적으로 `return_to: {"parent_run":"...", "step":"...", "call_id":"..."}`를 넣으면 호출자에게 같은 복귀 표식을 반환한다. 호출자는 반환 결과를 받은 뒤 이어서 실행한다. 모델이 임의의 중첩 workflow를 재귀 실행하는 도구는 열지 않는다.

2026-10-19 작업 코드와 `GENOS_SESSION_IDENTITY_20261019_R1` 반입본은 `team_id + session_id`로 실행·저장·조회·재개를 결속한다. `WORKFLOW_USER_ID`와 요청의 `user_id`는 필요하지 않으며 로그인 사용자 정보가 바뀌어도 같은 팀·세션·요청은 중복 실행되지 않는다. 서버 `TEAM_ID` 또는 신뢰된 resolver의 팀이 있으면 요청 팀과 일치해야 한다. resolver와 `request.state.workflow_principal`의 문서 범위는 그대로 제한하며 이 식별자는 플랫폼 인증을 대신하지 않는다. 세션을 생략하거나 익명 기본값으로 합치지 않는다. 상태 조회에도 서버 팀이 없으면 `team_id`를 전달한다.

기존 사용자 기준의 저장 기록은 자동 이행하거나 덮어쓰지 않는다. 새 코드는 새 채팅에서 시작한다. 이전 실행의 정확한 run ID·팀·세션 조회/재개도 코드·데이터·상태 결속을 통과해야 하며 버전이 바뀌면 원래 리비전이 필요하다. 이 수정은 일반 RAG의 세션 기반 멀티턴과 대사 실행의 저장·재개 식별자를 정리한 것이며, 별도 대사 실행 사이의 자연어 후속 대화 기능을 새로 추가한 것은 아니다. 선택된 로컬 MAIN87과 GENOS 현장 적용 상태는 별도로 확인한다. [반입 안내](../../../08_DEPLOYMENT/GENOS/handoffs/session_identity_20261019_r1/GUIDE_UTF8.txt).

## 모델과 데이터

`use_llm:true`는 내부 모델 또는 명시적으로 승인한 외부 모델 결속을 사용한다. 이번 Qwen3.8/Parasail FP8 호출은 사용자의 전송 허용을 팀·문서 ID·데이터 세대와 해시에 결속한 `workflow_authorization`으로 검사한다. 내부 자료의 공개 구분과 `export_allowed=false`는 유지한다. 일반 공개 RAG의 기존 허용 범위는 별개다. `use_llm:false`는 원문 조회와 미확인 리포트이며 법률 판정을 수행하지 않는다.

사용자가 정정한 사진 3장의 전사 문서는 **위험관리위원회운영준칙**, 2016-08-23 개정판이다. 본문 10조와 부칙 2개이며 현재 유효성은 미확인이다. 이전에 잘못 제공한 내규와 혼합하지 않는다. 이 문서에 유동성비율 수치 기준이나 위험관리기준시행세칙 제6-4조가 있다고 간주하지 않는다.

`risk-workflow-definitions-20261015-r1/generation`은 기존 1,546문서에 이 문서 1개를 추가한 세대에 명명 정의 635건과 정의–명시 참조 연결 635건을 보강한 것이다. 기존 문서 전체 재파싱·재색인은 하지 않았다. 원문과 이전 세대는 보존했다. 기존 RAG의 정의 조회·참조 원문 읽기 도구가 이를 소비한다. 링크 존재는 모델이 매 질문마다 반드시 추적한다는 뜻이 아니다.

선택 판본과 기준일 정보를 모델에 제공한다. 판본 유효성은 임의 승인하지 않으며, 정보 부족은 모델의 이유·미확인 사항에 남긴다. 판본 메타데이터가 없다는 이유만으로 비교 호출을 막지 않는다.

## 근거와 비교 계약

직접 인용, 상위 내규를 거친 경로, 내용 대응, 미확인, 무관은 LLM이 판단한다. 시스템은 선택한 원문 ID·인용·내외규 구분을 검사한다. 명시 근거 관계·적용성·판본·원문 완전성은 판단 맥락이며 기계적인 비교 허용 조건이 아니다. 내용상 대응해도 비교할 수 있고, 제정 근거 확정과 내용 비교는 구분해서 설명한다. 이미 판단한 상충이 부합으로 바뀔 때까지 재검색하지 않는다.

수치 항목은 이번 판단에 필요한 정의·분자·분모·단위·기간·예외 등을 LLM이 선택해 검토한다. 전체 차원을 반드시 채우도록 요구하지 않는다. 기준 수치나 산식이 미확보이면 그 내용을 남기며 규정 자체가 없다고 단정하지 않는다. 항목 상태와 설명은 LLM 의견이고, 인용이 없는 내용에는 근거 미선택 표시를 붙인다. 미확보 원문과 사용자 사실 부족은 구분한다.

상위 조문 확장, 정의·참조 추적, 내규 또는 외규만 재검색, 질문 범위 재검토를 부족 사유에 맞게 선택한다. 영향을 받지 않는 근거와 판단은 보존한다. 같은 행동 반복은 중단하고 추가 조사 순환은 최대 2회다. 잘못된 형식·인용·조사 위치의 수정은 같은 단계·근거에서 최대 1회이며 물리 호출은 기존 gateway의 총 예산에 포함한다. 의미 상태값 조합과 누락 설명만으로 수정 호출하지 않는다.

## 실패·재개·표시

상태는 `completed`, `partial`, `blocked`, `failed`로 구분한다. 프로세스 중단은 마지막 체크포인트에서 재개할 수 있지만, 예산 소진이나 불명확한 모델 호출 결과는 자동 재전송하지 않는다. 완료 응답과 원문 observation receipt가 저장되었다면 재사용한다. deadline, 물리 모델 시도, 도구 사용량은 재개 때 초기화하지 않는다.

부모 저장 경로는 선택된 runtime의 `workflows/<run_id>/journal.sqlite`이고, 양쪽 기존 RAG 기록은 `children/internal`, `children/external`에 보존한다. 부모에는 workflow checkpoint, 물리 모델·도구 예약, 자식 실행·결속·관찰 해시와 복귀 receipt를 기록한다. `rag_results.internal/external`로 두 답변, 원문 ID, 조사 기록 요약, 같은 사건의 후속 조사 정보를 반환한다. 파일 잠금과 revision을 통해 동시 실행을 차단한다. 프로세스 재시작의 진단값 process_id/process_instance_id는 실행 결속에서 제외하고, 나머지 코드·데이터·프로필·정책 필드는 그대로 검사한다. 권한·코드·세대·원문·저장 결과 해시가 다르면 저장 답변도 내보내지 않는다. 예상하지 못한 실행 오류는 실패로 남기며 완성 답변으로 표시하지 않는다.

조사 시간이 끝나면 최초 시점부터 최대 30초인 별도 원문 검증 시간을 journal에 저장한다. 이 시간에는 확보한 원문만 재검증하며 새 조사·모델 호출은 하지 않는다. 중단 후에도 시간을 새로 부여하지 않는다. 검증 실패·변조는 답변 없이 실패로 끝낸다.

답변은 질문에 대한 결과 → 근거 관계 → 대사표 → 추가 확인 → 읽은 원문 순서다. `workflow-source-v1` 출처와 `workflow-result-v1` 응답을 로컬 UI와 GENOS 표시 코드에 연결했다. GENOS 워크플로우 편집기 반영과 현장 검증은 별도 작업이다.

## 검증 범위와 재현

2026-10-15 MAIN72 실제 유동성 질문은 **양측 RAG 반환 뒤 대사 비교에 도달하지 못했다**. 내규 근거24건·외규70건과 답변·조사 기록을 합친 입력129,927자가 `max_context_chars=100000`을 초과하여 `VERIFY_BASIS`에서 중단됐다. BASIS/COMPARE 모델 호출0건, 비교 행0개이며 원문을 보존한 `partial` 응답만 저장됐다. 호출 수는16/40회로 호출 횟수 소진이 아니다. 상태 조회·중복 요청 재사용은 통과했으나 대사 완료 검사가 아니다. [ADR-0795 실제 기록](../../../../04_EXPERIMENTS/ADR/ADR-0795-main72-workflow-comparison/MAIN_RESULT.txt).

같은 관찰에서 내규/외규 자식이 양쪽을 묻는 원질문을 그대로 받아, 내규 전용 scope에서 외규 부족을 자기 미완료 사유로 기록했다. 비교용 `workflow_version`은 허용443문서 모두에 없어 현재 적용성 확정 계약과 데이터가 연결되지 않았다. 큰 비교 입력의 분할 검토, 자식별 조사 목표 분리, 적용 버전 연결은 미해결이다. MAIN72의 이전 서비스8건은 모델을 사용하지 않은 검사였으며, 실제 Qwen 유동성 외규 단독 답변 성공을 대사 종단 성공으로 해석하지 않는다. 이 확인에서는 제품 코드·포인터를 변경하지 않았다.

ADR-0790은 `06_TOOLS/EXPERIMENTS/adr_0790/test_orchestration.py`, `test_publication_deadline.py`와 관련 회귀 검사로 실제 API, 양측 기존 RAG 호출, 같은 사건의 후속 조사, 중복·재개·총 예산·권한·해시·부분 응답을 확인한다. 선택 후보·기준·검사 목록은 `artifacts/design/freeze.json`과 `regression-selection.json`으로 동결한다.

Qwen 실제 질문은 별도 관찰이다. 이전 ADR-0789 유동성 질문은 정답 제3-24조의4 제2항을 찾지 못했고 제공자의 큰 JSON schema 거절도 발생했다. 위원회 질문에서는 확보 원문을 잘못 해석한 사례가 있다. 기술 계약 통과를 법률 답변 정확도 통과로 해석하지 않는다.

부모 검증 결과는 ADR-0790 `artifacts/run-001/result.json`, 최종 재시작 검증·선택·한계·원복은 ADR-0791의 `MAIN_RESULT.txt`, `artifacts/main-binding-chain.json`, `main-service-smoke-first.json`과 `main-service-smoke-second.json`에 남겼다. 완료된 결과를 덮어써 재실행하지 않고 새 품질 비교는 별도 ADR을 선점한다. GENOS 현장 적용과 내부 모델 검증은 별도다.
