6. 11월4일에 할 만한 일 — 제안이며 아직 실행하지 않음

우선1. SQLite 하위 노드 조회를 기존 children 색인에 연결
이유: ADR1310에서 가장 큰 관측 병목이었다. 첫 단계는 Nodes.children과 document_tree.children의 순서·root·중복·순환·seen metadata 계약을 대조하는 것이다. 완료 기준은 기존 선택·보호 입력·원문·최종 결과 동일, 전체 노드 반복 순회 제거와 같은 저장 응답에서 실제 지연 감소 확인이다. 신규 비교는 별도 ADR 절차를 따른다. [E04]

우선2. 같은 요청의 구조 검증·개별 원문 조회 재사용
이유: resolve16/verify14회와 source JSON1345회·블록2281회 조회가 남는다. 먼저 요청 판본·권한·메타데이터·선택 해시가 같은 성공 검증의 재사용 지점을 확인한다. 완료 기준은 권한/판본 변화·부분 조회 거절 보존, 호출·메모리 상한과 재조회 감소의 계측이다. Oracle root/SourceScope는 SQLite와 별도 확인한다. [E04]

우선3. FINISH 이후 감독의 추가 조사 조건 점검
이유: no-progress 복구를 줄여도 종료 감독의 REDIRECT는 별도 경로로 남아 있다. 먼저 ADR1310의5~8번째 응답을 원래 요구·미확보·충돌·예상 답변 변화와 대조한다. 완료 기준은 필요한 추가 근거는 보존하면서 근거 없는 범위 확장과 추가 호출을 줄이고, 종료·부분답변·예산 계약을 유지하는 것이다. [E04]

우선4. Dataiku R6/R7·벡터 R1의 현장 실행 조건과 용량 확보 확인
이유: 로컬 SQL/합성 검사가 현장 전량 적재나 공간 확보를 입증하지 않는다. 먼저 기존 job state와 pending, 실제 패키지·원문/검색 판본, 읽기 전용 용량 결과를 확보한다. 완료 기준은 허용된 현장 경로에서 재개·중복·결과불명 처리를 확인하고, 전체 시간·적재 상태·서비스 활성화 상태를 각각 기록하는 것이다. 현재 미확정 값을 임의 생성하거나 자동 배포하지 않는다. [E18~E23]

우선5. 알려진 가정6실패와 실제 답변 미완료를 분리해 정리
이유: 테스트 상태 표시 불일치, 실제 공급자 UNKNOWN/429, 의미 답변 실패는 서로 다른 문제다. 먼저 보존 실패6개와 실제 wire/표시 계약을 대조하고 ADR1302 예약의 미완료 사유를 확인한다. 완료 기준은 실패 원인을 각각 연결하고, 필요한 fixture 수정과 제품 수정·실모델 후속을 별도 범위로 정하는 것이다. 기존 실패를 삭제하거나 예약만으로 완료 처리하지 않는다. [E07~E14]
