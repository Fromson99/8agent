# KRX·KOFIA 전체 원문 구조화 방안

작성일: 2026-09-17. 상태: 설계 제안·읽기 전용 현황 확인. 변환·모델 실험·재구축·MAIN 활성화는 미실행.
검토 환경: WSL `/home/jin/8-AGENT`의 현재 작업 코드. 기존 미커밋 변경을 포함하며 배포 코드와 동일하다고 가정하지 않는다.

## 판단

HWP를 원본 지면을 보존한 PDF로 변환하고 기존 PDF 구조화·VLM 검수 경로에 연결하는 것은 구현 가능한 후보다. 그러나 현재 HWP 경로의 합성 PDF와는 다르며, 변환 성공·VLM 승인만으로 원문과 구조의 완전성을 증명할 수 없다.

권고안은 HTML의 명시 구조를 본문 근거로 유지하고, 동일 버전의 공식 PDF 또는 HWP 렌더 PDF로 본문을 대조하며, HTML에 없는 별표·서식·매뉴얼을 PDF 경로로 보완하는 것이다. 모든 표현본은 보존하되 동일 본문을 RAG에 중복 적재하지 않는다.

범위는 미확정이다. 우선 설계 기준은 ‘두 기관의 현행 규정 전체와 모든 부칙·별표·서식·첨부’로 둔다. 과거 전체 개정 이력을 포함하면 수집 목록·버전 연결·평가 분모를 별도로 확대한다. 아래 보유량은 기관 전체 목록과 대조한 수집률이 아니다.

## 제안 실행 순서와 실패 처리

1. **전체 목록 고정:** 공식 목록과 문서·개정·첨부별 수집 영수증을 대조한다. 신규/폐지/개정 문서를 별도로 표시한다. timeout·누락·지원하지 않는 첨부를 완료 분모에서 빼지 않는다.
2. **원본 및 버전 보존:** HTML·HWP·공식 PDF 원본을 각각 보존한다. 이름만 같다고 동일 문서/버전으로 병합하지 않는다. 부칙·개정문·신구조문대비표·서식 역할을 구분한다.
3. **PDF 확보:** 동일 버전의 공식 PDF가 있으면 사용한다. 없으면 한글 PDF 저장 또는 검증된 변환기로 HWP를 렌더한다. 프로그램 버전·글꼴·옵션·원본/결과 해시·실제 좌표 출처를 영수증에 기록한다. 변환 후 빈 페이지·글자 깨짐·표/도형 잘림을 원본과 확인한다. 오류 파일은 격리하고 재개한다.
4. **파싱과 구조 복원:** PDF 텍스트·표·좌표를 추출해 기존 구조화 경로에 넣는다. OCR 누락과 잘못된 구조를 구분한다. VLM은 계층·소속·누락 후보를 확인하며, 보이지 않는 문구·표 셀을 생성하지 않는다. 표 셀·병합·각주·페이지 연결이 파서→source.sqlite→검색 결과까지 보존되는지 별도로 확인한다.
5. **교차 대조:** HTML 본문과 동일 버전 PDF의 조/항/호/목·텍스트·숫자·참조를 대조한다. 줄바꿈 등 비교 정규화는 파생 비교본에만 적용한다. 차이가 나면 버전 불일치, 변환 손실, 파싱 손실, 구조 오류로 분류하고 원본으로 판정한다. 자동으로 한쪽 내용을 덮어쓰지 않는다.
6. **완료 판정:** 본문/부칙/별표/서식/첨부 단위로 누락·미검수·소속 불명·미연결 참조를 보고한다. VLM이 승인했더라도 코드 검증과 원문 대조가 남아 있으면 보류한다. 애매한 표·페이지 경계는 사람이 원문과 대조한다.
7. **새 세대와 검색 확인:** 승인된 구조만 완료 대상으로 집계하고, 관련 원문·색인·통합 후보를 새로 생성한다. 조문이 별표를 인용하는 경우 해당 버전의 별표 본문까지 실제로 회수되는지 검증한다. 기존 세대와 활성 포인터를 보존하며 명시적 활성화 및 롤백 절차를 따른다.

원본 해시·변환기/파서/모델 설정이 바뀌면 새 지문으로 재실행한다. 변경 없는 단계의 검증된 결과만 재사용한다. 통신 실패는 해당 파일/검수 창 상태로 남기고, 재개로 호출 한도를 초기화하거나 미검수 범위를 승인 처리하지 않는다.

## 현재 VLM의 한계

작업 코드 v36의 basic 모드는 전체 페이지 검수 경로를 선택하지만, 경고 허용 및 호출 예산 때문에 모든 페이지의 승인을 보장하지 않는다. 기본 `STRUCTURE_RECIPE_ACCEPT_WARNINGS=on`은 보류·응답 오류·예산 소진을 `accepted_with_warnings`로 저장할 수 있다. 이는 원문 보존·처리 지속 목적이며 완전한 구조 승인과 다르다.

이번 목표용 실행에서는 `STRUCTURE_RECIPE_ACCEPT_WARNINGS=off`, 전체 검수 범위, 장문 분할·재개를 검토하되 전역 기본 설정을 바꾸지 않는다. 엄격 모드도 모델 오승인을 제거하지 못한다. 과거 ADR-0436의 모의 PDF 실험에서는 잘못된 부모 관계를 VLM이 처음부터 승인한 사례가 있었다. 과거 후보의 결과를 현재 KRX/KOFIA 문서 정확도로 환산하지 않는다.

현재 `prepare_converted`의 합성 PDF는 추출 결과를 재배치하므로 HWP 원본 지면 누락을 독립 검증하는 근거로 쓸 수 없다. 과거 HWP→HTML→WeasyPrint 변환도 `original_pagination_verified=false`인 연구 파생본이었다.

## 품질 목표·비용·도입

- G1(제안 목표): 선택 범위의 공식 목록 대조율, 본문/첨부 수집 상태 기록률, 페이지 처리/검수 범위 기록률 각각 100%. 분모는 고정 목록·파일·페이지로 분리한다.
- G2(제안 목표): 미해결 본문 누락·숫자 변형·부모 오류·필수 첨부 누락을 남긴 문서는 ‘완료’로 표시하지 않는다. 예외를 숨기지 않고 대기 상태로 노출한다. 전수 점검 통과도 절대 무오류의 수학적 보장은 아니다.
- U1(미확인): 최종 기관 전체 문서 수·PDF 페이지 수·변환 충실도·구조 정확도·필요한 사람 검토량. 현재 파일 수로 페이지 수나 비용을 추정하지 않는다.
- U2(미산정): 총 비용 = 변환 실행 비용 + 실제 입력/출력 토큰 비용 + 이미지 처리 과금(해당 공급자 기준, 중복 계상 금지) + 재시도 비용 + 사람 검토 시간×시간당 비용 + 색인/저장 비용. 지연은 변환·파싱·검수·재작업 단계별 실측이 필요하다.
- 조건부 기대: HTML을 이용한 초기 구조·대조로 PDF 구조 오류를 발견할 수 있으나, 모든 본문을 PDF로 재처리하면 추가 비용이 발생한다. 교차 대조 비용이 절감되는 모델·사람 수정 비용보다 작아야 비용상 이익이다. 버전 불일치가 많으면 재작업이 늘어난다.
- 선행 검증 후보: 일반 규정, 복잡한 표/병합 셀, 페이지를 넘는 표, 서식, 본문 없는 HTML의 HWP 매뉴얼, 개정문/대비표, 번호 체계가 다른 문서. 문서·버전을 독립 평가 단위로 고정하고 한 문서의 여러 페이지를 독립 문서 표본처럼 세지 않는다.
- 모델 품질 비교를 실제 시작할 때는 실험 표준 두 문서를 끝까지 읽고 동일 scope reservation 확인→ADR 선점→부모·입력·기준·arm 동결 후 실행한다. 신규 외부 모델은 Gemini `gemini-3.1-flash-lite`이며 반출 허용 범위 확인이 선행된다. 이 문서 작성에서는 호출하지 않았다.
- 실무 순서: 목록/미수집 현황 확정 → 변환 충실도 확인 → 사전 고정한 문서군의 구조/표/연결 검증 → 오류 보완 → 전체 분할 실행과 사람 검토 → 새 서빙 후보 검증. 일정은 페이지·변환 환경·검토량 측정 전 미산정이다.
- 역할: 수집 담당은 공식 목록·버전·첨부, 변환 담당은 지면 보존, 파이프라인 담당은 구조·계보·재개, 검토 담당은 원문 대조와 보류 해소를 책임진다.

GENOS에서는 내부 모델·선택 전처리기로 같은 계약을 검증해야 한다. 현재 세션은 현장 접근 불가이며 연결을 시도하지 않았다. 로컬 작업 코드 검토를 현장 배포/품질 성공으로 보고하지 않는다. 자체 검토 문서이며 독립 감독 검토는 수행하지 않았다.
