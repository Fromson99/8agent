## 판정

**조건부 구현 가능. 품질·비용 개선은 미검증.** 기존 Pipeline 포트·SourceStore·검색 부품·요청 저널을 재사용할 경로가 확인된다. 다만 v1 Domain/Profile은 닫힌 계약이므로, 새 필드만 추가하거나 현재 조사 스키마를 그대로 두고 “서버 장부”라고 이름만 바꾸면 작동하지 않는다. 후보 격리 후 명시적 v2 계약과 소비자 검사 필요.

최초 범위를 검색 역량 복원과 서버 관측으로 제한한 것이 타당하다. 전체 v2를 한 번에 넣는 것은 ADR-0474의 원인 분리 실패를 반복할 위험이 있다.

## 남은 결정과 다음 증거

1. 구현 시작 시 기존 reservation 확인과 ADR 선점, 부모 및 candidate snapshot 결속.
2. S0에서 기존 검색 기능·source ID/판본 호환과 모델 없는 계약 검사. 실패하면 품질 실험으로 넘어가지 않음.
3. 동일 baseline 입력을 바꾸지 않는 서버 기록부터 검증. 발췌, 참조 후보 확장, 검토 제어의 효과를 분리.
4. 품질 실행 전 평가 방식(Gemini 또는 수동), 최소 개선·회귀 허용·비용/지연·반복 횟수 고정.
5. CM 51 비교와 별도 holdout 이후에만 MAIN 승격 검토. 이 문서는 승인·완료 증명이 아님.

외부 문헌의 성능을 전이하지 않았으며 인터넷 법률 해석을 수행하지 않았다. 보고서 내 법률 사례는 기존 실패 흐름을 설명하기 위한 것으로 법률 정답을 새로 인증하지 않는다.
