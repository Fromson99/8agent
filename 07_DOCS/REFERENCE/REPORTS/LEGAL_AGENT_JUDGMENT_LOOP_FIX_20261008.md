## 1. 문제였던 것

### 1-1. 판단 단계가 "원문이 없다"고 해도 탐색 단계는 아무것도 하지 않고 끝냈다 (같은 루프)

**질문:** 벤처기업의 주식매수선택권은 언제부터 행사할 수 있나요? (ADR-0684 run-001)

| 회차 | 판단(ASSESS)이 낸 부족 | 탐색 단계의 다음 행동 |
|---|---|---|
| 1 | 제16조의5제1항 본문에서 '대통령령으로 정하는 경우'의 구체적 내용이 제공된 원문에 포함되어 있지 않아, 예외적 행사 가능 시점을 완전히 특정할 수 없다. | **FINISH** — "대통령령 위임 사항의 구체적 내용은 별도 시행령 확인이 필요하나, 질문의 핵심 쟁점인 행사 가능 시점과 법적·계약적 결정 요건은 현재 확보된 원문…" |
| 2 | 제16조의5제1항에서 '대통령령으로 정하는 경우'와 '대통령령으로 정한 요건'의 구체적 내용이 시행령에 위임되어 있으나, 해당 시행령 조항 원문이 제공되지 않았습니다. | **FINISH** — 같은 취지 |
| 3 | (2회차와 동일) | 재조사 한도 도달 → 부분 답변 |

- 모델 14회 호출에 201초가 걸렸다. 조사는 한 번도 하지 않았다.
- 검색 결과 7위에 `벤처기업육성에 관한 특별법 시행령`이 있었다. 하지만 재조사 화면에는 그 법령을 여는 행동이 없었다. 제시된 행동은 같은 법 조문 범위 읽기 4개, 일반 "연결 조사", 새 검색, 과거 시점 복귀뿐이었다.

**질문:** 부동산 PF 사업성 평가가 악화되는 경우 금융투자회사는 자산건전성 분류와 대손충당금 적립을 어떻게 연계해야 하는가? (ADR-0686 run-002)

- 판단은 세 번 연속 "제6-15조 ②의 '별표 17-1' 본문이 없다"고 했다.
- 탐색은 세 번 모두 똑같은 문장으로 끝냈다: "제6-15조 ①~③으로 … 확인했다. 세부 등급별 적립률(별표 17-1)과 경공매 기준(별표 17-2)은 본문에 없어 확인된 조문 범위에서 종료한다."

ADR-0680 #36(상법 제447조, 재무제표 구성)도 같은 패턴이었다. 탐색이 "상법 시행령 제16조에 위임되어 있으나 … 상법 조문으로 충분하다"를 두 번 그대로 반복했다.

**집계:** 60건 중 판단→탐색 재진입은 8번이었고, 그중 **6번은 탐색의 첫 행동이 아무 조사 없는 FINISH**였다.

**원인:**
- 부족 내용이 문장으로만 넘어갔고, 그것을 해결할 행동과 연결되지 않았다.
- 탐색이 종료할 때 부족을 처리했는지 검사하지 않았다.
- 다음 판단은 "이 부족은 이미 냈고 탐색이 못 찾았다"는 사실을 몰랐다.

### 1-2. 같은 검색식을 세 번 내다가 요청 전체가 실패했다 (같은 루프 → 422)

ADR-0680 #39(사내규정 제정의 결의 주체)에서 탐색 모델은 같은 검색을 세 번 그대로 냈다: 8번째 턴, 9번째 턴, 9번째 턴 재시도.

```
['상법 제362조 이사회 결의사항', '상법 제363조 이사회 결의사항 정관 변경']
```

- 매번 "같은 검색식" 오류로 거절됐다. 거절된 결정은 다음 화면에 보이지 않아서, 모델은 자기가 방금 거절당한 걸 몰랐다.
- 상법 제361조 원문은 이미 읽은 상태였다. 그런데 "읽기 ≠ 채택" 규칙 때문에 채택이 0건이 되었고, 결과는 `질문에 필요한 원문 조사가 완료되지 않았습니다`(HTTP 422)였다.
- ADR-0684에 기록된 GENOS 화면의 순서(결정 거절 → 재시도 → 422)도 같은 경로다.

중복 판정 자체에도 오류가 있었다. 검색어를 형태소로 쪼개면 조문번호가 숫자 한 자리씩 흩어진다.

```
상법 제362조 이사회 결의사항 → ['2', '3', '6', '결의', '사항', '사회', '상법', '이', '조']
상법 제236조 이사회 결의사항 → ['2', '3', '6', '결의', '사항', '사회', '상법', '이', '조']
```

그래서 서로 다른 조문을 찾는 검색이 "같은 검색"으로 거절될 수 있었다. 모델이 보던 검색 이력도 이 숫자 조각 형태라 무엇이 중복인지 알 수 없었다.

### 1-3. 판단이 "사소한 부족"이라고 두 번 말하면 요청 전체가 실패했다 (422)

- v6 이후 실패 5건 중 4건이 같은 원인이었다.
- 판단 계약은 미해결 참조를 빼고 모든 부족을 "중요(material=true)"로 표시하라고 강제했다.
- 모델은 "답은 충분, 이 부족은 사소함"으로 두 번 판단했다. 그러면 결과는 `원문에 연결된 판단을 확정하지 못했습니다`(422)였다.
- ADR-0680 #28은 수정 답안이 원래 답안과 글자까지 같았다.
- ADR-0684에서는 판단 첫 시도 3번이 모두 이 규칙에 걸렸다. 이 규칙은 1-1의 루프도 만들었다. 부족을 적기만 하면 무조건 "추가 조사 필요"가 되었기 때문이다.

### 1-4. 최종 답변이 판단 문장을 이어붙인 것뿐이라 뭉개지고 모순이 그대로 나갔다

**질문:** 금융투자회사가 일반 고객과 원화 환매조건부매매(RP)를 하는 경우 대상 채권의 종류와 신용등급 요건은 무엇인가? (ADR-0686 run-003)

> 첫 문단: "…다음 중 하나에 해당해야 한다: (가) 신용평가업자로부터 투자적격(회사채 BBB이상) 판정을 받은 증권, (나) 금융감독원장이 정하는 적격금융기관이 발행 또는 보증한 증권, (다) 정부 또는 지방자치단체가 보증한 증권, …"
>
> 둘째 문단: "…신용등급 요건은 다음과 같다: (1) 일반 경우: 신용평가업자로부터 투자적격(회사채 BBB이상) 판정을 받은 증권이어야 한다. …"

- 첫 문단은 BBB를 대체 요건 중 하나로 썼고, 둘째 문단은 모든 일반 고객 RP의 필수 요건처럼 썼다.
- 원문 검토(ADR-0687)에서 "제5-18조제2항제2호의 선택 구조와 모순"인 오답으로 판정됐다.
- "대손충당금과 대손준비금은 어떻게 구분되는가?"(run-001)에는 종합금융투자사업자 특례 조문 문장만 나열됐다. 정작 구분에 대한 결론이 없었다(부분정답).
- 원인: 답변 작성 단계는 모델을 부르지 않고 판단 문장을 순서대로 붙이기만 했다. 쟁점별 묶음도, 결론 문장도, 최종 검토도 없었다.

### 1-5. 한계 문구가 무엇이 빠졌는지 말하지 않았다

ADR-0686 run-002의 실제 답변 끝부분:

판단이 짚은 "별표 17-1"은 사용자에게 보이지 않았다. 종료 이유도 늘 같은 문장 하나였다.

### 1-6. 판단 입력의 대부분이 원문이 아니라 메타데이터였다

- 판단 호출 66건의 입력 크기는 중앙값 2.8만 자, 최대 25만 자였다.
- 법령 원문 비중은 **중앙값 19%**였다. 참조 연결 목록은 **43%**(최대 19만 자)였다.
- ADR-0684 run-001은 13.3만 자 중 9.7만 자가 참조 목록이었다. 79개 그룹이 연결마다 원문 문장을 반복했다.
- 탐색 화면도 중앙값 6.9만 자, 최대 12.6만 자로 설정 상한(10만 자)을 넘었다. 크기 검사는 없었다.

### 1-7. 멀티턴에서 과거 기록이 연결되지 않았다 (코드 경로 분석, 실행 재현은 안 함)

- **질문 목적이나 문서 범위를 고치면 실패:** 이전 조사 상태를 그대로 이어받다가 "조사 상태가 맞지 않음" 오류가 났다.
- **"근거 다시 골라줘", 검색어만 바꾼 재계획:** 이전 FINISH 결과를 모델 호출 없이 그대로 돌려줬다. 사용자는 같은 답을 다시 받았다.
- **이전 실행 기록 미사용:** 이전 정정 이력과 경험 기록은 실행 객체에 넣기만 하고 읽는 곳이 없었다. 새 질문은 직전 질문에서 읽은 법령을 모른 채 처음부터 검색했다.
- **재진입 한도 이월:** 이전 요청에서 소진한 재진입 횟수가 다음 요청으로 넘어갔다.
- **부분 답변 재생 (MAIN45만 해당):** 부분 답변으로 끝난 route도 "재생할 절차"로 저장됐다. 같은 질문을 다시 하면 같은 부분 답변 경로를 재생할 수 있었다. 실험은 매번 빈 상태로 시작해 실제 발생은 미확인이다.

## 2. 한 것

판단 기록 형식은 `investigation-completion-v2`로 올렸다. 이미 저장된 v1 답변은 원래 방식대로 다시 검증되며, 변하지 않는다.

### 2-1. 부족 처리 라운드 (1-1 대응)

판단이 부족을 내면 탐색에 "부족 라운드"가 열린다.

- 탐색 화면이 법령 목록 화면으로 돌아간다. 시행령·별표 같은 다른 문서를 열 수 있게 하기 위해서다.
- 다음 정보를 함께 보여준다: 부족별 `missing_target`(예: `모의 시행세칙 제2조`), 채택 원문에서 아직 읽지 않은 연결, 열 수 있는 법령, 검색 행동.
- FINISH하려면 부족마다 처리 결과를 적어야 한다.
  - `RESOLVED`: 부족 이후 **새로 채택한 원문**이 있어야 한다.
  - `NOT_AVAILABLE`: 부족 이후 **조사 행동이 한 번 이상** 있어야 한다.
  - `NOT_NEEDED`: 이유를 적으면 바로 허용된다.
- 다음 판단은 이 처리 결과(`gap_history`)를 본다.
- **같은 부족(문서·조문 표기 기준, 문장 표현과 무관)은 다시 조사로 되돌리지 않는다.**

합성 사례의 실제 출력:

| 상황 | 이전 | 지금 |
|---|---|---|
| 판단이 매번 같은 부족을 냄, 탐색은 `NOT_NEEDED` 처리 | 판단 3회 + 한도 종료 | 판단 **2회**, HTTP 200, 부분 충족 |
| 탐색이 처리 결과 없이 바로 FINISH (실제 기록의 패턴) | 바로 FINISH 수용, 판단 3회 | FINISH 1회 거절 → 재시도도 거절 → 강제 종료. 부족은 `UNRESOLVED`로 기록, 판단 **2회**, HTTP 200 |

```
확인 범위

- 승인 기준은? — 모의 시행세칙 제2조: 조사 단계에서 답변에 필요하지 않다고 판단해 추가 열람하지 않았습니다.
```

```
확인 범위

- 승인 기준은? — 모의 시행세칙 제2조: 추가 조사 중 확보하지 못했습니다.
- 근거 선택 결정을 확정하지 못해 확인한 근거 범위에서 답변합니다.
```

### 2-2. 거절 기록·검색 이력·행동 결과를 다음 화면에 (1-2 대응)

- 최근 거절된 결정 3개(행동, 검색어, 거절 이유)를 다음 화면에 보여준다.
- 이전 검색어를 형태소 조각이 아니라 **원래 문장**으로 보여준다.
- 조사 기록의 각 단계에 실제 결과를 붙인다: 새로 나온 법령, 새로 읽은 조문, 전달된 페이지 수, 채택·보류 변화.
- 검색 결과는 다음 검색 단계에서 "몇 개 법령이 나왔는지"로 채워진다.
- 오래된 단계는 행동, 이유, 결과만 남기고 줄인다. 최근 8단계는 그대로 둔다.
- 검색 중복 판정은 형태소에 **조문번호를 함께** 비교한다.

```
상법 제362조 이사회 결의사항 → 번호 ['제362조'] → 식별값 c1f47308de34
상법 제236조 이사회 결의사항 → 번호 ['제236조'] → 식별값 055492132669   (이제 다른 검색)
```

같은 검색이 거절되면, 거절 사유에 "앞서 실행한 `모의승인규정 제362조 승인`과 같다"처럼 실제 이전 검색어를 함께 적는다.

### 2-3. 422 대신 제한 답변 (1-2, 1-3 대응)

- **판단이 두 번 구조 오류로 거절될 때:** 서버가 보수적으로 정리한다. 숨긴 부족은 보이는 한계로 바꾸고, 완전 충족은 부분 충족으로 낮춰 답변을 돌려준다. 근거 없는 판단 문장이나 인용을 새로 만들지는 않는다. 판단 문장이 하나도 없을 때만 예전처럼 실패한다.

  ```
  확인 범위

  - 승인 기준은? — 모의 시행세칙 제2조: 추가 근거 자료 확인이 필요합니다.
  - 판단의 충족 표시를 기록된 원문 부족에 맞춰 부분 충족으로 조정했습니다.
  ```

- **탐색이 채택 없이 강제 종료될 때:** 실제로 화면에 전달한 원문으로 판단한다. 모델이 명시적으로 보류(DEFER)하거나 제외(EXCLUDE)한 원문은 쓰지 않는다. 한계에 "조사 단계의 근거 채택이 확정되지 않아, 실제로 열람한 원문을 기준으로 판단했습니다"를 붙인다.
- **모델이 스스로 보류(PENDING)를 고를 때:** 확인된 원문이 있으면 제한 답변으로 끝낸다.

### 2-4. 쟁점별 답변과 구체적인 한계 문구 (1-4, 1-5 대응)

- 쟁점이 둘 이상이면 답변을 쟁점별로 묶는다. 근거가 없는 쟁점은 그 사실을 적는다.

  ```
  1. 대손준비금은 언제 적립하는가?

  종합금융투자사업자는 미달액을 대손준비금으로 적립한다.

  2. 대손충당금과 무엇이 다른가?

  대손충당금은 회계기준에 따른 손실 추정액이다.

  3. 적용 대상 회사는?

  제공된 원문으로 이 쟁점의 판단 근거를 확인하지 못했습니다.
  ```

- 판단은 부족마다 빠진 문서·조문 표기를 짧게 적는다(`missing_target`). 한계 문구는 그 표기와 탐색 결과를 그대로 쓴다. 모델의 자유 서술 이유는 여전히 사용자에게 보이지 않는다.
- 종료 사유별 문구를 나눴다. 재조사 한도, 같은 부족 반복, 호출·시간 한도, 진전 없음, 결정 미확정, 보류 선택을 구분한다.
- 판단 지시를 보강했다.
  - 각 쟁점의 첫 문장은 직접 결론으로 쓴다.
  - 구분·비교 질문에는 차이를 직접 설명한다.
  - "다음 중 하나" 같은 선택 구조를 다른 문장에서 필수 요건처럼 쓰지 않는다.
  - 특례 조문만으로 일반 질문에 답하지 않는다.
- 질문 분해 지시를 보강했다: 질문에 없는 배경 쟁점을 만들지 않는다. **이 둘은 지시문만 바꾼 것이라 효과는 미확인이다.**
- 탐색이 끝낼 때 근거가 없는 쟁점이 있으면 한 번 되묻는다. 그대로 다시 끝내면 그 쟁점을 "조사 단계가 근거를 찾지 못함"으로 판단에 넘긴다.

### 2-5. 판단 입력 정리 (1-6 대응)

- 판단에 넘기던 참조 연결 전체 목록을 **아직 읽지 않은 연결의 단서**로 바꿨다. 출발 조문, 대상 조문, 연결 종류만 남기고 원문 문장은 넣지 않는다.
- 조사 기록은 오래된 단계를 줄인 형태로 넘긴다.
- 탐색 화면이 설정 상한을 넘으면 후보 법령 제목과 미리보기만 줄인다. 실제로 전달한 원문 페이지는 절대 줄이지 않는다.
- 판단 입력의 원문 중복은 아직 남아 있다(4절 참고).

### 2-6. 멀티턴 연결 (1-7 대응)

- **질문 목적이나 범위를 고치면:** 오류 대신 새 조사를 시작한다. 이전 조사에서 채택한 조문, 조사한 법령, 검색어, 부족 처리 결과는 "힌트(근거 아님)"로 보여주고, 그 법령은 목록에 바로 열 수 있게 둔다.
- **같은 질문을 다시 조사해 달라고 하면:** 이전 FINISH를 그대로 돌려주지 않는다. 조사를 다시 열어 새 결정을 받는다.
- **같은 세션의 새 질문:** 직전 질문의 조사 요약을 힌트로 받는다. 같은 질문 안에서 정정이 있었으면 최근 정정 이력도 힌트로 받는다. 지금까지 읽는 곳이 없던 이력·경험 기록이 실제로 쓰이게 됐다.
- **재진입 한도:** 요청마다 새로 센다. 같은 요청을 재개하는 경우에만 이어서 센다.
- **절차 재생:** 완전 충족이면서 한도로 멈추지 않은 답변만 재생 대상으로 저장한다.

새 파일은 `05_TESTS/CONTRACTS/test_judgment_loop_recovery.py`다. 각 테스트는 1절의 실패 하나를 고정한다. 기존 코드에서는 22개 모두 실패하고, 수정 코드에서는 22개 모두 통과한다. 기존 코드에서의 실패 내용 일부:

| 테스트가 고정한 상황 | 기존 코드의 실제 결과 |
|---|---|
| 같은 부족 반복 / 바로 FINISH / 판단 2회 거절 (API 종단) | `SOURCE_INVESTIGATION_INCOMPLETE` — "원문에 연결된 판단을 확정하지 못했습니다" (422) |

### 기존 테스트와의 비교

- 관련 테스트 파일 115개(약 1,550개)를 기존 코드와 수정 코드로 각각 돌렸다. **수정 코드에서만 실패하는 테스트는 0개**다.
- 수정하는 동안 기존 테스트 4개가 새로 실패했다. 원인을 고쳐 모두 통과시켰다.

  - 1개: 보류한 원문을 대체 경로에서 제외했다.
