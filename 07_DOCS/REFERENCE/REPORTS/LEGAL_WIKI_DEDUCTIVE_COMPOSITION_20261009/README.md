# legal_wiki의 분해·연역적 합성·새 개념 생성 설계

작성일: 2026-10-09. 상태: 제안 설계, 구현·실험·MAIN 변경 없음. 검토: 작성자 자체 검토.

사용자 목표는 shortcut으로 경험한 조사 경로를 일반화하는 데서 더 나아가, legal_wiki의 작은 정의와 규칙으로 이전에 경험하지 않은 추론 경로를 구성하고 새 legal_wiki를 생산하는 것이다. 이 문서는 [앞선 탐색 지연 개선 설계](../ONTOLOGY_RAG_LATENCY_DESIGN_20261009/README.md)를 확장한다. 앞선 설계의 조사 계획 재사용은 여기서 만들어진 지식을 소비하는 한 경로다.

## 1. 제안: 경험으로 배우고, 논리로 조합하고, 증명과 함께 축적한다

가능하다. 다만 현재 자연어 legal_wiki를 통째로 연결하는 것만으로는 원하는 연역이 성립하지 않는다. 각 위키를 개념 정의, 조건 규칙, 개별 사실, 예외, 조사 절차로 분해하고, 같은 뜻과 대상을 가리키는 항목만 연결할 수 있어야 한다.

목표 구조는 다음과 같다.

    shortcut: 실제 질문·사실·행동·채택 원문·결과
        ↓ 의미 추출·일반화 후보 생성
    원자 지식: 정의 / 조건 규칙 / 사실 / 예외 / 절차
        ↓ 원문·의미·적용범위 검토
    형식 지식: 타입이 있는 술어 + 명시적 전제·결론
        ↓ 규칙 합성·증명 검사
    파생 지식: 새 정의 + 새 조건부 정리 + 증명 의존성
        ↓ 제한된 범위로 게시·색인
    새 legal_wiki와 조사 계획
        ↓ 새 질문의 조건 확인·부족한 근거만 탐색
    현재 원문에 결속한 판단 → shortcut 피드백

위키 문장은 위 형식 지식의 사람이 읽는 표현이다. 생성된 설명문 자체를 다음 추론의 근거로 재추출하지 않는다. 다음 추론은 이미 검증한 명제 ID와 증명을 사용한다.

### 서로 다른 세 가지 생성

| 생성 | 예 | 의미와 처리 |
|---|---|---|
| 연역 | A→B, B∧C→D에서 A∧C→D | 전제가 성립하는 범위 안에서 논리적 귀결을 증명한다. |
| 정의 구성 | K(x) ≡ A(x)∧C(x) | 기존 조건 묶음에 새 내부 개념을 정의한다. K가 법령의 공식 용어라는 뜻은 아니다. |
| 귀납·가설 생성 | 여러 사례에서 A와 D가 함께 나타나 A→D를 제안 | 관찰만으로 증명되지 않는다. 별도 가설로 저장하고 누락 조건·반례·원문을 검토한다. |

shortcut에서 보편 규칙을 얻는 첫 단계에는 귀납과 해석이 들어간다. 그 뒤 기존 규칙으로 새로운 귀결을 구하는 단계가 연역이다. 새로운 정의에 이름을 붙이는 일과 그 정의에 대한 법률상 효과를 증명하는 일도 분리한다.

## 2. 수학·논리학에서 가져올 모델

### 설명 기반 학습: 성공 사례가 성립한 이유를 일반화

EBL/EBG는 배경 이론으로 사례를 설명하고 그 설명이 성립하는 조건을 일반화하는 연구다. 우리의 shortcut에서 사례 고유 값과 추론에 필요한 조건을 분리하는 데 참고할 수 있다. [Mitchell·Keller·Kedar-Cabelli, 1986](https://link.springer.com/article/10.1023/A:1022691120807).

그러나 고전 EBG의 한 방식은 원래 증명 구조를 유지하고 충분조건을 구하며, 다른 하위 목표 증명 경로까지 탐색하지 않는다. DeJong·Mooney는 이 한계를 분석하고 설명 구조를 변경하는 학습도 다룬다. 따라서 본 설계는 사례별 일반화에 더해 독립 규칙 사이의 새 증명 경로 합성을 둔다. [DeJong·Mooney, 1986, 특히 2·5.2·9절](https://www.cs.utexas.edu/~ml/papers/ebl-mlj-86.pdf).

### Horn 논리: 규칙을 연결하고 증명 기록을 남김

초기 연역 핵심은 제한된 Horn 규칙으로 제안한다. 규칙의 결론과 다른 규칙의 전제를 변수·타입에 맞춰 연결하고, 모든 전제가 확보될 때 결론을 도출한다. 실용적인 Datalog 시스템인 Soufflé에는 결과 튜플의 도출 과정을 증명 트리로 설명하는 기능이 있다. 이는 추론 결과와 도출 근거를 함께 남기는 구현 참고다. [Soufflé 공식 provenance 문서](https://souffle-lang.github.io/provenance).

일반 Datalog의 사실 도출만으로 새 보편 규칙이 자동 학습되지는 않는다. 본 설계의 파생 규칙 생성은 별도의 제한된 규칙 전개·합성 단계로 수행하고, 그 결과를 작은 증명 검사기가 확인한다. 구체 엔진 채택과 성능은 아직 결정·측정하지 않았다.

### 기술 논리·개념 구성: 작은 정의로 새 정의를 만듦

OWL 2는 기존 클래스를 교집합·합집합 등의 식으로 조합해 새 클래스를 정의한다. 또한 동치 정의와 한 방향의 포함 관계를 구별한다. 이 구분을 가져와 K≡A∧C와 K→D를 별개 항목으로 저장한다. 처음부터 OWL 전체 추론 기능을 도입하자는 제안은 아니다. [W3C OWL 2 Primer 5절](https://www.w3.org/TR/owl2-primer/#Advanced_Class_Relationships).

### 술어 발명: 기존 어휘로 표현하기 어려운 중간 개념을 제안

ILP의 predicate invention은 학습 과정에서 새 보조 술어를 도입하는 연구다. 반복되는 조건 묶음에 이름을 붙이거나 여러 규칙을 설명하는 중간 개념을 찾는 후보 생성기로 검토할 수 있다. 여기서 만들어진 규칙의 법률적 타당성은 별도 확인 대상이다. [Cropper·Morel, Predicate Invention by Learning From Failures](https://arxiv.org/abs/2104.14426).

첫 구현은 명시적 조건 묶음의 정의와 규칙 합성부터 시작한다. 이후 실제로 부족한 개념을 확인한 경우에 술어 발명을 확장한다. 처음부터 모든 개념을 자동 발명하는 범용 학습기를 임계 경로에 넣지 않는다.

### 예외가 있는 규칙: 조건부 결론의 철회

법률 규칙은 예외와 우선관계로 결론이 바뀔 수 있다. 관련 연구에서는 이런 규칙을 defeasible reasoning으로 형식화한다. 여기서는 예외 규칙의 우선관계가 명시적으로 검토된 경우에만 적용하고, 미해결 충돌은 보류한다. 해당 연구를 법률 원문의 자동 형식화가 해결됐다는 근거로 사용하지 않는다. [Lim 외, Automating Defeasible Reasoning in Law](https://arxiv.org/abs/2205.07335).

위 연구들은 구성 요소의 근거다. 이 저장소에서의 정확도·속도·법률적 적합성이 검증됐다는 뜻은 아니다.

## 3. 경험하지 않은 경로가 만들어지는 예

아래는 연역 구조를 설명하기 위한 가상 기호다. 실제 법령의 요건이나 결론을 주장하지 않는다. 모든 규칙은 같은 적용 대상·시점·관할에 있고 필요한 예외 조건이 반영됐다고 가정한다.

    위키 1: 모든 x에 대해 A(x) → B(x)
    위키 2: 모든 x에 대해 B(x) ∧ C(x) → D(x)

A를 만족하는 임의의 x는 위키 1에 의해 B를 만족한다. 같은 x가 C도 만족하면 위키 2에 의해 D를 만족한다. 따라서 다음 보조정리를 저장할 수 있다.

    파생 위키 3: A(x) ∧ C(x) → D(x)
    증명: 위키 1, 위키 2, 동일 변수 x의 연결

조건 묶음에 새 이름도 붙일 수 있다.

    새 내부 정의: K(x) ≡ A(x) ∧ C(x)
    K의 성질: K(x) → D(x)

여기서 D(x)→K(x)는 도출하지 않는다. D가 되는 다른 경로가 있을 수 있기 때문이다. A∧C는 D의 충분조건이며 전체 필요충분조건이라는 주장은 아니다.

이후 별개의 위키에서 다음을 얻었다고 하자.

    위키 4: X(x) ∧ Y(x) → A(x)

그러면 과거 shortcut에 전체 경로가 없더라도 다음을 증명할 수 있다.

    X(x) ∧ Y(x) ∧ C(x) → A(x) ∧ C(x) → D(x)

이것이 사용자가 원하는 다른 경로의 구성이다. 새로운 질문에서 X·Y·C가 확인되면 기존 질문 문장의 유사성과 무관하게 해당 결론까지 도달할 수 있다. C가 미확인이면 D를 확정하지 않고, C를 확인할 자료를 찾는 조사 목표가 만들어진다.

반대로 D까지 연결하는 규칙 자체가 전혀 없다면 연역만으로 그 연결을 만들 수 없다. 새 원문에서 연결 규칙을 확보하거나 가설 생성 단계에서 후보를 제안해야 한다.

## 5. 입력·출력 계약

### 원자 지식 계약 — 제안 이름 legal-logic-unit-v1

| 필드 | 보존할 내용 |
|---|---|
| id / revision / kind | 정의, 규칙, 사건 사실, 예외, 절차, 가설 구분 |
| predicate / arguments | 용어 ID에 연결한 의미, 대상 타입, 주체·행위·객체 등 인자 역할 |
| formula | 자유 변수가 남지 않는 양화 범위, 전제 목록, 결론, 방향. 정의 동치는 별도 표현 |
| scope | 관할, 적용 대상, 효력 시점, 문서 버전·세대. 미확인을 명시 |
| source_refs | 원문 ID·해시·정확한 span. 추출한 문장과 해석 이유 |
| assumptions / exceptions | 추가 가정, 미해결 예외, 명시적으로 검토한 우선 규칙 |
| provenance | shortcut 사건·원자 위키·추출 작업·검토의 ID와 버전 |
| assessments | 원문 최신성, 의미 형식화 검토, 논리 증명, 현재 적용성의 개별 상태 |
| access | 원문·사건의 접근 및 외부 전송 제한 |

원문 사실, 사용자 진술, LLM의 해석 후보를 같은 종류의 참 명제로 취급하지 않는다. 사건 사실은 case_id와 대상·시점에 묶는다. 용어집의 동의어 연결도 검토된 동일 의미일 때만 변수 연결에 사용할 수 있다. 이름이 비슷하다는 이유로 다른 법률상의 개념을 합치지 않는다.

### 증명 계약 — 제안 이름 legal-derivation-v1

입력은 버전이 고정된 전제·규칙과 목표 명제다. 출력에는 결론 식, 사용한 규칙 ID·버전, 변수 치환, 각 단계의 입력·출력, 원문까지 이어지는 의존성, 남은 가정, 적용범위, 검사기 버전·해시가 포함된다.

증명 성공은 Γ ⊢ φ, 즉 형식화한 전제 집합 Γ로부터 φ가 도출된다는 의미다. Γ가 실제 원문을 올바르게 표현했다는 검증까지 대신하지 않는다. 가설을 전제로 쓴 경우 증명은 유효할 수 있지만 결과는 그 가설에 의존하는 조건부 결과다. 승인된 법률 지식으로 자동 승격하지 않는다.

### 파생 legal_wiki 계약 — 제안 이름 legal-derived-wiki-v1

결과 유형은 DEFINITION, DERIVED_RULE, HYPOTHESIS로 분리한다. 설명문, 적용 조건, 새롭게 줄어드는 조사 단계, 증명 ID, 원문 전제 목록, 반례·충돌·미확인 사항을 제공한다. 문장 생성 시 형식 결론보다 강한 표현을 쓰지 않도록 구조화된 렌더링을 우선한다.

현행 직접 claim의 단일 원문 인용 요구를 삭제하지 않는다. 여러 규칙의 조합으로 얻은 결론은 DERIVATION 경로로 표시하고, 각 전제를 뒷받침하는 개별 원문 인용을 보존한다. 파생 문장 전체가 하나의 조문에 쓰여 있는 것처럼 인용하지 않는다.

## 6. 초기 추론 범위와 실패 처리

첫 범위는 타입 있는 양의 Horn 규칙, 유한한 사실 집합, 함수 기호 없는 안전한 규칙, 명시적 조건 묶음으로 제한한다. 안전한 규칙은 결론의 변수가 전제에 나타나는 등의 제한을 뜻한다. 고정된 이런 규칙 집합의 사실 도출은 유한하게 계산할 수 있지만, 가능한 새 규칙·새 개념의 생성까지 유한한 소량 작업으로 보장되는 것은 아니다. 합성 깊이·규칙 수·후보 수에 별도 한도를 둔다.

| 상황 | 원하는 처리 |
|---|---|
| 필요한 C가 기록에 없음 | UNKNOWN. C가 거짓이라고 간주하거나 생략하지 않고 C를 조사할 목표로 반환 |
| A→B만 있는데 B가 확인됨 | A를 역으로 추정하지 않음 |
| B(x)와 C(y)가 있는데 x=y 근거가 없음 | 동일 대상 전제로 결합하지 않음 |
| 적용 시점·관할·대상 범위가 다름 | 공통 적용범위가 증명되는 경우에만 합성. 비어 있거나 미확인이면 보류 |
| 한 위키가 허용, 다른 위키가 의무를 기술 | 서로 다른 술어로 유지. 허용에서 의무를 도출하지 않음 |
| 예외 미확인 | 해당 규칙의 최종 적용을 보류. 예외가 없다는 적극적 확인을 요구하는 guard를 별도로 둠 |
| 명제와 명시적 반대 명제가 함께 있음 | CONFLICT로 표시하고 해당 결론의 확정을 보류. 모순에서 임의의 결론을 도출하지 않음 |
| 규칙 A→B, B→A만 존재 | 시작 근거 없는 순환으로 A·B를 새로 참으로 만들지 않음 |
| 원문 또는 전제 개정·철회 | 증명 의존성으로 영향을 받는 결과를 재검사. 독립적인 유효 증명이 남는지 확인 |
| 일부 전제가 비공개 | 해당 증명의 열람 가능 대상은 모든 전제의 접근허용 교집합. 추상화해도 반출 허가 자동 생성 없음 |
| 형식화할 수 없는 복잡한 규정 | 자연어 원문과 미확인 사항을 유지하고 기존 조사·판단으로 처리 |

초기 엔진에서는 긍정·명시적 부정을 별도 증거로 관리하고, 검색 실패를 부정의 증거로 삼지 않는다. 이 미확인 처리 방향은 OWL의 열린 세계 설명과도 맞닿아 있다. 다만 본 설계의 UNKNOWN/CONFLICT 상태 체계가 OWL 표준 자체의 상태 모델이라는 뜻은 아니다. [W3C OWL 2 Primer의 열린 세계 설명](https://www.w3.org/TR/owl2-primer/).

## 7. 현재 파이프라인에 연결하는 순서

1. 기존 action-memory build / shortcut-v4 생산 경로에서, 새 명세를 선택한 빌드에 한해 형식 후보 추출을 실행한다. 입력 shortcut·원문·용어집·모델·프롬프트·정책 버전을 동결한다. 기존 비공개 입력의 외부 전송 제한을 유지한다.
2. 원자 단위의 원문 일치, 의미 검토, 타입·변수·조건 검사를 저장한다. 반복된 성공 사례 수만으로 규칙의 일반성을 승인하지 않는다. 미검토 후보도 버전과 이유를 보존한다.
3. 검토된 규칙의 결론 술어·인자 타입 색인으로 연결 후보를 찾는다. 같은 대상과 적용범위 안에서 규칙을 제한적으로 합성하고 증명 검사기로 확인한다. 가설을 포함한 합성은 가설 전용 공간에서 수행한다.
4. 자주 필요한 목표·반복되는 조건 묶음의 보조정리와 새 정의를 저장한다. 모든 조합의 위키를 만들지 않는다. 동등한 식·증명 부분은 정규화·해시로 공유한다.
5. 기존 unified-memory의 검토·게시·재구축 경로에 새 계약 지원을 추가한다. 원자 위키와 파생 위키는 같은 지식 생산 파이프라인 안에서 관리한다. 원문·용어 런타임 계약은 유지하고 폐기된 LEGAL_SCHEMA를 되살리지 않는다.
6. 요청 앞단에서 질문과 현재 사실을 한 번 정리하고, 필요한 목표 술어에 대해 승인된 규칙과 증명을 조회한다. 기존 entry에 후보 선택을 결합해 별도 경로 선택용 모델 호출을 늘리지 않는 방향으로 설계한다.
7. 증명에 필요한 사실·현재 원문이 부족하면 그 부분만 기존 RECALL/READ로 요청한다. 현재 SELECT/ASSESS에서 원문·적용조건·예외를 확인하고, 답변 소비자는 인용과 증명 경로를 전달한다. 초기 도입에서 ASSESS를 자동 제거하지 않는다.
8. 실제 사용 결과와 실패 원인을 shortcut에 남겨 다음 후보 추출로 연결한다. 파생 위키 사용 이력을 새 독립 원문 근거처럼 세지 않는다.

PIPELINE.json에는 단계별 생산자·소비자·스키마·설정·구축 명령을 함께 선언하고 실제 CLI 배선과 대조한다. 저장 위치는 workspace의 기존 논리 root로 해결한다. 별도 최상위 실행기나 운영 기본 경로에서 자동 선택되는 실험 지식 저장소를 만들지 않는다.

## 8. 저장·버전·도입 계획

형식 항목과 증명은 shortcut 공통 저장소의 새 명시적 세대에 추가한다. 기존 원문·shortcut·위키 이력은 보존한다. 기존 sw_* 테이블과 지식 버전에 연결하는 추가 테이블/계약을 설계하고, 구 소비자는 새 형식 지식을 무시하거나 명시적으로 미지원 처리한다. 새 세대를 구 코드로 읽는 암묵적 호환을 가정하지 않는다.

빌드 manifest는 입력 지식 revision, 원문·용어집 세대, 형식 스키마, 합성 정책, 증명 검사기, 게시 지식 인덱스의 해시를 결속한다. 모델을 사용하는 후보 추출 단계와 결정적인 증명 검사 단계를 별도로 기록한다. 원문·같은 증명 부분은 해시로 공유하며 위키마다 전체 본문·모델 입출력을 중복 저장하지 않는다.

실제 구현 시 기존 작업 코드와 후보의 차이를 먼저 대조한 뒤 통합한다. 후보 데이터와 설정을 격리하고, 후속 ADR에서 평가와 승격 기준을 호출 전에 동결한다. 검증한 동일 코드를 MAIN에 연결하고, 제품 승격 plan과 명시적 confirm-main 절차, 포인터·코드·프로필·원문·지식 세대·실제 service.service binding까지 확인해야 로컬 MAIN 완료다. 롤백은 이전 코드/프로필과 그에 맞는 이전 지식 세대로 함께 복귀한다.

GENOS는 별도 반입·워크플로우 편집·내부 모델·현장 검증 단계다. 현 세션에서 접근하거나 검증한 것으로 보고하지 않는다. 이 문서에서는 구현·새 ADR·모델 호출·배포를 실행하지 않았다.

## 9. 무엇으로 성공을 판단할 것인가

핵심은 문장만 바꾼 질문의 적중률보다 새로운 증명 조합의 처리다. 다음 구분을 사전 동결한 후 평가한다.

| 평가 묶음 | 확인할 능력 |
|---|---|
| 기존 경로의 표현 변경 | 기존 shortcut·위키 수준을 보존하는가 |
| 개별 규칙은 있었지만 전체 연결은 없던 질문 | 새로운 규칙 조합으로 올바른 결론과 증명을 만드는가 |
| 같은 결론에 이르는 다른 하위 증명 | 과거 하나의 성공 궤적에 고정되지 않는가 |
| 조건 하나 누락·반대 사실·다른 대상 | 부당한 일반화를 멈추고 부족한 전제를 특정하는가 |
| 시점 변경·규정 충돌·접근권한 철회 | 현재 유효한 근거만 사용하고 영향받은 파생 결과를 철회하는가 |
| 배경 규칙 자체가 없는 질문 | 연결을 발명해 확정하지 않고 탐색 또는 가설 후보로 분리하는가 |

훈련/구축 사례와 평가 사례는 질문 문자열뿐 아니라 사건·원문·규칙 조합·증명 구조의 중복을 기록한다. 새로운 조합 평가에서는 개별 규칙을 제공해도 전체 목표 경로와 답을 사전에 파생 인덱스에 넣지 않는 조건을 명시한다. 전체 경로가 사전 저장된 조건은 별도 조회 성능 평가로 분리한다. 평가 후 만든 규칙은 그 평가의 사전 지식으로 소급 취급하지 않는다.

품질은 전제 누락, 잘못된 변수 연결, 근거 없는 연결 규칙, 인용·권한 오류, 증명 실패를 각각 기록한다. 세부 의미 오류와 무결성 위반은 구분한다. 시간은 오프라인 추출·합성 비용과 온라인 조회·증명·추가 탐색·모델 시간을 나누고, 새로운 경로를 처리한 비율과 전체 요청의 지연을 함께 본다.

아직 성능 측정은 없다. 앞선 설계의 조건부 모델 호출 수 목표가 이 확장으로 자동 달성되는 것은 아니다. 잘 정리된 규칙은 조사 범위를 줄일 수 있지만, 무제한 합성·넓은 개념 목록·불명확한 형식화는 비용과 지연을 증가시킬 수 있다. 유용한 보조정리를 미리 만들고 질문별로 필요한 부분만 사용하는 구조를 먼저 검증해야 한다.

## 10. 자체 검토와 남은 미확인

확인한 사항: 현재 위키의 자연어·조건·원문·관계 계약, 여러 사건의 사실 혼합 차단, 현재 질문 조건에 묶인 재사용 소비자, 도메인 선택의 실제 동작, 기존 빌드·게시 경로. 연구 문헌의 열람 범위와 파일 해시는 evidence.json에 기록한다.

설계 판단: EBL로 경험의 설명을 일반화하고, 제한된 논리 합성으로 새 경로를 증명하며, 정의 구성과 가설 생성을 분리하는 구성이 사용자 목표에 맞는다. 이는 문헌에 실린 완제품을 그대로 적용한다는 주장이 아니라 현재 코드에 맞춘 제안이다.

미확인: 실제 위키 중 형식화 가능한 비율, 원문에서 규칙으로 옮길 때의 오류, 예외·우선관계 범위, 신규 경로 성공률, 오프라인 합성 규모, 온라인 지연, 운영 검토 비용, GENOS 실행 성능. 독립 검토·새 실험·서비스 실행 검증은 수행하지 않았다.
