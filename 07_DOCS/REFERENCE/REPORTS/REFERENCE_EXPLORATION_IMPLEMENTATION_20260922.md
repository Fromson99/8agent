## 추가 발견과 수정

`시작점 → B조 제10호 → B조 전체를 인용하는 C조 → 같은 참조를 거꾸로 다시 따라 B조 전체`의 왕복으로 제39호 연결까지 열리는 문제가 재현됐다. ADR-0521 결과를 보존하고 ADR-0522를 새로 선점해 수정했다.

최종 후보는 이동 직전의 참조와 출발 원문을 함께 기록한다. 같은 참조를 반대 방향으로 곧바로 되돌아가 원래 원문을 넓히는 이동을 억제한다. C조의 다른 참조, 하나의 범위 참조에 속한 다른 대상, 독립 검색에서 채택한 조 전체 시작점은 계속 탐색한다. 다른 유효한 명시 참조 경로로 더 넓은 범위를 다시 찾는 것은 허용된다. 임의의 역참조 깊이 제한을 넣지 않았다.

DB 이웃 조회는 물리적 범위별로 공유하고, 되돌아오는 경로의 문맥과 시작점 소유는 따로 계산한다. 시간·상태 예산 소진은 `PARTIAL`과 재개할 작업으로 남긴다. 현재 구현의 대규모 소유·제거 영향 계산과 원문/증거 직렬화 비용은 추가 측정 대상이다.

## 검증 결과와 성능 해석

- 최종 후보: **103개 계약·회귀 검사 통과**. HTTP 통합 검사 1개는 제외됐다. 샌드박스에서 TestClient가 끝나지 않아 중단했고, 화면 문법과 실제 앱 함수 연결은 별도로 검사했다.
- 기존 테스트의 입력 중 연결 원문까지 모델이 채택하던 부분을 시작점 선택 계약으로 이행했다. 초안·법률 검토·출처 번호 변환에 대한 기존 검증은 유지했다. 초기 실패 로그도 보존했다.
- 최종 4개 합성 시나리오에서는 필요한 원문 22/22를 유지하면서 왕복 때문에 추가되던 원문 2건을 제외했다. 같은 좁은 범위 구조를 재사용한 사례가 있으므로 독립 질문 4건의 법률 성능으로 해석하지 않는다.
- 앞선 ADR-0521 실제 DB 진단 6건은 모두 `PARTIAL`이었다. 과거 독립 검색 시작점 144~196개를 그대로 투입하자 평균 약 **8,098개 원문**에 도달했다. 해당 6건의 기준 원문 10/10이 포함됐지만, 이는 **앞선 후보의 원문 보존 수치**이며 최종 후보의 회수율이나 답변 품질을 입증하지 않는다.
- 최종 후보의 실제 DB 대규모 재생, 실제 LLM의 시작점 선택·재검색·보완 조사·답변 성능은 미측정이다. 모델 호출은 0회였다. 90/90을 합격 조건으로 강제하지 않았다.

따라서 **확인한 잘못된 확장 유형은 수정했지만, 실제 회수율 유지와 전체 탐색 폭발 해소를 완료 판정하지 않는다.** 실제 모델을 포함한 별도 표본 검증이 남았다.

## 운영 반영이 남은 이유

저장소 AGENTS.md는 `Accepted`, 표본 밖 검증, `decision_eligible=true`, 완료 arm만 MAIN 승격하도록 요구한다. 두 후보는 인샘플 진단이며 이 조건을 충족하지 않는다. 현재 `rag_main_promotion.py`의 실제 dispatcher는 `semantic_runtime.control`로 연결되어 품질 우회 승인서를 요구하므로, 과거 우회를 재사용하지 않고 활성화하지 않았다.

외부 모델 정책은 Qwen이지만 현재 반출 설정의 문서·세대·대상은 과거 Anthropic/Haiku 승인에 묶여 있다. 그 승인을 새로운 세대나 Qwen 전송으로 확대하지 않았다. GENOS에는 이 세션에서 접근할 수 없으므로 현장 결과도 없다.

다음 단계는 반출/현장 실행 범위가 맞는 환경에서 최종 후보를 새 ADR로 검증하고, 시작점 수·정확 항호 도달·누락 복구·모델 전달·실제 답변 인용·전체 지연을 각각 비교하는 것이다. 후보 패키지 자체를 운영 registry에 연결하지 않았다.
