# 읽기 결과 피드백과 단계 전환 수정 계획

작성일: 2026-09-20. 상태: **설계 제안, 코드 수정·모델 호출 미실행**.

## 1. 결정 요약

원문 중심 더블하네스의 책임 분리는 유지한다. 서버는 실제 도구 실행·읽기 범위·근거 연결·중복·예산을 관리하고, 모델은 근거의 관련성·충분성·답변 내용을 판단한다.

이번 변경은 **읽음 상태 표시 → 직전 행동 결과 전달 → 제한된 재판단**이다. 자동 근거 채택, 무조건 작성 전환, 예산 증액은 하지 않는다. CM003 정답/조문 ID에 맞춘 제품 분기도 만들지 않는다.

변경 대상은 ADR0476의 동결 후보에서 새로 분기할 연구 후보다. 기존 완료 ADR, 동결 revision, 운영 document-navigation-v1, 원문 세대는 수정하지 않는다. 설계 문서만 작성하는 현재 단계에서는 새 ADR 선점이나 유료 실험을 시작하지 않는다.

## 2. 확인된 실패와 미확인 원인

원문 자료: [실제 실행 보고](../../../../04_EXPERIMENTS/ADR/ADR-0476-source-first-qwen-autonomy/README.md), [지표](../../../../04_EXPERIMENTS/ADR/ADR-0476-source-first-qwen-autonomy/artifacts/metrics.json).

- 필요한 결정 조문 두 개가 첫 모델 입력에 있었다. 시행세칙 전문과 제4항도 전달됐다.
- 모델은 같은 카드 P3를 두 번 읽으라고 요청했고, select는 두 번 모두 빈 배열이었다.
- 두 요청 모두 system/user 두 메시지이며 이전 assistant/tool 대화 이력은 없었다.
- 두 번째 view에서 달라진 것은 base_state_revision, remaining, view_id뿐이었다. cards/evidence/limitations는 같았다.
- read()의 실제 결과는 서버에 저장됐지만 apply_decision()은 반환값을 모델용 실행 결과로 연결하지 않았다.
- 진전 없음 두 번으로 investigate()가 끝났다. selected가 비었으므로 answer_and_review()는 작성·검토를 호출하지 않았다.

**구현의 누락은 확인됐으나, 이 누락이 모델 반복의 유일한 원인인지는 미확인이다.** 카드와 원문은 제목으로 대조할 수 있었으므로 모델에 정보가 전혀 없었다고 설명하지 않는다. 입력량·프롬프트·모델의 결정 성향도 남는 가설이다.

아래 파일명은 새 후보에 복제할 기존 파일이다. 새 필드·정책은 모두 제안이며 아직 구현되지 않았다.

|---|---|---|---|

## 4. 변경 A — 읽음 상태와 근거 연결

서버 내부에서는 card → source → evidence/span 관계를 보유한다. 모델용 카드에는 다음을 제안한다.

```json
{
  "card": "P3",
  "read_state": "COMPLETE",
  "presented_evidence": ["E7"],
  "next_cursor": null,
  "citation_eligible": false
}
```

이 값은 관측 사례 설명용이며 제품 코드에 P3/E7을 하드코딩하지 않는다.

- read_state는 UNREAD/PARTIAL/COMPLETE/FAILED를 구분한다. next_cursor=null만 보고 COMPLETE라고 하지 않는다. 성공한 실제 READ의 coverage와 페이지/span 누적 범위로 판단한다.
- 긴 조문은 카드 하나에 여러 E가 연결될 수 있다. 새 cursor는 유효한 추가 읽기이며 중복으로 차단하지 않는다. 순서가 맞지 않는 페이지·부분 범위에서 전문 읽기를 주장하지 않는다.
- presented_evidence에는 **이번 view에 실제 원문이 들어간 E만** 표시한다. 읽었으나 컨텍스트에서 빠진 근거는 저장 상태와 제시 상태를 구분한다. 근거가 현재 입력에 없으면 별칭만 내보내 인용 자격을 만들지 않는다.
- E를 알고 있다는 사실과 인용 자격은 다르다. 실제 전달 성공은 기존 presentation/model_attempt 검사가 계속 확인한다. 발췌 카드 P 자체는 계속 인용 불가다.
- 새 view를 만드는 순서는 원문 예산 선정 → 제시 E 목록 확정 → 카드 연결 및 실행 결과 E 필터링 → 최종 입력 검증/저장이다. 중간에 제거한 E가 카드 연결에 남으면 실패 처리한다.

## 5. 변경 B — 도구 결과를 다음 모델 입력에 연결

apply_decision()은 실행한 모든 행동의 반환값을 받아 서버 소유 영수증으로 기록한다. read/search/page의 성공·실패·부분 성공을 구별한다.

```json
{
  "last_action_results": [
    {
      "tool": "read",
      "card": "P3",
      "status": "ALREADY_READ",
      "presented_evidence": ["E7"],
      "new_evidence_count": 0,
      "read_complete": true,
      "next_cursor": null
    }
  ]
}
```

상태 표시는 서버가 실제 관측한 기계적 사실만 담는다. “이 근거가 정답이다/충분하다” 같은 법률 판단은 넣지 않는다. raw 원문 속 명령을 실행 안내로 복사하지 않는다.

- 동일 scope/generation/source/span/cursor의 **성공한** 읽기만 재사용할 수 있다. 실패·불완전 결과는 완료 캐시로 쓰지 않는다. 캐시 재사용도 감사 event에 기록하고 도구 행동 회계에서 숨기지 않는다.
- 한 행동 묶음의 일부만 성공하면 성공 결과는 남기고 각 실패를 따로 전달한다. 전체 묶음 성공으로 표시하지 않는다.
- 최근 한 결정의 행동 묶음을 우선 전달하고, 오래된 이력 전체는 journal에 보존한다. 모든 과거 대화를 매번 붙이는 변경은 하지 않는다.
- 예산이 부족하면 카드 발췌·중복 설명을 먼저 줄인다. 실행 상태·관련 별칭·부분 읽기 cursor는 조용히 삭제하지 않는다. 유지 불가능하면 입력 예산 부족을 명시하고 중단한다.
- 마지막에 **전송할 전체 요청**의 문자·바이트 상한을 확인한다. 필드 추가가 컨텍스트 한도를 넘지 않는다는 가정으로 진행하지 않는다.

## 6. 변경 C — 진전 없음과 전환 복구

### 정상 전환

원문이 충분하다고 모델이 판단하면 현재 제시된 E를 select하고 DRAFT를 반환한다. 기존 검증과 서버 저장 후 작성으로 넘어간다. 새 READ와 DRAFT가 함께 오면 새 원문 제시를 먼저 완료하도록 CONTINUE하는 기존 안전 규칙은 유지한다.

### 중복·진전 없음

1. 첫 무진전 행동 뒤 다음 view에 실행 결과와 기계적 통지를 넣는다. 예: 이미 읽은 범위를 재요청했고 새 근거가 없다는 사실.
2. 기존 무진전 한도에 도달하면 즉시 종료하기 전에 **요청 전체에서 한 번만** 선택·탐색 재판단 기회를 제공한다. 새 phase/숨은 별도 모델을 만들지 않고 같은 gateway로 호출한다.
3. 재판단은 모델이 현재 원문을 선택하고 DRAFT, 다른 범위/검색으로 CONTINUE, 또는 선택 없이 보류 종료하는 경로를 허용한다. 특정 E 선택이나 답변을 강요하지 않는다.
4. 동일 실패가 이어지면 NO_PROGRESS_AFTER_RECOVERY로 제한 응답을 남긴다. 유효한 다른 행동이 있으면 정상 루프로 돌아가되, 회복 기회는 재지급하지 않는다.
5. 실제 근거가 있는데 DRAFT와 빈 select를 반환한 경우에도 같은 회복 한도를 공유한다. 영구 선택 누락과 원문 자체 부재를 구분한다. 무근거 답변을 만들지 않는다.

복구 호출도 물리 호출 한도를 소비하며, 기존 작성·검토 reserve를 침범하지 않는다. 한도·시간이 부족하면 복구하지 않고 구체적 사유로 종료한다. 요청당 14회 한도와 investigate의 reserve 규칙을 유지한다.

진전 여부는 카드/근거 **개수만** 비교하지 않는다. 실제 새 span·cursor 범위, 후보 내용, 선택 집합, 탐색 위치의 의미 있는 변경을 반영한다. 식별자·상태 revision·남은 예산 변경은 진전으로 세지 않는다. 제한 없는 페이지 이동으로 무진전 보호가 무력화되지 않도록 방문/행동 중복도 별도 관측한다.

FINAL은 실행 종료이고 성공은 아니다. 기존 외부 스키마를 유지하면서 unresolved와 서버 event에 EMPTY_SELECTION/NO_PROGRESS/INSUFFICIENT_EVIDENCE/INPUT_BUDGET 등을 구분한다. 모델이 근거 부족을 판단했을 때도 bounded 종료는 허용한다.

## 7. 실패 경계·이행

| 경우 | 필요한 동작 |
|---|---|
| 부분 읽기 또는 다른 cursor | 정상 READ 허용, PARTIAL 유지, 미읽은 범위 인용 금지 |
| 이미 읽었지만 현재 입력에서 빠진 원문 | 원문을 다시 제시하거나 명시적 예산 부족; 별칭만으로 채택 금지 |
| model format/network 오류 | 기존 분류와 bounded repair/retry 유지, 복구 논리 호출과 구분 |
| 중복 응답·오래된 view | 기존 check_view/중복 decision 검증 유지 |
| 선택 철회·초안 변경 | 기존 의존 주장/검토 무효화 유지 |
| scope/generation/source hash 변경 | 캐시·영수증 재사용 거부, 새 요청으로 재결속 |
| 재시작 | 이번 수정은 자동 재개를 추가하지 않음. 불완전 세션을 임의 이어 쓰지 않고 기존 publication 복구와 구분 |
| 틀린 근거를 모델이 자신 있게 선택 | 구조 검사로 의미정답 보장 불가; 주장별 검토 및 별도 독립 채점 필요 |

원문/색인 재구축은 필요하지 않다. 새 후보 코드·입력 view 정책·binding은 새 revision으로 동결한다. 기존 journal의 JSON body/event를 재사용할 수 있는지 확인하고, 관계 캐시를 위한 새 DB 테이블은 우선 도입하지 않는다. 동결 과거 journal은 수정하지 않는다. 운영 활성화와 MAIN promotion은 범위 밖이다.

## 8. 검증 순서와 합격 기준

### 먼저, 무모델 계약·실패 재현

- 현재 실패의 실제 view/결정을 오프라인 재생해 기준 후보에서 반복→빈 선택 종료를 재현한다. 실제 모델 응답을 다시 만든 것처럼 부르지 않는다.
- READ 응답 뒤 다음 요청에 해당 card/read_state/current E 연결/실행 결과가 함께 있는지 확인한다.
- 중복 READ, 부분 READ, 새 cursor, 다중 E, 현재 입력에서 제거된 E를 구분한다.
- 재판단 영수증이 실제 다음 입력에 들어가며, 종료 사유·모델 물리 호출 수·시간·reserve가 맞는지 확인한다.
- 모델이 거부/보류하면 선택 0을 유지한다. 서버의 자동 채택·강제 정답 생성이 없어야 한다.
- 허위 E, 미제시 E, stale view, source 변경, 선택 철회, 초안 변경을 거부/무효화한다.
- 재판단 예산 소진, 컨텍스트 상한, 일부 도구 실패, 모드 재진입에서도 무한 루프가 없어야 한다.
- 기존 후보 계약 검사를 함께 실행하고 기존 v1의 이미 알려진 실패는 분리 보고한다. 바뀐 view를 실제 Pipeline/StageRunner/최종 출력 소비자까지 연결 검사한다.

### 그다음, 승인 후 실제 Qwen 검증

새 ADR을 구현 수정 전에 선점한다. baseline은 ADR0476 동결 코드, candidate는 새 상태 피드백·복구 후보다. CM003과 동일 원문 세대/범위/모델/호출 상한을 사용한다. 기준군도 같은 시점에 실행하고 arm 순서를 사전 고정한다. 결과를 보고 같은 후보를 고치거나 반복 호출하지 않는다.

제품에는 정답·decisive ID·선택 힌트를 넣지 않는다. 실제 모델이 선택한 E, 도구 결과, transition, physical attempts를 저장한 뒤에만 gold를 결합한다.

성공 판단을 분리한다:

- **상태 전달:** 요청 직렬화에서 읽음/행동 결과가 정확하다.
- **전환:** 모델이 제시된 근거를 직접 선택하고 작성·검토까지 도달한다. 단순 FINAL은 성공으로 세지 않는다.
- **탐색:** server preread와 모델의 신규 발견/READ를 구분한다. CM003는 이미 결정 조문을 선읽기하므로 이 문항만으로 자율 검색 개선을 인증할 수 없다.
- **품질:** 답변·인용·단서·예외가 맞는지는 별도 채점이다. 자체 SUPPORTED 판정이나 두 조문 인용만으로 정답 처리하지 않는다. Gemini judge를 임의 추가하지 않는다. 독립 정답 채점은 실행 전에 사람/승인된 방식 중 확정한다.

최소 CM003 비교에서 전환이 되더라도 일반화·승격 근거가 아니다. 후속으로 결정 조문이 최초 입력에 없는 문항과 실제로 근거가 부족한 문항을 사전 선정한다. 51문항 동시 기준군 검증 전에는 운영을 바꾸지 않는다.
