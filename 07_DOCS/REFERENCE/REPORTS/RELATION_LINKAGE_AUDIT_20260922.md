# 명시 참조 연결 전수 진단 — 2026-09-22

## 범위와 상태

로컬 활성 포인터 `01_DATA/ACTIVE/local/ACTIVE_RELEASE.json`은
`legal-agent-v5-20260922-r3`를 선택한다. 릴리스는
`01_DATA/TERM/relation-subtree-main-serving-20260920-v1/generation`을 읽는다.
이 조사의 모집단은 그 세대의 `navigation/navigation.sqlite`에 저장된 명시 참조
`reference` 146,994행 전체다. 관계 생성 코드, 인덱스 계약, 주요 소비자 및
중단된 ADR-0519 후보의 경로 확장을 읽기 전용으로 대조했다. 용어 간 의미 관계
48,101행의 의미 정확도는 이 집계 대상이 아니다.

실험을 재개하거나 모델을 호출하지 않았고, 원문·인덱스·활성 포인터·완료 ADR을
바꾸지 않았다. GENOS 현장 상태는 이 로컬 조사로 판정할 수 없다.

## 연결별 원인

1. **제목을 인용으로 추출.** `term_references.compile_references`는 조문 제목
   제외 조건을 `s['blocks'][0]`, 첫 문자, 제목 뒤 괄호로 제한한다. 부칙
   source에는 여러 `제N조(…)` 제목이 별도 블록으로 들어가므로 뒤따르는
   제목은 일반 인용 정규식에 걸린다. 대상 사전은 `(document_id, 제N조)`로
   본문 조항을 찾으므로 부칙 제목 `제1조(시행일)`이 본문 `제1조(목적)`에
   연결된다. `ref:5b41e3550c4d04edf5aed739`는 원문·DB를 대조한 확정 사례다.
2. **부분 좌표 실패의 상태 혼합.** 조 ID를 찾은 뒤 항·호·목을 못 찾으면
   `reason=PROVISION_NOT_IN_STRUCTURE`를 달지만 조 ID는 유지한다. `record`는
   대상 ID만 있으면 `EXACT_*`를 준다. 조문으로 찾아가 검토하는 기능에는
   도움이 되지만 이를 정확한 하위 마디 연결로 취급하면 잘못이다. 현행
   테스트도 이 조 단위 fallback을 의도적으로 허용한다.
3. **원문 전체로 관계 역할 분류.** `explicit_role(text)`는 해당 인용의 주변
   문맥이 아니라 블록 전체에 `준용` 등이 있는지 확인한다. 한 블록에 여러
   인용이 있으면 별개 인용도 준용으로 분류될 수 있다. 이 항목은 코드상
   위험이며 개별 오분류 행 수는 아직 의미 판정하지 않았다.
4. **ADR-0519 확장 그래프의 정보 소실.** 후보의 `root_bundles`는
   `routes[target].anchor`만으로 인접 그래프를 만들고 선택 시작점에서
   무제한으로 순회한다. 참조 ID·방향·역할·확정 상태·target의 항호목
   경로를 통과 조건에 쓰지 않는다. 원문을 회수하지 않은 중간 anchor도
   순회한다. 진단된 `cm-004`는 시작 2개에서 직접 15개, 2단계 68개,
   7단계 200개가 되었고 경로상의 1,150개 중 950개는 회수 풀 밖이었다.
   이 함수는 중단된 연구 후보에 있으며 로컬 활성 v5의 함수가 아니다.
5. **서빙 소비자의 직접 연결 위험.** 활성 v5는 `reference_end`로 조항
   양방향 관계를 찾고, 증거 span과 `target_block_ids`가 있으면 역참조를
   걸러 target 범위를 읽는다. 이 경로는 비재귀·요청당 자동 읽기 제한이
   있지만, 저장된 제목 오인용도 관계 카드의 입력이 된다. `EXACT`만으로
   제목 여부나 정본 승인을 입증하지 않는다. v5의 자동 읽기는 작은 직접
   연결 묶음을 대상으로 하며 ADR-0519의 200개 재귀 결과와 혼동하면 안 된다.

## 재현된 세부 좌표 혼합

`ref:2ba4a0d1349450708ade6335`는 코스닥시장 상장규정 제26조에서
같은 규정 제2조 **제1항 제10호**를 가리킨다(`target_unit_path=[①,10.]`).
`ref:0bd816f397922782f25d9ab7`는 다른 규정 제10조의3에서 같은
제2조 **제1항 제39호 나목**을 가리킨다(`target_unit_path=[①,39.,나.]`).
조항 ID는 같아도 하위 좌표가 서로 포함되지 않으므로 첫 연결을 따라온 뒤
두 번째 역참조로 넘어가면 안 된다. 참조 방향은 원문 `source_id → target`과
검색 회수 경로 `anchor → candidate`를 별도 필드로 다뤄야 한다.

## 호 단위 수정이 이번 결과에 반영되지 않은 이유

현재 활성 인덱스의 manifest는 `term-navigation-index-v3`, 생성 시 컴파일러
SHA-256은 `02b1ea08…`이다. 현재 작업 코드와 활성 릴리스에 포장된
`term_references.py`의 SHA-256은 둘 다 `61a0ab6d…`이다. 따라서 이후
컴파일러 수정은 불변 인덱스에 자동 반영되지 않았다. 다만 위의 제10호와
제39호나목 좌표는 **기존 v3 DB에도 이미 존재**한다. 이 사례의 핵심 실패는
데이터 누락이 아니라 ADR-0519의 `root_bundles`가 그 좌표를 읽지 않은 것이다.
서빙의 관계 카드와 조항 읽기는 `target_block_ids`를 이용해 하위 범위를
보존할 수 있지만, ADR-0519의 별도 원문 선택 그래프는 `source_id`만 노드로
사용한다. 이전 단계의 호 단위 읽기 검사가 통과해도 이 그래프의 정확성을
보증하지 않는다.

ADR-0519 `cm-004`의 고정 회수 기록에서 모델 호출 없이 경로만 재계산했다.
원래 도달은 전체 1,150개/회수 풀 200개다. 블록 시작 `제N조(제목)` 형태의
의심 참조 route 133개를 제외해도 전체 1,062개/회수 풀 **188개**가 남는다.
이는 해당 제목 오인용만 제거해도 200개가 충분히 작아질 것이라는 가설을
뒷받침하지 않는다. 전체 관계 DB를 정확히 재구축했을 때의 최종 수나 품질은
이 사후 필터로 예측할 수 없다.

## 수정 경계와 검증 순서

1. 원본 DB를 제자리 수정하지 않고 새 인덱스 세대를 만든다. 추출 단계에서
   블록의 구조 제목 span을 제외하고 부칙 내부 조 좌표와 본문 조 좌표의
   namespace를 분리한다. 실제 문장에 있는 본문 인용은 유지한다.
2. 해석 상태를 `정확한 target 하위 좌표`, `조까지만 확인`, `미해결`,
   `검토 후보`로 분리한다. 조 단위 fallback은 탐색 후보로 남길 수 있지만
   하위 마디의 확정 연결로 승격하지 않는다. 관계 역할은 인용 mention의
   문장 범위에서 판정하거나 불확실하게 보존한다.
3. 탐색 edge에 reference ID, 법적 방향, 관계 종류, 양 끝의 정확한
   unit/block 경로, 확인 상태, 원문 witness를 묶는다. 역참조는 후보 발견과
   필수 연결 보존을 구분한다. 서로 겹치지 않는 하위 경로 간 이동과
   회수하지 않은 anchor를 통한 무조건 순회를 막는다.
4. `제1조(시행일)`/본문 `제1조(목적)`, 제2조 제10호/제39호나목,
   정상적인 부칙의 본문 개정규정 인용, 정확한 준용·위임, 좌표 미해결,
   복수 target, 순환 관계를 각각 계약 테스트로 검증한다. 이후 새 ADR에서
   기준과 후보의 전체 검색 품질을 비교한다. 18문항 중단 결과는 완성된
   평가로 사용하지 않는다.

## 조사 한계

숫자는 선택된 로컬 세대의 전체 `reference` 메타데이터를 순회한 결과다.
모든 행의 법적 의미를 사람이 판독한 결과나 GENOS 내부 데이터 오류율이
아니다. 엄격한 제목 패턴 밖의 제목 오인식, 누락된 정상 인용, 추출하지 못한
문서 간 관계는 추가 원문 대조가 필요하다. 코드 변경과 인덱스 재구축,
MAIN 활성화, GENOS 배포는 수행하지 않았다.
