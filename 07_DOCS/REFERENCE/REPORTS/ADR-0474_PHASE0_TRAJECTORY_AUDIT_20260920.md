# ADR-0474 0단계 궤적·어댑터 감사

- 감사일: 2026-09-20
- 모델 호출: 0
- 비교 대상: ADR-0473 `loop4-qwen::run-002` 저장 궤적 대 ADR-0474 `double-harness-v1` rev-035
- MAIN·서비스 배선: 변경 없음(`document-navigation-v1` 유지)

## 결론

분기 조건은 **"새 경로가 원문을 못 찾음"**으로 판정한다. 12문항 중 결정 조문이 하나라도
새 경로의 검색·위임 후보에 나타난 문항은 4건뿐이고, 실제 원문을 읽은 문항은 2건뿐이다.
완전하게 필요한 원문을 읽은 것은 `cm-003` 한 건이다. 반대로 이전 루프는 11/12에서 필요한
조문 전체를 카드로 제시했다.

따라서 다음 후보는 ADR-0473의 탐색·조문 선택·답변 방식을 복구하고, 더블하네스 장부는
서버가 옆에서 기록하는 sidecar로만 남기는 구조가 맞다. 근거 고정 후 작성·검토만 떼는
소실험은 현재 우선순위가 아니다. 51문항 동시 기준군 검증 전까지 서비스는 바꾸지 않는다.

## 판정 방법

고정 기준답의 `decisive_source_ids`를 사후 감사 키로만 사용했다. 제품 호출에는 넣지 않았다.

- 이전 루프 `뜸`: `shown_source_ids`에 포함
- 이전 루프 `근거`: `evidence_source_ids`에 포함
- 새 경로 `뜸`: SQLite observation 결과나 그 결과의 불투명 handle identity가 결정 조문을 가리킴
- 새 경로 `읽음`: `observation_evidence → evidence_unit.source_id`가 결정 조문을 가리킴
- `x/y`: 필요한 결정 조문 y개 중 확인된 x개

정본 입력은 ADR-0474 `artifacts/frozen-inputs.json`, 이전 궤적은 ADR-0473
`artifacts/loop-results.json`, 새 궤적은 ADR-0474 `artifacts/journals/*/journal.sqlite`와
`artifacts/live-results.json`이다.

## "전송 실패" 정정

`cm-008`, `cm-024`, `cm-051`은 네트워크 실패가 아니다. 세 사례 모두 OpenRouter의 HTTP 응답과
사용량 영수증이 저장됐고, 최초 출력과 내부 수리 출력이 연속해서 로컬 JSON Schema 검증을
통과하지 못했다.

| 사례 | 실제 오류 | 물리 호출 / 장부 시도 |
|---|---|---:|
| cm-008 | 허용된 tool action union에 맞지 않는 `read_node` action | 7 / 6 |
| cm-024 | `updates`가 `minItems`를 어긴 빈 배열 | 3 / 2 |
| cm-051 | `updates`가 `minItems`를 어긴 빈 배열 | 5 / 4 |

rev-035 어댑터가 이 형식 오류를 일반 `ExperimentCallError`로 올렸고, `ModelGateway`가 일반 예외를
`TransportError: single-send adapter failed`로 다시 감쌌다. 실제 네트워크 오류의 증거는 없다.

## 어댑터 결함과 수정

과거 `OpenRouterWire`는 게이트웨이 요청의 첫 system message와 마지막 user message만 꺼내
`OpenRouterProxyClient.generate()`로 새 요청을 만들었다. 그 과정에서 이전 message, `stream`,
`chat_template_kwargs`, 정확한 `response_format` 등 호출 설정이 유실됐다. 또한 클라이언트 내부
수리 6회가 장부 밖에서 발생하여 물리 호출 76회와 장부 model attempt 70회가 달라졌다.

수정 후 계약은 다음과 같다.

1. `messages`와 게이트웨이 생성 설정을 그대로 전달하고, provider·reasoning·usage 정책 필드만
   고정한다.
2. 한 번의 `send_once`는 정확히 한 번의 HTTP 호출만 한다. 형식 수리는 `ModelGateway`가 새
   model attempt로 기록한 뒤 다시 호출한다.
3. 네트워크 무응답은 `TransportError`, 응답을 받은 뒤의 형식 위반은 `ProposalError`, provider
   정책 위반은 `ContractError`로 분리한다.
4. 실패 사례도 `client.calls`를 물리 호출 정본으로 사용할 수 있다.

과거 rev-035 snapshot과 원시 산출물은 재현성을 위해 수정하지 않았다.
