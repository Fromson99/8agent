# AD 명령과 여러 턴 사용

모든 아래 작업은 단독 `[AD모드 시작]` 후 같은 chatId에서만 처리한다. `/chat`의 신뢰된 플랫폼 정보 또는 기존 코드서빙 접근 권한이 필요하다. 실수로 켠 경우 `[AD모드 종료]`를 입력한다.

| 목적 | 입력 예시 | 다음 턴 |
|---|---|---|
| 도움말 | 도움말 | 현재 상태 |
| 사건 목록 | shortcut 전체 보여줘 | 다음 / 이전 |
| 위키 목록/검색 | 위키 목록 / 위키 검색 상장 | 2번 자세히 |
| 전체 내부 데이터 | 전체 테이블 | 1번 열어 / 테이블 sw_fact |
| 스키마 | 전체 테이블 → 1번 자세히 | 열 이름·타입 확인 |
| 긴 본문 | 2번 자세히 | 계속 (끝까지 반복) |
| 사건 하위 기록 | shortcut 목록 → 2번 사실 보여줘 | 1번 자세히 |
| 발언/도구/갈래 | 2번 발언 보여줘 / 2번 도구 보여줘 / 2번 갈래 보여줘 | 다음 |
| 여러 항목 선택 | 2번과 5번 선택 | 선택한 것 승인 |
| 이전 표 지정 | 첫 표 2번 선택 / V표ID:21 자세히 | 선택 내용 |
| 승인/반려 | 2번 승인 / 선택한 것 반려 | 위키 목록 |
| 위키 게시 | 1번 게시 | 근거가 변경됐으면 오류 확인 |
| 단계별 수정 | 2번 수정 | 제목을 새 제목으로 수정 |
| 정확한 필드 수정 | /edit topic 새 주제 | /edit unresolved ["시행일 확인 필요"] |
| 사실 수정 | 사실 표 → 1번 선택 | /edit value {"kind":"duration","value":12,"unit":"month"} |
| 구조화 주장/절차 | /edit claims [구조화 JSON] | 스키마 오류가 나면 원인대로 수정 |
| 버리기 | 2번 버려 / 선택한 것 삭제 | 휴지통 |
| 복구 | 방금 버린 것 복구 | 휴지통 → 1번 복구 |
| 즉시 실행 | 야간작업 돌리기 | 진행상황 알려줘 |
| 리포트 | 야간작업 리포트 줘 | 1번 자세히 → 계속 |
| 실행 중단/재개 | 작업 중지 / 작업 재개 | 진행상황 |
| 작업 취소/재시도 | 작업 취소 / 실패 작업 재시도 | 실패 내용 |
| 다른 작업 선택 | 작업 목록 → 2번 작업 상태 | 2번 작업 중지 |
| 일회 예약 | 야간작업 시작 예약 저녁 12시 | 예약 목록 |
| 매일 예약 | 매일 자정 예약 | 1번 자세히 |
| 명시 일시 | 야간작업 예약 2026-10-08 00:00 | 표시된 한국시간 확인 |
| 모호한 시간 | 야간작업 예약 12시 | 자정 / 정오 |
| 예약 취소 | 예약 목록 → 1번 예약 취소 | 예약 목록 |
| 오류 | 오류 목록 | 1번 자세히 → 계속 |
| 기능별 ON/OFF | shortcut 꺼 / 위키 꺼 / 둘 다 꺼 | 현재 상태 |
| 다시 사용 | shortcut 켜 / 위키 켜 / 둘 다 켜 | 작업 재개 (자동 재개 안 함) |
| 일반 답변 복귀 | [AD모드 종료] | 일반 법률 질문 |

번호는 현재 표 전체의 번호다. 새 목록을 열면 이전 선택은 해제된다. 여러 표의 번호를 섞지 않으려면 V표ID:행을 쓴다. 표는 다른 대화에 이식하지 않는다. 선택 후 다른 작업자가 고쳤다면 AD_CONFLICT가 표시되며 새 목록에서 다시 선택한다.

실패 예: 법률 질문을 AD 안에 입력 → AD_COMMAND, 존재하지 않는 행 → AD_TARGET, 타 공간 ID → AD_SCOPE, 원문 필드 직접 변경 → AD_IMMUTABLE, 잘못된 claims 값 → AD_SCHEMA, 동일 요청 번호에 다른 명령 → AD_IDEMPOTENCY, 원본이 작업 대기 중 변경 → AD_INPUT_CHANGED. 모두 관리 기록과 응답에서 추적한다.

지원하지 않는 표현은 추측해 변경하지 않는다. 도움말에 나온 표현이나 정확한 필드 입력으로 다시 요청한다. 원문 법률 파일·배포 설정·모델·다른 시스템 테이블 편집은 이 관리 모드의 대상이 아니다.
