# 확장성·유지보수성·실제 문제 해결을 KPI로 설명하기

확인일: 2026-09-27. 사용자가 요청한 유추를 포함하되 **기록에서 계산한 값**, **그 값으로 설명할 수 있는 역량**, **실측이 없는 가정별 계산**을 구분한다. 가정 시나리오는 현재 시스템이 달성한 절감률이나 통계적 예상 범위가 아니다.

## 1. 측정 가능한 대리 KPI

확장성·유지보수성은 추상적인 특성이지만, 업무 추가에 필요한 변경량, 오류 원인까지 연결되는 기록, 수정 후 보존한 기존 기능, 원문 누락의 해소 정도로 관찰할 수 있다.

| 영역 | KPI | 기록에서 계산한 값 | 설명할 수 있는 가치 |
|---|---|---|---|
| 유지보수성 | 실행 입력 계보 확인률 | 61/61 = 100% | 각 선별 실행이 어떤 부모 원문 회수 결과를 사용했는지 파일과 해시로 확인 가능 |
| 유지보수성 | 준비된 근거의 출처 필드 보유율 | 437/437 = 100% | 근거를 문서·원문 위치·데이터 세대·해시로 연결할 수 있음 |
| 유지보수성 | 선택 원문의 패킷 연결률 | 373/373 = 100% | 선택 결과가 준비된 근거 패킷 어디에 들어갔는지 연결 가능 |
| 변경 통제 | 핵심 참조 결과 변경 범위 | 675/145,866 = 0.463% | 전체를 비교하면서 목적에 해당하는 연결 결과의 변화량을 좁혀 확인 |
| 변경 통제 | 기존 EXACT 연결 손실 | 0건 | 새 연결을 개선하면서 기존 EXACT를 미해소로 떨어뜨리지 않음 |
| 문제 해결 | 필수 원문 누락 해소 | 5개 → 0개 | 고정 평가의 회수 단계에서 빠졌던 필수 원문을 확보 |
| 문제 해결 | 선별 누락 복구 | 13개 → 10개, 23.1% 감소 | 선별 이후 추가 확인이 실제 필수 근거 3개를 회복 |
| 확장 기반 | 재사용할 자료 규모 | 159문서·33,443개 검색 단위·5,539,572건 용어 출현 연결 | 업무마다 다시 만들지 않고 같은 원문·검색 기반을 호출할 수 있는 구조적 기반 |

마지막 행은 규모·재사용 가능성의 근거다. 이미 신규 업무 구축비나 실제 재사용률이 측정되었다는 뜻은 아니다.

## 2. 유지보수성: 실패 원인을 원문까지 추적할 수 있는가

### 실행 입력 계보 확인률 100%

ADR-0517의 기존 문항별 결과 파일 61개에서 `input_parent_path`와 `input_parent_sha256`을 읽었다. 부모 파일의 존재와 실제 SHA-256을 대조했으며 61개 모두 일치했다.

실패 1건도 분모에 포함했다. 따라서 성공 사례만 추적할 수 있는지를 본 것이 아니라, 실패를 포함해 어느 입력에서 실행했는지 확인했다.

**발표 문장:** ‘61건의 실행 모두 사용한 입력 원본을 해시로 확인할 수 있어, 결과와 실패를 동일 입력까지 추적할 수 있었다.’

이 KPI는 입력 계보 확인이다. 모델을 재실행하면 같은 답을 얻는다는 의미의 완전 재현율이나 현행 전체 서비스 감사율이 아니다.

### 준비된 근거 출처 필드 보유율 100%

같은 실험에서 패킷이 생성된 60개 실행의 근거를 실행 내 evidence ID로 중복 제거했다. 총 437개 근거 항목 모두 다음 정보를 보유했다.

- 원문 ID와 문서 ID.
- 문서 내 구조 단위 ID.
- 데이터 세대 ID.
- 원문 산출물 해시와 텍스트 해시.

437은 실행별 근거 항목의 합계다. 같은 원문이 여러 질문에 쓰이면 여러 번 집계될 수 있으며, 전역 고유 조문 수는 아니다. 여기서는 필드의 존재를 확인했으며 개별 텍스트 해시를 모두 재계산하거나 내용의 정확성을 재심사하지 않았다.

선택된 논리 원문은 실행별 합계 373개이고 모두 패킷 내 source ID와 연결되었다. 한 논리 원문이 여러 근거 단위가 될 수 있으므로 437과 373은 다른 분모다.

**발표 문장:** ‘준비된 원문 근거 437건에 출처·위치·버전·해시를 연결해, 잘못된 결과를 원문 단위로 조사할 수 있게 했다.’

이는 실제 최종 답변에 인용된 근거의 비율이나 모델에 실제 전달된 비율이 아니다. 해당 실험은 최종 답변을 실행하지 않았다.

## 3. 변경 통제: 개선이 기존 연결을 얼마나 흔들었는가

ADR-0545 diff 결과의 공통 참조 키는 145,866개다. 같은 키의 비교 결과는 다음과 같다.

| 구분 | 건수 |
|---|---:|
| 동일 | 144,640 |
| 대상 또는 해소 결과 변경 | 675 |
| 근거 라벨만 변경 | 171 |
| 힌트 변경 | 380 |
| 합계 | 145,866 |

핵심 연결 결과 변경 범위 = 675 ÷ 145,866 × 100 = 0.4628%.

미해소→EXACT 개선은 675건이고, 기존 EXACT 손실은 0건으로 기록되어 있다. ‘기존 EXACT가 모두 의미적으로 옳다’는 뜻은 아니다. 기존 오류가 보존된 사례도 있다.

기준에만 있는 키 3개와 후보에만 있는 키 39개는 공통키 분모에서 제외되어 있으며 별도 차이로 기록된다. 라벨·힌트 변경도 있으므로 ‘0.46% 외에는 아무것도 바뀌지 않았다’고 쓰지 않는다.

**발표 문장:** ‘참조 수정 후보에서 675건의 미해소 연결을 개선하고 기존 EXACT 손실 0건을 확인했다. 공통 참조 키 가운데 핵심 연결 결과의 변경 범위는 0.46%였다.’

전체를 재컴파일·비교한 결과이므로, 계산량이나 재구축 비용이 99.54% 줄었다고 해석하지 않는다. 모델 품질이나 현장 배포 성과도 아니다.

## 4. 문제 해결: 어떤 실패를 실제로 줄였는가

### 문제 A — 관련 원문이 검색 과정에서 빠짐

관찰: 서로 다른 검색 경로 중 하나를 선택할 때 다른 경로의 필수 원문을 잃었다.

변경: 전역 검색과 법령별 검색에서 선택한 원문을 합쳐 보존하고 전체 구간을 확보했다.

결과: 61문항의 필수 원문 90개 중 전문 확보가 85개에서 90개로 증가했다. 평가상 누락은 5개에서 0개, 원문 확보율은 94.4%에서 100%다.

업무적 해석: 내규 비교·상충 검토의 출발점인 ‘필요한 비교 근거를 확보하는 능력’을 뒷받침한다. 실제 내규 문제를 100% 발견했다는 지표는 아니다.

### 문제 B — 넓게 찾은 자료를 줄이다 중요한 근거가 사라짐

관찰: 최초 선별에서 필수 원문 90개 중 13개가 빠졌다.

변경: 선택된 원문의 발췌와 보류 후보를 추가로 확인했다.

결과: 3개를 복구해 누락은 13개에서 10개로 감소했다. 누락 감소율은 23.1%, 최종 보존은 80/90개다. 평균 원문 후보는 229.6개에서 6.1개로 줄었지만 사전 무손실 기준에는 미달했다.

업무적 해석: 단계별 원인 진단과 복구 장치의 관측 결과다. 상충 탐지율·최종 답변 정확도·업무시간 절감률로 대체할 수 없다.

## 5. 확장성: 실측이 없을 때 계산 가능한 경제성 시나리오

목표는 같은 검색 기반에 내규–외규 비교와 내규 상충 검토를 연결하는 것이다. 실제 두 업무의 구현 공수 기록은 없으므로 아래는 **가정별 산술 예시**다.

### 계산 구조

- B: 두 업무가 공유할 수 있는 지식·검색·근거 관리 기반의 구축 작업량.
- W1, W2: 각 업무에 고유한 비교·결과·검토 기능의 작업량.
- I: 공유 기반으로 연결하면서 추가되는 통합·회귀 검사 작업량.
- 각각 독립 구축: 2B + W1 + W2.
- 기반 공유: B + W1 + W2 + I.
- 절감률: (B − I) ÷ (2B + W1 + W2).

공유 기반 자체의 중복 구축을 피하는 계산이다. 현재 이미 만든 기반의 비용을 제외한 신규 한계비용과 전체 신규 구축비를 섞지 않는다. 독립 구축 시 실제로는 기성 검색 서비스를 사용할 수 있다면 B가 작아지므로 절감도 줄어든다.

### 가정별 계산

각 업무를 독립 구축하는 작업량을 각각 100단위로 놓는다. 두 업무의 공통 기반은 같은 규모이며, 공유에 따른 추가 통합·검증 I는 총 20단위로 가정한다.

| 가정 | 독립 업무당 공통 기반 B | 업무별 고유 기능 W | 두 업무 독립 구축 | 공유 구축 | 작업량 감소 |
|---|---:|---:|---:|---:|---:|
| 공통 부분이 작은 경우 | 40 | 각 60 | 200 | 180 | 10% |
| 중간 계산 사례 | 60 | 각 40 | 200 | 160 | 20% |
| 공통 부분이 큰 경우 | 80 | 각 20 | 200 | 140 | 30% |

숫자는 실측 보정된 예측값이 아니다. 10~30%는 이 세 가정의 계산 결과이며 신뢰구간이나 실제 기대 범위가 아니다. 작업량 단위는 인일·시간·금액으로 환산하지 않았다.

**말할 수 있는 표현:** ‘공통 기반 비중과 추가 통합비를 가정하면, 두 업무를 독립 구축할 때보다 작업량 10~30% 감소 시나리오를 계산할 수 있다. 실제 절감률은 업무별 구현 공수로 검증한다.’

손익분기는 I=B다. 추가 통합·회귀 검사·운영 복잡성의 작업량이 공유로 피한 중복 기반 구축보다 커지면 효과가 없다. 새 업무에서 필요한 자료·모델·접근 계약이 크게 달라질수록 이 위험이 커진다.

현재 기반을 이미 구축한 이후의 새 업무 추가 비용은 W새업무 + I새업무다. 새로 독립 구축하는 비용 B새업무 + W새업무와 비교할 수 있지만, B와 W가 실측되어야 절감률을 성과로 발표할 수 있다.

## 6. 유지보수 시간: 기록이 있을 때 무엇이 줄어들 수 있는가

유지보수 전체 시간은 원인 파악, 수정, 회귀 검사, 반영으로 나뉜다. 이번 기록은 원인 파악을 도울 수 있다는 근거이며, 이후 모든 단계가 같은 비율로 줄어든다는 근거는 아니다.

시간 절감 시나리오는 다음과 같이 계산한다.

- f: 기존 전체 유지보수 시간에서 원인 파악이 차지하는 비율.
- r: 원인 파악 단계에서 줄어드는 시간 비율.
- o: 추적 기록·관리로 늘어나는 시간을 기존 전체 시간으로 나눈 값.
- 전체 순 시간 감소율 = f × r − o.

원인 파악 단계의 단축 r=60%, 추가 관리 o=5%를 가정하면 다음과 같다.

| 원인 파악 비중 f | 계산 | 전체 순 시간 감소 |
|---|---|---:|
| 25% | 0.25×0.60−0.05 | 10% |
| 50% | 0.50×0.60−0.05 | 25% |
| 75% | 0.75×0.60−0.05 | 40% |

이 역시 설명용 가정이다. 61/61 계보 확인이나 437/437 출처 필드 보유가 원인 파악 60% 단축을 증명하지 않는다. 추적 기록이 부정확하거나 오래되면 개선이 없거나 추가 시간이 들 수 있다.

**발표에서 권장하는 현재 표현:** ‘오류 원인을 원문과 실행 입력까지 추적할 수 있게 했다. 유지보수 시간 절감은 향후 같은 유형의 장애에서 단계별 소요시간을 측정한다.’

추정 슬라이드가 필요하면 ‘가정: 원인 파악 비중 50%, 해당 단계 60% 단축, 관리 부담 5% → 전체 순 시간 25% 감소 시나리오’라고 가정을 같은 화면에 표시한다. ‘유지보수 시간 25% 절감 달성’이라고 쓰지 않는다.

## 7. 실제 업무 가치 측정을 위한 최소 기록

| 영역 | 앞으로 남길 것 | 최종 KPI |
|---|---|---|
| 확장성 | 새 업무의 공통 기반 변경·업무 고유 기능·통합·회귀 검사 사람시간 | 독립 구축 기준 대비 신규 업무 추가 작업량 감소 |
| 유지보수성 | 장애 발견·원인 특정·수정 완료·검사 완료·반영 시각 | 원인 특정 시간과 전체 복구 시간의 중앙값·p95 |
| 변경 안정성 | 기존 성공 사례·변경 후 결과·새 결함·롤백 | 기존 성공 회귀율·변경 실패율 |
| 내규–외규 비교 | 사람이 확인한 요구·미반영 사항·발견·기각·검토시간 | 미반영 탐지 재현율·정밀도·사람시간 절감 |
| 내규 상충 | 확인된 실제 상충·해소 근거·오탐·검토시간 | 상충 탐지 재현율·정밀도·유효 발견당 검토시간 |

신규 업무 수, API 개수, 모듈 수만으로 재사용률을 산정하지 않는다. 비교 코드가 같은 원문 저장소를 쓰더라도 새로운 권한·범위·기준일·상태 계약의 검증 비용이 발생한다.

## 8. 포트폴리오 권장 문안

**유지보수성:** ‘실행 61건의 입력 원본을 해시로 확인하고, 준비된 근거 437건에 출처·위치·버전 정보를 연결했다. 오류가 발생하면 검색·선별·근거 구성 중 어느 단계에서 문제가 생겼는지 조사할 수 있게 했다.’

**변경 통제:** ‘참조 수정 후보에서 미해소 연결 675건을 개선하고 기존 EXACT 손실 0건을 확인했다. 공통 참조 키의 핵심 연결 결과 변경 범위는 0.46%였다.’

**문제 해결:** ‘고정 평가에서 필수 원문 누락을 5개에서 0개로 줄였고, 후속 선별에서는 추가 확인으로 누락 13개 중 3개를 복구했다. 회수와 선별의 손실을 나눠 분석하고 개선했다.’

**확장성:** ‘동일한 원문·용어·참조·검색 기반에 내규–외규 비교와 내규 상충 검토를 연결하도록 설계했다. 공통 기반과 업무별 기능을 분리해 새 업무에 필요한 추가 작업을 줄이는 구조다. 구축 작업량 절감은 가정별 10~30% 계산 시나리오이며 실측 검증이 필요하다.’
