# AGENT KPI — 확인된 성과와 업무 가치

확인일: 2026-09-27. 기존 실험 결과의 문항별 수치를 다시 합산하고, 로컬 활성 포인터가 선택한 데이터 세대의 SQLite 행 수를 읽기 전용으로 집계했다. 새 모델 호출·평가·재채점·현장 실행은 하지 않았다.

현재 확인된 강점은 **필수 근거를 확보하는 검색 구조, 대량 후보의 선별, 누락 복구, 재사용할 지식 기반의 규모**다. 내규–외규 비교와 내규 상충 검토의 시간 절감·발견률·ROI는 아직 측정되지 않았다.

## 1. 발표에 사용할 핵심 숫자

| 지표 | 확인한 값 | 보여주는 가치 | 반드시 붙일 범위 |
|---|---|---|---|

K01과 K02는 같은 결과의 다른 집계이며 독립적인 두 개선으로 더하지 않는다. 97.34% 후보 축소와 90/90 확보를 합쳐 ‘후단에서도 100% 품질 유지’라고 쓰지 않는다.

## 2. 가장 강한 검색 KPI: 무엇을 성공으로 센 것인가

ADR-0513은 전역 검색과 문서별 검색에서 선택한 원문을 합쳐 보존하는 실험이다. 고정된 61문항에 필요한 평가 원문 90개 중 전문을 확보한 수가 85개에서 90개로 늘었다.

- 기준: 85 ÷ 90 × 100 = 94.44%.
- 후보: 90 ÷ 90 × 100 = 100%.
- 개선: 5.56%p.
- 평가상 누락: 5개 → 0개.
- 질문별 필요한 원문 전부 확보: 56개 질문 → 61개 질문.

### 사용 문장

> 공개 법률·규정 145문서 기반의 고정 61문항에서, 필수 원문 90개의 전문 확보율을 94.4%에서 100%로 높였다.

작은 각주: ‘기존 노출 문항의 원문 회수 실험. 답변 정확도·독립 신규 질문·GENOS 현장 성능과 구분.’

### 함께 설명할 비용과 한계

더 넓게 확보하면서 평균 원문 후보는 159.97개에서 229.56개로 늘었다. 평균 원문 문자량도 약 25.9만 자에서 57.8만 자로 늘어, 후단 선별이 필요해졌다.

원문 회수 p50은 기록상 13.12초와 59.51초, p95는 64.36초와 129.04초다. 후보가 3 worker 동시 부하에서 측정되어 부모 직렬 실행과 환경이 달라, 이 차이를 동일 조건의 속도 성능 비교로 사용하지 않는다. 사용자 전체 응답 시간도 아니다.

기존 모델 검색 계획을 재사용했으므로 이 재생 단계의 신규 모델 호출은 0회였다. 검색 시스템 전체가 모델 호출 없이 동작하거나 운영 비용이 0이라는 뜻은 아니다.

## 3. 선별 KPI: 규모를 줄인 성과와 근거 손실을 함께 표시

ADR-0517은 위 회수 풀을 받아 제목·회수 경로로 선별하고, 발췌·보류 목록을 다시 확인해 근거를 추가하는 실험이다.

| 항목 | 값 |
|---|---:|
| 전체 시도 질문 | 61 |
| 선별 전 평균 원문 수 | 229.5574 |
| 최종 평균 원문 수 | 6.1148 |
| 최종 원문 수 중앙값 / p95 / 최대 | 5 / 12 / 18 |
| 원문 수 감소율 | 97.3363% |
| 최초 필수 원문 보존 | 77/90 = 85.56% |
| 복구 후 필수 원문 보존 | 80/90 = 88.89% |
| 복구한 필수 원문 | 3 |
| 최초 누락 대비 복구율 | 3/13 = 23.08% |
| 최종 필수 원문을 모두 보존한 질문 | 51/61 = 83.61% |
| 오류 질문 | 1/61 |

최종 평균은 오류가 있는 전체 61개 시도를 포함한다. 성공한 질문만 골라 계산한 값이 아니다.

### 사용 문장

> 선별 실험에서 최종 원문 후보를 평균 229.6개에서 6.1개로 줄였고, 추가 확인으로 필수 근거 3개를 복구했다. 최종 필수 원문 보존은 80/90개였다.

실험은 사전 90/90·오류 0 등의 기준에 미달해 Rejected다. 이후 사용자 지시로 관련 알고리즘이 로컬 경로에 연결된 것은 별도 상태이며 이 판정을 Accepted로 바꾸지 않는다. 원문 후보 수의 감소를 입력 토큰·비용·현업 검토 시간의 동일 비율 절감으로 해석하지 않는다.

## 5. 지식 기반의 규모: 현재 선택된 로컬 세대에서 직접 집계

| 데이터 | 행 수 | 올바른 의미 |

| 원문 블록 | 308,795 | 저장된 본문 블록 수 |
| 원문 검색 단위 | 33,443 | 검색 색인의 source 수. 고유 법조문 수와 동일하지 않음 |

### 사용 문장

> 로컬 선택 데이터 세대에서 159문서와 33,443개 원문 검색 단위를 구성하고, 약 554만 건의 용어 출현 연결·8,533건의 정의·약 14.7만 건의 명시 참조 기록을 검색 기반으로 관리한다.

원문 159문서와 외부 모델에 승인된 공개 145문서는 다른 범위다. 나머지 14개를 모두 실제 내부 문서라고 추정하지 않는다. 이 집계는 GENOS 현장 데이터 규모나 업무 적용 성과를 뜻하지 않는다.

용어 색인에는 253,324개 term 행, 48,101개 edge 행도 있지만 이를 곧바로 고유 개념 수나 검증 완료 지식 수로 홍보하지 않는다. 본문에서는 의미가 명확한 출현·정의·참조 수를 우선 사용한다.

별도 공개 사전 수집 스냅샷에는 출처별 설명 항목 4,747건(3,029+1,718)이 있다. 이는 기관 간 중복 제거 후 고유 개념 수도, 현재 활성 RAG에 모두 반영된 수치도 아니다.

## 6. 지식 유지보수 역량을 보여주는 추가 수치

ADR-0545의 참조 해소 개선 후보에서는 미해소 참조 675건이 EXACT 상태로 바뀌었고, 기준선의 기존 EXACT 손실은 0건이었다. 새로운 EXACT 가운데 서로 다른 70건을 에이전트가 원문과 대조했으며 오연결로 분류한 건은 0건, 구법 버전 주의는 3건이었다.

이 결과는 ‘기존 연결을 보존하며 새 연결을 개선하는 능력’을 보여준다. 그러나 사람 법률 검토도 아니고 전수 연결 정확도 100%도 아니다. 같은 법 선행사 문제 등 기존 결함이 남아 있다. 후보 상태는 Proposed, decision_eligible=false, MAIN 미반영이다. 후속 검색·답변 개선율은 아직 확인되지 않았다.

## 7. 두 업무 워크플로우의 KPI: 다음에 실제로 측정할 값

아래는 KPI 정의이며 달성 수치나 임의 목표를 넣지 않았다. 측정할 때 문서군·기준일·검토자·평가 조건을 고정한다.

| 우선순위 | 업무 KPI | 계산과 집계 단위 | 업무 가치 |
|---|---|---|---|
| 1 | 검토자 순 작업시간 절감률 | (수작업 사람시간−AI 활용 사람시간) ÷ 수작업 사람시간. 같은 품질의 완료 결과 기준 | 인력 생산성 |
| 2 | 외규 요구 반영·누락 탐지 재현율 | 사람이 확인한 실제 미반영 요구 중 발견한 수 ÷ 실제 미반영 요구 수 | 빠뜨린 요구 발견 |
| 3 | 내규 상충 탐지 재현율 | 사람이 확인한 실제 상충 사례 중 발견한 수 ÷ 실제 상충 사례 수 | 업무 위험 발견 |
| 4 | 검토 후보 정밀도 | 현업이 유효하다고 확인한 후보 ÷ 제시한 후보 | 오탐 검토 부담 감소 |
| 5 | 결과당 검토 부담 | 유효 발견 건당 확인·기각·추가 조사에 쓴 사람시간 | 발견 가치 대비 비용 |
| 6 | 처리 완결성 | 계획된 전체 항목 중 결과·보류·실패 상태가 기록된 항목 비율 | 조사 누락 관리. 적합률과 구분 |
| 7 | 근거 추적 완전성 | 양쪽 원문·버전·적용 조건을 모두 연결한 결과 ÷ 전체 비교 결과 | 검토·감사 가능성 |
| 8 | 개정 영향 확인 시간 | 새 버전 확정부터 영향 검토 완료까지의 경과시간 | 변경 대응 속도 |

사람시간과 경과시간을 분리한다. AI 실행을 기다리는 동안 다른 업무를 할 수 있다면 그 대기 전부를 사람시간으로 세지 않는다. 반대로 오탐 확인·수정·보류 해소·재작업은 AI 활용 사람시간에 포함한다.

전체 실제 상충의 정답 목록이 없으면 전사 상충 재현율은 계산할 수 없다. 별도로 확정한 평가 사례에서의 재현율과 운영에서 확인한 유효 발견 건수를 구분한다. 사람 검토가 안 끝난 후보를 유효 발견으로 세지 않는다.

## 8. 경영 가치로 연결하는 산식

최종 대표 KPI는 **품질을 유지한 검토자 순 작업시간 절감**과 **검증된 누락·상충 발견**을 함께 쓰는 것이 적합하다. 시간만 줄이고 놓치는 문제가 늘면 업무 가치는 떨어진다.

- 월 절감 사람시간 = 월 검토 건수 × (기존 건당 사람시간−AI 활용 건당 사람시간).
- 월 인건비 환산 여력 = 월 절감 사람시간 × 시간당 총인건비.
- 월 순 경제효과 = 인건비 환산 여력−추가 모델·서버·라이선스·운영 비용.
- 단순 회수기간 = 초기 구축·전환 비용 ÷ 양수인 월 순 경제효과.

단위는 검토 건/월 × 시간/건 = 시간/월, 시간/월 × 금액/시간 = 금액/월이다. 월 순 효과가 0 이하면 이 식으로 양의 회수기간을 제시하지 않는다. 절감된 시간은 처리 여력이며 실제 인원 감축이나 현금 절감과 동일하지 않다. 벌금·손실 예방액은 확률·규모 근거 없이 추정하지 않는다.

현재 월 건수·수작업 시간·AI 활용 후 사람시간·업무 품질·현장 운영비가 없어 금액 ROI는 미산정이다.

## 9. 발표용 한 장 구성

제목: **필요한 근거를 확보하고, 검토 대상을 좁히며, 재사용 가능한 지식 기반을 구축했다.**

1. **검색 근거 확보:** 고정 평가에서 필수 원문 85/90 → 90/90.
2. **후단 후보 선별:** 평균 원문 229.6 → 6.1개, 필수 원문 80/90 보존.
3. **누락 복구:** 추가 확인으로 필수 원문 3개 회복.
