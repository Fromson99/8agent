# 에이전트 판단 하네스 v5 개발·MAIN 연결 확인

2026-09-22 · 구현자 자체 검토 · 모델 성능 인증 아님

사용자가 요청한 판단 능력 보강과 실제 실행 연결을 구현했다. 명시 조건 추출·원문 설명·구체적 오류 교정 능력을 활용하되, 질문 요구·원문·주장·검토·행동을 서로 대조하도록 만들었다. 서버는 법률 의미의 정답을 만들어 내지 않으며, LLM의 관련성 선택을 법적 정답 승인으로 바꾸지 않는다.

## 구현 결과

|요청·발견한 문제|변경|확인|
|---|---|---|
|과거 개발 기능 누락|ADR-0505에 결속된 요청 요구 추적·번호 선택·원문 선택·직접 참조 개선을 작업 코드 v5로 이식. 실험용 외부 반출 예외는 이식하지 않음|v5는 운영 모듈만 참조, v2~v4 보존|
|한 글자 요구·이유|비앵커 정규식 `pattern: \\S` 제거, 의미 문구 길이·공백 검사, 오류 필드별 수정 안내|한 글자·공백 거절. provider 문법이 원인이었다는 인과 인증은 아님|
|판단과 행동의 불일치|빈 CONTINUE·DRAFT/CLARIFY와 도구 실행의 충돌·누락 사실 없는 CLARIFY 차단|실행 전 상태 불변 검사|

|계획 재작성으로 반복 은폐|계획 문구 재작성을 진전으로 계산하지 않음|동일 근거·동일 행동에서 progress key 불변|
|유사 개념·일반 규칙/특례·AND/OR·예외·확실성|검토 출처마다 원문과 초안의 실제 인용 및 6개 차원 대조|인용 위조·출처 누락·CHANGED/UNCERTAIN인데 SUPPORTED 거절|
|자기검토 모순|요구 전부 해결과 전체 질문 미해결의 충돌, 재작성 필요인데 연결 주장 전부 SUPPORTED인 충돌 차단|지원된 부분 답변 유지, 미확인 요구 노출|
|기존 읽기 기능 퇴행 위험|조문 전체/부분 범위 구분, 페이지 결속, 양방향 직접 참조·비재귀 자동 읽기 유지|14개 원문·연결 회귀 검사 포함|
|CLI 연결 누락|`pipeline run`에서 HTTP와 동일한 요청별 Coordinator/StageRunner 실행|모의 데이터로 CLI 결과와 COMPLETED 원장 확인|
|고정 릴리스의 누락 의존성|platform 패키지 초기화 의존성을 함께 해시 결속, 불변 코드 root와 가변 workspace/runtime root 분리|작업 폴더 검사와 고정 릴리스 검사를 별도로 수행|

원문에 명시된 조건을 대조하도록 강화했지만, 같은 모델이 조건을 잘못 이해한 채 초안과 검토 모두 통과시킬 가능성은 남는다. 더 많은 검토 필드가 의미적 정확성을 보장하지 않는다. 인용은 근거 확인용 증거이며 전체 원문을 대신하지 않는다.

## 검사와 범위

최종 관련 검사 **148개 통과**. 새 v5, 번호 매핑, 조문 읽기·직접 참조, 기존 v3/v4, 공유 v1 계약을 포함한다. HTTP 모의 모델은 기존 여섯 단계 호출에서 요구→주장→검토를 완료한다. 모델 단계나 평가자 호출을 새로 추가하지 않았다. 출력 토큰 상한 6,400과 호출/시간/반복 상한은 설정값이며 실사용 지연·비용 측정치가 아니다.

변경 전 코드로도 실패가 재현되는 v1 검사 2개(말미 괄호 문맥을 한 질문으로 병합, 원문 쟁점과 질문 쟁점의 자동 동일화)는 최종 검사에서 제외했다. 원질문 텍스트는 손실 없이 분할되며 v5는 배경/요구 구분을 별도로 검토한다. v5는 v1 쟁점 자동 병합 경로를 사용하지 않는다. 서로 다른 의미를 가진 쟁점을 같은 원문이라는 이유로 합치도록 바꾸지는 않았다. 폐기된 `semantic-contract-check` 프로필을 요구하는 과거 engine-host 검사도 현행 파이프라인 검증을 대신하지 않는다. 전체 저장소 모든 검사가 통과했다는 주장은 하지 않는다.

증거: [계약 검사](../../../../09_ARTIFACTS/AUDITS/legal-agent-v5-20260922/contracts.xml), [변경 전 실패 재현](../../../../09_ARTIFACTS/AUDITS/legal-agent-v5-20260922/preexisting.xml), [사용자 전환 지시](../../../../09_ARTIFACTS/AUDITS/legal-agent-v5-20260922/authorization.json). 새 Gemma 성능 실험과 GENOS 연결 시도는 하지 않았다. 실제 모델 정답률·비용·지연 개선은 미확인이다.

## 실행·모델·원복

[운영 안내](../../OPERATIONS/LEGAL_AGENT_V5.md)에 기존 HTTP/CLI 실행, GENOS 내부 모델 결속, 원장 확인과 원복 명령을 기록했다. 현재 모델 프로필은 **미결속**이므로 출처 조회는 실행 가능하지만 LLM 요청은 내부 모델 설정 후 사용할 수 있다. 실험용 OpenRouter Gemma를 비공개 질문까지 처리하는 기본 제품 모델로 자동 전환하지 않았다.

MAIN 전환은 사용자 지시의 `USER_DIRECTED_CUTOVER`, `quality_certified=false`다. Git main 병합·GENOS 배포·기존 서버 프로세스 재시작은 별도이며 이번 완료 범위에 포함되지 않는다. 데이터 세대와 원문은 유지했다.
