# 용어 학습·탐색 절차 재사용 설계 감독 검토서

## 1. 판정과 검토 범위

**구현 가능성은 조건부 타당, 제시된 산술은 타당, 실제 개선 효과·작업량 예측은 미검증이다.** 기존 탐색 도구와 명시적 세대 결속을 재사용하는 설계에는 연결 가능한 지점이 있다. 다만 보고서가 제안한 전체 시나리오는 현재 실행 가능한 기능이 아니다. 브릿지 입력, 서버 권한, 후속 질문 계약, 실행 확정·후보 원장, 절차 실행 제어를 구현·검증해야 한다.

대상 보고서가 이미 명시한 미연결 기능을 새로운 문서 오류로 세지 않았다. 최초 검토의 추가 보완점인 **빈 허용 문서 집합의 의미**는 개정 보고서 10.4절에 반영 완료됐다. 현행 `Pipeline.plan()`은 빈 목록을 전체 문서로 바꾸므로 구현·검증은 여전히 필요하다. 미적용 요청의 호출 변화도 16.2절에 반영됐다. 아래 최초 검토의 근거·발견 이력을 보존하며, 최신 문서 상태와 제한된 재검토 범위는 8절에 기록한다. 실제 누출·운영 성능을 관측한 결과가 아니다.

## 2. 직접 확인한 실행 연결

| 경로 | 확인한 사실 | 보고서 주장 판정 |
|---|---|---|
| `service.py._resolve_binding → application` | 명시 GENOS 세대, GENOS CURRENT, 로컬 릴리스 순으로 선택. 로컬 릴리스 manifest·files·데이터 manifest 해시를 검사하고 별도 패키지로 선택 코드 로드. `_APP` 캐시 존재 | 3.1·14절 타당. 파일 포인터 선택을 확인했으며 현재 가동 프로세스의 선택은 미확인 |
| 브릿지 `call_code_serving → service._normalize → app.ask` | 브릿지가 `channel/session_id/user_id/request_id`를 전송. `_normalize`는 `API_TYPE` 이외 필드를 body로 전달. `ask`는 `question/q/document_ids/use_llm`만 허용 | 10.2절의 정적 불일치 지적 타당. 현장 리비전의 실제 실패는 미확인 |
| 선택 `PIPELINE.json → Pipeline.run → stages.retrieve → Pipeline.plan → ServingNavigationAgent` | `legal-rag`는 retrieve/select/assemble/answer 순서. `navigation-loop-v1`을 선택하고 세대·스키마·엔진 해시 검사 | 기존 흐름에 붙이겠다는 제안은 연결 가능한 구조. 새로운 표현·절차 구현은 없음 |
| `glossary_assets → ReverseMatcher → NavigationSession` | 선택 릴리스는 설정의 glossary 결속 사용. 요청마다 glossary 자원과 역매칭 객체 구성. 문자열 NFKC/casefold·공백 제거 후 등록 표기 대조 | 전용 의미 연결이 현재 없다는 설명과 초기화 비용의 측정 필요성 타당 |
| `OPEN_TERM/GRAPH/LIST/READ/REFERENCES/JUDGE` | GRAPH 1~3홉 제한. 등록·발견 ID, 문서 범위, 읽은 구간을 확인. JUDGE는 읽은 문자열 안의 exact quote와 비어 있지 않은 claim 검사 | 재사용 가능. 형식 검사만으로 claim의 법적 타당성이 입증되지는 않음 |
| `NavigationAgent.retrieve → select/assemble/answer` | 매 요청 새 세션. `question_for_user=''`. 채택 원문의 ID·판단·읽은 구간·provider receipts를 하위 단계로 전달 | 3.2·8·10.2절과 일치. WAITING_FOR_FACTS와 부모 사실 재사용은 신규 계약 |
| `app.ask → contracts.write → record_feedback` | 파이프라인 반환 후 실행 파일을 최종 경로에 `open('x')`로 저장. 피드백은 실행·원문 해시를 결속한 `PROPOSED` 후보 | 10.3절의 원자적 완료·실패 원장 필요성 타당. 현재 자동 검토·재구축·승격 연결은 없음 |
| `pipeline.py glossary review → glossary_review`; 새 문서 `glossary_document_update.augment` | CLI 분기가 실제 검토 모듈을 호출. augment는 부모 사전을 새 초안으로 복사하고 정의·검토 후보를 추가하며 `canonical_approval=false`, `runtime_promoted=false` 유지 | 신규 정의에 기존 검토를 재사용하되 정의 없는 사용자 표현은 별도 계약으로 다루겠다는 7.3절 타당 |

선택 릴리스와 작업 코드의 `navigation_loop.py`를 직접 diff했다. 작업 코드에는 `term_card`의 `scope_document_id` 검사, `graph`의 범위 밖 이웃 제외, `references`의 원천 `document_id` 검사가 추가되어 있다. 선택 릴리스에는 이 추가 검사가 없다. `navigation_agent.py`의 작업 코드는 세대 manifest의 glossary를 설정보다 우선한다. 보고서 3.2절의 차이 설명은 정확하다.

현행 `Request`, `Query`, `Result`, `Answer`, `Event`, `Proposal`은 `additionalProperties=false`다. Request에는 `question/document_ids/use_llm`만 있다. 따라서 `parent_run_id`, `confirmed_facts`, 멱등성 키 또는 상위 결과 상태를 추가하는 제안은 스키마·PIPELINE 결속·API·소비자를 같이 개정해야 한다. 보고서가 이를 이미 선행 조건으로 구분한 것은 적절하다.

## 3. 발견사항과 잔여 조건

심각도는 해당 조건을 해결하지 않고 구현·운영한다고 가정했을 때의 영향이다. `문서에 반영됨`과 `구현 해결됨`을 구분한다. 이번 검토에서 보고서의 미연결 상태를 구현 완료로 오인한 중대한 과장은 발견하지 않았다.

현재 피드백 목록·실행 연결이 사용자 ACL을 이미 갖춘 것으로 판단하지 않았다. 보고서의 권한 신설 범위에는 이 소비자들도 포함되어야 한다. 구체적인 공격 가능성·현장 권한은 이번 정적 검토로 확정하지 않는다.

## 4. 시나리오의 성립 조건과 반례

| 시나리오 | 감독 판단 | 충족해야 할 관측·검사 |
|---|---|---|
| 알려진 표현 + 유효한 절차 | 조건부 타당 | 현재 세대에 해소되는 영구 ID, 적용 조건, 서버 허용 범위, 실제 읽은 근거를 거친 답변이 모두 연결돼야 함 |

이 표는 실행해 통과한 테스트 목록이 아니다. 제안 시나리오를 현재 코드·계약과 대조한 결과이며, 필요한 계약/회귀 검사로 옮길 항목이다.

## 5. 수치 원장과 독립 재계산

저장소 `.venv/bin/python`으로 아래 산식을 계산했다. 관측은 이번 검토에서 파일 내용으로 확인한 값이며 운영 실측과 구분한다. **산술이 맞는 것과 입력 가정이 현실적이라는 증거는 다르다.**

| ID·수치 | 종류·입력 | 직접 재계산 결과 | 가정 적정성·판정·필요 검증 |

`H*S-L`을 관측 지표로 만들 때는 같은 요청 모집단에서 기준과 후보를 비교해야 한다. S는 적용 요청의 평균 탐색 호출 차이, L은 전체 요청 분모의 신규 부담이어야 한다. 미적용 요청에서도 기존 탐색 호출량이 변한다면 그 효과를 추가 항으로 기록하거나 L에 포함하는 규칙을 고정해야 한다. 선택 실패·추가 질문·후속 처리·실제 전송 재시도를 빠뜨리지 않는다. 보고서는 대부분의 비용 범위를 이미 열거했지만 구현 전에 논리 호출과 실제 전송 시도의 구분이 필요하다.

계산 최소 재현식:

```python
cases = [(.20, 1, .8), (.40, 2, .5), (.60, 3, .3)]
print([round(h*s-l, 8) for h, s, l in cases])
print(.5/2, .10*2)
print(100*.10*4, 100*.10*4*20/60, 100*.30*4)
print(60/4, 30-60/4)
print(sum([2,4,5,3,4,3]), sum([3,7,9,5,7,5]), 21/5, 36/5)
print([1-.05**(1/n) for n in (20,100)])
```
