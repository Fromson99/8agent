# 설계 자기 검토

작성일: 2026-09-21. 대상: [DESIGN.md](DESIGN.md). 대상 SHA-256은 [BASELINE.json](BASELINE.json)의 `design_sha256`에 기록한다.

작성자가 구현 설계 스킬과 설계 현실성 검토 rubric을 적용해 수행한 **자기 검토**다. 독립 검토자나 새 모델 평가를 사용하지 않았다. 런타임 동작·성능·GENOS 배포를 인증하지 않는다.

## 판정

**구현 가능한 방향이나, v4 계약·저장 이행·배선 변경과 의미 품질 검증이 선행되어야 한다.** 설정이나 프롬프트만 고치는 범위를 넘는다. READ 후 이해 관찰을 넣는 것만으로 실제 법률 이해가 개선되는지는 미확인이다.

설계의 추가 위험을 반영했으며, 아래 ‘반영’은 문서 보완을 뜻한다. 코드 결함이나 운영 위험이 해결되었다는 뜻이 아니다.

## 수치 재검토

- N04–N05: 저장된 CM003 세 번째 request/response에서 compact view 59,531자, 행동 결과 43,784자, exact evidence 컨테이너 7,425자, 실제 원문 1,873자, 입력 31,857 tokens를 확인했다.
- N06: `43,784 ÷ 59,531 × 100 = 73.548235...%`, 문서의 73.55%와 일치한다. 주의 집중 효과의 크기나 인과 추정은 아니다.
- N01–N03/N07: 완료 ADR의 README와 diagnostics를 사용한다. 표본은 알려진 CM 3문항이며 반복 분산·out-of-sample 성능이 없다.
- N08–N09: 설정·코드 관측이다. 실제 평균 소비나 최적 예산이라고 해석하지 않는다.
- N10: 개선률·소요일은 미확인으로 남겼다. 비용 산식은 token당 단위와 백만 tokens 단위의 변환을 명시했다.

## 이번에 확인한 범위

기존 파일을 읽고 코드 조건과 완료 실험 입출력을 대조했다. 외부 레퍼런스의 성능 수치를 가져오지 않았다. 셸의 WSL 환경 검사, 문서 링크 확인, JSON 구문 확인, 기록한 코드·설정·활성 포인터의 전후 hash 비교만 수행했다. 이는 새 제품 테스트나 모델 실험이 아니다.

설계가 해결 대상으로 삼은 F01–F18에는 실행 확인과 정적 확인이 섞여 있으므로 모든 항목을 ‘재현된 런타임 결함 18건’이라고 요약하면 안 된다. 제시한 V01–V18은 **앞으로 수행할 검증 계획**이다.

## 남은 확인

후속 구현에서 v4 상태 reducer·저장·복구·UI까지 실제 경로를 연결해야 한다. 신규 ADR에서 Qwen 이해 진단, 입력 구성 비교, 제어기 비교, 통합 평가를 분리해야 한다. 정답률뿐 아니라 필요한 관계 누락, 잘못된 확정, 정당한 보류, 반복 비용, 초기 로딩과 동시성 영향을 확인해야 한다. GENOS 내부 모델·권한·현장 부하는 별도 미확인이다.
