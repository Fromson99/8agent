# Qwen 행동별 진단 — 기존 실행 기록 분석

2026-09-21. 새 모델 호출·재채점·제품 코드 수정 없음. ADR0489–0495의 기존 입력·반환·판정 기록을 읽은 진단이다. 대상은 외부 Qwen qwen/qwen3.5-122b-a10b, FP8, thinking off와 현재 도구/입력 구조다. 모든 LLM이나 Qwen의 일반 능력 순위로 확대하지 않는다. 구현과 입력이 달라진 소표본이므로 실행을 합쳐 일반 정확도를 계산하지 않는다.

가장 반복적으로 드러난 약점은 필요한 작업을 문장으로 설명한 뒤, 실제 도구 인수·허용 근거·최종 답변까지 일관되게 반영하는 능력이다. 아래 순위는 실패 영향과 반복에 따른 정성적 우선순위이며 능력별 통제 실험 점수가 아니다.

| 우선순위 | 능력 | 관측 | 해석과 서버 책임 |
|---|---|---|---|
| 1 | 상태·제약 유지와 오류 복구 | CM018은 정식 법령명으로 검색어를 바꾸면서 이전 커서를 유지했고 오류 후 반복. CM003/038은 선택되지 않은 E를 초안에 인용하고 재시도에서도 실패 | 목적을 설명하는 능력과 실제 인수를 고치는 능력 사이에 차이. 서버도 커서 오류에 corrective_actions=[]를 반환했고 compose 입력에는 허용/비허용 근거를 함께 제공 |
| 2 | 주제 관련성과 결론에 필요한 근거 구별 | 최신 CM038은 법률 제8조 대신 운영실태 공시 규정·부칙·평가/보고 기준을 선택. 최신 전체 선택 출처 관련성은 별도 평가1/6 | 단어가 겹치는 출처를 실제 쟁점 해결 근거로 좁히는 데 실패. 검색순위·미리보기·관계 목록 구성도 영향을 줌 |
| 3 | 탐색 우선순위와 종료 전환 | 최신 CM018 후보120개, READ0. CM003은 제26조 전체에서 정의·제31조 등으로 이동하면서 필수 시행세칙을 놓침 | 다음에 무엇을 읽어야 불확실성이 줄어드는지, 언제 검색 대신 읽기/답변으로 넘어갈지 불안정. 조기 종료·입력 누락은 별도 서버 문제 |
| 4 | 예외 확보와 충분한 근거에 따른 단정 | 최신 CM003 초안은 세칙 예외를 확인하지 않은 상태에서 제3자배정을 직접 규정한 제3호가 우선한다고 단정 | 누락된 예외가 결론을 바꿀 수 있음을 일관되게 반영하지 못함. 정확한 원문을 고정해 주는 통제 실험 전에는 독해 능력의 한계와 혼동하지 않음 |
| 5 | 검토에서 찾은 문제를 최종 답변에 반영 | ADR0490 CM003 검토 이유에는 세칙 제23조제4항제2호가 등장하지만 최종 답변은 일반/특별 조항 설명으로 끝남. 저장 평가자는 핵심 조건 누락으로 실패 판정 | 검토가 유용한 정보를 만들기도 하지만 답변 보완까지 보장하지 않음. 시스템도 검토 이유의 새 근거를 최종 문장에 반영하게 강제하지 않음 |

상대적으로 가능한 작업:

- 원문이 확보된 경우 본문·단서·절차의 설명: ADR0490/0494 CM038은 위임 허용 범위와 문서 제출 절차를 설명했고 저장 기준답 평가 통과. ADR0493 CM018은 제49조제1항의 본문·예외 구조를 설명해 평가 통과. 다만 CM018의 필수 출처 회수는1/2였고 품질 전체 통과는 아니다.
- 질문의 표면적 목표 파악과 검색어 변환: 제3호/제4호 비교라는 쟁점을 설명하고, 상증세법을 상속세 및 증여세법으로 풀어 검색하는 행동을 보임. 목적 파악이 올바른 실행을 보장하지 않는다.
- 구체적인 다음 동작 실행: ADR0493에서 제공된 다음 페이지 동작을 실제 사용했으며, 최신 CM018도 검색 조건이 같을 때는 두 차례 다음 페이지 동작을 사용. 검색 조건을 바꾸는 순간의 상태 전환은 실패.
- 구조화 출력 형식: 최신 ADR0495 제품 모델 호출32회에서 journal의 OUTPUT_SCHEMA_INVALID 기록0건. 이는 구조화 출력 제약 아래의 관측이며 대상·커서·선택 상태의 의미 검증 통과와 다르다.

최신 인용 오류의 입력 대조:

- CM003 compose 입력: exact_evidence 9개, support 허용2개. 모델은 허용1개와 표시됐지만 선택되지 않은1개를 함께 인용했다.
- CM038 compose 입력: exact_evidence 11개, support 허용4개. 모델이 인용한2개는 모두 표시됐지만 선택되지 않은 근거였다.
- 따라서 새 ID를 만들어 낸 오류가 아니다. 화면에 보이는 근거와 현재 인용할 수 있는 근거를 별도 목록으로 대조해야 하는 계약에 실패했다. 이를 전부 모델의 기억력/판단력 탓으로 돌리면 입력 설계 문제를 놓친다.

서버의 성공을 모델의 능력으로 계산하지 않는다. 계약35개 통과, 자동 연결 원문7건 전달, 원문 좌표·해시 보존은 서버 구현의 결과다. 검색 후보120개 역시 후보 발견 수이며 모델이 관련성을 검토한 수가 아니다. 원시 judge의 failure_type이 실제 실행 원인과 어긋난 사례도 있어 raw taxonomy만으로 능력 순위를 매기지 않았다. ADR0489의 원문카드를 답변으로 인정한 평가2건도 독해 성공 근거에서 제외한다.

아직 분리 검증하지 않은 사항:

| 구분 실험 | 고정할 조건 | 확인할 능력 |
|---|---|---|
| 필요한 원문만 주고 답변 | 검색·ID 선택 없이 상위 조문과 시행세칙을 완전히 제공 | 독해·조건·예외 판단 |
| 필요한 원문에 유사하지만 무관한 원문 추가 | 같은 질문·정답 근거, 방해 원문만 변경 | 근거 선택·주의 유지 |
| 같은 원문에 짧은 로컬 번호 또는 현재 불투명 ID 부여 | 내용·순서는 동일 | 내용과 ID 연결 |
| 오류 설명 또는 실행 가능한 수정 동작 제공 | 같은 잘못된 호출에서 시작 | 실제 오류 복구 |
| 검토 후 최종 답변 보완 요구 | 같은 초안·원문, 발견한 누락을 보완하도록 연결 | 검토가 답변 품질을 바꾸는지 |

위 실험은 제안이며 아직 실행하지 않았다. thinking on/off, 다른 모델, context 크기별 한계도 비교하지 않았으므로 원인으로 확정하지 않는다.
