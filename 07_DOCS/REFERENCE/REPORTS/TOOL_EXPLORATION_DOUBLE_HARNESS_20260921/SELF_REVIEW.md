# 설계 타당성 자체 검토

검토일: 2026-09-21. 방식: 작성 에이전트의 자체 검토. 독립 에이전트·외부 전문가·실모델 품질 검증이 아니다.
대상: DESIGN.md, CONTRACTS.md, ACCEPTANCE.md, contracts.schema.json. 최종 대상 해시는 review-targets.json에 별도로 결속한다. 관련 코드·실험 기록은 sources.json에 고정했다.

구현 가능성 판정: **조건부 타당**. 기존 API·Pipeline·요청 세션·원문/용어 색인·journal을 재사용할 수 있다. 아래 제어·스키마·도구·DB 변경을 모두 구현해야 하며 현재 연결 완료로 판정하지 않는다.

예상 수치 판정: **설정 관측과 조건부 비용식은 타당, 정확도·비용 절감·일정 예측은 미검증**. 개선률을 제시하지 않았다. 현행 한도를 성능 측정으로 사용하지 않았다.

## 문서 단계에서 추가 대조한 경계

- 사용자는 이번 대화에서 자료 범위를 제한하지 않았다. 일반 예외 조건을 현재 제약으로 오해하게 한 표현을 수정했다. 기본은 등록 자료 전체이며 임시 필터는 에이전트가 자유롭게 되돌린다. 현행 scope='기본'의 개정이력 제외는 사용자 제한과 구별하고, v2 기본 ROOT 변경과 v1 호환을 명시했다.

- 사용자의 수정 요구를 반영해 최초 목록·트리 조회를 의무 단계에서 제외했다. 정확 조문 바로 읽기와 tree 0회 사례를 A01로 고정했다.
- browse의 ROOT outline(문서 제목 목록)과 문서 outline(큰 헤딩/조문), child와 neighbor를 구분했다. 저장 부모 계층과 번호 문자열 추정을 혼합하지 않는다.
- schema는 별칭 타입을 검증할 뿐 존재·현재 제시·scope·cursor·문맥 충분성을 검증하지 못한다. C01/C02/C13에 의미 검증을 별도로 명시했다.
- 잘못된 도구 입력은 전체 결정 실행 전에 거절하고, 검증 후 실행 중 발생한 도구 부분 실패는 항목별로 보존한다. 두 경우의 원자성을 구분했다.
- ADOPT는 서버가 임의 부여하지 않는다. 읽었지만 평가하지 않은 원문을 REJECT로 집계하지 않는다. CHALLENGE 보존은 법적 적용 확정이 아니다.
- 검토자의 주장도 틀릴 수 있다. 근거 없는 전면 거부를 막고 구체적 objection/반론/영향 claim을 저장한다. 예산이 없어도 검토되지 않은 주장을 정답처럼 게시하지 않는다.
- evidence/claim 변경의 종속 무효화와 독립 부분답 보존을 함께 정의했다. 모든 답변 삭제와 모든 과거 승인 재사용을 피한다.
- 기존 Request에 resume/metadata 필드를 억지로 추가하지 않는다. 사용자 후속 발화 재개는 현재 구현 범위와 구분했다.
- 위키/사전은 역할을 명시하며, 짧은 표현 필터가 위키 때문에 해결됐다고 가정하지 않는다.
- 운영에서 frozen research snapshot을 import하는 배선은 금지하고 production adapter로 필요한 부품을 이식하는 계획을 명시했다.

## 수치·출처 검토

N01은 domain.py의 DEFAULT_PROFILE 관측이다. ‘모델 14회’는 물리 시도 상한이고 성공 호출 수·실제 사용량이 아니다. reserve와 cycle을 더해 추가 무료 호출로 계산하지 않는다.

N02는 초기 정책 가정이며 성능 근거가 없다. 같은 오류/주장에 대한 제한과 요청 전체 예산이 함께 필요하다. N03의 계약 fixture 전체 통과는 사용자 질문 정답률과 다른 분모다.

N04는 요율이 통화/토큰으로 정규화됐을 때 토큰×요율=통화가 된다. 요율이 백만 토큰 단위면 해당 배율로 나눈다. 도구 I/O·운영비도 같은 통화 단위로 환산한 뒤 합산한다. 비용 입력값이 없어 실금액 계산은 하지 않았다.

N05는 추가 비용과 절감 비용을 같은 요청당 단위로 합산한다. 둘이 같으면 ΔC=0이므로 손익분기 설명은 성립한다. 이것은 실측 기반 예측이 아니다. 더 많은 원문이나 검토가 늘어도 오답/중복 작업이 줄지 않으면 비용은 증가한다.

N06/N07은 미산정으로 남겼다. 순차 P1~P5에 필요한 작업을 나열했지만 인일·현장 대기·병렬 인력을 근거 없이 일정으로 환산하지 않았다. 스키마의 배열/깊이 상한은 메시지 계약의 방어 한도로서 설정안이며 throughput 예측이 아니다.

외부 레퍼런스는 사용하지 않았다. 저장소의 원문 코드와 과거 실험 기록을 참조했고 과거 점수를 현재 모델/전체 RAG 성능으로 전용하지 않았다. ADR-0481은 미완료 결과를 해석하지 않았다. GENOS 현장 실행은 확인하지 않았다.

## 정적 검사와 남은 실행

validate_design.py는 JSON Schema 자체, 각 도구 행동 예시, P/E 등 잘못된 타입 거부, 로컬 링크, 시나리오 ID 참조, 확인한 원자료 해시를 검사한다. 결과는 validation.json에 저장한다. 실제 제품 handler·모델 판단·API·수용 시나리오 실행 검사가 아니다.

다음 구현에서 가장 먼저 확인할 것은 단일 registry의 실제 호출 가능성과 기존 검색 능력 보존이다. 그 다음에 오류 복구, support/challenge 전달, 검토 이의 처리, API/publication 연결을 확인한다. 실제 품질은 별도 사전 동결 실험과 독립 평가가 필요하다.
