# 검토 지식 E2E 실행

관리 API 저장·게시 → 기존 RAG 질문 해석 → 원문 조사 → 답변·지식 버전 → 동일 요청 재사용을 한 실행으로 연결한다. 현재 로컬 MAIN96의 원문 세대를 공유하고, 앞서 구현한 작업 코드를 고정한 별도 로컬 검증 호스트에서 실행한다. 활성 MAIN 포인터는 바꾸지 않는다.

## 실행

WSL `/home/jin/8-AGENT`에서 실행한다.

```bash
# 모델 호출 없이 실제 원문 해시, 관리 API, 게시, 질문별 지식 조회와 오류 응답 확인
.venv/bin/python 06_TOOLS/EXPERIMENTS/adr_0959/e2e.py check

# 고정한 공개 질문 3건을 실제 모델로 순차 실행
.venv/bin/python 06_TOOLS/EXPERIMENTS/adr_0959/e2e.py run

# 실제 실행 결과와 같은 인증을 사용하는 관리 화면
.venv/bin/python 06_TOOLS/EXPERIMENTS/adr_0959/serve.py
```

화면 주소는 `http://127.0.0.1:8768/e2e/login`이다. 실행 터미널에 표시되는 로컬 토큰을 입력한다. 로그인 후 결과 화면에서 **지식 편집·게시 화면**으로 이동할 수 있다. 토큰은 저장소에 기록하지 않으며 서버를 다시 시작하면 바뀐다. 외부 인터페이스에는 바인딩하지 않는다. 종료는 `Ctrl+C`다. 화면에서 편집하는 지식은 `90_RUNTIME/legal-knowledge-e2e/ADR0959`의 별도 작업 DB에 저장한다. 완료 실험 기록을 덮어쓰지 않으며 화면 호스트의 모델 호출은 차단한다. 동결 실행기의 예전 `serve` 하위 명령 대신 위의 검증된 화면 진입점을 사용한다.

`run`은 완료된 사례를 다시 모델에 보내지 않고 저장 결과를 반환한다. 실패한 사례도 원래 실패로 남는다. 프로세스가 중단되어 완료 기록이 없는 경우 새 예산으로 자동 재실행하지 않는다. `started.json`, `provider/`, 기존 저널을 확인한 후 후속 실행을 새 ADR에 동결한다. 여러 프로세스로 동시에 실행하지 않는다.

## 데이터와 질문

- 원문: 선택 MAIN96과 같은 `latest-selection-20261015-r1/generation`, 총1,547문서. 실제 질의는 기존 공개 승인 범위와 Risk팀 범위의 교집합28문서다.
- 질문: ADR0686에 이미 등록된 충당금·준비금, PF 건전성, 원화 RP의 공개 합성 질문3개다. Risk팀 내부 원본105문항을 그대로 평가한 결과가 아니다.
- 지식: 위 세 주제의 합성 METHOD 검토 절차3개. 실제 금융투자업규정 원문의 위치·본문 해시에 연결하고 API로 게시한다. 법률 결론이나 정답을 넣지 않는다.
- 외부 입력: 고정한 질문·주체·원문 세대·검토 정의의 정확한 해시에 한정한다. 화면에서 임의로 편집한 새 정의를 외부 모델에 자동 반출하지 않는다.

원문과 색인은 복사하지 않고 기존 불변 파일을 읽는다. 검토 지식 저장만 `artifacts/run-001/knowledge-lab.sqlite`에 두는 **로컬 검증 어댑터**를 사용한다. 운영 코드의 Oracle factory에는 연결하지 않으며 GENOS용 저장 방식으로 사용하지 않는다.

## 확인할 기록

[후속 실행 기록](../../../../04_EXPERIMENTS/ADR/ADR-0959-legal-knowledge-e2e-wiring/README.md)의 결과표와 질문별 답변을 확인한다.

| 기록 | 내용 |
|---|---|
| `artifacts/design/freeze.json` | 실행기·질문·지식·선택 포인터·후보 코드 해시 |
| `artifacts/run-001/management.json` | 초안·게시 묶음·게시 버전·질문별 검토 계획 |
| `artifacts/run-001/<case>/response.json` | 실제 API 상태와 답변 또는 실패 응답 |
| `artifacts/run-001/<case>/result.json` | 모델 호출·사용량·시간·적용 버전·중복 검사 |
| `artifacts/run-001/<case>/provider/` | 실제 모델 요청·응답·스키마·사용량 |
| `artifacts/run-001/<case>/audit.json` | 저장 원문·span 해시, 지식 저널, 실제 모델 입력 |
| `artifacts/retrieval-ledger.json.gz` | 허용 원문·확보·모델 제시 좌표 집합 |

`PASS`는 인용을 포함한 답변의 연결 통과, `PASS_LIMITED`는 원문을 보존한 제한 답변의 연결 통과다. 두 상태 모두 법률 정답 판정이나 검색 품질 향상 인증이 아니다. 공급자 제한 등으로 답변이 발행되지 않으면 `FAILED`와 실제 HTTP 상태를 보존한다.

## 실패와 범위

첫 ADR0958 실행의 모델18물리호출과 실패 기록을 보존했다. 두 사례에서 공급자429가 발생했고, 검증 묶음의 표시 모듈 누락이 오류 응답까지 가렸다. ADR0959는 표시 의존성을 포함하고 실제 오류 API 사전 검사와 기존 gateway의429 처리에 연결했다. 공급자·모델을 바꾸거나 예산을 늘려 실패를 숨기지 않는다.

운영 Oracle, 사내 인증, GENOS 내부 모델·배포, 위키·숏컷 실자료를 연결한 E2E는 별도다. 관리/조건/참조의 기존 계약 검증과 이번 METHOD 게시 E2E를 구분한다. 코드와 선택 포인터가 달라지면 실행기는 해시 불일치로 차단하며 새 실행 명세에서 재결속해야 한다.

최종 실행에서 PF는 인용이 있는 부분 답변, RP는 원문을 보존한 제한 답변이었다. 충당금 질문은 공급자429가 반복되어 HTTP503으로 끝났다. 동일 요청 재전송은 답변이 나온 두 사례에서 추가 모델 호출0회였다. 원문·span 묶음162건 불일치0, 계약·회귀104개와 브라우저 확인을 통과했다. 전역 ADR graph의 기존9오류는 이번 기능의 해결 항목이 아니다.

기존 런타임이 중복 요청에서 만든 빈 보조 저널2개는 재기동 시 `OWNER_LOST`로 종료됐다. 실제 답변과 지식 기록이 있는 주 저널을 `response.run_id`로 선택하고 보조 저널도 감사 기록에 남겼다. 추가 모델 호출이나 다른 답변 덮어쓰기는 없었으며, 빈 저널 생성 자체는 이번 작업에서 수정하지 않았다.
