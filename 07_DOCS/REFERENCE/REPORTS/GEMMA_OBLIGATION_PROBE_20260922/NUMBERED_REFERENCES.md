# 검토·근거 번호 변경 및 기존 기능 점검

2026-09-22. [ADR0504 구현 기록](../../../../04_EXPERIMENTS/ADR/ADR-0504-gemma-numbered-reference-wiring/README.md), [기능 점검표](../../../../04_EXPERIMENTS/ADR/ADR-0504-gemma-numbered-reference-wiring/FEATURE_AUDIT.md).

모델이 조문·질문·요구·주장을 1, 2, 3으로 선택하고 서버가 해당 요청의 실제 ID로 복원하도록 격리 후보 rev-004에 구현했다. 목록의 정수만 선택하도록 스키마를 제한하고 서버에서도 검사한다. 데이터베이스·공개 근거 묶음의 실제 ID, 원문, 법령의 조 번호는 보존한다. 도구의 탐색 참조와 이어 읽기 커서도 번호 변환을 거친다.

직전 ADR0503 후보의 103개 파일 중 누락은 0개다. 98개는 해시가 동일하고 5개는 번호 연결/새 ADR 정책 결속으로 변경했다. 번호 변환 모듈 1개를 추가했다. 이 대조는 모든 과거 분기의 기능이 합쳐졌다는 의미가 아니다.

| 구분 | 결과 |
|---|---|
| 기존 구현 누락 | 새 요구 검토의 동적 enum 제한이 빠져 있었음. 이번에 추가 |
| 기존 흐름 | 조문 읽기·연결 원문·실행 가능한 수정 안내·질문별 검토 유지 |
| 계획만 있던 보강 | 원칙/특례 적용 이유의 전용 기록, 원문/초안 조건 표현 대조는 아직 미구현 |
| 구현과 효과의 구분 | 요구별 상태와 교정 경로는 있으나 판단 성능 개선은 미확인 |
| 별도 미해결 | 요구 설명 한 글자 생성 현상 |

모의 테스트 83개 통과(번호 25, 질문 요구/API 23, 기존 workflow 35). 후보 snapshot 검증 및 ADR `validate --final` 통과. 실제 Gemma 호출은 없으며 MAIN·GENOS에 적용하지 않았다.

전체 ADR graph 검사는 실행했으나 기존 오류 3개가 남았다: ADR0305 run purpose, ADR0444의 ADR0432 부모 선언, ADR0158/v2-candidate 소스 노드. ADR0504의 자체 최종 검사 통과와 전체 graph 성공을 구분한다. 기존 완료 이력은 수정하지 않았다.

후속 판단 보강은 요구 해석 정상화, 일반 규칙/특례 적용 이유, 원문/초안 조건 대조 순으로 검토한다. 실제 성능 비교 시 번호 변환 효과와 이 의미 보강의 효과를 분리한다.
