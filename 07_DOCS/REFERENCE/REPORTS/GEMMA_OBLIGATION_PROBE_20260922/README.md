# Gemma 판단 보강 전후: 실제 실행 확인

**현재 보강판의 성능 향상은 확인하지 못했다.** 이번 구현에서는 요구 추적용 문장이 한 글자로 생성됐고, 검토 대상 ID도 잘못 사용됐다. Gemma 자체의 판단 능력과 구현·출력 형식의 영향을 분리해야 한다.

공개 CM/FSC 7문항을 같은 Gemma FP8로 수정 전후 각 1회 실행했다. 실제 제품 호출은 **46회 → 53회**였다. 최종 답변의 전후 우열을 확정할 수 있는 쌍은 없었다. 실행 미완료와 평가 불일치를 오답으로 계산하지 않았다. 아래는 저장된 답변·초안·탐색 기록에서 직접 확인한 관측이며, 새로운 재채점이나 실험 결과가 아니다.

| 대상 능력 | 실제 관측 | 판단·보강 방향 |
|---|---|---|
| 원문 조건 설명 | CM009 수정 전 답변이 제외 대상·3년 요건·“적용하지 않을 수 있다”를 유지 | 긍정 신호. 이 능력은 유지해야 함 |
| AND/OR·예외 보존 | CM050 보강판의 두 번째 초안이 “신성장·원천기술 보유 **또는** 기술등급 상위 50%”와 해당 기업 유형의 제외 조건을 유지 | 긍정 신호. 최종 검토 완료나 전후 개선을 뜻하지는 않음 |
| 이해한 내용을 답으로 전달 | CM025 수정 전 탐색에서는 일반 계산과 별도 조정 규정의 차이를 설명했지만 최종 답변 문단은 비움 | 과도한 유보를 줄이고 확인한 범위의 답을 전달해야 함 |
| 확정·유보 구분 | FSC009 수정 전은 위탁 해당 여부를 조건부로 남기고 위법하지 않다는 방향으로 표현. 보강판 초안은 업무위탁보다 정보 구매에 가깝다고 판단 | 요구별로 답할 수 있는 범위를 나눠야 함. 양쪽 모두 저장 기준의 핵심 원문은 0/2개 제시돼, 원문 해석 능력 자체의 실패로 단정하지 않음 |
| 질문 요구 추적 | 보강판 **7/7문항**에서 requirement가 `국`, `상`, `주`, `별`, `공`, `제` 같은 한 글자 | 출력 스키마와 모델의 상호작용을 먼저 확인·수정해야 함 |
| 자기검토 연결 | CM033 보강판이 요구 ID 대신 질문 문장을 넣었고 재요청에도 반복 | 짧고 명확한 ID, 실제 허용 ID를 포함한 오류 안내 필요 |
| 오류 안내 후 수정 | CM009 보강판이 첫 초안의 근거 ID 혼동을 다음 초안에서 요구 ID로 수정 | 구체적 피드백을 통한 수정의 긍정 신호. 전체 검토 성공은 아님 |

## 한 글자 요구문은 모델 능력으로 바로 해석할 수 없다

동일 응답의 일반 `reason` 필드는 43~124글자였고, 첫 계획 7건 모두 `finish_reason=stop`이었다. 전체 출력이 토큰 한도로 잘린 형태는 관측되지 않았다. 새 요구·사실·검토 사유 필드는 `pattern: \S`, minLength 1, maxLength 400을 사용한다. 로컬 JSON Schema 검사에서는 한 글자와 정상 한국어 문장 모두 통과했다.

이 기록은 **SHORT 필드에 국한된 현상**을 보여준다. 원격 형식 제약이 원인인지, 프롬프트나 모델의 출력 선택이 원인인지는 분리 실험으로 확정하지 않았다. 이번 결과만으로 Gemma가 질문 분해를 못한다고 결론 내리지 않는다.

## 자동 점수는 성능 수치로 채택하지 않는다

Qwen 평가자를 제품과 분리하고 익명 순서를 뒤집어 두 번씩 채점했지만, 실제 입력과 맞지 않는 판정이 있었다.

- **CM033:** 최종 답변에 구체적인 유권해석 필요 문구가 없는데도 한 평가 이유에서 이를 있다고 설명했다.
- **FSC009:** 수정 전 답변의 두 요구가 실패했다고 설명하면서 `correct=true`를 반환한 평가가 있었다.
- **CM025·CM029:** 최종 답변이 없거나 해당 결론의 초안이 없는 경우에도 기준답과 일치하는 결론을 생성했다고 설명한 경우가 있었다.

원시 판정은 ADR0503에 보존했다. 그 집계의 ‘수정 전 2건/보강 후 0건’은 **평가자 출력의 집계**이며, 검증된 정답 수나 정확도로 사용하지 않는다. 두 순서가 같은 판정을 내렸다는 사실도 실제 답변과의 일치를 보증하지 않는다. 실제 답변·원문·판정 이유를 직접 대조한 위 표를 우선한다.

## 다음 수정 순서

1. 요구·사실·검토 사유가 의미 있는 문장으로 생성되도록 출력 형식 호환성을 확인한다.
2. 요구 ID 표현과 오류 안내를 단순화하고 실제 Gemma 응답으로 수정 가능 여부를 확인한다.
3. 질문의 각 요구에 대해 답변 가능·조건부·추가 사실 필요를 따로 판단하게 한다.
4. 같은 7문항에서 기존 장점의 회귀를 확인한 뒤 새로운 문제로 평가한다. 자동 평가에는 빈 답변·초안·최종 답변을 혼동하지 않는 검사를 추가한다.

제품 usage에서 확인된 비용은 약 **$0.3354**, 평가 비용은 약 **$0.0551**이다. 제품 요청 3건은 usage가 없어 전체 청구액 확정값은 아니다. MAIN과 GENOS는 변경하지 않았다.
