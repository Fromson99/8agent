# Claude 설계 수신 후 확인 메모

2026-10-09. `fromson99@gmail.com` 인증 상태를 확인하고 해당 연결을 명시하여 Claude Code Opus 5.5(`claude-opus-5-5`)에 전체 요청문을 전달했다. 정상 종료했고 설계 응답을 받았다. 원본 응답은 `CLAUDE_DESIGN.md`에 수정 없이 보존했다. 이번 작업은 코드 읽기 기반 설계 검토이며 제품 실험·성능 인증·MAIN 승격이 아니다.

## 코드와 대조한 핵심 지적

- `request_repair.progress_facts`는 요구 해결 여부와 별개로 새 법령·후보·구조 위치를 진전으로 센다. 대상별 실제 효과를 보는 설계가 필요하다는 지적은 코드와 일치한다.
- `annotate_reused_reads`는 현재 `data.sources`를 본다. 과거에 전달했지만 현재 화면에 없는 동일 원문까지 막는 보장은 없다. 재취득과 필요한 재표시를 구분해야 한다.
- `Investigation.execute`는 RESEARCH 결과 대기 중에도 `record_progress`를 적용하지만, `__init__`의 결과 수신 분기와 `record_search_outcome`은 그 결과에 따른 진전 계수를 갱신하지 않는다. `run`은 다음 화면을 만들기 전에 무진행 한도를 확인한다. Claude가 지적한 조기 종료 경로는 코드상 성립할 수 있으며, 실제 재현 여부는 후속 합성 반례로 확인해야 한다.
- `completion_execution`의 재진입은 핵심 gap·기존 gap 식별·예산을 중심으로 한다. 정확 대상이 이미 채택되어 다시 조사해도 새 정보가 생기지 않는 경우를 별도로 계획하는 제안은 후속 설계에 포함할 가치가 있다.

## 원본 설계의 수치 정정과 적용 전 보완

1. 원본의 “후보 9회”는 집계 오류다. 전달한 METRICS에는 ADR0719 후보 6회와 ADR0721 후보 6회, 총 12회가 있으며 성공 11회·통신 실패 1회다. 12회 모두 기록된 조사 단계가 2 이하이고 거절 판단은 0이다. 따라서 “이 검증만으로 복잡한 반복 루프 개선을 입증할 수 없다”는 결론은 유지된다.
2. 문서·좌표 없는 서로 다른 부족을 모두 `(issue, kind, PROSE)` 하나로 합치는 제안은 그대로 채택하지 않는다. 별개의 미해결 요구를 잃을 수 있다. 증명 가능한 같은 대상만 통합하고 모호성은 남겨야 한다.
3. EXACT_LOCK, 두 종류 탐색 실패 뒤 EXHAUSTED, 이미 채택된 대상의 재조사 생략은 검증할 정책 후보다. 일부 읽기·불완전 채택·예외 조문·명시 참조가 없는 필수 추가 근거를 막지 않는 반례가 필요하다. 특정 근거 EXCLUDE를 요구 자체가 불필요하다는 뜻으로 바꾸면 안 된다.
4. 계정 권한·데이터 세대 변경은 기존 접근권한과 버전 검증을 먼저 적용한다. boundary 증가만으로 기존 근거나 접근권한을 재사용하면 안 된다.
5. `ConnectError` 이름만으로 요청이 확실히 미전송됐다고 간주하지 않는다. 실제 전송 계층 증거로 구별한 별도 정책·ADR에서 검증하고 ADR0721 결과는 보존한다.
6. 기존 CM 진단의 로컬 읽기·반사실 재생과 외부 live A/B는 구분한다. 이전 반출 동의는 신규 호출에 재사용하지 않는다. 승인된 데이터 범위를 확인하기 전 실제 내부 질문을 외부로 다시 보내지 않는다.
7. “프로필 플래그만 끄면 롤백”은 불충분하다. 실행 중 요청의 고정 controller/스키마, 코드·프로필·데이터 해시, 선택 포인터와 apply/rollback receipt를 함께 연결해야 한다.

## 다음 구현 우선순위

1. 기존 실행 기록을 활용해 행동의 실제 대상·읽은 범위·신규 결과를 비교하고, 검색 결과를 요청한 행동에 귀속한다.
2. 이미 확보한 원문의 재사용·재표시와 새 조사를 구분하고, ASSESS 뒤 추가로 얻을 정보가 있는 경우만 재진입하도록 설계한다.
3. 반복 루프를 실제로 거치는 합성 반례와 기존 기록 재생을 먼저 동결한다. 쉬운 새 질문의 정상 응답만으로 통과시키지 않는다.

현재 활성 릴리스는 MAIN50 그대로다. ADR0722는 기존 코드 검증 예약 상태이며 이 설계 수신을 이유로 실행·통과·승격 처리하지 않았다.
