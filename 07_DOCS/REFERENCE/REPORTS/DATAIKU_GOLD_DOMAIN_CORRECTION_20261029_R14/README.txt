수정 내용
1. ID 도메인에 없는 1000을 제거했다.
   DOC_ID / STRC_UNIT_ID / UPPR_STRC_UNIT_ID / BODY_SLC_ID / SRC_UNIT_ID:
   5개 고유 컬럼·12개 적용 행을 VARCHAR2(1000 BYTE) → VARCHAR2(50 BYTE)로 수정했다.
   사용자 사진의 문서ID 50을 같은 ID 도메인 안에서 재사용했다.
   해시로 만든 조회자료ID·온톨로지/벡터 게시ID·벡터구간ID 및 개념그룹ID는 기존 확인값100을 유지했다.
   기존 문자열·선행 0·식별값을 유지하며 숫자형 변환이나 재번호화는 하지 않았다.

2. 한글 직접 저장 식별내용 3개는 기준 형식과 DB 바이트 길이를 구분했다.
   RFRN_DTA_IDNF_CTNT / BLNG_DTA_IDNF_CTNT / TAGT_DTA_IDNF_CTNT:
   기준 내용 VARCHAR2(1000) × 사용자 지시 한글3바이트 = VARCHAR2(3000 BYTE).
   내용3000이라는 새 인포타입을 임의로 만든 것이 아니다.
   엑셀 길이 셀 메모와 별도 인포타입 목록에 기준1000·배수3·DB3000을 각각 적었다.
   기존 검색키의 512 BYTE 초과 해시 처리·조회 알고리즘은 변경하지 않았다.

3. 문서명은 사진 판독 기록의 2250 BYTE를 유지했다.
   현재 기록에 최종 BYTE로 적힌 값이므로 다시3배 하지 않았다.
   환산 전 길이가750이었다는 확인은 없으므로750을 승인 인포타입으로 만들어 쓰지 않았다.
   사용자의 추가 확인값이 오면 그 값을 적용한다.

4. 한글 여부와 공통 도메인을 바로잡았다.
   벡터 표의 DOC_ID·SRC_UNIT_ID: Y → N.
   벡터 선택의 CHAN_NO: 번호 → 순번, 수식어 변경순번 → 변경, 한글 N → 해당 없음.
   CLOB·숫자 정밀도·일시·VECTOR에는 고정 문자열 길이3배를 적용하지 않았다.
