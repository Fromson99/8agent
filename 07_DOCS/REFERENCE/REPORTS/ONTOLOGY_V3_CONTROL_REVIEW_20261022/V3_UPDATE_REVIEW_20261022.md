# v3 갱신 반영 검토와 CM 핵심 근거 누락 진단

검토 대상: [클러스터·구성](../../ARCHITECTURE/ONTOLOGY_V3/CLUSTERING_AND_CONSTRUCTION.md), [질문·원문 매칭](../../ARCHITECTURE/ONTOLOGY_V3/QUESTION_MATCHING.md), 현재 MAIN100 코드, 완료된 ADR0987의 MAIN99 기반 후보와 실제 입출력. 파일 해시·활성 포인터·전송 입력 대조는 [근거 기록](V3_UPDATE_REVIEW_20261022_EVIDENCE.json)에 보존했다.

자체 검토이며 독립 전문가 심사가 아니다. 새 모델 호출·재채점·실험 재실행·원본 문서 변경·런타임 수정·배포는 수행하지 않았다. MAIN100 선택 파일419개의 해시 일치를 확인했다. 이미 미구현으로 명시된 사항은 새 문서 오류가 아닌 구현 선행 조건으로 분류했다.

## 핵심 항목을 설명하지 못한 직접 원인

**이번 후보가 강제한 범위는 근거 경로의 조회·원문 확보와 검토 안내 전달까지였다. 필요한 원문 span을 판단 입력에 유지하고, 그 검토 결과를 최종 주장까지 연결하는 계약은 없었다.** ‘원문을 가져왔는데 모델이 무시했다’는 설명만으로는 실제 실패를 설명할 수 없다.

CM008의 실제 전송 입력과 출력은 다음 순서였다.

| 단계 | 확인된 사실 |
|---|---|
| 숏컷 | `CORE_EVIDENCE_ROUTE_USED`가 상장규정13조와 세칙15조를 가리킴 |
| 원문 저장 | 기존 journal에 세칙15조의 핵심 block97이 읽힌 것으로 기록됨 |
| 검토 안내 | 실제6회 전송 모두 `listing.past_event`와3년·2년 조건이 안내에 포함됨 |
| 판단용 원문 | 마지막 판단 입력의 원문 목록에는 두 시장의 정의 조항과 코스닥 상장규정13조가 있음. **시행세칙15조는 없음** |
| 모델의 판단 | `MISSING_SOURCE`, `suggested_action=READ_SCOPE`: 세칙15조5항의 구체적 내용이 제공되지 않아 사유를 확인하지 못한다고 명시 |
| 종료 처리 | `ASSESSMENT_RESEARCH_DEFERRED_TO_USER`: 이미 작성한 주장C1을 내보내고 나머지는 후속 조사로 남김 |
| 답변 작성 | 상장규정13조에 근거한 기존 주장·원문만 설명.3년·2년 조건 누락 |

숏컷의 `core_evidence_route.direct_discovery`는 현재 좌표의 후보를 생성한다. 그것만으로 해당 span을 최종 판단의 필수 입력으로 지정하지 않는다. `knowledge_bridge.augment`는 지식을 `REVIEW_GUIDANCE_NOT_EVIDENCE`로 전달한다. 안내에 수치가 있다는 것과 그 수치의 원문이 판단용 근거로 제공됐다는 것은 다르다.

또한 동결 후보의 `completion_execution.py`는 `answer_first`가 켜져 있고 검증된 주장이 하나라도 있으면, 새로운 핵심 원문 부족이 남아도 `defer_to_user`로 종료할 수 있다. CM008에서 바로 이 사건이 기록됐다. 모델이 요청한 추가 원문 읽기가 실행으로 이어지지 않은 것이다. 로그로 확인한 이 경로를 모든 문항의 유일한 원인으로 일반화하지 않는다.

이 검토는 기존0/4 판정을 바꾸지 않는다. 141.13초→70.49초,27→23호출은 보존 결과에서 재계산한 관측치와 일치한다. 다만 일부 근거만으로 종료한 효과도 섞여 있어 **정답에 더 빨리 도달했다는 성능 근거로 사용할 수 없다.**

`KnowledgeCollection`, `KnowledgeDeliveryReceipt`, `find_for_source`는 이 검토에서 구체화한 **제안 이름**이며 현재 존재하는 클래스·API가 아니다. DB 초안의 SOURCE_ANCHOR 조회는 재사용할 수 있다. 클러스터 저장과 전달 사건을 추가할 때 현행 닫힌 스키마나 세 테이블만 허용하는 Oracle adapter에 필드를 임의로 넣어서는 안 된다.

## 우선 적용 순서와 확인할 결과

우선 **이미 찾은 핵심 원문을 판단 입력까지 전달하는 연결**을 다룬다. 그다음 일반 원문 읽기 후 지식 조회를 연결한다. 클러스터 화면·검색 고도화는 이 두 경로와 분리해 진행할 수 있다.

‘강제’의 대상은 선택한 관련 검토 사항의 원문 전달·상태 기록이다. 모델에 특정 법률 결론을 강제하거나, 모든 클러스터 항목을 무조건 조사시키는 것이 아니다. 항목별로 판단 완료·이번 질문과 무관함·사건 사실 부족·근거 부족을 구분하고 이유를 남긴다. 이미 확보한 근거를 다시 검색하는 루프를 만들지 않으며, 실제 미확인은 기존 예산 내 조건부 답변으로 끝낼 수 있어야 한다.

확인할 경로는 `관련 항목 선택 → 정확한 원문 span 확보 → 실제 모델 입력 전달 → 검토 결과 → 최종 주장/한계 연결`이다. 검색 적중·read journal·안내 삽입만으로 이 경로의 성공을 세지 않는다. 후속 코드 계약 검사와 모델 효과 비교는 별도 작업이며, 현재 읽기 전용 검토가 구현·성능 검증을 대신하지 않는다.

## 후속 격리 실험 — ADR-0993

[원문 전달 실험](../../../../04_EXPERIMENTS/ADR/ADR-0993-knowledge-original-delivery/README.md)은 MAIN100을 기준으로 `knowledge_delivery.enrich`와 SELECT→ASSESS→COMPOSE 원문 결속을 후보에 구현했다. 기존 연구용 온톨로지를 양쪽 조건에 동일하게 켜고 원문 전달 기능만 비교했다. 운영 코드·MAIN·GENOS에는 반영하지 않았다.

4문항×2조건에서 후보의 질문별 원문 참조113건이 실제 평가 입력에 모두 들어갔다. 하지만 핵심 설명은 기준11/18항목에서 후보5/18항목으로 감소했다. CM-008은 8호출·82.3초에서 3호출·30.6초로 줄었으나, CM-051은 원문 인용만 반환했고 CM-010·007은 평가 응답 길이 초과로 실패했다. 후보 채택은 거절했다. 소표본 관측이며 일반 성능 인증이 아니다.

이 결과는 R01의 **원문 전달** 구현 검증과 **항목별 설명 완료** 검증이 별개임을 보여준다. 다음 후보에서는 원문 묶음을 더 크게 만드는 것보다, 현재 질문에 필요한 검토 항목을 선택하고 각 항목의 근거·검토 상태·최종 주장 연결을 유지하는 계약을 다뤄야 한다. R02~R05와 Oracle 투영은 여전히 미구현이다. 무적중 plan의 방어 누락도 실험 기록에 남겼다.
