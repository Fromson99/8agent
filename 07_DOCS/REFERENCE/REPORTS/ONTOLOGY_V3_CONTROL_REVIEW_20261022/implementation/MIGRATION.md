## 10. 이행·실패·활성화

1. M04에서 기존 계약과 새 객체의 버전 매핑을 먼저 정의한다. M05·M06은 그 계약을 구현한다.
2. M03은 기존 원문·경험과 연결된 후보를 생성한다. 기존 위키의 PUBLISHED를 새 검토 승인으로 변환하지 않는다.
3. M10은 같은 M05·M06 API의 화면으로 확장한다. 기존 리걸위키 문서는 보존한다.
4. M07·M08을 현재 request_entry·조사·판단·발행 소비자에 연결한다. 등록만 하고 RAG가 읽지 않는 상태와 구분한다.
5. M09에 실제 사용 기록을 연결하고 개별 철회의 효력을 검증한다.
6. 동일 코드의 계약·연결 검사와 필요한 ADR 평가 후 로컬 MAIN 승격·포인터·실제 service 진입을 확인한다. GENOS 현장 인계·Oracle·내부 모델 검증은 별도다.

이행 중 구 함수는 새 구현에 위임하며, 구 객체의 revision·hash·권한·철회 상태를 읽을 수 있어야 한다. 구 consumer가 새 철회를 모르는 상태로 롤백하는 경우는 허용하지 않으며, 호환 adapter 또는 확인된 이전 데이터 계약으로 복원한다. 완료된 실험·원문·실패 이력은 유지한다.

| 실패 | 책임 구현과 처리 |
|---|---|
| 후보 형식·원문 불일치 | M03이 원제안과 오류를 보존, M06 게시 상태로 전환하지 않음 |
| 동시 수정·중복 명령 | M06이 기존 CAS·operation ID로 처리, 다른 계층의 중복 재시도 금지 |
| 원문·권한·사용 중단 변경 | M07 조회와 M08 발행 경계에서 현재 참조 재확인 |
| 의미 적용 불확실 | M08에 미확인·조건부 해석 기록, 확보한 원문과 제한 답변 전달 |
| 사용 기록 색인 지연 | M09가 미반영 범위를 표시, 기존 이벤트로 멱등 재구축 |
| 지식 조회 연결 실패 | 지식 안내 실패를 기록하고 기존 허용 원문 조사로 전환. 확보하지 못한 지식을 사용했다고 표시하지 않음 |
| 발행·저장 결과 불명 | 기존 발행 복구·operation 조회에서 같은 결과를 확인, 새 답변을 임의 연결하지 않음 |

검사는 코드 이동의 import 호환, 같은 입력·출력 보존, 객체별 권한·revision, 검토와 게시 분리, 실제 주장 연결, 철회 전후·재개·동시 수정·영향 미확인을 포함한다. 모델·프롬프트·검색 효과 비교는 기존 ADR 절차로 별도 수행한다.

성능·비용·일정 예상치는 미산정이다. 명명과 책임 분리만으로 속도·정확도가 개선된다고 주장하지 않는다. 구현 후 같은 원문·질문에서 조회·모델 비용, 중요 누락, 검토·정정 시간과 지식 갱신 비용을 확인한다.

## 11. 이번에 이름을 적용한 범위

- 전체 명칭과 구현 단위 M01~M12를 이 문서에 정의했다.
- 각 단위의 현재 코드·목표 파일·함수·입출력·소비자·기존 호환 경로를 연결했다.
- 온톨로지 v3에 이 이름표를 반영했다.
- 기존 코드 검토의 관측 내용과 EVIDENCE는 보존했다.
- **실제 Python 파일 rename·신규 기능 구현·DB 변경·MAIN 활성화는 하지 않았다.** 다음 구현에서 사용할 구체적인 이름과 경계가 정리된 상태다.
