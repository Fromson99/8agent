# CASE 2 — 법률·규정 AGENT 상세 정리

작성 기준: 2026-09-26. 첨부한 PART 0~1과 CASE 1의 설명 순서에 맞춘 슬라이드 문안·발표 해설이다. 실제 덱 파일을 편집한 결과는 아니다. 구현과 활성 릴리스, 확장 방향을 구분한다.

## 1. 전체 이야기를 관통하는 문장

**법령 원문·용어·정의·참조를 연결하고, 하네스로 탐색과 검토를 관리해, 답변의 근거와 수정할 위치를 추적하는 법률·규정 AGENT.**

CASE 1이 도면 객체와 매뉴얼을 연결했다면, CASE 2는 법령 원문과 전문용어, 정의와 명시 참조를 연결한다. 두 사례의 공통점은 AI가 활용할 근거 구조를 먼저 만들고, 그 구조를 사용하는 과정에 제약과 기록을 둔다는 점이다.

법률 사례에서는 문서가 연결되었다는 사실만으로 결론을 확정할 수 없다. 같은 용어도 문서마다 뜻이 다르고, 일반 규정과 예외 규정의 적용 범위가 다르기 때문이다. 따라서 연결은 탐색을 돕는 단서로 사용하고, 실제 적용 여부는 원문을 읽어 검토한다.

### 15 CASE 02 표지 — 법률과 규정

**발표 노트**

도면에서는 같은 설비를 여러 자료에서 찾아 연결해야 했다면, 법률·규정에서는 같은 업무를 가리키는 표현과 개념을 연결해야 했다. 현업의 질문은 일상적인 업무 언어지만 문서는 법률용어로 작성되어 있다. 관련 조항을 찾은 뒤에도 정의·적용 대상·조건·예외를 함께 확인해야 하므로, 검색과 판단을 하나의 단계로 취급하지 않았다.

### 16 법령 원문·용어·정의를 연결하고, 질문은 근거를 찾아간다

**본문 문안**

질문마다 AI가 법률용어와 문서의 관계를 새로 추측하지 않도록, (A) 원문의 구조와 위치를 보존하고 (B) 용어·정의·명시 참조를 연결했다. (C) 질문은 관련 개념과 검색 경로에서 출발해 필요한 원문을 확보하고, 답변에 사용할 근거를 선별한다. (D) 찾은 자료와 실제 읽고 사용한 근거는 구분해 기록한다.

- **A 지식 구축:** 문서·버전 확인 → 장·절·조·항·호·표의 구조 복원 → 본문·출처·위치 보존 → 용어집과 문서 연결.
- **B 지식그래프:** 원문 / 문서 구조 / 용어 / 문서별 정의 / 용어 출현 / 명시 참조 / 원본 위치와 버전.
- **C 경로 탐색:** 질문의 요구 확인 → 용어·본문·문서 구조·참조로 후보 탐색 → 원문 확보 → 근거 선별 → 누락 후보 재검토 → 답변과 원문 대조.
- **D 근거 보존:** 검색 후보, 확보한 원문, 모델에 실제 전달한 원문, 답변이 사용한 출처를 구분한다.

**발표 노트**

같은 단어가 들어 있다는 이유만으로 같은 개념이라고 보지 않는다. 용어의 뜻은 출처와 문서의 적용 범위를 함께 보존한다. 다른 조문을 가리키는 표현도 실제 대상을 확인해 연결하며, 구조나 판본이 모호한 연결은 미확인으로 남긴다.

현재 구조는 원문을 조건·효과의 고정 규칙으로 전부 바꾸어 저장하는 방식이 아니다. 원문을 보존하고, 용어와 참조를 원문을 찾아가는 단서로 쓴다. 따라서 원문을 잘못 요약한 내용을 정본으로 계속 사용하는 위험을 줄이도록 설계했다.

검색 목록에 보였다는 사실과 원문을 읽었다는 사실도 다르다. 제목만 본 자료, 일부 발췌만 본 자료, 전체 필요한 구간을 확보한 자료를 같은 근거로 취급하지 않는다. 선별 과정에서 필요한 원문이 빠졌는지를 별도로 확인하도록 구성했다.

### 17 하네스는 근거를 고르는 것과 결론을 확정하는 것을 구분한다

**본문 문안**

관련 조항을 찾았다고 질문에 대한 답이 완성되는 것은 아니다. (A) 질문에서 해결해야 할 요구를 유지하고, (B) 자료와 행동의 범위를 제약하며, (C) 원문과 답변의 조건·예외·확실성을 대조한다. (D) 확인한 부분은 답하고, 부족한 사실과 미해결 근거는 구분해 남긴다.

- **A 질문 유지:** 질문의 요구와 배경을 나누고, 요구 → 답변 주장 → 원문 근거 → 검토 결과를 연결한다.
- **B 실행 제약:** 허용 자료·도구·현재 제시된 후보만 사용하고, 실제 행동 없는 반복과 호출·시간 한도를 관리한다.
- **C 의미 검토:** 개념 / 적용 범위 / 조건 / 예외 / 확실성 / 질문 적합성이 원문에서 답변으로 이어지는지 확인한다.
- **D 완료와 보류:** 확인한 내용은 답변에 남기고, 필요한 추가 사실·미확인 적용 범위·새 조사가 필요한 부분을 표시한다.

**발표 노트**

하네스는 두 층으로 설명할 수 있다. 업무 하네스는 무엇을 확인해야 하는지 관리하고, 실행 하네스는 실제로 무엇을 읽고 어떤 행동을 했는지 관리한다. 규정의 적용 여부는 모델의 의미 판단이 필요하지만, 제공하지 않은 자료를 인용했는지, 같은 작업을 반복했는지, 수정된 답변에 오래된 검토를 붙였는지는 시스템에서 검사할 수 있다.

‘관련 자료로 선택했다’는 것은 법률 적용을 승인했다는 뜻이 아니다. 선택된 원문도 이후 주장과의 관계를 검토해야 한다. 같은 모델이 탐색·작성·검토를 수행하면 같은 의미 오류를 반복할 수 있으므로, 검토 통과를 법률 정답 인증으로 표현하지 않는다.

현재 로컬 활성 경로의 누락 복구는 확보한 후보 안에서 추가 근거를 고르는 방식이다. 검토 이후 완전히 새로운 조사가 필요한 경우에는 미완료로 표시하는 한계가 있다. 무제한 재탐색으로 모든 질문을 자동 해결한다고 설명하지 않는다.

### 18 지나간 경로에서 오류를 찾고, 검증한 변경을 새 버전으로 반영한다

**본문 문안**

두 사례 모두 답변만 저장하면 오류의 원인을 찾기 어렵다. (A) 답변에서 사용 근거와 선택 경로를 거슬러 올라가고, (B) 원본 위치와 버전에 연결해 잘못된 단계를 구분한다. (C) 수정은 검토 후보로 남기고, (D) 검증한 코드·지식·설정을 새 버전으로 반영하며 이전 상태를 보존한다.

| 추적 단계 | CASE 1 도면·매뉴얼 | CASE 2 법률·규정 |
|---|---|---|
| 최종 결과 | 설비·경로·조건에 대한 설명 | 질문의 요구에 대한 답변·주장 |
| 사용 근거 | 객체·연결·설정값·매뉴얼 본문 | 원문·정의·참조·주장별 출처 |
| 선택 기록 | 선택 객체와 조회 경로 | 검색·선별·전달·검토 기록 |
| 원본 위치 | 도면 번호·좌표·문서 절 | 문서·조항·본문 구간·버전 |
| 수정 후보 | 인식·매핑·조회·설명 오류 | 구조·연결·회수·선별·해석 오류 |

**발표 노트**

법률 AGENT에서는 필요한 조항이 DB에 없었던 것인지, 검색하지 못한 것인지, 찾았지만 선별에서 버린 것인지, 모델에 전달되지 않은 것인지, 읽었지만 적용을 잘못한 것인지를 나누어 볼 수 있다. 원인에 따라 수정 위치가 달라진다.

피드백은 답변과 실행·원문 버전을 가리키는 수정 후보로 남긴다. 과거 답변을 자동으로 정답 데이터에 넣거나, 피드백을 받자마자 활성 지식을 바꾸지는 않는다. 현재 구현된 후보 기록과 앞으로 이어야 할 자동 검증·반영 루프를 구분한다.

CASE 1에 대한 표의 내용은 첨부된 설명 범위다. 새 버전·롤백의 구체적 구현은 이번에 확인한 법률 AGENT의 근거를 사용하며 CASE 1의 구현 성과로 옮겨 말하지 않는다.

## 4. 세부 구조 — 지식을 만드는 과정

### 4.1 자료 반입: 어떤 문서를 사용하는지 먼저 고정한다

입력은 법령·규정·내규와 사전 자료다. 출처, 문서 식별자, 버전, 내용의 해시, 공개·내부 구분을 확인하고 원본을 보존한다. 문서의 이름이 비슷하거나 가장 최근에 저장되었다는 이유로 자동 선택하지 않는다.

이 단계가 있어야 나중에 ‘어느 판의 어떤 조항을 근거로 답했는가’를 확인할 수 있다. 개정된 원문이 들어오면 기존 답변의 근거 버전도 함께 구분할 수 있다.

### 4.2 구조화: 문장을 읽기 전에 소속과 순서를 복원한다

법률 문서의 의미는 문장뿐 아니라 장·절·조·항·호의 소속에도 영향을 받는다. 표와 주석, 부칙이 다른 본문에 붙으면 적용 범위를 잘못 이해할 수 있다.

형식에 맞게 원문을 읽고 전체 구조를 복원한다. PDF에서는 이미지 검토를 활용해 추출된 텍스트와 실제 페이지 구조를 대조하는 경로를 둔다. 본문·순서·상위 구조·원본 위치를 보존하고, 추출하지 못한 좌표나 표 셀을 임의로 만들어 채우지 않는다.

구조 검토 경고를 남기고 후속 처리를 계속할 수 있는 설정도 있으므로, 구조화 완료가 모든 페이지의 의미·인식 정확도 승인과 같은 뜻은 아니다.

### 4.3 용어집: 현업 표현과 문서 언어가 만나는 기반을 만든다

기관 사전과 문서 내 정의를 출처별로 수집하고 연결한다. 동일한 표제어라도 정의와 적용 범위를 함께 남긴다. 용어 목록 수집, 정의 수집, 관계 수집, 의미 검토는 서로 다른 완료 상태다.

AI는 정의의 의미 비교와 연결 후보 검토를 돕는다. 시스템은 출처·원문 구간·버전·검토 상태를 보존한다. 원문 구조화 자체는 용어집과 독립적으로 실행하고, 후속 단계에서 구조화한 문서와 용어집을 연결한다.

### 4.4 연결과 색인: 어디를 찾아가야 하는지 준비한다

연결은 다음의 서로 다른 역할을 가진다.

| 연결 | 질문 처리에 쓰는 목적 | 주의할 점 |
|---|---|---|
| 문서 → 조항 → 본문 | 원문의 소속과 범위를 찾기 | 다른 조항의 같은 번호와 섞이지 않아야 한다. |
| 용어 → 출현 위치 | 개념이 실제 쓰인 원문 찾기 | 등장했다는 사실이 적용 가능성을 증명하지 않는다. |
| 용어 → 정의 원문 | 해당 문서에서의 뜻 확인 | 다른 문서의 정의를 무조건 가져오지 않는다. |
| 원문 → 명시 참조 대상 | 함께 읽을 조문·규정 찾기 | 참조 대상과 준용 범위를 구분해야 한다. |
| 근거 → 원본 위치·버전 | 검토와 사후 추적 | 버전이 달라지면 같은 번호라도 다시 확인해야 한다. |

구조 좌표가 명확한 참조는 결정론적으로 연결할 수 있다. 문맥·약칭·판본·여러 후보의 해석이 필요한 참조는 후보와 정본 연결을 구분하고, 미확인 상태를 남긴다. 모든 연결이 이미 사람이 검토한 상태라고 주장하지 않는다.

새 문서와 수정한 관계는 새 색인·데이터 묶음으로 만든다. 구축이 완료되었다는 사실과 실제 질문에 쓰는 버전으로 선택되었다는 사실은 별개다.

## 5. 세부 구조 — 질문에 답하는 과정

### 5.1 질문의 요구를 잃지 않는다

예를 들어 ‘이 업무를 외부에 맡길 수 있는지, 가능하면 어떤 확인이 필요한지’를 묻는다면 가능 여부와 필요한 확인을 각각 추적해야 한다. 설명 중에 가능 여부만 답하고 절차 질문을 빠뜨리지 않도록 요구와 배경을 구분한다.

주체·행위·대상·조건은 질문을 설명하는 유용한 관점이다. 다만 현재 질문 계약 전체가 이 네 항목으로 고정된 의미 스키마라고 설명하지 않는다. 실제 구현의 중심은 질문 요구·배경과 주장·근거·검토의 연결이다.

### 5.2 여러 진입점에서 원문 후보를 확보한다

문서명과 조문 번호가 있으면 구조 단서를 보존한다. 업무 표현으로 질문했다면 관련 용어와 본문 검색을 활용한다. 정의와 명시 참조는 추가 원문을 찾는 단서가 된다.

현재 로컬 활성 경로는 질문에 따른 검색 계획, 전체·선택 문서 검색과 관계 후보의 회수, 필요한 원문 확보를 연결한다. 단일 검색 순위나 한 번의 그래프 이동만으로 모든 근거를 확정하지 않는다.

### 5.3 확보와 선별을 나누고 누락 후보를 다시 본다

넓게 회수한 후보를 모두 답변에 넣으면 관련 없는 자료와 문맥 부담이 늘어난다. 반대로 너무 일찍 줄이면 예외나 보조 근거가 사라질 수 있다.

그래서 원문을 확보하는 단계와 답변에 사용할 자료를 고르는 단계를 나눈다. 현재 로컬 활성 경로는 제목·회수 경로를 이용한 1차 선별과, 발췌·보류 목록을 이용한 추가 선별을 수행한다. 후보 중 최대 16개를 먼저 고르고 최대 8개를 추가하는 상한이 있으며, 이는 품질 성과가 아니라 실행 설정이다.

원문 하나가 여러 페이지로 나뉘면 여러 근거 항목으로 전달될 수 있다. 논리 원문 개수와 페이지·근거 항목 개수를 혼동하지 않는다.

### 5.4 답변을 만들고 원문과 대조한다

답변의 주장과 질문 요구를 연결한다. 근거가 실제로 전달되었는지 확인하고, 원문과 초안에서 개념·범위·조건·예외·확실성이 달라졌는지를 검토한다.

검토 역할은 주장에 대한 반론과 누락 사실도 살핀다. 실행 시스템은 자료 선택의 유효성, 실제 전달 기록, 상태의 모순, 오래된 검토의 재사용을 검사한다. 의미 판단은 여전히 모델 오류가 가능한 영역이다.

현재 작업 코드에는 인용 문자열 불일치를 기록하고 제한된 결과로 계속하는 임시 설정도 있다. 따라서 어느 환경에서나 인용 문자열 불일치를 항상 차단한다고 발표하지 않는다. 이 설정은 로컬 활성 고정 릴리스와 별도로 구분한다.

### 5.5 확인한 부분과 미확인 부분을 나누어 종료한다

근거가 부족한 이유는 서로 다를 수 있다. 질문에 사실이 빠졌을 수도 있고, 원문을 찾지 못했을 수도 있고, 적용 범위가 모호할 수도 있다. 필요한 추가 사실, 미해결 요구, 더 조사할 근거를 구분해 남긴다.

현재 선별·복구 경로의 재검토 범위는 확보한 후보 안으로 제한된다. 이후 검토에서 새 조사가 필요해지면 현재 실행에서 완료하지 못했음을 표시한다. 종료 상태가 남는다는 사실과 법률 답변 품질이 인증되었다는 사실은 다르다.

## 6. 하네스 — AI·시스템·현업의 책임

| 주체 | 담당하는 일 | 단독으로 확정하지 않는 것 |
|---|---|---|
| AI | 질문 해석, 검색 방향·자료 선택, 원문 종합, 조건·예외 검토 | 법률 정답 인증, 정본 지식 승인, 릴리스 활성화 |
| 시스템 | 자료·도구 범위, 형식과 식별자, 실제 전달, 상태·예산·기록 관리 | 원문의 법적 의미가 언제나 옳게 해석되었다는 보장 |
| 현업·운영자 | 업무 사실 보완, 해석·연결 후보 검토, 기준과 변경의 확인 | 모든 수정이 즉시 무검증으로 서비스에 반영되는 것 |

### 업무 하네스에서 확인할 질문

- 무엇을 답해야 하는가? 질문의 요구를 전부 유지했는가?
- 어떤 개념과 문서 범위가 관련되는가?
- 원문의 조건·예외·불확실성을 답변이 보존했는가?
- 확인한 사실과 추가로 필요한 사실을 구분했는가?

### 실행 하네스에서 확인할 질문

- 현재 허용된 후보·도구·문서 범위를 사용했는가?
- 목록을 본 것과 원문이 실제로 전달된 것을 구분했는가?
- 계속 조사하겠다는 판단에 실제 새 행동이 있는가?
- 주장이나 근거가 바뀌었는데 이전 검토를 재사용하지 않는가?
- 시간·호출·반복 상한에 도달했을 때 상태와 한계를 남기는가?

이 구분을 통해 모델이 선택할 영역과 시스템이 직접 검사할 영역을 분리한다. 비슷한 질문에 같은 관리 기준을 적용하는 것을 목표로 하며, 같은 답변이나 같은 탐색 경로가 항상 재현된다고 보장하지 않는다.

## 7. 한 질문으로 보는 전체 흐름

아래는 구조를 설명하기 위한 가상 업무 질문이며 실제 법률 판단이나 실행 결과가 아니다.

> “이 업무를 외부 업체에 맡겨도 되나요? 가능하다면 어떤 확인이 필요한가요?”

1. **질문 요구:** 위탁 가능 여부와 필요한 확인 사항을 구분한다. 대상 업무·회사·상대 업체 등 빠진 사실도 확인 대상이다.
2. **탐색 출발점:** 관련 용어와 문서·본문 후보를 찾는다. 질문의 ‘맡긴다’와 법률 개념의 관계는 검토해야 할 검색 가설이다.
3. **원문 확보:** 관련 정의·일반 규정·명시 참조를 따라 필요한 원문을 확보한다. 찾지 못한 연결과 자료도 남긴다.
4. **근거 선별:** 실제 업무에 관련될 후보를 고르고, 빠뜨렸을 수 있는 후보를 다시 확인한다.
5. **적용 검토:** 해당 업무가 규정의 대상인지, 조건과 예외를 적용할 사실이 있는지 확인한다.
6. **답변 구성:** 확인된 내용과 조건부 설명, 추가로 필요한 사실을 구분한다. 자료가 부족하면 가능·불가를 임의로 확정하지 않는다.
7. **원문 대조:** 선택 원문이 답변 주장과 맞는지, 가능 여부 외에 확인 사항까지 답했는지 검토한다.
8. **기록과 수정:** 어떤 원문을 확보·전달·사용했는지와 미해결 요구를 남겨 이후 오류 원인을 찾는다.

표현을 기존 용어로 지속 등록하고 검토된 탐색 절차를 재사용하는 기능은 별도의 선택형 구현이다. 위 예시의 모든 새 표현이 현재 활성 경로에서 자동 학습된다는 뜻은 아니다.

## 8. 경로 추적 — 오류에 따라 수정 위치가 달라진다

| 확인한 문제 | 살펴볼 기록 | 수정할 위치 |
|---|---|---|
| 원문 내용이나 조항 소속이 잘못됨 | 원본과 구조화 결과 | 문서 파싱·구조 복원 |
| 다른 뜻의 용어가 연결됨 | 출처별 정의·범위·검토 상태 | 용어 연결·의미 검토 |
| 다른 문서·항목으로 참조가 연결됨 | 참조 문자열·원문 위치·해소 대상 | 참조 해소·좌표 처리 |
| 필요한 원문을 찾지 못함 | 검색 계획·회수 후보·조회 경로 | 검색 진입점·범위·색인 |
| 찾았지만 답변 자료에서 빠짐 | 회수 풀·선별 이유·보류 목록 | 선별·누락 복구 |
| 확보했지만 모델이 받지 못함 | 원문 구간·실제 전달 기록 | 문맥 구성·분량 관리 |
| 원문은 받았으나 조건을 잘못 해석함 | 주장·원문·검토 결과 | 해석·작성·검토 절차 |
| 수정한 답변이 이전 검토를 사용함 | 주장·근거·검토의 버전 관계 | 상태 전이·검토 무효화 |

실행 경로 기록은 원인을 좁히는 근거다. 기록만으로 모든 오류 원인이 자동 확정되는 것은 아니다. 범위가 정해진 수정도 하위 단계와 전체 답변에 미치는 영향을 확인해야 한다.

## 9. PART 2 — 확장가능성과 연결할 내용

**재사용하는 것은 개별 답변보다 지식을 연결하고 검토하는 구조다.**

새 팀이나 업무에 적용할 때 원문 구조화, 출처·버전 관리, 용어·정의 연결, 명시 참조, 질문 요구 추적, 주장·근거 검토, 실행 기록의 공통 구조를 활용할 수 있다. 업무마다 달라지는 문서·용어·적용 범위·필수 확인 항목은 새로 확인한다.

| 재사용할 공통 구조 | 업무별로 다시 확인할 것 |
|---|---|
| 문서·조항·본문과 출처의 저장 계약 | 문서 형식·구조·버전·누락 |
| 용어·정의·참조 연결 | 같은 단어의 다른 뜻·약칭·범위 |
| 질문 요구와 주장·근거의 연결 | 해당 업무가 요구하는 판단과 절차 |
| 도구·예산·상태·기록 관리 | 허용 범위·자료 권한·실행 환경 |
| 검토·변경·롤백 절차 | 새 자료에서의 품질과 회귀 |

‘현업이 업무 언어로 연결과 기준을 관리한다’는 확장 목표를 설명할 수 있다. 다만 현재의 DB 기반 작업 하네스와 표현·절차 재사용 구현을 전체 현업용 노코드 운영 제품의 완성으로 표현하지 않는다. 팀별 문서 선택도 접근권한 인증 체계 전체를 대신하지 않는다.

## 10. PART 3 — 의사결정과 실험으로 연결할 내용

**원인을 구분할 수 있어야, 무엇을 바꿔 비교할지도 정할 수 있다.**

회수 실패라면 탐색 방법을, 선별 실패라면 선택·복구 방식을, 전달 실패라면 문맥 구성을, 해석 실패라면 답변·검토 절차를 후보로 삼는다. 변경하지 않은 조건과 부모 버전을 고정하고, 필요한 근거의 보존·누락, 최종 답변, 기존 성공의 악화, 지연·비용을 구분해 확인한다.

자료를 찾은 비율과 답변 정답률을 하나의 점수처럼 취급하지 않는다. 과거 평가에서 좋은 수치를 얻은 사실, 검증 조건을 충족한 사실, 현재 활성 경로로 반영한 사실, GENOS 현장에서 확인한 사실은 각각 기록한다.

발표에서는 ‘실험을 많이 했다’보다 ‘실패 단계를 나누어 다음 변경을 정하고, 검증한 후보만 선택할 수 있도록 이력을 남겼다’를 중심으로 설명한다. 이번 정리에서는 새로운 성능 수치를 만들거나 모델 실험을 실행하지 않았다.

## 13. 1분 발표 문안

법률·규정 프로젝트에서는 현업의 질문을 정확한 원문과 연결하는 것이 핵심이었습니다. 문서를 구조화하고 용어·정의·명시 참조를 연결해, AI가 근거를 찾아갈 수 있는 기반을 만들었습니다. 그리고 질문에서 무엇을 답해야 하는지, 어떤 원문을 실제로 읽었는지, 답변이 조건과 예외를 보존했는지를 하네스에서 관리했습니다.

관련 자료를 찾았다는 사실과 그 규정이 업무에 적용된다는 판단은 구분했습니다. 확인된 부분은 답하고 부족한 사실과 미해결 근거는 남기도록 했습니다. 오류가 생기면 원문 구조화, 연결, 검색, 선별, 전달, 해석 중 어느 단계에서 문제가 생겼는지 기록을 따라 확인합니다.

이 프로젝트에서 제가 주도한 것은 문서 처리부터 지식 연결, 답변과 검토, 실험·변경 관리까지 이어지는 전체 설계와 개발입니다. 새 업무로 확장할 때도 개별 답변을 복제하기보다, 근거를 연결하고 검토하는 구조를 재사용하는 것을 지향했습니다.
