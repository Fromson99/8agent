# 워크플로우 통합 설계 근거

확인일 2026-09-26. 사용자 요청은 기존 검색 기반 위에 내규–외규 비교와 내규 간 상충 검토의 플로우를 그리고, 기존 프로젝트 설명과 합치는 것이다. 이번 산출물은 설계·설명 원고다. 코드 수정·새 실험·모델 호출·배포·실제 내부 문서 판정은 하지 않았다.

## 확인한 현재 연결과 설계상 영향

| 근거 | 확인한 내용 | 설계에 반영한 판단 |
|---|---|---|
| `00_SYSTEM/ARCHITECTURE.md` | 전체 MAIN의 입력·구조화·용어 연결·색인·RAG·피드백 | 검색 서버·원문 구축을 중복 생성하지 않음 |
| `00_SYSTEM/DATA_MODEL.md` | 현행 원문·용어 계약, 구 의미 규칙 스키마 제거, 팀은 권한 아님 | 비교 해석을 실행별 관측으로 저장. 정본 규칙 DB를 재도입하지 않음 |
| `00_SYSTEM/PIPELINE.json` | 엔진·계약·프로필과 선택 경로 | 업무 프로필과 새 계약을 공통 실행 명세에 등록하도록 제안 |
| `semantic_runtime/app.py:create_app` | 목록·목차·읽기·참조·ask·feedback API와 ask의 닫힌 입력 필드 | 기존 ask에 임의 필드를 넣지 않고 같은 앱에 새 reviews API 제안 |

| `semantic_runtime/pipeline.py:Pipeline.plan/run` | 팀·문서 범위를 고정하고 요청 세션으로 실행 | 모든 하위 검색·원문 조회에 고정된 문서 범위 전달 |
| `semantic_runtime/legal_agent_adapter.py:ServingLegalAgent.retrieve/open_session` | use_llm 조회는 요청 세션 필요, 모델·세대·scope·원장 결속 | 기존 세션을 유지한 근거 묶음 어댑터 필요. 단순 GET search와 품질 경로를 혼동하지 않음 |
| `semantic_runtime/stage_runner.py:StageRunner.execute` | 엔진 manifest·입출력 계약 검증 | 같은 실행 기반을 이용한 업무 단계 추가 |
| `semantic_runtime/legal_agent/coordinator.py:run` | 네 단계 이름의 정확한 집합 검사 | 기존 RAG Coordinator에 비교 노드를 단순 추가할 수 없음 |
| `semantic_runtime/legal_agent/gate.py:evaluate` | 미해결 상충과 연결된 일반 답변 결론 제외 | 업무 검토 결과를 별도 계약·검사로 보존. 상충 발견을 오류로 지우지 않음 |
| `semantic_runtime/feedback.py` | RAG 답변·실행·세대에 연결된 PROPOSED 피드백 | 검토 결과용 ReviewDecision을 별도로 설계 |
| `07_DOCS/REFERENCE/OPERATIONS/BOUNDED_SOURCE_RECOVERY_MAIN.md` | 후보 안의 제한적 복구, 새로운 조사 미완료 처리 | 상위 workflow의 예산 있는 하위 검색을 제안. 자율 무제한 탐색을 가정하지 않음 |
| `07_DOCS/REFERENCE/OPERATIONS/GENOS_LEGAL_AGENT_TEAMS.md` | 팀은 문서 필터, API마다 명시 전달, 교차 팀 문서 거절 | 업무 범위와 접근권한을 별도로 확인. 하위 작업에서 필터 유실 방지 |
| `GENOS.md` | 망분리 접근 불가, 편집기 워크플로우 적용과 코드 배포 별도 | 현장 실행 성공으로 주장하지 않음. E2E는 워크플로우 테스트 화면에서 확인 |
| `01_DATA/ACTIVE/local/ACTIVE_RELEASE.json` | r3, generation 24, quality_certified=false | 검색 기반 상태와 새 workflow 품질·배포를 분리 |

위의 `semantic_runtime/` 경로는 저장소 `02_BACKEND/semantic_runtime/`를 뜻한다.

## 설계 선택과 제한

- 두 워크플로우의 업무 존재와 목표는 사용자 진술에 근거한다. 이번에 확인한 검색·서빙 경로에서 전수 검토 전용의 완료된 API와 실행을 확인하지 않았으므로 새 연결은 제안으로 표시했다.
- 내규–외규 비교는 양방향이다. 내규 출발 검색만으로 외규 요구의 미반영을 모두 발견할 수 있다고 가정하지 않았다.
- 상충은 같은 적용 상황에서 양립 가능한지 검토한다. 단순 수치·표현·승인자 차이를 자동 상충으로 만들지 않았다.
- 검색 후보를 줄이면 회수 누락 위험이 있다. 전체 항목 처리율, 후보 회수율, 최종 판정 품질을 별도로 정의했다.
- 비교용 기간·수치 예시는 모두 가상이며 법률 조언·실제 회사 규정의 판정이 아니다. 외부 법령의 우선순위나 법적 효력을 이 보고서에서 새로 단정하지 않았다.
- 공통 검색의 기존 알고리즘 재사용과, 근거 묶음만 반환하는 새 경계의 구현 필요를 구분했다.
- 같은 모델의 작성·검토가 독립적인 의미 검증을 보장하지 않는다. 이번 문서 자체의 검토도 작성자의 자체 검토다.
- 정확도·비용·속도·구현 인일은 새 workflow의 실측이 없어 미산정이다. 쌍 비교 수와 후보 제안 수의 수식은 작업량 관계를 설명할 뿐 측정 성과가 아니다.
- 실제 PPT 편집이나 Mermaid 화면 렌더링은 수행하지 않았다. 본문에 Mermaid 원본을 포함했다.
