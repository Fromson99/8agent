## 확인된 문제

1. 메뉴가 개념 표제어를 삭제해 연결 종류만 남겼다. 실제 이하 연결을 모델은 주식등 정의 연결이라고 추측했다.

2. 저장소 heads는 entity_id 순서이고 메뉴는 앞 12개다. 현재 질문 관련성 우선 정렬이 없다. 실제 첫 메뉴에는 교육비납입증명서와 다른 법령 부칙도 섞였다.

3. 메뉴 notice_presented=false는 고정값이라 상세가 이미 제시된 뒤에도 같은 표시가 남는다. 메뉴 카드 유형과 실제 펼침·읽기·판단 상태를 분리해 표시해야 한다.

4. 상세의 이하를 보고도 모델은 결과 설명을 수정하지 않았다. 표시뿐 아니라 모델의 결과 해석 실패도 있다.

5. 8회 모두 원문·관계 평가 배열이 비어 있어도 탐색이 계속된다. 목적 설명은 남지만 확인 사실·관련 여부·남은 정보의 갱신을 요구하지 않는다.

6. 같은 관계 펼치기를 세 번 허용한 뒤 진행 없음으로 종료했다. 재호출 전에 기존 결과와 새로 필요한 정보가 무엇인지 확인하는 복구 동작이 없다.

## 근본 변경 방향

원문 읽기 → 그 결과에서 확인된 사실·질문 관련성·미확인 범위를 짧게 기록 → 남은 정보에 맞는 관계/원문 선택 → 충분한 근거의 답변 검토 순서로 연결한다. ADOPT를 강제하지 않고 REJECT/DEFER를 허용한다. 관계 메뉴에는 출발 구절·표제어·대상 이름·유형·실제 처리 상태를 보존한다. 다른 관계는 삭제하지 않고 종류별 추가 탐색으로 유지한다. 같은 대상·같은 범위를 다시 확인할 때는 새 정보 유무를 구분한다. 이 진단에서 구현이나 새 실험은 수행하지 않았다.
